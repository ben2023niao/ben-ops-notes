1. 模块目标

首页是产品的核心流量分发页，承担三大目标：

  1. 赛事曝光：用顶部赛事主视觉 + 今日赛程 + 时间线让用户秒懂今天/全程的赛事节奏
  2. 直播分流：把"正在直播"的房间用瀑布流推到用户面前，引导进入直播间消费
  3. 竞猜转化：把"热门竞猜"和"我的竞猜"放在显眼位置，最大化押注转化

2. 用户角色

角色 说明
已登录用户 完整首页（含"我的竞猜"、钱包余额、头像）
未登录用户 同样可看，但点击任何 CTA（进入直播间、押注）跳登录页

4. 业务规则

  1. 大屏主推：顶部赛事主视觉直接使用今日赛程数据；默认取当天最靠前的赛事作为主卡，其余赛事作为副卡，不接广告 banner。
  2. 倒计时：主推赛事开赛前显示倒计时（HH:MM:SS），开赛后切换为"LIVE"状态。
  3. 今日赛程数量：默认显示 4 张，按时间正序；超过 4 场用左右箭头滑动；不足 4 场右侧留白。
  4. 正在直播 N：默认 N=6，按主播 GMV/热度倒序；房间下播立刻从列表移除。
  5. 热门竞猜：取进行中 + 未开始 状态的活动，按"奖池总量"倒序；最多 4 条；点击跳竞猜中心或赛事详情。
  6. 我的竞猜统计口径： - "进行中"= 状态为"竞猜进行中" 或 "竞猜待开奖"的活动数 - "在押"= 所有未开奖活动的押注本金累计 - 列表显示最近 4 条，按时间倒序
  7. 时间线显示范围：含全部 64 场比赛；今天的场次居中；可滑动看历史/未来。
  8. 未登录展示：导航右侧钱包/头像区域显示"登录/注册"按钮；"我的竞猜"卡片显示"登录后查看"。
  9. 数据刷新策略： - 大屏倒计时：前端本地计时器 1s tick - 直播间列表：进入页面拉一次 + 30s 轮询 + WS 推送（开播/下播） - 比分（时间线 / 大屏中的 LIVE 场次）：30s 轮询 - 我的竞猜：进入页面拉一次 + 押注下单后主动刷新 - 钱包余额：进入页面拉一次 + 钱包变动 WS 推送

5. 边界与异常

场景 系统行为 提示/状态
大屏配置为空 取最近的 1 场 LIVE 或最早未开赛场 不显示倒计时副卡
今日无任何比赛 "今日赛程"显示空状态 "今日无比赛 · 看看明天 →"
当前无直播 "正在直播"显示空状态 "暂无直播 · 等待主播上线"
无任何竞猜活动 "热门竞猜"显示空状态 "竞猜活动准备中"
用户未押注过 "我的竞猜"显示空状态 "还没参与竞猜 · 去试试 →"
接口失败 该卡片降级显示 skeleton 重试按钮
钱包余额接口 timeout 显示上次缓存值 + 红点 "余额可能不准，点击刷新"

6. 权限与风控

  1. 首页可匿名访问，所有点击 CTA 需登录。
  2. 不涉及资金、订单的写操作。
  3. 不涉及审计日志（首页是纯读）。

streamer_room services/go-app 直播间表（房间 ID、主播、比赛关联、状态）
predict_activity services/go-app 竞猜活动表
predict_bet services/go-app 用户押注记录（用于"我的竞猜"）
user_wallet services/go-app 用户钱包（RMB + 钻石）
ad_slot services/go-app 广告位定义，前台按 slot_code 拉取
ad_creative services/go-app 广告内容，挂在广告位下，含图片/文案/跳转/时间窗

HOME-009 WS /ws/v1/wallet services/realtime（后续启用） 待设计
通用 GET /api/v1/me/profile（含用户信息、钱包） services/go-app 待设计

首页广告读取约定：

slot_code 位置 后台管理入口 前台行为
home_middle Web 首页时间线下方广告位 后台「广告管理」 若为空，不渲染广告模块

不再新增聚合接口：首页通过多个小接口并发加载，广告也按 slot_code 独立拉取，便于 CDN/缓存和投放开关隔离。

10. 测试要求

  1. 单元测试：倒计时计算、卡片状态映射逻辑
  2. 集成测试：聚合接口 /home/feed 数据完整性
  3. E2E：登录 → 首页 → 副卡切换 → 进入直播间 → 返回首页
  4. 性能：首页首屏 LCP < 2.5s，首页 API 总耗时 < 500ms
  5. 截图：登录态 / 未登录态 / 空状态（无直播/无竞猜）
