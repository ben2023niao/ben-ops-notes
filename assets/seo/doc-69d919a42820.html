  pywebio.exceptions.SessionNotFoundException:
  Can't find current session. Maybe session closed or forget to use `register_thread()`.
发布锁随后释放，发布流程异常结束。

根因分析

CICD Web 基于 PyWebIO 会话模型。发布流程把 Docker 构建的长日志实时渲染到浏览器会话 scope：
run_stream -> logger.log -> pywebio output.set_scope -> get_current_session

构建期间运维页面会话丢失（浏览器关闭/刷新/切后台超时/网络中断等），
logger 在向已失效的会话输出日志时抛出 SessionNotFoundException，
异常沿 run_stream -> build_image -> run_deploy 一路向上，导致整个发布流程中断。

结论：这是 CICD Web 应用自身的会话依赖问题，不是业务代码或镜像构建失败。
证据：发布中断后 Docker 构建仍在后台继续，18:03:36 镜像 youdianse-php:main-45af8d1487af
构建成功（1.16GB）；业务 git 45af8d1487af 为正常 merge commit。

发布锁已自动释放，无脏状态残留

下次避免措施

1. 优先用 CLI 发布（本记录命令），特别是需要长时间构建（Phalcon 编译等）时，不要依赖 Web 页面会话。
2. 必须用 Web 页面时：发布开始后不要关闭/刷新页面、不要切走标签页；确认浏览器不休眠、
   无网络切换；避免超过会话超时（本次约 4.5 分钟构建即触发）。
3. 治本方向（CICD 改造）：长任务发布改为独立后台线程/进程执行，页面只订阅展示状态，
   日志输出不再依赖活动会话（register_thread / 任务队列），会话丢失不中断发布。
4. 失败恢复标准化：先确认发布锁已释放 -> 检查镜像是否已在后台构建完成 ->
   直接 CLI 重发即可，无需改动业务代码。
5. 发布前确认线上业务仓库已 fetch 目标 git id（本次 45af8d14 已在仓库内）。
