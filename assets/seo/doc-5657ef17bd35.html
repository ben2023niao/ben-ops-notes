用途：把测试环境已经完成的“新增运维人员到网页发布和机器人通知”操作，按同样思路同步到正式环境 main 分支。

把下面整段提示词发给 AI，先把占位符补齐，再让 AI 执行。

你是运维自动化助手。我要在“正式环境 / main 分支”新增一个运维发布人员，并更新发布机器人通知 @ 列表。

新增运维：
- Telegram 用户：@melo_sre
- 网页发布人员显示名：运维-@melo_sre

当前正式运维名单应为 4 人，顺序固定：
1. @Ben_Bird
2. @jett_yunwei
3. @Kermit0824
4. @melo_sre

目标：
1. 在 main 分支的 CICD Web 发布页面“操作人/人员”列表里增加 `运维-@melo_sre`。
2. 发布机器人、配置同步、自动更新、健康监控等运维通知里的 @ 列表改为：
   `@Ben_Bird @jett_yunwei @Kermit0824 @melo_sre`
3. 保持后端人员列表不变，不删除已有人员。
4. 不打印 Telegram token、发布密码、webhook token、chat_id 等敏感信息。
5. 提交并推送 main 分支。
6. 在正式服务器拉取 main，重启发布机器人 CICD Web，并验证运行态配置已经加载新人员。

正式环境信息：
- 运维仓库本地路径：<LOCAL_MAIN_REPO_PATH>
- 正式分支：main
- 正式服务器：<MAIN_SERVER_IP>
- SSH：<MAIN_SSH_USER>@<MAIN_SERVER_IP>
- SSH key 或登录方式：<MAIN_SSH_KEY_OR_LOGIN_METHOD>
- 服务器运维目录：<MAIN_SERVER_OPS_DIR>
- CICD Web 管理脚本：./cicd-web.sh
- CICD Web 正式访问地址：<MAIN_CICD_URL>

参考测试环境已完成的改动：
- 提交：50534e4 Add melo sre to ops operators
- 测试环境关键文件：
  - cicd-web/config/settings.json
  - README.md
  - docs/2026-06-25-0900-【运维记录】测试环境CICD-Web自动更新与定时任务边界说明.md
  - ops/test/install-health-monitor.sh
  - ops/test/2026-06-23-0116-【优化】测试环境健康监控与告警说明.md

本地修改要求：
1. 先确认本地仓库在 main 分支：
   git status --short --branch
   git branch --show-current
2. 搜索所有旧的 3 人运维 @ 列表：
   rg -n "Ben_Bird|jett_yunwei|Kermit0824|ops_mentions|YOUDIANSE_OPS_MENTIONS|运维-" -S .
3. 必改 `cicd-web/config/settings.json`：
   - `publish.operators` 运维人员前 4 项改为：
     - `运维-@Ben_Bird`
     - `运维-@jett_yunwei`
     - `运维-@Kermit0824`
     - `运维-@melo_sre`
   - `telegram.ops_mentions` 改为：
     `@Ben_Bird @jett_yunwei @Kermit0824 @melo_sre`
4. 如果正式环境有健康监控脚本或文档，也同步默认 mentions：
   - `YOUDIANSE_OPS_MENTIONS`
   - `mentions`
   - `ops_mentions`
   统一使用：
   `@Ben_Bird @jett_yunwei @Kermit0824 @melo_sre`
5. 如果 README 或 docs 里写了 “@ 3 个运维” 或旧名单，改成 4 人名单。
6. 不要改 token、密码、chat_id、业务配置、发布分支、域名。

本地验证：
1. JSON 校验：
   python3 -m json.tool cicd-web/config/settings.json >/tmp/settings.json.check
2. 如果改了 Python 脚本，执行对应 py_compile。
3. 确认发布页面人员列表：
   python3 - <<'PY'
   import json
   cfg=json.load(open('cicd-web/config/settings.json', encoding='utf-8'))
   print('\n'.join(cfg['publish']['operators'][:4]))
   print(cfg['telegram']['ops_mentions'])
   PY
   预期输出：
   运维-@Ben_Bird
   运维-@jett_yunwei
   运维-@Kermit0824
   运维-@melo_sre
   @Ben_Bird @jett_yunwei @Kermit0824 @melo_sre
4. 搜索确认旧的 3 人列表没有残留在需要同步的配置里：
   rg -n -F "@Ben_Bird @Kermit0824 @jett_yunwei" .
   rg -n -F "3 个运维" .

提交推送：
1. git diff --stat
2. git add <实际改动文件>
3. git commit -m "Add melo sre to ops operators"
4. git push origin main

正式服务器部署：
1. SSH 登录正式服务器。
2. 进入正式运维目录：
   cd <MAIN_SERVER_OPS_DIR>
3. 先确认状态：
   git status --short --branch
   git rev-parse --short HEAD
4. 拉取 main：
   git pull --ff-only origin main
5. 重启发布机器人：
   ./cicd-web.sh restart
   ./cicd-web.sh status
6. 如果正式服务器本地 `cicd-web/runtime/secrets.env` 里写了 `YOUDIANSE_OPS_MENTIONS`，需要把它改成：
   `YOUDIANSE_OPS_MENTIONS=@Ben_Bird @jett_yunwei @Kermit0824 @melo_sre`
   注意不要输出 secrets.env 全文，不要打印 token/password/chat_id。
7. 验证运行态配置，不打印敏感值：
   set -a && . cicd-web/runtime/secrets.env && set +a
   python3 - <<'PY'
   import sys
   sys.path.insert(0, 'cicd-web')
   import config
   print('operators:')
   for op in config.PUBLISH_OPERATOR_OPTIONS[:4]:
       print(op)
   print('ops_mentions:', config.OPS_MENTIONS)
   PY
   预期输出包含：
   运维-@Ben_Bird
   运维-@jett_yunwei
   运维-@Kermit0824
   运维-@melo_sre
   ops_mentions: @Ben_Bird @jett_yunwei @Kermit0824 @melo_sre
8. 最后确认：
   git status --short --branch
   ./cicd-web.sh status

完成后汇报：
1. 本地 main 分支提交号。
2. 正式服务器是否已拉到最新提交。
3. CICD Web 是否已重启并运行中。
4. 发布页面运维人员前 4 项。
5. 运维通知 @ 列表。
6. 是否发现 secrets.env 覆盖了 `YOUDIANSE_OPS_MENTIONS`，如有是否已同步。
