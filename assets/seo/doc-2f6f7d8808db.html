背景

用户反馈测试环境登录要加载很久，要求优先处理，操作一步通知一步。前期诊断（见 2026-08-17_1940-【修复记录】测试环境后端API无响应导致登录加载慢.md）已定位到「测试后端 PHP/API 整体超时」，重启容器只能恢复几分钟，随后再次全站 504，H5 SSR/登录页 30-60 秒。

根因链（本次最终定位）

  1. 配置表 config 中 vip_growth_rule（会员成长规则富文本，type=5）今天 19:11 被误粘贴成 3,642,264 字节（约 3.6MB）的腾讯文档 HTML（tdoc-data-src 编辑器序列化数据，非正常内容）。
  2. ConfigService::getAll() 会把全部配置合并后整包写入/读取单个 Redis key 18game_system_config（db3），因此该缓存膨胀到 3,651,041 字节。
  3. 每个 API 请求（system/info、AppVersion/latestVersion、modules/home 等）都会执行 cache()->get(CacheKey::SYSTEM_CONFIG)；当应用服务器 → 数据库服务器（103.207.68.124）网络出现抖动时，一次 3.6MB 的 Redis GET 实测耗时 93 秒（数据库本机 GET 仅 15ms）。
  4. 测试后端 PHP-FPM pm.max_children = 5，几个请求被 3.6MB 缓存卡住后，5 个 worker 全部被占满，其余请求排队至 nginx 60s 超时 → 全站 API 504，H5 Nuxt SSR 渲染等待接口超时降级 → 登录页/首页 30-60 秒。

关键证据

  • Redis：STRLEN 18game_system_config = 3651041；应用侧持久连接 GET 该 key 耗时 93.092s；数据库本机 GET 仅 0.015s。
  • PHP-FPM slow.log 调用栈：AppVersionRepository -> ConfigService::getAll() -> get() (ConfigService.php:32)，即 cache()->get(SYSTEM_CONFIG)。
  • Mongo：config.vip_growth_rule 值头部为 <header class="yds-hero">... tdoc-data-src ...，非 JSON，明显是腾讯文档页面整页粘贴。
  • 时序吻合：vip_growth_rule.updated_at = 2026-08-17 19:11:44，此后 slow_api（system/info 60-100s）密集出现。

处理过程

  1. 备份：mongodump --db 18game --collection config → /tmp/vipfix_backup_20260817/18game/config.bson（含原 3.6MB 脏值，可回滚）。
  2. 修复数据：vip_growth_rule 恢复为 771 字节正常富文本；正文从误粘贴内容中提取保留（会员体系/会员等级/成长值获取/成长值衰减），格式为简洁 HTML。
  3. 清理缓存：redis-cli -n 3 DEL 18game_system_config。
  4. 重启 youdianse-dev-php-web 容器，清空 worker 内存中的静态配置缓存。

遗留观察项

  1. 会员成长规则页面内容为从脏数据提取的简化排版，如需原样式请在后台重新编辑保存。
  2. 结构风险：ConfigService 把全部配置（含富文本大字段）合并进单个 Redis key 且每次请求整包读取，遇到大字段 + 网络抖动会放大为全线超时。建议后续把富文本/大字段类配置移出统一缓存或按需读取。
  3. 测试后端 pm.max_children = 5 偏小，多人同时使用容易排队，建议按需调大。
  4. 应用→数据库链路本次出现 3.6MB 传输耗时 90s 的抖动（约 38KB/s），疑似该链路存在周期性丢包/限速，建议观察；本次修复后小缓存不受影响。
