加域名全部分流与失败回滚优化

背景

用户确认：所有域名（主域名、二级域名、h5.* / pc.* 前缀）加进来都按设备分流：电脑打开→PC(3004)、手机打开→H5(3003)。

此前加 youdianse.com 时默认按 h5 处理（新增 h5.youdianse.com 但该主机已存在、并尝试重签证书导致 certbot 失败），需要优化加域名流程。

变更

服务器 nginx

10-youdianse-prod-maps.conf：移除 ~^pc\..+$ pc; 规则，全部域名默认 ua 分流（h5.* / pc.* 同样分流）；仅跳转类（yds-pc-h5-* 根域/www）保持 redirect，显式条目可覆盖。

备份：/root/.codex-backup/10-youdianse-prod-maps.conf.pre-all-ua.bak、20-youdianse-prod-unified.conf.pre-all-ua.bak

服务器维护脚本 youdianse-domain-maint.py

  1. mode_of：默认一律 ua（不再对 pc.* 特判）。
  2. add 默认类型 h5 → ua：直接回复根域名（如 youdianse.com）即按 UA 分流接入。
  3. 移除 h5. / pc. 前缀自动识别为纯 H5/纯 PC 的逻辑（按用户要求全部走分流）。
  4. issue_cert：目标主机已有有效证书时跳过签发（避免 h5.youdianse.com 这类软链证书重复签发失败）。
  5. add 证书签发失败自动回滚 server_name/maps 并 reload，不留下半成品。

备份：/root/.codex-backup/youdianse-domain-maint.py.pre-add-opt.bak

验证

域名 模式

pc.yds-pc-h5-01.cc ua ✅
h5.yds-pc-h5-01.cc ua ✅

  • youdianse.com → 新增 youdianse.com ua
  • pc.demo-x.com → 新增 pc.demo-x.com ua
  • h5.demo-x.com → 新增 h5.demo-x.com ua

证书跳过与回滚

  • cert -d h5.youdianse.com → “已有有效证书，跳过签发” ✅
  • add rollbacktest-abc123.com --cert（DNS 不存在）→ certbot 失败后自动回滚，server_name/maps 无残留，nginx -t 通过 ✅

公网抽验

  • taokju.com / shouyek.com：手机 H5、电脑 PC ✅

机器人侧

  • 插件加域名提示：默认 ua（电脑→PC、手机→H5），示例 youdianse.com。
  • 客户端 add 用法说明同步默认 ua；新增域名状态标记为 new。
  • ben-bot 容器已重建，启动通知 10/10。

结论

  • 加域名默认全部分流（主域名/二级/h5/pc 前缀均手机 H5、电脑 PC）。
  • 已有证书跳过签发；签发失败自动回滚，避免半成品。
  • 注意：youdianse.com 根域名 DNS 当前仍指向老宝塔 16.208.5.147，需先切到 16.208.38.88 后机器人加域名+证书才能成功。

追加：加域名幂等检查（2026-08-12）

  • 需求：重复添加已存在的域名时，先检查该域名当前配置（server_name / 模式 / 证书）是否正确。
  • 实现（youdianse_domain_maint.py add_domain）：
  • 全部正确 → 输出“域名已存在，配置正常：<主机>”，不再重复操作。
  • 主机缺失 / 模式不对 / 证书缺失 → 自动补齐修复（写 server_name/mode、reload、补签证书）。
  • 证书签发失败仍自动回滚本次变更。
  • 客户端 add：按输出主机名同步状态（已增加/已修正/配置正常均登记为新域名），不再按类型猜测。
  • 验证：
  • add 118acs2.com / add shouyek.com → “域名已存在，配置正常” ✅
  • add h5.youdianse.com（此前模式残留 h5，现默认 ua）→ 自动对齐为 ua，配置正常 ✅
  • add shouyek.com --type pc --dry-run → 显示“将新增/修正 mode: {'pc.shouyek.com': 'pc'}”（模式不对会修正）✅
  • add taokju.com --type h5 --dry-run → 显示新增 h5.taokju.com h5（主机缺失会新增）✅
  • ben-bot 重建启动通知 10/10 ✅

追加：删除域名功能（2026-08-12）

  • 需求：新增 🗑 删除域名；搜索到域名后点按钮删除。
  • 实现：
  • 菜单新增 🗑 删除域名（回复域名即可删除）；续签列表 / 搜索结果每个域名行带 🗑 按钮。
  • 点击 🗑 → 弹确认（✅ 确认删除 / ↩ 取消），确认后异步执行删除并回发结果。
  • 服务器 del 子命令：从 nginx server_name + $h5pc_mode 移除并 reload；证书文件保留（避免误伤共享证书）。
  • 客户端 del：同步从机器人状态文件移除该域名。
  • 验证：
  • del youdianse.com --dry-run → 显示将删除 server_name + 模式条目（不写入）✅
  • 临时主机 del-test-x.com 实删 → server_name/maps 均移除、nginx -t/reload 通过 ✅
  • 不存在域名删除 → 提示“域名不存在于 nginx” ✅
  • ben-bot 重建启动通知 10/10 ✅
  • 测试事故记录：验证删除时一次内联脚本把 10-youdianse-prod-maps.conf 截断为空（open(...,"w") 在参数求值异常前已截断文件），已立即用仓库版本恢复并 nginx -t/reload，恢复后 md5 与仓库一致（ec384652…），无业务影响。

追加：DNS未生效域名照常加入 + 操作前自动备份（2026-08-12）

  • 需求： 1. 新增域名时若 DNS 尚未完全生效、暂时做不了 SSL，也要把域名加入 nginx（证书失败不再回滚删除，稍后可到 SSL 续签里补签）。 2. 增加/删除/修改SSL/续签等操作前，备份服务器全部 nginx 配置 + SSL 证书，用人类可读时间命名压缩发群；备份默认保留 100 份。 3. 增加/删除/更新SSL 的提示词改用案例域名（example.com），不写业务域名。
  • 实现：
  • backup_all()：操作前把 /etc/nginx（nginx.conf/conf.d/sites-enabled）与 /etc/letsencrypt（live/archive/renewal）备份到 /root/.codex-backup/nginx-ssl-<YYYY-MM-DD_HH-MM-SS>/；生成群发送压缩包 *-group.tar.gz（剔除 privkey 私钥，安全考虑），服务器保留完整备份（含私钥）；默认保留最新 100 份。
  • add/del/cert/renew 执行前自动调用备份（dry-run 不备份）。
  • add_domain 证书签发失败不再回滚：域名照常加入 nginx，输出“域名已加入 nginx；DNS 生效后可在机器人 SSL 续签里补签证书”。
  • 客户端拉取群备份包到本地并输出 BACKUP_FILE；插件/文本钩子在增加/删除/签发/续签结果里自动把备份包发到群（发送后清理临时文件）。
  • 提示词：增加示例 example.com、删除示例 example.com / h5.example.com、搜索示例 example.com / example，不再出现业务域名。
  • 验证：
  • add test-pending-dns-xyz.com --cert（DNS 不存在）→ 域名加入 nginx（server_name/maps 各 1 条），证书失败但保留，提示稍后补签 ✅
  • 备份目录 /root/.codex-backup/nginx-ssl-2026-08-12_14-29-24 等生成；群包含 nginx+letsencrypt、privkey 计数 0 ✅
  • 轮转保留：当前 4 份（操作前 3 份 + del 1 份）✅
  • del test-pending-dns-xyz.com 清理成功，两处残留 0，del 也生成备份 ✅
  • ben-bot 重建启动通知 10/10 ✅

追加：修复备份发群与续签缓存刷新（2026-08-12）

  • 用户反馈：①刚加的域名在 SSL 续签/搜索里搜不到；②操作后没看到备份包发群。
  • 根因： 1. SSL 续签列表/搜索读取 data/upload/domain_maint_renew.json 缓存快照，加/删/签后缓存未失效（实测缓存停留在 11:24，早于新增域名）。 2. 客户端用 scp 以 ubuntu 身份读取 /root/.codex-backup/（root 目录权限不足），报 No such file or directory，备份包从未拉取成功。
  • 修复（客户端 youdianse_domain_maint_client.py）：
  • _fetch_backup 改用 ssh + sudo cat 二进制拉取备份包到容器 /tmp，输出 BACKUP_FILE 供机器人发群。
  • 新增 _invalidate_caches()：add/del/cert/renew 成功后删除 domain_maint_renew.json + domain_maint_page.json，下次 SSL 续签/搜索自动重新拉取最新域名。
  • 验证（容器内实测）：
  • cert -d shouyek.com → BACKUP_FILE=/tmp/nginx-ssl-…-group.tar.gz（56KB）生成，缓存清理 ✅
  • add test-cache-chk.com → 域名加入、备份生成、load_renew_rows 重新拉取后 test-cache-chk.com 可搜到 ✅
  • del test-cache-chk.com 清理成功，临时备份文件清理 ✅
  • ben-bot 重建启动通知 10/10 ✅

追加：全部域名 API 403 修复（参照宝塔 nginx，2026-08-12）

  • 现象：所有域名页面能开但接口 403（CloudFront 提示无法连接源站 / nginx 日志大量 SSL_do_handshake failed 到 www.youdianse.com 上游）。
  • 根因：youdianse.com / www.youdianse.com / h5.youdianse.com 的 DNS 被切到新 CloudFront d38owkgqvg83bq，而新服务器 unified conf 的 /api|channel|customer 反代到 www.youdianse.com → API 上游走新 CF 自指/回源循环 → 403。
  • 参照宝塔配置（16.208.5.147）：
  • 宝塔 new.youdianse.com.conf（server_name 含 www.youdianse.com 等）把 / 反代到内网 203.0.113.1:3003（H5 容器，内部代理 /api 到后端）。
  • youdianse.com.conf 为 PHP 后端（enable-php-82）。
  • 修复：新服务器 20-youdianse-prod-unified.conf 的 API 上游改为宝塔内网 IP 203.0.113.1 + SNI/Host www.youdianse.com（proxy_ssl_name www.youdianse.com），完整复刻宝塔链路，不再依赖 www.youdianse.com 的 DNS/CF。
  • 验证：
  • 公网 API 连续 3 轮：taokju / shouyek / www.bochuang99 / ydsplay.net 全部 200 ✅
  • www.youdianse.com、h5.youdianse.com 页面 200 + 接口 200 ✅
  • 118acs2、taokju 页面 200 + 接口 200 ✅
  • nginx error log 15:20 后无新增 SSL_do_handshake failed ✅
  • 遗留（CloudFront 账号侧，服务器无法解决）：youdianse.com 裸根域名公网 HTTPS 仍握手失败（新 CF 证书未覆盖裸根），需在 CF 该 distribution 添加 youdianse.com 的 Alternate Domain Name + 对应证书（可导入宝塔老证书或 ACM 新签）。
