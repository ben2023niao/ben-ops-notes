一、方法与节点

对比对象：
  我方入口：https://ind-h5.dbqpplus999.com/pgbronline/（PG H5 大厅）
  竞品入口：https://m6kk678n.com/main/inicio（熊猫大厅，测试账号登录）

节点：
  巴西 GRU     宝塔 ben-bot 容器（Playwright Chromium）
  马尼拉       本机 macOS（Playwright Chromium）
  东京         GCP 临时 e2-micro asia-northeast1（HTTP 级，已删）
  新加坡       GCP 临时 e2-micro asia-southeast1（HTTP 级，已删）
  香港         34.92.13.108（HTTP 级）

两种口径：
  A. curl 5 次 TTFB/总耗时（五地区）；
  B. Playwright（手机 UA 390x844）浏览器加载 + 录屏 + Navigation
     Timing + 全部资源 timing（域名/类型/体积/缓存状态），
     分“禁缓存冷加载”与“正常缓存（预热后）”两轮。
工具：docker/scripts/speed_compare_browser.py（本次新增）。

三、浏览器 F12 级结果（正常缓存=预热后真实场景）

马尼拉：
  我方：TTFB 0.32-1.38s（多次波动）｜DOMContentLoaded≈1.55s
        116 资源 / 5.48MB（113 张封面 img，全部 CF HIT=预热生效）
  竞品：TTFB≈0.06s｜DOM≈0.19s
        140 资源 / 约 31KB（Service Worker + CF HIT 大量 0 transfer）

巴西 GRU：
  我方：TTFB 0.77s｜DOM≈0.93s
        116 资源 / 5.48MB（HIT 56 + REVALIDATED 57 冷测时）
  竞品：TTFB 0.09s｜DOM≈2.7s / load 3.9s
        125 资源 / 1.33MB（HTML 边缘 HIT，DOM/API 反而慢）

禁缓存冷加载补充（巴西）：
  我方 57 张图片 REVALIDATED，单张最慢约 3.0s（逐张回源校验）；
  竞品跨域 api4.a-b-c-8.com 30+ 次 DYNAMIC fetch，单次最高约 0.9s。

四、响应头关键证据

我方 ind-h5 HTML：
  server=cloudflare；cf-cache-status=DYNAMIC；无 cache-control
  -> 每次请求都回巴西源站（这就是巴西/亚洲 TTFB 高的主因）
竞品 m6kk678n.com HTML：
  server=cloudflare；cf-cache-status=HIT；age=119（边缘已有缓存）
  -> HTML 壳在 CF 边缘直接命中

五、竞品做法（他们的快与慢）

快：
  1) 入口 HTML 在 CF 边缘 HIT（app shell 可缓存）；
  2) Service Worker 缓存壳资源：二次访问大量 CSS/JS/图片 0 transfer；
  3) 图片走独立 CDN 子域（game-logo.6-q-r-s.com / upload-us.*）并懒加载；
  4) 资源域名拆分（main / api4 / upload / logo / fonts），并行度更高。
慢：
  - 跨域 API 数量多（30+ 次 fetch，单次 0.4-0.9s），巴西 DOM≈2.7s；
  - 依赖动态接口完成后才渲染，边缘 HTML 快但整体 DOM 不快。

六、我方差距与可优化清单

P0-1 H5 大厅 HTML 边缘缓存：
      现状 ind-h5 HTML = DYNAMIC 每次回源；
      建议大厅 HTML 壳做 CF Cache Rule（短 TTL 60-300s + 发布失效/版本盐），
      或确认页面无个性化内容后缓存；
      预期：巴西 TTFB 0.74s -> 0.1-0.2s，亚洲 0.2s -> 0.1s。

P0-2 大厅封面图策略：
      一次预载 113 张 / 5.48MB；建议懒加载 + 首屏限载 +
      WebP/AVIF 压缩 + 独立图片子域；
      预期减少 50-80% 首屏图片字节，并解除图片与 HTML 同域 6 连接瓶颈。

P1 图片缓存 immutable 长 TTL：
      禁缓存冷测 57 张 REVALIDATED、单张最慢 3s；
      版本化文件名或目录 + Cache-Control immutable，
      避免逐张回源校验。

P2 H5 大厅 Service Worker：
      竞品用 SW 缓存 app shell；我方可在确认版本策略后引入 SW
      （壳资源 + 版本清理），让二次/多次访问更稳定。

P3 资源域名拆分：
      我方 114/116 资源来自同一 host（ind-h5.dbqpplus999.com），
      浏览器同域连接受限；JS/CSS/图片按类型拆独立子域（CF CNAME
      前缀池已有类似能力，H5 侧可复用）。

七、我方已有优势

1) 封面图已全部预热（CF HIT 113/116），首屏“冷”图片问题已消除；
2) 我方大厅 DOM 更快（巴西 0.93s vs 竞品 2.7s）——我方 HTML/JS 轻；
3) 静态游戏资源已 git->GCS->CF 双区 + 20 zone 预热体系，发布即热。
