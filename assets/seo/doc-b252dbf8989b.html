1. 目的与适用场景

本文档用于以后所有“测试环境 env/.env.dev 配置修改”的纯手动运维操作，本次以 [aws] 段新增 AWS_DOMAIN_ENCRYPT_KEY 为例。

适用对象：运维人员 / AI 助手 / 发布机器人。

适用环境：

运维仓库：18game.18git.com/root/docker-youdianse-php.git，分支 dev
业务仓库：18game.18git.com/php/youdianse-php.git，分支 dev
Live 测试前后端：15.152.247.196（内网 203.0.113.1）
Live /opt 运维目录：/opt/docker-youdianse-php
数据库：15.152.6.51 内网 203.0.113.1（Mongo 27017 / Redis 6379）
回滚旧机：38.92.8.34（只作回滚基线，不在本文档流程内改动）

安全边界：

只操作测试环境 dev；不触碰正式环境 main；
不输出/不记录/不提交 Telegram token、chat_id、SSH 密码、发布密码、私钥、带凭据仓库 URL；
`AWS_DOMAIN_ENCRYPT_KEY` 密钥正文不写入文档、Git、workbench 与通知；如需人工新增请从需求方安全渠道取值。

文件：

env/.env.dev

[aws]
...
AWS_DOMAIN_ENCRYPT_KEY=<密钥正文，不落文档>

远端基线：

origin/dev = 180438e（Merge branch 'root-dev-patch-30851' into 'dev'）

3. 运维可完全手动执行的完整步骤

3.1 只读确认现状（每次先做，不改动）

在本地 / 运维电脑执行：

git remote -v
git branch --show-current
git status --short --branch
git fetch origin dev
git log origin/dev -3 --oneline

确认：

当前分支 = dev
origin/dev 是最新目标提交
没有未提交改动，或有确认可保留的本地改动

若远程新增了目标配置但本地落后，先同步：

git merge --ff-only origin/dev
git status --short --branch

3.2 修改 env/.env.dev（手动新增/修改配置段时使用）

编辑本地文件：

code env/.env.dev

在 [aws] 段内追加或修改目标 key，例如：

[aws]
[敏感内容已脱敏]
[敏感内容已脱敏]
AWS_DEFAULT_REGION=...
AWS_BUCKET=...
AWS_DOMAIN=...
AWS_DOMAIN_ENCRYPT_KEY=<密钥正文，按安全渠道填写>

校验（只输出 key 是否存在，不输出正文）：

python3 - <<'PY'
import configparser
cp = configparser.ConfigParser(strict=False, interpolation=None)
cp.read('env/.env.dev', encoding='utf-8')
print('has [aws]:', cp.has_section('aws'))
print('has AWS_DOMAIN_ENCRYPT_KEY:', cp.has_option('aws', 'AWS_DOMAIN_ENCRYPT_KEY'))
PY

提交并推送：

git add env/.env.dev
git commit -m "config(test): update env aws config"
git push origin dev

若只是把远端已合入的配置同步到本地，则无需手工编辑，直接执行 3.1 的 git merge --ff-only origin/dev 即可。

3.3 live /opt 同步（关键步骤）

使用具备 live 权限的发布机器人 / SSH 登录：

ssh root@15.152.247.196

进入运维仓库并只读确认：

cd /opt/docker-youdianse-php
git branch --show-current
git status --short --branch
git rev-parse --short HEAD

目标状态：分支 dev，HEAD 应为目标提交（本次 180438e）。

若工作区 clean 且落后远端，执行同步：

git fetch origin dev && git merge --ff-only origin/dev
git rev-parse --short HEAD

若工作区有本地运行态改动，先人工确认后再处理，禁止直接丢弃；例如只保留预期改动后可提交到远端或暂存后同步。本次目标为远端已合入配置，冲突时以远端 180438e 为基准并确认 DB host=203.0.113.1 不丢失。

注意：若 env/.env.dev 上存在“仅服务器本地维护”的配置段（例如 [cdn.tencent.spj2-apk.showfifa.com]、[trtc] 等），不要用 git merge --ff-only 直接覆盖整份文件，否则会丢掉这些本地段。正确做法见第 3.6 节“本地维护段保留的增量同步法”。

3.6 本地维护段保留的增量同步法（本次实测采用）

适用场景：

/opt env/.env.dev 同时存在需要保留的本地段（spj2/trtc 等），
远端 origin/dev 只新增/修改部分 key（本次为 AWS_DOMAIN_ENCRYPT_KEY）。

步骤：

cd /opt/docker-youdianse-php
git fetch origin dev

# 1. 先备份当前运行 env
mkdir -p cicd-web/runtime/env-backups
cp -p env/.env.dev "cicd-web/runtime/env-backups/.env.dev.before_manual_sync_$(date +%Y%m%d_%H%M%S).bak"

# 2. 从远端目标提交提取本次要合入的 key 行（不打印正文）
git show origin/dev:env/.env.dev | grep '^AWS_DOMAIN_ENCRYPT_KEY=' > /tmp/target_key.txt

# 3. 本地 env 已存在则替换，不存在则在 [aws] 段 AWS_DOMAIN 后追加
#    手工编辑或脚本处理，保证：
#    - host 保持 203.0.113.1（7 处）
#    - spj2/trtc 等本地段原样保留
#    - AWS_DOMAIN_ENCRYPT_KEY 仅出现一次且值等于远端

# 4. 发布
docker compose --env-file .ops-build.env --profile cron up -d --force-recreate --no-build web nginx cron

发布后必须回到 3.5 验证，并补充记录“本次 live HEAD 是否前移”。

3.4 发布到容器运行态

配置修改必须发布，不能只 git pull：

cd /opt/docker-youdianse-php
docker compose --env-file .ops-build.env --profile cron config
docker compose --env-file .ops-build.env --profile cron up -d --force-recreate --no-build web nginx cron

说明：

--force-recreate：强制重建 web/nginx/cron
--no-build：不重新构建镜像，只让最新运行配置重新挂载
web/nginx/cron：后端、Nginx、cron 三个容器

如果业务代码也需要发布，可改走 CICD 页面 / Webhook 自动发布，发布模式选择“携带 php-cron 执行容器部署”。

3.5 验证

宿主机验证：

cd /opt/docker-youdianse-php
git rev-parse --short HEAD                 # 期望 180438e
git status --short --branch                # 期望 clean
grep -q '^AWS_DOMAIN_ENCRYPT_KEY=' env/.env.dev && echo 'env key: configured'

容器内验证（web / cron 都要）：

docker exec youdianse-dev-php-web sh -lc \
  'grep -q "^AWS_DOMAIN_ENCRYPT_KEY=" /var/www/html/youdianse-php/.env && echo "web env key: configured"'
docker exec youdianse-dev-php-cron sh -lc \
  'grep -q "^AWS_DOMAIN_ENCRYPT_KEY=" /var/www/html/youdianse-php/.env && echo "cron env key: configured"'

运行态验证：

docker ps --filter name=youdianse-dev-php-web --filter name=youdianse-dev-php-nginx --filter name=youdianse-dev-php-cron
curl -ksS -o /dev/null -w '%{http_code}\n' https://admin.youdianse-test.xyz/admin1866/login
curl -ksS -o /dev/null -w '%{http_code}\n' https://cicd.youdianse-test.xyz/

CICD 日志复核：

打开 https://cicd.youdianse-test.xyz
“最近 5 次发布日志”中最新一条应显示：

发布结果 = SUCCESS
HTTP = 200
Redis / MongoDB = 连通

5. 回滚

若需回滚本次配置：

cd /opt/docker-youdianse-php
# 将 env/.env.dev 回退到上一个已确认提交，并重新发布
git fetch origin dev
git checkout <上一个已验证提交> -- env/.env.dev
docker compose --env-file .ops-build.env --profile cron up -d --force-recreate --no-build web nginx cron

回滚后复测：

git -C /opt/docker-youdianse-php rev-parse --short HEAD
