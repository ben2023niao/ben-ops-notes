检查方法

评估覆盖一组公开和被动 DNS 中发现的主机名，分别检查：

  • DNS 与 HTTPS 可达性。
  • 根路径状态、跳转、内容类型和页面标题。
  • TLS 证书与协议。
  • HSTS、CSP、nosniff、Referrer Policy 和 Permissions Policy。
  • 正常 CORS 与预检响应。
  • 公开 JavaScript 中的接口和第三方配置指纹。
  • WebSocket 握手及 Origin 处理。

这类检查只能说明公开面可观察行为。握手成功、预检成功或匿名接口可读，都必须在服务端鉴权、请求体和业务权限层面继续确认。

暴露面概况

多数 QA 主机由 Cloudflare 拦截，未直接暴露页面。可解析资产可以归纳为生产站、下载页、图片 CDN、上传 API、WebSocket、支付专用域和测试环境。

主要关注点不是服务数量本身，而是不同业务域共享了统一前端、Cookie 作用域或公开 CDN 配置，导致测试环境、支付域和用户会话边界不够清晰。

重点发现

1. UAT 环境公开可达

UAT 站点可以在没有额外身份代理的情况下打开完整单页应用，匿名业务接口仍返回未认证状态，没有发现未授权业务数据。

风险在于测试账号、测试数据和调试配置会长期暴露给公网，未来测试环境出现鉴权回归时容易被直接利用。

建议将 UAT 放到 Cloudflare Access、VPN 或固定 IP 白名单之后，并禁止测试环境使用生产支付、短信、KYC 和第三方回调凭据。

2. 支付专用域返回完整主站应用

支付域当前会回退到主站单页应用。统一前端路由可能是有意设计，但支付域应只开放二维码、回调、状态查询和健康检查等必要能力。

需要重点确认：

  • 认证 Cookie 不应以整域父域形式暴露给全部子域。
  • 支付域不应继承主站全部路由。
  • 支付回调签名、日志和密钥应与主站前端配置分离。
  • 支付域的 WAF、CSP 和访问日志应独立管理。

3. CORS Origin 固定为 HTTP

部分前端 API 的预检响应固定返回 HTTP 主站 Origin，并允许携带凭证。未知 HTTPS Origin 没有在本轮响应中得到对应的 ACAO，因此没有确认跨域读取漏洞。

该配置仍属于不规范的边界设计。CORS 应由服务端动态判断请求 Origin，只返回精确匹配的 HTTPS 白名单，并正确设置 Vary: Origin。不能把协议或来源写死为 HTTP。

4. WebSocket Origin 未校验

公开 WebSocket 入口允许完成握手，响应没有因未知 Origin 而直接拒绝。本轮没有发送认证帧，也没有读取消息，因此不能据此认定聊天鉴权缺失。

应确认首帧或订阅动作必须携带不可伪造的用户凭据，服务端将 Token 与用户、会话、房间和权限绑定，并在连接断开后立即失效。若只依赖 Cookie 自动认证，必须校验 Origin，或改用短时一次性连接票据。

5. 上传接口是重点写入口

上传域存在允许凭证的 CORS 预检，业务自身仍可能要求上传 Token。由于没有执行写入，本轮不能判断文件上传是否存在未授权访问。

上传接口需要分层校验：

  • CORS 不是鉴权，POST/PUT 必须独立验证用户和会话。
  • MIME、扩展名、文件大小、图片解码和对象路径都要由服务端校验。
  • 存储桶不能回源执行 HTML、SVG 或 JavaScript。
  • 临时上传 Token 必须短时、单用途，并绑定用户和文件哈希。
  • 上传后的对象访问权限应与业务数据权限一致。

6. 图片 CDN 与对象存储

图片 CDN 根路径返回对象存储 AccessDenied XML，没有目录列表；公开图片使用宽松 CORS，这对静态内容通常是正常设计。

仍需确认桶内不存在备份、日志、用户上传原件或其他私有对象。CDN 缓存时间也要与内容类型匹配，敏感文件不应进入公开缓存。

7. 安全头覆盖不一致

主站安全头较完整，但测试域、支付域和部分接口域覆盖不一致。多个主机缺少 nosniff、统一 Referrer Policy 或 CSP。

建议按资产类别建立统一基线：生产页面优先，支付和 KYC 页面更严格；静态对象使用独立策略，避免复制页面级 CSP 导致资源失效。

8. 生产前端包含开发环境配置

生产前端静态资源中出现开发 Firebase 项目的公开 Web 配置。Web API Key 通常允许公开，但必须限制允许的 API、应用包名、站点来源和配额。

必须同时确认 Firebase Security Rules 没有开放读写，避免把“公开配置”扩大成真实数据访问。

风险汇总

风险项 当前证据 建议优先级
UAT 公网可达 页面可打开，业务接口仍要求认证 P1
支付域路由过宽 返回完整主站 SPA P1
CORS 固定 HTTP Origin 已观察预检响应，未知来源未获得匹配 ACAO P1
WebSocket Origin 宽松 可握手的入口未拒绝外部 Origin，认证状态未知 P1
上传写入口边界 CORS 允许凭证，实际鉴权未测试 P1
安全头覆盖不一致 不同子域策略不同 P2
开发 Firebase 配置出现在生产包 静态资源可读，Rules 未验证 P2
公开 CDN 桶权限 根路径无列表，桶内对象范围未枚举 P2

优先处置顺序

  1. 给 UAT 增加统一身份代理或网络白名单。
  2. 将支付域限制到最小路由集合，并拆分 Cookie 和签名密钥。
  3. 把 CORS 改为精确 HTTPS Origin 动态白名单。
  4. 复核 WebSocket 首帧 Token、Origin 和频道订阅权限。
  5. 对上传接口做双账号写入、MIME、路径、对象权限和重放测试。
  6. 统一不同资产类别的安全响应头。
  7. 验证 Firebase API Key 限制和 Security Rules。
  8. 检查 CDN 桶是否包含非公开对象。

结论

本轮没有确认公开目录列表、源码映射、调试接口、未授权业务数据或可直接利用的高危 CVE。Cloudflare 对大部分 QA 环境提供了有效拦截，主站和聊天接口的基础认证表现正常。

最值得继续跟进的是公开 UAT、支付域路由、CORS、WebSocket Token/Origin、上传写入口和 CDN 对象权限。
