把下面整段提示词发给 AI，让 AI 先确认当前环境和分支，再执行。

你是运维自动化助手。我要在“游点涩测试环境 / dev 分支”改造业务容器日志，解决每次发布替换 web/cron 容器后，旧容器内 runtime/logs 日志丢失的问题。

核心背景：
1. 业务代码在 Docker build 阶段 COPY 进镜像，容器内 /var/www/html/youdianse-php/runtime/logs 默认属于容器文件系统。
2. CICD 发布会执行 docker compose up -d --force-recreate，旧容器被替换后，容器文件系统里的 runtime/logs 会随旧容器消失。
3. 正确方案是把业务运行日志持久化到宿主机目录，再 bind mount 回容器原路径。
4. 首次上线持久化前，需要先把旧 web/cron 容器里的 runtime/logs 同步到宿主机目录，避免第一次挂载空目录时看不到旧日志。
5. 日志文件经常一直追加，mtime 会持续更新；不要依赖“30 天前文件自动删除”作为主要清理手段。
6. 本次要求不自动删除业务日志。目录超过 2G 时发送 Telegram 普通文本提醒，明确告诉运维到哪台服务器、哪个目录、如何手工排查和清理。

测试环境信息：
- 运维仓库本地路径：<LOCAL_DEV_REPO_PATH>
- 仓库分支：dev
- 测试服务器：root@38.92.8.34
- 服务器运维目录：/opt/docker-youdianse-php
- Web 容器：youdianse-dev-php-web
- Cron 容器：youdianse-dev-php-cron
- Nginx 容器：youdianse-dev-php-nginx
- 容器内业务日志目录：/var/www/html/youdianse-php/runtime/logs
- 宿主机持久化日志目录：/opt/docker-youdianse-php/runtime/app-logs
- 日志告警阈值：2G
- Telegram token/chat_id 来源：服务器本地 cicd-web/runtime/secrets.env 或 cicd-web/config/settings.json；不要打印敏感值。

目标：
1. 新增宿主机持久化日志目录配置：runtime/app-logs。
2. docker-compose.yml 中 web 和 cron 都挂载：
   ./runtime/app-logs:/var/www/html/youdianse-php/runtime/logs
3. 发布流程在重建容器前：
   - 创建宿主机日志目录。
   - 如果旧容器还没有使用该挂载，先 docker cp 旧容器 runtime/logs 到宿主机目录。
   - 如果旧容器已经使用该挂载，跳过重复同步。
   - 统计宿主机日志目录总大小。
   - 大于等于 2G 时发 Telegram 提醒，不自动删除。
4. 配置同步流程 sync-config 也要在重建容器前执行同样的日志准备和大小检查。
5. README 写清楚日志路径、2G 告警和手工清理原则。
6. 提交并推送 dev 分支。
7. 测试服务器拉取 dev 后，多次发布验证日志持久化。
8. 最后发送 Telegram 普通文本总结，并附上本提示词文档。

边界要求：
1. 只操作测试环境，不要改线上 main 分支，不要登录线上服务器。
2. 不要打印服务器密码、SSH key、Telegram token、chat_id、发布密码、私钥。
3. 不要把任何密码、token、chat_id 写进 Git。
4. 不要自动删除业务日志；超过 2G 只发通知，让运维确认后手工清理。
5. 不要改 PHP 版本、业务代码、nginx 配置、env 配置、定时任务边界。
6. 如果服务器工作区有非本次操作产生的改动，先汇报，不要覆盖。

本地确认：
1. 进入运维仓库：
   cd <LOCAL_DEV_REPO_PATH>
2. 确认分支和工作区：
   git status --short --branch
   git branch --show-current
   git rev-parse --short HEAD
3. 搜索现有日志路径和发布流程：
   rg -n "runtime/logs|docker compose|force-recreate|sync_runtime_config|up_services|deploy" -S docker-compose.yml cicd-web entrypoint README.md

本地修改：
1. .gitignore 增加：
   runtime/
2. cicd-web/config/settings.json 增加：
   paths.app_log_dir = "runtime/app-logs"
   defaults.app_log_alert_gb = 2
3. cicd-web/config.py 增加：
   APP_LOG_DIR
   APP_LOG_ALERT_GB
4. docker-compose.yml：
   - web volumes 增加：
     ${YOUDIANSE_APP_LOG_DIR:-./runtime/app-logs}:/var/www/html/youdianse-php/runtime/logs
   - cron volumes 增加同样挂载。
   - environment 可增加：
     APP_LOG_DIR=/var/www/html/youdianse-php/runtime/logs
5. cicd-web/core.py：
   - write_build_env 写入 YOUDIANSE_APP_LOG_DIR。
   - 发布 up_services 前调用日志准备函数。
   - sync_runtime_config_no_build 重建前也调用日志准备函数。
   - 日志准备函数逻辑：
     a. mkdir -p runtime/app-logs
     b. inspect 旧 web/cron 容器挂载，如果旧容器已经挂载 runtime/app-logs，则跳过同步
     c. 否则执行 docker cp <container>:/var/www/html/youdianse-php/runtime/logs/. runtime/app-logs
     d. 统计 runtime/app-logs 总大小
     e. 大于等于 2G 时 send_telegram_immediate 普通文本提醒
6. README：
   - 说明容器内日志路径仍是 /var/www/html/youdianse-php/runtime/logs。
   - 说明宿主机持久目录是 runtime/app-logs。
   - 说明系统不自动删除业务日志。
   - 说明目录大于 2G 时发 Telegram，消息包含服务器、目录和手工清理命令。

Telegram 2G 告警消息必须包含：
1. 标题：业务日志目录过大提醒。
2. 宿主机身份：hostname / public IP。
3. 当前大小。
4. 告警阈值：2G。
5. 宿主机目录：/opt/docker-youdianse-php/runtime/app-logs。
6. 容器内目录：/var/www/html/youdianse-php/runtime/logs。
7. 手工排查命令：
   cd /opt/docker-youdianse-php
   du -sh runtime/app-logs
   find runtime/app-logs -type f -printf '%s %TY-%Tm-%Td %p\n' | sort -nr | head -30
8. 手工清理示例：
   : > runtime/app-logs/queue/watchdog.log
   find runtime/app-logs -type f -name '*.log' -mtime +30 -delete

多轮持久化验证：
1. 连续执行至少 3 轮真实发布。
2. 每轮发布前，在 web 和 cron 容器内同一个日志标记文件写入内容：
   docker exec youdianse-dev-php-web sh -lc 'mkdir -p /var/www/html/youdianse-php/runtime/logs/persist-verify && echo before-web-round-N >> /var/www/html/youdianse-php/runtime/logs/persist-verify/round-N.log'
   docker exec youdianse-dev-php-cron sh -lc 'mkdir -p /var/www/html/youdianse-php/runtime/logs/persist-verify && echo before-cron-round-N >> /var/www/html/youdianse-php/runtime/logs/persist-verify/round-N.log'
3. 执行发布：
   python3 cicd-web.py deploy --git-id <BUSINESS_GIT_SHA> --with-cron
4. 发布后从新容器确认标记仍存在：
   docker exec youdianse-dev-php-web sh -lc 'grep -q before-web-round-N /var/www/html/youdianse-php/runtime/logs/persist-verify/round-N.log'
   docker exec youdianse-dev-php-cron sh -lc 'grep -q before-cron-round-N /var/www/html/youdianse-php/runtime/logs/persist-verify/round-N.log'
5. 确认挂载：
   grep -n "YOUDIANSE_APP_LOG_DIR" .ops-build.env
   du -sh runtime/app-logs
   docker inspect youdianse-dev-php-web --format '{{json .Mounts}}' | grep /opt/docker-youdianse-php/runtime/app-logs
   docker inspect youdianse-dev-php-cron --format '{{json .Mounts}}' | grep /opt/docker-youdianse-php/runtime/app-logs
