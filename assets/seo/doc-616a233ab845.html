时间：2026-09-02 14:53（Asia/Manila） 项目：某业务公司 / PGServer cn（香港入口） 范围：把 client 代码仓库最新 PG 全部静态资源同步到香港 S3（pg/pg3/pg4/pg5/pg6/pg7 六前缀） 执行：Codex（本地工作区 + 巴西宝塔 192.0.2.8 + 香港入口机 192.0.2.14）

背景与目标

用户反馈 pg-static 缺资源，示例：
  https://pg-static.hkcloudplay03.com/85/c445ebb91e.cadb1.json 返回 403。
确认：从代码仓库（client.git master）拉最新全量 PG 静态资源；资源不经过本地电脑中转，
由服务器端完成“仓库 -> 云存储”。

一、前置核验

cn 分支：工作区干净；本地领先 origin/cn 12 个提交（本次继续本地提交、不推送）。
client 仓库 master=1764a68b：
  pgnew 39256 / pg3 7304 / pg4static 21955 / pg5static 6394 /
  pg6static 684 / pg7static 1053，均无 ._/.DS_Store 残留；
  缺失文件 pgnew/85/c445ebb91e.cadb1.json 在仓库中存在。
香港 S3 现状：pg-static 34327 / pg3-static 3463 / pg4-static 21975 /
  pg5-static 6396 / pg6-static 684 / pg7-static 1053。
巴西宝塔 origin 凭据可读 platgames/client.git（只读验证通过）。

二、执行内容（全程服务器间，无本地中转）

1. 巴西宝塔凭据直连仓库，sparse 拉取 master=1764a68b 六个 PG 目录到
   /root/pg-latest-20260902/client（76646 文件约 6.5GB，._/.DS_Store 为 0）。
2. rsync 宝塔 -> 香港机 /root/pg-repo-20260902（分目录、--partial 可断点续传）。
3. 香港机 AWS_PROFILE=bizops-hk aws s3 sync 增量上传（不删除）：
   pgnew -> s3://bizops-h5-hk-517506432530/pg-static/
   pg3 -> pg3-static/；pg4static -> pg4-static/；pg5static -> pg5-static/；
   pg6static -> pg6-static/；pg7static -> pg7-static/。
4. CloudFront 全量失效：E2JLARIGDV5VZV（pg-static）、E1MELSI31IM0FQ（pg3）、
   E310K7HLRALCN8（pg4）、EAUVKSKQC1239（pg5），全部 Completed。
5. 清理两端临时目录（/root/pg-latest-20260902、/root/pg-repo-20260902）。

三、验证结果

缺失文件恢复：https://pg-static.hkcloudplay03.com/85/c445ebb91e.cadb1.json
  原始 URL 200（无需 cache-buster）；S3 直连 200。
内容一致性：抽查 4 个新增文件 S3 ETag 与香港机源 md5 完全一致：
  85/c445ebb91e.cadb1.json = 7f31312cacea23f00e07f7bacc6b949c
  pg3/1950910/index.html   = d63a0e67fba5730ac59c0fe69ae1baf3
  pg4/1804577/index.html   = 48004e80f0cec73bdee223ad264cc16c
  pg5/1850016/index.html   = 12a93811a7b37fddf879fdbc97a5e118
同步后对象数：
  pg-static 39264（仓库 39256，保留历史多余 8 个）
  pg3-static 7314（仓库 7304，保留 10 个）
  pg4-static 21975（仓库 21955，保留 20 个）
  pg5-static 6396（仓库 6394，保留 2 个，已核实为游戏 91 目录与 public-probe 探针）
  pg6-static 684 / pg7-static 1053（与仓库一致）

回滚 / 遗留事项

回滚：本次为增量上传（不删除），如需回滚需按新增对象清单删除；S3 对象级无覆盖回滚能力，
  内容变更需从仓库旧 commit 重新同步。
遗留：
  - 巴西侧 PG 资源同样滞后于仓库（宝塔 pg-static 34323 vs 仓库 pgnew 39256 等），
    巴西 GCS 侧需按相同来源更新（建议走新架构，避免再次大文件落盘）；
  - 用户提出“git -> GCS/S3 直连同步、不落盘服务器”改造诉求，已另立分析（见工作台/最终回复）。
