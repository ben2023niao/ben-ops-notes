一、目标

  1. 搭一套运维入口：堡垒机统一纳管 UAT 服务器，账号集中、操作可审计。
  2. 搭监控：服务器与容器状态可视，异常自动告警到 Telegram。
  3. 域名访问：堡垒机和监控用域名 + HTTPS，不暴露 IP 直连。

二、机器

角色 内网 IP 公网 IP 说明
堡垒机（管理机） 203.0.113.1 43.249.251.15 4C8G，blk-uat-oob，LVM 另有 154G 未分配
中间件节点 203.0.113.1 43.249.251.11 blk-uat，8C32G
Swarm Manager 203.0.113.1 43.249.251.12 blk-uat-mgt
Swarm Worker 203.0.113.1 43.249.251.13 blk-uat-worder01（原文拼写如此）
Swarm Worker 203.0.113.1 43.249.251.14 blk-uat-worder02

系统统一 Ubuntu 24.04，服务目录统一 /opt。

三、做了什么

1. 基础环境（5 台）

  • 装 Docker（官方 apt 源）+ docker compose 插件，开机自启。
  • /etc/docker/daemon.json：日志轮转 100m×3、live-restore: true（业务机另加了内部 Harbor 的 insecure-registries）。
  • 运维账号 blkuat 免密 sudo：/etc/sudoers.d/90-blkuat-nopasswd。

2. 堡垒机（JumpServer）

  • 版本 jumpserver/jms_all:v4.10.19（容器内置 PostgreSQL 17 + Redis）。
  • 目录 /opt/jumpserver：docker-compose.yml + .env（随机密钥）+ data/ + pgdata/。
  • 关键前置：镜像里的 PG 数据目录是初始化好的，必须先把 /var/lib/postgresql 拷进 pgdata/，否则挂空目录启动会报 No PostgreSQL cluster found。
  • 端口：Web 只监听 203.0.113.1:8081（外网走 nginx），资产 SSH 接入 2222。
  • 初始化：运维组/开发组/管理员组；用户 admin、ben、ak、berd、bruce；资产按 角色-公网IP 命名，分 UAT、运维管理 两个节点；每台两个账号（blkuat 登录、root 提权，su_from 指向 blkuat）；授权按组发放（运维组 @ALL、开发组 blkuat）。
  • 提权方式：Linux 平台的 su_method 改成 sudo（默认走 su 会要 root 密码，连接直接 EOF）。
  • MFA：全局 + 每个用户强制 GA（SECURITY_MFA_AUTH 语义：0 不开启 / 1 全员 / 2 仅管理员）。
  • 审计验证：用 ben 账号连 UAT-middleware，选 root 账号，成功拿到 root shell，会话录像与命令记录都能在后台回放。

3. 监控（Beszel）

  • Hub：/opt/beszel，docker run 一行部署，8090 端口，数据在 /opt/beszel/beszel_data。
  • Agent：5 台全部安装，镜像 henrygd/beszel-agent:alpine，用通用 token 自动注册，agent 主动外连 hub，业务机不用开端口。
  • 告警：Shoutrrr Telegram URL，每台默认 4 条规则（离线、CPU>80%、内存>80%、磁盘>80%，各持续 10 分钟）。
  • S.M.A.R.T.：虚拟机是 KVM virtio 磁盘，不暴露 SMART（smartctl --scan 为空），机房确认 HCI 平台已在采集物理盘状态，这块不在虚拟机里做。

4. 域名与反向代理

  • 域名：manage.evercare.id（堡垒机）、beszel.evercare.id（监控），Cloudflare 代理，源站 43.249.251.15。
  • nginx：容器 + network_mode: host，配置在 /opt/nginx/conf.d，反代到本机 8081 / 8090。
  • 证书：Let's Encrypt（certbot webroot），/opt/nginx/renew-cert.sh + /etc/cron.d/certbot-renew 每天 3 点续期。
  • Cloudflare 真实 IP：real_ip_header CF-Connecting-IP + CF 网段，审计日志记录真实来源。
  • 未匹配域名或直接用 IP 访问 → 302 跳到堡垒机域名。

四、踩的坑（都已在手册里）

  1. Docker 源报 NO_PUBKEY：keyring 直接用下载的 .asc，不要 gpg --dearmor。
  2. JumpServer 起不来报 No PostgreSQL cluster found：pgdata 目录没预置（见上文关键前置）。
  3. 连资产提示 No account found：授权里的账号字段要填别名（blkuat / @ALL），写 UUID 会导致 permed_accounts 为空。
  4. 提权报 EOF、目标机日志显示 su 认证失败：平台 su_method 要设成 sudo。
  5. 强制首次改密导致登录 500：v4.10.19 + Python 3.14 的已知问题，不设"首次必须改密"。
  6. 改 MFA 相关配置不生效：设置在进程里有缓存，改完重启容器。
  7. 80 端口冲突：nginx 要占 80，先把 JumpServer 改到 203.0.113.1:8081 再起 nginx。
  8. 证书签发 404：certbot 的 -w 目录必须和 nginx 里 acme-challenge 的 root 一致。
  9. 域名 521：Cloudflare SSL 模式要 Full 或 Full(strict)。
  10. Beszel 告警 webhook 曾经被界面保存操作清空，导致告警发不出来——保存通知设置后要回看一眼并点测试。
