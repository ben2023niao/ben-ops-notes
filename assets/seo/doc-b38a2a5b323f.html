这套东西能不能跑起来，80% 取决于 macOS 的隐私权限（TCC）。 这一节把它讲透，因为踩一次坑能浪费一小时。

1. 需要两个权限

权限 用途 不给会怎样
辅助功能（Accessibility） 遍历 UI 树拿窗口/行矩形、给输入框置焦点 读不到窗口结构，也按不了键
屏幕录制（Screen Recording） ScreenCaptureKit 抓窗口画面 截图成功但是空白图，OCR 什么都认不出来

两个都在：系统设置 → 隐私与安全性。

2. 关键：权限是按"可执行文件"授权的

这是最容易踩的坑。TCC 授权的主体不是"你这个人"，而是发起调用的那个二进制。

  • 你在 VS Code 的终端里跑脚本 → 授权对象是 Visual Studio Code.app （子进程会继承父进程的授权）
  • 你在 macOS 自带的终端 / iTerm 里跑 → 授权对象是那个终端 App
  • launchd 拉起来的进程 → 授权对象是它实际执行的那个二进制

所以会出现这些现象：

  • 你在终端里跑得好好的，配成定时任务就失败
  • 你给 LINE 授过权，但脚本还是读不到东西（那是给 LINE 授权，不是给脚本）

2.1 两条实践建议

做法 A（简单）：给"跑的宿主程序"授权

如果你打算用终端手动跑，就给终端 App 授权， 然后重启那个 App（改完权限不重启不生效）。

做法 B（推荐用于 launchd）：让脚本独立授权

launchd 任务执行的是 .venv/bin/python。这个二进制第一次尝试访问受保护资源时， 前台会话会弹授权框 —— 但 launchd 任务不在前台，弹不出来，于是静默失败。

规避方法：

  1. 先手动跑一次 ./.venv/bin/python punch.py doctor，让授权框正常弹出并点"允许"
  2. 确认 doctor 全绿
  3. 再安装定时任务

macOS 会记住"这个路径的二进制已被授权"，之后 launchd 用同一个路径执行就不会再被拦。

2.2 用 .app 启动器让授权不随 Python 版本失效（已实现）

问题：直接给 .venv/bin/python 授权时，macOS 会把它解析成真实路径再登记：

kTCCServiceScreenCapture | /opt/homebrew/Cellar/python@3.11/3.11.15_4/.../bin/python3.11 | 2
                                                                      ↑ 这里带版本号

brew upgrade python@3.11 一升级，路径就变了 → 授权失效 → 定时任务静默失败。

解法：项目里有 LinePunch.app，定时任务现在走它：

~/line-punch/
├── LinePunch.app/
│   └── Contents/
│       ├── Info.plist              CFBundleIdentifier = com.ben.linepunch
│       └── MacOS/LinePunch         编译出来的 Mach-O 启动器（源码 tools/launcher.swift）
├── .venv/bin/python
└── punch.py

启动器用 execv 把自己替换成 Python，所以 PID 不变、进程身份延续， TCC 认的是 app 的 bundle id：

kTCCServiceAccessibility | com.ben.linepunch | client_type=0 | 2
kTCCServiceScreenCapture | com.ben.linepunch | client_type=0 | 2

client_type=0 就是"按 bundle id"，与 Python 装在哪、什么版本完全无关。

两个实现细节（都是踩出来的）：

  • 主可执行文件必须是编译出来的二进制，不能是 shell 脚本。脚本会被内核通过 shebang 交给 /bin/bash 执行，TCC 就会把权限归到 bash 头上，授权界面里也不出现这个 app。
  • 启动器用 execv 而不是 fork+exec，保证进程身份延续。

授权步骤（只需要点一次）：

open ~/line-punch/LinePunch.app      # 或者直接跑 ./.venv/bin/python punch.py grant

会弹出两个系统对话框，分别允许即可。之后可以在 系统设置 → 隐私与安全性 里看到名为 「LINE 打卡」（LinePunch） 的两个条目。

验证：

./tools/install_agent.sh install --in-window 07:30-08:30 --out-window 20:00-20:50
launchctl kickstart -p gui/$(id -u)/com.ben.linepunch.in
tail -20 logs/latest.log     # 应该看到「确认截图与权限 OK」

3. 部署步骤

3.1 安装依赖

cd "/Users/ben/Desktop/line-自动化打卡上班下班"
python3.11 -m venv .venv
./.venv/bin/pip install -r requirements.txt

requirements.txt 里只有 PyObjC 系列（macOS 系统框架的 Python 绑定）， 没有第三方网络库 —— Telegram 汇报是直接用标准库 urllib 打的。

3.2 授权

./.venv/bin/python punch.py doctor

如果出现 ❌，按提示去系统设置里勾选，然后重启运行它的那个程序，再跑一次 doctor。

3.3 确认能读到 LINE

./.venv/bin/python punch.py status

应该能看到当前会话的标题和最近几条消息。 如果标题是空的或者乱码，基本可以断定是屏幕录制权限没给。

3.4 空跑验证

./.venv/bin/python punch.py type 下班打卡 --keep-focus

看到「下班打卡」出现在 LINE 的输入框里、且没有被发出去，说明链路是通的。

建议连续验证 3–5 次（不同时间、不同会话状态下），确认"目标校验"每次都命中， 再考虑开启真实发送。

3.5 开启真实发送

编辑 config.toml：

[behavior]
allow_send = true

然后：

./.venv/bin/python punch.py send --out --yes

4. 配成定时任务（launchd）

4.1 一键安装

./tools/install_agent.sh install --in 08:55 --out 18:05 --weekdays 1,2,3,4,5

它会在 ~/Library/LaunchAgents/ 下生成两个任务，并立即加载：

  • com.ben.linepunch.in.plist —— 上班打卡
  • com.ben.linepunch.out.plist —— 下班打卡
./tools/install_agent.sh status      # 看是否加载
./tools/install_agent.sh uninstall   # 卸载

4.2 为什么必须挂到 gui 域

launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.ben.linepunch.in.plist

gui/<uid> 表示"这个用户的图形会话"。只有挂在图形会话里的进程才能连上 WindowServer， 才能截图、才能操作窗口。挂到 user/<uid> 域的话进程能跑起来，但看不到任何窗口。

tools/install_agent.sh 已经处理好了这一点。

4.3 几个必须知道的行为

Mac 睡着时会补跑。 StartCalendarInterval 的语义是：到点了机器没醒， 醒来后会补执行一次。如果不希望补跑（比如 8:55 的上班卡 11 点才补发）， 得自己加判断逻辑，或者把任务时间设在机器通常醒着的时候。

改完 plist 要重新加载：

launchctl bootout gui/$(id -u)/com.ben.linepunch.in 2>/dev/null
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.ben.linepunch.in.plist

直接用 install_agent.sh install 重装也行，它会先 bootout 再 bootstrap。

手动触发一次（不用等到点）：

launchctl kickstart -p gui/$(id -u)/com.ben.linepunch.out

看 launchd 自己的输出：

tail -f logs/launchd-out.out.log logs/launchd-out.err.log

注意这两个文件里只有脚本的 stdout/stderr。 真正详细的日志还是在 logs/run-*.log。

4.4 定时任务上线第一天一定要看日志

tail -f logs/latest.log

重点看两件事：

  1. 「校验目标会话」这一步是不是 OK，header 字段里是不是真的抓到了「打卡」
  2. 有没有 Telegram 汇报失败 之类的 WARNING

5. 安全建议

  • config.toml 里有机器人 token，已经 chmod 600 并写进 .gitignore， 不要提交到任何仓库，也不要发到群里
  • 更稳妥的做法是把 token 放环境变量，配置文件里留空：

bash export [敏感内容已脱敏]

配置文件里对应的值会被环境变量覆盖 * logs/ 和 shots/ 里包含你的群名、消息片段和屏幕截图。 默认 30 天自动清理，机器要给别人之前记得先清空这两个目录 * 机器人 token 如果泄露过，去 BotFather 用 /revoke 换一个新的

6. 项目不能放在 ~/Desktop（launchd 必踩）

这一条会直接让定时任务跑不起来，而且报错很不直观。

现象： launchd 任务完全不产生 logs/run-*.log，只有：

/bin/bash: /Users/ben/Desktop/line-自动化打卡上班下班/tools/run_punch.sh: Operation not permitted

原因： ~/Desktop、~/Documents、~/Downloads 是 macOS 的 TCC 保护目录。 launchd 拉起的进程不属于任何获得授权的 App，对这些目录没有任何访问权， 连脚本文件都读不到。

实测（在 launchd 上下文里跑）：

ls ~/Desktop        → Operation not permitted   ❌
ls ~/Documents      → Operation not permitted   ❌
cat ~/.somefile     → 正常读到                   ✅

解决：把项目移到 Home 根目录下。 这是最简单的做法，不需要额外授权：

mv "~/Desktop/line-自动化打卡上班下班" ~/line-punch
ln -s ~/line-punch "~/Desktop/line-自动化打卡上班下班"   # 桌面留个入口，访问方式不变
cd ~/line-punch
./.venv/bin/python punch.py doctor

tools/install_agent.sh 会检测这种情况并直接拒绝安装，同时把这段命令打出来。

另一条路（不推荐）： 给执行任务的 Python 解释器授予「完全磁盘访问权限」。 代价是那个解释器跑的所有脚本都拿到全盘权限，范围太大。 而且 .venv/bin/python 是指向 Homebrew Python 的符号链接，授权对象容易搞错。

7. 想更彻底地隔离

如果不希望打卡时抢占你的焦点，可以在同一台 Mac 上再建一个 macOS 用户：

  1. 新建用户（例如 linepunch），设置自动登录
  2. 在新用户里登录 LINE、把本项目复制过去、跑一次 doctor 完成授权
  3. 在新用户里安装 launchd 任务

这样打卡全程发生在另一个图形会话里，你的主账号完全不受影响，代码一行都不用改。

代价是那个用户会话必须处于活动状态（也就是这台 Mac 得开着，并且切换到那个用户， 或者用自动登录让它常驻）。
