2026-09-02 17:55 补充：显式化后实测仅 01 可用、02-05 失败，根因是 CloudFront 缓存键不含 Origin 导致串源；最终将 17 个静态分配缓存策略改为 Managed-CachingDisabled（逐请求回源），详见 2026-09-02-1755-【网络调整】香港静态域名CORS按Origin回显修复记录.md。

一、需求

1. 静态域名跨域不能使用 *，要按具体页面域名显式放行（游戏客户端严格解析 ACAO）；
2. 只处理静态，动态接口不动；
3. 动态接口 CORS 由后端服务代码处理，运维此前在 nginx 覆盖的需还原。

二、允许 Origin 清单（用户确认，43 项，无通配）

- 大厅/H5：https://ind-h5.dbqpplus999.com
- 游戏页：pg/pp/ppk/panda/jili/playson/g759 的
  https://<vendor>-games.hkcloudplay01.com ~ ...05.com（7×5=35）
- 固定 API 前端：https://api.hkcloudplay01.com ~ ...05.com（5）
- 核心前端：https://api.hkplaycore.com、https://games.hkplaycore.com

三、执行内容

1. 动态接口 CORS 还原（先做）

根因：nginx 代理片段 dbqp-hongkong-proxy.conf 自提交 1cc458b7 起“统一覆盖上游 CORS、
直接响应 OPTIONS”（ACAO:*），与“动态由后端处理”冲突。
修复：移除片段内 OPTIONS 直答与 add_header/proxy_hide_header 覆盖，改为纯透传；
备份 /root/dbqp-hk-cors-20260902/dynamic-revert-backup-*.conf；
nginx -t 通过并 reload。
验证：api.hkplaycore.com / pg-games.hkcloudplay01.com 响应改为后端返回
  ACAO=https://ind-h5.dbqpplus999.com（精确）、allow-credentials=true、
  methods/headers 由后端定义；OPTIONS 204 由后端应答。

2. S3 桶 CORS 显式化

工具：docker/deploy/hongkong/configure_s3_bucket_cors.py（已部署 /opt/dbqp-hk-ops）
桶：dbqp-h5-hk-517506432530
规则：AllowedOrigins = 43 项显式（原 *），AllowedMethods GET/HEAD，
  AllowedHeaders *，ExposeHeaders 原样，MaxAge 3600。

3. CloudFront 静态分配策略

问题：17 个静态分配挂 Managed-CORS-With-Preflight（Origins=*），若保留会在
S3 未放行时重新加回 ACAO:*；IAM（dbqp-hk-nginx-ai）无 CreateResponseHeadersPolicy
权限，无法建自定义策略。
方案：移除托管 CORS 响应头策略（ResponseHeadersPolicyId=""），保留
CORS-CustomOrigin OriginRequestPolicy（88a5eaf4…）转发预检头；
S3 显式 CORS 成为唯一来源（S3 直连与 CloudFront 路径一致）。
工具：docker/deploy/hongkong/configure_cloudfront_static_cors.py（已更新部署）
对 17 个静态分配提交 /* 全量失效清旧缓存（9/2 09:32-09:33 UTC）。

4. nginx 静态兜底显式化

docker/deploy/hongkong/nginx-dbqp.conf：
新增 map $http_origin $dbqp_static_cors_origin（43 项精确正则，default ""）；
pp-static 特殊块与合并静态块所有 ACAO 由 "*" 改为 $dbqp_static_cors_origin；
备份 /root/dbqp-hk-cors-20260902/nginx-backup-*；nginx -t 通过并 reload。

5. 验证脚本更新

validate_cloudfront_static.py：CORS 断言由 cors == "*" 改为
cors == EXPECTED_CORS_ORIGIN（https://ind-h5.dbqpplus999.com）。

四、验证结果

1. GET：70 静态域名（14 前缀×5）带允许 Origin（ind-h5）ACAO 精确回显 70/70；
2. 允许的游戏 Origin 抽样（pg/pp/panda-games.hkcloudplay01-05）逐域精确回显；
3. 非法 Origin（evil.example.com）：GET 无 ACAO、OPTIONS 403 拦截（S3/CF 一致）；
4. S3 直连：允许 Origin 200+精确回显；非法 Origin 无 ACAO；
5. OPTIONS 预检：允许 Origin 200+精确回显（缓存失效后 Miss 复测通过）；
6. 动态：api/pg-games 保持后端 CORS 透传，未覆盖；
7. 真实静态文件 200 无回归。

回滚 / 遗留

回滚：
  - S3：put-bucket-cors 恢复 AllowedOrigins ["*"]（configure_s3_bucket_cors.py 改回即可）；
  - CloudFront：静态分配 ResponseHeadersPolicyId 恢复 5cc3b908（Managed-CORS-With-Preflight）；
  - nginx：恢复 dbqp-hongkong-proxy.conf CORS 覆盖块 / 静态 ACAO "*"（备份在
    /root/dbqp-hk-cors-20260902/）；
  - 静态策略移除后如需 CF 层补充 CORS，需先给 IAM 增加 CreateResponseHeadersPolicy 权限。
遗留：非法/未列入 Origin 的浏览器访问将无 CORS（预期）；如后续新增门户域名，需同步加入
  S3 桶规则、nginx map 与 validate 预期清单。
