背景

后端反馈测试环境已新增 Vesper 提供的 CDN 专用配置，要求发布并验证。

用户边界：

CDN 配置值不发群/不写入文档，相关字段只核验存在与生效状态。

配置与代码

运维仓库 origin/dev=9da1850
env/.env.dev [aws] 新增字段（名称）：
  AWS_CDN_ACCESS_KEY
  AWS_CDN_KEY_ID
  AWS_CDN_REGION

业务代码 origin/dev=90c985bc
DomainPublishService 已改为使用 AWS_CDN_* 专用凭据创建 CloudFrontClient，
不再混用 S3 上传凭据；CloudFront 区域固定使用 AWS_CDN_REGION（默认 us-east-1）。

操作记录

  1. 本地/远端核对：
本地 worktree clean；origin/dev 新增 3b91b9a/9da1850；
merge 后本地 env/.env.dev 已含 CDN 字段名。
  1. live env 增量合入：
live origin/dev fetch 到 9da1850；
env 备份后仅写入 AWS_CDN_* 三个字段（各 1 处、与远端一致，值不输出）；
保留本地维护段 spj2/trtc 与 7 处 203.0.113.1 host。
  1. 发布业务代码：
触发 CICD Webhook 自动发布；
第一次发布业务 90c985bc 成功，HTTP 200，
但健康检查 Redis/Mongo 落到 203.0.113.1（告警）。
  1. 健康检查根因与修复：
根因：env [aws] AWS_DOMAIN_ENCRYPT_KEY 的值尾部含 "=" 且未加引号，
      CICD 健康检查使用 PHP parse_ini_file 时整文件解析中断，
      redis/database.mongodb.default 读不到 host，回退 203.0.113.1。
修复：将该值改为标准 INI 引号形式（PHP/Phalcon 均验证值不变）。
  1. CDN 验证：
使用新 CDN 专用配置执行无害路径失效探测：成功（Invalidation InProgress）。
  1. 重发全绿：
再次触发 CICD 发布：
业务 git id=90c985bc
HTTP=200
Redis=203.0.113.1:6379 open
MongoDB=203.0.113.1:27017 open
综合结论=SUCCESS
容器 web/nginx/cron Up；admin/cicd/h5 HTTP 200。

结果

Vesper CDN 配置已在测试环境生效；
后端可继续执行域名推送并应得到 cdn_status=1；
值未在群内/文档中展开。
