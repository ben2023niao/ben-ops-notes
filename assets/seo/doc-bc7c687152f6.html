1. 背景

用户反馈 /start 主页没有出现 version.json / server_configs 两个热更新按钮，随后补充最新要求：不要两个按钮，合并成 1 个按钮，一次选择 Git 版本后同时更新这两个文件。

本次继续使用 workbench，并读取/承接前置文档：

  • docker/doc/2026-08-06-1505-【优化】端口一一对应与运行配置热更新按钮改造记录.md
  • docker/doc/2026-08-06-1450-【补静态资源+数据维护】巴西PLAYSON与PG资源同步记录.md
  • docker/doc/2026-08-06-1142-【补静态资源+数据维护】香港PLAYSON与PG资源同步记录.md
  • docker/doc/【运维记录】DBQP运维AI交接总览.md

2. 排查结论

线上 /start 未出现按钮的原因：

  • 宝塔 /opt/pgserver 当时仍是旧代码。
  • dbqp-ben-bot 容器内 /app/app/benbot/home.py 属于镜像内应用代码，不是 /app/data/scripts 挂载目录。
  • 之前仓库侧已改好按钮，但线上机器人容器未重建/重载，所以用户看到的还是旧主页。

3. 本次改造

3.1 主页合并按钮

文件：

  • docker/ben-bot/app/benbot/home.py

结果：

  • /start 首页新增 1 个合并按钮：
热更新 version.json + server_configs
  • 该按钮单独占一行。
  • callback：
plugin:<同步维护节点>:ver:hc:runtime-configs

3.2 同步维护动作

文件：

  • docker/ben-bot/data/scripts/.dbqp_common/action_runtime.py
  • docker/ben-bot/data/scripts/同步维护/action.py
  • docker/ben-bot/data/scripts/同步维护/run.py
  • docker/scripts/hot_update_runtime_config.py

结果：

  • 新增动作短码：hc -> hot-configs。
  • 点击合并按钮后进入 Git 版本选择页。
  • 确认后执行：
同步维护/run.py hot-configs <version>
  • hot-configs 会顺序执行：
hot_update_runtime_config.py version.json <version>
hot_update_runtime_config.py server_configs <version>
  • 仍然保留文件白名单，只允许更新 version.json 和 server_configs。
  • 正式执行仍然是 docker cp 到所有目标运行容器 /app/<filename>，并在容器内校验 SHA256 和 test -f。

4. 线上处理

本次只处理机器人自身：

  • 同步必要文件到宝塔 /opt/pgserver。
  • docker cp 新版 home.py 到 dbqp-ben-bot:/app/app/benbot/home.py。
  • 仅重启 dbqp-ben-bot，让 Python 进程重新加载主页代码。

未执行：

  • 未重启 PG/TADA/PP/PPK/PLAYSON/PANDA/platform-api 业务容器。
  • 未覆盖线上业务容器中的 /app/version.json 或 /app/server_configs。
  • 未修改线上 Nginx 或防火墙。

5. 验证

5.1 本地验证

python3 docker/ben-bot/data/scripts/同步维护/run.py hot-configs HEAD --dry-run --no-fetch
python3 docker/ci/check.py

结果：

  • 本地 /start 渲染仅 1 个热更新按钮。
  • 版本选择 callback 最大长度 56，低于 Telegram 64 字节限制。
  • hot-configs dry-run 顺序跑通 version.json 与 server_configs。
  • docker/ci/check.py 通过。

5.2 线上机器人渲染验证

容器：dbqp-ben-bot

渲染结果包含且仅包含 1 个热更新按钮：

7. 当前结论

dbqp-ben-bot 首页现在应显示 1 个合并按钮：

热更新 version.json + server_configs

使用方式：

  1. 群里发送 /start。
  2. 点击 热更新 version.json + server_configs。
  3. 选择 latest 或最近 Git 短 ID。
  4. 确认执行后，机器人会把该 Git 版本里的 version.json 和 server_configs 顺序更新到全部目标运行容器。

执行该按钮时不重打业务镜像、不重启业务容器。
