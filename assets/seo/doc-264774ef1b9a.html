任务边界

用户要求：

更新 cn 分支的静态资源代码；
client 仓库中两个文件夹（jilistatic / jilistatic1）更新到香港；
按固定流程：检查仓库状态与最新提交 -> 读取 doc/workbench -> 每步发群通知 -> 验证 -> 更新文档 -> 汇总发群 -> 本地提交（不 Push）。

一、前置情况

本地 cn：5c3b3de6，工作区干净，与 origin/cn 一致（未做任何 Push，符合要求）。
client 仓库 master 今日（2026-08-19）新提交：
  527f88b44 jilistatic（整目录替换，29,350 文件 / 2.9GB）
  8e6017ff8 jilistatic1（整目录替换，5,839 文件 / 1.1GB）
香港映射（已核验 CloudFront OriginPath）：
  jilistatic  -> S3 tada-statics（jili-static.hkcloudplay01-05.com 源）
  jilistatic1 -> S3 tada-statics1（jili-static1.hkcloudplay01-05.com 源）

二、执行

1. 稀疏检出 client master 的 jilistatic / jilistatic1 两个目录。
2. 本地 md5 与 S3 ETag 全量比对：
   - tada-statics：16,648 个文件有差异（约 1.12GB），其中 15,613 个为 S3 新对象；
   - tada-statics1：3,695 个文件有差异（约 756MB），其中 3,631 个为 S3 新对象。
3. 仅打包差异文件（20,343 个 / 1.8GB）-> scp 香港机 -> 解包到 /root/jili-update-stage/。
4. AWS_PROFILE=dbqp-hk aws s3 sync 增量上传（未使用 --delete，未删除任何现有对象）。
5. 发现并修复：macOS bsdtar 打包带入约 4.9 万个 ._ AppleDouble 残留对象，
   使用 aws s3 rm --recursive --exclude "*" --include "*/._*" --include "._*" 全部清理；
   清理后对象数与预期一致（tada-statics=33,132、tada-statics1=6,267，._ 残留=0）。
6. CloudFront invalidation（均 Completed）：
   - jili-static E2KICAEYOWJ24E：I9Z0V4H8PIC5WJHPKTUYQ78COZ
   - jili-static1 EIKLXE4BT0I05：I9VN2UZ6SHUV749KE9XS6ASOLT
