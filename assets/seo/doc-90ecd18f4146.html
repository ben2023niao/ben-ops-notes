四、根因：prod-02 的 pg 容器消失了

排查时状态：prod-02（192.0.2.1）上 8 个业务容器里**唯独没有 game-service-pg-prod**
  （api / vendor_b / pp / ppk / vendor_d / vendor_c / g759 / vendor_a_ws 都在）
  docker inspect game-service-pg-prod -> No such container
影响：standby 的 pg upstream 是「192.0.2.1:9091 + 192.0.2.1:9091」双后端，
  其中一半不可用时，nginx 先把请求投给它 -> connect failed -> 再 failover 到 prod-01。
  表现为：pg 游戏偶发变慢/失败（玩家侧「进不去」），error.log 里 5,230 次连接失败；
  access.log 里 pg-games.06 的 502/504 也是这段时间最多。
备注：容器带 restart=always/unless-stopped，若仅崩溃会自愈；本次是**容器本身不存在**，
  没有自愈路径 —— 需要人工重新拉起。

六、「域名这块有没有办法查日志」

1) 现状：域名层（Cloudflare 边缘）日志/分析当前取不到——
   GraphQL Analytics 返回：
     Actor ... does not have permission 'com.cloudflare.api.account.zone.analytics.read'
   即现有 token 缺 Zone Analytics:Read；Logpush 在免费版不可用。
2) 可用方案（任选）：
   a) 给 Cloudflare token 补 Zone Analytics:Read，即可用 GraphQL Analytics 查
      任意 zone 的按小时请求量、状态码分布、国家分布（本侧可写成脚本定期导出）；
   b) 面板 Cloudflare -> 该 zone -> 分析 手动查看（无需 API）；
   c) 需要逐条请求日志则要开 Logpush（付费档位）。
3) 当前替代口径：我们自己的香港入口 nginx 有**全量转发日志**
   （/var/log/nginx/access.log + 轮转 access.log.1），域名、状态码、耗时、客户端 IP 都能查，
   本轮故障就是靠它 + error.log 定位的。

七、遗留与建议

1. prod-02 的 pg 容器为何消失仍未知（本侧未删除；容器 restart 策略无法覆盖「容器不存在」）——
   建议后续在入口机加一条「关键容器存在性巡检」（缺失即告警 + 自动拉起）。
2. 8765（vendor_a ws / vendor_b 复用）目前仍只在 prod-02，prod-01 未监听 -> ws 单点。
3. vendor_b-static.hkcloudplay06.com 仍是 403（zone Cache Rules 缓存的旧错误），需 purge。
4. 静态资源 25/26 正常（lib 及商家桶均已公开读）。
