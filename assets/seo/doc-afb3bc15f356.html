排错顺序永远是：先跑 doctor，再看 logs/run-*.log，再看 shots/<run_id>/*.png。

./.venv/bin/python punch.py doctor
./.venv/bin/python punch.py logs --tail 100
open shots/$(ls -t shots | head -1)      # 打开最近一次运行的截图目录

1. 启动阶段

ModuleNotFoundError: No module named 'Quartz'

用了系统 python3。

./.venv/bin/python punch.py doctor

如果 .venv 不存在：

python3.11 -m venv .venv
./.venv/bin/pip install -r requirements.txt

Assertion failed: (did_initialize), function CGS_REQUIRE_INIT

自己写脚本时容易遇到：调用 ScreenCaptureKit 之前没有初始化 CoreGraphics 连接。 本项目里已经在 macos_shot.ensure_nsapp() 处理了 （NSApplication.sharedApplication() + 设置成 Prohibited，保证不会抢焦点）。

截图成功，但 OCR 一个字符都认不出来

最常见的原因是没有屏幕录制权限，拿到的是全白或全黑图。

验证方法：

open shots/$(ls -t shots | head -1)

如果图是空白 → 去系统设置授权屏幕录制，然后重启运行它的程序。

2. LINE 相关

退出码 11：没找到 LINE 进程

  • LINE 没开
  • 或者 line.bundle_id 不对（正常是 jp.naver.line.mac）

退出码 12：拿不到 LINE 主窗口

LINE 收在菜单栏没开窗口。点一下 Dock 图标把窗口调出来。 （LINE 关闭窗口后进程还在，只是没有窗口。）

退出码 13：窗口布局不对

LAYOUT: LINE 窗口太窄，右侧聊天面板没有渲染

LINE 在窗口偏窄时会显示"展开此窗口可在右侧显示聊天"，此时右侧根本没有控件。

两种解法：

  1. 手动把 LINE 窗口拉宽
  2. 打开自动拉宽（不抢焦点）：

toml [behavior] auto_expand_window = true

退出码 14：目标会话不匹配（重要）

日志长这样：

目标校验：期望包含 '打卡'，实际标题 'LINE 官方账号' -> 不通过
运行结束  状态=aborted

这是保护机制生效了，不是 bug。 它拦下了"把打卡消息发到错误的会话"这件事。

处理：

  1. 看 shots/<run_id>/01-header.png，确认脚本看到的画面和你看到的一致
  2. 在 LINE 里把「打卡」群打开
  3. 如果群名确实不是「打卡」，改 config.toml 里的 line.group_name

输入框内容为空 / 和期望不一致

日志里会有：

输入框复核：写入 '下班打卡'，读回 ''

可能原因：

  1. 环境不认 CGEventPostToPid。 这是最可能的原因。脚本会自动激活 LINE 重试一次， 如果还是不行，把配置打开走老路：

脚本默认是 input_mode = "auto"：先按老方式（事件流）试一次， 没进输入框就自动换 PostToPid 兜底，日志里会写明哪一次命中：

输入方式 [事件流] 没进输入框（读回 ''），换 PostToPid 重试 输入方式 [PostToPid] 命中

如果两种都不行，把 behavior.step_settle_ms 调大（例如 800）再试。 2. 输入框里本来就有草稿。 脚本会因此中止并提示，加 --clear-first 清空后重试。 3. 有输入法（IME）在中间截胡。脚本用的是 Unicode 键盘事件，理论上绕开输入法， 但如果输入法处于"候选窗打开"状态会吃掉按键。手动按一下 Esc 再跑。 4. 搜索框里残留了关键字，把聊天列表过滤成了搜索结果，导致"找不到目标群"。 脚本读列表之前会自动清空搜索框，日志里会有一条 WARNING 说明它清掉了什么。

找不到目标群 / 标题校验不通过

先看日志里这两行：

目标校验：期望 '打卡'，标题 '...' → 解析出 '...'；<不通过的原因>
聊天列表里没有找到 '打卡'，列表实际内容：[...]

标题匹配的规则（strict_title_match = true）是：先切掉成员数角标 (5)， 再要求等于群名。所以：

  • 打卡（5） 4心 → 解析出 打卡 → 通过（4心 是标题图标的 OCR 噪声，被角标规则一起切掉了）
  • 打卡2（5） → 解析出 打卡2 → 不通过
  • 打卡群（5） → 解析出 打卡群 → 不通过

如果确实需要放宽（比如群名和 OCR 结果总差一点），可以关掉严格模式， 它会退化成"前缀 + 词边界"匹配 —— 仍然拒绝 打卡2 / 打卡群：

[behavior]
strict_title_match = false

消息发出去了，但发送后复核失败

复核靠的是"OCR 消息流里能不能看到刚发的内容"。失败可能只是 OCR 没认准， 不一定是真的没发出去。

先去 LINE 里人工看一眼。 然后看 shots/<run_id>/ 最后一张图。

如果确实发出去了但经常误报，可以把复核关掉：

[behavior]
verify_after_send = false

（不建议关；关了以后发送失败就完全静默了。）

3. 定时任务

手动能跑，launchd 跑不起来

99% 是 TCC 权限问题。launchd 进程不在前台，弹不出授权框，只会静默失败。

处理步骤：

  1. 手动跑一次 ./.venv/bin/python punch.py doctor 并点掉授权框
  2. ./tools/install_agent.sh uninstall 再 install
  3. 用 launchctl kickstart -p gui/$(id -u)/com.ben.linepunch.out 立刻触发一次
  4. 看 logs/run-*.log

如果还是不行，说明授权挂在了别的二进制上（比如你是从 VS Code 跑的）。 这种情况建议按 03-权限与部署.md 第 2.2 节打包成 .app。

到点了但什么都没发生

launchctl list | grep linepunch       # 确认加载了
cat logs/launchd-out.err.log          # 看 launchd 捕获的 stderr
ls -lt logs/run-* | head              # 看有没有产生新的运行日志

如果完全没产生 run-*.log，说明脚本压根没启动起来，问题在 launchd 那一层 （plist 路径、gui/ 域、PATH）。

时间不对 / 补跑了

StartCalendarInterval 用的是系统本地时间。如果你改了时区， 或者 Mac 在到点时处于睡眠状态，行为会和预期不同（睡眠会在唤醒后补跑）。

4. Telegram 汇报

完全收不到消息

./.venv/bin/python punch.py notify-test
  • 报 未配置 bot_token → config.toml 里没填
  • 报 401 → token 不对
  • 报 400 chat not found → chat_id 不对， 或者你还没在 Telegram 里给这个机器人发过 /start（机器人不能主动给没交互过的用户发消息）

文字消息能收到，日志附件收不到

日志里会写：

Telegram 日志附件已发送：run-....log

或

WARNING  Telegram 附件发送失败：URLError: <urlopen error [Errno 54] Connection reset by peer>

后者是网络问题（挂 VPN / 代理时常见）。上传比发文字更容易被重置。 已经做了 2 次重试；如果经常失败，可以关掉附件：

[telegram]
attach_log = false

或者只对长时间运行才发附件：

attach_log_min_seconds = 10

汇报很慢（每次调用几十秒）

现象：日志里 机器人身份：@xxx 要等 30–40 秒才出现，整个运行被拖到几分钟。

原因：这台机器挂了 VPN（看 api.telegram.org 的 IPv6 路由是不是黑洞）。 curl 有 Happy Eyeballs，IPv6 不通会立刻回落到 IPv4；Python 的 urllib 没有， 于是会一直等到超时。

本项目默认已经开启 IPv4 优先：

[telegram]
force_ipv4 = true

打开后每次调用应该在 1–2 秒。如果反而报连接失败（极少数只开 IPv6 的网络）， 把它改成 false。

收到了，但状态是 failure

以 logs/run-*.log 里的记载为准，Telegram 上只是摘要。 汇报文本里的 run_id 就是用来对应日志文件的。

5. 快速自查清单

上线之前过一遍：

  • [ ] punch.py doctor 全绿
  • [ ] punch.py status 能正确读出会话标题
  • [ ] punch.py type 空跑 3 次以上，每次「校验目标会话」都 OK
  • [ ] punch.py notify-test 能收到消息
  • [ ] config.toml 里 group_name 和 LINE 里的群名完全一致（含空格/括号）
  • [ ] logs/ 能正常写入（有 run-*.log 在生成）
  • [ ] 定时任务的执行时间点，机器通常是醒着的
