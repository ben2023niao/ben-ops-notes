状态：发布页批次逻辑完成，Chrome 渲染与防误操作验证通过。

一、开始前基线

本地 ops master：3b4c86b4
本地领先 origin/master：3 个提交
工作区：干净

二、目标

  1. 巴西：01 先发，确认正常后 02、04、05 一起进入同一批量步骤。
  2. 香港：01 先发，确认正常后当前 02 进入批量步骤；未来 03、04、05 自动并入同组。
  3. 任何时刻都保留服务器承接 Nginx 流量。
  4. 不能绕过 01 直接发布批量组，也不能在批量组完成前发“可以测试”。

三、实现

新增 BACKEND_TARGETS：

巴西
  01 canary = 34.39.183.154
  bulk = 02/04/05

香港
  01 canary = 34.92.83.132
  bulk = 02
  后续 03/04/05 追加到同一 bulk 数组

新增 bulkReleaseCmd(region)：

  • 将每个批量节点的完整发布命令拼成一个可复制批次。
  • 外层启用 set -e，任一主机失败后停止后续主机。
  • 巴西按 02 → 04 → 05 顺序执行。
  • 香港按当前 bulk 数组顺序执行，未来增加编号无需改页面布局。

四、前端门禁

巴西 01 未确认：不能提交巴西批量组
香港 01 未确认：不能提交香港批量组
巴西批量组未完成：不能发巴西“可以测试”
香港批量组未完成：不能发香港“可以测试”

这样不会出现所有承流节点同时重启或 01 未稳定就继续批量发布。

五、页面变化

  • 巴西 02 卡片改为“巴西 02/04/05 同组发布”。
  • 香港 02 卡片改为“香港 02 起同组发布”，并注明未来 03/04/05 自动并入。
  • 验证步骤动态列出全部已配置节点。
  • 顶部状态和页脚更新至 2026-10-29。

六、验证

HTML 解析：通过
Chrome 实际渲染：通过
巴西批量命令：包含 02、04、05，按顺序且外层 set -e
香港批量命令：当前包含 02，数组可扩展
未确认巴西 01 时点批量：提示“请先完成并确认巴西 01”
未确认香港 01 时点批量：提示“请先完成并确认香港 01”

本轮只修改发布页和文档，未修改服务器、容器、Nginx、DNS、CDN 或业务数据。
