1. 现象

  • 2026-09-02 07:03 与 11:03（北京时间）数据汇报bot 在群里发送“游点涩测试健康 异常”：
  • 磁盘 根盘65.7% 数据盘65.7%；CPU/内存/负载正常；
  • 容器列表为老宝塔容器名（youdianse_test-beszel-agent 等）；
  • 数据库 Mongo主 / Mongo从1 / Mongo从2 / Redis 全部“断”。
  • 实际新库 15.152.6.51（单节点 Mongo + Redis）正常，业务无影响；Kermit 判断“数据库没问题，估计是机器人的问题”，方向正确。

2. 根因

  • 测试环境健康监控仍是迁移前的老部署，运行在老宝塔 38.92.8.34（容器清单、磁盘 65.7%、旧库主/从/从拓扑唯一匹配）。
  • 其数据库 TCP 检查仍指向已停止的旧库 103.207.68.124（Mongo 主/从1/从2 + Redis），因此误报“全断”；监控对象也还是旧机器（jett 的疑问“监控的服务器是不是还是之前的”确认成立）。
  • 新环境 15.152.247.196 已核实：无健康脚本、无 /etc/youdianse-health-alert.json、无 health cron——监控尚未迁移。

3. 处理

把测试健康监控迁移部署到新测试环境：

3.1 部署（15.152.247.196，ec2-user + sudo）

  • 采集脚本：/usr/local/sbin/youdianse-server-health-alert.py（源码 docker-youdianse-php/ops/test/scripts/youdianse-server-health-alert.py）。
  • 小时汇总：/usr/local/sbin/youdianse-health-hourly-summary.py（源码 docker-youdianse-php/ops/test/scripts/youdianse-health-hourly-summary.py；单机采集，无需 SSH 跳板）。
  • 配置：/etc/youdianse-health-alert.json（0600）：
  • 阈值：磁盘 80% / 内存 70% / CPU 80% / 负载 200%（沿用测试口径）；
  • network_checks：Mongo 203.0.113.1:27017、Redis 203.0.113.1:6379（新库内网，单节点，去掉 从1/从2）；
  • Telegram：bot token 取自 ben-bot 容器环境（运行态，不入 Git），chat_id=-4929911895（18game运维）；
  • mentions：@Ben_Bird @jett_yunwei @Kermit0824 @melo_sre @Daviea2。
  • crontab（root，带 BEGIN/END 标记；原 crontab 已备份 /root/crontab.backup.before_healthmon_20260902.txt）：
  • */5 * * * * 采集；
  • 3 * * * * 小时汇总（与旧版同一分钟，延续习惯）。

3.2 顺带修复

  • 采集脚本 docker stats 输出原截断 1200 字符，导致容器清单只显示 5/7、漏报 logbus-v2 与 beszel-agent；测试版副本改为 6000 字符上限。

5. 旧宝塔误报源停用（2026-09-02 14:28 已完成，阻塞项解除）

  • 通道：本仓库无宝塔 SSH 密钥，改经 Spug 主机 103.207.68.124（仓库密钥可登）读取 Spug hosts(id=2) 存储的执行凭据，登入老宝塔 38.92.8.34（root）；密钥只在 Spug 机上临时落盘（600），用后即删，未入 Git/文档/群。
  • 现场只读核验：旧 health cron 带 BEGIN/END 标记；/etc/youdianse-health-alert.json chat=-5039045344，Mongo主/从1/从2/Redis 均指向已停止旧库 103.207.68.124 —— 误报实锤。
  • 已执行：
  • crontab 备份：/root/crontab.backup.before_disable_healthmon_20260902.txt；
  • 删除 YOUDIANSE_HEALTH_ALERT 与 YOUDIANSE_HEALTH_SUMMARY 两段 cron；
  • 保留无关任务（app-log-hourly-rotate）。
  • 核验：老宝塔 /var/spool/cron/crontabs/ 仅 root 有 crontab，health 条目 0 残留；无 health 进程运行。
  • 效果：15:03 起不再收到“数据库全断”误报；新环境监控（15.152.247.196）正常时静默、异常才报。
  • 回滚：如需恢复旧监控，cat /root/crontab.backup.before_disable_healthmon_20260902.txt | crontab -（宝塔 root）。

6. 遗留与建议

  • 新库 15.152.6.51 本机未部署资源采集（磁盘/CPU/内存），当前仅由新前后端做 TCP 连通性检查；如需覆盖库机资源，可后续在库机部署采集并扩展汇总（记录为可选优化）。
  • 监控 Telegram 发送方从旧“数据汇报bot”变为 ben-bot（game18_report_bot）；如需沿用原 bot，需提供旧 /etc/youdianse-health-alert.json 的 token 配置再替换。
