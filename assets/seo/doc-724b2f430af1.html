2. 原始记录处理原则

原始记录是聊天记录和工作流水，正式周报不能直接照搬，需要做结构化归纳。

处理原则：

  • 保留可汇报的工作事项、结果、协同和风险。
  • 过滤账号、密码、验证码、会议链接、系统入口、截图细节、域名敏感细节和群聊噪音。
  • 对未确认的问题不直接下结论，例如 MongoDB 内存告警只写“证据化排查”，不写死原因。
  • 对团队成员按实际参与情况分摊到个人任务。
  • 新人事项要明确“低风险协助 / 带教 / 高风险操作仍由老运维确认”的边界。

3. 本周主要信息提炼

本周从原始记录中提炼出的核心事项如下。

3.1 发布自动化

  • 修复游点涩测试环境 Webhook 自动发布遇到 dirty 工作区卡住的问题。
  • Webhook 自动发布前执行工作区清理，再拉取 dev 最新代码。
  • 手动发布继续保留 dirty 拦截，避免误删人工排查改动。
  • 通过安全 dirty 文件验证自动清理、拉取和发布流程，结果为 SUCCESS。

3.2 ben-bot 值班系统

  • 运维值班表从月历按钮、多日按钮、折叠文本逐步收敛为“今日动态值班面板”。
  • 早班：14:00-22:00，Ben / Jett / Kermit。
  • 晚班：17:00-01:00，Melo / Davie。
  • 每人按 8 小时计算，展示未上班、在岗、剩余时间和已下班状态。
  • 值班人员姓名支持点击联系。
  • 值班面板每 60 秒原位刷新，参考 CICD 发布进度的编辑原消息方式。
  • 机器人部署、重启、上班、下班和交接通知统一展示实时值班信息。
  • 修复 APScheduler 上海时区兼容问题。
  • 补充星期日全员休息规则，避免周日误发早班、晚班和交接通知。

3.3 监控、日志和资源治理

  • 推动业务日志持久化落盘。
  • 确认 GD WebP / 图片压缩依赖支持。

  • MongoDB 内存告警按定时任务、处理量、日志和服务器负载继续证据化排查。
  • 清理已关停老 18game 服务器监控项。
  • 跟进测试环境磁盘垃圾清理、Masobu 磁盘清理和资源续费/停用评估。

3.4 域名、CDN、证书和云资源

5.2 生成方式

本次环境中 spreadsheet 专用 @oai/artifact-tool 不可用，也没有已连接的 Excel 文档控制会话；openpyxl 也未安装。

因此采用兼容处理方式：

  1. 将上一周 xlsx 作为模板。
  2. 使用 Python 标准库 zipfile 解包/重写 xlsx 内部 XML。
  3. 只替换 xl/worksheets/sheet1.xml 中的表头日期、每日内容、审核状态、提交天数、缺交天数和周评语。
  4. 保留模板中的样式、列宽、行高、workbook、theme、styles、sharedStrings、drawing、metadata 等结构。
  5. 写回同名 xlsx。
  6. 使用 unzip -t 校验 xlsx 压缩包结构。

注意：这类 xlsx 是二进制文件，不能用 apply_patch 直接编辑，只能通过脚本或表格工具生成。

6. xlsx 格式问题和修复

6.1 初始问题

第一次生成 xlsx 后，VSCode 插件 XLSX, CSV, TSV & Markdown Editor 打开时报错：

Error reading XLSX file: TypeError: Cannot read properties of undefined (reading 'Target')

Excel 本身可能可以打开，但 VSCode 插件无法渲染。

6.2 排查过程

检查 xlsx 内部关系文件：

xl/worksheets/_rels/sheet1.xml.rels
xl/_rels/workbook.xml.rels
_rels/.rels

确认 Target 字段存在。

继续对比历史文件和新文件的 xl/worksheets/sheet1.xml，发现差异：

历史文件：

<drawing r:id="rId1" />

异常文件：

<drawing ns1:id="rId1" />

原因是 Python ElementTree 重写 XML 时将关系命名空间自动命名成了 ns1。Excel 能识别这个命名空间，但 VSCode 插件可能写死读取 r:id，导致它找不到对应关系，再读取 Target 时触发 undefined。

6.3 最小修复

将工作表 XML 中的命名空间恢复为历史格式：

xmlns:r="http://schemas.openxmlformats.org/officeDocument/2006/relationships"

并将：

<drawing ns1:id="rId1" />

替换为：

<drawing r:id="rId1" />

修复后再次执行：

unzip -t "work-运维部工作进度-周报/2026-07-06_07-13/运维组_周台账_2026年第28周_0706-0713.xlsx"

结果：

No errors detected in compressed data

6.4 后续兼容方案

如果 VSCode 插件仍然报同样错误，可继续做插件兼容版：

  • 移除空 drawing：

text xl/drawings/drawing1.xml xl/worksheets/_rels/sheet1.xml.rels sheet1.xml 末尾的 <drawing r:id="rId1" /> [Content_Types].xml 中 drawing override

  • 移除 Google metadata：

text xl/metadata workbook.xml 中 GoogleSheetsCustomDataVersion2 extLst workbook.xml.rels 中 rId5 [Content_Types].xml 中 /xl/metadata override

这两个结构对台账正文无影响，但有些轻量 xlsx 插件可能解析不完整。

8. 后续复用流程

以后生成新一周周报时，建议按下面顺序执行。

  1. 新建周目录，例如：

text work-运维部工作进度-周报/2026-07-13_07-20/

  1. 放入原始记录：

text 原始记录.txt

  1. 参考上一周：

text 周计划.txt 周计划反馈-Ben运维.txt 运维组_周台账_*.xlsx

  1. 从原始记录提炼：
  • 日常任务
  • Ben 工作
  • Kermit 工作
  • Jett 工作
  • Melo 新运维带教/参与事项
  • 重点推进事项
  • 特殊情况说明
  1. 生成：

text 周计划.txt 周计划反馈-Ben运维.txt 运维组_周台账_YYYY年第X周_MMDD-MMDD.xlsx

  1. xlsx 优先用上一周模板替换内容，保持样式不变。

  2. xlsx 生成后必须校验：

bash unzip -t 文件名.xlsx

  1. 如果 VSCode 插件打不开，优先检查：

text xl/worksheets/sheet1.xml 中是否存在 <drawing ns1:id=...>

如存在，恢复为：

text <drawing r:id="rId1" />

  1. 检查 git 状态：

bash git status --short -- work-运维部工作进度-周报/对应周目录

9. 注意事项

  • 不要把原始聊天记录中的敏感信息写入正式周报。
  • 不要把未入职/未正式接入的人员写成正式台账成员。
  • Melo 已确认是新运维，后续周报和台账中应持续保留新运维身份，直到团队不再需要特别标注。
  • Davie 当前只适合写“候选/待接入/后续晚班模型规划”，除非后续明确入组。
  • xlsx 不建议从零创建，优先复用上一周模板，避免样式和插件兼容问题。
  • 如果使用 Python ElementTree 改 xlsx XML，注意命名空间可能被自动改成 ns1，需要恢复为历史文件中的 r:。
