处理范围

  • 香港入口 Nginx：192.0.2.14。
  • 静态域名：PG、vendor_a、PP、PPK、vendor_c、PANDA，共 11 个前缀、55 个域名。
  • 动态游戏/API：PG、vendor_a、PP、PPK、vendor_c、PANDA 的 30 个动态域名，以及 9 个 hkplaycore.com API/verify 域名。
  • 参考巴西宝塔各游戏厂家 Nginx 的 CORS 规则；巴西配置和服务器未修改。

Nginx 处理

动态反代公共片段 docker/deploy/hongkong/bizops-hongkong-proxy.conf 统一执行：

if ($request_method = OPTIONS) {
    add_header Access-Control-Allow-Origin "*" always;
    add_header Access-Control-Allow-Methods "GET, POST, OPTIONS" always;
    add_header Access-Control-Allow-Headers "*" always;
    return 204;
}

proxy_hide_header Access-Control-Allow-Origin;
proxy_hide_header Access-Control-Allow-Methods;
proxy_hide_header Access-Control-Allow-Headers;
proxy_hide_header Access-Control-Allow-Credentials;
add_header Access-Control-Allow-Origin "*" always;
add_header Access-Control-Allow-Methods "GET, POST, OPTIONS" always;
add_header Access-Control-Allow-Headers "*" always;

静态域名在 docker/deploy/hongkong/nginx-bizops.conf 使用相同规则。隐藏 GCS 上游 CORS 响应头后由香港 Nginx 统一返回，避免重复的 Access-Control-Allow-Origin。

PP 静态域名额外保留巴西已有的特殊处理：

location ~* /customizations\.info$ {
    default_type application/octet-stream;
    return 200 "";
}

该 location 同样包含 OPTIONS 和普通响应的 CORS 头。

发布结果

  • 主配置：/etc/nginx/sites-available/bizops-hongkong.conf。
  • 公共代理片段：/etc/nginx/snippets/bizops-hongkong-proxy.conf。
  • 发布前同时备份主配置和公共代理片段。
  • nginx -t 成功。
  • systemctl reload nginx 成功。

全域名 CORS 验证

使用以下请求头执行预检：

Origin: https://frontend.example.com
Access-Control-Request-Method: GET
Access-Control-Request-Headers: content-type,x-token

验证结果：

范围 通过数 总数 结果
静态域名 OPTIONS 55 55 全部 204，ACAO=*，Methods/Headers 正常
动态游戏/API OPTIONS 39 39 全部 204，ACAO=*，Methods/Headers 正常

静态代表性 GET 覆盖 pg-static、pg3-static、pg4-static、pg5-static、vendor_a-statics、vendor_a-statics1、vendor_a-statics2、pp-static、ppk-static、vendor_c-static、vendor_d-static，全部返回真实对象并带 Access-Control-Allow-Origin: *。

动态代表性 GET：

  • platform、PG/verify：200，并带 ACAO=*。
  • PP：403，已到应用，并带 ACAO=*。
  • PPK、PANDA：404，已到应用，并带 ACAO=*。
  • vendor_c：503，符合“后端未部署”的设计，并带 ACAO=*。
  • vendor_a：普通请求仍因两台后端 9096 未监听而返回 502；入口 Nginx 直连响应已带 ACAO=*，OPTIONS 已通过。vendor_a 仍不列入前端可用动态域名。

PP 进游戏 HTTP 链路验证

测试入口：https://ind-h5.bizopsplus999.com/pponline/。

测试游戏：ID 102，symbol vs20starprss。

环节 结果
Logintest code=0
香港 launcher HTTP 200，ACAO=*
gs2c/html5Game.html HTTP 200，ACAO=*
动态 gs2c/gamename.json HTTP 200，ACAO=*，4306 字节

游戏 HTML 中的静态 datapath 模板也已确认指向：

https://pp-static.hkcloudplay0[1-5].com/gs2c/common/v5/games-html5/games/vs/<symbol>/

当前会话没有可用的内置浏览器，因此本轮完成的是完整 HTTP 启动与资源链路验证，不把它表述为已完成人工画面验收。前端清理浏览器/CDN 缓存后再点击一次 PP 游戏，可作为最终画面确认。

结论

  • 香港全厂商静态和动态域名的 CORS 已按巴西规则统一补齐。
  • PP 的 GCS 对象路径、公共脚本、游戏 bootstrap 和 customizations.info 均已恢复正常。
  • PP 游戏已通过完整 HTTP 启动链路验证。
  • vendor_a、vendor_c 的既有后端状态没有改变，不应因 CORS 修复而提前交付前端。
