一、当前与竞品对比（同基准，3 轮，备用机）

点继续→加载出：我方 8.3/8.2/7.6（均值 8.0s）vs 竞品 7.3/8.0/7.2（均值 7.5s）→ 竞品快 0.5s
点击图标→完整加载：我方 12.6/13.5/11.8（均值 12.6s）vs 竞品 12.5/14.9/12.3（均值 13.2s）→ 我方快 0.6s
画布出现：我方 1.2-2.3s vs 竞品 2.1-3.9s → 我方明显快

二、最大差距（第一名头号目标）

1. API TTFB（差距 8 倍）

我方 api.xqv9m8.icu：0.42-2.50s，均值 ~1.1s（波动大，有毛刺）
竞品 m6kk678n.com/api/：0.09-0.18s，均值 ~0.13s

动作：platform-api 慢请求专项（DB 连接池、慢查询、日志、连接复用）， 目标均值 ≤0.2s。

2. 点继续→加载出段（差 0.5s）

我方 8.0s vs 竞品 7.5s：游戏包体大小/渲染启动段
动作：游戏静态资源体积（已做 WebP/Brotli/immutable）、vendor_a _nuxt 分包（需 vendor 源码）、
      preconnect 到静态域（launcher 已加）、包体压缩（vendor 侧）

三、全链路可操作优化清单（更新）

服务器

已做：keepalive、源站缓存、gzip（宝塔修正+备用机补齐）、sysctl syn_backlog 512→2048
      /netdev_backlog→3000（本轮，已持久化 sysctl.conf，备份 .bak-20260830）
待做：备用机 sysctl 同步；后端容器资源巡检（P3）

前端静态

已做：PNG→WebP（源站省50%+Polish 40-50%）、hash JS immutable 1年、Montserrat woff2
待做：vendor_a _nuxt 分包（vendor 灰度）、pp 1.1MB JS 孤儿确认、JSON 专项审计

后端

已做：launcher P0-1、动态接口 gzip、/shared/ 边缘缓存
待做（P0）：API TTFB 专项（DB/连接池/慢查询）
待做（P1）：launcher P0-2 模板边缘缓存；GET 配置接口短缓存

CDN / 域名

已做：HTTP3/0-RTT、Argo 3套、CacheRule 静态全缓存、Brotli、EarlyHints、Polish、immutable JS
待做：t6qv8m/q7m9v8 Argo 重试；香港静态切 CF + 东京桶（cn 分支）

四、第一名冲刺优先级

P0 API TTFB 专项（1.1s → ≤0.2s）
P0 点继续→加载出段（8.0 → ≤7.5s，包体/vendor 分包）
P1 备用机 sysctl 同步；vendor_a _nuxt 分包灰度；香港切 CF
P2 JSON 专项审计；前端封面图懒加载；pp 孤儿 JS 确认

五、本轮变更

  • 宝塔 sysctl：tcp_max_syn_backlog 2048、netdev_max_backlog 3000（持久化，备份）；
  • 6 条带水印对比视频已发群；
  • 本记录文档。

六、对比问题解决进展（2026-08-30 第二轮）

API TTFB：已澄清解决（巴西打平）

分层测量：后端直连 3-8ms、宝塔 nginx 14ms、CF+巴西 0.09s、竞品 0.08s
结论：巴西视角（真实用户）我方与竞品打平；马尼拉 1.1s 为跨洲假象，无需改动

点继续→加载出 0.5s：确认为稳定差距（6 轮）

我方 8.0s（8.3/8.2/7.6/8.0/7.5/8.5）vs 竞品 7.5s（7.3/8.0/7.2/8.2/7.2/7.2）
我方游戏静态加载 12.3MB/72 请求（已 WebP/Brotli/immutable 优化）
定位：游戏引擎启动/网络尾段（vendor 侧）
我方侧已完成：preconnect（launcher）、静态全缓存、压缩
下一步（需 vendor）：引擎启动配置专项、游戏包体预加载/分包
