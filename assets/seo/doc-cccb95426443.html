本文件定义当前项目在公共验收框架上的项目级补充要求。

1. 验收入口

项目验收至少需要同步维护：

  1. docs/qa/acceptance-evidence.md
  2. docs/qa/project-acceptance.md
  3. docs/qa/test-environments.md
  4. docs/agents/logs/**
  5. docs/prd/requirements.md
  6. docs/quality/code-standards.md
  7. docs/architecture/database-design-standards.md
  8. docs/architecture/capability-gates.md
  9. docs/qa/architecture-capability-evidence.json
  10. docs/operations/ops-readiness.md
  11. docs/operations/deployment-strategy.md
  12. project.config.json

2. 模块验收

每个启用模块都必须有验收记录。

模块 验收要求
apps/mobile 真实设备视口、关键流程、API 接入、错误状态
apps/web 响应式、SEO异常验证、下载入口、隐私/条款链接
apps/web PC/H5 响应式、SEO异常验证、权限态、API 接入
apps/admin 登录、RBAC、审计日志、敏感操作二次确认
services/go-app OpenAPI 覆盖、服务端测试、鉴权、幂等
services/laravel-app 路由、Request、Resource、Policy、Filament 权限
services/realtime 连接、鉴权、事件、重连、降级
services/worker 队列、重试、幂等、告警

3. 完成声明

AI Agent 只有在以下条件同时满足时，才能声明项目或模块完成：

  1. PRD、需求 ID 和 OpenAPI 已覆盖对应能力。
  2. 代码实现接入真实 API 或明确登记为受控 fixture。
  3. 代码实现符合 docs/quality/code-standards.md。
  4. 数据表、迁移、索引、账本和审计符合 docs/architecture/database-design-standards.md。
  5. 复杂业务已按 docs/architecture/capability-gates.md 完成架构能力判断，不涉及项写明不适用原因。
  6. 部署、回滚、密钥、备份恢复、观测和故障响应符合 docs/operations/ops-readiness.md。
  7. 自动化测试和人工验收都有证据。
  8. 红蓝对抗结论允许合入。
  9. 没有未登记的 mock/fallback/placeholder。
  10. npm run check 通过。
