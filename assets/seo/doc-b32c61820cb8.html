一、先搞清楚「线上入口是哪一台」——这一步最容易搞错

线上静态域名：CNAME -> GCS 桶（由 Cloudflare Worker 处理），不经过 nginx。
线上动态/游戏域名：A 记录 -> 192.0.2.13 = bizops-saopaulo-nginx-standby-01（备用 nginx 入口机）
                        ↓ 反向代理
                    后台 01/02/03 的容器

⚠️ 宝塔 192.0.2.8（192.0.2.1）**当前不是线上入口**，
   它上面也有一份同样的 upstream 配置，但线上流量不经过它（保持两份一致只是为了切换时少踩坑）。

判定命令（随时可复核）：

# 1) 看域名回源（在能访问 CF API 的机器上；token 在宝塔 /root/bizops-cf-dns.env）
curl -s -H "Authorization: Bearer $TOKEN" \
  "https://api.cloudflare.com/client/v4/zones/<zone_id>/dns_records?name=vendor_a-games.xqv9m8.icu" \
  | python3 -m json.tool | grep -E '"name"|"content"'
#   期望：content = 192.0.2.13

# 2) 看入口机 nginx 访问日志有没有真实用户流量
ssh root@192.0.2.13 'tail -3 /www/wwwlogs/vendor_a-games.xqv9m8.icu.log'
#   有 172.71.x.x（Cloudflare）进来的请求 = 这台就是线上入口

二、切换开关在哪个文件

线上（真正生效）：  192.0.2.13 : /etc/nginx/conf.d/00.vendor-upstreams.conf
宝塔（保持一致）：  192.0.2.8  : /www/server/panel/vhost/nginx/00.vendor-upstreams.conf

仓库存档：
  docker/线上服务器信息/standby-nginx/00.vendor-upstreams.conf
  docker/线上服务器信息/baota/nginx/panel-vhost-nginx/00.vendor-upstreams.conf

每台机器一行 server <IP>:<端口> ... down;：带 down 的不接流量，不带的那台接全部流量。

三、⚠️ 各机器的端口不一样（切换前必须核对）

厂家        01(192.0.2.1)  02(192.0.2.1)  03(192.0.2.1)
pg          9091            9091            9091
vendor_a(http)  9096            9096            9096
vendor_a(ws2)   8765            8765            8765
api/socket  9090            9090            9090
pp          9101            9099            9101
ppk         9103            9098            9103
vendor_c     9104            9020            9104
vendor_d       9102            9018            9102
g759        9019            9019            9019

为什么 02 不一样：01/03 的容器是「宿主机 910x -> 容器 90xx」映射，
02 上这批 game-service-*-prod 容器是直接按容器端口发布（9098/9099/9018/9020）。
所以**改机器时必须同时改端口**，只改 IP 会 502。

切换前检查端口（可选但推荐，把 <02IP> 换成目标机）：

for spec in "pg 9091" "vendor_a 9096" "ws2 8765" "api 9090" "pp 9099" "ppk 9098" "vendor_c 9020" "vendor_d 9018" "g759 9019"; do
  set -- $spec
  printf "%-9s :%-5s -> %s\n" "$1" "$2" "$(curl -s -o /dev/null -w '%{http_code}' --max-time 5 http://<02IP>:$2/ || echo 连不上)"
done
# 只要不是「连不上/000」就说明该端口在听（400/403/404 都是应用正常响应）

四、标准切换步骤（以切到 02 为例，全量）

### 1) 备份（两台机器都做，入口机必须做）
ssh root@192.0.2.13
cp -a /etc/nginx/conf.d/00.vendor-upstreams.conf \
      /etc/nginx/conf.d/00.vendor-upstreams.conf.bak-$(date +%Y%m%d-%H%M%S)-before-switch

### 2) 改开关：目标机去掉 down，其它机器加 down（注意 02 的端口不一样）
#    pg   : 192.0.2.1:9091
#    vendor_a : 192.0.2.1:9096      ws2: 192.0.2.1:8765
#    socket:192.0.2.1:9090
#    pp   : 192.0.2.1:9099      ppk: 192.0.2.1:9098
#    vendor_c:192.0.2.1:9020     vendor_d:192.0.2.1:9018    g759:192.0.2.1:9019

### 3) 只改完先验语法，再 reload
nginx -t && systemctl reload nginx        # 宝塔是 /www/server/nginx/sbin/nginx -t && nginx -s reload

### 4) 验证（见第五节），有 502 立刻回滚
cp -a ...bak-...-before-switch /etc/nginx/conf.d/00.vendor-upstreams.conf && systemctl reload nginx

五、切换后必须做的三层验证

# 第 1 层：直连后端端口（确认目标机在听，来自入口机执行）
curl -s -o /dev/null -w '%{http_code}\n' http://192.0.2.1:9091/      # pg 期望 200
curl -s -o /dev/null -w '%{http_code}\n' http://192.0.2.1:9096/      # vendor_a 期望 403

# 第 2 层：经入口机 nginx（Host 头指向本机，确认反代通）
curl -sk -o /dev/null -w '%{http_code}\n' --resolve vendor_d-games.xqv9m8.icu:443:192.0.2.1 \
     https://vendor_d-games.xqv9m8.icu/health        # 期望 400（应用响应，不是 502）

# 第 3 层：公网域名（走 Cloudflare，最终用户视角；从任意外网机器执行）
for u in pg-games vendor_a-games pp-games ppk-games vendor_c-games vendor_d-games g759-games; do
  printf "%-16s " $u
  curl -s -o /dev/null -w '%{http_code}\n' --max-time 12 -A 'Mozilla/5.0 (iPhone; CPU iPhone OS 18_5 like Mac OS X)' \
       "https://$u.xqv9m8.icu/health"
done      # 期望全部 200

# WebSocket（vendor_a WS2）单独验：
curl -s -D - -o /dev/null --http1.1 --max-time 8 \
  -H 'Connection: Upgrade' -H 'Upgrade: websocket' -H 'Sec-WebSocket-Version: 13' \
  -H 'Sec-WebSocket-Key: x3JJHMbDL1EzLkh9GBhXDw==' \
  https://vendor_a-games.xqv9m8.icu/lifeservice/ws2 | head -2    # 期望 101 Switching Protocols

七、回滚 / 切到 03

# 回滚到 01（全部）：把 01 行的 down 去掉，其余加 down；注意 01 的端口是 910x
# 切到 03：03 的端口同 01（9091/9096/8765/9090/9101/9103/9104/9102/9019）
nginx -t && systemctl reload nginx
# 然后按第五节三层验证；WS2 必须单独验 101

八、踩过的坑（务必记住）

  1. 线上入口是 192.0.2.13（备用 nginx），不是宝塔。只在宝塔上改 = 线上毫无变化。
  2. 02 的端口和 01/03 不一样（9098/9099/9018/9020），只改 IP 会 502。
  3. vendor_a WS2 必须跟 HTTP 一起切：WS2 与 HTTP 同属一个容器； 目标机没发布 8765 时，网页能开但游戏会卡在加载（本次就先留在 01）。
  4. 静态域名（*-static.*）是 CNAME 到 GCS + Cloudflare Worker，和这次切换无关，不需要动。
  5. 两条链路的开关文件路径不同（入口机在 /etc/nginx/conf.d/，宝塔在 /www/server/panel/vhost/nginx/）， 改完记得两边一致，避免下次切错。
