1. 变更目标

  • 启用新测试环境：
  • 测试环境-前后端-ec2：15.152.247.196
  • 测试环境-数据库-ec2：15.152.6.51
  • 迁移 Redis 及 MongoDB 数据到新数据库 EC2
  • 迁移后端、前端容器代码到新前后端 EC2
  • 更新域名解析：*.youdianse-test.xyz 泛解析切到新前后端
  • 修改 Spug 几十条定时任务执行主机/脚本/env 到新环境
  • 验证测试自动化 CICD（前端 H5/PC 发布 + 后端 dev 发布）
  • 老测试环境暂作保留（38.92.8.34 宝塔），作为回滚点，全程不停机

2. 当前真实测试环境基线（迁移前确认）

组件 现状

3. 迁移前准备（22:00 前完成）

3.1 只读核验清单

  • 新前后端 15.152.247.196 SSH 可达，确认登录用户（待确认，不走猜测）
  • 新数据库 15.152.6.51 SSH 可达，确认登录用户（待确认，不走猜测）
  • 两台新 EC2 的 Docker/Compose/Nginx 版本记录
  • 老库 Mongo/Redis 运行状态与备份能力确认
  • DNS 服务商（DNSPod）泛解析修改入口与 TTL 确认
  • 新环境证书方案确认（*.youdianse-test.xyz 泛域名证书或逐域名证书，SAN 必须覆盖 h5/pc/test-h5/test-pc/sdk/admin）
  • Spug 任务清单导出（几十条）
  • 安全组/防火墙规划（迁移窗口老→新 27017/6379 放行，完成后收紧）

3.2 敏感信息处理

  • 本方案只写环境变量名/端口/路径，不写密码、Token、私钥、完整连接串
  • 连接串、密码在服务器现场 env 中管理，群消息与文档不出现原文

4. 分步执行计划（含耗时、操作、验证、回滚）

步骤 1：备份测试环境 Mongo 和 Redis（约 20 分钟）

目标：老库全量备份，形成可回滚基线。

操作：

  1. 记录老库连接信息与库列表（Mongo 库名、Redis db 数）
  2. Mongo 备份： - 使用 mongodump 全量导出到备份目录（例如 /backup/testenv_mongo_20260901） - 导出后打包并计算校验值，记录文件大小
  3. Redis 备份： - 执行 BGSAVE，等待完成 - 复制 dump.rdb 到备份目录（例如 /backup/testenv_redis_20260901/） - 记录各 db 的 key 数（DBSIZE）、关键 key 大小（STRLEN 18game_system_config）
  4. 把备份文件同步一份到新数据库 EC2 或独立备份盘（异机冗余）

验证：

  • mongodump 输出无 error；备份目录非空且大小合理
  • redis-check-rdb 校验通过；dump.rdb 时间戳为备份时刻
  • 记录 collection 文档数与 db key 数作为导入后比对基线

回滚点：老库保持原样，备份文件保留 7 天以上。

步骤 2：准备和检查网络权限（约 30 分钟）

目标：新环境基础服务可用、网络链路打通。

操作：

  1. 测试环境-前后端-ec2（15.152.247.196）： - 检查 SSH、Docker Engine、Compose、Nginx - 准备 Node（前端构建/运行）、PHP（后端运行）所需组件，版本与老环境一致 - 准备代码目录与运行目录（H5/PC/后端）
  2. 测试环境-数据库-ec2（15.152.6.51）： - 安装/确认 MongoDB（27017）与 Redis（6379） - 设置访问控制与密码（按老环境同策略），本地只读校验可连
  3. 网络放行： - 新前后端 → 新库：27017、6379 - 老库/老宝塔 → 新库：仅迁移窗口需要（步骤 3 导入用），完成后收紧 - 公网 80/443（页面与 API）
  4. 域名解析准备： - 确认 *.youdianse-test.xyz 泛解析改法（DNSPod） - 确认证书签发/同步方案

验证：

  • 新前后端可连新库：nc -zv <db_ip> 27017、nc -zv <db_ip> 6379
  • 两台新 EC2 Docker/Nginx 健康页可访问
  • 记录新库连接串变量名（如 MONGO_URI_NEW、REDIS_HOST_NEW），不落明文

回滚点：未切流，新环境独立，不影响老环境。

步骤 3：导入数据 Mongo + Redis（约 20 分钟）

目标：备份数据导入新库，数据层先行就绪。

操作：

  1. Mongo： - mongorestore 恢复到测试环境-数据库-ec2 15.152.6.51 - 保持库名/collection 名与老库一致
  2. Redis： - 用备份的 dump.rdb 恢复（或按需导入配置缓存、token、session 等关键 key） - 启动后确认 db 结构与 key 数

验证：

  • Mongo collection 文档数与备份基线一致；config/game 等关键库抽样查询正常
  • Redis db 数量、DBSIZE、18game_system_config 大小、token/session 计数与老库一致

回滚点：新库可清空重导；老库未动。

步骤 4：正式迁移后端、前端容器代码（约 30 分钟）

目标：代码与运行环境切到新前后端 EC2。

操作：

  1. 后端： - 把老宝塔 /opt/docker-youdianse-php 的代码、Dockerfile、compose、env 同步到新前后端（env 脱敏后传输，库连接改指向 15.152.6.51） - 构建镜像并启动 web/nginx/cron 容器 - 容器名沿用 youdianse-dev-php-web/nginx/cron
  2. 前端： - H5/PC 代码同步到新前后端（代码目录沿用 18game_h5_client / 18game_pc_client） - 构建并启动 H5（3003）、PC（3004）容器 - nginx 反代 /api、/channel、/customer 同域路由对齐
  3. 老宝塔容器保持运行，暂不停机

验证：

  • 后端容器全部 Up；健康检查 HTTP 200、Session writable、Redis/Mongo open
  • 前端容器 Up；/version.json、/version.txt 可访问
  • 新环境本机通过 Host 头访问 h5/pc 页面 200

回滚点：老宝塔容器仍在运行，DNS 未切前不影响老环境。

步骤 5：代码迁移结束后调试配置（约 20 分钟）

目标：新环境配置与老环境对齐，业务可用。

操作：

  1. env 核对： - 数据库连接串、Redis - CDN/S3 静态域（18game-nuxt-static-test-h5 / test-pc 默认域） - API 域 admin.youdianse-test.xyz - 上传/图片域（CloudFront d1rct3ku9n07y3.cloudfront.net）
  2. PHP-FPM 池配置（沿用老环境参数，评估 max_children=5 是否保留或按新机器资源调整）
  3. nginx 反代、robots/UA 分流、静态资源缓存策略对齐
  4. 后台登录、H5/PC 首页 SSR、核心 API 冒烟： - system/info - AppVersion/latestVersion - modules/home

验证：

  • 后台可登录；H5/PC 首页与核心接口 200，延迟正常
  • 无新增 slow_api/错误日志

回滚点：配置未切流，可继续调整；有问题回老环境。

步骤 6：修改域名解析（约 30 分钟生效）

目标：页面/API 域名切到新环境。

操作：

  1. 修改 *.youdianse-test.xyz 泛解析 A 记录： - 38.92.8.34 → 15.152.247.196 - 覆盖 h5/pc/test-h5/test-pc/sdk/admin 等全部子域
  2. 等待 TTL 生效（按记录 TTL，一般 5-30 分钟）
  3. 如新环境证书未覆盖全部子域，先补证书再切解析

验证：

  • 多节点/多次解析确认指向 15.152.247.196
  • h5.youdianse-test.xyz、pc.youdianse-test.xyz、admin.youdianse-test.xyz 严格 HTTPS 200，证书匹配
  • 页面与 API 冒烟通过

回滚点：DNS 改回 38.92.8.34 即回老环境（保留旧解析记录截图/备份）。

步骤 7：修改 Spug 几十条定时任务到新服务器（约 30 分钟）

目标：定时任务执行主机/脚本/env 全部指向新环境。

操作：

  1. 导出/列出 Spug 当前任务清单（几十条），逐条核对： - 执行主机 - 脚本路径 - 参数与 env
  2. 把测试环境相关任务的目标主机改为测试环境-前后端-ec2 15.152.247.196
  3. 同步脚本与依赖到新机，路径保持一致或同步调整
  4. 更新任务引用的 env（库连接、域名、S3 等）

验证：

  • 随机抽 3-5 条任务手动执行一次，确认成功且写库落在新库
  • 任务清单全部核对，无遗漏项
  • 输出修改前后任务清单差异供复核

回滚点：Spug 任务执行主机批量改回老环境；保留修改前清单备份。

步骤 8：测试自动化 CICD / 测试发布前端、后端（约 20 分钟）

目标：自动发布链路切到新环境并验证。

操作：

  1. 前端： - 把 ben-bot 测试 H5/PC 发布入口 SSH 目标从老宝塔改为测试环境-前后端-ec2 15.152.247.196 - 触发一次测试发布（H5 + PC），确认镜像打包、容器启动成功
  2. 后端： - 触发 dev 分支 webhook 自动发布 - 确认构建、容器切换、健康检查 SUCCESS

验证：

  • H5/PC 新发布版本 version.json/页面 200，静态资源 S3 域名正常
  • 后端发布后 web/nginx/cron running，健康检查与核心 API 通过
  • GitLab webhook 记录无 error

回滚点：CICD/发布入口切回老环境即可重新触发；老环境保留。

步骤 9：待机监控（预留 1 小时）

目标：迁移后观察稳定性，异常快速回滚。

操作：

  1. 监控新环境： - API 延迟（核心接口抽样） - slow_api/错误日志 - 磁盘/CPU/内存
  2. 观察： - H5/PC 页面、后台登录 - 定时任务执行 - CICD 发布是否持续正常
  3. 保持回滚点就绪： - DNS 改回老环境命令已备份 - 老宝塔容器运行状态持续确认

验证：

  • 持续 30 分钟无新增异常
  • 关键指标与老环境基线对比无劣化

7. 风险与注意事项

  • 白天测试环境正常使用，22:00 后开始切换，期间测试服务可能出现短暂中断
  • 老测试环境暂作保留，不做删除/停机操作
  • 所有变更先备份、验证、再切流；操作按 C1 级执行
  • 每完成一个明确步骤立即通知 18game运维 群
  • 不写密码/Token/私钥/完整连接串到文档与群消息
  • 新环境上线后同步更新：
  • workbench（servers.yml、运行链路、机器矩阵）
  • ben-bot 测试 H5/PC/后端发布入口目标
  • Spug 任务与值班/巡检脚本引用
  • 迁移过程中如发现事实冲突（IP、路径、版本不一致），先停止写操作，核验后再继续
