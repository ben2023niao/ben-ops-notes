一、背景

触发：代理（英格麗 / Brian Lin）已开通腾讯云国际站账号（预充 2500U，子账号给到操作人邮箱），
      C++ 侧明确「不是要服务器，是 CDN」，目的是解决香港项目「纯 Cloudflare 面向大陆覆盖不全、
      网络不好」的问题；对方已提示「走境内节点要备案」「跨境取源会有延迟」。
策略（2026-09-29 更新，用户口径）：**多 CDN 渠道 + 免备案优先**，把大陆覆盖补齐；
      备案只作为「能过就多加一条大陆节点快路」的加强项，不作为唯一依赖。
本轮产出：给代理一份说人话 + 链路示意图的现状说明 + 需要我们内部先确认的前置条件。
本轮为文档/沟通口径整理，无任何生产变更，不发送飞机群通知。

二、可直接发送的口语版（带示意图，推荐发这个）

先说结论：大陆玩家现在下载游戏资源是绕路的，而且单靠一家 CDN 覆盖不全；
我们想同时接多家 CDN，哪家在大陆覆盖好就走哪家，尽量不依赖备案这条路，把大陆补齐。

【现在的路怎么走的】

静态资源（图片/JS/CSS/音频，量最大）：

  玩家(大陆)
     |
     v
  Cloudflare 节点（大陆没有就近节点，实际绕到境外/香港）
     |
     v
  AWS S3 大阪  <-- 所有客户端资源都存在这里

动态接口（游戏 API、WebSocket）：

  玩家(大陆) --> Cloudflare --> 香港自建入口 nginx --> 香港后端
                                （这条路源站就在香港）

【问题在哪】

  玩家(大陆) --X--> Cloudflare --X--> 大阪 S3
      大陆三网部分省份绕路、丢包，晚高峰抖；表现就是第一次进游戏慢、版本更新卡。
      而且只挂一家 CDN，电信/联通/移动总有一家覆盖不好，没法互相补。

【我们想改成：多家 CDN 一起上，免备案优先，把大陆覆盖补齐】

  玩家(大陆)
     |
     | 访问同一个域名（玩家那边地址不用改）
     v
  项目代码智能调度（多 CDN 域名竞速；DNS 也可按地区/运营商分线路）
     |
     +--> 渠道 A：腾讯云国际版（先国际版；若能备案，再上国内版大陆节点）
     +--> 渠道 B：HansCDN + 回国优化线路
     +--> 渠道 C：Cloudflare（境外用户 + 兜底）
                  |
                  +-- 静态：回源 AWS S3 大阪；首次回源，之后吃边缘缓存（7 天）
                  +-- 动态：回源香港后端（API/WebSocket 不缓存）

  一句话：用「免备案的境外/香港节点 + 回国优化线路」先把大陆覆盖补齐，
  备案如果能过，等于再加一条大陆节点快路；但不想把方案全押在备案上。

【想请你们确认 3 件事】

  1) 不备案能覆盖到哪一步：你们能提供哪些「不需要备案、但对大陆三网覆盖不错」的 CDN 或线路？
     分别覆盖哪些地区/运营商、延迟大概什么水平？腾讯云如果大陆节点必须备案，
     那它的香港/新加坡节点回大陆的体验怎么样？
  2) 多 CDN 怎么调度：能不能按地区/运营商分线路（DNS 智能解析），切换和回滚要多久、
     有没有对玩家影响最小的灰度方式？
  3) 源站是 AWS 大阪 S3 + 香港后端：各家回源有没有限制、延迟大概多少、能不能回源到
     香港/新加坡中转？另外先给测试额度，我们拿一两个域名实测覆盖再决定整体切换。

另外两个小问题：支持自有证书吗（或者免费证书）？能不能开子账号 + API 密钥，
我们要用脚本批量配域名和缓存规则，还要能导出访问日志。

说明：上面这段用的都是「玩家 -> 节点 -> 源站」的箭头链路，粘到群里对齐不乱（等宽字体）。 如果对方要看正式一点的书面版，用下面第三节。

三、正式版（需要更书面时用）

您好，同步一下香港项目的现状，方便你们判断方案。

【业务形态】面向中国大陆玩家的手机游戏，两类流量：
1) 静态资源（占大头）：游戏客户端资源，HTML/JS/CSS/图片/音频，单文件多为几十 KB ~ 几 MB，
   但文件数量多、请求量大，新版本发布时会集中下载。
2) 动态接口：游戏 API + WebSocket。

【现有架构】
- 静态：域名形如 pg-static.hkcloudplay06.com、vendor_b-static.hkcloudplay06.com，共 13 个静态前缀；
  源站对象在 AWS S3（目前主要在日本大阪 ap-northeast-3，另有香港 ap-east-1 桶做兜底）。
  对外目前走 Cloudflare（Worker + Cache Rules，边缘缓存 7 天）。
- 动态：同一主域名体系下的 *-games.hkcloudplay0N.com，走我们香港自建入口（nginx）
  反代到香港后端，源站全在香港。
- 域名：hkcloudplay01~07.com、hk-socket.com，均为境外注册，未做中国大陆 ICP 备案。

【当前的问题】纯 Cloudflare 面向大陆三网的覆盖和稳定性不够：部分地区/运营商回源慢、丢包、
晚高峰抖动，客户端首次加载和版本更新体验受影响；而且只挂一家，电信/联通/移动里总有覆盖差的，
没有互补。

【目标】多 CDN 渠道并行，**免备案优先**，把大陆覆盖补齐：
  渠道 A 腾讯云国际版 CDN（境外节点起步；若备案可行再接大陆节点）；
  渠道 B 另一家 CDN 的香港节点 + 回国优化线路；
  渠道 C Cloudflare（境外用户与兜底）；
由智能调度（按地区/运营商分线路，或客户端自测速择优）决定大陆玩家走哪条。

【希望你们确认/提供的】
1) 免备案覆盖能力：你们能提供哪些「不需要备案、但对大陆三网覆盖不错」的 CDN 或回国优化线路？
   各自覆盖地区/运营商、延迟量级；腾讯云如果大陆节点必须备案，其香港/新加坡节点回大陆表现如何。
   请一并说明备案路径（对域名注册商/主体要求、材料、周期）作为可选加强项。
2) 多 CDN 调度：能否按地区/运营商分线路（DNS 智能解析或多 CNAME 加权）；切换与回滚时长、
   灰度方式（同主域下多子域分批切）；各家回源限制与延迟，是否支持回源到香港/新加坡中转。
3) 功能匹配：静态小文件高并发（目录跳转 302、Range 断点续传、自定义 CORS 响应头、
   按路径或后缀设缓存 TTL、边缘缓存 7 天）；动态 API 不缓存、HTTPS 回源到香港；WebSocket 加速。
4) 证书与切流：支持自有证书上传或免费证书；CNAME 切换与灰度能力（同一主域下多个子域能否分批切）。
5) 计费与配额：大陆节点流量/带宽单价、计费方式、是否保底或预充、限速与应急扩容；
   能否先给测试额度，我们先拿 1~2 个域名压测。
6) 管理：能否开子账号 + API/密钥（我们要脚本化下发配置和巡检），以及访问日志导出方式。

四、群内短版（不想发长文时用）

补充下我们的情况，一张图说明：

  玩家(大陆) --> Cloudflare --> AWS S3 大阪   静态资源（现在绕路，大陆体验不好）
  玩家(大陆) --> Cloudflare --> 香港自建入口 --> 香港后端   动态 API/WebSocket（源站在香港）

想改成「多家 CDN 一起上，免备案优先，先国际版腾讯和 CF」：

  玩家(大陆) --> 项目代码智能调度（多 CDN 域名竞速）
                   |
                   +--> 渠道A 腾讯云国际版（先国际版，若能备案再国内版）
                   +--> 渠道B HansCDN + 回国优化线路
                   +--> 渠道C Cloudflare（兜底）
                        |
                        +-- 静态回源大阪 S3（首次回源，之后吃边缘缓存 7 天）
                        +-- 动态回源香港后端（API/WebSocket 不缓存）

三个关键点请帮忙确认：
1) 不备案的前提下，你们哪些 CDN/线路能把大陆三网覆盖做好？各自覆盖和延迟大概什么水平？
   我们域名是境外注册、没有大陆备案，腾讯云大陆节点要备案的话就先不用它；
2) 多家 CDN 怎么按运营商/地区分线路调度，切换和回滚要多久？
   源站在大阪 S3 + 香港后端，各家回源限制和延迟多少，能不能回源到香港/新加坡中转；
3) 先给测试额度，我们拿一两个域名实测覆盖再决定整体切流。

五、内部备注（不发给对方）

0. 策略口径（2026-09-29 更新）：**多 CDN 渠道 + 免备案优先**，目标是「把大陆覆盖补齐」，
   不把方案押在备案上；备案只作为「能过就加一条大陆节点快路」的加强项。
   实现手段两条腿：
   a) DNS 侧：按地区/运营商分线路（智能解析/加权 CNAME），大陆走覆盖最好的渠道；
   b) 客户端侧：我们自己控制游戏客户端，可以在客户端做多域名/多 CDN 并发测速择优 + 失败自动换线
      —— 这是最直接有效的「多 CDN」，不依赖任何备案，也不依赖单家厂商。
1. 备案是硬前置，且卡点在「域名注册商」而不只是主体：
   大陆 CDN 节点按政策必须 ICP 备案，备案需要域名注册商是工信部批准的机构。
   hkcloudplay0N.com 若在境外注册商（Cloudflare/GoDaddy 等），通常无法提交备案 ——
   要么把域名转入国内注册商（腾讯云/阿里云）再备案，要么另注册可备案域名承载大陆流量（改域名成本高）。
   需先确认：这几个域名的注册商是谁（whois），以及公司是否愿意用大陆主体备案。
2. 免备案可用的渠道候选（评估用，别对外承诺名单）：
   a) 香港/新加坡节点 + 回国优化线路（CN2 GIA / 移动优化 / 联通优化一类的精品线路）；
   b) 国际大厂的境外节点（Cloudflare / Akamai / CloudFront / CDNetworks / 腾讯云国际版等），
      大陆用户实际落到香港/日本/新加坡节点，覆盖好坏按运营商差异明显，必须实测；
   c) 大陆节点（腾讯云/阿里云境内）一律要备案，不列入免备案路线。
3. 若备案走不通或来不及，替代组合（按性价比）：
   a) 动态 API / WebSocket 走「全球应用加速 GAAP」跨境专线：不需备案、走专线，正好治晚高峰抖动；
   b) 静态源从大阪挪到腾讯云 COS（香港/新加坡）+ 国际版 CDN 境外节点，回源就近；
   c) 大陆侧自建/租用备案域名的加速域名做「静态壳」，只用于资源下载。
4. 验收口径：多 CDN 的价值必须实测——按大陆三大运营商各省抽样（或让测试同学用多省节点）
   分别测各渠道的解析结果、首包/下载耗时、丢包率，再决定分线路规则；不要只看厂商 PPT。
5. 对外只说「面向大陆玩家的手机游戏 / 游戏客户端资源」，不要写具体厂商名、桶名、内网 IP、
   业务性质描述（对方已在群里问过「直播？老虎机？」，回复保持在「游戏客户端资源 + 动态 API」即可）。
6. 现有可复用事实（本仓库）：
   - 静态链路与域名归属：docker/doc/2026-09-24-1119-【问题排查】香港CN国内域名客户端资源托管归属核验记录.md
   - 静态前缀与源站映射：docker/deploy/hongkong/hk_static_worker.js（PREFIX_MAP，13 前缀 -> bizops-s3-* 大阪桶）
   - 香港自建入口与后端：docker/workbench/CURRENT_STATE.md「环境」「当前动态端口」
