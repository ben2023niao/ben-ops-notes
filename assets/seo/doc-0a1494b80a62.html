用途

这份文档用于把测试环境已经完成的 workbench/ 轻量运维工作台，按同样思路复刻到线上环境 main 分支。

目标不是复制测试环境事实，而是复制工作台结构和工作方法，然后把内容替换为线上环境实时核验后的事实。

线上落地前必须确认

cd /Users/ben/Documents/ben/docker/main/docker-youdianse-php
git status --short --branch
git log -3 --oneline

注意：2026-07-29 在测试环境编写本文时，只读观察到本地线上仓库 main 已存在未提交变更和大量文档重命名痕迹。线上复刻前必须先确认这些变更是否属于当前用户的工作：

如果是用户正在处理的变更：不要覆盖、不要回滚，基于现状继续。
如果是已完成但未提交的文档重命名：先让用户确认是否提交。
如果不确定来源：停止写操作，先问用户。

不要在未确认 dirty workspace 来源时执行：

git reset --hard
git checkout -- .
git clean -fd

文件内容映射

START_HERE.md

用途：新会话统一入口，只写读取顺序、工作原则、风险等级、事实状态和常用入口。

线上差异：

标题：游点涩线上环境轻量运维工作台
默认分支：main
默认原则：本仓库对应线上环境，生产写操作必须先得到用户批准。
通知规则：沿用线上仓库 AGENTS.md；如果线上 AGENTS.md 没有逐步通知规则，应先补齐或按线上既有通知规则执行。

必须包含：

事实优先级：实时只读核验 > 当前 Git/服务器状态 > CURRENT_STATE.md > CURRENT_TASK.md > 历史文档 > 聊天记录
风险等级：R0 / C1 / P2 / D3 / E4
秘密边界：不保存密码、token、Secret Key、私钥正文、完整 Signed URL

CURRENT_STATE.md

用途：保存线上当前可快速恢复的事实，不写历史流水账。

需要实时核验后写入：

项目：游点涩线上环境
运维仓库 remote / branch / commit
业务仓库 remote / branch / commit
线上服务器角色、公网 IP、内网 IP、hostname
宝塔、后端、前端职责边界
CICD、后台、H5、API、定时任务入口
当前容器名称、端口、镜像和运行状态
关键路径：运维仓库、业务仓库、env、secrets.env、logs、Nginx 配置
最近一次验证时间、验证命令和结果
最近完成的线上变更文档和提交

线上环境不要直接复制测试环境的：

38.92.8.34
youdianse-test
youdianse-dev-php-*
env/.env.dev
cron.youdianse-test.xyz
cicd.youdianse-test.xyz

应替换为线上事实，例如线上仓库已有文档中记录的宝塔、后端、前端机器和 main 容器，但写入前仍要实时只读核验。

CURRENT_TASK.md

用途：记录当前任务、最后安全点、下一步和本地特殊状态。

线上建议初始内容：

当前没有正在执行中的生产操作。
最后安全点：只读核验完成，未执行生产写操作。
当前待注意事项：本地 main 工作树是否存在未提交变更。
下一步建议：按用户目标生成 context / plan / manifest。

如果线上分支已有未提交改动，必须写进：

本地工作树存在未提交变更，来源待确认；后续提交不得误带无关文件。

ACTIVE_TASKS.md

用途：保存仍需推进的任务和已完成任务索引。

线上建议：

当前活跃生产任务：无 / 待确认
待办：线上 workbench 首次只读核验、未提交变更归属确认、服务器状态巡检
已完成但需保留索引：线上服务器详细信息文档、文档命名规范、最近生产变更

DECISIONS.md

用途：记录用户已确认的业务/架构/运维决策。

线上必须写清：

线上环境生产写操作必须由用户批准。
文档文件名使用 YYYY-MM-DD-HHMM-【分类】线上环境标题.md。
工作台不保存秘密正文，只保存秘密位置。
历史文档不是执行授权。
生产变更必须有备份、验证和回滚设计。

MACHINE_ACCESS_MATRIX.md

用途：机器和权限矩阵，只记录秘密位置，不记录秘密正文。

线上应写：

宝塔入口服务器
后端服务器
前端服务器
SSH 用户
公网 IP
内网 IP
hostname
登录凭据索引：例如仓库根目录私钥文件名、服务器本地 secrets.env 路径或安全保管位置
状态：VERIFIED / USER_CONFIRMED / UNKNOWN

禁止写入：

SSH 密码
私钥正文
Telegram token
chat_id
发布口令
带凭据 Git URL
数据库密码

PROJECT_RUNTIME_CHAINS.md

用途：线上运行链路快速版。

线上应写：

公网用户 / CDN / DNS
  -> 宝塔入口
  -> H5 前端
  -> 后端 API
  -> CICD Web
  -> 外部定时任务系统

并列出：

域名到目标机器/端口映射
H5 页面链路
H5 API 分流链路
后端 Docker 链路
php-cron / queue-watchdog 链路
配置发布链路
业务发布链路
标准验证命令

AUDIT_CONFLICTS.md

用途：记录冲突、风险和停止条件。

线上应至少包含：

本地 main 工作树存在未提交变更时，不得误清理或覆盖。
线上/测试环境混淆风险。
多机器环境下宝塔、后端、前端职责混淆风险。
敏感信息误提交风险。
生产写操作未批准时必须停止。

handoff 模板

模板可以从测试环境复制，但要把默认项目改成：

项目：游点涩线上环境
环境：线上环境 / main

并保留：

context
plan
manifest.json
result

建议执行步骤

步骤 1：只读核验线上仓库

cd /Users/ben/Documents/ben/docker/main/docker-youdianse-php
git status --short --branch
git remote -v
git branch --show-current
git log -3 --oneline
find . -maxdepth 2 -type f -name 'AGENTS.md' -o -name 'README.md'

完成条件：

确认当前仓库是线上 main。
确认 dirty workspace 来源。
确认本次只新增/修改 workbench 和 README 快速入口。

步骤 2：只读核验线上服务器

根据线上 ops/production/ 文档和机器矩阵候选信息，逐台只读核验：

hostname
whoami
pwd
df -hT /
docker ps
ss -lntp

后端运维仓库：

cd /opt/docker-youdianse-php
git status --short --branch
git rev-parse --short HEAD
docker compose ps

完成条件：

宝塔、后端、前端角色确认。
线上域名和本机端口确认。
当前容器和关键路径确认。

步骤 3：创建线上 workbench

复制测试环境结构，但重写事实内容：

mkdir -p workbench/handoff/to-cc workbench/handoff/from-cc workbench/handoff/templates
touch workbench/handoff/to-cc/.gitkeep
touch workbench/handoff/from-cc/.gitkeep

建议从测试环境复制模板：

cp /Users/ben/Documents/ben/docker/dev/docker-youdianse-php/workbench/handoff/templates/* workbench/handoff/templates/

然后逐个替换：

测试环境 -> 线上环境
dev -> main
测试服务器 -> 宝塔 / 后端 / 前端
测试域名 -> 线上域名
测试容器 -> 线上容器

步骤 4：更新 README 入口

在线上 README.md 前部新增：

## AI 快速入口

新会话优先读取轻量工作台：

workbench/START_HERE.md
workbench/CURRENT_TASK.md
workbench/CURRENT_STATE.md
workbench/MACHINE_ACCESS_MATRIX.md
workbench/PROJECT_RUNTIME_CHAINS.md
workbench/DECISIONS.md

步骤 5：验证

git diff --check -- README.md workbench
python3 -m json.tool workbench/handoff/templates/TASK-manifest.template.json >/tmp/youdianse-main-manifest-check.txt

相对链接检查：

perl -ne 'while (/\\[[^\\]]+\\]\\(([^)#][^)]+)\\)/g) { next if $1 =~ m{^(https?://|mailto:|/)}; print "$ARGV\\t$1\\n" }' README.md workbench/*.md workbench/handoff/*.md workbench/handoff/templates/*.md | while IFS=$'\\t' read -r file link; do base=$(dirname "$file"); target="$base/$link"; if [ ! -e "$target" ]; then echo "missing_link $file -> $link"; fi; done

敏感信息扫描：

rg -n "BEGIN (RSA|OPENSSH) PRIVATE KEY|[A-Za-z0-9_-]{35,}:[A-Za-z0-9_-]{20,}|password\\s*=\\s*[^.<\\s][^\\s]*|token\\s*=\\s*[^.<\\s][^\\s]*|chat_id\\s*=\\s*[-0-9]+|Secret Key|Access Key" README.md workbench -g '*.md' -g '*.json'

说明：如果只命中“不得写入 Secret Key / token”的禁止说明，可人工判定通过；不得命中真实秘密值。

步骤 6：提交推送

只暂存本次 workbench 相关文件，避免带入其他 dirty 变更：

git add README.md workbench
git status --short
git diff --cached --stat
git commit -m "docs: add lightweight ops workbench"
git push origin main

如果线上仓库已有无关未提交变更，必须用明确路径 git add README.md workbench，不要使用：

git add .

步骤 7：通知与附件

按线上仓库通知规则发送总结，至少包含：

【线上环境｜步骤 N 完成】轻量工作台提交总结
完成内容：新增线上环境轻量运维工作台 v1，并更新 README AI 快速入口。
验证结果：链接检查、敏感扫描、JSON 模板校验、git diff --check 通过。
当前版本：<commit>
文档路径：workbench/START_HERE.md
下一步动作：后续新会话优先读取 workbench/START_HERE.md。

如果线上通知规则要求附件，同时发送：

workbench/START_HERE.md

或另写线上事件文档：

docs/YYYY-MM-DD-HHMM-【运维记录】线上环境轻量运维工作台改造记录.md

可直接给 Codex 的复刻提示词

请在 /Users/ben/Documents/ben/docker/main/docker-youdianse-php 的 main 分支，参考测试环境提交 96bf28b 和文档 docs/2026-07-29-1944-【运维记录】测试环境到线上环境轻量工作台改造复刻详细说明.md，给线上环境落地轻量 workbench。

1. 先读 AGENTS.md，确认线上通知规则。

8. 只 git add README.md workbench，不要 git add .。
9. 提交信息使用 docs: add lightweight ops workbench。
10. 按线上规则发送 Telegram 总结；如果需要附件，发送 workbench/START_HERE.md 或事件文档。

验收标准

线上复刻完成后，应满足：

workbench/START_HERE.md 存在，并且 README.md 有 AI 快速入口。
CURRENT_STATE.md 记录的是线上 main 的实时事实，不含测试环境 IP 或测试容器名。
MACHINE_ACCESS_MATRIX.md 只记录秘密位置，不含秘密正文。
PROJECT_RUNTIME_CHAINS.md 能快速说明线上宝塔、后端、前端和域名链路。
CURRENT_TASK.md 能让新会话知道最后安全点和下一步。
handoff/templates/TASK-manifest.template.json 是合法 JSON。
敏感扫描未发现真实秘密。
提交只包含 README.md 和 workbench/，除非用户明确批准附加事件文档。
