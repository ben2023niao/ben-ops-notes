B1【已关闭】竞猜活动列表 — 后端已按契约修复

  • 黑盒 GET /api/v1/predict/activities?page=1&size=2：返回 match_brief/name/market_type/pool_total/participant_count/rake_rate/open_at/open_ts/close_at/close_ts，含嵌套 options[]（option_key/name/rate/pool_amount/participant_count）与 result_option_key，完全符合 PredictActivity 契约，旧字段（title/category/close_at_ms 等）已消失。
  • UI：首页「热门竞猜」+ /predict 列表队名、玩法、赔率、状态分桶（进行中 1 / 未开始 0 / 待开奖 1 / 已开奖 3）均正常渲染，无空值、无 SSR 500。
  • 证据：.playwright-mcp/screenshot/verify-predict-list-B1.png

B3【已关闭】个人资料 — 后端已返回 id + 嵌套 wallet

  • 黑盒 GET /api/v1/me/profile：返回 id（非 user_id）+ 嵌套 wallet:{rmb_balance,rmb_frozen,rmb_withdrawable,diamond_balance}，符合 UserProfile 契约。
  • UI：/member 顶部 UID 正常显示（21086007738761217，不再是 --），钱包余额 / 可提现 / 累计消费均正确读取嵌套 wallet。

B2【代码已修，待 dev 通道启用】充值 — 后端改契约，前端本轮对齐

根因变化

后端没有把字段改回旧契约，而是更新了契约源（packages/contracts/openapi/v1.yaml + docs/api/openapi.yaml，见 2026-05-26-web-contract-feedback-recheck.md）：

RechargeInitRequest.required = [rmb_amount, channel, pay_type, agree_terms]
  rmb_amount  : string, 10.00-50000.00
  channel     : enum [shark]
  pay_type    : enum [alipay, wechat, union, usdt, dyhbPay, digitalRmb]
  agree_terms : boolean

前端代码仍发旧字段 → 被拒。属正常红方待办：契约已更新，前端按新契约对齐（非写转换器迁就错误返回）。

复验取证（修复前）

  • 浏览器走「member → 充值 → 立即支付」，请求体 {"amount_rmb":"100.00","channel":"wechat"} → HTTP 400
  • 响应：参数 channel 取值必须是 [shark] 之一; 参数 rmb_amount 必填; 参数 pay_type 必填; 参数 agree_terms 必填
  • 证据：.playwright-mcp/screenshot/verify-recharge-fail-B2.png

本轮前端修复

文件 改动
apps/web/shared/types/wallet.ts RechargeInitRequest 改为新契约形状（rmb_amount/channel:shark/pay_type/agree_terms），新增 RechargeChannel/RechargePayType 类型
apps/web/app/pages/recharge/qr.vue 下单体改为新契约；支付方式映射为 pay_type（wechat→wechat/alipay→alipay/union→union/ecny→digitalRmb），channel 恒为 shark，agree_terms:true（入口页已展示充值协议同意文案）
apps/web/app/layouts/default.vue 充值入口 query 透传完整支付方式，不再把 union/ecny 塌成 wechat

复验取证（修复后）

  • 请求体 {"rmb_amount":"100.00","channel":"shark","pay_type":"alipay","agree_terms":true} → 参数校验通过，进入支付层
  • 响应：code 10001 大白鲨支付通道未启用（dev 环境通道未开）
  • UI：付款码页失败态优雅显示「充值失败 · 大白鲨支付通道未启用」，无崩溃
  • 证据：.playwright-mcp/screenshot/verify-recharge-B2-fixed-channel-disabled.png

附带发现（次要，非阻断）

  1. 注册接口错误文案字段名误印：POST /api/v1/auth/register 缺 agree_18plus 时，错误文案打印为「参数 agree_18_plus 必填」（多了下划线）。后端 binding 实际正确识别契约字段 agree_18plus，仅错误消息把 Agree18Plus 错误蛇形化为 agree_18_plus。属与 B2 同类的首字母缩写蛇形化文案问题，建议后端按 binding.go 既有修复方式一并处理。前端无需改动。
