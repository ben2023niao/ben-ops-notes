项 内容
日期 2026 年 10 月 16 日
事项 ben-bot 代码按日期打包，发到 Telegram 报警群；并配置每天 09:00 自动发送
报警群 BKLUAT ALARM　chat_id -1004438007285

一、需求

  1. 把全部代码打包，文件名带日期。
  2. 发到飞机群。
  3. 每天早上 9 点自动发一次。

二、做法

1. 备份脚本

位置 说明
仓库内 code/ben-bot-运维机器人/scripts/daily_code_backup.sh（跟代码一起版本管理）
服务器 /opt/ben-bot/scripts/daily_code_backup.sh
产物目录 /opt/ben-bot-backup/，只保留最近 7 份（CODE_BACKUP_KEEP 可调）
运行日志 /var/log/ben-bot-code-backup.log

脚本做的事：按 Shanghai 时区取当天日期 → 打包 app / data/scripts / docker / deps / deploy.sh / README.md（跳过 __pycache__、*.pyc、data/upload）→ 用 Telegram sendDocument 发到报警群 → 检查返回里是否 "ok":true 并把结果写日志 → 清理旧包。

文件名格式：ben-bot-代码-2026年10月16日.zip。

2. 定时任务

位置：/etc/cron.d/ben-bot-code-backup

# 服务器时区是 UTC：01:00 UTC = 09:00（Asia/Shanghai）。改了服务器时区要同步改这里。
0 1 * * * root /opt/ben-bot/scripts/daily_code_backup.sh >> /var/log/ben-bot-code-backup.log 2>&1

三、时区这个坑（重要）

服务器时区是 Etc/UTC，团队作息按 Asia/Shanghai。原本想用 CRON_TZ=Asia/Shanghai + 0 9 * * *，实测这台机器（Ubuntu 24.04 自带 cron）不认 CRON_TZ：设了 3 分钟后的测试任务，到点没触发。

所以改成按服务器本地时间换算：09:00 上海 = 01:00 UTC，cron 写 0 1 * * *；脚本内部仍用 TZ=Asia/Shanghai 取日期，保证文件名和日志日期符合团队作息。

四、验证

  1. 手动执行脚本：输出 发送成功，日志记录 … ben-bot-代码-2026年10月16日.zip（80K）发送成功，依据是 Telegram 返回里的 "ok":true。
  2. cron 触发验证：临时建了一个 2 分钟后执行、只写文件的测试任务，到点正常触发，说明 /etc/cron.d + root + 脚本路径这条链路没问题（测试任务已删除）。
  3. 本地也存了一份：dist/ben-bot-代码-2026年10月16日.zip。

五、后续

  1. 换发送目标：改脚本里的 CODE_BACKUP_CHAT_ID，或在 cron 里传环境变量。
  2. 换时间：改 /etc/cron.d/ben-bot-code-backup（记得按 UTC 换算）。
  3. 保留份数：CODE_BACKUP_KEEP（默认 7 份）。
  4. 以后代码改用 GitLab 托管后，这套每日备份可以继续留作离线留痕，也可以改成从 GitLab 导出。
