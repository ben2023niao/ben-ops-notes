背景

2026-11-10 对 789Bingo 的 Web、子域、公开搜索面和 Android 3.0.11 客户端做了分阶段核验。评估重点是确认公开资产边界、客户端会话安全、身份认证回跳、聊天鉴权、上传入口和更新链路，不执行登录态越权、支付操作、用户数据读取或破坏性测试。

结论摘要

  1. 公开主站由 Cloudflare 代理，未从公开 DNS、历史索引和对象存储对照中得到可信的当前源站地址。
  2. 主站 HTTPS、证书、跳转和多项浏览器安全头正常，未发现开放目录、公开 source map、接口文档或敏感备份索引。
  3. 子域评估发现 UAT 环境公开、支付域路由过宽、CORS Origin 不够严格、WebSocket Origin 未校验以及上传写入口需要重点复核。
  4. Android 客户端签名与 App Links 归属链完整，生产环境固定；但 KYC 回跳的 origin 校验、本地会话存储、自更新完整性和 H5 Bridge Token 权限仍有整改空间。
  5. 聊天客户端按当前登录会话换取聊天凭据，未发现客户端直接指定其他用户 ID 的入口；服务端 IDOR、频道权限和管理员动作仍需用隔离测试账号做 A/B 验证。
  6. 公开搜索只确认博客使用 WordPress；未发现公开的游戏运营、支付、财务或客服总后台。

风险优先级

优先级 事项 当前判断
P0 KYC 回跳必须绑定精确 HTTPS Origin 和一次性短时凭据 静态审计发现需要优先修复的条件性风险
P0 确认供应商客户端参数是否为长期秘密 若属于共享密钥，应立即轮换并改为服务端短时签发
P1 UAT 访问控制、支付域路由、WebSocket 与上传鉴权 需要结合服务端配置和授权账号复核
P1 Token 安全存储、更新包完整性、全局明文 HTTP 客户端安全边界需要收敛
P2 CSP、DMARC、CAA、DNSSEC、安全联系渠道 属于域名治理和防御纵深提升

证据边界

  • “未发现”只表示在公开证据、APK 静态代码和可读取配置中没有发现，不等于运行时绝对不存在。
  • WebSocket 可以完成握手，不代表聊天鉴权缺失；上传接口可以预检，不代表存在未授权写入。
  • CORS 返回了某个 Origin，不代表未知来源一定可以读取响应，必须结合实际浏览器凭证和 ACAO 匹配规则判断。
  • CVE 匹配必须以精确组件、版本和调用路径为依据，不能仅凭框架或依赖名称推断命中。
