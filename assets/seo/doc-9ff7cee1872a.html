操作范围

本次仅调整巴西两台后端服务器的日志保留策略，不修改业务代码、数据库、Redis、Nginx 和域名配置。

角色 hostname 公网 IP

操作采用逐台滚动方式：先完成后端 01 的配置、Docker 重启、日志轮转和健康验证，再处理后端 02，避免两台后端同时重启。

操作前检查

操作前两台服务器均未配置业务日志 7 天清理、Docker JSON 日志大小限制和 journald 容量上限。

仓库中原有的 168h 清理仅用于磁盘使用率达到阈值后的旧 Docker 镜像和构建缓存，不会清理 /opt/pgserver/logs 业务日志。

已落地配置

业务日志

配置文件：/etc/bizops-logrotate/pgserver

策略如下：

  • 匹配 /opt/pgserver/logs/*/*.log。
  • 每天轮转；单文件超过 1GB 时由小时任务提前轮转。
  • 轮转文件最多保留 7 天，使用 gzip 压缩。
  • 使用 copytruncate，不要求业务进程重新打开日志文件。
  • 使用日期和时间后缀，避免同一天内大文件多次轮转时重名。
/opt/pgserver/logs/*/*.log {
    su root root
    daily
    rotate 200
    maxage 7
    maxsize 1G
    missingok
    notifempty
    compress
    copytruncate
    dateext
    dateformat -%Y%m%d-%H%M%S
}

Docker 日志

Docker daemon 配置文件：/etc/docker/daemon.json

{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "100m",
    "max-file": "7"
  }
}

该配置对后续新建或重新创建的容器生效。现有业务容器没有为修改日志参数而强制重建，改由 /etc/bizops-logrotate/docker-json-existing 对现有 JSON 日志执行 100MB × 7 外部轮转；业务正常发布并重建容器后，会自动使用 Docker daemon 内建轮转参数。

journald

配置文件：/etc/systemd/journald.conf.d/99-bizops-retention.conf

[Journal]
SystemMaxUse=1G
SystemKeepFree=10G
MaxRetentionSec=7day
MaxFileSec=1day
Compress=yes

journald 最长保留 7 天，总占用上限 1GB，同时为根磁盘至少保留 10GB 空闲空间。

定时任务

新增 systemd 单次任务和定时器：

/etc/systemd/system/bizops-log-maintenance.service
/etc/systemd/system/bizops-log-maintenance.timer

定时器每小时执行一次，并增加 0 至 5 分钟随机延迟，依次处理业务日志、现有 Docker JSON 日志和 journald。定时器已设置为开机自动启用，并使用独立 logrotate 状态文件，避免与系统默认 logrotate 任务冲突。

业务健康验证

两台服务器均完成以下检查：

  • bizops-* 业务容器运行数量为 7。
  • TCP 8765、9090、9091、9096、9101、9102、9103、9104 全部连通。
  • bizops-log-maintenance.timer 状态为 enabled 和 active。
  • 首次执行和第二次幂等复跑均为 Result=success、ExecMainStatus=0。
  • 使用临时容器验证 Docker daemon 默认日志参数，两台均返回：
{"Type":"json-file","Config":{"max-file":"7","max-size":"100m"}}
  • 两台六份配置文件 SHA-256 完全一致。
  • 配置完成后再次检查，业务容器数量和全部八个端口仍正常。

常用复核命令：

systemctl status bizops-log-maintenance.timer --no-pager
systemctl list-timers bizops-log-maintenance.timer --no-pager
systemctl start bizops-log-maintenance.service
systemctl show bizops-log-maintenance.service -p Result -p ExecMainStatus
du -sh /opt/pgserver/logs
journalctl --disk-usage
find /opt/pgserver/logs -type f -name '*.log' -mtime +7

备份与回滚

操作前配置和 Docker 容器 inspect 信息已分别备份：

后端 01：/root/bizops-log-retention-backup-20260715_151804
后端 02：/root/bizops-log-retention-backup-20260715-152400

如需停用本次策略，可先执行：

systemctl disable --now bizops-log-maintenance.timer
rm -f /etc/systemd/system/bizops-log-maintenance.timer
rm -f /etc/systemd/system/bizops-log-maintenance.service
rm -rf /etc/bizops-logrotate
rm -f /etc/systemd/journald.conf.d/99-bizops-retention.conf
rm -f /etc/docker/daemon.json
systemctl daemon-reload
systemctl restart systemd-journald
systemctl restart docker

如果服务器操作前已有同名配置，应从对应备份目录恢复，而不是直接删除。回滚 Docker 时仍应逐台执行，并在每台完成七个容器和八个端口检查后再处理下一台。
