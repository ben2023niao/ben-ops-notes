一、目标

原 ben-bot 面向发布、配置查看、脚本执行等一堆功能。这次给 UAT 单独做一份精简版：

  1. 主菜单只留「📅 运维值班表」一个功能按钮 + 「🖥 堡垒机」「📊 监控」两个链接按钮。
  2. 帮助页只讲值班表。
  3. 值班人只有 @Ben_Bird，工作时间 09:00-19:00，每周日单休。
  4. /start 显示当前信息（用户、用户ID、身份、权限、聊天ID、聊天类型；群里额外显示群名称）。

二、代码改动

文件 改动
app/benbot/constants.py 项目 token 统一成 8811246714:...（本地/线上一致）；VISIBLE_TOP_LEVEL_DIRS 顶层菜单白名单；OPS_USERNAMES 只留 Ben_Bird；BACKEND_USERNAMES 加入 SVDSeven / brenttto / Markwu999；版本 v1.0.3
app/benbot/plugin_registry.py 顶层只放行白名单目录；目录节点也支持 action=link + url（给堡垒机/监控按钮用）
app/benbot/permissions.py 运维和后端都算"全部权限"；其他人只能看值班表；目录节点按角色过滤（原来 category 一律放行，是个漏洞）；/sh 权限放开给后端
app/benbot/home.py /start 重写：当前信息卡片 + 按角色渲染按钮（link 节点直接给 URL 按钮，点开就是 Telegram 内嵌浏览器）
app/benbot/help_center.py 帮助内容只讲值班表 + 命令说明
app/benbot/duty_status.py 重写为单人值班：09:00-19:00、周日单休、按日期覆盖（rest_by_date / duty_by_date）；值班提醒事件改为 08:30 / 09:00 / 19:00；DUTY_NOTIFY_CHAT_IDS 指向报警群
app/benbot/main.py 去掉无关 handler（/download、上传、文本处理、/script），保留 /start /help /id /sh；启动通知改成只在配置了目标时发那些会话；启动文案改成值班表口径
data/scripts/运维值班表/ weekend_duty.json 单人配置；duty_schedule.py 重写（可单独执行，输出文本或 JSON）；benbot_plugin.py 重写（渲染 + 刷新按钮）
data/scripts/堡垒机/.benbot.json、data/scripts/监控/.benbot.json 新增两个链接入口（action=link + url）

三、部署

  • 服务器：堡垒机 /opt/ben-bot，docker compose -f docker/docker-compose.yml up -d --build（脚本 deploy.sh）。
  • 本地留一份精简版：code/ben-bot-运维机器人/（含 README、deploy.sh），与原项目 Documents/ben/自动化发布/.../ben-bot 保持同步。
  • 机器人是主动轮询 Telegram，不占端口。
  • compose 里 TELEGRAM_API_TOKEN 用 `${[敏感内容已脱敏] 默认报警群。

四、踩的坑

  1. 目录节点权限一律放行：can_access_menu_node 里 kind in {"root","category"} 直接 return True，导致访客也能看到堡垒机/监控按钮。改成目录按角色判断路径。
  2. 启动通知刷屏：默认发给所有已知会话（当时有 4 个），改成"配置了 STARTUP_NOTIFY_CHAT_IDS 就只发这些"。
  3. 一个 token 只能一个实例轮询：这个 token 同时给监控告警发消息（只发不收，不冲突），但不能再起第二个 ben-bot，否则互相抢更新；本地调试要用另一个 token。
  4. Compose 空环境变量：[敏感内容已脱敏] token 覆盖成空字符串导致启动失败，改用${VAR:-默认值}` 写法。

五、后续

  1. 值班提醒目前只发报警群，如需发到其他群改 DUTY_NOTIFY_CHAT_IDS。
  2. 需要更多入口时，在 data/scripts/ 下加目录 + 白名单即可。
