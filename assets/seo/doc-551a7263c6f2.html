整理日期：2026-10-10 13:40｜日期依据：文件名日期

时间：2026-10-10 13:40（北京）/ 05:40（UTC） 需求（群里逐步明确）：

1) 每天北京时间 15:00 发头一天的错误日志
2) 时间换算成北京时间（日志本身是 UTC）
3) 巴西项目 + 香港项目都要，且要标识「项目」和「后端 01/02」
4) 群里只发错误日志，别加废话
5) 错误日志从 01/02 上传到 **AWS S3**（专门放日志的桶）→ 群里发**各厂家的 S3 下载链接**
   → 上传成功就删除本地错误日志文件
6) 日志不要再发运维内部群（调试期误发过，已停止）

状态：脚本 + 四台机器的定时任务都已上线并实测跑通； 唯一待办是目标群（后端技术群）的 chat_id（拿到前定时任务带 --no-notify，只上传不发群）。

一、最终方案（S3 + 预签名链接）

01/02（巴西 07:00 UTC / 香港 15:00 CST，同一时刻 = 北京 15:00）
  → 逐厂家抽「北京昨天」全天错误记录（整条记录，保留完整 Traceback）
  → 行首时间戳换算北京时间（+0800）
  → 每个厂家单独 gzip
  → aws s3 cp 上传到 s3://dbqp-backend-game-logs-176528004422/error-packs/<项目>/prod-XX/<北京日期>/<厂家>.log.gz
  → aws s3 presign 生成 7 天预签名下载链接
  → 群里发一条消息：项目 + 后端 + 日期 + 每个厂家的条数与下载链接
  → 该厂家上传成功后删除本地那份临时文件（源日志 /data/server-runtime/logs 只读、不动）

桶：沿用现成的日志桶 **dbqp-backend-game-logs-176528004422**（ap-northeast-3），
    用独立前缀 `error-packs/` 与既有归档日志分开。
    （该 IAM 用户没有 s3:CreateBucket 权限，实测 AccessDenied，所以没法另建新桶；
      若确实要独立桶，需 AWS 侧补权限或控制台新建。）
凭据：/etc/dbqp-game-log-s3.env（IAM user s3-game-prod，600）
    巴西 01/02 本来就有；香港 01/02 原先没有 aws cli 与凭据 → 已装 awscli 并从巴西 01
    复制同一份凭据（写入探针已通过）。

二、为什么不用 GCS（先评估过，已放弃）

· 巴西 01/02、香港 01/02 的 VM access scope 都是 **devstorage.read_only**：
  既不能 `buckets create`（403 Provided scope(s) are not authorized），也不能写对象。
  只有宝塔和巴西 03 的 scope 是 cloud-platform（实测能写）。
· 该 SA 也签不了 URL（缺 iam.serviceAccounts.getAccessToken，自 impersonate 亦被拒）。
· 现有 GCS 桶全是私有的（匿名 403）。
→ 要满足「01/02 自己上传 + 群里能直接下载」，GCS 侧至少需要控制台改权限/发密钥；
  S3 侧用现有凭据零改动即可，且预签名链接实测可用，故改 S3。

三、脚本：docker/scripts/daily_vendor_error_pack.py

厂家 ↔ 日志目录（用各目录 Traceback 里的 /app 路径实测确认）
  巴西：api->logs/main（/app/platform-api/）  pg->logs/server（/app/pg/）
        tada->logs/tada（tada 主服务与 tada_ws 混在同一目录）
        ppk/pp/playson/panda/g759 -> 同名目录
  香港：api->main  pg->server  jili->jili（/app/tada/，香港的 TADA 家族厂家）
        tada_ws->tada（目录可能未生成，自动跳过）  ppk/pp/playson/panda/g759 -> 同名目录

关键实现点
  · 项目/后端标识：按主机名识别（dbqp-saopaulo-* / dbqp-hongkong-*；后缀 -01/-02）→
    消息标题「巴西项目 prod-01｜错误日志 2026-10-09（北京时间）」、key 路径含 br|hk + prodXX
  · 窗口：北京 D 日 00:00~23:59 = UTC (D-1)16:00 ~ D16:00
  · 抽取：日志只有记录首行带时间戳（Traceback 堆栈行没有）→ 必须**按记录整条**抽取；
    实现是 awk 扫描源日志（只读）+ Python 处理抽出来的小结果
  · 性能坑：最初 Python 逐行 + 正则 + ionice -c3(idle) 跑 16GB/天 11 分钟未完
    （业务日志持续写盘，idle 级被饿死）；改 awk + `ionice -c2 -n7` → **151 秒**
  · 不上传成功绝不删本地：只有该厂家 s3 cp 返回 0 才删掉它的临时文件
  · 可选 --fallback-document：S3 不可用时退回「tar.gz 直接发群」
  · --no-notify：只上传不发群（当前定时任务就是带这个参数在跑）

五、目标群已确定：监控报警群（并发现该群已升级为超级群，id 变了！）

用户 2026-10-12 指示：链接与每日错误日志都发 **监控报警群**。
发送时发现：**该群已从普通群升级成超级群（supergroup），chat_id 变了**——
  旧 id：-5203304347
  新 id：-1004456082456      （getChat 确认 title=监控报警群、type=supergroup）
  旧 id 发送会报：400 Bad Request: group chat was upgraded to a supergroup chat
                 （附带 migrate_to_chat_id=-1004456082456）

影响面（重要）：所有机器上的 /opt/benbot-runtime.env 里
  BEN_BOT_MONITOR_CHAT_ID / STARTUP_NOTIFY_CHAT_IDS 都还是旧 id，
  也就是说**这期间如果任何监控要发告警，都会发失败**。
  已排查：容器监控、权限自愈、重启监控、入口探活 的日志里**没有发送失败记录**，
  说明这段时间它们没有触发过告警 —— 没有真的丢告警，但隐患已消除。

已做的修正（2026-10-12）：
  1) 7 台机器的 /opt/benbot-runtime.env 全部把旧 id 替换为新 id（各改 2 处：
     BEN_BOT_MONITOR_CHAT_ID + STARTUP_NOTIFY_CHAT_IDS），改前均备份
     .bak-<时间戳>-before-supergroup-id。
     覆盖：巴西 01/02/03、宝塔、备用入口机、香港 01/02。
  2) 四台后端 cron 去掉 `--no-notify`，改为发群（用 env 里的新 id）。
  3) 实测：BR-01 与 HK-01 各跑一次 → 都成功发到 -1004456082456（ok:true）。
  4) panda 一周日志的两条 S3 链接已发到该群（带文件大小标注）。

⚠️ 后续注意：其它地方如果还有硬编码旧群 id（例如机器人自己的配置、
   其它项目的脚本），应一并替换；判断依据就是 Telegram 报的那句
   "group chat was upgraded to a supergroup chat" + migrate_to_chat_id。

五bis、原来的待办（已解决，保留备查）：目标群 chat_id

要发的是「后端技术群」，但机器人侧拿不到该群 id：
  · bot 源码只调 forget_chat、从不 remember_chat → 群注册表停在 7 月的 4 个老群；
  · getUpdates 被两个实例抢着消费（宝塔主 bot + 入口机备用 bot 同 token 轮询，
    日志里有 "Conflict: terminated by other getUpdates request"），pending = 0；
  · bot 文件日志 9/10 之后未再写入。
请二选一：
  a) 把 @userinfobot / @RawDataBot 拉进「后端技术群」，它会把 group id 打出来，转给我；
  b) 允许我给 ben-bot 加一个 /chatid 命令（改代码 + 重启主/备两个 bot 容器，约 10~20 秒不可用），
     你在群里发 /chatid 即可。
拿到后：把四台 cron 里的 `--no-notify` 换成 `DBQP_ERROR_PACK_CHAT_IDS=<群id>` 即可（我可以直接做），
       定时任务第二天 15:00 就会自动发链接；也可以让我立刻补跑一次把今天的链接发出去。

六、运维手册

# 试跑（只看抽取结果，不上传不发群）
nice -n 10 ionice -c2 -n7 /usr/bin/python3 /opt/dbqp-scripts/daily_vendor_error_pack.py --date 2026-10-09 --dry-run

# 正式跑但暂不发群（当前 cron 就是这个）
nice -n 10 ionice -c2 -n7 /usr/bin/python3 /opt/dbqp-scripts/daily_vendor_error_pack.py --no-notify

# 正式跑并发群
DBQP_ERROR_PACK_CHAT_IDS=<群id> nice -n 10 ionice -c2 -n7 \
  /usr/bin/python3 /opt/dbqp-scripts/daily_vendor_error_pack.py

# 换桶 / 换前缀 / 换链接有效期
DBQP_ERROR_PACK_S3_BUCKET=<桶> DBQP_ERROR_PACK_S3_PREFIX=error-packs \
DBQP_ERROR_PACK_LINK_TTL_SECONDS=604800 ...

# 查已上传的对象
set -a; . /etc/dbqp-game-log-s3.env; set +a
aws s3 ls --recursive "s3://$DBQP_LOG_S3_BUCKET/error-packs/"

# 日志
tail -20 /var/log/dbqp-error-pack.log
