本文记录 2026-07-14 宝塔新增 verify.pgofficialbx.com 后的 Nginx 反向代理、HTTPS、Cloudflare、CORS、双后端连通性验证和飞机群通知结果。

变更背景

新增验证域名：

verify.pgofficialbx.com

域名通过 Cloudflare 代理，宝塔负责 HTTPS 和 Nginx 反向代理，实际请求转发到两台 PG 后端的 9091 端口。

宝塔本机 203.0.113.1:9091 没有服务监听，因此没有直接照搬旧站点的本机代理配置，而是使用双后端 upstream：

34.39.183.154:9091
34.95.230.202:9091

宝塔配置

线上配置文件：

/www/server/panel/vhost/nginx/verify.pgofficialbx.com.conf

原配置备份：

/www/server/panel/vhost/nginx/verify.pgofficialbx.com.conf.bak.20260714-164540

主要配置效果：

HTTP 80 和 HTTPS 443 均监听
HTTPS 启用 HTTP/2
请求按 least_conn 转发到两台 PG 后端
连接失败、超时或 502/503/504 时自动切换后端
OPTIONS 预检直接返回 204
正式请求统一返回 CORS 响应头
隐藏后端原有 CORS 头，避免重复响应头

Nginx 配置检测结果：

nginx: the configuration file /www/server/nginx/conf/nginx.conf syntax is ok
nginx: configuration file /www/server/nginx/conf/nginx.conf test is successful

CORS 验证

对 /history/71.html 发起 OPTIONS 预检请求：

Content-Type: text/plain; charset=UTF-8

Access-Control-Allow-Methods: GET, POST, OPTIONS
Access-Control-Allow-Headers: Content-Type, Authorization
Access-Control-Max-Age: 3600

正常 GET 请求返回：

HTTP/2 200
Access-Control-Allow-Origin: *

Access-Control-Allow-Headers: Content-Type, Authorization

响应中没有重复的 Access-Control-Allow-Origin，也没有通配 Origin 与 Credentials 同时出现的问题。
