工单与目标

参考：测试环境配置抽离独立仓库与 CICD 兼容改造（origin/dev 7a63021 / 4664fca / f981d16）
目标：
1. 新建生产配置仓库 root/docker-youdianse-php-config-main（单分支 main）；
2. 授权 ben / jett / kermit / melo（Maintainer）；
3. 抽离 env/.env.prod + alb_white.txt + alb_white_secret.txt；
4. CICD 兼容独立配置仓库，并支持按配置 git id 发布；
5. 生产禁止自动发布，只能由机器人/运维显式触发；

CICD 兼容改造（生产 main）

新增：
  cicd-web/config_repo.py
    - 拉取配置仓库 main（URL 从运维仓库 origin 推导，含凭据，不落库）；
    - 写 env/.env.prod（0644）；
    - 写 cicd-web/runtime/app-local-files/alb_white*.txt（0600）；
    - 记录 cicd-web/runtime/config-repo.last_commit / last_ref；
    - 支持 ref 指定配置 git id（一次性检出，不写入分支缓存）。

修改：
  cicd-web/config.py
    - 新增 CONFIG_REPO_DIR / URL / BRANCH、APP_LOCAL_FILE_SOURCE_DIR；
    - Telegram 群列表：chat_id + TG_CHAT_IDS + TG_EXTRA_CHAT_IDS 合并去重。
  cicd-web/telegram.py
    - 文本与文档通知按群列表逐个发送（支持双群）。
  cicd-web/core.py
    - 白名单本地源目录机制（业务目录 / 本地源 / 备份三段式）；
    - 正常发布与 sync-config 前同步配置仓库；
    - no-build 重建与正常发布后，把白名单 docker cp 进 web/cron 容器（0640 www-data）。
  cicd-web/cli.py
    - 新增 sync-config-repo 命令；
    - sync-config 支持 --force 与 --ref（机器人配置发版入口）。
  cicd-web-auto-update.py
    - 通知改双群；
    - 去掉“自动执行 sync-config”，生产不做自动发布（只做 CICD 自更新与重启）。
  cicd-web.sh
    - 启动时加载 cicd-web/runtime/secrets.env（运行密钥，不入库）。
  .gitignore
    - 新增 config-repo/、env/.env.prod、env/.env.prod.bak*；env/.env.prod 取消跟踪。
  README.md
    - 补充生产配置仓库流程与双群通知说明。

验证结果

1. 上线文件与本地逐文件 sha256 一致（11 个文件）。
2. CICD 进程环境加载 TG_CHAT_IDS：配置模块识别 2 个群。
3. 配置仓库同步（只写 /opt，不重建）：
   sync-config-repo -> config-repo 2ae10c14a405；
   env/.env.prod 0644、alb_white*.txt 0600。
4. 机器人路径发布实测：sync-config --force --ref 2ae10c14a405
   -> web/nginx/cron no-build 重建；白名单 docker cp 进 web/cron 并 chmod 0640；
   -> 结果“运行配置同步完成，复查已一致”；通知发送 2 个群成功。
5. 一致性：
   宿主机 / web / cron 容器 .env sha256 一致（14e0fa6f...）；
   alb_white*.txt 在宿主机源 / web / cron 三方 sha256 一致。
6. 容器：web/nginx/cron Up，无 fatal/uncaught 日志。
7. 健康：本机 admin 200、CICD 200、前端 h5 version.json 200。
8. 无自动发布：auto-update 手动执行输出“工作区有未提交改动，跳过自动 pull”；
   代码中已无自动 sync-config 执行路径。
9. 镜像说明：本次 no-build 重建按当前 .ops-build.env 的 tag 执行，
   容器运行 youdianse-php:main-5a0cefb2cdab（业务 main=5a0cefb2，构建时间 2026-09-09）；
   此前运行的 a321bb2457d1 为旧镜像。

可手动操作运维手册

1. 修改线上配置（唯一入口）

1. 打开 https://18game.18git.com/root/docker-youdianse-php-config-main
2. 只修改 main 分支：
   - env/.env.prod
   - app-local-files/alb_white.txt
   - app-local-files/alb_white_secret.txt
3. 提交后不会自动发布；需要机器人/运维显式触发（见下）。

2. 机器人/运维发布（在线上后端 16.209.16.108）

cd /opt/docker-youdianse-php

# 只同步配置仓库到 /opt 运行路径（不重建容器，用于核对）
sudo bash -c 'set -a; . cicd-web/runtime/secrets.env; set +a; \
  cicd-web/runtime/venv/bin/python cicd-web.py sync-config-repo'

# 按配置仓库 main 最新提交发布（no-build 重建并同步白名单进容器）
sudo bash -c 'set -a; . cicd-web/runtime/secrets.env; set +a; \
  cicd-web/runtime/venv/bin/python cicd-web.py sync-config --force'

# 按指定配置 git id 发布（机器人按钮使用；历史配置可回放）
sudo bash -c 'set -a; . cicd-web/runtime/secrets.env; set +a; \
  cicd-web/runtime/venv/bin/python cicd-web.py sync-config --force --ref <配置 git id>'

3. 发布后验证

cd /opt/docker-youdianse-php
sudo cat cicd-web/runtime/config-repo.last_commit
sudo cat cicd-web/runtime/config-repo.last_ref
sudo sha256sum env/.env.prod
sudo docker exec youdianse-main-php-web sha256sum /var/www/html/youdianse-php/.env
sudo docker exec youdianse-main-php-cron sha256sum /var/www/html/youdianse-php/.env
sudo docker ps --filter name=youdianse-main-php --format '{{.Names}} | {{.Status}} | {{.Image}}'
curl -s -o /dev/null -w 'admin=%{http_code}\n' http://203.0.113.1:8088/admin1866/login
curl -s -o /dev/null -w 'cicd=%{http_code}\n' http://203.0.113.1:18090

4. 回滚

# 方式一：按历史配置 git id 发布回放
cd /opt/docker-youdianse-php
sudo bash -c 'set -a; . cicd-web/runtime/secrets.env; set +a; \
  cicd-web/runtime/venv/bin/python cicd-web.py sync-config --force --ref <历史配置 git id>'

# 方式二：恢复 env 备份文件后重建（备份位于 env/.env.prod.bak.*）
# 方式三：如镜像需回退，按 CICD 正常发布流程指定业务 git id 发布

安全边界

配置仓库为 private；配置内容不在群通知、工作台或本文档展开；
root 密码、API token、Git 凭据、Telegram token/chat_id、SSH 密码、私钥均未输出或入库；
chat_id 仅存服务器 cicd-web/runtime/secrets.env（0600）与运行文件，不写入 Git。

遗留事项

1. 机器人侧按钮需指向生产发布入口：
   cicd-web.py sync-config --force --ref <配置 git id>
   （本仓库已提供 CLI 能力与测试环境同款参数）。
2. 服务器运维仓库工作区仍有历史本地改动，auto-update 会跳过自动 pull；配置发布不受影响。
3. 若要彻底避免 token/chat_id 入库，后续可把 settings.json 中的 Telegram 与发布口令迁移到
   runtime/secrets.env（当前只迁移了运维群 TG_CHAT_IDS）。
