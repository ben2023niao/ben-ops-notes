一、先认清一个硬约束

同一个主机名，不可能同时被「Cloudflare 橙云」和「EdgeOne」加速 —— DNS 只能指向一家。
现状：hkcloudplay06/07.com 的 NS 在 Cloudflare，且所有记录（静态 + 动态）都是**橙云**
      （实测解析到 192.0.2.43 / 192.0.2.44 = CF 边缘 IP）。
所以「加腾讯 CDN」只有下面三条路，选一条：

  路线 1（推荐先做）多主机名竞速：EdgeOne 用**新增子域**（如 xxx-eo.hkcloudplay06.com），
       老记录一动不动，客户端在两个域名之间测速择优。
  路线 2  DNS 按运营商/地区分线路：同一个主机名，电信走 EdgeOne、联通走 CF……
       前提是 DNS 得支持分线路解析（Cloudflare 免费版不支持，需换腾讯云 DNSPod 之类）。
  路线 3  整站迁移：把 06/07 整体交给 EdgeOne，CF 只留境外兜底（定型阶段再谈）。

二、推荐架构（路线 1）

玩家(大陆)
  |
  | 项目代码做多 CDN 域名竞速（并发测速，谁快用谁，失败自动换线）
  |
  +--> 渠道 C  Cloudflare : pg-static.hkcloudplay06.com
  |                          -> CF Worker -> 边缘缓存 7 天 -> AWS S3 大阪
  +--> 渠道 A  EdgeOne    : pg-static-eo.hkcloudplay06.com     ← 本次新增
  |                          -> EdgeOne 边缘缓存 -> AWS S3 大阪（直连桶）
  |
  +--> 渠道 C  Cloudflare : pg-games.hkcloudplay06.com
  |                          -> 192.0.2.37 standby nginx -> 香港后端
  +--> 渠道 A  EdgeOne    : pg-games-eo.hkcloudplay06.com      ← 本次新增
                             -> 192.0.2.37 standby nginx -> 香港后端

老域名 01-05 与 06/07 现有记录：全程不动。
新增的 *-eo 子域在 Cloudflare DNS 里加「灰云 CNAME」指向 EdgeOne 的加速域名（不经 CF）。

三、EdgeOne 站点配置清单（一个站点同时装静态与动态）

站点：hkcloudplay06.com（07 同理，或先只做 06） 接入模式：CNAME 接入 ｜ 加速区域：全球（不含中国大陆）（未备案）｜ 证书：EdgeOne 免费证书

3.1 静态子域（13 条，源站直连 S3 桶）

加速域名（新增） 源站类型 源站地址 回源协议 缓存
pg-static-eo.hkcloudplay06.com 域名 bizops-s3-pg-static.s3.ap-northeast-3.amazonaws.com HTTPS（S3 可信证书） 按后缀 7 天
pg3-static-eo / pg4-static-eo / pg5-static-eo / pg6-static-eo / pg7-static-eo 域名 bizops-s3-<前缀>.s3.ap-northeast-3.amazonaws.com HTTPS 7 天
pp-static-eo / ppk-static-eo / vendor_d-static-eo / vendor_c-static-eo / g759-static-eo 域名 同上 HTTPS 7 天
vendor_b-static-eo / vendor_b-static1-eo 域名 同上 HTTPS 7 天 
回源 Host：默认（= 源站域名，S3 必须按桶域名访问，别改成别的）
缓存键：如果开 CORS 回显，必须把 Origin 放进缓存键（见第五节坑 2）
目录请求 /xxx/：用边缘函数或 URL 重写补 index.html（见第五节坑 1）

3.2 动态子域（8 条 + socket，源站指香港 standby）

加速域名（新增） 源站类型 源站地址 回源协议/Host 缓存
pg-games-eo / api-eo IP 192.0.2.37 HTTP:80，Host=pg-games.hkcloudplay06.com 不缓存
vendor_b-games-eo IP 192.0.2.37 HTTP:80，Host=vendor_b-games.hkcloudplay06.com 不缓存，开 WebSocket
pp-games-eo / ppk-games-eo / vendor_d-games-eo / vendor_c-games-eo / g759-games-eo IP 192.0.2.37 HTTP:80，Host=对应现域名 不缓存 
回源为什么用 HTTP：standby nginx 443 是自签证书（CN=hkcloudplay06.com，SAN 里没有 *-eo 域名），
  EdgeOne 回源 HTTPS 会证书校验失败。等换可信证书（或补 SAN）再改 HTTPS。
回源 Host 为什么要写现域名：nginx 按 server_name 分站，Host 对不上会落到默认站（80 返回 404）。
WebSocket：vendor_b 的 /lifeservice/ws2、/ws2 必须显式开启 WS 支持，否则握手 400。

四、为什么静态源站直连 S3、不要过 nginx

现在 CF 上的静态就是 Worker 直连 S3（不经香港服务器），EdgeOne 保持一致：
  玩家 -> EdgeOne 边缘缓存 -> S3 大阪桶
好处：① 少一跳（不过香港 nginx）；② 香港进口带宽不承担静态流量；
     ③ 与现状行为一致，便于两边结果比对。
代价：未备案只能走境外节点，回源大阪属跨境回源，命中率不高时会慢 —— 所以要开缓存 + 发布后预热。

五、必须复刻的 4 个行为（现在由 CF Worker 负责）

1. 目录请求 302/重写：/xxx/ -> /xxx/index.html（现在 Worker 返回 302；EdgeOne 用规则引擎
   「URL 重写」或边缘函数实现，二选一）。
2. CORS：现在香港是「平台自有域名精确回显 + 其它 *」并带 Vary: Origin。
   在 CDN 上做回显时，**缓存键必须包含 Origin**，否则会把 A 域名的响应复用给 B 域名
   —— 2026-09-02 就是这么串源的。省事做法：EdgeOne 一律返回 *（与巴西口径一致）。
3. OPTIONS 预检：边缘直接 204，不回源。
4. health.json：单独处理（不缓存或独立缓存键），避免与真实对象互相污染。

六、分阶段执行

Phase 0（本周，0 风险）：拿测试域名 m4q7z1.shop 在 EdgeOne 建站。
  先验动态（源站 192.0.2.37:80，回源 Host=pg-games.hkcloudplay06.com），
  再验静态（源站指 bizops-s3-pg-static 桶，看缓存命中与 CORS）。
  填写口径见 docker/doc/2026-09-30-1129。

Phase 1（低风险）：在 Cloudflare DNS 给 06（先不加 07）加新增的 *-eo 灰云 CNAME，
  指向 EdgeOne 加速域名。老记录一动不动，随时可删。

Phase 2（需开发配合）：platform-api 下发的静态地址（static_hosts）加上 EdgeOne 候选地址；
  客户端做多域名竞速择优 + 失败换线。这一步做完才算真正「多 CDN」。

Phase 3（需用户决策）：按实测覆盖数据决定是否做 DNS 分线路（换 DNSPod）或整站迁移 EdgeOne。

七、风险与注意事项

1. 未备案 = 只有境外/香港节点，别期待等同国内 CDN；大陆节点必须备案（域名注册商是硬卡点）。
2. 静态跨境回源大阪有延迟，靠缓存命中率摊平；建议开「预热缓存」并在发布后主动预热。
3. 源站是自签证书 -> 回源先走 HTTP；长期应换可信证书（也利于以后开回源 HTTPS 校验）。
4. 动态 API 过 CDN 会多一跳，收益主要是隐藏源站 + 抗打；建议先静态灰度，动态后跟。
5. WebSocket、CORS 回显、目录 302 这三件事如果没配好，会出现「静态 403/404、WS 400、
   跨域名串源」等典型故障，验收时必须逐项测。
6. 计费按流量，静态是大头；先小流量灰度，观察用量再放量。
