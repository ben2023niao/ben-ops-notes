用途：把测试环境已经完成的“清理仓库定时任务清单、明确外部可视化系统管理、CICD Web 重启前发飞机群说明”改造，按同样思路同步到正式环境 main 分支。

把下面整段提示词发给 AI，先把占位符补齐，再让 AI 执行。

你是运维自动化助手。我要在“正式环境 / main 分支”做一套和测试环境相同的定时任务边界清理，并在重启发布机器人前往 Telegram 飞机群说明本次更新优化内容。

核心背景：
1. 业务定时任务已经由外部可视化系统统一管理，不在 docker-youdianse-php 运维仓库维护调度清单。
2. 线上定时任务入口：https://cron.youdianse-main.xyz
3. 测试定时任务入口：https://cron.youdianse-test.xyz
4. 后端发布入口仍是 CICD Web：
   - 线上后端发布：https://cicd.youdianse-main.xyz
   - 测试后端发布：https://cicd.youdianse-test.xyz
5. php-cron 容器仍保留，但它只是外部可视化系统调用 PHP 任务的执行环境，不负责保存调度时间。

参考测试环境已完成的改动：
- 测试提交：fdf788a Remove repo cron schedules
- 测试服务器验证结果：
  - 本地和远端 `cron/` 目录不存在。
  - README 已明确业务定时任务走外部可视化系统。
  - `docs/2026-06-25-0900-【运维记录】测试环境CICD-Web自动更新与定时任务边界说明.md` 已改成边界说明，禁止恢复 `cron/`。
  - CICD Web 重启前已发送 Telegram 更新说明。

目标：
1. 删除 main 分支仓库里的 `cron/cicd-web-auto-update`。
2. 删除 main 分支仓库里的 `cron/youdianse-cron`。
3. 如果删除后 `cron/` 目录为空，目录不再保留。
4. README 顶部或固定信息处明确：
   - 线上定时任务：https://cron.youdianse-main.xyz
   - 测试定时任务：https://cron.youdianse-test.xyz
   - 业务定时任务由外部可视化系统管理。
   - 本仓库不保存、不安装业务定时任务清单。
5. README 中所有“从 `cron/youdianse-cron` 生成 root crontab / 安装 `/etc/cron.d` / 复制 cron 清单”的旧说明都要删除或改成禁止项。
6. 文档中保留 `php-cron` 的正确定位：
   - `php-cron` 容器只提供 PHP 执行环境。
   - 外部系统通过 `/usr/local/bin/cron-task-runner.sh <Class> <method>` 调用业务任务。
   - 队列仍由 `/usr/local/bin/queue-watchdog.sh` 守护。
7. 重写旧的自动更新/定时任务提示词文档，明确：
   - 禁止创建 `cron/` 目录。
   - 禁止恢复 `cron/youdianse-cron`。
   - 禁止恢复 `cron/cicd-web-auto-update`。
   - 禁止从仓库生成 root crontab managed block。
   - 禁止安装 `/etc/cron.d/youdianse-cron`。
   - 禁止安装 `/etc/cron.d/cicd-web-auto-update`。
8. 如果代码里有对 `cron/youdianse-cron` 的特殊预览、注释或提示，也一并清理。
9. 提交并推送 main 分支。
10. 正式服务器拉取 main 后，重启 CICD Web。
11. 重启前必须发 Telegram 飞机群说明本次更新优化了什么。

   - 如果 UI 文件特殊识别 `cron/youdianse-cron`，删除这个特殊判断。

本地验证：
1. 语法检查：
   python3 -m py_compile cicd-web-auto-update.py cicd-web.py cicd-web/core.py cicd-web/ui_helpers.py
   bash -n cicd-web.sh entrypoint/cron-task-runner.sh entrypoint/queue-watchdog.sh entrypoint/cron-entrypoint.sh entrypoint/web-entrypoint.sh
2. diff 检查：
   git diff --check
3. 确认 `cron/` 不再被 Git 跟踪：
   git ls-files cron
   预期无输出。
4. 确认工作区没有 `cron/` 目录：
   test ! -d cron && echo "cron directory absent: OK"
5. 搜索确认没有旧安装教程残留：
   rg -n "生成 root crontab|安装 root crontab|业务任务从 cron/youdianse-cron|cron/youdianse-cron 仍作为|sed -n '1,20p' cron|cron/cicd-web-auto-update 作为" -S README.md docs docker-compose.yml cicd-web entrypoint ops || true
6. 允许保留的关键词：
   - “禁止创建 cron/ 目录”
   - “不要恢复 cron/”
   - 外部系统入口 URL
   - 容器内日志路径 `runtime/logs/cron/<任务名>.log`

提交推送：

正式服务器部署前 Telegram 通知：
1. 登录正式服务器并进入运维目录。
2. 在重启 CICD Web 之前，先发送一条 Telegram 普通文本消息到运维飞机群。
3. 不要打印 token/chat_id；从 `cicd-web/runtime/secrets.env` 或 `cicd-web/config/settings.json` 读取。
4. 消息模板：

【游点涩线上】CICD Web 重启更新说明
本次更新：清理仓库内历史 cron 定时任务清单，避免后续误从 Git 生成 root crontab 或 /etc/cron.d。
优化点：
1. 删除 cron/youdianse-cron 和 cron/cicd-web-auto-update。
2. README 明确定时任务由外部可视化系统管理。
3. 保留 php-cron 仅作为外部系统调用业务任务的执行环境。
4. 重写旧自动更新/定时任务提示词，明确禁止恢复 cron/ 目录。
入口：线上定时任务 https://cron.youdianse-main.xyz；测试定时任务 https://cron.youdianse-test.xyz
稍后将拉取最新 main 并重启 CICD Web。

正式服务器部署：
1. SSH 登录正式服务器。
2. 进入正式运维目录：
   cd <MAIN_SERVER_OPS_DIR>
3. 确认状态：
   git status --short --branch
   git rev-parse --short HEAD
4. 拉取 main：
   git pull --ff-only origin main
5. 重启 CICD Web：
   ./cicd-web.sh restart
   ./cicd-web.sh status
6. 确认 `cron/` 目录不存在：
   test ! -d cron && echo "cron directory absent: OK"
7. 确认仓库干净：
   git status --short --branch
8. 如果正式服务器上有旧的 `/etc/cron.d/youdianse-cron` 或 `/etc/cron.d/cicd-web-auto-update`，不要直接删除，先汇报给用户确认；业务定时任务应迁移到 https://cron.youdianse-main.xyz 后再清理。

完成后汇报：
1. 本地 main 分支提交号。
2. 删除了哪些 `cron/` 文件。
3. README/docs 是否已明确外部可视化定时系统入口。
4. Telegram 飞机群是否已发送重启更新说明。
5. 正式服务器是否已拉到最新 main。
6. CICD Web 是否已重启并运行中。
7. 正式服务器 `cron/` 目录是否不存在。
8. 是否发现旧 `/etc/cron.d` 文件，如有是否已暂停等待确认。
