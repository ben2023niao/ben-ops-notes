二、问题现象

从运维发布页复制巴西 02/04/05 批量发布命令，粘贴到 macOS zsh 后，命令执行失败时当前终端直接退出，后续错误和失败节点难以检查。

三、根因

旧版 bulkReleaseCmd() 在整段复制命令的最外层生成 set -e。 这条命令直接粘贴到交互式终端，因此 ERR_EXIT 被设置到了用户当前 shell， 而不是只影响发布脚本。任一 SSH 或远程校验返回非零时，当前终端也随之退出。

远程 bash -s 脚本内部的 set -e 是正确且必要的，问题仅在复制命令的外层。

四、修复方式

bulkReleaseCmd(region) 改为简单的多 IP 循环：

读取 “节点编号|内网目标” 清单
→ 按 02、04、05 顺序循环
→ 每个节点调用同一套远程发布脚本
→ 节点成功则继续下一个
→ 节点失败则记录失败码并中止后续节点
→ 子 shell 返回失败码
→ 当前交互式终端保持打开

实现要点：

  • 外层不再生成 set -e；
  • 循环体放在独立子 shell 中，失败只退出子 shell；
  • 远程脚本内部仍保留 set -e，镜像拉取、同步、启动或镜像 ID 校验失败仍会立即停止；
  • 节点清单使用 zsh/bash 均可解析的 while IFS='|' read，不依赖 zsh 默认不做单词拆分的差异；
  • 巴西批量组仍为 02 → 04 → 05，香港当前仍为 02；以后新增节点只需继续追加 BACKEND_TARGETS 清单；
  • 批量开始时显示节点顺序，每个节点开始前显示编号、IP 和北京时间；
  • 结束时分开展示“批量完成”或“批量未完成”提示。
