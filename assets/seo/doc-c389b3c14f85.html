整理日期：2026-09-04 14:59｜日期依据：文件名日期

现象

运维群内后端反馈：数据库连不上，报 connection refused calling hello on '103.207.68.124:27017'。
群内确认正确地址：测试环境 EC2 数据库内网地址 203.0.113.1（业务走内网）。

环境事实（2026-09-04 实时核验）

本地运维仓库：dev = 6dbb855，领先 origin/dev（c6fcd30）10 个提交，工作区干净。
DNS 实测：cicd/admin/h5/pc.youdianse-test.xyz 均解析到迁移后的新 EC2 15.152.247.196。
HTTP 实测：https://cicd.youdianse-test.xyz/、admin 登录页、H5 首页均 200。
旧测试服务器 38.92.8.34：仍可 SSH（root），/opt/docker-youdianse-php env/.env.dev 指向老库 103.207.68.124。

正确配置来源

workbench/CURRENT_TASK.md 迁移步骤 4 记录：
“env/.env.dev 7 处 Mongo/Redis host 改为 203.0.113.1；容器内 Mongo 连接+查询 OK、Redis ping OK”。

涉及节点（host 需为 203.0.113.1，端口不变）：

[database.mongodb.default]   27017
[database.mongodb.slave1]    27017
[database.mongodb.slave2]    27017
[database.mongodb.channel]   27017
[session.Redis]              6379
[redis]                      6379
[cache]                      6379

根因分析

1. 2026-09-01 迁移步骤 4 对 /opt/docker-youdianse-php/env/.env.dev 的 7 处 host 修改，
   只存在于服务器工作区，没有提交运维仓库 dev。
2. 运维仓库中 env/.env.dev 是被 git 跟踪文件，最后一次提交停在 2026-08-07（a93aba4），
   内容仍为老库公网地址 103.207.68.124。
3. 此后任何以仓库 HEAD 为基准的 git pull/checkout/自动更新，或以旧机为基准的 rsync/同步，
   都会把运行 env 覆盖回老地址；容器重建/重启后业务即连老库，报 connection refused。
4. 与群内“是不是配置文件被覆盖了 / 别又覆盖上去了”的判断一致。

处理动作

1. 本地仓库 env/.env.dev：7 处 Mongo/Redis host 由 103.207.68.124 恢复为 203.0.113.1；
   端口 27017/6379 及 dbname、用户名密码等其它行不变。
2. 本地验证：git diff 仅 7 行 host 变更；文件中老地址计数 0、新地址计数 7；
   git diff --check 通过；排除 docs/ops/workbench/历史备份后，无其它运行配置残留老地址。
3. 更新事件文档与 workbench（CURRENT_STATE / CURRENT_TASK / ACTIVE_TASKS /
   MACHINE_ACCESS_MATRIX / DECISIONS）。
4. 提交本地 Git（提交 sha 见收口通知）。
5. 推送 origin/dev，使仓库成为正确配置基准。
6. live 新机 15.152.247.196：/opt 仓库 git pull 后执行运行配置同步（sync-config）或携带容器发布，
   再做容器内 Mongo/Redis 连通与后台 HTTP 验证（步骤 7，需新机 SSH/发布权限，当前本机无凭据）。

验证结果

本地修复与代码检查通过：
- env/.env.dev 行 13/20/27/35/50/59/71 host = 203.0.113.1。
- 变更文件仅 env/.env.dev 一个。
服务器运行验证：待 live 新机步骤（见“待执行/遗留”）。

通知与安全

每个步骤完成后已按 AGENTS.md 发送【测试环境｜步骤 N 完成】到已配置群。
Telegram 密钥仅在测试服务器 secrets.env 本地使用；未输出/记录 token、chat_id、密码、私钥。
旧测试服务器 38.92.8.34 与老库 103.207.68.124 作为回滚基线未做改动。

待执行 / 遗留

- live 新机 /opt 同步与容器内 DB 连通验证（需新机 SSH 或由运维执行发布）。
- README/运行链路等仍含 38.92.8.34 旧描述的段落，建议后续按迁移后拓扑统一修订。
- workbench 中 162.211.181.13 备案反代、Redis 巡检等历史条目保留，作为历史事实。
