日期：2026-09-01（Asia/Manila） 状态：✅ 已恢复（Workers Paid 生效） 文档：本次为紧急故障处置全记录，含根因、恢复、防复发与费用说明。

1. 事故概述

现象：全部静态域名（242 条 CNAME → GCS 桶，经 summer-wave-c94f Worker 改写 Host）返回 Cloudflare error code: 1027（HTTP 429），游戏页面静态资源无法加载，各厂家游戏可用性监控 大面积报警；动态域名 /health（api/games 等）全程正常 200。

影响范围：pg / pg3 / pg4 / pg5 / vendor_a-statics / vendor_a-statics1 / vendor_a-statics2 / pp / ppk / vendor_c / vendor_d / g759 全部静态前缀 × 全部 zone。

2. 时间线

时间（UTC+8） 事件
~17:05-18:20 静态监控/游戏可用性监控陆续报警（HTTP 429 / error 1027）
18:30 本地复核确认：静态 1027、动态 200；账户无 Workers Paid 订阅（Free：10 万请求/日）
18:33 群通知：根因确认（Worker Free 额度被打爆）

18:50 监控脚本降耗改造（去掉每次 cache-buster、全量字节校验降为每小时）并部署宝塔
19:00 全量校验跑完、落档、提交

3. 根因分析

3.1 Worker 架构

  • 所有静态域名 CNAME 到各自 GCS 桶 *.storage.googleapis.com。
  • summer-wave-c94f Worker（Workers 路由 *-static.* / *-statics*.*）改写 Host 后回源 GCS， 内置 Cache API 对 GET 200 缓存 7 天（health.json 用版本盐 /v3 定点失效）。
  • 动态域名不经过该 Worker，所以全程正常。

3.2 额度打爆来源

Workers Free 计划限制：100,000 请求/日（UTC 0 点重置）。

当日消耗叠加：

  1. 全厂家/全游戏 CDN 预热（5 地区：日本、新加坡、香港、马尼拉、巴西）——一次性大额消耗；
  2. 静态 CNAME 监控每 10 分钟对 ~242 个域名各打 1 次带 ?cb=<毫秒时间戳> 的请求， 每次绕过 Cache API 强制回源 GCS，约 3.5 万次/日，且完全不落缓存；
  3. 游戏可用性浏览器测试（多厂家/多游戏页面加载，每个页面数十到数百个静态请求）；
  4. 巴西多地区健康检查（8 个 DNS/HTTP 节点 × 域名）。

三者叠加导致当日额度提前耗尽 → CF 对 Worker 路由统一返回 1027。

4. 恢复处置

4.1 升级 Workers Paid

API：POST /accounts/{account_id}/subscriptions

{
  "frequency": "monthly",
  "rate_plan": { "id": "workers_paid" }
}

⚠️ 注意：rate_plan id 必须用下划线 workers_paid（账户级），旧文档中的 workers.paid.v1 已被 Cloudflare 废弃（API 返回 7501 unknown or deprecated rate plan）。

结果：state=Paid、price=5（USD/月）、scope=account、周期 2026-08-29 ~ 2026-09-29。

4.2 验证

升级后立即抽检（Health 文件字节级校验）：

  • pg4-static.xqv9m8.icu / pg-static.xqv9m8.icu → 200
  • vendor_a-statics.vendor_a-cdn-2026.icu / vendor_a-statics1.cdn-tokyo-bizops.icu / vendor_a-statics2 → 200
  • vendor_d-static.7v8k3.cyou / vendor_c-static.m7v8k3.cyou / ppk-static.m6xv8q.cyou / pp-static.xqv9m8.icu → 200
  • 动态 /health：全程正常

5. 防复发措施

5.1 监控降耗（已上线）

docker/scripts/cf_static_cname_monitor.py v2（宝塔 /opt/bizops-scripts/ 已同步）：

  • 轻量探测走 CF 路径、不带 ?cb=：命中 Worker 内置 7 天缓存，不再每次强制回源 GCS；
  • 全量字节校验（带 ?cb=，CF 路径 vs 桶直连）最多每小时 1 次（CF_FULL_VERIFY_INTERVAL=3600）；
  • 动态 /health 不经过 Worker，保持每次全量探测；
  • 状态文件 /root/bizops-cf-cname-state.json 新增 last_full_verify 时间戳；
  • 告警口径不变：仅状态变化（新发现 / 变异常 / 恢复）发群。

旧版备份：/opt/bizops-scripts/cf_static_cname_monitor.py.bak-20260901

5.2 预算与额度

Workers Paid：1000 万请求/月（含），超出 $0.30/百万；CPU 100 亿 ms/月（含）。

  • 静态监控轻量探测 ~242 次/10 分钟 ≈ 3.5 万/日 ≈ 105 万/月（在含额内）；
  • 浏览器游戏可用性测试仍是大头，建议保持适度频率，避免集中预热+全量巡检同时进行；
  • 若 10M/月仍紧张，可把静态 CNAME 监控 cron 从 /10 调整为 /30。

6. 费用说明

项目 金额
Workers Paid（含 10M 请求/月） $5/月
超出流量/请求 $0.30/百万请求（按量）

当前周期用量（面板）：请求 811k、CPU 545,568 ms，均在 Paid 含额内，账单 $0.00。

7. 相关资产

  • Worker：summer-wave-c94f（源码：docker/scripts/summer-wave-static-proxy.js）
  • Worker 路由：*-static.* / *-statics1.* / *-statics2.*（当前挂在 3 个 zone：6qv8m/cdn-tokyo-bizops.icu/cdn-tokyo-bizops.cyou，以及按需扩展的 zone）
  • 全权限 CF token：宝塔 /root/bizops-cf-workers.env（已加密管理，不入库）
  • DNS token：宝塔 /root/bizops-cf-dns.env
  • 发群：宝塔 /tmp/send_tg.py + /opt/benbot-runtime.env
  • Account ID：eaf1a5f4eb53c8cd384ce9088181b97c

8. 结论

本次故障为 Worker Free 额度被监控/预热流量打爆所致，非 DNS、GCS 或 nginx 问题。 升级 Workers Paid（$5/月）后额度提升 100 倍，静态链路已全部恢复； 监控脚本已改为缓存友好模式，降低回源与额度消耗，后续按小时全量校验兜底。
