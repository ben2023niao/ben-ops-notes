一、用户要求与口径

1. CF 的 hkcloudplay06/07.com 静态是 Worker 实现的；
2. 腾讯云 EdgeOne 的 m4q7z1.shop 要改成「用源服务器的 nginx 实现」——动态和静态都由 nginx 出；
3. 二级域名与 06/07 尽可能完全一致；
4. 做完后列出 m4q7z1.shop 全部二级域名，给开发写进客户端配置做测试。

二、nginx 侧变更（standby 34.150.1.185 / 203.0.113.1）

文件：/etc/nginx/sites-available/dbqp-hk-standby.conf
备份：/etc/nginx/sites-available/dbqp-hk-standby.conf.bak-20260930-m4q7z1
仓库：docker/deploy/hongkong/nginx-standby.conf（尾部追加「m4q7z1.shop」段，未改任何 06/07 的块）
动作：nginx -t 通过 -> systemctl reload nginx

新增内容：
  · 7 个动态 server 块（pg-games+api 合一、jili-games 含 ws、pp/ppk/panda/playson/g759）
  · 1 个静态 server 块：server_name ~^(?<dbqp_static_prefix>[a-z0-9]+-static[0-9]?)\.m4q7z1\.shop$
        -> proxy_pass https://dbqp-s3-$dbqp_static_prefix.s3.ap-northeast-3.amazonaws.com
        （与 CF Worker 同内容：一个前缀一个 AWS 大阪桶；回源 Host 用桶域名；含 resolver）
        -> 目录请求 302 -> index.html；OPTIONS 204；CORS 固定 *

验证（直连 nginx:80，用 Host 头模拟，未过 CDN）：

动态 8/8 -> 200：pg-games / api / jili-games / pp-games / ppk-games / panda-games / playson-games / g759-games
静态 11/14 -> 200：pg-static / pg3 / pg4 / pg5 / pg6 / pg7 / pp / ppk / panda / playson / g759
       jili-static / jili-static1 -> 403（桶里还没有对象，开发上传后即 200）
       jili-static2 -> 404（没有对应桶 dbqp-s3-jili-static2；与 CF 现状一致）
行为对齐 CF：`/` -> 403、`/xxx/` -> 302 `/xxx/index.html`、CORS `*`、OPTIONS 204 —— 与
  https://pg-static.hkcloudplay06.com 实测一致

三、EdgeOne 侧变更（zone-3vm5evyb78ic）

· 删除测试用的 dyn.m4q7z1.shop / static.m4q7z1.shop（以及它们的两条旧规则）
· 新建 22 个加速域名，源站统一 = IP 34.150.1.185，回源协议 HTTP / 80（源站 443 是自签证书）
· 规则 25 条：
    static-cache-7d      14 个静态子域 -> 节点缓存 604800s（忽略源站 Cache-Control）
    dynamic-nocache      8 个动态子域 -> 不缓存
    jili-websocket       jili-games -> WebSocket 开启（超时 120s）
    hostheader-<name> x22  每个子域显式把回源 Host 重写成该子域自身（不依赖默认行为）
· DNS：EdgeOne 自动创建的 22 条 CNAME 全部启用（*.m4q7z1.shop -> *.eo.dnse3.com）

五、API 踩坑补充（本轮新增）

1. 删除加速域名的接口是 **DeleteAccelerationDomains（复数）**，参数 DomainNames 是数组；
   DeleteAccelerationDomain（单数）返回 InvalidAction。
2. CreateL7AccRules 单次最多 **20 条** 规则（超过报 FailedOperation.InvalidParam: rules cnt err），
   超过要分批；本轮的 22 条 hostheader 规则分 20+2 两批创建。
3. DescribeAccelerationDomains 默认 Limit=20，不传 Limit 会少看到站点；查全量要 Limit=200。
4. WebSocket 动作参数 {"Name":"WebSocket","WebSocketParameters":{"Switch":"on","Timeout":120}} 可用。

七、NS 核验与控制台提示不一致（13:10 追加）

控制台现象：站点概览提示「您的 DNS 服务器还未修改」，22 个加速域名状态列显示「请修改NS」，
           站点 Status=pending / ActiveStatus=inactive，加速域名 DomainStatus=init。

核验证据（**注册局层面 NS 已经改好**）：
  1) 直接问 .shop 注册局：
     dig NS m4q7z1.shop @a.gmoregistry.net +norecurse
     -> AUTHORITY: m4q7z1.shop. 86400 IN NS ns1.teodns.com. / ns2.teodns.com.
  2) 公网解析器一致：8.8.8.8 / 1.1.1.1 查 NS 均返回 ns1/ns2.teodns.com
  3) EdgeOne 权威(teodns) 已能回答本站点记录：CNAME、TXT 均可查
  结论：NS 委派与 EdgeOne DNS 都正常，是 **EdgeOne 侧的「NS 已修改」检测未通过/未更新**
        （NS TTL 86400，若其检测走了缓存旧 NS 的解析器，最长可能等到 24 小时）

本轮为推进所做的两件事：
  1) **关闭了通配 A 记录** `*.m4q7z1.shop A 34.150.1.185`（原为直连测试用）：
     关掉之前，EdgeOne 权威对本站点 22 个加速域名答的是通配 A（把 CNAME 压住了），
     关掉后 `pg-static/pg-games.m4q7z1.shop` 均正常返回 `*.eo.dnse3.com` CNAME。
  2) 按 `IdentifyZone` 返回的归属验证信息，在站点 DNS 里创建 TXT：
     `edgeonereclaim.m4q7z1.shop TXT "reclaim-jbygynwfp42mnrdmzqsgepoqc7b5upwd"`（已生效，ns1 可查）
     —— 该 TXT 说明 EdgeOne 认为本域名曾在其体系内出现过（reclaim 流程），需验证归属。

仍未解决：站点仍 pending；`pg-*.m4q7z1.shop.eo.dnse3.com` 尚未解析出 EdgeOne 节点 IP。
下一步（需要人工/原厂）：
  · 控制台站点概览看是否有「立即检测/重新验证」按钮，点一下；
  · 或让代理（英格麗/Brian Lin）找腾讯云确认「注册局 NS 已是 teodns 但站点仍提示未修改 NS」；
  · 备选：等 NS 缓存过期（≤24h）后自动通过；极端情况下删站重建（配置可用本仓库脚本一键复现）。
