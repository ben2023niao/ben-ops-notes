1. 用途

本规范用于生成运维组各成员的个人周报（运维中台月报格式）。自 2026-09-01 起，生成个人周报统一按本模板，不再使用旧的自由格式。

适用人员：仅组长 Ben。

2026-10-12 起规则变更：个人周报只由组长 Ben 编写，组员（Kermit / Jett / Melo / Davie / fyb99） 不再单独提交周报；此前已生成的组员周报作废并已从群里撤回。组长周报要写详细：写清关键现象（含量化数据）、 根因、处置动作与结果。组长的周报还必须包含【组员工作安排】：逐一写清各成员 （Kermit / Jett / Melo / Davie / fyb99）的负责领域与本期安排。

3. 字段说明

3.1 标题

# 周报 · <名称> · <年份> <起日> - <止日>
  • 名称：Ben运维、Kermit运维、Jett运维、Melo运维、Davie运维。
  • 日期段：周报覆盖的日期段，例如 2026 08-24 - 08-31。
  • 分隔符：标题内使用 · 分隔，日期段使用 -（两侧空格）。

3.2 元信息头

[REPORT-ORG:运维中台] [LEVEL:L1] [TYPE:月报] [DATE:2026-09-01]
> 提交人: 名称
> 工号: DN0000
> 岗位: 运维 OPS
> 层级: L1
> 日期: 2026-09-01
  • REPORT-ORG：固定 运维中台。
  • LEVEL：运维层级，默认 L1。
  • TYPE：周报类型，默认 月报（沿用模板；如用户指定周报可保持模板原样）。
  • DATE：提交日期，格式 YYYY-MM-DD。
  • 提交人：与标题名称一致。
  • 工号：按人员工号对照表填写，不写占位符。
  • 岗位：固定 运维 OPS。
  • 层级：固定 L1。
  • 日期：提交日期，格式 YYYY-MM-DD，通常与 DATE 相同。

4. 章节规则

4.1 【本周结果】

  • 每条以 - 开头。
  • 写本周实际完成/推进的事项，结果化表述。
  • 建议 5-7 条，覆盖本周主要产出。
  • 避免口语、表情、聊天噪声。

4.2 【死锁阻碍】

  • 每条以 - 开头。
  • 写当前阻塞、待处理、待确认的事项。
  • 无事可写时留空或写“无”。
  • 阻塞必须写清楚原因和当前状态，不夸大已解决。

4.3 【专项复盘】

  • 每条以 - 开头。
  • 选本周 1-2 个重点事项做复盘，写清背景、处理动作、结果、后续观察点。

4.4 【下周动作】

  • 每条以 • 开头（无空格时保持模板原样，有空格时统一 •）。
  • 写下周计划动作，具体可执行。
  • 建议 3-5 条。

4.5 【组员工作安排】（2026-10-12 起，仅组长周报需要）

  • 放在【下周动作】之后、@ 行之前；每条以 - 开头，一名成员一条。
  • 逐一写清各成员（Kermit / Jett / Melo / Davie / fyb99）的负责领域 + 本期安排，具体可执行。
  • 写的是工作分工与安排，不做绩效评价式夸奖；新人写明值班时段与「高危操作由老运维复核」约束。

6. 生成步骤

  1. 读取本周目录 原始记录.txt 与本周 周计划.txt。
  2. 事项全部归口到组长 Ben，参考 2026-09-01 的个人周报格式（周报-Ben运维-2026-09-01.txt）。
  3. 按第 2 节模板只生成组长 Ben 一份（内容写详细：关键现象 + 量化数据 + 根因 + 处置 + 结果），文件命名：
周报-<名称>-YYYY-MM-DD.txt
  1. 填写各人工号（对照第 5 节）。
  2. 检查章节、日期段、名称、工号、敏感信息。

6.1 交付方式（群发送规范，2026-09-15 起）

  • 个人周报生成后必须以纯文本正文发送到群（2026-10-12 起仅组长 Ben 一份）， 正文直接使用 .txt 文件内容，不加代码块围栏（```），方便群里直接复制粘贴到月报/台账系统。
  • .txt 文件是留档产物，不能只发文件附件：附件可以补充发送，但不能替代正文文本消息。
  • 群发送前先做第 8 节质量检查；发送前核对目标群名，避免发错群。
  • 涉及线上环境的步骤通知与个人周报文本发送是两件事：步骤通知按 AGENTS.md 标题规范，个人周报按本模板正文发送。

6.1.0 发送目标群（2026-10-12 起）

个人周报的正文文本需同时发送到以下两个群：

群名称 说明
18game运维 运维机器人所在群，周报正文逐条发送（-4929911895）
平台运维群-工作号 平台运维工作号群，周报正文逐条发送（-1003894163466；2026-10-26 原群升级为超级群，旧 -5308750841 已拒绝发送）
  • 两群发送同一份正文（周报-<名称>-YYYY-MM-DD.txt 的内容），顺序一致；发送前核对群名，避免发错群。
  • 若某群机器人无法发送（未入群/无权限），必须记录阻塞项，不得伪造已通知。

6.1.1 @ 提及规则（2026-09-24 起，用户要求）

  • 中台群由组长手动发布：周报到运维中台群的发布动作由组长（Ben）手动操作， AI/机器人不直接发送到中台群；中台群 = 迷境运维中台大群（chat_id -5178809123， 如群名实际为 运维中台大群 chat_id -5438620844，以组长确认为准）。
  • 生成时把 @ 行附在正文末尾，方便直接复制粘贴到群/中台系统：
  • 每条周报都要 @毅哥 @wangyi00001；
  • 每条周报末尾还要 @ 报告采集机器人 @xiaoy1988_bot（2026-10-12 起，用于机器人采集周报）；
  • 组员不再单独提交周报；组长本人周报不需要 @ 自己 —— 即 Ben 的周报末尾为 @wangyi00001 @xiaoy1988_bot。
  • 示例（成员周报正文末尾）：
## 【下周动作】
• ……

@Ben_Bird @wangyi00001
  • 机器人群侧交付（如需）仍在 18game运维 群以纯文本逐条发送，与中台群的人工发布互不冲突。

7. 写作要求

  • 保留事实，不夸大完成度。
  • 把聊天口语改写成正式运维表述。
  • 不编造未在原始记录或参考文件中出现的成果。
  • 不写入密码、Token、私钥、完整连接串、会议链接与会议密码。
  • Melo、Davie 为新人，阻塞项可体现“高风险操作由老运维复核”的约束，不写绩效评价式夸奖。

8. 质量检查清单

  • 标题格式：# 周报 · 名称 · 年份 起日 - 止日。
  • 元信息头六行齐全（REPORT-ORG/LEVEL/TYPE/DATE + 提交人/工号/岗位/层级/日期）。
  • 工号为真实工号，无 DN0000 占位残留。
  • 四个章节齐全，顺序固定：【本周结果】→【死锁阻碍】→【专项复盘】→【下周动作】。
  • 组长周报在上述四节之后追加【组员工作安排】（Kermit / Jett / Melo / Davie / fyb99 每人一条，含负责领域 + 本期安排）。
  • 【本周结果】用 -，【下周动作】用 •。
  • 无敏感信息，无口语与聊天噪声。
  • 已按 6.1 以纯文本正文逐条发群（每名一条消息），并非只发 .txt 附件。
  • 正文末尾已附 @ 行：组长 Ben 的周报为 @wangyi00001 @xiaoy1988_bot （2026-10-12 起仅组长编写、组员不单独提交；中台群由组长手动发布，AI/机器人不直接发中台群）。
