背景

线上后端扩容至 16 核 / 30G 后，按真实性能优化 PHP-FPM 与 PHP 参数。 期间出现 pm.max_children 打满 WARNING（后端反馈后台登录异常、部分接口不可用）， 已回滚代码缓解；本次基于扩容后容量重新调优。

优化内容

php/fpm-pool.conf（挂载 www.conf）：
  pm.max_children   30 -> 64   （16核×4，IO 密集；64×35MB≈2.2G，内存充裕）
  pm.start_servers   8 -> 16
  pm.min_spare_servers 5 -> 8
  pm.max_spare_servers 15 -> 32
  pm.max_requests   500 -> 2000（减少 worker 重建开销）

php/fpm-logging.conf（zz 覆盖）：
  pm.max_children   25 -> 64   （与 pool 统一，消除两文件覆盖漂移）

php/dev.ini：
  memory_limit      128M -> 256M（高并发大响应更稳）
  opcache.memory_consumption 128 -> 256
  opcache.interned_strings_buffer 8 -> 16
  opcache.max_accelerated_files 10000 -> 20000

执行与故障处理

1. 本地修改 -> scp 同步线上（原文件备份 .bak.20260821）；
2. docker restart youdianse-main-php-web；
3. 首次重启循环：php-fpm 配置注释误用 #（应使用 ;），
   容器 Restarting(78)；本地改 ; 后重新同步，容器自动恢复；
4. 验证通过。

验证

php -i：memory_limit=256M、opcache.memory_consumption=256、
        max_accelerated_files=20000、interned_strings_buffer=16；
php-fpm pool workers=64（max_children=64 生效）；
后台 /admin1866 200、https://www.youdianse.com 200；
php-fpm 日志无新增错误。

后续

1. 观察高峰时段 pm.max_children 使用率，必要时再调整；
2. 配置文件注释统一使用 ;（php-fpm 不支持 # 注释）；
3. 后续 PHP 参数调整走本文件 + 发布/容器重启流程。
