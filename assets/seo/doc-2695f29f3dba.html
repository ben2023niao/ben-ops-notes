v0.2 变更（2026-05-22）：取消手机号/邮箱双模式 + 验证码登录 + 验证码下发 + 自助找回密码。改为简单账号 + 密码注册/登录。

v0.3 变更（2026-05-23 对齐原型 v4.45）： 1. 账号长度 4-20 位 → 6-20 位；密码规则强化为 大写+小写+数字+特殊符号（5 项实时 chip 校验）。 2. 注册字段去昵称：注册时只填 账号 + 密码 + 确认密码 + 协议；昵称（改名"用户名"）登录后在"我的"修改；首版用户名默认 = 注册账号。 3. 账号丢失不可恢复：平台不提供密码修改 / 找回功能；原 AUTH-012（客服重置密码）废弃；注册/登录成功后强制提示用户保存字证图 PNG 到本地。 4. 选端 modal 改二步式：第一步选 Web / H5；第二步（仅选 H5 时）展示字证图预览 + 下载按钮 + 4 条警示后才允许进入 H5。 5. 客服入口走 TG 中转页：忘记密码按钮 → 跳 #page-telegram 模拟 t.me 落地页 → 用户跳真 Telegram。

1. 模块目标

为 18+ 用户提供最简化的注册登录入口，承担：

  1. 流量入口：未登录用户从首页、直播间、押注等 CTA 触发跳转到本页
  2. 合规拦截：通过 18+ 协议勾选、未成年禁用条款落地法律免责
  3. 多端选择：登录成功后引导用户进入 Web 端或 H5 端

2. 用户角色

角色 说明
新用户 第一次到达 Kickoff，填账号 + 密码 + 确认密码 + 18+ 协议 → 注册即登录 → 强制保存字证图
老用户 凭账号 + 密码登录
已登录用户 检测到本地 token 有效，跳过本页
忘记密码用户 平台不提供找回；可走 TG 中转页联系客服咨询（仅信息咨询，不重置密码）

4. 业务规则

4.1 账号规范

  1. 账号格式：6-20 位，仅允许英数字 + 下划线（^[a-zA-Z0-9_]{6,20}$），全局唯一；注册后不可修改，作为登录唯一凭证。
  2. 用户名格式（昵称，仅展示用）：2-20 字符（允许中英文+数字+常用符号），登录后在"我的"修改；首版默认 = 注册账号。
  3. 密码格式：8-20 位，必须同时满足： - length ≥ 8 && length ≤ 20 - /[A-Z]/ 大写字母 - /[a-z]/ 小写字母 - /\d/ 数字 - /[^A-Za-z0-9\s]/ 特殊字符（生产建议白名单 [!@#$%^&*()_+\-=\[\]{};':",./<>?|~]` 防 emoji）
  4. 确认密码：注册与登录页均显示"确认密码"字段，必须与第一次输入完全一致。
  5. 18+ 协议：注册必须勾选；登录每次勾选（首次后端记 agreed_at，后续可记忆免勾）。

4.2 注册流程

进入注册页 →
  输入: 账号 / 密码（实时 5 chip 校验） / 确认密码（实时一致性校验） / 勾选 18+ 协议 →
  前端 4 项必填校验 + 协议勾选 → POST /auth/register →
  后端校验账号唯一性 + 密码强度 →
  创建 user + user_wallet + 默认等级（取后台等级配置基础等级，当前为 L1；username 字段默认 = account）→
  返回 access + refresh token →
  弹出二步式选端 modal:
    第 1 步: 选 Web / H5
    第 2 步（仅 H5）: 显示字证图预览 + "保存账号密码图"下载按钮 + 4 条警示 →
  用户确认后跳 #page-home 或 #page-h5

4.3 登录流程

进入登录页 →
  输入: 账号 / 密码 / 确认密码 / 勾选 18+ →
  POST /auth/login（仅传 account + password；确认密码仅前端用于防误输）→
  后端校验 + 失败计数 →
  返回 token →
  弹出二步式选端 modal

4.4 忘记密码 = 不可恢复

  1. 登录页"忘记密码？"按钮 → 弹窗强调"平台不提供密码修改 / 找回功能，丢失不可恢复"。
  2. 弹窗附"联系客服咨询"按钮 → 跳 #page-telegram 中转页 → 中转页"SEND MESSAGE" CTA 跳真 Telegram @kickoff_vip（生产环境换运营配置的真账号）。
  3. 客服仅提供咨询，不能 重置密码、不能查看密码、不能查看用户原始密码哈希。
  4. 用户必须在注册时通过字证图自行保存账号密码；丢失只能放弃账号重新注册。
  5. 写审计：所有"忘记密码？"按钮点击 / TG 中转页跳转 全部记录（用于未来评估是否上自助流程）。

4.5 字证图（Credentials Card）

  1. 触发时机： - 注册成功后 → 选端第 2 步必出（仅选 H5 时）；Web 端可选下载 - "我的"→ 头像旁的"保存信息"chip 主动触发（详见 kickoff-member.md）
  2. 生成方式：客户端 <canvas> 渲染 PNG，不走任何后端 API（避免密码上传）。
  3. 图像规格：760 × 600 PNG，含： - 左上 LOGO 占位（黑底圆角 + "LOGO" 字样） - 产品名 "小蓝看夜场" + 副标 ACCOUNT CREDENTIALS · 账号字证 - 账号 / 密码 / 平台 URL 三段 - 4 条警示：
    • 账号密码是您登录的唯一凭证,请务必妥善保管
    • 切勿告知任何人（包括自称客服 / 主播 / 工作人员）
    • 平台不提供密码修改 / 找回功能,丢失无法恢复
    • 建议保存到手机相册或密码管理器
    • 右下时间戳 YYYY-MM-DD HH:mm
  4. 文件名：小蓝看夜场-账号信息-YYYYMMDD-HHMM.png。

4.6 18+ 协议

  1. 协议链接：《用户协议》《隐私政策》（v1 静态页面）
  2. 注册必须勾选；登录每次都要勾选（首次后端记 agreed_at，后续可记住）
  3. 后台可标记账号"未成年举报" → 冻结

4.7 JWT 与设备指纹

  1. access 2h + refresh 30d
  2. refresh token 绑定 device_fp（设备指纹）
  3. 新设备登录 → 顶下旧设备（旧 refresh 失效）
  4. 风控规则 R-101 新设备登录触发二次验证（v1 简化为"提示用户并记日志"，不强制二次验证；待产品评估是否补入额外校验机制）

4.8 登录失败限流

  • 同账号连续失败 5 次 → 锁定 5 分钟
  • 同 IP 连续失败 10 次 → 锁定 5 分钟（双维度）
  • 第 6 次提示"账号已锁定，5 分钟后重试"

4.9 二步式选端 modal

登录/注册成功后弹出，分两步：

第 1 步 · 选端：

   Web 端（浏览器全功能版）  → 直接跳 #page-home
   H5 端（移动端原型）       → 进入第 2 步

第 2 步 · 字证图保存（仅选 H5 才进入）：

   1. canvas 渲染字证图预览（含 LOGO / 账号 / 密码 / 4 条警示）
   2. 主按钮"保存账号密码图" → 下载 PNG（点击后按钮变绿 + "已保存 ✓"）
   3. 4 条红色警示文案区域（与字证图内容一致）
   4. 副按钮"进入 H5 端" → 真正跳 #page-h5（可在不下载情况下点击，仅做警告）

记忆用户选择到 localStorage，下次登录跳过第 1 步直接走默认端；第 2 步始终不再触发（避免每次登录都强保存）。

5. 边界与异常

场景 系统行为 提示/状态
账号已存在（注册） 阻止提交 "该账号已被注册，请直接登录"
密码不符合规则 阻止提交 "密码需 8-20 位，含大小写字母+数字+特殊字符"
账号格式非法 阻止提交 "账号仅允许 6-20 位英数字下划线"
两次密码不一致 阻止提交 "两次输入不一致"
未勾选 18+ 协议 阻止提交 "请勾选并同意用户协议"
登录失败 5 次 锁定 5 分钟 "账号已锁定，请 5 分钟后重试"
网络异常 提示重试 "网络异常，请检查后重试"
token 过期但 refresh 有效 自动续签 用户无感
refresh 过期 跳登录页 "登录已过期，请重新登录"
新设备登录顶旧设备 旧设备失效 旧设备下次请求得 30001 跳登录
用户已被冻结 拒绝登录 "账号已冻结，请联系客服 @kickoff_vip"
字证图 canvas 渲染失败（浏览器不支持） 选端第 2 步显示降级提示 "无法预览字证图，请手动记下账号密码" + 文本形式展示
用户在第 2 步不下载直接进入 H5 允许进入，但记审计 不强制阻塞（防止用户被锁在选端页）

6. 权限与风控

  1. 登录/注册：不需要登录；不需要权限
  2. 审计日志：登录成功 / 登录失败 / 注册 / 忘记密码按钮点击 / TG 中转页跳转 全部落审计
  3. 敏感字段：密码 Bcrypt cost=12；password_hash 永不出库（即使管理员后台也只显示掩码）
  4. 字证图安全：纯客户端 canvas 渲染，密码明文不离开浏览器；图片不上传任何服务器
  5. 风控规则（原型 PRD 已定义）： - R-101 新设备登录 LOW → 二次验证（v1 简化为提示+记日志，待产品评审）

同设备/同 IP 短期高频注册的拦截在中间件层实现，是否升级为独立风控规则待产品评审。
