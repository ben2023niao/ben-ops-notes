7.4 优化策略清单

7.4.1 接口层

  • 限流：滑动窗口 + 多维度（IP / UID / API 路径）；关键接口 /predict/bet 200 QPS 全局 + 5 QPS 单用户
  • 熔断：触发上游错误率 > 30% → 暂停 30s，降级返回 cached 数据
  • 超时：上游调用全部超时配置（DB 1s / Redis 100ms / 三方支付 3s）
  • 重试：仅幂等接口；指数退避 1s/3s/9s 最多 3 次
  • 降级：CDN 故障 → 静态首页；Redis 故障 → 直读 DB + 严格限流；MQ 故障 → 业务降级（关闭非关键异步通知）

7.4.2 缓存层

  • 热点活动赔率：进入直播间 / 首页时高频读 → 强缓存 30s + singleflight 防击穿
  • 多级缓存：进程内 LRU（10s TTL，避免抖动）+ Redis（30s TTL，跨实例共享）
  • TTL 随机化：基础 TTL ± 20%，防雪崩
  • 缓存预热：每场比赛开赛前 10min 预热相关活动 / 赛事 / 直播间元数据
  • 失效驱动而非过期驱动：业务变更主动 DEL，配合短 TTL 兜底
  • 布隆过滤器：用户 ID / 房间 ID 防穿透

7.4.3 数据库层

  • 索引治理：开发期间 EXPLAIN 强制；每周慢查询 review
  • 批量写入：派彩、对账走批量 SQL，单事务 ≤ 100 行
  • 连接池：MySQL MaxOpenConns=200, MaxIdleConns=50, ConnMaxLifetime=30min
  • 预编译：所有 SQL 走 sqlc 生成的 Prepared Statement
  • 慢查询阈值：> 100ms 进 mysql-slow.log，每日 review
  • 避免锁等待：SELECT FOR UPDATE 仅锁单行，避免范围锁；事务尽量短

7.4.4 异步层

  • 削峰：押注、打赏的"通知"路径走 Streams，主流程不阻塞
  • 批量消费：派彩 worker 一次拉 100 个事件批处理
  • 死信处理：消费失败 3 次进死信队列，每日扫告警

7.4.5 水平扩展

  • Go API / WS 网关 / Worker 全部无状态，K8s HPA 自动扩容
  • HPA 指标：CPU > 70% 持续 3min 或 QPS > threshold
  • 最大副本数提前设上限（防成本失控），单服务 ≤ 10 Pod

7.5 压测计划

7.5.1 压测阶段（赛季前 T-7 ~ T-3）

阶段 范围 目标
单接口压测 押注 / 充值 / 提现 / 首页 / 进入直播间 找性能瓶颈，达成 SLO
直播链路压测 1k 并发拉流 + 5 主播推流 验证 CDN 命中率 / 回源压力
弹幕压测 1k 并发 WS 连接 + 100 msg/s 入站 验证扇出延迟 < 100ms
派彩压测 模拟 1w 命中用户的批量结算 < 60s 完成
全链路压测 8k CCU + 50 主播 + 200 押注/s + 100 打赏/s + 500 弹幕/s 持续 1h 全链路 SLO 达标
极端场景 决赛日 1w 命中 + 100 并发押注/s 无穿仓，对账归零

7.5.2 混沌测试（赛季前 T-5）

故障注入 验证
MySQL 主切从 业务降级 < 30s 自动恢复
Redis 主切换 业务能短暂降级到 DB（错误率 < 1%）
SRS Origin 重启 推流自动切到备 Origin
CDN A 故障 DNS GSLB 自动切 CDN B < 60s
通道 A（微信）故障 R-604 触发，告警 + 引导用户切支付宝
Kafka/Streams 堆积 业务降级，关键链路（资金）不受影响
网络丢包 30% 客户端重试 + 服务端幂等

  • wrk / vegeta：HTTP API 压测
  • k6：脚本化场景压测
  • ghz：gRPC（未来）
  • artillery：WebSocket 压测
  • ffmpeg + ffplay：模拟主播推流 + 观众拉流
  • chaos-mesh：K8s 混沌注入
  • mysql-tools：mysqlslap / sysbench
  • redis-benchmark：Redis 压测

7.5.4 验收标准

每场景必须满足：

  1. SLO 全部达标（§7.1）
  2. 错误率 ≤ 0.1%
  3. 资金对账 = 0 差异
  4. CPU / 内存 / 连接 / IO 无异常爆涨
  5. 监控告警全部正常触发（验证告警链路）

7.6.3 应急降级开关（运行时可配）

开关 行为
feature.predict.enabled 关闭后所有押注接口返回"赛事过热，请稍后重试"
feature.tip.combo.disabled 关闭连击合并，每次打赏独立写库（性能↓但简单）
feature.danmaku.broadcast.throttle 弹幕广播降级：仅 L3+ 用户的弹幕广播
feature.home.cache.aggressive 首页强缓存 5min → 30s，源站压力↑但精度↑（反向开关）
feature.live.fallback.hls 强制所有用户切 HLS（如 FLV 链路异常）

开关用 Redis Hash 存储，go-api 启动加载 + 5s 监听。
