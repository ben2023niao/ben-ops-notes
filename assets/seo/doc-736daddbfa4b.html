整理日期：2026-07-16 00:00｜日期依据：文件名日期

本文记录 TADA 幸运鹦鹉试玩加载到 100% 后提示断线 MSG 999.2，浏览器把正确游戏域名 tada-games.p8m7xv.cyou 错误拼成 tada-games.p8m7xv.cyou.com 的排查、修复、Cloud CDN 刷新和公开验证过程。

问题现象

测试页面来自：

https://tada-statics2.xqv9m8.icu/lm/?...

浏览器 Network 中失败的预检请求：

OPTIONS https://tada-games.p8m7xv.cyou.com/lm/req
Origin: https://tada-statics2.xqv9m8.icu
Access-Control-Request-Method: POST
Access-Control-Request-Headers: token

错误域名 tada-games.p8m7xv.cyou.com 无 DNS 记录，浏览器无法建立请求。

初始部署记录复核

此前覆盖的新文件：

/www/wwwroot/tada-statics2/lm/index.html
size: 95433 bytes
md5: 56c84444263376cbc1c8ded516ac6637
sha256: 9f966f2d282cc152d1798dec0ebabb17a1fd50611e3ac2801624773b29576bb5

宝塔、GCS live、GCS backup 和公开 CDN 的 /lm/index.html 均已是新版本，原验证结论对这个精确对象成立。

但实际试玩 URL 使用 /lm/?...，不是 /lm/index.html?...。

根因

Google Cloud Storage backend bucket 不提供 Nginx 风格的目录索引，不会自动把 /lm/ 转换成 /lm/index.html。

DBQP 的 GCS 静态同步脚本会为包含 index.html 或 index.htm 的目录额外生成一个末尾带斜杠的对象：

源文件：lm/index.html
斜杠别名对象：lm/

此前手工覆盖只更新并刷新了：

/lm/index.html

遗漏了实际试玩入口使用的：

/lm/

修复前两个 GCS 桶的斜杠对象均为旧版本：

size: 32318 bytes
sha256: a4193744a5f79af2c601e856fc1a0d475a254b8a328cd29926b8d4ec79048070

新旧页面精确 diff 显示，新 index.html 在页面头部新增了约 63KB 的混淆 JavaScript，旧 lm/ 页面没有这段脚本。浏览器访问 /lm/?... 时一直执行旧页面，因此没有加载供应方本次提供的域名修正逻辑。

修复前备份

覆盖 GCS 斜杠对象前，分别保存 live 和 backup 的旧响应体：

/root/dbqp-static-import/live-tada-statics2-lm-slash-before-20260716-203500.html
/root/dbqp-static-import/backup-tada-statics2-lm-slash-before-20260716-203500.html

两个备份均为：

size: 32318 bytes
sha256: a4193744a5f79af2c601e856fc1a0d475a254b8a328cd29926b8d4ec79048070

GCS 斜杠对象修复

使用与 /www/server/cron/gcs_static_sync 中 sync_slash_aliases 相同的 GCS JSON API 逻辑，将宝塔新 index.html 内容写入精确对象名：

gs://dbqp-gcs-tada-statics2/lm/
gs://dbqp-game-statics-gcs/tada-statics2/lm/

上传结果：

live object: lm/
live generation: 1784205307084920
backup object: tada-statics2/lm/
backup generation: 1784205309240064
size: 95433 bytes
GCS md5Hash: VshERCYzdsvByN7VFqxmNw==
sha256: 9f966f2d282cc152d1798dec0ebabb17a1fd50611e3ac2801624773b29576bb5

上传后通过两个公开 GCS URL 重新下载响应体，HTTP、大小和 SHA256 均通过。

Cloud CDN 刷新

从线上 /opt/pgserver/platform-api/conf/domains/tada.json 的 SPECIAL_GAMES_v2.static_hosts 读取 22 个 tada-statics2.* 域名，对每个 host 提交精确路径 /lm/ 的缓存失效。

最终 operation 状态：

目标：22
DONE：22
缺失：0
错误：0

operation 清单：

/root/dbqp-static-import/tada2-lm-slash-invalidation-ops-20260716.txt

公开验证

TADA2 全域名目录入口

对 22 个 tada-statics2.* 域名请求：

/lm/?verify=<cache-bust>

验证结果：

域名：22
HTTP 200：22
size=95433：22
SHA256 匹配：22
新 63KB 脚本存在：22
Access-Control-Allow-Origin=*：22
失败：0

随后再次对不带任何查询参数的精确 /lm/ 缓存键验证：

HTTP 200：22/22
size=95433：22/22
SHA256 匹配：22/22
Age：约 92-93 秒

非零 Age 证明 Cloud CDN 当前缓存的是修复后的新页面，不是依靠 cache-bust 每次回源得到的临时成功结果。

正确游戏接口预检

使用与问题截图一致的请求头测试正确域名：

OPTIONS https://tada-games.p8m7xv.cyou/lm/req
Origin: https://tada-statics2.xqv9m8.icu
Access-Control-Request-Method: POST
Access-Control-Request-Headers: token

响应：

HTTP 204
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, POST, OPTIONS
Access-Control-Allow-Headers: *

错误域名对照：

tada-games.p8m7xv.cyou.com
curl exit: 6
结果：Could not resolve host

这与浏览器截图中的失败行为一致。

飞机群更正通知

修复和验证完成后，通过宝塔 dbqp-ben-bot 向监控报警群发送更正通知：

ok: true
chat_id: -5203304347
chat_title: 监控报警群
message_id: 2692

更正通知明确说明：此前 message_id=2690 只验证了 /lm/index.html，没有覆盖实际入口 /lm/；应以 message_id=2692 的修复结论为准。

二次浏览器实测与运行时域名修正

补齐 lm/ 斜杠对象后，使用本地 Docker Chromium 从测试大厅真实点击 gameID=598。浏览器确认加载的是 95KB 新页面，但游戏加载到约 96% 后仍然发出：

POST https://tada-games.<domain>.cyou.com/lm/req
POST https://tada-games.<domain>.icu.com/lm/req

因此，斜杠对象漏同步是第一层问题，但供应方提供的 95KB 页面仍未覆盖游戏运行阶段实际发出的 Fetch 请求。正确 sip=tada-games.<domain>.cyou|icu 会被游戏代码再次追加 .com，最终触发 DNS 失败和 MSG 999.2。

先在容器浏览器启动阶段临时注入同等规则验证修复方向：

.cyou.com -> .cyou
.icu.com  -> .icu

临时验证结果：正确 /lm/req 两次 HTTP 200，错误域名为 0，游戏进入完整引导页。临时注入截图未作为线上成功截图发送。

随后在 index.html 最前部加入正式 Fetch/XHR URL 规范化逻辑，并重新发布。正式文件：

size: 96447 bytes
md5: 709e9706b93166170eaac81199c24125
sha256: f91b9a1d8ee2aa8a55fc2fcf3ff83592968da58a79590d84a097c9a98babb87e

宝塔旧文件备份：

/www/wwwroot/tada-statics2/lm/index.html.bak-20260716-2108

GCS 覆盖前的 95KB 对象备份：

/root/dbqp-static-import/live-lm-index-before-20260716-2108.html
/root/dbqp-static-import/live-lm-slash-before-20260716-2108.html
/root/dbqp-static-import/backup-lm-index-before-20260716-2108.html
/root/dbqp-static-import/backup-lm-slash-before-20260716-2108.html

正式文件同步到四个精确对象：

gs://dbqp-gcs-tada-statics2/lm/index.html
gs://dbqp-gcs-tada-statics2/lm/
gs://dbqp-game-statics-gcs/tada-statics2/lm/index.html
gs://dbqp-game-statics-gcs/tada-statics2/lm/

四个对象重新下载后均为 96447 bytes，SHA256 全部匹配。

二次 CDN 刷新与公开验证

对 22 个 TADA2 静态域名同时刷新：

/lm/
/lm/index.html

计划目标为 44 个 invalidation。前台与后台续跑交接期间，东京 .cyou 域名的 /lm/ 重复提交一次，因此实际产生 45 个 operation；45/45 最终均为 DONE，重复刷新不影响内容。

operation 清单：

/root/dbqp-static-import/tada2-lm-fix-invalidation-ops-20260716-2108.txt

对 22 个域名、两个不带 cache-bust 的真实路径执行 44 次公开验证：

HTTP 200：44/44
size=96447：44/44
SHA256 匹配：44/44
正式补丁标记存在：44/44
失败：0

验证记录：

/root/dbqp-static-import/tada2-lm-fix-public-verify-20260716-2108.txt

最终测试不再注入任何浏览器临时规则，直接使用 CDN 返回的正式 index.html：

浏览器：Docker Chromium / Playwright
入口：测试大厅真实点击 TADA 幸运鹦鹉，gameID=598
随机静态域名：tada-statics2.t6qv8m.icu
运行时间：91.2 秒
请求数：507

错误 .cyou.com/.icu.com 请求：0

结果：ok=true

容器先进入完整游戏引导页，自动点击 Continuar 后进入 ARARA DA SORTE / JOGAR 可开始界面。最终截图：

/private/tmp/dbqp-lucky-macaw-output/lucky-macaw-loaded.png

公共框架仍会重试若干非阻断性可选资源并返回 404，但不影响登录、两次 /lm/req、引导页或 JOGAR 主启动画面。

飞机群最终截图通知

正式浏览器验收通过后，通过宝塔 dbqp-ben-bot 向监控报警群发送截图和校验摘要：

ok: true
chat_id: -5203304347
chat_title: 监控报警群
message_id: 2693

message_id=2692 是第一阶段斜杠对象修复通知；message_id=2693 是最终运行时域名修正及容器浏览器截图验收结果。

人工复测建议

旧 32KB 页面可能仍在测试人员浏览器内存或磁盘缓存中。复测时应：

1. 关闭旧游戏标签页后重新打开试玩入口；或
2. 打开 DevTools，勾选 Disable cache，再执行硬刷新；
3. 在 Network 确认 Document 请求路径是 `/lm/?...`，响应体大小为 `96447 bytes`；
4. 确认 `/lm/req` 的 Request URL 不包含 `.cyou.com` 或 `.icu.com`；
5. 确认游戏能进入 `JOGAR` 界面，且没有 `MSG 999.2`。

后续发布规则

以后手工覆盖任意静态目录的 index.html 或 index.htm 时，必须同时处理并验证两类 URL：

/path/index.html
/path/

最低检查项：

1. 宝塔 index 文件哈希；
2. GCS live/backup 的 index 对象哈希；
3. GCS live/backup 的斜杠别名对象哈希；
4. CDN 的 /path/index.html；
5. CDN 的 /path/；
6. 两个路径均提交对应的 CDN invalidation；
7. 按真实试玩 URL 形式进行最终验证。

最终结论

幸运鹦鹉断线包含两层原因：第一次手工发布遗漏 GCS lm/ 斜杠别名对象；补齐后，供应方 95KB 页面在运行阶段仍把自定义 .cyou/.icu 后端追加为 .com。现已在 index.html 加入最小 Fetch/XHR 域名规范化逻辑，四个 GCS 对象均更新为 96KB 正式版本，22 个域名的两个入口 44/44 内容验证通过。最终无临时注入的 Docker Chromium 实测已进入 JOGAR 页面，/lm/req 两次 200，错误域名和 MSG 999.2 均为 0；截图已发送监控报警群 message_id=2693。
