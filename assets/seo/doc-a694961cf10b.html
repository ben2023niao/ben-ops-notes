一、背景

Ben 提供“static-gcs-proxy (Slot Game Ultimate Edition)”草稿，指出它只优化了
静态资源；询问动态接口类域名（api.<zone> / <vendor>-games.<zone>）有哪些
可做的优化，并要求“写出优化后的 worker 代码看看”，不更新线上。

二、动态链路现状

平台-api 单 Argo 域收敛后：
  api.xqv9m8.icu            平台 API（9090 端口多进程）
  <vendor>-games.xqv9m8.icu 各厂家游戏网关（pg/vendor_a/pp/ppk/vendor_c/vendor_d/g759）
主要接口形态（platform-api/main.py 路由）：
  /health、/web-api/game-proxy/v2/Ping/Get（测速）、/GameEntry/Get（带 uid/token）、
  /User/Get|Set（用户态）、GameVerifyURL、风控相关，以及 launcher /network-report。
结论：绝大多数请求携带 uid/token/签名、返回与用户相关 -> 不能整页缓存；
真正适合“边缘短缓存”的只有健康检查等全局一致的 GET。

三、可优化项清单（按收益排序）

1) CORS OPTIONS 边缘 204（动态+静态全域名）：
   当前每次预检都回巴西源站；改后 0 回源。收益高、改动小、风险低。
2) iOS WebKit 304/204 修复下沉到动态域：
   204/304 清除 Content-Type/Content-Length，避免弱网 Safari Fetch TypeError。
3) 安全白名单 GET 短 TTL 缓存（默认仅 /health，TTL 10-60s）：
   - 有 Authorization/Cookie/Range、POST、非 200、no-store、Set-Cookie 一律不缓存
   - 缓存键 = 真实域名 + 版本盐 + 路径 + 查询（不同动态域不互串）
4) 静态侧修正“跨前缀统一缓存键”风险（Slot 草稿的 shared-static-pool）：
   - 改为按 bucket 隔离的缓存键，不同桶同路径不再互串
   - 同时保留 Slot 草稿优点：json/atlas/manifest 短缓存强校验、
     图片/音效/字体 30 天强缓存、CORS 头、iOS 304 修复、OPTIONS 204
5) 头处理区分静态/动态：
   - GCS 静态：清 Cookie/Origin/Referer 与 x-*（非 x-goog）
   - 动态透传：原样保留（Cookie/Authorization/Origin 不能删）
6) 无条件透传：WebSocket/SSE、POST、Range/206、带鉴权 GET。

四、明确不做 / 待业务确认

1) game.list / Ping/Get 等“疑似可缓存”接口：未确认响应全局一致前不缓存
   （Ping/Get 用于测速，缓存会失真）；
2) Asia 边缘实例/地理路由：架构级改动（历史 P0 方案 B），不在 Worker 草稿范围；
3) Image Resizing 自动 WebP：默认关，需账户开通付费功能后手动置 true；
4) stale-while-error / 源站超时重试：可作为二期，避免草稿期引入不可控行为；
5) 动态 CORS Allow-Origin:* 是“放宽项”，评审时建议收敛为反射 Origin 白名单。

五、草稿文件

docker/scripts/summer-wave-static-proxy.dynamic-optimized-draft.js
- 单一 Worker 覆盖静态 + 动态；
- 静态：桶隔离缓存键 + 配置类短缓存 + 媒体类 30 天 + OPTIONS 204 +
  iOS 304/204 修复 + Range/206 不入全量缓存；
- 动态：白名单 /health 短 TTL + 其余透传；
- 大量中文注释（含上线路由/风险提示）。
