所有命令都通过项目自带的虚拟环境运行：

cd "/Users/ben/Desktop/line-自动化打卡上班下班"
./.venv/bin/python punch.py <子命令> [参数]

为什么不能直接 python3 punch.py？因为 PyObjC 装在 .venv 里。 用系统 python3 跑会提示你改用虚拟环境，并以退出码 3 结束。

全局参数

参数 说明
--config PATH 指定配置文件，默认 ./config.toml
-v, --verbose 控制台输出 DEBUG 级日志（默认 INFO）
--no-notify 本次不发 Telegram 汇报
--version 显示版本

子命令

doctor —— 环境自检

./.venv/bin/python punch.py doctor

逐项检查，不通过时直接告诉你去哪儿修：

✅ Python 依赖（PyObjC 框架）      全部可导入
✅ 辅助功能权限                    已授权
✅ 屏幕录制权限                    已授权
✅ LINE 进程                       运行中 pid=37638 版本=26.5.0
✅ LINE 主窗口                     (369,240 742x490)
✅ 窗口截图 + OCR                  window_id=76679 抓到 742x490px，识别到 204 个字符
✅ 中文（Unicode）键盘事件          可构造，无需输入法
✅ 配置文件                        /Users/ben/.../config.toml
✅ Telegram 机器人                 @Bklnoc_bot (Bkl-alarm)
✅ Telegram 发送测试               已发送一条测试消息

会真的发一条 Telegram 测试消息（静音），用来确认汇报通道是通的。 不想要就加 --no-notify，或把配置里的 telegram.enabled 暂时设为 false。

这一步不会碰你的桌面（只抓一张 LINE 窗口的图）。

read —— 读聊天/群列表

./.venv/bin/python punch.py read

输出：

聊天列表（共 2 条）：
   1. Keep备忘录 | 发送任何您想要保存的文字、照 | 片、视频和链接。
   2. 打卡（5） | 下午 1:06 | 泰铢换 人民币 5.08 泰铢 | 换U 33.5

完全不抢焦点。| 是同一视觉行里从左到右的多个文本片段。

status —— 看当前会话

./.venv/bin/python punch.py status

当前会话：打卡（5） 4心 QC目： 5 @Aken @maggie
是否目标群「打卡」：是

最近消息：
  - @Aken @maggie | 上班 下 | 上午 8:04
  - Bob | 上班打卡 | 上午 8:30
  - ⑨ | cw-阿果（资金往来当面） | 泰铢换 人民币 5.08 泰铢换 | U 33.5 | 下午 1:06

不抢焦点。排错时先用它确认"脚本眼里的世界"和实际是否一致。

type —— 空跑（输入但不发送）

./.venv/bin/python punch.py type 下班打卡
./.venv/bin/python punch.py type 下班打卡 --keep-focus

完整走一遍流程：定位 → 检查布局 → 校验目标群 → 打字进输入框 → 复核输入框内容，但不按回车。

参数 说明
text（位置参数，可选） 要输入的文字，省略则用配置里的 messages.clock_out
--keep-focus 输入完不把焦点还给原来的程序，方便你当场看效果
--clear-first 输入前先清空输入框里的残留草稿

这是唯一会抢焦点的只读类命令（约 2 秒）。上线前请务必用它验证几次。

send —— 真实发送

./.venv/bin/python punch.py send --out --yes
./.venv/bin/python punch.py send --in  --yes
./.venv/bin/python punch.py send --text "临时打卡" --yes
参数 说明
--in 用 messages.clock_in 的文案
--out 用 messages.clock_out 的文案
--text TEXT 自定义文案（优先级最高）
--yes 确认发送
--keep-focus 发送后不归还焦点
--clear-first 发送前清空残留草稿

三个人一起满足才会真的发出去： --yes + behavior.allow_send = true + 用的是 send 子命令。 缺任何一个都会自动退化成空跑，并在日志里留一条 WARNING 说明原因。

notify-test —— 测汇报通道

./.venv/bin/python punch.py notify-test

只发 Telegram，不碰 LINE。

logs —— 看最近一次运行的日志

./.venv/bin/python punch.py logs --tail 80

prune —— 清理过期日志

./.venv/bin/python punch.py prune            # 用配置里的 keep_days
./.venv/bin/python punch.py prune --days 7

退出码

接入外部告警时用得上。

码 含义
0 成功（含"空跑成功"）
1 未预期的异常
2 配置错误
3 用错了 Python（应该用 .venv/bin/python）
10 LINE 操作失败（基类）
11 没找到 LINE 进程
12 拿不到 LINE 主窗口
13 窗口布局不对（太窄，右侧聊天面板没渲染）
14 目标会话不匹配，已中止（最重要的一类）
20 校验不通过（含输入没进输入框、发送后复核失败）

配置文件参考

见 config.example.toml，每一项都有注释。要点：

键 作用
line.group_name 防发错群的唯一凭据，发送前 OCR 标题必须解析出它
behavior.allow_send 总开关，默认 false
behavior.verify_before_send 关掉它 = 关掉防发错群保护，不建议
behavior.verify_after_send 发送后复核消息是否真的出现在消息流里
behavior.strict_title_match 严格标题匹配（切掉成员数角标后必须等于群名），默认 true
behavior.reverify_before_send 按回车之前再校验一次目标会话，默认 true
behavior.require_group_badge 要求标题带成员数角标 (N) 才认群，默认 false
behavior.input_mode 键盘投递方式：auto（默认）/ event_tap / post_to_pid
behavior.auto_expand_window 窗口太窄时自动拉宽（不抢焦点）
schedule.clock_in_window / clock_out_window 随机打卡窗口，见下节
schedule.salt 随机种子的盐，改掉之后每天的落点整体变化
behavior.focus_settle_ms 激活 LINE 后等焦点稳定的毫秒数，机器慢就调大
messages.clock_in / clock_out 上下班的打卡文案
telegram.bot_token 也可以用环境变量 LINEPUNCH_TG_TOKEN 覆盖
telegram.chat_id 也可以用环境变量 LINEPUNCH_TG_CHAT_ID 覆盖
telegram.attach_log 是否把日志作为附件一起发
log.file_level 保持 DEBUG 才有"详细日志"
log.keep_days 日志保留天数，0 = 永不清理

环境变量覆盖示例（避免 token 落盘）：

export [敏感内容已脱敏]
export LINEPUNCH_TG_CHAT_ID="5440591117"
./.venv/bin/python punch.py send --out --yes
