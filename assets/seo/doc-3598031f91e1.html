背景

大数据团队反馈：每次线上发布后会出现大量重复提交数据和缺数据。已排查确认：

1. 订单 GAC202608181426341787034394178 未上报（te.log 全量 0 命中）；
2. 08-18 充值类事件整体缺失；
3. logbus2 与当前版本 SDK 写入链路正常（实测）；
4. 重复机制：上报无幂等键 + TDAnalytics 未开启 #uuid + 批量任务无游标；
5. 丢失机制：TDFileConsumer 内存缓冲（满 100 条才落盘）+ #time 为空时 strict=false 静默丢弃。

本次通过 SDK 能力实现“去重 + 防丢失”的代码改造，改动文件已发群请开发审核。

改动内容（3 个文件）

1. app/Services/Common/BigDataJobService.php

// 防丢失：bufferSize=1，每条事件立即落盘，容器重建/进程中断时不再丢失内存缓冲数据。
// 防重复：enableUUID=true，SDK 自动为每条事件生成 #uuid，TE 平台可按 UUID 去重。
$consumer = new TDFileConsumer($logPath, 200, true, 'te', 1);
return new TDAnalytics($consumer, true);

2. app/Jobs/BigData/RechargeReportJob.php

// #time 兜底：时间缺失时用当前时间，避免 strict=false 时事件被 SDK 静默丢弃。
$timeStr = $timeTs > 0 ? date('Y-m-d H:i:s', $timeTs) : date('Y-m-d H:i:s');
// 业务去重键：同订单同状态重复上报时 #uuid 相同，TE 平台可按 UUID 去重。
'#uuid' => md5('recharge:' . (string)($data['order_num'] ?? '') . ':' . (string)($data['status'] ?? '')),

3. app/Jobs/BigData/SpendReportJob.php

// #time 兜底：时间缺失时用当前时间。
$timeStr = $payTime > 0 ? date('Y-m-d H:i:s', $payTime) : date('Y-m-d H:i:s');
// 业务去重键：spend 仅 status=1，同订单重复上报时 #uuid 相同。
'#uuid' => md5('spend:' . $spendOrderId . ':1'),

验证结果

SDK 行为实测（生产容器）：
  enableUUID=true -> 每条事件自动带 #uuid（如 f057bebd-...）
  properties 显式 '#uuid' -> SDK 原样写入（业务去重键）
  bufferSize=1 -> 事件立即落盘
PHP 语法：3 个文件用生产 PHP 7.4.33 php -l 全部通过
Diff：3 文件 +12/-4

去重原理说明（供开发审核）

1. TE 平台按 UUID 去重需大数据/TA 侧开启对应去重配置；
2. 业务 #uuid 为 md5(业务键)，同一订单同一状态无论重复跑多少次 UUID 都相同，
   即使 TE 未配置自动去重，也可在数据侧按 #uuid 二次去重；
3. 开启 enableUUID 后其它 Job 也会自动带 #uuid，全量事件具备去重基础。

上线方式与待确认

1. 开发审核通过后合并到业务仓库 main，走正常发布流程；
2. 发布前建议同时确认 TE 平台 UUID 去重配置；
3. 发布后执行端到端验证：触发一笔测试充值 -> 确认 te.log 出现 #uuid 事件 -> TE 平台可查且不重复。
