1. 静态页面

本地预览：

python3 -m http.server 8080 --bind 203.0.113.1

检查：

  • 浏览器控制台无 JavaScript 错误；
  • 折叠命令块可展开；
  • 版本号默认当天且可编辑；
  • 巴西批次包含 02/04/05；
  • 未完成 01 时批量确认被阻断。

2. 容器

docker logs -f --tail 200 dbqp-ops-console
docker inspect dbqp-ops-console --format '{{.State.Status}} {{.Health.Status}}'
curl -v http://203.0.113.1:8788/api/health
curl -v http://35.247.205.6:8787/api/health

3. WebSocket

浏览器开发者工具中检查：

101 Switching Protocols

如果没有升级：

  • 检查反向代理 Upgrade/Connection 头；
  • 检查 proxy_read_timeout；
  • 检查访问控制是否拦截 WebSocket；
  • 检查 Job ID 和 after_seq 参数。

当前实时执行使用 Server-Sent Events，不是 WebSocket：

GET /api/jobs/{id}/events
Content-Type: text/event-stream

Nginx 必须设置 proxy_buffering off，否则输出会延迟到任务结束。

4. SSH 不通

先绕过应用手工检查：

ssh root@<target>
nc -zv <target> 22

再检查：

  • Secret 文件权限；
  • 目标 IP/端口；
  • UFW/GCP 防火墙；
  • 控制台所在 VPC 路由；
  • SSH 用户和 key/password 是否匹配。

5. 容器任务失败

按顺序检查：

目标镜像是否已 pull
→ 目标容器是否 Up
→ 容器实际 Image ID 是否一致
→ RestartCount 是否增加
→ 宿主机端口是否监听
→ Nginx 是否可以访问

失败 Job 必须保留：

  • job_id；
  • 失败阶段；
  • 目标主机；
  • stdout/stderr；
  • 退出码；
  • 是否已中止后续主机。

结果集权限步骤应同时看到：

RESULT_PERMS_TIMER=OK
RESULT_PERMS_NOW=OK

缺少任一标志时，先检查：

systemctl is-enabled dbqp-result-perms.timer
systemctl is-active dbqp-result-perms.timer
tail -20 /var/log/dbqp-result-perms.log
find /data/server-runtime/game_result_datas \
  \( ! -uid 1000 -o ! -gid 1000 \) -print -quit

rsync 发版必须带 --chown=1000:1000；定时任务只是最后兜底，不能替代 同步参数和启动前校验。

6. Job 卡住

  • 检查任务锁是否仍被旧进程持有；
  • 检查子进程是否没有超时；
  • 检查 WebSocket 断开后后台任务是否仍运行；
  • 检查 /data/jobs/<job_id>/ 最新日志时间；
  • 取消操作只能终止当前 Job，不能删除其他 Job 的锁。

7. Secret 泄露排查

在日志和页面中搜索：

sshpass 明文密码参数
Authorization:
Bearer
敏感凭据：[已脱敏]
eyJ

发现后立即轮换 Secret，并修正全链路脱敏规则。
