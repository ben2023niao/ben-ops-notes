事项 监控告警中文化；报警与各类通知统一发到新报警群；通知链接从 localhost 改成公网 IP；监控系统名带公网 IP
参与 Ben（执行）、Mark Wu（建报警群）、SVD / brent
报警群 BKLUAT ALARM　chat_id -1004438007285（supergroup）

一、需求

  1. 报警和所有通知（启动通知、值班提醒）统一发到新的报警群 BKLUAT ALARM。
  2. 告警文案中文化（原来是 Connection to UAT-middleware is down 🔴 这种英文）。
  3. 通知下面的链接原来是 http://localhost:8090/system/...，点不开，要换成服务器公网 IP。
  4. 监控里的系统名带上公网 IP（UAT-middleware-43.249.251.11），一眼知道是哪台。

二、做了什么

1. 通知目标统一到报警群

通知类型 原来 现在
监控告警 运维内部群 -1004318632106 BKLUAT ALARM -1004438007285
机器人启动通知 所有已知会话（4 个） 只发报警群
值班提醒（08:30/09:00/19:00） 不外发 只发报警群

机器人侧改了两处代码：

  • duty_status.py 的 DUTY_NOTIFY_CHAT_IDS 填报警群 ID。
  • main.py 的 get_startup_notify_chat_ids()：以前是"配置的 + 所有已知会话"合并，改成只要配置了目标就只发配置的会话，避免通知散到多个群。

2. 监控系统名带公网 IP

UAT-堡垒机-43.249.251.15
UAT-middleware-43.249.251.11
UAT-manager-43.249.251.12
UAT-worker01-43.249.251.13
UAT-worker02-43.249.251.14

报警内容直接带 IP，例如 UAT-middleware-43.249.251.11 已断开 🔴。

3. 通知链接改公网 IP

Beszel 的通知链接由环境变量 APP_URL 决定（默认没设 → 生成 http://localhost:8090/...）。改成：

environment:
  APP_URL: "http://43.249.251.15:8090"

4. 告警中文化（自建中文版镜像）

Beszel 的告警文案是写死在 Go 代码里的，官方没有多语言开关（title := fmt.Sprintf("Connection to %s is %s %v", ...)）。做法是打补丁 + 重新构建镜像：

文件 位置
中文补丁 code/ops-scripts-运维部署脚本/beszel/beszel-zh-alerts.patch
构建用 Dockerfile code/ops-scripts-运维部署脚本/beszel/Dockerfile.zh
镜像 beszel-zh:v0.21.0（官方 v0.21.0 源码 + 文案补丁）
compose code/ops-scripts-运维部署脚本/beszel/docker-compose.yml（image + APP_URL）

翻译范围：离线/恢复、CPU/内存/磁盘等阈值告警、容器健康、systemd 服务、S.M.A.R.T.、ZFS 存储池、网络探测、以及"测试通知"文案。逻辑一行没动。

构建命令（堡垒机 /opt/beszel-src）：

patch -p1 < beszel-zh-alerts.patch
docker build -f Dockerfile.zh -t beszel-zh:v0.21.0 .

三、验证结果

  1. 二进制里确实有中文文案：已断开×2、已恢复×2、超过阈值、低于阈值、测试告警、查看×5、异常容器×3；官方镜像里对应的是 is down×3。
  2. 实际外发参数抓包：Shoutrrr 调用 URL 里带 $title=测试告警，证明外发标题已经是中文。
  3. AppURL 查询结果 = http://43.249.251.15:8090，通知链接不再是 localhost。
  4. 报警群里已收到中文测试通知。

四、踩的坑

  1. Beszel 告警文案不可配置：没有 i18n 开关，只能改源码重建镜像；补丁已留档，升级时重打一次即可。
  2. 通知链接是 localhost：没设 APP_URL 时 Beszel 用 localhost 拼链接，必须显式设置。
  3. scratch 镜像没有 shell：docker exec ... sh 会失败，验证镜像内容要用 docker create + docker cp 把二进制取出来再看 strings。
  4. 抓包验证更省事：用 Shoutrrr 的 generic://203.0.113.1:9099?template=json&disabletls=yes 可以把通知打到本地抓包服务，直接看到 Beszel 发出去的标题/正文/链接。
  5. 界面保存通知设置会清空 webhook（10-15 遇到过，这次也确认了风险）：改完通知设置要回来看一眼 webhooks 还在不在，并点一次测试。

五、后续

  1. 升级 Beszel 时：下载新版源码 → 打 beszel-zh-alerts.patch → 重新构建 beszel-zh:<新版本> → 改 compose 的 image 标签。
  2. 报警群里的接收人如需调整，直接在群里加人即可（机器人不需要额外配置）。
  3. 如需把值班提醒发到别的群，改 DUTY_NOTIFY_CHAT_IDS。
