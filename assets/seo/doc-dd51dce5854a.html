一、现象

用户：不小心同步，把香港 01/02 的 /data/server-runtime/conf 搞没了。
核实（两台一致）：
  · /data/server-runtime/conf/domains/*.json 内容变成了巴西域名
      pg.json 里是 pg-static.xqv9m8.icu / pg-games.vendor_a-cdn-2026.icu 等
  · conf/ 下还有 configs-*.py 六个文件，时间戳同为 10-02 07:51（也被本次同步覆盖）
  · 之前放在 conf/ 下的备份目录（domains.bak-20260930-m4q7z1 / -20261002-k8x2v9 /
    -20261002-3domains）**一并被 rsync --delete 删掉** —— 备份放错位置，不能放同步目录里
影响：conf/domains 是以 bind mount 挂进容器的（/app/config/domains），
      容器读到的是巴西域名 → 香港客户端会拿到错误域名。属线上配置回退。
补充：两台业务容器当前**没有运行**（只剩 beszel-agent）；用户 2026-10-02 明确要求本轮不启动容器。

二、恢复动作（已完成）

1. 用仓库快照覆盖回两台：docker/deploy/hongkong/hk-domains-3domains/*.json（10 个文件）
2. 覆盖前先把当时的目录留档到 /root/conf-domains-br-backup-20261002/（放在 /root，不会被同步删）
3. 校验：
   · 两台 pg.json / vendor_b.json / vendor_a.json 的 md5 与仓库快照完全一致
     （pg af826677cb9bff5aead12578e1bc9406 / vendor_b b2ec5748aa6a26731583510c1725e05d / vendor_a 3a0c65f41949ed66be35326d5cce3ec3）
   · 10 个文件 JSON 全部解析通过
   · 已无 xqv9m8.icu / vendor_a-cdn-2026.icu 残留
4. 恢复后配置内容（两台一致）：
     static_hosts = ["pg-static.m4q7z1.shop", "pg-static.k8x2v9.shop"]
     game_hosts   = ["pg-games.m4q7z1.shop",  "pg-games.k8x2v9.shop"]
     api_hosts    = ["socket.p3w9n5.shop",    "socket.hk-socket.com"]

三、防复发（本轮新增）

1. 安全副本（放在 /data 之外，同步删不到）：
     两台 /opt/bizops-hk-ops/hk-domains/  ← 10 个 json 的权威副本（与仓库快照同源）
2. 一键恢复脚本：
     两台 /opt/bizops-scripts/restore_hk_domains.sh
       - 先把当前 conf/domains 留档到 /root/conf-domains-lost-<时间戳>/
       - 再从 /opt/bizops-hk-ops/hk-domains/ 复制回去
       - 自动做 JSON 校验 + 巴西域名残留检查 + 打印三组域名
     已在本轮演练执行通过。
3. 约定（下次同步必守）：
     rsync 同步 /data/server-runtime 时必须带 `--exclude 'conf/domains'`；
     日常只想更新代码时用最小同步范围（只同步 share.so），不要全量覆盖 conf/。
4. 仓库侧的权威快照：docker/deploy/hongkong/hk-domains-3domains/

四、遗留与建议

· conf/configs-*.py 这次也被同步覆盖成巴西副本（它们不在容器挂载里，暂不影响运行；
  若香港需要独立内容，应同样纳入安全副本并加同步排除）。
· 业务容器未运行（按用户要求不启动）：配置是 bind mount + 每请求读文件，
  容器起来后自动生效，不需要额外操作。
· 建议把「配置目录不进同步、备份不放同步目录」写进香港运维交接清单。
