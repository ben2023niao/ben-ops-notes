精简前/后对照（测试环境）

精简前（Web 页面发布，约 10 条）：
1. 发布占用｜已进入发布流程
2. 发布占用｜第一步：查看确认
3. 发布占用｜第二步：选择部署 git id
4. 发布占用｜第三步：选择部署模式
5. 发布占用｜第四步：等待开始执行
6. 发布占用｜第四步：开始执行
7. 发布开始（目标/服务/配置）
8. 发布结果（成功/警告/失败）
9. 详细部署日志文件
10. 发布占用｜发布锁已释放

精简后（3 条，且只发原运维监控报警群）：
1. 发布开始（操作人/机器/目标/服务/配置）
2. 发布结果（成功/失败 + 版本/镜像/健康检查）
3. 详细部署日志文件（完整步骤、构建输出、验证细节都在文件里）

说明：测试环境 2026-08-11 已把发布类通知收口到原运维监控报警群（TG_PUBLISH_CHAT_IDS， 18game运维 不接收发布类通知）；本次精简后仍保持该收口，只是消息从 10 条减到 3 条。

改动内容

1. 发布群通知精简（对应线上 3a09d5b）

cicd-web/core.py：
  update_publish_state 的 notify 默认值 True → False：步骤流水只写锁文件与页面，不再触发群通知；
  try_begin_publish_session 不再发送“已进入发布流程”占用通知（保留 TG_PUBLISH_CHAT_IDS 发布专用群覆盖，
  保证 run_deploy 的开始/结果/日志文件仍只发原运维群）；
  人工“强制踢人”通知保留（显式 notify=True / 直接 send_telegram）。
cicd-web-auto-update.py：
  移除“自动更新开始”通知，只保留“完成”（含版本与提交清单）与“失败”；细节在 auto-update.log。

2. CICD 发布会话丢失降级（对应线上 a886838）

cicd-web/command.py：
  WebLogger 增加 _render 统一捕获会话异常；浏览器关闭/刷新/超时导致 PyWebIO 会话失效时，
  输出降级为控制台，发布流程不因 SessionNotFoundException 中断；文件日志与 Telegram 通知不受影响。
cicd-web/steps/publish.py：
  发布开始前提示“发布中请勿关闭/刷新页面，即使会话中断发布仍会继续，结果以 Telegram 为准”；
  第五步最终状态渲染 try/except 降级，发布完成后页面会话丢失不影响发布结果。

验证结果

1. 本地：python3 -m py_compile 全部通过；行为测试（dry-run）确认发布会话期间
   占用/步骤流水/锁释放 0 条群通知；会话内 resolve=1 群（仅原运维群），结束后恢复 2 群。
2. 测试服务器：同步并重启 CICD Web 后 HTTP 200；运行态核对 notify 默认值 False、
   auto-update 无“开始”通知、WebLogger 含 _render 降级。
3. 与线上代码 diff 对照一致（core/auto-update 同 3a09d5b；command/steps 同 a886838）。

精简后通知结构（测试环境）

正常发布（Web / CLI / Webhook 一致）：
1. 发布开始
2. 发布结果
3. 详细部署日志文件
预检查失败：仅 1 条“发布流程日志”文件
人工强制踢人：保留 1 条（低频率）
CICD 自动更新：1 条“完成”（原 2 条）

回滚

回退测试环境 dev 本次提交并同步 /opt、重启 CICD Web 后恢复原通知与页面行为。
