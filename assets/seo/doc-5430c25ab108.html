测试环境磁盘清理后自动发布构建慢修复记录

背景

手动清理测试服务器磁盘后，Webhook 自动发布构建镜像变得很慢/卡住（10 分多钟未完成），后端反馈“部署很慢”“第一次构建应该是 git 拉不了一个依赖导致的”。

排查过程

1. 发布会话卡在“Webhook：自动部署中”，docker compose build web 进程运行 14+ 分钟未完成，已被强制踢出但进程仍挂着。
2. 构建日志 #8 显示在拉取 php/composer 基础镜像层：单个 17MB 层下载耗时 700+ 秒，几乎无进展。
3. /etc/docker/daemon.json 配置了镜像源 https://docker.1ms.run。
4. 实测：该镜像源拉 alpine 需 29.4 秒；Docker Hub 直连仅 1.9 秒。
5. 结论：磁盘清理清掉了镜像缓存，首次构建必须重新拉基础镜像，走慢镜像源导致卡住；
   慢的不是 composer 业务依赖（构建日志里 thinkinggame/ta-php-sdk 等依赖安装正常）。

处置

1. 停掉被强制踢出但仍挂着的 docker compose build 进程；发布锁随后自动释放。
2. 备份 /etc/docker/daemon.json，将 registry-mirrors 清空（改为 Docker Hub 直连），重启 Docker；
   容器与 CICD Web 均正常。
3. 预拉基础镜像：php:7.4-fpm（1.2s）、composer:2.5（17s）。
4. 重新触发 Webhook 自动发布验证。

验证结果

构建恢复正常推进：
  pecl mongodb 编译 152.6s；
  Phalcon 源码走 ghfast.top GitHub 代理下载编译；
  composer install 14.7s 安装全部依赖（含 thinkinggame/ta-php-sdk v3.1.1）；
  综合结论：SUCCESS。
镜像：youdianse-php:dev-d6cca6435ebb
容器：web / nginx / cron 均 Up
HTTP：后台 200、CICD 200
容器内：vendor/thinkinggame/ta-php-sdk 存在

结论与后续

根因：慢镜像源 docker.1ms.run 拉取基础镜像层极慢（从本服务器实测 15 倍于 Docker Hub 直连）。
修复：daemon.json 清空 registry-mirrors，Docker Hub 直连。
后续：本次构建成功后基础层已缓存，后续发布走缓存快速完成；
若再次清理磁盘/镜像缓存，首次构建会重新拉基础镜像，直连速度正常（数秒级）。

回滚

恢复 /etc/docker/daemon.json.bak.* 并重启 Docker 即可回到原镜像源配置。

安全说明
