日期：2026-05-26 来源：apps/web 红蓝对决全流程测试 用途：交后端团队对接，推动接口按 OpenAPI 契约修复 权威契约：docs/api/openapi.yaml（唯一源 packages/contracts/openapi/v1.yaml）

结论先行

Web 用户端竞猜、充值、余额三大功能当前不可用 / 显示异常，根因均在后端接口实际返回与 OpenAPI 契约脱节。前端代码严格遵循契约，未做任何字段适配（按团队约定，前端不写转换器迁就后端错误返回）。后端按契约修齐后，前端无需改动即可恢复。

下列三处脱节均经 curl 实测核实。

B1【阻断】GET /api/v1/predict/activities 竞猜活动列表字段与契约不符，且不返回 options

影响：竞猜卡片队名 / 玩法 / 奖池 / 赔率全部为空；列表无 options 导致无法展示赔率与下注选项。叠加前端历史上缺空值保护时，曾造成首页 + 竞猜页整站 SSR 500（前端已加防御性保护止血，但数据仍缺）。

契约定义（docs/api/openapi.yaml → PredictActivity schema, line 6949）：

id, match_id, match_brief, market_type, name, status,
open_at, open_ts, close_at, close_ts,
pool_total, participant_count, rake_rate,
options[],            # PredictOption: option_key, name, rate, pool_amount, participant_count
result_option_key

后端实际返回（curl 实测 item 字段）：

{
  "id": "...", "match_id": "...",
  "title": "蓝方测试-西班牙vs加拿大",
  "category": "match_result",
  "status": "OPEN",
  "min_bet_diamond": 100, "max_bet_diamond": 50000,
  "close_at_ms": 1779793200000,
  "total_bet_count": 0, "total_bet_amount": 0,
  "settled_at_ms": ..., "winner_option_id": "..."
}

字段对照：

契约字段 后端实际字段 状态
match_brief / name title 字段名不符
market_type category 字段名不符（且取值不同：契约示例 WIN_DRAW_LOSE，实际 match_result）
pool_total total_bet_amount 字段名不符
participant_count total_bet_count 字段名不符
result_option_key winner_option_id 字段名不符
close_at(ISO) + close_ts(ms) close_at_ms 结构不符
open_at / open_ts / rake_rate （缺） 缺字段
options[] （列表完全不返回） 缺字段，关键
— min_bet_diamond / max_bet_diamond / description / settled_at_ms 契约未定义的额外字段

建议：后端按 PredictActivity 契约调整列表返回（含嵌套 options[]）。若列表出于性能考虑确实不返回 options，请在契约中显式区分「列表精简版 schema」与「详情完整版 schema」，由前端按详情接口取 options。

B2【阻断】POST /api/v1/wallet/recharge/init 请求体要求与契约不符，充值完全不可用

影响：充值下单返回 400，充值功能不可用。前端发送的是契约规定字段，无错。

契约定义（docs/api/openapi.yaml → RechargeInitRequest, line 7049）：

required: [amount_rmb, channel]
amount_rmb: string, pattern '^[0-9]+(\.[0-9]{2})?$'   # 例 "50.00"
channel:    string

前端实际发送（符合契约）：

{ "amount_rmb": "100.00", "channel": "wechat" }

后端实际返回 400（code 20001）：

参数 channel 取值必须是 [shark] 之一;
参数 r_m_b_amount 必填;
参数 pay_type 必填;
参数 agree_terms 必填

字段对照：

契约 后端实际要求 状态
amount_rmb r_m_b_amount 字段名不符（疑似 Go struct tag 自动蛇形转换把 RMBAmount 拆成了 r_m_b_amount）
channel (任意 string) channel 必须 ∈ [shark] 取值约束契约未声明
（契约无） pay_type 必填 契约缺字段
（契约无） agree_terms 必填 契约缺字段

建议： 1. 修正字段名 r_m_b_amount → 契约的 amount_rmb（或修 Go 序列化 tag）。 2. 把 channel ∈ [shark] 的枚举约束、pay_type / agree_terms 两个必填字段补进契约 RechargeInitRequest，前端再按更新后的契约补字段。当前 pay_type 取值集合、agree_terms 语义前端无从得知，需后端在契约中明确。

B3【严重】GET /api/v1/me/profile 返回扁平结构，契约为嵌套 wallet 对象

影响：余额恒显示 0；用户 UID 显示 --。前端历史上读 profile.wallet.rmb_balance 无可选链时曾致登录态全站 500（前端已补 wallet?. 止血）。

契约定义（docs/api/openapi.yaml → UserProfile, 约 line 6645）：

id, account, username, level, status, ...
wallet: { rmb_balance, rmb_frozen, rmb_withdrawable, diamond_balance }   # 嵌套对象

后端实际返回（扁平）：

{
  "user_id": "...",       // 契约为 id
  "account": "...", "username": "...", "level": 0, "status": "...",
  "rmb_balance": "...",   // 平铺在顶层，无 wallet 包裹
  "diamond_balance": "...",
  "created_at_ms": ...
  // 无 wallet 子对象；缺 rmb_frozen / rmb_withdrawable
}

字段对照：

契约 后端实际 状态
id user_id 字段名不符
wallet.rmb_balance 顶层 rmb_balance 结构不符（扁平 vs 嵌套）
wallet.diamond_balance 顶层 diamond_balance 结构不符
wallet.rmb_frozen / wallet.rmb_withdrawable （缺） 缺字段

建议：后端按契约返回嵌套 wallet 对象并补齐 rmb_frozen / rmb_withdrawable，主键字段 user_id → id。

附：处理原则

  • 上述脱节前端未做适配映射，按契约读取 + 仅加防御性空值保护（避免单个数据问题拖垮整站 SSR）。
  • 修复方向应为「后端对齐契约」或「先改契约 packages/contracts/openapi/v1.yaml 再 make openapi 同步、前端按新契约调整」，两者择一，避免前后端各自为政。
  • 若部分字段是后端有意演进（如 min_bet_diamond / max_bet_diamond），请同步进契约，前端再接入。
