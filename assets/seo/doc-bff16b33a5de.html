一、结论（先说最重要的）

1. 本账号只跑 CDN，所以权限很简单：**一条 EdgeOne 策略 + 一个子用户密钥**即可（见 2.0）。
2. 但不要把「主账号 API 密钥」交给 AI —— 主账号密钥等于账号全权（含充值/计费、开新资源、改权限、
   管理其它密钥），泄漏的影响面是「整个账号 + 钱」，而不是「只改 CDN 配置」。
   控制台里那条 2026-09-29 18:07 创建的主账号密钥（IKIDDUjj…），如果还没被脚本用到，
   建议直接**禁用/删除**，改用下面创建的「子用户密钥」。
3. 正确做法：访问管理(CAM) -> 新建**子用户** -> 只勾「编程访问（API 密钥）」-> 只授予
   EdgeOne 相关权限 -> 创建时**立即保存 SecretId/SecretKey**（腾讯云自 2023-11-30 起
   不再提供 SecretKey 二次查询，只显示一次）。
4. 密钥只落地在服务器上的 root-only 文件（600），仓库里**只记录路径**；CI 已拦截密钥入库。
5. 国际站账号要用国际站的 endpoint/SDK（域名带 intl），与国内站不通用 —— 详见第四节。

二、控制台步骤（子用户 + API 密钥）

2.0 最省事路径（本账号只有 CDN，就这样办，2 分钟）

这个腾讯云账号只用来跑 CDN（EdgeOne），所以权限不用拆细，一条策略就够：

  步骤1  访问管理 -> 用户 -> 新建用户 -> 自定义创建
         用户名 ai-edgeone-operator ｜ 只勾「编程访问」
  步骤2  权限策略搜「EdgeOne」，只勾一条：QcloudEdgeOneFullAccess（EdgeOne/TEO 全读写）
  步骤3  建好后 -> API 密钥 -> 生成密钥 -> 当场复制 SecretId/SecretKey

完事。这条策略管的就是"改 CDN 配置"，不含计费、不含其它产品，正好对应"只需要管理 CDN"。

新建用户页面的三个易混项：
  · 创建方式选「自定义创建」，别用「快速创建」（快速创建不能细选访问方式）
  · 「需添加已存在账号作为您的子账号？」= 协作者邀请，不点
  · 「仅用于接收消息」= 消息接收人，跟我们无关，不点
  · 访问方式只勾「编程访问」，**不要勾控制台访问**（要登录再另说）

权限那一步（设置用户权限）：
  搜索框输入 `TEO`（EdgeOne 在 CAM 里的产品名是「边缘安全加速平台 EO」，API 代号 TEO；
  搜 EdgeOne 无结果时务必改搜 TEO）。实测 2026-09-30 搜 TEO 得到三条：
    `QcloudTEOFullAccess`       边缘安全加速平台 EO 全读写访问权限   ← 勾这条
    `QcloudTEOReadOnlyaccess`   边缘安全加速平台 EO 只读访问权限     ← 只读，不够用
    `QcloudCOSDataWriteOnly`    对象存储 COS 数据只写               ← 无关，不勾
  ⚠️ 列表顶部的 `AdministratorAccess` / `QCloudResourceFullAccess` / `QCloudFinanceFullAccess`
     一律不要勾（全局或财务权限，等于把主账号钥匙给出去）。
  若搜不到 EdgeOne 的预设策略（部分账号未开预设策略），新建自定义策略 -> 按策略语法，用：
      { "version": "2.0",
        "statement": [ { "effect": "allow", "action": ["teo:*"], "resource": ["*"] } ] }
      起名如 edgeone-cdn-operator，保存后回到向导勾选它；或走「按产品功能」勾 EdgeOne 读写操作。

2.1 详细步骤（需要更细的控制时再看）

1) 访问管理 -> 用户 -> 新建用户
   用户类型：自定义创建
   访问方式：只勾「编程访问」（不要给控制台登录密码；要登录再单独给）
   用户名建议：ai-edgeone-operator（谁用、干什么一眼能看懂）

2) 设置用户权限（策略）：搜索并勾选 EdgeOne / TEO 相关策略
   - 只读排障：QcloudEdgeOneReadOnlyAccess（或控制台搜索「EdgeOne」后带 ReadOnly 的）
   - 需要配置 CDN：QcloudEdgeOneFullAccess（EdgeOne/TEO 全读写；不含计费与其它产品）
   如需更小权限，可自定义策略，只放开 zone/加速域名/规则引擎/缓存 相关的 Action。
   ⚠️ 策略名以控制台搜索结果为准（EdgeOne 在 API 层又叫 TEO）。

3) 创建完成后，在用户详情 -> API 密钥 -> 生成密钥，**当场复制 SecretId + SecretKey**。

4) 可选但强烈建议：给这个子用户/密钥加「限制来源 IP」
   - CAM 策略条件里限制 SourceIp = 我们执行 AI 的那台机器公网 IP（例如香港 standby 34.150.1.185），
     这样密钥即使泄漏，也只能从我们自己的服务器调用。

三、密钥怎么「给 AI」

原则：密钥进服务器，不进聊天、不进仓库。

存放位置（沿用现有 Cloudflare Token 的约定）：
  香港机器（入口机或 standby）：/root/.config/tencentcloud/edgeone.credentials   权限 600
  内容建议用「键值对」，便于脚本读取：
      [敏感内容已脱敏]
      [敏感内容已脱敏]
      region     = ap-hongkong            # 或 EdgeOne 要求的区域参数
      endpoint   = <按国际站文档填，见第四节>
  或者写成 JSON（/root/.config/tencentcloud/edgeone.json），脚本直接 load。

给 AI 的方式（任选）：
  a) 告诉 AI「凭据在该路径」——AI 通过 SSH 在该机器上直接读文件调用（推荐，最省事也最安全）；
  b) 本地跑脚本时用环境变量注入（TENCENTCLOUD_SECRET_ID / TENCENTCLOUD_SECRET_KEY），
     注意别写进 .env 提交、别出现在命令行历史（用 env 文件 + chmod 600）。

禁止：把 SecretKey 贴进群聊/工单/文档/仓库；也不要贴到 AI 对话里（贴了就该轮换）。

四、AI / 脚本怎么调用（4 条路）

1) tccli（腾讯云官方 CLI，最快）
   安装：pip install tccli；tccli configure set secretId ... secretKey ... region ...
   调用：tccli teo DescribeZones / tccli teo CreateAccelerationDomain ...
   注意：国际站要用国际站的 endpoint（文档里会写明，形如 xxx.intl.tencentcloudapi.com），
         tccli 可用 --endpoint 指定；国内站账号与国际站账号的密钥不通用。

2) Python SDK（推荐写成脚本，便于纳入我们仓库）
   包：tencentcloud-sdk-python（国际站用对应的 intl 包/文档示例）
   模块：tencentcloud.teo.v20220901（EdgeOne 的 API 产品名是 TEO，版本 v20220901）
   调用链：DescribeZones -> ModifyZone / CreateAccelerationDomain /
          ModifyAccelerationDomain / CreateL7AccRules（规则引擎）/ PurgeCaches / PreloadCaches

3) API Explorer（控制台内置，用来确认参数名最省事）
   在控制台「工具 -> API Explorer」搜 EdgeOne/TEO，填参数就能生成调用示例和签名，
   适合把「我要改什么」翻译成确定的接口名。

4) Terraform（把 CDN 配置当代码管理，跟我们 CF 的脚本化思路最接近）
   provider：tencentcloud；EdgeOne 资源前缀是 tencentcloud_teo_*（如 tencentcloud_teo_zone、
   tencentcloud_teo_zone_setting、tencentcloud_teo_rule_engine_setting）。
   适合以后固定配置、做 review 与回滚；前期先用 tccli/SDK 摸接口。

⚠️ 上面接口名/策略名以国际站最新文档为准；不确定就先用 API Explorer 验证一次。

五、安全清单

[ ] 主账号密钥已禁用/删除（或至少不用来跑脚本）
[ ] 子用户只勾「编程访问」，只给 EdgeOne 权限，不给计费/其它产品
[ ] 密钥文件 600，属主 root，路径固定、只记路径不记值
[ ] 可选：CAM 策略限制 SourceIp（只允许我们的服务器调用）
[ ] 定期轮换（建议 90 天；换密钥时先建新、验证通过再禁用旧的）
[ ] 开启操作审计（云审计 CloudAudit）：谁在什么时候改了哪个 CDN 配置可追溯
[ ] 密钥泄漏时的处置：先禁用密钥、再查审计日志、最后轮换

六、落到本仓库的约定

1. 密钥索引登记在 docker/workbench/MACHINE_ACCESS_MATRIX.md「云权限索引」表，只写路径与状态。
2. docker/ci/check.py 已扩展拦截腾讯云密钥样式（secret_id/secret_key/敏感凭据：[已脱敏]
   server-info 目录内出现即 CI 失败。
3. 调用脚本建议放 docker/deploy/hongkong/tencent_edgeone_api.py（参照 cf_api.py 的写法），
   密钥路径从环境变量或 /root/.config/tencentcloud/edgeone.credentials 读取，绝不写在脚本里。
