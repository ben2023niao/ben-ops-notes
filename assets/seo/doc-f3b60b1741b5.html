本协议定义 Agent 什么时候可以提交完成申请。它属于 Agent-neutral Core，不绑定 Codex、Claude Code 或任何 hook。

乌托邦 的铁律是：AI Agent 只有完成申请权，没有完成裁决权。

Agent 可以声明自己已经实现或验证了某个切片，但不能自己宣布项目已完成、验收通过或可以上线。真正的完成裁决必须来自 Project Decision，由 CI、QA、Reviewer、Owner 和验收矩阵共同决定。

1. 基本原则

  1. 没有证据，不能声明完成。
  2. 只跑冒烟测试，不能声明完成。
  3. 只验证某一端，不能声明项目完成。
  4. MVP 可以分阶段，但每个阶段必须写清边界、风险和下一步。
  5. Hook 是 Adapter 可选增强，不是 Core 默认完成条件。
  6. Agent Claim 只能是 implemented、verified、blocked。
  7. Project Decision 才能是 pending-review、accepted、rejected、released。

2. 状态模型

层级 允许状态 谁填写 含义
Agent Claim implemented Agent 已实现，等待验证或 review。
Agent Claim verified Agent 已按证据完成验证，提交完成申请。
Agent Claim blocked Agent 有阻塞，不能继续推进或不能验收。
Project Decision pending-review Reviewer / Owner / CI 已收到完成申请，等待裁决。
Project Decision accepted Reviewer / Owner / QA / CI 验收证据满足当前阶段要求。
Project Decision rejected Reviewer / Owner / QA / CI 证据或实现不满足要求，需要返工。
Project Decision released Owner / Release Manager / CI 已通过发布流程并完成上线。

Agent 不允许把自己的 Agent Claim 写成 accepted、released、已完成、验收通过 或 可以上线。

3. 完成申请前必须回答

问题 证据
对应哪个需求 ID docs/prd/requirements.md 或模块 PRD
改了哪些文件 Agent 日志修改清单
接口是否变更 OpenAPI、事件或不涉及原因
数据/权限是否变更 数据模型、权限、审计或不涉及原因
跑了哪些自动化测试 命令和结果
跑了哪些手工/E2E 场景 场景、环境和结果
UI 是否真实验证 截图、视口、console、交互结果或不涉及原因
是否更新验收矩阵 docs/qa/acceptance-evidence.md 和 docs/qa/project-acceptance.md
是否做红蓝对抗 蓝队、红队、合入判断
还有什么风险 未完成、阻塞、后续建议

4. 禁止完成声明

出现以下情况时，Agent 必须写 不允许合入 或 未完成验证：

  1. 验收证据缺失。
  2. UI 页面没有截图或真实视口验证。
  3. 接口没有契约或 mock 来源说明。
  4. 后台没有权限和审计说明。
  5. 资金、订单、扣费、收益、权限、处罚等高风险逻辑没有服务端测试。
  6. 只有健康检查、冒烟测试或接口 200。
  7. 测试失败但未修复。
  8. 红队发现阻塞问题。

5. 最终回复格式

Agent 最终回复至少包含：

  1. Agent Claim：implemented / verified / blocked。
  2. Project Decision：pending-review，或引用 reviewer/CI/Owner 已给出的裁决。
  3. 完成申请范围。
  4. 验证命令。
  5. 验收证据路径。
  6. 剩余风险。
  7. 合入判断。

建议使用 docs/templates/completion-report-template.md。
