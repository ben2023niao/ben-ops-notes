执行方式

按用户要求，尽量使用 Python 做维护逻辑，shell 只作为 SSH 启动器。

流程：

1. 本地 Python 生成 docker/补宝塔游戏静态文件/126 文件 manifest。
2. 计算每个文件 size 和 sha256。
3. 通过 ssh 调宝塔远程 Python，比对 /www/wwwroot/pg-static/126。
4. 本地打 tar.gz，scp 到宝塔 /tmp。
5. 宝塔远程 Python 安全解压到 /www/wwwroot/pg-static。
6. 再次按 manifest 做 size + sha256 比对。
7. 宝塔远程 Python 调 gsutil rsync 同步 GCS live 和 backup。
8. 本地 Python 做公开 URL 巡检。

后续注意

1. 如果测试仍反馈 brazil 多语言未显示，优先抓 Network 里具体 404 的文件路径。
2. 如果 404 发生在 pg-static / GCS，按本流程补文件并同步。
3. 如果静态资源均 200，但页面仍不显示多语言，再看游戏前端语言参数、缓存、Service Worker 或 API 返回。
4. 这类补文件操作继续优先用 Python manifest + sha256 比对，避免盲目覆盖。
