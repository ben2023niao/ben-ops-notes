背景

alb_white.txt 和 alb_white_secret.txt 都需要在测试环境容器内存在，否则业务读取白名单或密钥文件时会异常。

2026-07-30 起，这两个文件统一按测试服务器本地运行文件维护。业务仓库里即使存在同名文件，测试环境运行也不以业务仓库版本为准；发布拉代码后会用测试服务器本地源文件覆盖容器内同名文件。

策略

运维仓库 CICD 发布流程增加业务本地保护文件机制：

"protected_app_local_files": [
  "alb_white.txt",
  "alb_white_secret.txt"
]

服务器本地源目录：

cicd-web/runtime/app-local-files

备份目录：

cicd-web/runtime/app-local-file-backups

两个目录都位于 runtime 下，不提交 Git。源文件和备份文件权限设置为 0600。

发布流程

  1. 拉取/清理业务代码前，先检查服务器本地源目录。
  2. 如果业务目录里只有这两个受保护 txt 出现 dirty，先迁移到服务器本地源目录，再恢复业务 Git 工作区。
  3. 拉取/切换业务代码后，检查服务器本地源文件是否存在。
  4. 如果源文件缺失，则优先从业务目录现有文件初始化；仍缺失时从 cicd-web/runtime/app-local-file-backups 恢复。
  5. 如果源文件和备份都缺失，则发布失败，避免构建出缺少保护文件的容器。
  6. 容器重建后，发布流程用服务器本地源文件覆盖 web/cron 容器内同名文件，并修正权限。
  7. 发布健康检查成功后，再用服务器本地源文件刷新备份。

安全边界

  • 不读取、不输出、不提交 alb_white_secret.txt 内容。
  • 只记录文件名、存在性和大小。
  • 保护文件路径必须是业务仓库内相对路径，禁止绝对路径和 ..。
  • alb_white.txt 和 alb_white_secret.txt 的测试环境新增内容都只维护在测试服务器本地源目录。
  • 两份文件允许开发和运维在测试服务器本地维护更新；发布流程不会把内容提交到业务仓库。
  • 业务仓库出现仅这两个文件的本地改动时，发布流程会先迁移到服务器本地源目录，再恢复业务 Git 工作区，避免 dirty 阻塞。
  • 业务仓库拉取到的同名文件只视为代码仓库基线，不作为测试环境运行版本。

容器内权限

web 和 cron 容器启动时会对两份保护文件执行权限修正；发布器在容器重建后也会执行同样权限修正：

chgrp www-data alb_white.txt alb_white_secret.txt
chmod 0640 alb_white.txt alb_white_secret.txt

原因：PHP-FPM worker 使用 www-data 用户运行。文件如果是 root:root 0600，容器里虽然 is_file=true，但业务代码 file() 读取会失败，导致 checkTokenV2 无法读取平台私钥并返回 4002 Service Error。

验证

python3 -m py_compile cicd-web.py cicd-web/core.py cicd-web/config.py cicd-web/telegram.py cicd-web/command.py
bash -n entrypoint/web-entrypoint.sh entrypoint/cron-entrypoint.sh entrypoint/cron-task-runner.sh entrypoint/queue-watchdog.sh cicd-web.sh
docker compose --profile cron config >/tmp/youdianse-dev-compose-local-secret-check.yml

发布后确认：

test -f /opt/docker-youdianse-php/cicd-web/runtime/app-local-files/alb_white.txt
test -f /opt/docker-youdianse-php/cicd-web/runtime/app-local-files/alb_white_secret.txt
test -f /opt/docker-youdianse-php/cicd-web/runtime/app-local-file-backups/alb_white.txt
test -f /opt/docker-youdianse-php/cicd-web/runtime/app-local-file-backups/alb_white_secret.txt
docker exec youdianse-dev-php-web test -f /var/www/html/youdianse-php/alb_white.txt
docker exec youdianse-dev-php-web test -f /var/www/html/youdianse-php/alb_white_secret.txt
docker exec youdianse-dev-php-cron test -f /var/www/html/youdianse-php/alb_white.txt
docker exec youdianse-dev-php-cron test -f /var/www/html/youdianse-php/alb_white_secret.txt

权限验证：

docker exec youdianse-dev-php-web stat -c "%n owner=%U:%G mode=%a" /var/www/html/youdianse-php/alb_white.txt /var/www/html/youdianse-php/alb_white_secret.txt
docker exec -u www-data youdianse-dev-php-web php -r 'foreach (["alb_white.txt","alb_white_secret.txt"] as $f) { $p="/var/www/html/youdianse-php/".$f; echo $f." readable=".(is_readable($p)?"yes":"no").PHP_EOL; }'
