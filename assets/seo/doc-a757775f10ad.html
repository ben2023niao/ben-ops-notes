二、真实输出暴露的问题

1. 时间混在一起（已修复）

03 和巴西后端是 UTC，香港是 CST，原输出里同时出现 07:57 和 16:05。 现在所有分段统一为：

========== [2026-10-23 16:01:42 北京] 停止容器 ==========

使用 TZ=Asia/Shanghai date '+%F %T'，三地执行器都能正常输出北京时间。

2. 空行在粘贴时被吞（已修复）

真实终端里出现 echo ""echo "===..."，两个命令粘到一行。 已把 echo "" + echo "====" 改成单条：

printf '\n========== [%s 北京] 镜像 ==========\n' "$(TZ=Asia/Shanghai date '+%F %T')"

3. 打包输出太长（已加精简模式）

完整日志约 1000+ 行，主要是 Docker legacy builder 的 19 个 Step（8 个厂家）。 页面新增“精简模式”：

sh build.sh all 20261023-ben 2>&1 | tee /tmp/build-20261023-ben.log \
  | grep --line-buffered -E '开始构建厂商|Successfully tagged|镜像打包并推送成功|ERROR|error|失败'

只显示每个厂家的开始/成功/失败，完整日志仍保存在 /tmp/build-20261023-ben.log。

4. 构建上下文 2.6GB

/data/pgserver 约 2.6GB（vendor_a 794M、pg 489M、pp 390M 等）， docker build 每次都把整个目录发给 daemon。 建议给 build.sh 加动态 .dockerignore 或临时构建目录，只带当前厂家源码、 requirements.txt 和 Dockerfile。

5. 停止容器占了大部分时间

事件日志显示 docker stop 每个容器约 10 秒，9 个厂家约 84 秒：

08:01:53 stop api
08:02:04 stop pg
08:02:14 stop vendor_a
...
08:03:17 stop g759

可把 stop.sh 改成 docker stop -t 3，或一次性并行：

docker stop $(docker ps -q --filter name=game-service-)

每台通常可省 1 分钟以上。

三、页面本轮改动

  1. 所有步骤默认折叠。
  2. 每个步骤输出加北京时间分段，空行改用 printf，粘贴不会再粘行。
  3. rsync 改为 --info=progress2，只显示总进度。
  4. 打包新增精简模式（完整日志落盘）。
  5. 验证输出按机器分段，docker ps 改表格。
  6. 补充“构建上下文 2.6GB”和“stop 80 秒”两条优化建议。

四、验证

  • 四组折叠默认关闭
  • 手机 390 / 电脑 1280 无横向溢出
  • 后端、打包、检查、验证命令均通过 bash -n
  • 北京时间和实际执行时间一致
