三、源站间歇性 502

故障现象

整点前后多个域名同时出现 502，一两分钟后自动恢复。10-26 01:00 受影响域名包括：

  • szlitongdasha.com
  • jstglm.com
  • jshymc.com
  • lycccn.com

真实配置

项目 实际值
Nginx 1.18.0
H5 上游 203.0.113.1:3003，keepalive 32
PC 上游 203.0.113.1:3004，keepalive 32
Node v22.19.0
Node keepAliveTimeout 5000ms
Node headersTimeout 60000ms
Node requestTimeout 300000ms

日志证据

2026/10/26 00:50:07 recv() failed (104) ... upstream: "http://203.0.113.1:3004/"
2026/10/26 01:00:08 recv() failed (104) ... host: "zhezc.com"
2026/10/26 01:00:09 recv() failed (104) ... host: "lycccn.com"
2026/10/26 01:00:10 recv() failed (104) ... host: "csajs.com"

同时存在：

upstream prematurely closed connection while reading response header from upstream

根因

  • Nginx 复用上游空闲连接。
  • Node 默认 5 秒后关闭空闲连接。
  • Nginx 连接池内仍保留该连接，下一次请求复用时返回 104/502。
  • 整点流量集中时，一次失效连接会影响多个域名，看起来像整站闪断。
  • 两个 Node 容器均未重启，数据库、证书和 CDN 配置不是本次根因。

修复方式

Nginx 1.18 不支持较新版本的上游 keepalive_timeout 指令，因此从 Node 侧对齐：

参数 修复后
keepAliveTimeout 75000ms
headersTimeout 76000ms
Nginx 上游空闲连接 约 60 秒先关闭

Node 比 Nginx 晚关闭连接，Nginx 不会再取到 Node 已关闭的空闲连接，同时保留上游连接复用性能。

当前容器部署

  • 预加载文件：/app/http-keepalive-preload.cjs
  • PM2 node_args：--require /app/http-keepalive-preload.cjs
  • 使用 PM2 cluster 滚动 reload，未重启整个容器
  • H5：8/8 worker online
  • PC：8/8 worker online

每个 worker 启动日志：

[http-keepalive] keepAliveTimeout=75000ms headersTimeout=76000ms

后续发布固化

以下文件已加入同一预加载逻辑：

  • devops/python/ben-bot/data/scripts/.shared/http-keepalive-preload.cjs
  • devops/python/ben-bot/data/scripts/测试环境-游点涩-h5-发版/remote_youdianse_h5_templates.py
  • devops/python/ben-bot/data/scripts/测试环境-游点涩-h5-发版/remote_youdianse_h5_deploy.py

后续前端构建会：

  1. 写入 http-keepalive-preload.cjs
  2. 复制到最终镜像
  3. 在 PM2 NODE_OPTIONS 和 node_args 中注入预加载

因此正常重建前端镜像后不会回退到 Node 默认 5 秒。
