建设范围

本次在 Google Cloud 香港区域新增一套独立运行环境，不迁移、不替换巴西环境，不修改现有线上 DNS。

明确边界：

  • 香港业务后续统一使用开发创建的 cn 分支。
  • 当前远程仓库尚无 cn 分支，因此本次不部署业务代码和容器。
  • 不迁移、不新建、不调整 MySQL 和 Redis，业务后续继续使用代码当前配置的数据服务。
  • 香港入口机不安装宝塔面板，只保留 Docker、Nginx 和资源同步必需工具。
  • 不复制巴西机器人、旧计划任务、宝塔目录和旧 Nginx 站点配置。

Google Cloud 资源

项目：infra-alc-20260511

VPC：bizops-hongkong-slotsapi-network-v2

子网：bizops-hongkong-slotsapi-subnet-v2

区域与网段：asia-east2 / 192.0.2.1/20

角色 实例 可用区 规格 内网 IP 固定公网 IP 系统盘
香港入口/Nginx bizops-hongkong-game-results-data-bt asia-east2-a e2-medium 192.0.2.1 192.0.2.14 500GB pd-balanced
香港后端 01 bizops-hongkong-sanic-prod-01 asia-east2-b e2-standard-8 192.0.2.1 192.0.2.16 500GB pd-balanced
香港后端 02 bizops-hongkong-sanic-prod-02 asia-east2-c e2-standard-8 192.0.2.1 192.0.2.17 500GB pd-balanced
香港禅道 bizops-hk-zentao-prod-01 asia-east2-a e2-standard-2 192.0.2.1 192.0.2.12 100GB pd-balanced

三台实例分散在 a/b/c 三个可用区。根文件系统均已自动扩展到约 484GB。

SSH 与堡垒机接入

三台香港服务器均已启用：

  • root SSH 登录。
  • SSH 密码认证。
  • SSH 公钥认证继续保留。
  • root 密码统一使用现有 PGSERVER_DEPLOY_PASS，文档不记录明文。

已逐台禁用本地公钥和 SSH Agent，仅使用密码完成登录实测：

hostname 公网 IP root 密码登录
bizops-hongkong-game-results-data-bt 192.0.2.14 通过
bizops-hongkong-sanic-prod-01 192.0.2.16 通过
bizops-hongkong-sanic-prod-02 192.0.2.17 通过

堡垒机录入时使用以上 hostname、公网 IP、用户 root 和现有巴西发布密码即可。

最小化环境

香港入口机：

  • Ubuntu 22.04 LTS
  • Docker 29.1.3
  • Docker Compose 2.40.3
  • Nginx 1.18.0
  • curl、wget、git、rsync、jq、unzip
  • UTC 时区

香港后端 01/02：

  • Ubuntu Minimal 26.04 LTS
  • OpenSSH Server
  • Docker 29.1.3
  • Docker Compose 2.40.3
  • curl、git、rsync、jq、unzip
  • UTC 时区

后端的一次性 Google startup-script 已在初始化完成后移除，后续重启不会重复执行安装流程。

网络规则

当前香港 VPC 只放行：

  • 带 hk-ssh 标签的实例：公网 TCP 22。
  • 带 hk-baota 标签的入口机：公网 TCP 80/443。
  • 带 hk-baota 或 hk-backend 标签的三台实例：公网 TCP 45876，供 Beszel Hub 连接 agent。
  • 入口机 192.0.2.1 到后端：TCP 8765、9090-9104。
  • 香港子网内部：SSH 和 ICMP。

未复制巴西 VPC 中对公网开放 MySQL、Redis、Docker API 和大范围游戏端口的旧规则。

2026-07-20 新增禅道实例使用 hk-ssh,hk-zentao 标签：公网只开放 TCP 22/80，不开放 3306。部署和快照细节见 docker/doc/2026-07-20-【架构改造】香港禅道服务器Docker部署与每日快照配置记录.md。

每日快照

  • 香港入口/Nginx：bizops-hk-nginx-daily-snapshot，香港时间每日 04:00，保留 7 天。
  • 香港禅道：bizops-hk-zentao-daily-snapshot，香港时间每日 05:00，保留 7 天。
  • 两个策略的快照存储位置均为 asia-east2。

入口机 Nginx 当前只有最小默认站点：

GET /healthz -> 200 ok
其他未知请求 -> 404

公网实测：http://192.0.2.14/healthz 返回 200 ok。

Beszel 监控

香港三台服务器均已运行 henrygd/beszel-agent：

hostname 公网 IP 容器状态 重启策略 监听端口 公网连通
bizops-hongkong-game-results-data-bt 192.0.2.14 running unless-stopped TCP 45876 通过
bizops-hongkong-sanic-prod-01 192.0.2.16 running unless-stopped TCP 45876 通过
bizops-hongkong-sanic-prod-02 192.0.2.17 running unless-stopped TCP 45876 通过

Google Cloud 防火墙规则：

name: bizops-hk-allow-beszel-agent
network: bizops-hongkong-slotsapi-network-v2
direction: INGRESS
source: 192.0.2.3/0
target_tags: hk-baota, hk-backend
allow: tcp:45876

Beszel 的 TOKEN、agent 私钥和其他认证信息不写入文档。确认 Hub 固定出口 IP 后，建议把 source 从 192.0.2.3/0 收紧为 Hub 出口地址。

静态资源

现有静态资源已经通过 Google HTTPS Load Balancer、Cloud CDN 和 GCS 全球分发。香港环境继续复用该链路，不把约 24GB 静态目录重复复制到香港入口机。

香港独立域名尚未配置；等待域名清单和 cn 分支后再新增 Cloudflare DNS、证书及 Nginx server 配置。

结果资源同步

巴西源目录大小约 120GB：

/www/wwwroot/game_results_data/

本次采用一次性后台同步链路：

巴西入口 /www/wwwroot/game_results_data/
  -> 香港入口 /www/wwwroot/game_results_data/
  -> 香港后端 01/02 /opt/game_results_datas/

巴西入口上的后台 unit：

bizops-hk-results-bootstrap.service

状态和进度检查：

systemctl status bizops-hk-results-bootstrap.service
tail -n 50 /var/log/bizops-hk-results-bootstrap.log
du -sh /www/wwwroot/game_results_data

同步使用独立 SSH key，并限制来源 IP。没有创建自动周期任务；业务发布前需要再执行一次增量同步和目录完整性核对。

后续待办

  1. 等待开发创建并推送远程 cn 分支。
  2. 将部署脚本改成巴西与香港两套独立 inventory，香港固定拉取 cn。
  3. 从 cn 分支部署全部游戏容器和 platform-api 到香港后端 01/02。
  4. 根据香港独立域名生成最小 Nginx upstream 和站点配置。
  5. 配置 Cloudflare DNS 和证书，保持巴西域名及流量不变。
  6. 完成结果资源末次增量同步、端口健康检查和浏览器游戏巡检。
  7. 发布成功后再决定是否收紧公网 SSH 来源范围及回收临时 Google IAM 管理角色。

待购买域名规划

香港环境计划购买 7 个根域名，全部使用 .com，不使用 m.<root> 形式的移动端子域名。

业务域名池 6 个：

hkcloudplay01.com
hkcloudplay02.com
hkcloudplay03.com
hkcloudplay04.com
hkcloudplay05.com
hkcloudplay06.com

API、Socket 和 Verify 共用根域名 1 个：

hkplaycore.com

hkplaycore.com 计划派生 games、socket、verify 及各厂商 *-api 子域名。业务域名池计划派生各厂商 *-games、*-static 等子域名；这些子域名不需要单独购买。

2026-07-15 通过 Verisign .com RDAP 实时检查，以上 7 个候选均返回未注册；最终可购买状态和是否存在溢价以注册商结算页面为准。域名购买完成前不写入 Cloudflare、Nginx 或业务配置。
