背景与事件复盘

2026-08-10 已为线上后端 ip-172-31-31-108 接入 500G 数据盘并把业务日志迁移到 /data/docker-youdianse-php/app-logs（bind 到 runtime/app-logs）。但磁盘清理守护的 业务日志阈值仍停留在旧的 20G，导致 2026-08-13 22:00 发生误删：

触发：app logs 20.0G >= 20.0G
根盘：34.9% -> 33.1%（根盘并无压力）
S3 归档任务：exit=2（S3 写权限 403，preflight 失败）
本地兜底删除：7 个，4.9G（S3 未上传成功的情况下仍被删除）

根因：数据盘扩容后没有同步调整清理阈值；S3 403 未修复时，YOUDIANSE_DISK_CLEAN_LOCAL_DELETE_FALLBACK=1 仍按“旧日志已上传 S3”的前提删除本地日志，造成无备份删除。

现状核对

根盘 /：49G，已用 37%，可用 31G
数据盘 /data：492G，已用 4%，日志目录 17G
业务日志：/opt/docker-youdianse-php/runtime/app-logs（bind 到 /data）
S3 保留脚本：preflight 失败时返回 2 且不删除本地日志（安全）

调整内容

1. 业务日志阈值：20G -> 100G

root crontab：YOUDIANSE_DISK_CLEAN_APP_LOG_THRESHOLD_GB=100
脚本默认值：youdianse-disk-auto-clean.py 默认 100G
CICD 告警：cicd-web/config/settings.json defaults.app_log_alert_gb = 100

/data 可用 492G，100G 约为数据盘的 20%，既保留足够增长空间，也能对异常膨胀兜底。

2. 关闭 S3 失败时的本地兜底删除

root crontab：YOUDIANSE_DISK_CLEAN_LOCAL_DELETE_FALLBACK=0

S3 写权限 403 未修复前，不再无备份删除本地日志；S3 失败时保留本地日志，待写权限修复后恢复 “上传成功再删除”闭环。删除记录目录保留：runtime/disk-auto-clean/local-delete。

3. 保留项

根盘阈值：75%（根盘 49G 与 /data 独立，仍用于 docker 等根盘空间兜底）
S3 保留天数：3 天
巡检频率：每 10 分钟

后续事项

1. S3 写权限 403 为历史待办，仍需修复凭据或 bucket policy，恢复“上传成功再删除”闭环。
2. 日志阈值提高到 100G 后，观察 /data 使用率与日志增长曲线，必要时再调整。
3. 08-13 被兜底删除的 3 天外旧日志无法恢复（S3 未上传成功），后续避免同类删除。

回滚

1. 恢复 crontab 备份：sudo crontab /root/crontab.before-youdianse-disk-threshold.20260814-055721
2. 代码回滚：git revert 77daa35 并推送 main，线上同步后 ./cicd-web.sh restart
