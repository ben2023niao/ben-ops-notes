新建 Skill

Skill 名称：bkl-daily-server-monitor

仓库源目录：

devops-bkl/code/ops-skills-运维技能/bkl-daily-server-monitor/

用户级安装入口：

~/.codex/skills/bkl-daily-server-monitor
→ devops-bkl/code/ops-skills-运维技能/bkl-daily-server-monitor

Skill 内容：

  • SKILL.md：固定巡检、处置、通知、文档、验证和 Git 流程。
  • scripts/monitor_snapshot.py：登录 Beszel，读取 7 台、告警、容器和 24 个业务服务。
  • scripts/notify_ops.py：先核对群标题，再向“机器人操作通知群” -5397881134 发送文本或文档。
  • scripts/run_scheduled.sh：定时任务入口，带单实例锁、日志和失败通知。
  • references/runbook.md：自动处置边界、只报告风险、通知模板和失败处理。
  • assets/com.bkl.daily-server-monitor.plist：macOS LaunchAgent 模板。

私有配置：

~/.config/bkl-monitor/env

权限为 600，保存 Beszel API 和 Telegram Bot 凭据，不进入 Git，不在群消息中输出。

定时配置

Label: com.bkl.daily-server-monitor
Type: macOS LaunchAgent
Schedule: 每天 00:00（电脑本地时区 Asia/Manila）
Command: codex exec --dangerously-bypass-approvals-and-sandbox
Prompt: $bkl-daily-server-monitor

launchctl print gui/501/com.bkl.daily-server-monitor 已确认：

  • type = LaunchAgent
  • state = not running
  • Hour = 0
  • Minute = 0
  • 程序和 working directory 均正确

电脑需要开机、联网并保持用户会话；若 00:00 处于睡眠，launchd 会在唤醒后补跑。

通知策略

所有操作通知到机器人操作通知群：

  • 巡检开始
  • 每台异常服务器的处理结果
  • 全量汇总
  • 文档/附件
  • Git 提交结果
  • 定时任务失败

无异常时仍发送开始和最终完成通知。

验证

  • quick_validate.py：Skill is valid!
  • monitor_snapshot.py：7 台 up，0 告警，83/83 容器 up，24 服务/48 任务 all_up。
  • notify_ops.py --dry-run：目标群标题匹配“机器人操作通知群”。
  • 实际开始通知：已发送到 机器人操作通知群。
  • LaunchAgent plist：plutil -lint 通过，launchctl print 已加载。
  • 定时入口不使用 UI 自动化，因此不依赖 ChatGPT 桌面端 Scheduled 页面。

验证过程中发现本机缺少 PyYAML，导致官方 quick_validate.py 首次运行失败；已安装用户级 PyYAML 6.0.3 后复验通过。

安全边界

  • 自动处置只允许明确、可回滚、低风险的项目。
  • 不自动升级数据库、中间件、业务镜像。
  • 不删除业务数据、持久化卷、Harbor 数据或 Jenkins 主 workspace。
  • 不开放公网 Docker API。
  • 默认只提交本地 main，不自动推送远程。
  • 高风险变更只通知和分析，等待人工授权。
