五、发布规则

H5/PC 前端

1. 前端构建后双推 AWS S3 + 腾讯新加坡 COS。
2. H5 静态资源优先走 test-h5-s3.hbabaxb.cn。
3. PC 静态资源优先走 test-pc-s3.hbabaxb.cn。
4. 前端构建静态资源当前不加密。
5. 页面 HTML/SSR 中的业务 uploads 图片必须使用后端接口返回的 token/t URL。

后端 uploads 图片

1. 后端 uploads 图片防盗刷只走 test-img.* 链路。
2. CommonService::getCdnUrl() 负责把 uploads 图片 URL 转成 token/t。
3. 旧 sign/t、裸图、空 token 都返回默认占位图。
4. AWS CloudFront 老链路作为兜底保留，不做当前 test-img 防盗刷规则。

测试后端发布

1. 更新 workbench/CURRENT_TASK.md，记录当前步骤和下一步。
2. 完成一个明确步骤后，发送 Telegram 飞机群通知。
3. 只提交非敏感文件，不提交 env/.env.dev 中的 key 明文。
4. 推送 dev。
5. 测试服务器 /opt/docker-youdianse-php 执行 fast-forward。
6. 必要时重建 web/nginx/cron。
7. 复测 CommonService 签名、页面 HTML 图片 token/t、裸链占位图。
8. 更新 docs 和 workbench，发送最终总结通知。

七、前几次操作补记

1. 广告缓存旧 sign/t 修复

问题：

PC 顶部推荐/广告 banner 中残留旧 sign/t URL。
Nginx test-img 当前只认 token/t，不认 sign/t。
旧 sign/t 因签名无效返回默认占位图。

处理：

1. 在测试后端 PHP 容器刷新 AdvService::refreshCache()。
2. 重启 web/nginx/cron。
3. 验证 H5/PC/test-pc 页面 token 全量恢复、sign=0、裸链=0。

文档：

docs/2026-07-30-1850-【修复Bug】测试图片默认图与广告缓存旧签名修复记录.md

2. CDN 配置改为默认段 + domains

问题：

早期每新增一个 test-img 域名，都要复制完整 [cdn.tencent.<域名>] 配置段。
后续域名会越来越多，重复配置容易漏改 ttl/token_param/time_param/key。

处理：

1. 后端 CommonService.php 支持 [cdn.tencent._default] 默认配置。
2. [cdn.tencent.test-img] 只维护 domains 列表。
3. 当前 domains=test-img.hbabaxb.cn,test-img.hbazuua.cn。

当前约定：

新增同规则域名只追加 domains。
不要重复写完整单域名段。

3. key_file 方案回退为 key= 字符串

过程：

1. 曾尝试将 CDN key 放到 cicd-web/runtime/tencent-cdn-auth.key。
2. 容器内挂载到 /run/youdianse-tencent-cdn-auth.key。
3. 核验 PHP is_readable 返回 yes，说明不是单纯权限不可读。
4. 为减少挂载/权限/入口脚本风险，最终按用户要求改为 env 直接 key=。

当前状态：

本地 VSCode env/.env.dev：key=<已设置>，key_file=
测试服务器 /opt/docker-youdianse-php/env/.env.dev：key=<已设置>，key_file=
docker-compose.yml：不再挂载 /run/youdianse-tencent-cdn-auth.key
web/cron 容器：key_file 挂载数量为 0

注意：

env/.env.dev 含 CDN key 明文。
该文件可以在本地和测试服务器保留为运行态修改。
不要 git add、不要提交、不要输出完整 diff。

4. H5 /game 裸链回归修复

现象：

H5 /game 页面图片大量变成裸 test-img URL。
浏览器 Network 显示 from service worker，但 HTML SSR 中已经存在裸链。

排查：

1. Service Worker 不是裸链根因。
2. H5 toSizedImage() 会保留 query。
3. 容器内直接调用 GameRepository::getLists() 能返回 token/t。
4. H5 SSR payload 一度为裸 URL，偏向后端/H5 进程态缓存或发布后进程未刷新。

处理与验证：

1. 后端 env 切为 key= 后重启 web/nginx/cron。
2. 重启 H5 测试容器 youdianse_test_18game_h5_client_3003。
3. 外网抓取 /game：
   test_img=123
   敏感凭据：[已脱敏]
   sign=0
   bare=0

九、后续注意

1. 页面图片显示默认图时，先区分前端静态资源域名和后端 uploads 图片域名。
2. test-h5-s3/test-pc-s3 是前端静态资源，不按 uploads token/t 鉴权。
3. test-img.* 是后端 uploads 图片防盗刷域名，必须带 token/t。
4. 浏览器 from service worker 只说明请求由 SW 接管或缓存，不代表裸链由 SW 生成。
5. 后端更新 env 或 CommonService 后，如页面仍有旧 URL，优先刷新业务缓存和 SSR/Nitro 进程。
6. 广告位容易缓存旧 URL，重点看 AdvService::refreshCache()。
7. 每次操作必须先写 workbench，再通知飞机群，再继续下一步。
