对齐 PRD v0.1，目标：赛季开打前完成 v1 生产部署，支撑 32 天赛季。

10.1 总览

阶段 时间窗 主题 关键交付
P0：契约 + 骨架 T-30 ~ T-25（6 天） 立项启动 OpenAPI + 项目骨架 + DB schema + 监控接入 + ADR
P1：资金核心 T-24 ~ T-15（10 天） 资金闭环 充值 / 提现 / 兑换 / 押注 / 派彩 / 对账 + 完整测试
P2：直播 + 竞猜联调 T-14 ~ T-7（8 天） 直播链路 推流 / 拉流 / 转码 / 录制 / 截图 / 鉴黄 / 弹幕 / 押注弹窗 / 派彩 worker
P3：后台 + 主播端 + H5 T-6 ~ T-1（6 天） 端到端联调 后台 8 模块 + 主播端 5 步 + H5 5 pane + 灰度
P4：赛季运营 T+0 ~ T+32（32 天） 稳定运营 监控 / 对账 / 应急 / 调优
P5：复盘 + 转型 T+33 ~ 数据沉淀 用户画像 / 复盘报告 / 矩阵导流

T-0 = 世界杯开幕日（2026-06-13）。本路线图按 T-30 = 2026-05-14 起算。

10.2 Phase 0：契约 + 骨架（6 天）

10.2.1 任务清单

任务 输出 Owner 工期
OpenAPI v1 完整契约 packages/contracts/openapi/v1.yaml @kickoff/contract 2 天
项目骨架（cmd × 8 / internal 结构） services/go-app/** 可跑通 hello @kickoff/backend 2 天
DB schema 全量 migration（33 表） services/go-app/migrations/0001-0033.sql @kickoff/backend 2 天
K8s 基础 manifest（dev / staging） deploy/k8s/** @kickoff/devops 2 天
GitLab CI 跑通 .gitlab-ci.yml 全绿 @kickoff/devops 1 天
Prometheus + Grafana 基础大盘 接入 dev 环境 @kickoff/devops 1 天
SRS 测试集群单节点 / 云直播 SDK 集成 推/拉流跑通 hello stream @kickoff/backend 2 天
ADR-0001 ~ ADR-0012 写完 docs/decisions/ @kickoff/tech 2 天

10.2.2 里程碑

  • M0（T-25）：API 骨架 + DB 全表 + 基础部署可跑通；ADR 全部签字

10.2.3 风险

  • 直播方案 ADR-0003 未决：建议 P0 期内决策完成，否则 P2 阻塞

10.3 Phase 1：资金核心（10 天）

10.3.1 任务清单

任务 模块 工期
登录注册（含验证码 / JWT / 设备指纹 / 18+ 协议） kickoff-auth 1.5 天
钱包基础（user_wallets / user_consume_total / wallet_ledger） kickoff-wallet 1.5 天
充值（微信 + 支付宝双通道，含回调验签 / 二维码 / 状态轮询 / 30min 超时） kickoff-wallet 2 天
提现（含 KYC / 风控引擎 / 审核状态机 / 通道转账） kickoff-wallet 2 天
兑换（正向 + 反向扣 20% / 日次数限制） kickoff-wallet 1 天
押注下单（强一致事务 / 幂等 / 限额 / 累计消费 / 等级升级） kickoff-predict 2 天
派彩 worker（活动结算 / 极端缩放保险丝） kickoff-predict 1.5 天
T+1 对账跑批 worker worker-cron 1 天
审计日志中间件 + audit_log + admin_audit_log infra 1 天
资金完整测试（单元 + 集成 + 并发 + 混沌） QA + Backend 全程并行

10.3.2 测试覆盖率要求

范围 单测 集成 并发 混沌
资金类（wallet / predict） 100% 100% ✓ ✓
鉴权类（auth） 90%+ 90%+ — —
其他业务 80%+ 80%+ — —

10.3.3 里程碑

  • M1（T-15）：资金闭环全打通，对账归零，混沌测试通过

10.3.4 风险

  • 微信 / 支付宝商户号申请周期长（建议 T-30 已开始）
  • KYC 服务商签约可能滞后（v1 可先做"提现 > 1000 阻塞"状态）

10.4 Phase 2：直播 + 竞猜联调（8 天）

10.4.1 任务清单

任务 模块 工期
SRS 集群上线 / 云直播完整接入（按 ADR-0003 决策） infra 3 天
CDN 接入 + 双厂商 GSLB infra 1 天
go-srs-hook 服务 + 推流校验 / 关播登记 kickoff-streamer 1 天
录制 + 截图 worker worker-realtime 1 天
AI 鉴黄接入（阿里云内容安全） worker-realtime 1 天
WebSocket 弹幕（含等级限制 / 敏感词过滤） kickoff-live 1.5 天
进场广播（含 L6 全平台震撼） kickoff-live 0.5 天
打赏 + 连击合并 kickoff-live 1 天
浮动竞猜活动卡 + 押注弹窗 kickoff-predict 1 天
比赛事件流（手工录入 + WS 推送） kickoff-match-detail 1 天
全链路压测 8k CCU + 200 押注/s QA 1.5 天

10.4.2 SRS 自建分支补充任务（若 ADR-0003 选 SRS）

  • SRS Push Edge / Origin / Pull Edge 各 2-4 节点部署
  • 转码集群 FFmpeg × 4
  • Nginx + Lua 播放鉴权
  • 共享存储（NFS）
  • SRS HTTP API exporter

10.4.3 云直播分支补充任务（若 ADR-0003 选 云直播）

  • 云直播商户开通 + 推流域名 + 回调配置
  • 云直播 SDK 集成（推流 URL 生成 / 播放 URL 生成 / 回调验签）
  • 录制 / 截图 webhook 对接

10.4.4 里程碑

  • M2（T-7）：直播链路打通；全链路压测通过；竞猜场景全跑通

10.4.5 风险

  • SRS 自建路径下转码 CPU 压力可能超预期 → 准备弹性扩 SRS Origin / 启用 GPU
  • AI 鉴黄误判率高 → 建立"申诉 + 人工复审" 通道

10.5 Phase 3：后台 + 主播端 + H5（6 天）

10.5.1 任务清单

任务 模块 工期
后台 RBAC + 2FA + IP 白名单 kickoff-admin 1 天
数据看板（4 KPI / 7 日 GMV / 24h 事件流 / TOP 主播） kickoff-admin 1 天
主播管理（列表 / 详情 / 颁发授权码 / 强制下播 / 封禁） kickoff-admin 1 天
用户管理（列表 / 详情 / 冻结 / 手动调余额含双人复核） kickoff-admin 1 天
订单中心（押注 / 充值 / 提现三 tab + 审核 + 退单 + 补单） kickoff-admin 1 天
风控告警（活跃告警 / 处置 / 规则维护） kickoff-admin 1 天
通道对账（自动跑批 / 差异处置 / 历史记录） kickoff-admin 1 天
内容审核（举报队列 / 弹幕违规 / 房间封禁 / 敏感词词库） kickoff-admin 1.5 天
赛事 & 赔率管理（v1 必上：创建赛事 / 配置活动 + 赔率 / 锁盘解盘 / 触发结算） kickoff-admin 1.5 天
主播端 5 步流程 + 3 异常态 kickoff-streamer 1.5 天
H5 5 pane + 沉浸式直播间 kickoff-h5 2 天
端到端联调 + 灰度 24h QA 1 天
Runbook 完善 + on-call 排班 DevOps 0.5 天

★ "后台赛事 & 赔率管理" 和 "内容审核 v1 可用版" 即本次 v1 必须实现，超出原 PRD v1 占位范围。需求增量已在技术文档识别为"建议补入 PRD"，请产品在 P3 前回写 PRD（ADM-201 / ADM-801 状态从"草稿"改"已确认"）。

10.5.2 里程碑

  • M3（T-1）：四端联调通过；灰度 24h 无重大问题；on-call 排班发布；应急预案演练完成

10.5.3 风险

  • 后台前端 v1 简化用模板（Naive UI Admin），美观度妥协可接受
  • 内容审核 v1 仅"最小可用"，复杂场景靠人工

10.6 Phase 4：赛季运营（32 天）

10.6.1 日常工作

  • 每日：T+1 对账（自动 + 人工复核差异）
  • 每日：监控告警值班 24/7
  • 每日：on-call 主备轮值
  • 每日：业务大盘 review（GMV / DAU / 主播质量）
  • 每周：性能调优（慢查询 / 缓存命中 / 容量）
  • 每周：复盘会议（告警 / 故障 / 优化项）

10.6.2 关键比赛日

阶段 时间 重点
小组赛 6/13 - 6/27 流量上升期；用户增长峰值；CDN 带宽签约校验
16 强 7/9 - 7/12 流量加速；押注 GMV 攀升
8 强 7/13 - 7/16 主播分级；大 R 行为分析
半决赛 7/15 + 7/16 高流量预警；扩容到位
决赛 7/19 ★ 全员 on-call；提前 1 周扩容 30%；预案演练

10.6.3 变更冻结

  • 决赛前 1 周禁止非紧急变更
  • 决赛当日 0 变更
  • 紧急变更必须超管 + on-call 双批准 + 灰度

10.6.4 里程碑

  • M4（T+32）：赛季无重大事故；累计 GMV 达标；用户净推荐值 > 30

10.7 Phase 5：复盘 + 转型（赛季后）

10.7.1 数据回流

  • 用户画像（DAU、付费、流失原因）
  • 主播画像（GMV、留存、转化）
  • 业务大盘（GMV 时段分布、市场偏好）
  • 风控复盘（命中率、误判率、漏判）

10.7.2 框架沉淀

  • ADR 全量归档
  • 代码 / SQL 模式抽出公共组件
  • 经验沉淀到 docs/decisions/ 和 docs/agents/logs/

10.7.3 转型评估

  • 评估"夜场经济"模式在非赛事窗口的可持续性
  • 引入 Kafka（按 messaging-strategy.md §5.6）
  • 评估服务拆分（按 system-architecture.md §1.11）
  • 拟定 v2 路线图

10.10 风险矩阵

风险 概率 影响 应对
支付商户号申请被卡 中 高 T-45 提前申请；备选第三方聚合
直播方案 ADR 难产 中 高 T-25 前必须决策；技术负责人决策权
决赛日流量超估算 2x 中 高 提前 1 周扩容；HPA + 降级开关
主播刷量 / 内幕 中 中 风控规则 + 主播禁押注
