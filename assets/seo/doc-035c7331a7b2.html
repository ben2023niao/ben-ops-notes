背景

数据汇报 bot 连续报告后端 ip-172-31-31-108 根盘 75%+（75.5% -> 76.2%），磁盘自动清理每次 都返回“清理完成但失败步骤=1”：S3 归档 exit=2（403）、本地兜底删除 0、业务日志 195G 不变。 用户要求：清理全部服务器磁盘垃圾；操作一步、分析一步、飞机群通知一步；默认只本地 Commit 不 Push。

巡检基线（2026-08-31 实时核验）

后端 ip-172-31-31-108：根盘 77%（49G，可用 12G）；数据盘 42%（196G，业务日志 195.8G）
  主要占用：/var/lib/docker 24.5G（13 个旧 php 发布镜像约 15G）、journald 2.5G
前端 ip-172-31-16-205：根盘 60%（49G，可用 20G）；Docker Build Cache 19.36G；journald 2.2G
宝塔 ip-172-31-26-125：根盘 31%（49G，可用 34G）；数据盘 3%；journald 1.6G；wwwlogs 4.6G

清理执行

后端

- 删除 11 个旧 php 发布镜像（保留当前 1aff98 + 最近 2 个回滚位 95f3b7/261124；均可从 Git 重建）
- journald 压缩至 500M（2.5G -> 528M，释放约 1.9G）
- apt 缓存清理
- 根盘 77%（可用 11.4G）-> 69%（可用 15.3G）

前端

- docker builder prune -af（Build Cache 19.36G -> 0）
- journald 压缩至 500M（2.2G -> 432M，释放约 1.7G）
- apt 缓存清理；保留新旧 h5 镜像作为回滚位
- 根盘 60%（可用 19.5G）-> 19%（可用 39.3G）

宝塔

- journald 压缩至 500M（1.6G -> 536M，释放约 1.1G）
- apt 缓存清理
- 8/16 未压缩旧轮转日志 gzip（237MB -> 12.6MB）；wwwlogs 业务访问日志未删除，保留审计
- 根盘 31%（可用 33.7G）-> 28%（可用 35.0G）

S3 归档失败根因与修复

现象：youdianse-log-s3-retention.py preflight 403（exit=2），自 2026-07-31 起每日失败
实测：
  aws sts get-caller-identity                    OK（arn:aws:iam::176528004422:user/s3-game-prod）
  aws s3api put-object / delete-object           成功（同桶同前缀）
  aws s3api head-bucket                          403（无 ListBucket）
  rclone copyto / deletefile（v1.53.3-DEV、v1.75.0） 403：操作前必做 HeadObject（无 GetObject）
根因：IAM s3-game-prod 只有 PutObject/DeleteObject，rclone 无法跳过对象 HEAD -> 403
修复：脚本上传/删除改用 aws s3api put-object / delete-object（>4G 走 aws s3 cp 兜底），
      移除 rclone 依赖；rclone v1.75.0 已装 /usr/local/bin 备用（旧版备份 .v1.53.3-DEV.bak）
小批量实测：--max-files 3 -> deleted=3 failed=0

全量归档结果

manifest：runtime/log-s3-retention/manifests/20260831-002719.jsonl
结果：724 条 uploaded-deleted，0 failed，0 kept
业务日志：195.8G -> 19G（释放约 176G）
数据盘：42% -> 5%（可用 447G）
保留：3 天（08-29 起）共 103 个文件；2 个 0 字节空占位文件按设计跳过
对象前缀：ops/server-logs/ip-172-31-31-108/app-logs/YYYY/MM/DD/

自动清理脚本加固

youdianse-disk-auto-clean.py 新增 prune_old_release_images：
  触发清理时保留最新 3 个发布镜像 + 运行中镜像，删除其余旧发布镜像（可从 Git 重建）；
  通知文本新增“旧发布镜像”字段。
线上同步：/opt/docker-youdianse-php 工作区 dirty，cicd-web-auto-update.py 因 dirty 跳过 pull，
  符合“只本地提交、不推送”规则；待后续推送后自动更新恢复。
dry-run 验证：skip: root=69.6%, app_logs=19.0G, threshold=75.0%/200.0G；
  --force dry-run：builder=0、image=0、旧发布镜像=0、S3 exit=0、失败步骤=0

      5 容器全部 Up；CICD 200、后台 200；自动清理 dry-run=skip；S3 保留 dry-run candidates=0

宝塔：根盘 28%（35G 可用）；nginx -t 通过；h5/主站 200

后续事项

1. S3 归档每日 04:22 任务恢复正常，观察 3-5 天确认无 403；
2. 自动清理触发时会自动删除超过保留位的旧发布镜像（保留 3 个），回滚需重建镜像；
3. 宝塔 wwwlogs 旧访问日志未删除（业务审计日志），如需归档清理需单独确认；
4. 本地提交未推送；线上工作区手工同步后保持 dirty，待推送后自动更新恢复。

回滚

1. 脚本回滚：git revert 本次提交并同步线上；
2. rclone 旧版备份 /usr/local/bin/rclone.v1.53.3-DEV.bak（当前未使用）；
3. 已删除的旧发布镜像可经 CICD 按 Git 提交重建。
