1. 用户需求

  1. 读取 docker/doc 中补资源文档，使用 workbench，并读取之前操作留下的 doc 文档。
  2. 每步操作发群通知；操作完成后先验证，再汇总文档并把汇总和文档发群里。
  3. 优化厂家端口，使宿主机端口尽可能与容器内监听端口一一对应。例如 PLAYSON 从历史 9104 -> 9020 调整为目标态 9020 -> 9020。
  4. version.json 与 server_configs 后续 git 更新后，不需要重新打包镜像，也不需要重启业务容器；机器人主页增加两个按钮，点击后可选择 Git 版本并更新到全部运行容器内。
  5. 两个热更新按钮放在机器人主页，单独横向占一行。

后续修正：2026-08-06 15:35 用户要求把 version.json 与 server_configs 两个按钮合并为 1 个按钮，一次选择 Git 版本后同时更新两个文件。最终线上状态见 docker/doc/2026-08-06-1535-【优化】机器人运行配置热更新按钮合并上线记录.md。

  • docker/ben-bot/data/scripts/同步维护/action.py

结果：

  • 机器人主页新增独立横向一行：
  • 热更新 version.json
  • 热更新 server_configs
  • 两个按钮直接进入 Git 版本选择页，可选 latest 或最近 Git 短 ID。
  • 版本选择文案从“选择发布版本”调整为“选择 Git 版本”，避免运行配置热更新被误解成整包发布。
  • Telegram callback 增加短码：
  • hv -> hot-version
  • hsc -> hot-server-configs
  • 已验证按钮 callback 最大长度为 56，低于 Telegram 64 字节限制。

3.2 运行配置热更新脚本

新增文件：

  • docker/scripts/hot_update_runtime_config.py

能力：

  • 白名单仅允许更新：
  • version.json
  • server_configs
  • 根据所选 Git 版本执行 git show <revision>:<file> 抽取文件。
  • version.json 会做 JSON 解析校验。
  • 计算本地文件 SHA256。
  • 默认目标后台：
  • 203.0.113.1:01
  • 203.0.113.1:02
  • 默认目标容器：
  • dbqp-pg-release-01/02
  • dbqp-tada-release-01/02
  • dbqp-pp-release-01/02
  • dbqp-popok-release-01/02
  • dbqp-playson-release-01/02
  • dbqp-panda-release-01/02
  • dbqp-platform-api-release-01/02
  • 正式执行时流程： 1. 验证目标容器运行中。 2. scp 文件到后端临时目录。 3. docker cp 到每个运行容器的 /app/<filename>。 4. 容器内 sha256sum 校验。 5. test -f /app/<filename> 校验存在。
  • 不重打镜像、不重启业务容器。
  • dry-run 不连接后端，只验证 Git 文件、SHA256 与目标容器清单，便于本地安全校验。

注意：正式执行依赖运行环境提供 PGSERVER_DEPLOY_PASS，不写入仓库、不输出密钥。

4. 线上影响说明

本次只修改仓库代码与文档：

  • 未重启 PG/TADA/PP/PPK/PLAYSON/PANDA/platform-api 容器。
  • 未重建业务容器。
  • 未覆盖线上 /app/version.json 或 /app/server_configs。
  • 未修改线上 Nginx upstream。
  • 未修改线上防火墙或云防火墙。

端口目标态后续真正落地时，需要在维护窗口内同步完成：

  1. 业务容器按新 PORT_MAPPINGS 重建。
  2. 宝塔 upstream 切换到新端口并 reload。
  3. 后端机器防火墙和云防火墙确认放行新端口。
  4. 公网入口和内网 upstream 健康检查同步验证。

7. 后续建议

  1. 后续运维或开发仅更新 version.json / server_configs 时，可走机器人主页两个热更新按钮，选择 Git 版本后执行文件级热更新。
  2. 端口目标态上线前，需要单独开维护窗口执行容器重建、宝塔 upstream 切换和防火墙检查。
  3. 当前生产运行态仍以历史文档和实时核验为准；不要因为仓库目标态已改，就假设线上端口已经迁移。
