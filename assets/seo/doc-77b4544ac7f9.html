789Bingo Android 3.0.11 客户端静态安全审计

公开版整理说明：本次只对官方 APK 做静态检查，没有运行客户端、登录账号或读取真实 Token、聊天、KYC 与支付数据。文中不提供可直接复用的攻击步骤、硬编码秘密值或完整源码片段。

范围

审计对象为 789Bingo Android 3.0.11，只检查 APK、DEX、Manifest、资源、原生库元数据和 Flutter AOT 产物。样本 SHA256 为 da4e09695176458d01f869fb96033afb07ceceb3f517a7ae068922a9d6864410。

静态检查关注登录与会话、H5 Bridge、KYC 回跳、聊天 Token、自更新、网络安全配置、敏感字符串、日志和隐私保护。没有对生产后端做主动利用测试。

样本与签名

  • 包名为 com.betbingo.game，版本为 3.0.11。
  • APK v2 签名有效，不是 Android Debug 证书。
  • 官方 App Links 声明的包名和证书与 APK 一致。
  • allowBackup=false。
  • 业务逻辑主要在 Flutter AOT 生成的 libapp.so 中。
  • 应用包含 Firebase、Adjust、EngageLab、Facebook、WebView、生物识别和 KYC 组件。

签名和 App Links 一致，说明官方应用归属链完整；这不代表客户端内部逻辑不存在风险。

正向控制

客户端具备以下安全设计：

  • 生产环境固定，API、H5、上传和 WebSocket 使用 HTTPS/WSS。
  • 默认只有少数登录与公开配置接口不附加认证。
  • 401 处理会区分已登出、静默请求和 Token 已更新等状态。
  • Refresh 流程串行化，避免并发刷新覆盖新会话。
  • H5 Bridge 要求 HTTPS，并校验当前页面精确 host。
  • 外部网页深链只允许主域及其子域，HTTP 会升级为 HTTPS。
  • WebView 拒绝 javascript:、file:、data: 和 intent: 等危险导航。
  • 未发现证书错误绕过回调。
  • 遥测具备 Token、密码、手机号、证件号和 Session 的脱敏逻辑。
  • 未发现 AWS 主账号密钥、私钥或公开 source map。

主要风险

1. KYC 回跳缺少完整 Origin 绑定

身份认证 WebView 判断流程完成时，主要依赖 URL 路径片段，之后会把平台会话凭据附加到当前回调地址并重新加载。该实现没有同时绑定精确 scheme 和 host。

只有在供应商页面出现 XSS、开放重定向、恶意导航或第三方脚本被篡改时，该缺陷才可能发展为跨源会话泄露。因此应把它定位为“高危、带前置条件”的静态审计问题，不能表述成已经可远程利用。

建议：

  • 回跳地址只接受精确的 HTTPS 主站 Origin 和精确页面路径。
  • 不把长期 Access Token 放进 URL 查询参数。
  • 使用一次性、短时、绑定 KYC Session 的回跳码。
  • App 用回跳码换取认证结果后立即作废。
  • 供应商页面和第三方资源使用严格的 CSP、脚本清单和供应链监控。

2. 供应商参数可能属于长期秘密

KYC 供应商地址中有客户端硬编码的模板标识和额外的供应商参数。当前只能确认这些值存在，不能仅凭静态代码判断其是否为公开模板标识、短期签名或长期共享密钥。

若供应商参数具有签名或授权能力，应视为客户端不可安全保存的秘密。处理方式是向供应商确认权限后立即轮换，并把签发逻辑迁到服务端，客户端只保留公开模板 ID 和短期 Session。

3. Token 存储保护不足

Access Token、Refresh Token、Session、用户 ID 和过期信息会序列化后写入普通 SharedPreferences，没有使用 Android Keystore、EncryptedSharedPreferences 或等价加密存储。

普通非 Root 设备仍受应用沙箱保护，allowBackup=false 也降低了备份提取风险。但 Root、调试、取证镜像或设备解锁可以读取完整会话材料，Refresh Token 长期存在会扩大影响周期。

建议把会话材料迁到 Keystore 支持的加密存储，并在服务端为 Refresh Token 增加设备绑定、单会话撤销和轮换检测。

4. 自更新缺少内容完整性校验

更新接口响应可以直接把下载地址传给 Android DownloadManager。客户端没有校验 APK SHA256、版本响应签名、下载域名白名单或独立更新清单。

Android 安装器仍会检查包名与签名一致性，因此不能安装不同签名的普通替换包；但更新链路仍缺少供应链完整性和可审计性。

建议固定下载域，版本响应同时下发 SHA256、versionCode 和签名清单；下载完成后先在应用私有目录验证，再交给安装器。

5. 全局允许明文 HTTP

网络安全配置全局允许明文流量。当前主要业务地址使用 HTTPS，但系统不会阻止未来误配置的 HTTP API、更新地址或 WebView 页面。

生产构建应默认关闭明文流量。确需开发例外时，只对明确域名建立临时 domain-config，并确保生产包不包含 QA/UAT/dev 例外。

6. H5 Bridge Token 权限范围偏大

Bridge 的 host 校验能阻止普通第三方页面调用，但已授权主域页面可以请求平台 Access Token。任何主域页面注入、第三方脚本被篡改或危险 H5 路由都可能扩大 Token 暴露面。

建议把 Bridge 授权收窄到明确路径，并使用短期、单用途 Bridge Token；同时为 H5 引入 CSP、Trusted Types、第三方脚本清单和 SRI。

7. KYC 与资金页面缺少截屏保护

未发现用于阻止截屏和录屏的安全窗口标志。身份证、人脸、银行卡、提现明细等页面可能被系统截屏、录屏或具备屏幕采集能力的应用捕获。

建议对敏感页面启用 FLAG_SECURE，在任务切换时遮挡内容，并要求敏感页面退出后不进入普通最近任务缩略图。

8. 其他收口项

  • GIPHY Key 硬编码在客户端，应确认供应商配额和域限制，或改由后端代理。
  • 生产包保留 QA/UAT/dev 深链及测试地址，增加误配置和攻击面。
  • 本地随机 UUID 被用作“设备指纹”，不能独立承担反欺诈或设备可信判断。
  • 符号和构建路径未有效裁剪，降低逆向成本，但不直接等于凭据泄露。

风险分级

等级 问题 结论
高，条件触发 KYC 回跳未绑定精确 Origin 需供应商页被篡改或发生恶意导航，可能导致会话泄露
高，待供应商确认 KYC 供应商参数可能为长期秘密 需确认权限并在必要时轮换
中 Token 明文存于 SharedPreferences 需本地文件读取能力，Refresh Token 生命周期较长
中 自更新缺少哈希和签名清单 系统签名校验仍在，但供应链完整性不足
中 全局允许明文流量 缺少系统级误配置防线
中 Bridge 可向主域页面下发 Access Token 依赖主域内容安全
低至中 KYC 和资金页面未禁止截屏 本地隐私保护不足
低 生产包残留测试深链、第三方 Key 和调试信息 攻击面和逆向便利性增加

整改优先级

P0

  1. 修复 KYC 回跳 Origin 绑定，改用一次性短时回跳码。
  2. 向供应商确认客户端参数权限；若属于秘密，立即轮换。

P1

  1. 会话材料迁入 Android Keystore 支持的安全存储。
  2. 更新链路增加固定域、SHA256、versionCode 和签名清单。
  3. 关闭全局明文 HTTP。
  4. Bridge 收窄到路径白名单并使用短期凭据。

P2

  1. 对 KYC、银行卡和提现页面启用截屏保护。
  2. 轮换并限制第三方 API Key。
  3. 移除生产包中的测试深链和调试能力。
  4. 裁剪符号与构建路径，修复更新接口异常。

复测标准

  • 非预期 Origin 无法获得 Access Token。
  • KYC 回跳凭据一次性、短时并绑定 Session。
  • 普通文件和普通备份无法直接恢复 Refresh Token。
  • 更新包哈希、版本或来源异常时必须拒绝安装。
  • 生产客户端不允许任意明文 HTTP。
  • KYC 页面无法被系统截屏或录屏。
  • Bridge 来源、路径、动作和返回数据均有白名单和审计。

结论

789Bingo 3.0.11 的 APK 签名、App Links 归属链和生产网络地址固定等基础控制有效，没有发现可直接匿名利用的高危 CVE、服务端主密钥、私钥或存量用户 Token。

最优先处理的是 KYC 回跳 Origin 校验和供应商参数权限，其次是 Token 安全存储、自更新完整性和 H5 Bridge 权限范围。静态审计的“未发现”不等于运行时一定不存在，真实存储、网络和认证逻辑仍需在授权窗口中复测。
