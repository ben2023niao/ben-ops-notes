用户要求：参考巴西后端服务器配置，为香港项目创建 2 台后端服务器。

1. 2 台，Docker 环境
2. 与香港现有 nginx 入口机（192.0.2.14 / 192.0.2.1）内网相通
3. 公网 IP 固定
4. root 密码按用户指定值设置（密码明文不入库，见第七节）

四、执行动作

1. 在香港入口机写入初始化脚本 /root/hk-backend-startup.sh（945 字节，
   sha256 918da669a127b69cffae649d14038e767598545ca6e01863d7bfdfbadce4d0a7）：
   设置 root 密码、开启 SSH 密码登录、时区 UTC、安装基础包与 Docker、启用 docker 服务
2. 小规格试跑一台探针实例，确认服务账号具备创建权限、镜像族可用，随后删除
3. 创建 bizops-hongkong-sanic-prod-01（asia-east2-b，内网 192.0.2.1，绑定 192.0.2.16）
4. 创建 bizops-hongkong-sanic-prod-02（asia-east2-c，内网 192.0.2.1，绑定 192.0.2.17）
5. 两台共用同一份 startup-script（创建时通过 mevendor_ata 注入）

遇到的问题与处理：

问题：创建时 --image-family=ubuntu-pro-2604-lts-amd64 报 imageFamilyViews not found。
处理：改用实践可用的 ubuntu-2204-lts（与香港入口机同版本）。
问题：startup-script 执行成功（串口日志 exit status 0、Docker 已装），但 SSH 密码登录
  仍被拒（Permission denied (publickey)）。
原因：Ubuntu 云镜像的 cloud-init 写 /etc/ssh/sshd_config.d/50-cloud-init.conf，
  内含 PasswordAuthentication no；sshd 配置为「首次匹配优先」，主配置里追加的设置不生效。
处理：新增 /etc/ssh/sshd_config.d/00-bizops-password.conf（字母序在 50- 之前），
  写入 PasswordAuthentication yes + PermitRootLogin yes 并重启 sshd；
  通过 gcloud compute ssh（项目 mevendor_ata 临时密钥）进入执行，
  修复后两台 `sshd -T` 均为 passwordauthentication yes / permitrootlogin yes。

七、安全说明（重要）

1. root 密码按用户指定值设置，明文不写入本仓库、工作台、日志或文档。
2. 初始化脚本 /root/hk-backend-startup.sh 含该明文密码，仅保留在香港入口机（权限 700），
   需要时可删除；实例 mevendor_ata 的 startup-script 也含该值，如需收敛可在实例内
   `gcloud compute instances remove-mevendor_ata --keys=startup-script` 清除。
3. 为执行修复，`gcloud compute ssh` 向项目 mevendor_ata 写入了运维公钥
   （key 名 `compute.511057654766442468`、`compute.2166080764923942857`）。
   如不需要，可在 GCP 控制台/命令删除对应 ssh-keys 条目。
4. 两台新机只加了 ssh/内网/beszel 端口规则，未开放数据库、Redis、Docker API 等公网端口。

八、待办（本次未做）

1. 后端容器/业务代码部署（cn 分支不携带后端发布体系，需后端流程或另行授权）。
2. Beszel 监控 agent（旧后端曾运行 henrygd/beszel-agent，需 TOKEN 后补装）。
3. 每日快照策略（现有 bizops-hk-nginx-daily-snapshot / bizops-hk-zentao-daily-snapshot，
   新后端可参照新增 bizops-hk-backend-01/02-daily-snapshot）。
4. nginx 上游接入：香港入口机的 external 后端目前是 192.0.2.18 / 192.0.2.19，
   若要切到自建后端，需在新机起服务后调整 nginx upstream 并验证；
   防火墙已放行入口机 192.0.2.1 → 8765 与 9090-9104。
5. 工作台与服务器索引已同步更新（见关联文件）。

九、边界与决策

本次为香港项目新增后端机器，超出「cn 只维护入口与云资源」的旧边界 （原决策 DEC-20260716-CN-NO-BACKEND-DEPLOY）。机器已创建并通过验证， 但后端代码/容器发布体系仍未纳入 cn 分支，docker/ci/check.py 的边界检查未放宽。 是否把后端发布纳入 cn 由用户后续确认。
