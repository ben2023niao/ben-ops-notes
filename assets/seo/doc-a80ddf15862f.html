Packages 分层与公共包边界

Packages 分层与公共包边界。本文属于业务系统运维 / 小蓝直播，packages 是公共能力目录，不是杂物间。AI Agent 新增公共代码前，必须先判断平台、来源和消费者，不能把 Go、PHP、前端、UI、生成物混放到一个 shared 目录。 JSON Schema / DTO schema。

packages 是公共能力目录，不是杂物间。AI Agent 新增公共代码前，必须先判断平台、来源和消费者，不能把 Go、PHP、前端、UI、生成物混放到一个 shared 目录。

1. 推荐结构

packages/
  contracts/              # 平台无关契约源头
    openapi/
    events.md
    errors.md

  generated/              # 从 contracts 生成，不手写业务逻辑
    ts/
    go/
    php/

  ts/                     # TypeScript 生态公共包
    shared/
    web/
    mobile/

  ui/                     # 设计 token 和 UI 组件
    tokens/
    web/
    mobile/

  go/                     # Go 多服务公共包
    kit/
    httpx/
    observability/

  php/                    # PHP / Laravel 公共包
    support/
    filament/

2. 依赖方向

apps/mobile      -> packages/ts/mobile
apps/mobile      -> packages/ui/mobile
apps/mobile      -> packages/generated/ts

apps/web     -> packages/ts/web
apps/web     -> packages/ui/web
apps/web     -> packages/ui/tokens
apps/web     -> packages/generated/ts

apps/admin -> packages/ts/web
apps/admin -> packages/ui/web
apps/admin -> packages/ui/tokens
apps/admin -> packages/generated/ts

services/go-app     -> packages/go/*
services/go-app     -> packages/generated/go

services/realtime -> packages/go/*
services/worker   -> packages/go/*

services/laravel-app -> packages/php/*
services/laravel-app -> packages/generated/php

禁止：

packages/ts/*     -> packages/go/*
packages/go/*     -> packages/ts/*
packages/php/*    -> packages/go/*
packages/ui/*     -> services/*
packages/contracts -> apps/* 或 services/* implementation

3. Contracts 与 Generated

packages/contracts 是源头：

  1. OpenAPI。
  2. 事件契约。
  3. 错误码。
  4. JSON Schema / DTO schema。

packages/generated 是生成物：

  1. generated/ts 给前端、Nuxt、React Native 使用。
  2. generated/go 给 Go 服务使用。
  3. generated/php 给 Laravel 使用。

生成物不得手写业务逻辑。修改 API 字段时，先改 contracts，再重新生成。

4. TypeScript 包

packages/ts/shared
packages/ts/web
packages/ts/mobile

规则：

  1. ts/shared 只放 TS 通用常量、纯函数、环境无关类型。
  2. ts/web 只放 Nuxt/Web/浏览器相关 helper。
  3. ts/mobile 只放 React Native/App 相关 helper。
  4. API 字段类型优先从 generated/ts 引入，不手写重复 DTO。

5. UI 包

packages/ui/tokens
packages/ui/web
packages/ui/mobile

规则：

  1. tokens 放 CSS-first token，供 Tailwind CSS v4 和其他端消费。
  2. web 放 Nuxt/Vue/Web UI。
  3. mobile 放 React Native UI。
  4. UI 包不调用业务 API。
  5. 页面级业务流程不放 UI 包。

6. Go 包

packages/go/kit
packages/go/httpx
packages/go/observability

规则：

  1. 只给多个 Go 服务复用。
  2. 服务私有代码留在 services/*/internal。
  3. 不放业务 use case、repository、handler。

7. PHP 包

packages/php/support
packages/php/filament

规则：

  1. 只给 PHP/Laravel 使用。
  2. Laravel app 私有逻辑留在 services/laravel-app/app。
  3. 不放具体业务 Resource、Controller、Model、Job。

8. Agent 判断规则

新增公共代码前必须回答：

  1. 这个代码是否被至少两个 app/service 复用？
  2. 它属于 contracts、generated、ts、ui、go、php 哪一类？
  3. 它是否引用了平台私有运行时？
  4. 它是否会让另一个平台被迫安装不需要的依赖？
  5. 如果只给单个服务使用，为什么不放在该服务内部？

没有明确答案时，默认放在 app/service 私有目录，不放 packages。
