v0.2 变更（2026-05-22）： - C 端登录简化为"账号+密码"，无验证码 - 主播完全无 web 端，无独立鉴权（仅 stream_key 推流校验） - 后台新增"房间管理员"角色（room_admin），权限范围限定到分配的房间

9.1 两类鉴权身份（v0.2 移除主播 web 鉴权）

身份 鉴权方式 Token 存储 有效期
C 端用户 账号+密码 → JWT 客户端 LocalStorage + HttpOnly Cookie（refresh） access 2h / refresh 30d
后台（含 super / ops / room_admin / finance / risk / moderator） 账号密码 + TOTP 2FA + IP 白名单 HttpOnly Secure Cookie access 1h / refresh 8h
主播（推流） OBS 推流时通过 stream_key HMAC 校验（SRS on_publish hook） 不在客户端持有 token stream_key 常驻；后台可轮换

9.2 JWT 设计

9.2.1 结构

{
  "iss": "kickoff",
  "sub": "1234567",
  "aud": "kickoff-web",
  "exp": 1719411600,
  "iat": 1719404400,
  "jti": "uuid",
  "kid": "k202607",
  "user_id": 1234,
  "level": 3,
  "device_fp": "abc...",
  "scope": ["user.read","wallet.write","predict.bet"]
}

scope 字段控制接口粒度，后台 token 用更细的 admin.user.freeze / admin.withdraw.approve 等。

9.2.2 签名算法

  • HS256（v1，简单）+ KMS 托管 secret
  • v2 升级 RS256（公私钥分离，便于多服务验签）
  • kid 字段支持轮换（旧 key 保留 7 天）

9.2.3 刷新机制

1. access token 过期 → 客户端调 /auth/refresh + refresh token
2. 校验 refresh token 哈希在 user_devices 表中且未撤销
3. 校验设备指纹一致
4. 颁发新 access + 新 refresh（轮换）
5. 旧 refresh 立即失效

9.2.4 主动撤销

场景 实现
用户登出 写 Redis 黑名单 auth:revoked:{jti} TTL = exp-now
设备顶号 旧 device 的 refresh hash 标记 revoked，旧 access 进黑名单
风控冻结 用户所有 device revoked，所有 access 进黑名单
密码重置 同上

JWT 验签后必查 Redis 黑名单。

9.3 主播鉴权

9.3.1 6 位授权码

  • 由后台运营生成，通过外部渠道（微信/邮件）发给主播
  • 服务端存 SHA256 哈希
  • 输入错误 3 次 → 锁定 5 min（IP/session 级，不锁账号）
  • 主播登录后颁发主播专用 JWT（独立 audience kickoff-streamer-portal）

9.3.2 单设备并发禁止（R-108）

详见 risk-control-rules.md §6.2.2。

9.3.3 推流密钥

  • 业务侧动态生成：HMAC-SHA256(secret, streamer_id || session_id || expire_at)
  • 时间窗 5 min
  • SRS 或云直播侧 hook 验签
  • 旧密钥到期自动失效；新密钥每次开播单独颁发

9.4 后台鉴权

9.4.1 三因素

  1. 账号 + 密码（Bcrypt cost=12）
  2. TOTP 2FA（Google Authenticator 兼容）
  3. IP 白名单（账号粒度配置，仅允许办公网 + VPN 段）

9.4.2 RBAC

角色 资源权限
super * × *
ops dashboard:read + streamer:* + user:read + order:read + moderation:*
finance order:* + recon:* + withdraw:approve + audit:read
risk risk:* + user:freeze + user:read + audit:read
moderator moderation:*

中间件 requirePermission("user.freeze") 装饰所有写操作路由。

9.4.3 大额操作双人复核

操作 触发条件 复核流程
手动调余额 任何金额 操作人 + 第二审批人，二人必不同
提现放行 单笔 > ¥50,000 同上
押注退单 单活动 > 1000 笔 同上
主播解封 — 同上
风控规则修改 HIGH severity 规则 同上

实现：操作单 → 待审批 → 第二人审批 → 执行；全程审计。

9.5 接口防护

9.5.1 多维限流

维度 配置示例
全局 单 API /predict/bet 全局 200 QPS（防 抗压能力测试）
单 IP 1 IP 同 API 60 req/min
单 UID 1 UID /predict/bet 5 req/s
单 UID 全局 1 UID 全 API 30 req/s
注册防刷 同设备 24h ≤ 5 次 / 同 IP ≤ 10 次
验证码 同手机 24h ≤ 10 次，60s 冷却
登录失败 同账号 5 次 → 锁 5min

实现：Redis ZSET 滑动窗口 / 令牌桶。

9.5.2 CSRF

  • C 端 Web：JWT 在 Header 中传，CSRF 风险低（无 Cookie）
  • 后台：Cookie + 双提交 token（同时校验 Header X-CSRF-Token）
  • 所有写操作 POST/PUT/DELETE

9.5.3 XSS

  • 弹幕 / 昵称 / 房间标题：HTML escape
  • 富文本字段：白名单 sanitizer
  • 客户端 React/Vue 默认 escape，避免 dangerouslySetInnerHTML

9.5.4 SQL 注入

  • 全部参数化查询（sqlc 生成的 Prepared Statement）
  • 严禁字符串拼接 SQL
  • 后台搜索字段额外过滤特殊字符

9.5.5 文件上传

  • 仅头像、运营素材
  • MIME 白名单（image/jpeg, image/png, image/webp）
  • 大小限制（头像 < 2MB，运营素材 < 10MB）
  • 服务端二次校验文件头（防 MIME 欺骗）
  • 存对象存储（不入业务服务器）

9.5.6 接口签名（v2）

外部 API（如开放给主播 PC 工具）：HMAC 签名 + nonce + timestamp 防重放。

9.6 数据安全

9.6.1 敏感字段

字段 存储 传输 显示
密码 Bcrypt 哈希 明文 over TLS 不返回
手机号 明文 + 索引 明文 over TLS 后台默认掩码 138****1234
邮箱 明文 + 索引 明文 over TLS 同上
身份证 AES-256（KMS 托管 key） TLS 后台超管可见
银行卡 同上 同上 同上
支付宝账号 哈希用于对账 + 明文加密用于转账 TLS 后台默认掩码

9.6.2 PII 脱敏

接口出参中间件统一处理：

func MaskPII(s string, type_ MaskType) string {
    switch type_ {
    case Phone:    return s[:3] + "****" + s[7:]
    case Email:    return s[:3] + "****@" + domain
    case Alipay:   return s[:3] + "****" + s[len(s)-4:]
    case IDCard:   return s[:6] + "********" + s[14:]
    }
}

所有面向后台的"查看完整信息"操作必须二次确认 + 审计。

9.6.3 TLS

  • TLS 1.2+ 强制
  • HSTS 启用，max-age 1 year
  • 证书 Let's Encrypt 自动续期
  • 内网服务间通信 v2 升级 mTLS

9.6.4 数据库连接

  • TLS 强制
  • 业务账号 IP 白名单（仅业务 Pod 子网）
  • 权限分离：业务账号无 DDL 权限；DBA 账号独立
  • 密码 90 天轮换

9.7 三方接口安全

9.7.1 支付回调

  • 验签必须（微信 HMAC-SHA256 / 支付宝 RSA2）
  • 回调 IP 白名单（微信 + 支付宝官方 IP）
  • 回调幂等（third_party_no UNIQUE）
  • 原始 payload 落库 365 天

9.7.2 短信通道

  • 通道密钥 K8s Secret
  • 下发限流（防恶意刷短信成本授权安全测试）
  • 验证码使用一次后立即失效

9.7.3 KYC

  • 阿里云实人认证 API
  • 用户照片不入业务库，仅入证书厂商
  • 我方仅存认证状态 + 三方流水号

9.8 客户端安全

9.8.1 Web

  • CSP（Content-Security-Policy）严格白名单
  • X-Frame-Options DENY（防点击链路风险验证）
  • X-Content-Type-Options nosniff
  • Referrer-Policy strict-origin-when-cross-origin

9.8.2 H5

  • 同 Web
  • 微信内置浏览器额外注意 token 泄露（不输出到 console）

9.8.3 OBS 推流端

  • 推流 URL 显示在主播端时部分掩码（防截图泄露）
  • 推流密钥时效短（5 min）+ 一次性

9.9 安全审计

9.9.1 内部审计

  • 季度密码强度检查
  • 月度未使用账号清理
  • 月度权限审查（最小权限原则）
  • 半年外部渗透测试

9.9.2 合规审计

  • 用户数据保留期：注销账号后 30 天硬删除（除合规要求保留）
  • 资金审计日志：永久保留
  • 风控告警：365 天保留
  • 数据出境合规：v1 全部数据在境内

9.9.3 日志审计

  • 后台访问日志（不仅写操作，读操作也记录）
  • 资金类全链路 Jaeger 100% 采样
  • 异常访问模式监控（同账号短期高频敏感操作）

9.10 安全应急

9.10.1 后台账号被攻破

  1. 立即撤销该账号所有 token（写 Redis 黑名单）
  2. 强制改密 + 2FA 重置
  3. 审计该账号最近 30 天所有操作
  4. 受影响业务回滚 / 补偿
  5. 全员通知 + post-mortem

9.10.2 密钥泄露

  1. 立即轮换泄露密钥
  2. 审计该密钥可访问数据的最近访问日志
  3. 评估影响范围
  4. 通知用户（如涉及）
  5. 安全审计强化

9.10.3 数据泄露

  1. 评估泄露规模
  2. 法务介入（合规报告）
  3. 受影响用户通知
  4. 加固防护
  5. 内外部复盘
