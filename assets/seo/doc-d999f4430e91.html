1. 背景与目标

  • UAT 环境服务器已就位，需要先搭好运维基础能力，再配合开发做 UAT 部署。
  • 本期目标：部署 JumpServer 堡垒机，把 UAT 服务器全部纳管，实现统一入口、账号集中托管、操作可审计。
  • 下一期目标：服务器与容器监控预警（Beszel）接入 Telegram / 邮件通知。
  • 原则：全部运维系统统一容器化部署（Docker Compose），与现有环境风格一致。

4. 架构要点（来源：视讯项目UAT部署.xmind）

  • 应用服务：Docker Swarm（Docker Stack）部署，模拟生产高可用。
  • 中间件服务：独立 Docker Compose 部署，降低资源占用。
  • 运维支撑：GitLab、Nexus、Harbor、Jenkins、ELK、SRS 与 dev / test 环境共享。
  • 中间件节点：Nginx（前端静态文件 + 反向代理）、MySQL、Redis、RabbitMQ、RocketMQ、Nacos、MinIO、xxl-job。
  • 后端集群：1 Manager + 2 Worker，按项目划分 game / middle-station / pay 三个 Stack，服务副本数 2。
  • 发布方式：前端页面发布到中间件节点；后端 docker stack deploy --with-registry-auth --force-redeploy。

5. 堡垒机部署要求

5.1 机器与资源

  • 部署在管理机 43.249.251.15，Ubuntu 24.04。
  • 4C8G 是 JumpServer 官方最低配置（推荐 4C16G），磁盘要求 ≥100G。
  • 该机器不再承载其他业务；资源无余量，后续纳管机器增多需要扩容。

5.2 部署方式与端口

项 规划
部署方式 Docker Compose（JumpServer 官方 all-in-one）
Web 80 / 443（HTTPS，域名或 IP + 证书）
SSH 资产接入 2222（koko）
RDP（备用） 3389（guacamole，如有 Windows 资产）
数据库 3306，仅本机访问
访问控制 待确认：仅内网访问，还是公网 + IP 白名单

5.3 数据、备份与审计

  • 数据目录统一放独立路径（如 /data/jumpserver），便于整体备份。
  • 备份范围：数据库 + 配置 + 会话录像；保留周期待确认。
  • 机房不上云快照，备份方式（机房侧备份 / 脚本定时导出）待确认。
  • 审计保留：会话录像、登录日志、命令记录时长待确认。

待确认：开发组是否允许文件上传 / 下载、是否启用危险命令过滤、是否限制登录来源 IP。

资产账号与提权

  • 现状：4 台机器共用同一个 blkuat 密码，存在横向风险。
  • 建议：纳管后改为每台独立密码或密钥，统一由堡垒机托管，关闭服务器 root 密码直连。
  • "切换到 root 不需要输密码"：建议通过堡垒机 sudo 提权实现（操作可录制、可审计），不在服务器上放开免密 root 登录。

8. 安全基线

  1. PO 单中"开放端口 ANY"需收敛为最小端口清单：22（仅堡垒机 / 白名单来源）、80/443、业务必要端口。
  2. 关闭 root 密码直连，密码登录改密钥，部署 fail2ban，防火墙按白名单放行。
  3. 4 台机器共用同一密码的问题纳入本次整改。
  4. 堡垒机公网访问需限定来源 IP；如可只走内网则优先内网。

9. 监控预警（阶段二）

项 方案
主机 + 容器监控 Beszel（agent 装在管理机与各 UAT 机器）
容器日志 Beszel 实时查看；历史日志待确认方案
程序运行状况 容器健康检查、重启次数、接口存活探测
告警通道 Telegram 机器人 + 邮件

待确认：监控数据保留时长、告警阈值标准、告警接收人。堡垒机只负责运维入口与审计，不承担监控告警。

11. 部署步骤（我方计划）

  1. 获取管理机登录信息，完成环境检查（系统版本、Docker、资源、时区、防火墙策略）。
  2. Docker Compose 部署 JumpServer all-in-one，配置 HTTPS 与访问白名单。
  3. 初始化组织、分组、账号（admin / 运维组 3 人 / 开发组 1 人），强制开启 GA。
  4. 建立资产树与服务器组 UAT，按 UAT-xxxxxx 命名录入 5 台机器。
  5. 配置系统账号、sudo 提权、命令过滤、会话录制与文件传输策略。
  6. 连通性验证：4 台机器 SSH 纳管测试；确认 SRS 私网可达性。
  7. 交付账号与文档（部署说明、账号清单、运维手册）。
  8. 阶段二：部署 Beszel，接入 Telegram 机器人与邮件告警。

12. 风险提示

风险 说明 建议
资源无余量 管理机 4C8G 为最低配置，同时要跑堡垒机与监控 不再部署其他服务；后续纳管增多时扩容内存
单点 堡垒机单机部署，故障时运维入口中断 数据定期备份；如需高可用再评估双节点
公网暴露 43.249.251.15 为公网地址 加 IP 白名单，最好改密钥登录 + 关闭密码登录
共用一个密码 4 台机器账号密码相同 纳管后改为独立密钥，由堡垒机托管
网络隔离 dev 与 UAT 不在同一机房，SRS 走 IEPL 私网 纳管前确认路由，必要时走专线 / VPN
