四、自动化与工具现状（已完成清单）

4.1 发布自动化

  • 前后端统一 CICD：GitLab Webhook → CICD 平台（cicd.youdianse-test.xyz / 线上对应）自动构建 Docker 镜像并发布 web/nginx/cron；
  • 前端多环境发版入口（测试 H5/PC、前置 H5/PC、线上 H5/PC、新 H5/PC）全部机器人按钮化，选择 git id 即可发布，发布后自动回传版本号/页面/接口；
  • 发布会话丢失、分叉分支、配置覆盖等问题均已修复并加守护（systemd 守护 CICD、auto-update 定时更新、发布日志自动发群）。

4.2 域名与证书

  • 线上新服务器 nginx 按类型合并 conf（UA 分流/纯 H5/纯 PC/跳转），新增域名只需改 server_name + 证书；
  • 域名维护脚本 /usr/local/bin/youdianse-domain-maint.py：增加/删除/续签/检查域名，机器人按钮化（快速检查/SSL 续签分类/增加域名/删除域名/搜索）；
  • Let's Encrypt 证书自动续期（cron 03:10），SSL 状态按“没证书/快到期/正常”分类，失败自动回传完整日志；
  • 所有域名操作前自动备份 nginx 配置 + 证书并发群（保留 100 份轮转）。

4.3 监控与告警

  • Beszel 监控面板：http://52.79.252.255:8090（服务器 CPU/内存/磁盘/网络）；
  • 健康告警：磁盘使用率、CPU、容器状态，测试/线上主机均接入；
  • 值班面板与事件提醒（上班/换班/下班、出勤统计）机器人自动化。

4.4 日志与数据

  • PHP 全量日志持久化 + 小时轮转 + 容量告警（5G/200G 阈值）；
  • api_request / api_response / 大数据上报日志结构化；logbus2 大数据链路去重与防丢失；
  • 小时数据报告自动生成（Spug 调度），缺失有兜底与告警。

4.5 日常运维自动化

  • 磁盘清理定时任务（构建中自动跳过、只删未用镜像/旧日志，保留近期构建缓存）；
  • 服务器巡检脚本化（扩容后全量巡检、域名巡检、证书巡检）；
  • 机器人文档/帮助/值班表/周报等入口化。

六、容灾与备份现状

✅ 已有： - AWS 多节点分布（网关/后端/宝塔/老 H5/新 H5+PC 分机部署），后端与网关同 VPC 内网加速； - 日本前置服务器作为备用回源候选（40C/32G/877G）； - AWS 实例快照（已组织多人巡检各服务器快照完整性）； - 配置/证书/数据库关键变更前均备份并可回滚； - 后端扩容后容量充足（16C/30G，load 由 5-6 降至 1.5）。

七、近期问题复盘（为什么要 24h 值班 + 高级运维）

7.1 SDK 域名批量链路风险验证（2026-08-20，E4 安全事件）

  • 10 个 SDK 域名（安卓 5 + iOS 5）在注册商 Gname 被批量改 DNS（NS→Cloudflare 指向第三方短剧站），导致多款游戏登录/注册失败、支付回调受影响；
  • 处置：逐款解包 APK 核验 baseUrl、恢复解析到平台 AWS CloudFront/网关、加固网关 nginx（worker_connections 4096 + keepalive）、更新 pay.callback 域名并重建容器；
  • 启示：需要 7×24 盯防 + DNS 变更审计 + 注册商加固 + 备用通道。

7.2 CPU 持续高位（2026-08-20，容量瓶颈）

  • 晚间 QPS 约 280，4 核后端 load 5-6、idle 1.5%，连续 CPU 99% 告警；
  • 处置：扩容 4C/7.5G → 16C/30G，PHP-FPM 调优（max_children 64、opcache 256M、memory_limit 256M），全量巡检验证；
  • 启示：容量规划要按 QPS/接口成本测算，扩容后仍需调优，需要懂 PHP-FPM/OpCache 的运维。

7.3 Redis 连接端口耗尽偶发 500（2026-08-21）

  • 高 QPS 下容器 ephemeral 端口被打满（2.8 万 TIME_WAIT），约 50% 请求 500；
  • 处置：compose 加 sysctls（端口范围翻倍 + tcp_tw_reuse）+ 应用侧连接复用建议；
  • 启示：需要懂 TCP/内核参数/连接池的深度运维，且要能独立复盘定位。

7.4 其他近期问题

  • 正式包打入测试 SDK 域名导致登录失败（发布/打包链路校验）；
  • 大数据上报缺数据/重复（logbus2 链路改造：去重+防丢失）；
  • 发布会话丢失/分叉（CICD 加固）；
  • 测试环境配置缓存被 3.6MB 脏数据撑爆（Redis 大 key 治理）；
  • 自动发布构建失败（GitHub 429 → 镜像源切换）；
  • 磁盘/日志告警治理。

8.1 平台技术栈

  • 云与网络：AWS（EC2/S3/CloudFront/VPC/快照）、腾讯云（COS/CDN/EdgeOne）、DNSPod/Gname 域名与 DNS、Cloudflare；
  • 容器与发布：Docker / Docker Compose、GitLab CI（Webhook）、CICD 自研平台（Python/Tornado/PyWebIO）；
  • 服务端：Nginx（反代/分流/SSL/realip）、PHP 7.4 / Phalcon / PHP-FPM（调优）、Node.js（Nuxt SSR/H5/PC）、Python（自动化脚本/机器人）；
  • 数据：MongoDB、Redis（缓存/大key/连接治理）、消息队列与大数据上报（logbus）；
  • 监控与运维：Beszel / 自建告警、日志持久化与轮转、定时任务（Spug）、值班机器人（Telegram Bot）。

8.2 岗位核心能力要求（高级运维 / 运维开发）

  1. 自动化与开发能力（优先）：能用 Python/Shell 写发布、巡检、域名、证书、监控、机器人等自动化；熟悉 GitLab CI / Webhook / Docker 构建链路。
  2. Linux 与网络：系统/内核参数调优（TIME_WAIT/端口范围/文件句柄）、TCP/IP、DNS/HTTP/TLS 排查（链路风险验证、回源、SNI、证书）。
  3. Web 服务：Nginx 深入（反代/分流/缓存/realip/worker 调优）、PHP-FPM/OpCache 调优、常见 500/超时/连接池问题定位。
  4. 中间件：MongoDB 慢查询/索引/备份、Redis 缓存与连接治理、消息队列。
  5. 云与 CDN：AWS 常用服务、CDN 回源/缓存策略、域名注册商与 DNS 安全（防链路风险验证）。
  6. 监控与值班：监控接入/告警规则、日志分析、7×24 值班意识、能独立处理凌晨故障。
  7. 软素质：抗压、快速响应、文档沉淀、跨部门协作（前端/后端/发行/HR）、安全意识（不泄露凭据）。

十一、运维中台定位与边界（对外口径）

  • 名义：建立运维中台，统一管理发行侧与游戏侧运维；两边的服务器、发布、域名、监控、值班都可纳入。
  • 实际策略：我们侧制度与监控已完善，外部只需“见证”与提优化建议；可优化内容不多，最终反馈老板“平台侧已基本完善”。
  • 边界：游戏侧短板（SDK 域名/包体/渠道）通过中台制度暴露与推动整改；不承接对方历史包袱，只做标准化接入（监控/发布/域名/值班规范）。
  • 对外展示重点：自动化程度（发布/域名/证书/监控/值班机器人）、容灾（多节点/快照/备用回源/扩容）、文档与复盘能力、24h 值班制度。

十二、可优化点清单（真实，供会议讨论）

  1. 高可用：线上后端/网关单台 → 增加备机或容器编排（docker swarm/k8s 可选，按成本评估）；
  2. DNS 安全：注册商加固（开启域名锁/双因素）、DNS 变更审计告警、备用权威 DNS；
  3. 监控补强：接入 Prometheus/Grafana（可选）、接口/支付成功率拨测、证书到期提前告警；
  4. 值班工具：值班看板 + 告警转群 + 一键 SOP 按钮；
  5. 容量规划：按 QPS 常态化压测，老 H5 4C/8G 升级、ben-bot 机升级（可选）；
  6. 数据库：Mongo 慢查询/索引巡检自动化、Redis 大 Key/连接池治理常态化；
  7. 发布：前后端发布门禁（分支/版本校验、回滚按钮化）、打包链路自动校验测试域名；
  8. 文档与演练：故障手册、容灾演练（每月一次），让值班人能独立处置。

十三、明天会议口径建议

  1. 先讲“我们已经做了什么”（自动化/监控/容灾/复盘），展示完整度；
  2. 再讲“当前真实短板与优化点”（上节清单），表明可优化空间有限且明确；
  3. 24h 值班：明确现行覆盖与缺口，给出排班方案，说明“能排则排、排不过来再招”；
  4. 招聘：按第九节 JD 提技能要求，薪资按市场区间（建议由 HR 定），重点是“要能独立处理问题 + 会写自动化”；
  5. 中台：对外统一口径（见第十一节），不主动接对方历史包袱。
