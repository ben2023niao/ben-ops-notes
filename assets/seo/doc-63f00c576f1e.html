临时群🍊🍎紧急事件 -5247199745：接收 某业务公司 人工运维与发布台操作通知。

四、通知路由修改

4.1 命令行运维通知

修改：

scripts/bizops_notify.py

选择顺序更新为：

--chat-id 显式覆盖
→ 某业务公司_OPERATIONS_CHAT_ID
→ BEN_BOT_MONITOR_CHAT_ID（兼容回退）
→ 某业务公司_MONITOR_CHAT_ID（兼容回退）

宝塔运行时配置新增：

/opt/benbot-runtime.env
某业务公司_OPERATIONS_CHAT_ID=-5247199745

备份：

/opt/benbot-runtime.env.bak-20261107-013256

4.2 运维发布台通知

bizops-ops-console 的通知目标 Secret 从原监控群切换为新群：

/opt/bizops-ops-console/secrets/telegram_chat_ids
内容：-5247199745
owner：10001:10001
mode：0400

备份：

/opt/bizops-ops-console/backups/telegram_chat_ids.before-20261107-013303

Secret 在每次发送时动态读取，因此无需重启控制台容器。

五、验证

5.1 默认群校验

python3 scripts/bizops_notify.py --check
群配置正常：临时群🍊🍎紧急事件（-5247199745）

5.2 新群实际发送

bizops_notify.py 运维通知路由测试：message_id 8001
运维发布台 /api/notify 路由测试：message_ids [8002]

两条消息均已在“临时群🍊🍎紧急事件”确认。

5.3 监控群隔离

BEN_BOT_MONITOR_CHAT_ID 未修改。
服务器监控、容器健康、重启告警仍发送原监控报警群。

六、影响范围

1. 仅切换 某业务公司 人工运维和发布台通知目标；
2. 未修改业务服务器、游戏容器、Nginx、DNS、CDN 或业务配置；
3. 未重启 bizops-ops-console；
4. 未重启任何游戏业务容器；
5. 未修改监控报警群配置。

七、提交前安全检查附带修复

敏感信息扫描发现 scripts/sync_game_results_data.py 仍把服务器密码作为 代码默认值。该问题不是本次通知路由修改引入，但不能在提交时继续保留：

1. 删除脚本内明文密码默认值；
2. 改为必须从 GAME_RESULTS_SYNC_PASSWORD 或
   GAME_RESULTS_SYNC_PASSWORD_FILE 读取；
3. 所有 sshpass 调用改为 sshpass -e，密码仅通过进程环境传递；
4. 未修改宝塔现有 shell 定时任务，未触发结果集同步。

八、回滚

命令行运维通知：

cp -a /opt/benbot-runtime.env.bak-20261107-013256 /opt/benbot-runtime.env

运维发布台通知：

cp -a /opt/bizops-ops-console/backups/telegram_chat_ids.before-20261107-013303 \
  /opt/bizops-ops-console/secrets/telegram_chat_ids
chown 10001:10001 /opt/bizops-ops-console/secrets/telegram_chat_ids
chmod 400 /opt/bizops-ops-console/secrets/telegram_chat_ids

代码回滚：

回退 scripts/bizops_notify.py 中对 某业务公司_OPERATIONS_CHAT_ID 的优先读取。
同时恢复 sync_game_results_data.py 旧版本。
