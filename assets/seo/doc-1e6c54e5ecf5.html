6.1 规则总表（v1，原型评审版 6 条）

规则 ID 名称 类型 严重度 触发条件 自动动作
R-101 新设备登录 账号安全 低 新设备指纹 + IP 异常 二次验证（短信 / 邮箱）
R-108 主播多设备并发 账号安全 高 同主播账号 2+ 设备同时推流 自动暂停推流 + 人工核查
R-204 异常充提链路 反洗钱 高 充值 24h 内提现 ≥ 80% 余额 人工审核
R-301 单笔大额押注 资金风控 高 单笔押注 ≥ ¥10,000 等值 财务复核
R-502 弹幕违禁词高频 内容安全 中 房间 10 min 内命中 ≥ 15 次 进入直播间 / 人工巡查
R-604 通道成功率骤降 系统 中 15 min 内成功率下降 ≥ 5% 查看 / 联系通道

6.1.1 字段说明

  • 规则 ID：全局唯一，不可重用
  • 类型：账号安全 / 反洗钱 / 资金风控 / 内容安全 / 系统
  • 严重度：高 / 中 / 低
  • 触发条件：用业务语言描述，工程实现时翻译为 SQL / 表达式
  • 自动动作：系统自动执行（不需要人工）

6.2 各规则技术实现

6.2.1 R-101 新设备登录

实现位置：internal/service/auth/login.go

// 登录成功后：
deviceFP := req.DeviceFingerprint
known, _ := repo.UserDevice.IsKnown(ctx, userID, deviceFP)
if !known {
    ipCountry := geoip.Lookup(req.IP)
    historicalCountry := repo.UserDevice.LastIPCountry(ctx, userID)
    if ipCountry != historicalCountry {
        // 触发 R-101
        riskService.Trigger(ctx, "R-101", RiskTriggerCtx{
            UserID: userID, DeviceFP: deviceFP, IP: req.IP,
        })
        // 阻塞登录，要求二次验证
        return ErrNeedSecondaryVerify
    }
    repo.UserDevice.Register(ctx, userID, deviceFP, req.IP, req.UA)
}

6.2.2 R-108 主播多设备并发（v0.2：基于 stream_key）

实现位置：internal/service/liveroom/publish.go + SRS on_publish hook

v0.2 简化：原 PRD 设计依赖"主播登录主播端 + 设备指纹"，v0.2 改为主播无 web 端，纯基于 stream_key 检测。

// SRS on_publish hook：
// 1. 解析推流 URL 中的 stream_key → 反查 live_rooms.streamer_id + room_id
// 2. 校验 stream_key 是否有效 + room 是否被封禁
// 3. 查 Redis: SETNX live:active:{room_id} = client_id EX 60s
// 4. 失败 → 已有 active 推流
//    - 触发 R-108：
//      a. 拒绝新推流（返回 403）
//      b. 写 risk_alerts
//      c. 推送通知给该房间的房间管理员（Telegram bot webhook）
//      d. 房间管理员判断真伪，决定是否轮换 stream_key（前者作恶）或人工协调主播切回原端
// 5. 心跳：on_publish 后每 20s 续期 live:active 这个 key
// 6. on_unpublish: 立即清除 live:active key

6.2.3 R-204 异常充提链路

实现位置：internal/service/wallet/withdraw.go 风控引擎

// 用户提交提现申请：
recentRecharge := repo.RechargeOrder.Sum24h(ctx, userID, "PAID")
currentBalance := wallet.RMB
amount := req.Amount

// 触发条件：充值 24h 内 提现金额 ≥ 80% × 该 24h 累计充值
if recentRecharge > 0 && amount >= recentRecharge*0.8 {
    riskService.Trigger(ctx, "R-204", RiskTriggerCtx{
        UserID: userID, Recharge24h: recentRecharge, WithdrawAmount: amount,
    })
    // 自动动作：标记为高风险，进入人工审核队列
    return WithdrawResult{Status: "待审核（高风险）", RiskScore: 90}
}

// 押注成功后：
amountRMBEquiv := bet.Amount / 10.0 // 钻石转 RMB 等值
if amountRMBEquiv >= 10000 {

        AmountDiamond: bet.Amount, AmountRMBEquiv: amountRMBEquiv,
    })

6.2.5 R-502 弹幕违禁词高频

实现位置：go-ws 弹幕入站处理 + worker-risk 聚合

// go-ws 收到弹幕：
hits := forbiddenWord.Match(content)
if len(hits) > 0 {
    // 不广播给观众
    repo.RoomAuditLog.Record(ctx, roomID, userID, "FORBIDDEN_HIT", content, hits)
    redis.Incr(ctx, fmt.Sprintf("room:hit:%d:%s", roomID, time.Now().Format("200601021504")))
}

// worker-risk 每分钟跑：
for each room:
    count := redis.GetSum(ctx, fmt.Sprintf("room:hit:%d:*", roomID), last10Min)
    if count >= 15 {
        riskService.Trigger(ctx, "R-502", RiskTriggerCtx{RoomID: roomID, Count: count})
        // 自动动作：仅生成告警，等待人工巡查（PRD 明确"人工巡查"）
    }

6.2.6 R-604 通道成功率骤降

实现位置：worker-cron 每分钟跑

// 每分钟评估每个通道：
for each channel in [wechat, alipay]:
    last15min := repo.RechargeOrder.Stats15Min(ctx, channel)
    successRate := float64(last15min.Paid) / float64(last15min.Total)

    // 与基线对比
    baseline := redis.Get(ctx, fmt.Sprintf("channel:baseline:%s", channel))
    drop := baseline - successRate

    if drop >= 0.05 {
        riskService.Trigger(ctx, "R-604", RiskTriggerCtx{
            Channel: channel, SuccessRate: successRate, Baseline: baseline,
        })
        // 自动动作（PRD）：触发系统告警 → 推 Telegram + 邮件 → 运营查看 / 联系通道
        // PRD 未要求自动切通道，技术架构识别此为可补入点，见 §3.1
    }

T-304 高赔率选项异常集中 单一高赔率选项被 ≥ N 人异常集中下注 财务复核 + 暂时锁盘 高 防内幕交易，赛事场景核心风险
T-102 短期高频注册 同设备 24h 内 ≥ 5 次 / 同 IP ≥ 10 次 阻断 中 防垃圾账号

规则 评审决策点

6.4 风控引擎实现

6.4.1 当前落地范围（v0.3.4）

本期已落地风控 MVP，覆盖后台 ADM-601~ADM-605 与竞猜 R-301：

  • risk_rules / risk_alerts 两张表由 000018_create_risk_tables 创建，包含 down migration。
  • 默认种子规则 R-301：单笔押注 min_bet_diamond >= 100000（¥10,000 等值）触发 HIGH 告警。
  • C 端下注成功后，services/go-app/internal/service/predict/service.go 在资金事务完成后生成 risk_alerts，同一 rule_code + source_type + source_id 去重。
  • 后台 /api/v1/admin/risk/* 已支持 KPI、告警列表、告警详情、告警处置、规则列表、规则启用/禁用。
  • 告警处置写 admin_audit_logs，冻结用户动作会把 users.status 从正常改为冻结。

6.4.2 目标模块结构

internal/service/risk/
├── engine.go         # 规则引擎入口
├── rules/
│   ├── r101.go       # 每条规则独立 evaluator
│   ├── r108.go
│   ├── r204.go
│   ├── r301.go
│   ├── r502.go
│   └── r604.go
├── action.go         # 动作执行器（人工审核队列、自动阻断、告警）
└── alert.go          # 告警生成（写 risk_alerts 表 + 推 Telegram + 邮件）

6.4.3 规则评估方式

评估时机 实现
同步评估 业务请求路径内调用 riskService.Evaluate(ctx, ev) 立即决策（R-101 / R-108 / R-204）
异步评估 worker-risk 消费 stream:risk.signal，跑批 / 滚动窗口（R-502 / R-604）
事件后评估 资金事务完成后异步通知风控（R-301 押注后）

6.4.4 规则配置化

规则参数存 risk_rules 表。当前 MySQL 实现使用 id BIGINT UNSIGNED 雪花主键 + rule_code 唯一键，状态和严重度使用 TINYINT UNSIGNED，避免字符串 enum：

CREATE TABLE risk_rules (
    id           BIGINT UNSIGNED PRIMARY KEY,
    rule_code    VARCHAR(32) UNIQUE,
    name         VARCHAR(64) NOT NULL,
    category     VARCHAR(32),         -- funds/account/content/system
    severity     TINYINT UNSIGNED,    -- 1=LOW 2=MEDIUM 3=HIGH 4=CRITICAL
    enabled      TINYINT UNSIGNED,
    threshold_json JSON,              -- 规则参数，如 {"min_bet_diamond":100000}
    action       VARCHAR(64),         -- 'auto_pause'/'block'/'manual_review'/'alert'
    updated_by   BIGINT,
    created_at   DATETIME(3),
    updated_at   DATETIME(3),
    deleted_at   DATETIME(3)
);

后台 ADM-606（PRD）"新增/编辑规则" 直接改这张表，5min 缓存刷新。

6.5 告警与处置

6.5.1 告警生成

CREATE TABLE risk_alerts (
    id           BIGINT UNSIGNED PRIMARY KEY,
    rule_id      BIGINT UNSIGNED,
    rule_code    VARCHAR(32),
    severity     TINYINT UNSIGNED,    -- 1=LOW 2=MEDIUM 3=HIGH 4=CRITICAL
    target_type  VARCHAR(32),         -- user/streamer/room/order/channel
    target_id    VARCHAR(64),
    source_type  VARCHAR(32),         -- predict_bet/withdraw_order/...
    source_id    VARCHAR(64),
    payload_json JSON,                -- 触发时的上下文快照
    status       TINYINT UNSIGNED,    -- 1=OPEN 2=REVIEWING 3=CLOSED 4=IGNORED
    handled_by   BIGINT,              -- admin_user id
    handled_at   DATETIME(3),
    created_at   DATETIME(3),
    INDEX(status, severity, created_at)
);

6.5.2 处置 SLA（PRD kickoff-admin.md §3.7）

严重度 响应时间 处置时间
高 ≤ 5 min ≤ 1 hour
中 ≤ 30 min ≤ 24 hour
低 ≤ 2 hour ≤ 7 day

6.5.3 处置动作

动作 实现
查看 跳转告警详情 + 关联数据
冻结账户 调 admin API POST /admin/users/{id}/freeze
封禁主播 调 admin API POST /admin/streamers/{id}/ban
强制下播 调 admin API POST /admin/streamers/{id}/force-end
财务放行 提现订单 approve
财务驳回 提现订单 reject + 填理由
忽略 标记 已忽略，写审计

所有处置写入 admin_audit_log。

6.6 风控审计

  • 每次规则触发 → INSERT risk_alerts
  • 每次处置 → INSERT admin_audit_log
  • risk_alerts 保留 365 天，admin_audit_log 永久保留

6.7 监控指标

指标 阈值
高优告警未处理数 ≥ 3 → 通知 oncall
高优告警平均响应时长 > 30 min
中优告警平均处置时长 > 24h
风控规则触发率 同比突增 > 200%
风控引擎错误率 > 1%
