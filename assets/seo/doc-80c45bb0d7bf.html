快速导入

快速导入。本文属于基础设施与自动化 / BKL UAT，Git 仓库（建议先 git status 确认工作区） 可选：VS Code、Telegram Bot、任一 AI 服务 API Workbench 本身不依赖第三方 Python 包。 假设套件解压在 workbench-kit-v1.0.0/ ：

1. 前置条件

  • Python 3.9+
  • Git 仓库（建议先 git status 确认工作区）
  • 一个可写的项目目录
  • 可选：VS Code、Telegram Bot、任一 AI 服务 API

Workbench 本身不依赖第三方 Python 包。

2. 安装

假设套件解压在 workbench-kit-v1.0.0/：

cd workbench-kit-v1.0.0
python3 scripts/install.py /path/to/your-project \
  --name "你的项目名" \
  --slug your-project \
  --owner "负责人" \
  --with-vscode

安装到当前目录：

python3 scripts/install.py . --name "我的项目" --with-vscode

只预览、不写文件：

python3 scripts/install.py . --name "我的项目" --dry-run

3. 参数

参数 说明
target 目标项目目录，默认当前目录
--name 项目名称，写入模板
--slug 项目标识，默认由名称生成
--owner 负责人
--date 初始化日期，默认今天
--with-vscode 写入 .vscode/extensions.json、settings.json、tasks.json
--force 覆盖已有文件（谨慎）
--dry-run 只打印将写入的文件
--create 目标目录不存在时创建

4. 安装后生成什么

your-project/
├── AGENTS.md
└── workbench/
    ├── README.md
    ├── START_HERE.md
    ├── ACTIVE_TASKS.md
    ├── PROJECT_INDEX.md
    ├── MACHINE_ACCESS_MATRIX.md
    ├── PROJECT_RUNTIME_CHAINS.md
    ├── NOTIFICATION_TARGETS.md
    ├── AUDIT_CONFLICTS.md
    ├── projects/your-project/
    │   ├── CURRENT_STATE.md
    │   └── CURRENT_TASK.md
    ├── templates/
    ├── handoff/to-cc/
    ├── handoff/from-cc/
    ├── scripts/
    │   ├── check.py
    │   ├── context_pack.py
    │   └── notify.py
    ├── docs/
    ├── config/ai.env.example
    ├── notify.env.example
    ├── Makefile
    └── .gitignore

如果项目已有 AGENTS.md，安装器不会覆盖，而是把模板写到 workbench/AGENTS.template.md。

5. 第一次 30 分钟

5.1 填机器矩阵

编辑 workbench/MACHINE_ACCESS_MATRIX.md：

  • 主机名
  • 内网 / 公网地址
  • 角色
  • 登录账号名
  • 密码保存位置（不写密码本身）

5.2 填运行链路

编辑 workbench/PROJECT_RUNTIME_CHAINS.md：

  • 域名 → nginx → 后端端口
  • 数据库、缓存、消息队列端口
  • 证书方式
  • 已知网络限制

5.3 填通知目标

编辑 workbench/NOTIFICATION_TARGETS.md：

  • 群名称
  • chat_id
  • 使用场景

不要写 bot token。

5.4 填当前状态

编辑 workbench/projects/<slug>/CURRENT_STATE.md：

  • 已验证事实
  • 用户确认事实
  • 未知项
  • 入口

5.5 配置通知

cp workbench/notify.env.example workbench/notify.env
chmod 600 workbench/notify.env
# 编辑文件，填 TELEGRAM_API_TOKEN 和 TELEGRAM_CHAT_ID
python3 workbench/scripts/notify.py --verify-chat

5.6 跑检查

python3 workbench/scripts/check.py .

看到 Workbench 检查通过 即可。

5.7 生成第一份上下文

python3 workbench/scripts/context_pack.py --project . --out /tmp/context.md

把 /tmp/context.md 粘贴给 AI，或让 AI 自己读文件。

6. 日常使用

开始一个任务

  1. 在 workbench/ACTIVE_TASKS.md 登记任务 ID
  2. 在 workbench/handoff/to-cc/ 写 <TASK-ID>-context.md
  3. 写 <TASK-ID>-plan.md
  4. 执行前只读核验
  5. 每步通知
  6. 完成后写 result 和 doc
  7. 提交 Git

生成上下文

python3 workbench/scripts/context_pack.py --project . --task TASK-001

检查

python3 workbench/scripts/check.py .

通知

python3 workbench/scripts/notify.py \
  --title "【项目名】步骤 1 前置检查" \
  --text "本地/远端一致，工作区干净"

Makefile 快捷方式

make -f workbench/Makefile check
make -f workbench/Makefile context
make -f workbench/Makefile notify-test

7. 多项目使用

每个项目独立安装一份 Workbench，互不影响：

python3 scripts/install.py ~/code/project-a --name "项目 A" --slug project-a
python3 scripts/install.py ~/code/project-b --name "项目 B" --slug project-b

如果使用 VS Code 多根工作区，可以在 .code-workspace 中同时打开多个项目，每个项目保留自己的 Workbench。

8. 升级模板

  1. 下载新版本套件
  2. 先 git status，确保工作区干净
  3. 用 --dry-run 预览差异
  4. 只更新 workbench/scripts/ 和 workbench/docs/
  5. 业务事实文件（机器矩阵、当前状态、任务）不要被覆盖

建议：

python3 new-kit/scripts/install.py . --name "项目名" --dry-run

确认后手工复制脚本，避免 --force 覆盖项目事实。

9. 卸载

Workbench 只是普通文件，删除即可：

# 先确认没有把重要内容只放在 workbench 里
git status
# 手工删除 workbench/ 和 AGENTS.md 中对应段落

建议用 Git 提交删除，保留历史。

10. 常见问题

问题 原因 处理
检查提示占位符未替换 模板里的 {{PROJECT_NAME}} 还在 手工替换，或重新安装
通知 401 token 错误或已失效 找 BotFather 重新生成
通知 400 chat not found chat_id 错误或机器人不在群 重新获取 chat_id，拉机器人进群
上下文太长 包含太多 doc 降低 --max-chars，或不用 --include-docs
安装覆盖了文件 使用了 --force 从 Git 恢复，后续先 --dry-run
VS Code 设置冲突 项目已有 .vscode 安装器只补缺失项，不覆盖已有键

11. 安全清单

  • [ ] workbench/notify.env 已加入 .gitignore
  • [ ] git status 没有 .env、密钥、证书
  • [ ] MACHINE_ACCESS_MATRIX.md 只写账号名，不写密码
  • [ ] NOTIFICATION_TARGETS.md 只写 chat_id，不写 token
  • [ ] 高风险操作有 plan 和回滚
  • [ ] 通知内容不含密码、token、连接串
