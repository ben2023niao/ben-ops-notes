背景与目标

用户要求： 1. 巴西项目静态资源桶使用圣保罗地区（southamerica-east1），香港项目使用亚洲（东京）桶； 2. 静态资源 URL 直接使用 GCS 桶公开地址（storage.googleapis.com），不再依赖 Google CDN/负载均衡， 也不需要 Cloudflare 二级域名映射； 3. 巴西用户就近访问圣保罗桶，亚洲用户后续访问亚洲桶。

技术约束（实测确认）

  • GCS 要求请求 Host 头等于桶名：域名 CNAME 直指 BUCKET.storage.googleapis.com 时浏览器带的是原域名， GCS 返回 404，因此"二级域名直接解析到桶"不可行；
  • Cloudflare Free 套餐无法为 242 条静态记录做 Host 改写（Origin Rules 改 Host 仅 Enterprise、 Transform Rules 禁改 Host、Snippets Free 不可用、Page Rules 仅 3 条/zone）；
  • 最终选定方案：platform-api 静态域名配置直接使用桶公开地址（虚拟主机域名），游戏资源 URL 直出桶。

执行内容

1. 圣保罗桶创建与同步（southamerica-east1）

11 个巴西 live 桶复制为圣保罗桶（-sa 后缀）并全量同步：

bizops-gcs-pg-static-sa / pg3 / pg4 / pg5
bizops-gcs-vendor_a-statics-sa / vendor_a-statics1-sa / vendor_a-statics2-sa
bizops-gcs-pp-static-sa / ppk-static-sa / vendor_c-static-sa / vendor_d-static-sa
  • 全部配置公开读（allUsers objectViewer）+ CORS（GET/HEAD/OPTIONS，origin *）；
  • g759 桶 bizops-gcs-g759-static 本就在圣保罗，无需复制；
  • 东京桶保留为香港/亚洲副本（ASIA），备份桶 bizops-game-statics-gcs 不变。

2. 过渡切换（保留）

Google HTTPS LB backend bucket（bb-*）已全部切到圣保罗桶并做 CDN 缓存失效， 线上静态二级域名（242 条灰云 A 记录）验证 11/11 generation 与圣保罗桶一致。 该链路保留为兜底，不参与新 URL 生成。

3. platform-api 静态域名配置（核心改动）

platform-api/conf/domains/*.json 巴西 7 厂商 static_hosts 全部改为桶虚拟主机域名：

PG      https://bizops-gcs-pg-static-sa.storage.googleapis.com
PG3     https://bizops-gcs-pg3-static-sa.storage.googleapis.com
PG4     https://bizops-gcs-pg4-static-sa.storage.googleapis.com
PG5     https://bizops-gcs-pg5-static-sa.storage.googleapis.com
vendor_a    https://bizops-gcs-vendor_a-statics-sa.storage.googleapis.com
vendor_a1   https://bizops-gcs-vendor_a-statics1-sa.storage.googleapis.com
vendor_a2   https://bizops-gcs-vendor_a-statics2-sa.storage.googleapis.com
PP      https://bizops-gcs-pp-static-sa.storage.googleapis.com
PPK     https://bizops-gcs-ppk-static-sa.storage.googleapis.com
vendor_c https://bizops-gcs-vendor_c-static-sa.storage.googleapis.com
PANDA   https://bizops-gcs-vendor_d-static-sa.storage.googleapis.com
G759    https://bizops-gcs-g759-static.storage.googleapis.com

game_hosts（动态域名）保持不变。

4. 配套脚本同步

  • sync_all_game_domains_to_baota.py：新增 GAME_STATIC_BUCKET_HOSTS 桶域名模式（默认开启， =0 可回退）；宝塔线上脚本 + cron 包装已同步（备份 .bak-20260828）；
  • gcs_static_sync：LIVE 目标切到圣保罗桶，新增 ASIA 组（东京桶），备份组不变； 宝塔线上脚本已备份并切换；
  • entry_health_monitor.py：静态游戏页抽样改桶地址（备用机每 2 分钟巡检已同步并跑通 OK）；
  • static_resource_integrity_audit.py：live 桶引用改 -sa。

5. 发布

  • 本地提交 + 合并 origin/master（开发提交 1ca3baff/ed7736d8 等）+ 推送 master；
  • 最终版本：d24ecff4（Merge remote-tracking branch 'origin/master'）；
  • 通过备用机 bot 发布链路部署 platform-api 到后台 01/02/03：成功 3/3。

验证结果

  1. 12 个桶域名根路径 + 游戏资源页全部 200（/126/index.html、/wondershow/index.html、 /gs2c/openGame.html、/popok/.../29.html、/power_crown/index.html、/iron-valor/index.html）；
  2. 三台后端容器内 /app/platform-api/conf/domains/*.json 全部为桶地址（pg/pg3/pg4/pg5、 vendor_a×3、pp、ppk、vendor_c、vendor_d、g759）；
  3. 入口巡检（备用机）新地址跑通：OK，无报警；
  4. 动态域名无回归：pg-games 200、api 200，vendor_a/pp 403 为无参数业务形态（与发布前一致）。

回滚方式

  • platform-api 配置：改回旧 static_hosts（或 GAME_STATIC_BUCKET_HOSTS=0 重新生成）后重新发布；
  • GCS 桶：东京桶内容保留完整（ASIA 副本），Google LB 兜底链路可用；
  • 宝塔脚本：*.bak-20260828 备份可还原。

待办（香港第二批）

  • 香港 6 个 zone 的静态 CNAME（CloudFront）后续切到亚洲（东京）桶公开地址；
  • 香港 g759/vendor_b 静态需先补齐亚洲桶副本；
  • 巴西 242 条静态二级域名记录保留（兜底），后续可评估下线。

补充（2026-08-28 22:40 双桶测速自动选优）

用户确认巴西桶与香港桶内容一致，且亚洲测试巴西桶偏慢。 launcher 前端本就有并发测速逻辑（HEAD + ?t= 防缓存，先响应者胜）， 因此把巴西（圣保罗）桶与香港/亚洲（东京）桶并列写入 static_hosts：

例：PG  -> ["bizops-gcs-pg-static-sa.storage.googleapis.com",      # 圣保罗
             "bizops-gcs-pg-static.storage.googleapis.com"]        # 东京

浏览器加载时自动选快：巴西用户→圣保罗桶，亚洲用户→东京桶。
