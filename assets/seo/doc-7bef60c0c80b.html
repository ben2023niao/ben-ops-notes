六、本次清理记录（线上网关 16.208.38.88）

  • 根因：/var/log/nginx 25G（access.log 13G+5.4G，轮转 delaycompress 堆积）；Docker 构建缓存 8.3G（可回收 7.3G）。
  • 处理：gzip 未压缩日志（13G→946M）；截断活动访问日志并 reopen；清理 24h 前构建缓存（5.99G）；journal 限额 200M；/tmp 旧文件。
  • 结果：磁盘 82% → 34%（释放约 23G）。
  • 建议：后续为网关 nginx 配置按天压缩+减少保留天数（当前 rotate 14 天 ≈ 25G），或对静态/图片请求关闭 access_log，避免再次堆积。

七、新运维上手建议

  1. 登录前先看 workbench/MACHINE_ACCESS_MATRIX.md 与 devops/ai_context/servers.yml（密钥位置、不做记录外泄）。
  2. 常见操作：ssh 登录（见 servers.yml）、docker ps/logs、nginx -t && nginx -s reload、磁盘/内存巡检。
  3. 发布与域名维护走 ben-bot 按钮；线上/生产变更先快照、通知、备份、验证、回滚。
  4. 密码/token/私钥一律不写入文档与群消息；文档参考 workbench/AI运维教程.md。
