一、需求

开发给的地址（在**动态**域名上）：
  https://vendor_b-games.m4q7z1.shop/lj500/
  https://vendor_b-games.m4q7z1.shop/lj500/index.html
运维侧确认：这个由 nginx 来处理（不是后端路由）。
本轮按要求不通知飞机群。

二、定位

1) 现状：这两条地址都由 **vendor_b 后端**（Sanic，容器 9093）返回 404（14B 纯文本）；
   在 06 链路（CF）上表现相同 —— 说明后端确实没有这个路由。
2) 但页面本身是存在的，在 **vendor_b 静态桶**里：
     bizops-s3-vendor_b-static1/lj500/index.html -> 200 / 97,383B   ← lj500 在这里
     bizops-s3-vendor_b-static /ifff/index.html  -> 200 / 34,238B   ← ifff 页在这里
   对照：PG 的游戏入口是后端自带路由（pg-games.<域>/65/index.html -> 200），
        vendor_b 没有对应路由，所以要在 nginx 侧做兜底。
3) 巴西没有 vendor_b（只有 vendor_a-statics*），仓库里巴西的 vhost 备份是空文件，
   因此按「后端 404 → 回 vendor_b 自己的静态桶」这个口径实现。

三、实现（standby nginx，两个新域名的 vendor_b-games server 块）

    recursive_error_pages on;          # 关键：允许 error_page 链式跳转（nginx 默认 off）

    # 只匹配「单段路径 + 可选 index.html」，避免影响 /webservice、/sso-login.api 等接口的 404 语义
    location ~ ^/[A-Za-z0-9_-]+(/index\.html)?/?$ {
        include snippets/bizops-hk-standby-proxy.conf;
        proxy_pass http://bizops_hk_standby_vendor_b;     # 先走后端
        proxy_intercept_errors on;
        error_page 404 = @vendor_b_page_static1;        # 后端没这个路由才兜底
    }

    location @vendor_b_page_static1 {                   # 第 1 跳：vendor_b 静态桶 1
        internal;
        resolver 192.0.2.2 192.0.2.31 valid=300s ipv6=off;
        rewrite ^(.+)/$ $1/index.html break;         # /lj500/ -> /lj500/index.html
        proxy_ssl_server_name on;
        proxy_ssl_name bizops-s3-vendor_b-static1.s3.ap-northeast-3.amazonaws.com;
        proxy_set_header Host bizops-s3-vendor_b-static1.s3.ap-northeast-3.amazonaws.com;
        proxy_intercept_errors on;
        error_page 403 404 = @vendor_b_page_static0;     # S3 缺对象返回 403，一并拦截
        proxy_pass https://bizops-s3-vendor_b-static1.s3.ap-northeast-3.amazonaws.com;
    }

    location @vendor_b_page_static0 {                   # 第 2 跳：vendor_b 主静态桶
        internal;
        resolver 192.0.2.2 192.0.2.31 valid=300s ipv6=off;
        rewrite ^(.+)/$ $1/index.html break;
        proxy_ssl_server_name on;
        proxy_ssl_name bizops-s3-vendor_b-static.s3.ap-northeast-3.amazonaws.com;
        proxy_set_header Host bizops-s3-vendor_b-static.s3.ap-northeast-3.amazonaws.com;
        proxy_pass https://bizops-s3-vendor_b-static.s3.ap-northeast-3.amazonaws.com;
    }

踩坑：只写 error_page 链是没用的 —— nginx 默认 `recursive_error_pages off`，
      第二跳（static1 403 → static）不会触发，最终返回 nginx 自带的 403 页面。
      加上 `recursive_error_pages on;` 后链式兜底才生效。
备份：/etc/nginx/sites-available/bizops-hk-standby.conf.bak-20261005-vendor_bpage

四、验证（源站 + 经 EdgeOne）

请求 结果
vendor_b-games.m4q7z1.shop/lj500/ 200 / 97,383B（= vendor_b-static1 桶里的文件）
vendor_b-games.m4q7z1.shop/lj500/index.html 200 / 97,383B
vendor_b-games.k8x2v9.shop/lj500/、/lj500/index.html 200 / 97,383B
vendor_b-games.<域>/ifff/、/ifff/index.html 200 / 34,238B（走第 2 跳，从 vendor_b-static 桶取）
vendor_b-games.<域>/health 200 / 105B（后端，未受影响）
vendor_b-games.<域>/webservice/nope 404 / 14B（仍是后端 404，语义未变）
经 EdgeOne 公网：/lj500/、/ifff/ 200（97,383B / 34,238B，text/html） 
EdgeOne 侧动态域名规则是「不缓存」，所以之前后端 404 不会留下边缘缓存，无需清缓存。

五、影响面与回滚

影响面：只影响 vendor_b-games.<新域名> 上「单段路径 / <game>/ 或 <game>/index.html」且后端返回 404 的请求；
        接口路径（多段，如 /webservice/xxx、/sso-login.api）与 WebSocket（/lifeservice/ws2、/ws2）完全不受影响；
        06/07 的 vendor_b-games 未改动（如需同口径，同一段配置复制过去即可）。
回滚：cp /etc/nginx/sites-available/bizops-hk-standby.conf.bak-20261005-vendor_bpage \
        /etc/nginx/sites-available/bizops-hk-standby.conf && nginx -t && systemctl reload nginx
