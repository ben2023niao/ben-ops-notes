  • 影响面：线上全站入口（网关 203.0.113.1 + 宝塔源站 203.0.113.1）
  • 起因：iOS plist 误拦修复后复核「安卓/浏览器是不是真的默认放行」，实测发现 UA 规则还在误伤真实客户端， 且搜索引擎爬虫全部被拦（站点无法被收录）

一、结论

原「UA 真实性」规则是白名单式（默认 0 = 不是完整真实客户端就 444），名单偏窄，导致三类流量被误杀：

  1. 搜索引擎爬虫全部被拦：Googlebot / bingbot / Baiduspider / 搜狗 / 360 / PetalBot 等一个都进不来， 站点等于对搜索引擎关门（Googlebot 桌面版 UA 是 Mozilla/5.0 AppleWebKit/... (compatible; Googlebot/2.1; ...)， 没有平台括号，旧正则必然判 0）。
  2. 国产手机浏览器被拦：华为/荣耀机型 UA 里带 GMSCore 25.38.30 (260400-807569344) 这种嵌套括号， 旧正则 \([^)]+\)[ ]+ 只能吃一层括号 → 整条 UA 判 0 → 真实用户被 444。
  3. Apple 系统网络进程被拦：Safari 的 NetworkingExtension/...、MobileSafari、Firefox 的 MozacFetch、 com.apple.*、CFNetwork —— 与今天 plist 那次是同一类问题。

本次按实测数据把名单重排为「真实客户端 + 全部搜索引擎爬虫」，共 95 条规则。

3.2 修掉「嵌套括号」误杀（真实浏览器）

- "~*^Mozilla/5\.0[ ]+\([^)]+\)[ ].*(AppleWebKit|Gecko|…)" 1;
+ "~*^Mozilla/5\.0[ ]+\(.*(AppleWebKit|Gecko|Trident|Chrome|Chromium|CriOS|FxiOS|Firefox|Safari|Edg|OPR|
   YaBrowser|MiuiBrowser|MiBrowser|HuaweiBrowser|HonorBrowser|Quark|UCBrowser|MicroMessenger|MQQBrowser|
   QQBrowser|SogouMobileBrowser|BIDUBrowser|VivoBrowser|OppoBrowser|HeyTapBrowser)" 1;

去掉了只吃一层括号的 [^)]+，改为 .* + 引擎标识，GMSCore 25.38.30 (260400-…) 这类不再误判。

3.3 补齐 Apple 系统进程 / 国产浏览器

  • Apple：^com.apple.（appstored / WebKit.Networking / AuthenticationServices 等）、NetworkingExtension、 MobileSafari、MozacFetch、CFNetwork、CFNetwork/、Darwin/、AppStore/、MacAppStore、itunesstored
  • 国产/第三方浏览器：com.huawei.hmos.browser、HuaweiBrowser、ANDROID-、android、Xiaomi、vivo、 OPPO、Honor、Quark、UCBrowser、MiuiBrowser、MiBrowser、MQQBrowser、QQBrowser、 SogouMobileBrowser、BIDUBrowser、HeyTapBrowser
  • 安卓下载器：AndroidDownloadManager（apk 分发链路）

3.4 仍保持拦截（防护没有被削弱）

curl / Wget / python-requests / Go-http-client（除支付等豁免路径）/ Java / Scrapy / 极简伪造 UA Mozilla/5.0 / 空 UA / 未识别 UA（default 0）。

注意：放行 UA ≠ 取消限制。IP 黑名单、限流（网关 API 50r/s、源站 30r/s、登录 5r/s） 对所有来源继续生效，爬虫也一样受限流约束。

  • 应继续拦：python-requests / Mozilla/5.0 / curl / Wget / Go-http-client / 空 UA → 依旧 444

经 CloudFront 端到端复测：Googlebot、Baiduspider、荣耀浏览器 UA 请求首页 → 200； 支付回调（Go-http-client UA）→ 200（未受影响）。

5.2 真实流量对比

| 窗口 | 荣耀/华为浏览器 | Apple 系统进程 | 搜索引擎爬虫 |

| --- | --- | --- | --- |

| 修复前（约 12 分钟） | 239 次被拦 + 7,063 次放行 | 146 次被拦 | 183 次被拦 |

| 修复后（当前窗口） | 全部 200，无 444 | 无 444 | 无 444 |

该类别最后一条 444 出现在 11:11:38（本次 reload 是 11:09:48）， 属旧 worker 收尾（nginx 未设 worker_shutdown_timeout，老 worker 要等长连接自然结束才退出）， 其后至今无新增；nginx worker 已全部为 11:09:48 新进程。

六、遗留与建议

  1. worker_shutdown_timeout 未设置：reload 后旧 worker 会继续用旧规则服务一段时间， 造成「改了配置但个别请求仍被旧规则拦」的假象（本次排障就踩到了）。 建议在网关 nginx.conf 加 worker_shutdown_timeout 5s，让 reload 秒级收敛。
  2. 爬虫 UA 可伪造：按 UA 放行意味着伪造 Googlebot UA 也能过 UA 层（仍受限流与 IP 黑名单约束）。 如需更严格，可对 Googlebot/Bingbot 增加反向 DNS 校验（FCrDNS）后再放行。
  3. AI 爬虫未单独列出：GPTBot / ClaudeBot / PerplexityBot 属 compatible; xxxBot 形态， 会被本次兜底规则放行；若确定不希望被 AI 抓取，需要单独加回拒绝。
  4. Apache-HttpClient 仍在拦：部分合作方/游戏服务端 SDK 会用这个 UA（今天实测仍有 15 次被拦）， 若确认是合作方调用，需要按「路径级豁免」或加白处理。
