一、结论

dbqp-ops-console 已从静态 HTML 方案升级为可执行的 FastAPI 控制台， 部署于巴西宝塔，通过 SSH 调用白名单入口对应的发布命令；浏览器可实时查看 stdout/stderr、退出码和状态，并把操作与完整输出写入 SQLite 审计库。

本次同时把结果集权限处理纳入每次后端发布：

  1. rsync 拉取运行时统一加 --chown=1000:1000；
  2. 同步完成后立即静默执行 fix_result_perms.sh；
  3. 启动容器前校验 dbqp-result-perms.timer 为 enabled + active；
  4. 再次扫描 game_result_datas，仍有错误属主或 owner 不可读写时立即中止；
  5. 六台后端的运行期 timer 均保持 enabled + active，作为最后兜底。

三、告警证据与根因

2026-11-02 16:24～16:31（北京）结果集权限 timer 在巴西 01、02、04、05 检测到同一类异常：

命令来源：发版 rsync -a
异常条目：821 个左右
典型属主：root:root
典型权限：777
目标属主：1000:1000（宿主机显示 ubuntu:ubuntu）
修复结果：剩余 0

rsync -a 会保留源端 owner/group，打包机源目录中的 root 属主因此覆盖后端 运行目录。timer 已经能自愈并告警，但发布时间仍可能出现短窗口；本次把这层 自愈移动到同步与启动之间，并从同步源头强制目标属主。

四、控制台实现

4.1 部署拓扑

浏览器
  -> 203.0.113.1:8787（宝塔 Nginx）
  -> 203.0.113.1:8788
  -> dbqp-ops-console 容器
  -> 私网 SSH
  -> 03 / 巴西后端 / 香港后端

容器名：dbqp-ops-console

容器不挂载宿主机 Docker Socket；发布命令通过私网 SSH 到达目标机。宝塔 Nginx 负责公网端口反代，容器端口只绑定本机回环。

4.2 鉴权与审计

  • 单密码登录，无用户名；
  • HttpOnly + SameSite=Strict Cookie；
  • 默认会话 12 小时；
  • 同 IP 5 分钟内失败 5 次限速；
  • SQLite 保存登录、页面点击/输入、执行命令、输出、退出码和通知结果；
  • sshpass 密码、URL 内嵌凭据、Bot Token 在落库前脱敏；
  • 密码、SSH 密码、GitLab URL、Telegram Token/Chat ID 只从只读 Secret 文件读取。

4.3 实时输出与状态

  • 执行接口创建 Job 后返回 events_url；
  • 前端使用 SSE 接收 stage/stdout/vendor/complete/error/cancelled；
  • 输出显示在被点击命令的下方；
  • 执行中同步更新巴西 01/02/04/05、香港 01/02、打包机 03 状态；
  • 8 个镜像厂家分别更新“待打包/已打包”；
  • 页面刷新后从 /api/jobs 恢复服务器和镜像状态；
  • 断线后 EventSource 重连并从事件序号继续读取。

4.4 页面操作

  • 命令默认折叠，但折叠标题右侧也能点击“执行”；
  • 一键准备：通知、拉代码、构建、检查；
  • 一键巴西：01 金丝雀后按 02 → 04 → 05；
  • 一键香港：01 后按配置批量；
  • 移动端一键按钮竖向排列，服务器状态为两列，审计抽屉不超出视口；
  • Cloudflare 缓存区明确提示必须登录固定页面，不能在控制台内直接清除。

五、结果集权限闭环

每个后端发布命令的固定阶段变为：

pull images
→ stop containers
→ rsync
→ NOTIFY=0 /opt/dbqp-scripts/fix_result_perms.sh
→ check dbqp-result-perms.timer enabled + active
→ scan game_result_datas
→ start containers
→ verify Image ID
→ print container status

同步参数：

rsync -a ... --chown=1000:1000 ...

启动前门禁：

RESULT_PERMS_TIMER=OK
RESULT_PERMS_NOW=OK

任一检查失败，命令以非零退出码结束，后续启动和批量节点不再执行。

十、安全边界

  • 控制台只绑定 203.0.113.1:8788；
  • GCP 防火墙只开放宝塔入口 8787；
