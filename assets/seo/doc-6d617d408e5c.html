复杂业务架构能力门禁

本文定义 乌托邦 的 Architecture Capability Gates。它用于防止 AI Agent 或初级工程实现把复杂业务误做成简单 CRUD、同步接口、静态页面、本地资源或不可观测的临时方案。

乌托邦 不做“低门禁模式”。所有任务都有不可降低的基础完成底线；复杂业务按风险自动追加架构能力判断。MVP 可以分阶段实现，但不能没有架构意识。

1. 设计目标

  1. 让 AI 在实现前先判断业务复杂度，而不是默认 CRUD 足够。
  2. 让复杂业务提前考虑异步、缓存、CDN、统计、搜索、推荐、高可用、可观测、数据一致性、权限、安全、迁移和回滚。
  3. 让“不上某项能力”的选择可审查，必须写清不适用原因、当前边界和升级触发条件。
  4. 让架构成熟度证据沉淀到 PRD、ADR、OpenAPI、数据模型、QA、运维和 Agent 日志中。
  5. 让项目可以分阶段交付，但不能把低成熟度方案包装成完成。

2. 适用范围

以下任务必须进行架构能力判断：

  1. 新增业务模块、核心流程、后台能力、支付/订单/钱包/账本、用户关系、消息、音视频、Feed、搜索、推荐、审核、处罚、内容管理、数据统计。
  2. 修改影响并发、性能、可用性、数据一致性、安全、权限、隐私、审计、部署、回滚或迁移的逻辑。
  3. 引入第三方服务、对象存储、CDN、队列、缓存、搜索引擎、埋点、数据看板、风控、支付、音视频、IM 或异步回调。
  4. 将功能从试验状态推进到真实用户、真实资金、真实运营或生产环境。

纯文案、只读文档、无运行时影响的改动可以标记为不适用，但 Agent 日志必须写清原因。

3. 不允许的 AI 偷懒模式

  1. 只写 CRUD 接口，不判断是否需要队列、缓存、幂等、审计或事务。
  2. 只用本地图片或本地视频，不判断 CDN、对象存储、缩略图、转码和防盗链。
  3. 只写同步接口，不判断慢任务、回调、重试、死信和补偿。
  4. 只做页面展示，不接真实契约、权限、数据状态和错误处理。
  5. 只写“后续优化”，不写升级触发指标。
  6. 用“当前 MVP”作为跳过架构判断的理由。
  7. 把不涉及项直接省略，而不是写“不适用”及原因。
  8. 高风险业务没有权限、审计、幂等、回滚和验证证据。
  9. 没有可观测性，却宣称生产可用。
  10. 没有数据迁移和回滚方案，却修改数据结构或数据口径。

4. 不可降低的基础完成底线

无论项目处于 MVP、growth、scale 还是 enterprise，以下底线不能降低：

  1. 需求 ID。
  2. PRD 或任务说明。
  3. 验收标准。
  4. Agent 日志。
  5. 验证证据。
  6. 明确结论：允许合入 / 不允许合入 / 阻塞。
  7. 不涉及项必须写“不适用”及原因。

MVP 可以少做能力实现，但不能少做能力判断。

5. 风险驱动追加门禁原则

乌托邦 不按 MVP 降低门禁，而按业务风险追加门禁：

风险信号 必须追加的判断
资金、订单、余额、扣费、收益、退款、账本 事务、幂等、审计、对账、补偿、权限、回滚
用户数据、隐私、账号、安全 权限、风控、合规、审计、数据删除和恢复
Feed、搜索、推荐、首页排序 缓存、召回、排序、冷启动、指标口径、权重配置
图片、视频、音频、下载 对象存储、CDN、缩略图、转码、防盗链、清理策略
聊天、通知、音视频、实时状态 实时服务、事件、超时、重试、降级、可观测性
后台审核、处罚、敏感操作 RBAC、审批流、审计日志、回滚和操作证据
高并发或高频接口 缓存、限流、熔断、压测、SLO、慢查询
数据迁移、表结构、口径调整 migration、回滚、备份恢复、双写/兼容、数据校验

6. MVP 的正确理解

MVP 是分阶段交付，不是低成熟度交付。

正确写法：

当前阶段不上 CDN，因为内测环境每日资源量低于 1GB，且只面向内部用户。
边界：仅内测使用，资源不用于公开传播。
升级触发：公开发布、每日资源超过 10GB、图片加载 P95 超过 800ms、出现盗链风险。
后续方案：对象存储 + CDN + 缩略图服务 + 防盗链。

错误写法：

MVP 阶段，暂不考虑 CDN。

Agent 必须写清楚当前方案边界和未来迁移成本。不上某项能力可以，但不能不判断。

7. 架构能力清单

7.1 异步任务 / Queue / Worker / Retry / DLQ

项目 内容
什么时候触发 任务耗时、第三方回调、批处理、通知、审核、转码、补单、同步外部数据、定时任务、用户请求不应等待的工作。
需要回答的问题 哪些任务异步化？是否幂等？失败如何重试？何时进入死信队列？如何补偿？如何观测队列积压？
推荐沉淀位置 docs/architecture/scaling-strategy.md、docs/architecture/data-model.md、docs/operations/ops-readiness.md、services/worker/README.md、ADR。
最低验收证据 任务状态、重试策略、幂等键、失败处理、队列指标、Agent 日志。

7.2 缓存 / Redis / 本地缓存 / 缓存失效 / 防击穿 / 限流

项目 内容
什么时候触发 热点读、首页、Feed、排行榜、配置、用户资料、价格、权限、频繁查询、慢查询或高并发接口。
需要回答的问题 缓存 key、TTL、失效策略、穿透/击穿/雪崩防护、数据一致性、权限态是否可缓存、限流策略。
推荐沉淀位置 docs/architecture/scaling-strategy.md、docs/architecture/observability-baseline.md、docs/api/**、ADR。
最低验收证据 缓存策略说明、命中率指标、失效路径、限流配置或不适用原因。

7.3 CDN / 对象存储 / 图片视频资源分发 / 缩略图 / 转码 / 防盗链

项目 内容
什么时候触发 图片、视频、音频、下载包、用户上传、公开内容、App 官网、落地页、动态、头像、礼物资源。
需要回答的问题 资源存哪里？谁生成缩略图？是否转码？是否防盗链？缓存多久？如何清理违规内容？如何迁移本地资源？
推荐沉淀位置 docs/architecture/scaling-strategy.md、docs/operations/deployment-strategy.md、docs/project/third-party.md、infra/deploy/README.md、ADR。
最低验收证据 存储方案、资源 URL 规则、缩略图/转码边界、防盗链或不适用原因、回滚和清理策略。

7.4 统计分析 / 埋点 / 事件 Schema / 指标口径 / 数据看板

项目 内容
什么时候触发 增长、运营、转化、充值、留存、审核效率、内容质量、搜索效果、推荐效果、广告或活动。
需要回答的问题 事件名是什么？字段含义是什么？指标口径是什么？谁消费数据？是否影响隐私？看板在哪里？
推荐沉淀位置 packages/contracts/events.md、docs/architecture/data-model.md、docs/qa/acceptance-evidence.md、docs/project/third-party.md。
最低验收证据 事件 schema、指标口径、采集位置、验证方式、看板或导出说明。

7.5 搜索 / 推荐 / Feed 排序 / 召回排序 / 冷启动 / 权重配置

项目 内容
什么时候触发 首页推荐、发现页、内容列表、用户列表、搜索、标签、附近、热度、付费权重、多语言/国家排序。
需要回答的问题 召回源是什么？排序权重是什么？冷启动怎么处理？权重谁配置？如何解释结果？如何回滚排序策略？
推荐沉淀位置 docs/prd/**、packages/contracts/openapi/**、docs/architecture/scaling-strategy.md、docs/decisions/**。
最低验收证据 排序规则、配置入口、测试样本、边界说明、指标或人工验收结果。

7.6 高可用 / 超时 / 重试 / 熔断 / 降级 / 灰度 / 回滚

项目 内容
什么时候触发 外部依赖、支付、音视频、IM、搜索、CDN、核心 API、上线发布、跨服务调用。
需要回答的问题 超时多久？重试几次？是否幂等？失败如何降级？灰度如何控制？如何回滚？用户看到什么状态？
推荐沉淀位置 docs/operations/ops-readiness.md、docs/operations/deployment-strategy.md、docs/templates/ops-runbook-template.md、ADR。
最低验收证据 超时/重试/降级策略、回滚步骤、故障演练或手工验证记录。

7.7 可观测性 / 结构化日志 / trace id / metrics / alert / 慢查询 / 队列积压

项目 内容
什么时候触发 任何生产服务、后台敏感操作、队列、缓存、第三方回调、高风险业务和性能敏感接口。
需要回答的问题 日志字段是什么？trace id 如何贯穿？有哪些指标？告警阈值是什么？慢查询和队列积压如何发现？
推荐沉淀位置 docs/architecture/observability-baseline.md、docs/qa/performance-evidence.json、docs/operations/incident-response.md。
最低验收证据 日志样例、指标名称、dashboard/alert/runbook 或不适用原因。

7.8 数据一致性 / 事务 / 幂等 / 账本 / 对账 / 补偿 / 审计日志

项目 内容
什么时候触发 资金、订单、余额、扣费、收益、礼包、会员、支付回调、补单、退款、账户状态、敏感资料变更。
需要回答的问题 事务边界是什么？幂等键是什么？账本如何记？如何对账？失败如何补偿？审计日志记录哪些字段？
推荐沉淀位置 docs/architecture/database-design-standards.md、docs/architecture/data-model.md、docs/templates/database-table-template.md、ADR。
最低验收证据 事务设计、幂等规则、账本/审计字段、异常补偿路径、服务端测试。

7.9 权限与安全 / RBAC / 敏感操作 / 风控 / 合规

项目 内容
什么时候触发 登录、账号、后台、审核、处罚、举报、用户数据、资金、配置、导出、删除、第三方密钥。
需要回答的问题 谁能操作？权限模型是什么？敏感操作是否二次确认？是否审计？是否涉及隐私和合规？如何防滥用？
推荐沉淀位置 docs/security/risk-control.md、docs/api/admin-api.md、docs/architecture/admin-platform.md、docs/operations/secrets-management.md。
最低验收证据 RBAC 规则、鉴权测试、审计字段、风控策略或不适用原因。

7.10 数据迁移 / Migration / 回滚 / 备份恢复

项目 内容
什么时候触发 新表、改字段、改索引、数据口径变化、批量修复、历史数据迁移、拆库分表、事件回放。
需要回答的问题 migration 如何回滚？是否需要备份？是否兼容旧代码？是否有数据校验？失败如何恢复？
推荐沉淀位置 docs/architecture/data-model.md、docs/operations/backup-restore.md、docs/operations/deployment-strategy.md、ADR。
最低验收证据 migration 文件、回滚步骤、备份恢复说明、校验 SQL/脚本、灰度计划。

9. Agent 实施前必须回答的问题

  1. 这个需求是否只是 CRUD？如果不是，复杂点在哪里？
  2. 是否涉及异步、缓存、CDN、统计、搜索、推荐、权限、审计、高可用？
  3. 是否涉及资金、订单、扣费、收益、审核、处罚、用户数据、生产发布？
  4. 如果现在不上某项能力，未来迁移成本是什么？
  5. 当前 MVP 方案的边界是什么？
  6. 什么指标触发架构升级？
  7. 不涉及的能力为什么不涉及？
  8. 哪些判断需要写入 PRD、OpenAPI、ADR、数据模型、QA、运维或 Agent 日志？

10. 证据和门禁

结构化证据写入：

docs/qa/architecture-capability-evidence.json

门禁命令：

npm run check:capability-gates

完成状态必须包含能力判断、MVP 边界、升级触发条件、红蓝对抗和合入判断。证据不完整时只能标记为 in-progress、blocked 或 not-applicable。
