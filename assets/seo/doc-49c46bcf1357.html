一、结论

开发在新增 domains-hk 时没有使用香港线上配置，而是把其他环境的 jili.json 和旧 cn 分支 Host 复制进香港目录。

直接证据：

提交：2d725319 增加香港域名配置
作者：ben <[邮箱已脱敏]>
时间：2026-11-02 14:48:33 +0800
巴西 jili.json blob：6760d9d2dd32108a3934649332cc288e5238f5f6
香港 jili.json blob：6760d9d2dd32108a3934649332cc288e5238f5f6

两个文件完全相同，且香港 jili.json 自该提交后从未修改。更准确地说，这不是 普通“测试环境配置”，而是把巴西 Jili 的多 CDN 域名配置原样复制到了香港。

二、故障证据

修复前：

jili-aws.cxkerui.com/game-setting/game-info-list    502
jili-ali.shangdefu.com/game-setting/game-info-list  502
jili-cf.nuvastone.com/game-setting/game-info-list   502

香港应用容器和端口正常：

HK01 game-service-jili-prod：running，RestartCount=0，OOMKilled=false，9093
HK02 game-service-jili-prod：running，RestartCount=0，OOMKilled=false，9093

因此不是 Jili 应用崩溃，而是配置下发了香港不可用的动态/静态 Host。

五、校验器加固

scripts/validate_domains.py 新增香港 Host 精确定位校验：

  • 每个厂家 default/static/game Host 必须等于香港线上配置；
  • PG 各特殊组静态域名及 Socket API 域名必须完整；
  • TADA/JILI v1～v5 使用各自香港扩展静态域名；
  • 20261028 新游戏组沿用所属环境已验证 Host；
  • 新增 Host 或更换线路必须显式更新校验规则，不能直接复制其他环境配置。

验证：

DOMAIN_CONFIG_OK
BR_HOSTS_VS_LIVE=PASS
HK_HOST_FAMILY_CHECK=PASS
