一、现象与线索

用户/开发：从 https://97578aa.com/come.html?timestamp=… 用游客登录进 vendor_b 游戏「还是无法进入」，
并给了浏览器 DevTools 的完整请求列表（Copy as cURL），关键几条：
  1) POST https://socket.p3w9n5.shop/web-api/game-proxy/v2/User/Logout
  2) POST https://socket.p3w9n5.shop/web-api/game-proxy/v2/GameEntry/Get   {"uid":"BAILI_541218","hall":2,"gi":109,…}
  3) HEAD https://vendor_b-static.m4q7z1.shop/?t=1791441043005      ← 返回 403
  4) HEAD https://vendor_b-static.k8x2v9.shop/?t=1791441043006      ← 返回 403
  5) HEAD https://vendor_b-games.m4q7z1.shop|k8x2v9.shop/?t=…      （动态域名，403，巴西同样 403）
  6) POST https://vendor_b-games.k8x2v9.shop/network-report + OPTIONS
  7) GET  https://vendor_b-static.m4q7z1.shop/fg/?apiId=…&gameID=109&sip=vendor_b-games.k8x2v9.shop…（iframe 导航）

先核对整体健康：四套动态域名 /health 200、静态页与资源 200、01/02 容器正常 —— 服务没挂。
再看这个用户的会话（BAILI_541218，北京 14:28–14:35）：/fg/req 46 次全 200、/webservice/event/user 200，
说明默认分组（fg，gameID 109）在他这边其实跑起来了；同窗口还有 `GET /mp2/index.html → 404`（mp2 = gameID 303，v3 分组）。

二、两个真问题（都在静态域名这一层）

问题 1：静态域名根路径探活 403（巴西是 200）

大厅在拉起游戏前会对静态域名根做一次探活：`HEAD /?t=<ts>`（sec-fetch-mode: no-cors）。
对照两条链路实测：
  巴西（内容在 GCS）：vendor_a-statics3.t6qv8m.icu/?t=…   → 200（GCS 桶根 200）
  香港（内容在 S3）： vendor_b-static.m4q7z1.shop/?t=…    → 403（S3 桶根 AccessDenied）
→ 大厅判定「静态域名不可用」，游戏拉不起来。
（动态域名根的 403 两边一致，不是问题。）

问题 2：v2~v5 分组的静态域名 404

线上 conf/domains/vendor_b.json：
  default → vendor_b-static.<新域>            （内容在 vendor_b 大阪桶 bizops-s3-vendor_b-static，OK）
  v1      → vendor_b-static1.<新域>           （既在 vendor_b 大阪桶，也有 vendor_a 前缀兜底，OK）
  v2      → vendor_b-static2.<新域>           ← 香港侧没有 bizops-s3-vendor_b-static2 桶
  v3      → vendor_b-static3-aws.hkcloudplay0[67].com
  v4      → vendor_b-static4-aws.hkcloudplay0[67].com
  v5      → vendor_b-static5-aws.hkcloudplay0[67].com
`-aws` 这几个经 CF 通配解析落到本机 standby，但本机没有这些 server_name → 命中默认站点（平台页/404），
实测 `GET /mp2/index.html → 404`。
这些分组的内容其实在 **GCS**（与巴西 Worker 的 BUCKET_MAP `vendor_a-statics2..5` 一致）：
  newgg2-bizops-gcs-vendor_a-statics3/mp2/index.html = 200（v3）
  newgg2-bizops-gcs-vendor_a-statics4/gb/index.html  = 200（v4）
  newgg2-bizops-gcs-vendor_a-statics5/c7d/index.html = 200（v5）
  newgg2-bizops-gcs-vendor_a-statics2/lm/index.html  = 200（v2）

三、修复（standby nginx）

1) 新增 snippets/bizops-hk-standby-static-root-ok.conf：静态域名根路径
   `location = /` 仍先回源（桶里真有根 index.html 就照常返回），只有 403/404 时兜成 200 空响应（对齐 GCS）。
   · include 进 vendor_b 静态块、m4q7z1/k8x2v9 两个通用静态块；
   · 06/07 通用静态块（用主桶前缀）内联了同样的处理。
2) 新增 snippets/bizops-hk-standby-gcs-static.conf + 一个 server 块：
   `server_name ~^vendor_b-static(?<bizops_gcs_group>[2-5])(-aws)?\.(hkcloudplay0[67]\.com|m4q7z1\.shop|k8x2v9\.shop)$`
   → 按分组回源 `newgg2-bizops-gcs-vendor_a-statics<2..5>`，并带上静态口径：
     目录 302 → index.html、OPTIONS 204、.js 强制 MIME、customizations.info 空 200、CORS *、根路径 200。
   放在通用静态块之前（先匹配先赢）。
3) 静态 CORS 仍是运维口径（ACAO *）；动态域名 CORS 未动（按既定职责划分）。

备份：bizops-hk-standby.conf.bak-20261008-1433-rootok、snippets/*.bak-20261008-1433；
      nginx -t 通过后 reload（active）。

五、遗留 / 待确认

· 06/07（Cloudflare 链路）的静态域名走 **Worker**，不经本机 nginx，根探活仍是 403；
  若以后有平台走该链路，需要开发在 Worker 里补一条「/ 返回 200」（或把静态域名切到腾讯线）。
· v2~v5 现在直接回源 GCS（跨国），能跑但不如本地 S3 快；
  后续可把 `newgg2-bizops-gcs-vendor_a-statics2..5` 同步到香港侧桶（或大阪桶）再切回，参照 sync_gcs_to_s3.py。
· 平台侧 403 的小图标资源（`/<game>/htt/smallicon/setting.json`、`/lj500/favicon0.ico`）仍是缺文件，
  各源都没有，需要开发补传（不影响进入游戏）。
