  • 对比口径：同为 22:00-23:00 一小时（原因见下）

一、为什么只取一小时

api_request-2026-10-16.log 的 第一条记录是 22:15:08（当天日志从 22:15 才开始写）， 所以 10-16 的 870MB 只覆盖 1.75 小时；而 10-17 的 7.13GB 覆盖完整 24 小时。

直接拿「10-16 0.85GB vs 10-17 7.13GB」得出「涨 8 倍」是错的——那是覆盖时长差异造成的假象。 必须按同一小时对比，本包即按 22:00-23:00 取样。

二、同小时实测

| 指标 | 10-16（正常日）22:00-23:00 | 10-17（异常日）22:00-23:00 | 变化 |

| --- | ---: | ---: | ---: |

| api_request 行数 | 776,327 | 911,306 | +17.4% |

| api_request 原始体积 | 345 MB | 403 MB | +17% |

| api_response 行数 | 20,434 | 88,826 | +334%（4.3 倍） |

| api_response 原始体积 | 54 MB | 263 MB | +387% |

结论：请求条数只涨了 17%，但响应日志条数涨了 4.3 倍——说明相同请求量下，单请求返回的内容明显变大/变多，这与数据库侧看到的「读放大」方向一致。

三、包内容

每个日期的包（zip 分卷，需先合并）：

10-16-正常日-22点-原始日志.zip.part-00 / part-01
10-17-异常日-22点-原始日志.zip.part-00 / part-01

合并与解压：

cat 10-16-正常日-22点-原始日志.zip.part-* > a.zip && unzip a.zip
cat 10-17-异常日-22点-原始日志.zip.part-* > b.zip && unzip b.zip

zip 内文件：

api_request-2026-10-1X-22h.gz.part-00/01   # 原始请求日志（gzip 分卷）
api_response-2026-10-1X-22h.log.gz          # 原始响应日志（gzip）
README.txt                                  # 时间范围/行数/解压方式

解压请求日志：

cat api_request-2026-10-16-22h.gz.part-* > req.gz && gunzip req.gz

四、可直接对比的字段

api_request 每行是一个 JSON，含：

logId / data.method / data.url / data.action / data.ip / data.deviceType /
data.deviceTypeNew / data.deviceId / data.version / data.userId / data.params / time

api_response 每行含 logId / data.action / data.url / data.response / time。

建议对比方式（同一小时、同一接口）：

# 两天各接口调用量
zcat req-16.gz | grep -o '"url":"[^"]*"' | sort | uniq -c | sort -rn | head -30
zcat req-17.gz | grep -o '"url":"[^"]*"' | sort | uniq -c | sort -rn | head -30

# 同接口的响应体大小分布（在 api_response 里）
zcat resp-16.gz | grep -o '"url":"[^"]*"' | sort | uniq -c | sort -rn | head
zcat resp-17.gz | grep -o '"url":"[^"]*"' | sort | uniq -c | sort -rn | head

五、附注（数据完整性）

  • 后端 nginx access 的本地轮转只保留当天（10-19），10-16/10-17 的 access 已按策略归档到 S3（youdianse-prod-gateway-logs），对象名为 nginx/access.log.N.gz，不含日期，无法直接定位到某一天，故本次用应用层 api_request/api_response 做对比。
  • 若需要 10-16/10-17 的 nginx access 原始文件，可另行从 S3 批量拉取（需按文件内时间戳筛选）。
