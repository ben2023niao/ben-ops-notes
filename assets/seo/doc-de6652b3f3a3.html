二、授权安全测试一：业务面「登录接口撞库/爆破」（仍未拦住）

2.1 授权安全测试者

来源 IP（XFF 真实客户端）：3.1.244.240（AWS 新加坡段；请求经 CloudFront 边缘 64.252.x.x / 52.46.x.x 回源）
本轮规模：约 1 小时内 2,663 次请求（集中在 15:00 UTC = 23:00 北京）

2.2 打点路径（换路径 + 换方法 + 换 UA）

HEAD /api/v1/Login/username              UA: python-requests/2.32.5   → 444（被 UA 规则拦下）
HEAD /api/v1/Login/email                 UA: python-requests/2.32.5   → 444
POST /api/v1/Login/account               UA: 伪造 Windows Chrome      → 200（透过 UA 规则）
POST /api/v1/LoginNew/account            UA: 伪造 Windows Chrome      → 200（635B 业务响应）
POST /api/v1/UserProduct/getProductList  UA: 伪造 Windows Chrome      → 200（尝试拉业务数据）

统计：python-requests/2.32.5 1,343 次全部 444；伪造 Chrome 1,320 次全部 200。

2.3 要点

  1. UA 黑白名单已被绕过：一半请求用脚本 UA（被拦），另一半换成完整 Windows Chrome UA 就通过了 —— UA 真实性只能滤掉懒脚本，挡不住有意的撞库。
  2. 踩在限流阈值下：约 22 次/分钟（≈0.37 次/秒），低于网关 50r/s、登录 5r/s 的阈值，因此没有触发任何 429，也没触发 CC 守卫。
  3. 覆盖 4 条登录路径（含 LoginNew/account），说明授权安全测试者在探测我们的接口版本。
  4. 该 IP 目前不在网关/宝塔拦截清单中（abuse-blocklist.conf、10-abuse-blocklist.conf 均无）。

6 排查同类容器 网关 / 后端 / 宝塔 / 测试 EC2 均无同类容器、无 8111 监听

六、未闭环风险（按优先级）

  1. 【高】IAM 凭据未轮换：IAM 用户 18game-devops（账号 176528004422）的访问密钥与控制台密码曾放入公网可达容器、并明文提交进仓库（git 历史仍在）；授权安全测试者做过 ${AWS} 环境变量注入探测 → 必须轮换并同步更新使用方。
  2. 【高】登录撞库仍在进行：3.1.244.240 未被封禁、未触发限流；UA 规则挡不住换 UA 的授权安全测试者 → 建议立即封禁该 IP、并对登录路径加严 + 增加账号级失败锁定/验证码。
  3. 【高】运维接口公网可达且无鉴权：/dns_check.php、/boce_*.php、/18game.php、/glances*.php、项目成本页、S3 管理器 8111 → 建议加 IP 白名单或 Basic Auth；管理类能力改为服务端鉴权 + 仅内网。
  4. 【中】报告页与内部页面泄露信息：/dns_check/*.html 含我们的域名清单（很可能就是授权安全测试者的"清单来源"）；成本/监控页面含内部数据 → 建议清理或下线，改为内网访问。
  5. 【中】被删对象未恢复：ace/ace-021122.ipa（454MB）。
  6. 【中】守卫覆盖不足：当前 CC 守卫以 SSR 根路径 QPS 与 /api 泛刷量为主，对"低速率、换 UA、换登录路径"的撞库没有识别能力 → 建议新增登录失败次数/成功率异常、非浏览器 UA 打登录、同 IP 多路径探测等规则。

七、建议的直接动作（可按序执行）

1) 封禁 3.1.244.240（网关 maps + 宝塔清单 + iptables），并为登录接口增加"按 IP 失败次数"计数封禁
2) 轮换 18game-devops 的访问密钥与控制台密码（AWS 控制台），更新所有使用方
3) 运维接口收敛：8080 的 /dns_check.php、/boce_*.php、/18game*.php、/glances*.php 加白名单/鉴权；
   报告目录与成本页面下线或仅内网
4) 补回 ace-021122.ipa
5) 给 CC 守卫增加"登录撞库"识别规则（低速率 + 换 UA + 多路径）并接入告警
