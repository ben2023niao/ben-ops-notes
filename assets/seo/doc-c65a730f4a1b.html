一、目标

  1. 巴西静态资源就近（圣保罗桶），亚洲少量用户就近（东京桶）；
  2. 去掉 Google CDN 域名映射，游戏资源 URL 直出 GCS 桶公开地址；
  3. 缩短"进游戏"链路（对比竞品 m6kk678n.com / 96A.com）；
  4. 建立可复用的自动化对比/录屏工具。

二、GCS 静态双桶就近（已完成）

圣保罗桶

  • 11 个 live 桶复制为圣保罗（southamerica-east1，-sa 后缀）并全量同步： pg/pg3/pg4/pg5、vendor_a-statics×3、pp、ppk、vendor_c、vendor_d；
  • 全部公开读（allUsers objectViewer）+ CORS（GET/HEAD/OPTIONS，origin *）；
  • g759 桶本就在圣保罗；新建 bizops-gcs-g759-static-asia（东京）作亚洲副本并全量同步；
  • 东京桶保留为香港/亚洲副本（ASIA），备份桶 bizops-game-statics-gcs 不变。

配置直出桶地址

  • platform-api/conf/domains/*.json 巴西 7 厂商 static_hosts 改为桶虚拟主机域名；
  • 每厂商并列两个地址：圣保罗桶 + 东京桶，launcher 前端并发测速自动选优 （巴西→圣保罗，亚洲→东京，实测选优生效）；
  • sync_all_game_domains_to_baota.py 新增 GAME_STATIC_BUCKET_HOSTS 桶域名模式（默认开， =0 回退），宝塔线上脚本+cron 已同步；
  • gcs_static_sync：LIVE→圣保罗桶，新增 ASIA 组（东京桶），备份组不变；
  • entry_health_monitor.py 静态游戏页抽样改桶地址（备用机已同步，巡检通过）；
  • static_resource_integrity_audit.py live 引用改 -sa。

GCS 缓存头

  • 对象原无显式 cache-control（吃默认 3600s）；
  • 批量设置：图片/css/字体 → public, max-age=31536000, immutable； js → max-age=86400；html/json 保持默认（12 桶全量完成并抽查验证）。

三、Cloudflare 协议优化（已完成）

  • 42 zone 全部开启：TLS 1.3、HTTP/3(QUIC)、0-RTT Connection Resumption；
  • 马尼拉复测：回访连接建立 0.2-0.7s 收益（Logintest 752→386ms、api 1154→440ms）；
  • 竞品 api4 仍 36ms（其源站/边缘在马尼拉附近），协议层补不平源站距离。

四、启动链路优化（已完成/部分完成）

P0-1 launcher 测速优化（已发布 226c814d）

  • 测速超时 3000→800ms（环境变量 LAUNCHER_PING_TIMEOUT_MS 可调）；
  • 并发批 5→8；选中 host 记忆 localStorage（回访免测速）；
  • platform-api 三台后端发布成功 3/3。

瀑布诊断（马尼拉，游戏 126）

游戏 HTML(pg-games) TTFB 1363ms（动态，回巴西）
shared/report.js           968ms（静态，源站 no-cache → CF BYPASS）
api/report/timing         1021ms
东京桶静态资源             ~23ms（无瓶颈）

report.js / shared 静态边缘缓存（纯 nginx 实现）

  • 根因：宝塔 WAF(btwaf) Lua 注入 server_name_session cookie，CF 免费版不缓存带 Set-Cookie 响应；
  • 宝塔：/shared/ 专属 location（按 host 映射厂商 upstream）+ Cache-Control public 1 天
  • 隐藏 Set-Cookie；btwaf header.lua 对 /shared/ 跳过 cookie 注入；
  • 备用机同步相同配置（无 WAF，天然无 cookie）；
  • 实测：cf-cache-status BYPASS → MISS → HIT（age 递增），report.js 1s → 边缘 ~50ms；
  • 备份：nginx/btwaf 相关文件 .bak-20260829。

nginx 连接复用（宝塔 + 备用机同步）

  • 根因：0.websocket.conf map 把非 WS 请求 Connection 设为 close → 每次新建后端连接；
  • 修复：'' close; → '' "";（启用 upstream keep-alive）；
  • keepalive_timeout 60→300s，keepalive_requests 10000；
  • gzip 原本已开启；TLS 会话缓存 10m 够用。

preconnect / Early Hints（评估后暂缓）

  • 游戏页 HTML 为厂商页面、launcher 路由在镜像内，repo 侧无法注入 preconnect/Link 头；
  • 需要厂商/前端配合或 Cloudflare 响应头规则（规则集权限），记为后续。

五、竞品对比测试（多轮，结论）

入口 30 次循环（马尼拉）

我方 TTFB 中位 386ms / p95 764ms（116 资源，5.48MB）
竞品 TTFB 中位 1484ms / p95 2144ms（110 资源，1.37MB）
我方首屏体积大 4 倍（封面图预加载）

静态/CDN 30 次采样（马尼拉 TTFB p95）

我方东京桶 66ms（稳定） / 圣保罗桶 1949ms（跨洲慢尾巴，选优已避开）
竞品 game-logo 119ms

同游戏旧标准（点击游戏卡→网络稳定）

优化前：我方 9.7s vs 竞品 4.0s（结论：2.4 倍差距）
优化后冷缓存：基本持平（7.7s/10.7s）
优化后回访：出画 4.9s（-36%）、稳定 7.9s（-26%）

新标准（点击"继续游戏"→可玩，备用机巴西视角）——最终结论

游戏            我方    竞品
Fortune Tiger   7.6s   7.7s
麻将胡了        8.2s   7.4s
寻宝黄金城      8.9s   8.5s
赏金大对决      10.0s  7.9s
寻龙探宝        8.9s   8.4s

关键发现： 1. 竞品同样存在"设备检测/继续游戏"环节，之前 4.0s 是未点继续的假象； 2. 新标准下双方几乎打平（差 0.3-2.1s）； 3. 我方全程走圣保罗桶（or=pg4-static-sa），静态无瓶颈。

六、自动化工具（已完成）

docker/scripts/game_load_video_compare.py + README： - 支持 --side our/comp/both、--games、--out； - 自动：打开游戏 → 等可见画布 → 点击"继续"（候选点+像素变化）→ 等网络稳定； - 计时：canvas_ms + continue_ready_ms（点击继续→可玩，新标准）+ stable_ms； - 输出：webm + MP4（ffmpeg 转 H.264/faststart，Telegram 自动播放）+ PNG + results.json； - 失败自动重试 1 次；竞品登录账号可用环境变量覆盖。

七、多地区部署 / AWS 评估结论

  • A 档（边缘缓存静态/稳定 GET）：已部分落地（shared/report.js、GCS 缓存头）；
  • B 档（亚洲 platform-api + Redis 副本）：可行但 MySQL 仍回巴西，收益有限， 需 MySQL 只读副本；亚洲用户约 10%，性价比需评估；
  • C 档（游戏服务亚洲化）：追平竞品源站距离的完整路径，成本最高；
  • AWS CloudFront 用于动态 API：边缘不解决源站距离（源站仍在巴西），不建议切换。

八、剩余优化清单（按性价比）

P1 冷启动/游戏页回巴西：亚洲 platform-api 实例（B档）+ 游戏服务亚洲化（C档）
P2 CF Argo Smart Routing（付费）：回源省 100-200ms/请求
P3 launcher 服务端按 cf-ipcountry 直接定 host（去掉客户端测速）
P4 更多 GET 接口边缘缓存（game.list/配置类，短 TTL）
P5 前端：封面图 WebP/懒加载（5.5MB→1MB）、APP 弹窗可跳过
