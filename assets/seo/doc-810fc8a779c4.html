背景

香港项目静态资源已切到 AWS S3 + CloudFront，但客户端资源仍与巴西项目共用同一套源资源。巴西项目下午补资源后，香港 AWS S3 也需要同步跟进，避免 CloudFront 访问缺文件或目录入口 403。

本次目标：

  • 检查巴西侧 Google S3 / GCS 静态资源是否有新增或变化。
  • 将变化同步到香港 AWS 私有桶 bizops-h5-hk-517506432530。
  • 保持 vendor_b 复用 vendor_a 前端资源的特殊关系。
  • 同步完成后抽检 CloudFront 域名。

执行位置

  • 香港 Nginx 运维机：192.0.2.14
  • 同步工具：/usr/local/bin/bizops-sync-gcs-to-s3
  • AWS Profile：bizops-hk
  • AWS S3 桶：bizops-h5-hk-517506432530

执行命令：

AWS_PROFILE=bizops-hk bizops-sync-gcs-to-s3

说明：

  • 目标对象数包含额外同步的“目录入口对象”，因此工具使用 adjusted_destination_count 与源端对象数对齐校验。
  • 本轮实际有变化的重点是：
  • PG 系列目录入口对象补齐。
  • PANDA 目录入口对象补齐 51 个。
  • vendor_a2 目录入口对象补齐 3 个。
  • vendor_b 前端复用 vendor_a 资源，因此 vendor_a2 变化后已触发 vendor_b-static2 CloudFront 刷新。

CloudFront 刷新

本轮 vendor_a2 有 3 个目录入口变化，工具已自动创建 vendor_b static2 分配刷新：

marker_invalidation_created comment=某业务公司 HK vendor_b-static2 distribution=E38M63JF95BKAL paths=3

当前结论

本轮巴西 GCS 到香港 AWS S3 同步完成，所有配置内前缀均校验通过。PANDA 与 vendor_a2 的新增目录入口已经同步到 AWS，并可通过 CloudFront 访问。

vendor_b 当前仍以开发提供资源为准；开发确认缺资源的问题不在本轮继续处理，本轮只负责同步源端已经存在的资源。

说明：
