任务边界

用户要求：

确认备用流量入口服务器公网 IP 是否固定；
把宝塔上的 ben-bot 机器人迁移到备用服务器运行测试，机器人的各个功能都需要测试；
实现：宝塔服务器出故障时，机器人跑到备用流量入口服务器也能正常工作全部功能。
按标准工作流：workbench、逐步群通知、完成后验证、汇总文档发群、最后合并提交本地代码。

1. 公网 IP 确认（VERIFIED）

dbqp-saopaulo-nginx-standby-01 = 34.151.249.53
GCP 地址资源：dbqp-saopaulo-nginx-standby-01（southamerica-east1），status=IN_USE
实例 accessConfig：natIP=34.151.249.53，type=ONE_TO_ONE_NAT（静态地址，非临时 IP）
结论：公网 IP 已固定。

2. 迁移内容（宝塔 -> 备用机，内网传输）

仓库：/opt/pgserver（1.53GB，含 .git）rsync 到备用机同路径。
镜像：dbqp-ben-bot:latest（3.57GB）docker save -> ssh -> docker load。
运行时环境：宝塔容器 env 直传备用机 /opt/benbot-runtime.env（root 600，未落日志/仓库/群）。
数据目录：data/upload、data/scripts、known_chat_ids.json 随仓库同步。
SSH 密钥：/root/.ssh/id_ed25519 -> 备用机仓库 线上服务器信息/35.247.205.6_id_ed25519（root 600）。
gcloud 凭据：三个 SQLite 库 sqlite3 .backup + 配置文件 rsync 到备用机 /root/.config/gcloud。

3. 备用机部署

容器：dbqp-ben-bot-standby（镜像 dbqp-ben-bot:latest，restart unless-stopped）
挂载：/opt/pgserver、data/upload、data/scripts、/www/wwwroot、/www/server、/www/wwwlogs、/root/.config/gcloud
脚本：docker/ben-bot/run_standby_bot.sh（idle=待命不轮询 / poll=接管轮询，二选一）
待命模式：不轮询，避免与宝塔 bot 双轮询冲突（同 token 双轮询会 409）。

5. 切换演练（failover drill）

步骤：停宝塔 dbqp-ben-bot -> 备用机 run_standby_bot.sh poll -> 备用机 bot 轮询接管
结果：
  - 备用机 bot 启动轮询无 409 冲突，webhook 清理成功；
  - 启动通知已发送到监控报警群（chat_id=-5203304347）；
  - 切换演练完成后已切回：备用机恢复 idle 待命，宝塔 dbqp-ben-bot 重新启动并发送启动通知。
结论：宝塔故障时，机器人可切到备用入口机正常运行全部功能（发布/热更新/检查/信息/通知等）。
