目标背景：
1. 线上后端发布会替换 web 和 cron 容器。
2. 业务日志原来写在容器内 /var/www/html/youdianse-php/runtime/logs，容器替换后不方便保留和排查。
3. 改造后，web 和 cron 容器都把业务日志落到宿主机持久化目录。
4. Telegram 发布通知、健康通知、运行配置同步通知里要带业务日志路径，方便运维和开发上服务器查日志。
5. 日志目录达到 20G 时只发送 Telegram 提醒，不自动清理。

安全要求，必须严格遵守：
1. 不要在回复、日志、提交信息、文档或群消息里输出密码、Git token、Telegram bot token、私钥内容、证书私钥或含凭据的仓库 URL。
2. cicd-web/config/settings.json 和服务器运行环境可能包含敏感配置，只能描述“已配置/未配置”，不要复制具体值。
3. 检查 Docker 日志或 CICD 日志时，如果出现含账号凭据的 URL，必须脱敏后再汇报。
4. 不要把 runtime/app-logs、Docker json 日志、业务运行日志提交进 Git。
5. 不要回滚用户已有改动；修改前先看 git status。

已完成的核心改造：
1. .gitignore 忽略 runtime/，避免业务日志进仓库。
2. docker-compose.yml 给 web 和 cron 增加日志目录 bind mount：
   ${YOUDIANSE_APP_LOG_DIR:-./runtime/app-logs}:/var/www/html/youdianse-php/runtime/logs
3. cicd-web/config/settings.json 增加：
   paths.app_log_dir = runtime/app-logs
   defaults.app_log_alert_gb = 20
4. cicd-web/config.py 增加：
   APP_LOG_DIR
   APP_LOG_ALERT_GB
5. cicd-web/core.py 增加：
   APP_CONTAINER_LOG_DIR = /var/www/html/youdianse-php/runtime/logs
   prepare_app_runtime_logs...
   copy_app_logs_from_container...
   check_app_log_size...
   app_log_location_line...
6. 发布和 no-build 同步前会准备宿主机日志目录。
7. 第一次挂载前，如果旧容器日志还在容器内，会先复制到宿主机目录。
8. write_build_env 会写入 YOUDIANSE_APP_LOG_DIR=./runtime/app-logs。
9. Telegram 发布开始、成功、失败、健康检查、运行配置同步、详细日志 caption 中会追加业务日志路径。

20G 提醒处理 SOP

达到 APP_LOG_ALERT_GB 阈值时只提醒，不自动删除。

先看大文件：

cd /opt/docker-youdianse-php
du -sh runtime/app-logs
find runtime/app-logs -type f -printf '%s %TY-%Tm-%Td %p\n' | sort -nr | head -30

确认无排障价值后再清理，示例：

: > runtime/app-logs/queue/watchdog.log
find runtime/app-logs -type f -name '*.log' -mtime +30 -delete

清理前要确认业务是否仍需这些日志，避免影响问题追踪。

已知观察项

2026-07-06 手动发布后观察到业务运行期输出：

event_mqs not found, task_id=s
event_mqs not found, task_id=i
event_mqs not found, task_id=b

这不是日志持久化挂载失败。需要后端确认是否为业务队列任务的正常提示。

另一个维护项：

  • entrypoint/web-entrypoint.sh 和 entrypoint/cron-entrypoint.sh 会输出 YOUDIANSE_PHP_REPO_URL。
  • 如果运行环境里该变量含认证信息，Docker json 日志里可能出现敏感仓库 URL。
  • 后续应把 entrypoint 输出改成脱敏格式，只展示仓库域名/路径或 https://***@...。
  • 修改后需要重新构建并发布一次镜像；如果线上 Docker json 日志已经包含敏感内容，需要评估是否清理或轮转对应容器日志。

后续建议

  • 把客服 URL 等频繁变化配置逐步从 .env 迁到后台或安全配置中心。
  • 给 runtime/app-logs 增加更明确的人工清理 SOP。
  • 保持 ops/production/ 只记录可提交的脱敏运维信息。
  • 每次改 CICD 发布流程，都要重新做一次手动发布或 no-build 同步验证。
