背景与目标

  • 线上后端 ip-172-31-31-108 根盘 49G，长期处于 75%+，磁盘自动清理任务反复触发（业务日志约 8.8-8.9G）。
  • 运维已接入新盘 /dev/nvme1n1 500G（AWS EBS vol025fdec769bf703c5），本次将日志目录迁移到新盘，缓解根盘压力。
  • 方案：/data 独立挂载 + /data/docker-youdianse-php/app-logs bind 回原 runtime/app-logs。容器、CICD 与日志脚本路径保持不变，无需重建镜像，风险最小。

服务器与磁盘信息

主机：ip-172-31-31-108（线上后端）
公网：16.209.16.108；内网：203.0.113.1；用户：ubuntu（sudo）
系统：Ubuntu 22.04.5 LTS
新盘：/dev/nvme1n1 500G，AWS EBS vol025fdec769bf703c5
根盘：/dev/nvme0n1p1 49.9G ext4（/）
业务日志：/opt/docker-youdianse-php/runtime/app-logs（挂载前 8.9G，27 个文件）

执行步骤

1. 准备与只读核验

读取仓库历史文档与 workbench，确认本仓库 main 对应游点涩线上正式环境；核对线上 Telegram 配置目标群为 18GAME_ 上线群（正式環境）。SSH 只读核验 hostname、lsblk、df、fstab、容器状态、日志目录与 CICD 运行配置。

2. 新盘分区、格式化与挂载 /data

# 备份 fstab
sudo cp -a /etc/fstab /root/fstab.before-youdianse-data-mount.20260810-143258

# GPT 分区 + 格式化（仅对 nvme1n1，未触碰根盘 nvme0n1）
sudo parted -s /dev/nvme1n1 mklabel gpt
sudo parted -s /dev/nvme1n1 mkpart primary ext4 1MiB 100%
sudo partprobe /dev/nvme1n1
sudo mkfs.ext4 -L youdianse-data /dev/nvme1n1p1

# fstab 追加（nofail，启动失败不阻塞）
# UUID=10bef820-20fa-464c-a943-c45a3e5c82d2 /data ext4 defaults,nofail 0 2
sudo mkdir -p /data
sudo mount -a

3. 日志迁移与 bind 挂载

sudo mkdir -p /data/docker-youdianse-php

# 全量复制日志到新盘，并核对大小/文件数
sudo rsync -a /opt/docker-youdianse-php/runtime/app-logs/ /data/docker-youdianse-php/app-logs/

# 原目录改名保留（根盘回滚点），新建空目录后 bind 挂载新盘目录
sudo mv /opt/docker-youdianse-php/runtime/app-logs /opt/docker-youdianse-php/runtime/app-logs.rootfs.20260810-143605
sudo mkdir -p /opt/docker-youdianse-php/runtime/app-logs
sudo mount --bind /data/docker-youdianse-php/app-logs /opt/docker-youdianse-php/runtime/app-logs

# fstab 追加 bind 行（依赖 /data 先挂载）
# /data/docker-youdianse-php/app-logs /opt/docker-youdianse-php/runtime/app-logs none bind,nofail,x-systemd.requires-mounts-for=/data 0 0
sudo findmnt --verify --verbose /etc/fstab

4. 容器重启与运行验证

cd /opt/docker-youdianse-php
sudo docker compose --env-file .ops-build.env --profile cron restart web nginx cron

重启目的：让 web/nginx/cron 容器内已打开的日志句柄全部重新解析到新盘。

5. 旧日志清理与根盘释放

清理前把根盘旧目录（含迁移窗口新增日志）增量合并到新盘，确认副本完整后删除旧目录：

sudo rsync -a /opt/docker-youdianse-php/runtime/app-logs.rootfs.20260810-143605/ /data/docker-youdianse-php/app-logs/
sudo rm -rf /opt/docker-youdianse-php/runtime/app-logs.rootfs.20260810-143605

当前挂载与 fstab

/dev/nvme1n1p1 ext4 -> /data（UUID=10bef820-20fa-464c-a943-c45a3e5c82d2，defaults,nofail 0 2）
/data/docker-youdianse-php/app-logs -> /opt/docker-youdianse-php/runtime/app-logs（bind,nofail,x-systemd.requires-mounts-for=/data 0 0）

验证结果

挂载：findmnt /data 与 runtime/app-logs 均指向 /dev/nvme1n1p1，写入测试设备号一致
fstab：findmnt --verify Success, no errors or warnings detected
副本：迁移前 8.9G/27 文件，清理前增量合并后新盘 8.9G/29 文件
容器：web/nginx/cron 全部 Up，php-fpm -tt 通过
HTTP：本地后台 200，本地 CICD 200
落盘：容器内写测试文件出现在 /data/docker-youdianse-php/app-logs，设备号一致
句柄：容器重启后旧目录已无进程占用（lsof +D = 0）
根盘：49G 已用 77% -> 59%（可用 21G）
数据盘：492G，已用 8.9G，使用率 2%

回滚

1. 恢复 fstab：从 /root/fstab.before-youdianse-data-mount.20260810-143258 恢复，
   或删除新增的两行 fstab 记录。
2. sudo umount /opt/docker-youdianse-php/runtime/app-logs
3. sudo umount /data
4. 日志恢复：根盘原目录已清理，恢复副本位于 /data/docker-youdianse-php/app-logs；
   如需日志留在根盘，rsync 回根盘目录后移除 bind 挂载即可。

后续事项

  • 观察根盘使用率与磁盘自动清理任务（触发条件：根盘 >=75% 或业务日志 >=20G），预计不再频繁触发。
  • S3 写权限 403 为历史待办，与本次挂载无关，仍待修复。
  • 日志小时轮转、S3 三天保留、磁盘自动清理脚本路径均保持 runtime/app-logs 不变，bind 挂载后自动落到新盘。
