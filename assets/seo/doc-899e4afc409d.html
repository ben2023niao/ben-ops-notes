二、发现的重点问题

1. GitLab 容器日志 123.3 GB（最大单点）

/var/lib/docker/containers/8b0feb…/8b0feb…-json.log   → 124 GB

已截断，并写入 Docker 日志轮转配置：

{ "log-driver": "json-file", "log-opts": { "max-size": "100m", "max-file": "3" } }

该配置对现有容器需重启 Docker 才生效（GitLab 会中断 1~2 分钟），建议低峰执行；已备份原 /etc/docker/daemon.json。

2. 后端与网关的构建缓存长期不清理

后端 6.07 GB、网关 8.58 GB、前端 9.62 GB 的 build cache——发布频繁的机器应定期 docker builder prune。

三、未能清理的主机（需要人工介入）

主机 水位 原因
msb-Mongo文件 139.162.56.98 67.8% 无 SSH 通道（不在我们的密钥清单）
测试 H5 38.92.8.34 59.2% 无 SSH 通道
打包机 154.95.24.45 55.2% 无 SSH 通道
宝塔 16.208.5.147 37% SSH 可登录但 sudo 需要密码，无法清理
msb 其余、SPJ 三台、短剧、RAK 1.3%~35% 无 SSH 通道（水位不高，暂不紧急）

需要运维提供：上述主机的 SSH 入口（或堡垒机账号）与宝塔的 sudo 权限；拿到后按同一脚本清理。

四、清理脚本

# 通用清理（保守策略，只清日志轮转/包缓存/悬空镜像/构建缓存/旧临时文件）
sudo bash /tmp/disk_clean.sh

脚本要点： - journalctl --vacuum-time=7d - docker container/image/builder prune -f（不动数据卷、不动运行中容器） - apt-get clean / yum clean all / dnf clean all - /var/log 下 .gz/.old/.N 且 >14 天的文件 - /tmp 下 >14 天的普通文件（不删目录）
