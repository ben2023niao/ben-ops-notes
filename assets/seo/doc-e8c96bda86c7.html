背景

开发反馈：08-16 的订单及其他上报集中在凌晨 4 点和中午 12 点左右丢失 te.log 数据； 用户要求排查原因，并确认是否存在服务器清理操作。运维侧确认无定时清理 （磁盘清理阈值 500G 的 70%，当前未触发）。

排查结论速览

1. 08-16 04:00-04:59 与 12:00-12:59 的 te.log 小时文件异常小（0.34MB / 0.56MB，
   其它小时 3-15MB），且只包含 game_first_enter，其余事件全部缺失。
2. 缺口与外部 cron 整点批量任务并发窗口强相关：
   04:00:03 / 12:00:02-03 同时并发 10+ 个 docker exec 批量任务，
   gameNotify 每分钟执行一次。
3. 批量任务触发的 BigData Job 在 big_data_* 日志中全部成功，但对应事件未写入 te.log。
4. 排除项：无容器重启、无 CICD 发布、无磁盘清理、logbus2 消费正常、
   文件属主正常（www-data）、整点并发每天都有但只有 08-16 缺失。

2. 订单级验证

  te.log 03_0 / 04_0 / 05_0：均未命中
结论：Job 执行成功但 SDK 写入 te.log 丢失。

4. 排除项

1) 容器重启：web/cron 08-19 14:23 才重启，08-16 无重启；
2) 发布：cicd-web/logs 08-16 无发布日志；
3) 清理：磁盘清理 08-16 无 te.log 删除记录（且 app_logs 未到 100G 阈值）；
4) logbus2：offset.json 显示 04_0/12_0 已完整消费（End == 文件大小）；
5) 文件属主：08-16 所有 te.log 均为 www-data:www-data 0644，非权限问题；
6) 整点并发：08-15/16/17 04:00:00-30 均为 12 个 docker exec，只有 08-16 缺失。

根因判断

08-16 04/12 缺口与整点批量任务并发窗口强相关：外部 cron 在整点并发拉起大量
docker exec CLI 进程，这些进程触发的 BigData Job 在 big_data 日志中成功，
但 SDK（TDFileConsumer，旧版 bufferSize=100）写 te.log 未落盘。
最可能机制：高并发下 SDK 文件写盘静默失败（flock/fwrite 失败不抛错），
或容器内写入未及时同步到宿主（“docker 同步日志到外部”的固有风险）。
由于属主/权限/消费均正常，且该问题仅 08-16 出现，判断为并发写窗口 + 缓冲丢失的偶发组合。

加固建议

1) 已落地待审核（业务 efaa33d9）：
   TDFileConsumer bufferSize=1（每条事件立即落盘）——消除缓冲丢失；
   TDAnalytics enableUUID=true（#uuid 去重）；
   Recharge/Spend #time 兜底 + 业务 #uuid。
2) 整点错峰：把 04:00/12:00 批量任务延迟到 04:10/12:10 后启动，
   避开整点文件切换与并发窗口（外部 cron 侧调整）。
3) te.log 小时健康检查：每小时结束时检查当前小时文件大小，明显偏小即告警。
4) 对账告警：big_data_* 每小时 Job 数 vs te.log 事件数对账，偏差超阈值告警。
5) 根治方向（开发侧）：大数据上报改队列串行写入 te.log，避免并发争写。
