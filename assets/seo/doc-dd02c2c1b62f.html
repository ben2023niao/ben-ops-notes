vendor_a/static_res 410M 15753 文件

可操作优化

项 说明 优先级 状态
PNG → WebP/AVIF 4995 张 PNG 批量转 WebP（可省 60-80% 体积），重同步 GCS 桶 P1 待做

二、服务器（宝塔/备用机/后端）

已做/已验证

nginx：worker auto、connections 51200、sendfile/tcp_nopush/tcp_nodelay on、
       keepalive 300s/10000、proxy_cache static_cache（静态）、/shared/ 边缘缓存
sysctl：tcp_tw_reuse=2、fin_timeout=60、somaxconn=4096
资源：宝塔 mem 6.4Gi 可用、磁盘 66%（有清理 cron）

本轮修复

  1. 宝塔 gzip_types 去掉 image/*（图片已压缩，不再白耗 CPU）；
  2. 备用机 nginx 此前完全未开 gzip，已补（level 5、文本类型），实测 content-encoding: gzip。

建议（P3）

- sysctl net.ipv4.tcp_max_syn_backlog 512 -> 2048、net.core.netdev_max_backlog 提升（高并发峰值）
- 后端容器资源定期巡检（docker stats）

三、后端（platform-api / 游戏后端）

已做：launcher P0-1 测速优化、keepalive、动态接口 gzip、/shared/ 缓存
建议：
  P1 launcher 模板 P0-2 边缘缓存（launcher.html 静态化 + ticket 小接口，省 0.3-0.6s）
  P2 接口短 TTL 缓存（game.list 等 GET 配置类）
  P2 DB/Redis 连接池与慢查询专项

四、CDN / 域名

已做（CF）：HTTP3/0-RTT 42 zone、Argo 3 套、CacheRule（静态 HTML 全缓存）、
          Brotli、Early Hints、nginx 源站缓存、GCS 缓存头
建议：
  P1 CF Polish 开启（3 套 Pro，图片自动优化，提示词已发）
  P2 更多 GET 接口边缘缓存（短 TTL）
  P2 域名精简（game_hosts 已 3 套）；t6qv8m/q7m9v8 Argo 待重试
  P3 HSTS 已开；Tiered Cache 需 Enterprise（不采用）

五、优先执行建议

1. CF Polish（Agent Lee，已发提示词）——图片优化立竿见影，零改动
2. 前端 PNG → WebP 批量转换（P1，需生成脚本 + 同步 GCS）
3. sysctl syn_backlog 提升（P3，低风险）
4. launcher P0-2 边缘缓存（P1，后端代码）

六、本次变更

  • 宝塔/备用机 nginx：gzip_types 修正 + 备用机补 gzip（服务器侧，备份 .bak-20260829-gzip）；
  • 本记录文档（提交）。

七、CF Polish 开启提示词（2026-08-29 补充，供 Agent Lee 执行）

请对我的 Cloudflare 账户（[邮箱已脱敏]）在以下 3 个 Pro zone 开启 Polish 图片优化：
xqv9m8.icu
vendor_a-cdn-2026.icu
cdn-tokyo-bizops.icu

执行步骤：
1. 对每个 zone 用 API 开启 Polish：
   PUT /zones/{zone_id}/settings/polish，body：{"value":"lossy"}
   （如希望无损质量优先可改 lossless；游戏素材推荐 lossy，体积更小、肉眼差异小）
2. 对每个 zone 开启 WebP：
   PUT /zones/{zone_id}/settings/webp，body：{"value":"on"}
3. 逐个 GET 验证：
   GET /zones/{zone_id}/settings/polish 和 /settings/webp
4. 开启后为 3 个 zone 各执行一次全站缓存清理：
   POST /zones/{zone_id}/purge_cache，body：{"purge_everything":true}
   让图片优化立即生效（如果担心全站清理，可改为只清图片路径或等缓存自然过期，TTL 1天）
5. 不要动 DNS、SSL/TLS、Page Rule、Cache Rule、其他任何设置

输出：zone 名 | Polish | WebP | 缓存清理结果

说明：Polish 只对经 CF 缓存且为图片的请求生效；静态子域已开 Cache Everything，满足条件。

Polish 执行状态（2026-08-29 补充）

Agent Lee API 权限已移除；我方 DNS token 缺 Zone Settings/Cache Purge 权限 （实测 polish/webp/purge 均 Authentication error/Unauthorized）。 待用户选择：

A. 面板手动（3 zone：速度→优化→Polish=Lossy + WebP=开；缓存→配置→Purge Everything）
B. 新建 API Token（Zone Settings Edit + Cache Purge Edit，范围 3 zone），贴给我执行

完成后验证：抓静态图确认 Content-Type: image/webp + 体积对比。

Polish 验证结果（2026-08-29 完成）

3 zone（xqv9m8 / vendor_a-cdn-2026 / cdn-tokyo-bizops）Polish=lossy + WebP=on，已清缓存
实测（真实 URL，无参数）：
  小图 20067B PNG -> 11442B WebP（省 43%）
  大图 82942B PNG -> 45454B WebP（省 45%）
  cf-polished: ok, orig_size=xxxx；不支持的浏览器自动回退 png
收益：静态图片体积平均省 40-50%
