2. Job API

POST /api/jobs
{
  "recipe": "deploy-br-canary",
  "version": "20261029-ben",
  "vendors": ["api", "pg"],
  "dry_run": false
}

服务端返回：

{"job_id":"...","status":"queued"}

客户端订阅：

WS /api/jobs/{job_id}/events?after_seq=0

打包源校验接口：

GET /api/build-info

服务端通过固定白名单目标登录 03，读取 share.so、巴西 version-bx 和香港 version-zh 的 MD5、大小与修改时间。浏览器不能提交路径或目标主机。

Worker 代码查看和任务复盘接口：

GET /api/worker-files
GET /api/worker-file?key=latest/worker.js
GET /api/worker-file?key=history/cloudflare/<backup>.js
GET /api/jobs/{job_id}/export

Worker 文件只从镜像内固定备份目录读取；任务导出包含完整命令、事件序号、 stdout/stderr、时间戳和退出码。

香港 CDN 缓存清理接口：

POST /api/cdn/purge
{
  "providers": ["edgeone", "cloudflare"],
  "vendors": ["pg", "tada", "pp"],
  "dry_run": false
}
  • 浏览器只能提交 provider、vendor 和 dry-run，不能提交任意 host/zone/URL；
  • EdgeOne 站点、Cloudflare zone、厂家到静态前缀的映射全部固定在服务端；
  • EdgeOne 使用 CreatePurgeTask(Type=purge_host, Method=invalidate)；
  • Cloudflare Worker 自定义缓存只能整 zone purge_everything；
  • 腾讯云 SecretId/SecretKey 和 Cloudflare Token 只从容器 Secret 文件读取；
  • 任务复用现有 jobs/job_events，页面实时显示 JobId、失败列表和退出码。

3. 新增厂家

  1. 在服务端 VENDORS 白名单增加厂家；
  2. 增加容器名、端口和镜像映射；
  3. 增加 pull、start、image ID 和 health 校验；
  4. 更新前端厂家选择；
  5. 增加 dry-run 和失败测试；
  6. 更新交付文档。

4. 新增后端

  1. 在 backend-targets.example.json 增加节点；
  2. 确认是否属于金丝雀或批量组；
  3. 检查 Nginx 活跃后端数量；
  4. 加入内网连通和端口测试；
  5. 加入 Beszel 与 RestartCount 监控。

5. 新增 Recipe

  • Recipe 必须声明允许的角色；
  • 必须声明是否 dry-run；
  • 必须声明超时和取消行为；
  • 必须返回结构化阶段和检查；
  • 不得接受浏览器原始 Shell；
  • 失败时说明是否允许继续下一阶段；
  • 写操作必须有审计和二次确认。

6. 状态机门禁

服务端必须保存：

br_canary_passed
br_bulk_unlocked
hk_canary_passed
hk_bulk_unlocked

前端勾选不能替代服务端状态。

7. 测试

最低覆盖：

  • 鉴权失败；
  • 任意 Shell 请求被拒；
  • 01 未通过时批量被拒；
  • 单主机失败后停止后续；
  • WebSocket 断线续传；
  • 日志脱敏；
  • 任务锁；
  • 巴西/香港区域并行，同区域和全局任务互斥；
  • 取消；
  • 容器重启后历史查询；
  • dry-run 不产生写操作。

8. 发布

  • 使用独立镜像版本；
  • 记录 commit SHA 和镜像 digest；
  • 先在只读模式验证；
  • 再灰度开放 operator；
  • 最后开放正式发布。
