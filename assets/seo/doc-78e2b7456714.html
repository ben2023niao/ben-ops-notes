执行范围：bizops-ops-console、03 打包机、运维发布页状态恢复逻辑。

一、问题

用户点击“一键准备”后任务 85546b26e1644f24 在拉代码后失败：

Updating e1af715a..9f59b4f3
share.so MD5: 989c90d5772fc6bcc0356756a7126bc8
❌ /data/pgserver/sync_results.sh 不可执行
执行结束，退出码 1

03 当前脚本权限：

-rw-r--r-- root root /data/pgserver/sync_results.sh

该脚本一直由 sh sync_results.sh all 调用，不需要可执行位。发布页却先做 test -x，因此出现误判。

服务器状态同时显示六台全部失败，原因是内部并发验证任务也写入了 job 日志， 页面恢复状态时把这些测试任务的失败状态套到了正式服务器。

二、修复

2.1 结果集脚本门禁

test -f sync_results.sh
test -r sync_results.sh
sh sync_results.sh all

不再要求可执行位。03 实测 sh -n sync_results.sh 通过。

2.2 失败后刷新 MD5

准备/拉代码任务无论成功失败，页面结束后都会重新调用 /api/build-info。 因此拉代码后即使后续步骤失败，也会刷新最新 MD5：

HEAD：9f59b4f3
share.so：989c90d5772fc6bcc0356756a7126bc8

2.3 源文件绝对路径

/api/build-info 页面展示改为 MD5 + 绝对路径：

989c90d5772fc6bcc0356756a7126bc8  /data/pgserver/share.so
48dd8cd59d364b2e22d460c331c697fe  /data/pgserver/version-bx/server_configs
9332e4ea4c3cdc5eb64e2a0c7d8d23a6  /data/pgserver/version-bx/version.json
b470633efcb472419a3e57456fc847ba  /data/pgserver/version-zh/server_configs
0129deedee195b963df3008ae774034f  /data/pgserver/version-zh/version.json
3b576ac97f6bb4c5aa7e6772354af0b0  /data/server-runtime-hk/conf/configs-api.py

2.4 服务器状态恢复

  • 恢复任务状态时忽略标签含“测试”“并发控制验证”“同区域互斥验证”的内部任务；
  • 状态文案由英文 passed/failed 改为“成功/失败/执行中/排队”；
  • 真实正式发布仍覆盖对应区域；最近真实准备任务失败仍正确显示打包机 03 失败。

回归结果：

巴西 01/02/04/05：成功
香港 01/02：成功
打包机 03：失败（对应本次真实准备任务失败）

包含 test -f、test -r、sh sync_results.sh all
03 上 sync_results.sh 可读，sh -n 通过
r6 容器 running / healthy
无运行中任务
