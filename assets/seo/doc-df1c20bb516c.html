1. 这次要解决什么

把新的备案域名 hbazuua.cn 也接入测试环境，先做三条测试域名：

  • test-img.hbazuua.cn：后端 uploads 图片反代域名
  • test-pc.hbazuua.cn：测试 PC 页面入口
  • test-h5.hbazuua.cn：测试 H5 页面入口

目标是让 hbazuua.cn 和已有的 hbabaxb.cn 都能作为测试备案域名使用。后续图片加载可以做成多域名候选：谁快用谁；两个腾讯备案图片域名都不可用时，再回退到 AWS CloudFront 老图片地址。

2. 当前已经接入的域名关系

2.1 图片域名

已有域名：

https://test-img.hbabaxb.cn

新增域名：

https://test-img.hbazuua.cn

两者作用一致：

用户浏览器
-> 腾讯 EdgeOne
-> 测试服务器 38.92.8.34 Nginx
-> AWS CloudFront d1rct3ku9n07y3.cloudfront.net/uploads/*
-> AWS S3 后端上传图片

说明：

  • 后端上传仍然写 AWS S3，不改上传流程。
  • test-img.* 只是展示域名和反代入口。
  • 裸 uploads 图片 URL 不返回原图，Nginx 直接返回默认占位图。
  • 带 token/t 的 uploads 图片 URL 才返回原图。

  • signCdnUrlIfNeeded() 只处理 env 配置命中的 host 和 path prefix。
  • 当前只处理 test-img.hbabaxb.cn、test-img.hbazuua.cn 的 /uploads/*。
  • 其他绝对 URL 原样返回，包括 AWS CloudFront。

  • 不改 AWS S3。
  • 不改前端打包静态资源。

8. “谁快用谁 + AWS 兜底”的推荐做法

浏览器不会自动在两个图片域名之间赛跑。后端返回一个字符串 URL 时，浏览器只会请求这一个 URL。

要实现“谁快用谁”，需要前端图片组件或统一图片加载工具做候选列表。

推荐顺序：

1. https://test-img.hbabaxb.cn/uploads/xxx?敏感凭据：[已脱敏]
2. https://test-img.hbazuua.cn/uploads/xxx?敏感凭据：[已脱敏]
3. https://d1rct3ku9n07y3.cloudfront.net/uploads/xxx

注意：

  • 前两个腾讯备案域名走防盗刷签名。
  • AWS CloudFront 作为最后兜底，不加密。
  • token 当前只按 path 和时间计算，不按 host 计算；同一张图可以把 host 替换成另一个 test-img 域名复用同一组 token/t。
  • 不建议每张图都无脑并发请求两个腾讯域名，会把流量翻倍。

更稳的实现：

  1. 页面初始化时分别请求两个 test-img 域名的轻量探测文件或同一张小占位图。
  2. 记录哪个域名更快。
  3. 本页图片默认使用更快的域名。
  4. 单张图片加载失败时，再切到另一个腾讯域名。
  5. 两个腾讯域名都失败，最后切 AWS CloudFront。

这样既能做到“用户面前谁快用谁”，又不会把每张图请求都翻倍。

9.1 回滚 DNSPod 解析

删除或暂停：

在 EdgeOne hbazuua.cn 站点里停用或删除：

test-pc.hbazuua.cn
test-h5.hbazuua.cn

9.3 回滚 Nginx

10. 后续待办

  • 等 EdgeOne 免费证书状态从 applying 变成完成状态后，再做一次无 -k 的 HTTPS 严格校验。
  • 如果证书校验长期失败，先复查 _dnsauth CNAME 是否仍在，再重新执行 CheckFreeCertificateVerification。
  • 补齐 H5 vhost 本地模板，避免后续发布覆盖掉 test-h5.hbazuua.cn。
  • 前端如果要实现真正“谁快用谁”，需要做统一图片加载候选逻辑；只配 DNS/CDN 无法让浏览器自动在多域名之间择优。
  • 后端如果要直接返回 hbazuua，可以把 cdn_image 主展示域名切过去；当前没有切，避免影响现有 hbabaxb 链路。
