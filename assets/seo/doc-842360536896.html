需求合理性判断

需求合理，可以基于现有容器日志链路完成，不需要引入额外 Agent：

Python stdout/stderr
  -> Docker json-file
  -> 宿主机 /opt/pgserver/logs/<container>/*.log
  -> logrotate hourly + gzip
  -> aws s3 sync / s3api 校验
  -> AWS S3
  -> ben-bot 日志排查按钮

现有发布脚本已经把各游戏厂家容器的业务日志写到宿主机 /opt/pgserver/logs，本次改造不改业务代码输出方式，只补齐宿主机小时轮转、归档、清理和机器人查询入口。

S3 归档设计

S3 使用专用 bucket：

  • Bucket：dbqp-backend-game-logs-176528004422
  • Region：ap-northeast-3
  • Prefix：backend-game-logs
  • AWS Account：176528004422

对象路径：

backend-game-logs/<hostname>/<vendor>/<yyyy>/<mm>/<dd>/<hour>/<file>.gz

示例：

backend-game-logs/dbqp-saopaulo-sanic-prod-02/playson/2026/07/15/07/playson.log-20260715-072347.gz

说明：

  • 创建 bucket 权限曾返回 s3:CreateBucket AccessDenied，后续确认专用 bucket 已存在且可读写。
  • 后端与宝塔均使用 /etc/dbqp-game-log-s3.env 管理 S3 归档配置，权限 600 root:root。
  • S3 30 天外清理由宝塔 dbqp-log-s3-cleanup.timer 每日执行，不依赖 Dozzle 或 Agent。

后端部署内容

两台后端均已部署：

/usr/local/bin/dbqp_game_log_archive.py
/etc/dbqp-game-log-s3.env
/etc/dbqp-logrotate/pgserver
/etc/systemd/system/dbqp-log-maintenance.service
/etc/systemd/system/dbqp-log-maintenance.timer

logrotate 关键配置：

/opt/pgserver/logs/*/*.log {
    su root root
    hourly
    rotate 200
    maxage 7
    maxsize 1G
    missingok
    notifempty
    compress
    copytruncate
    dateext
    dateformat -%Y%m%d-%H%M%S
}

维护服务执行顺序：

logrotate /etc/dbqp-logrotate/pgserver
logrotate /etc/dbqp-logrotate/docker-json-existing
journalctl --vacuum-time=7d
journalctl --vacuum-size=1G
/usr/local/bin/dbqp_game_log_archive.py upload-old

归档行为：

  • 当前 .log 留在宿主机继续写入。
  • 每小时切出 *.log-YYYYMMDD-HHMMSS.gz。
  • 7 天内 .gz 保留在宿主机。
  • 7 天外 .gz 上传到 S3。
  • 上传后执行 S3 head-object 校验对象大小，校验成功才删除本地旧 .gz。

S3 清理

宝塔已部署：

/usr/local/bin/dbqp_game_log_archive.py
/etc/dbqp-game-log-s3.env
/etc/systemd/system/dbqp-log-s3-cleanup.service
/etc/systemd/system/dbqp-log-s3-cleanup.timer

Timer：

OnCalendar=*-*-* 03:35:00
RandomizedDelaySec=10m
Persistent=true

清理行为：

  • 每日扫描 s3://dbqp-backend-game-logs-176528004422/backend-game-logs/
  • 删除 S3 LastModified 超过 30 天的对象。
  • 本次 dry-run 扫描到 12 个对象，删除 0 个。

ben-bot 日志排查

新增入口：

/start
  -> 日志排查快捷厂家按钮

/start
  -> 检查诊断
  -> 日志排查

支持厂家：

PG / TADA / TADA-WS2 / PP / PPK / PANDA / PLAYSON / platform-api

按钮行为：

  • 点击厂家后，机器人合并读取 prod-01、prod-02 的日志列表。
  • 列表包含两种来源：
  • [7天内]：服务器本地小时 .gz
  • [S3]：S3 历史小时 .gz
  • 支持按月份筛选、上一页/下一页翻页。
  • 点击 [7天内] 项：机器人通过内网 SSH + SFTP 拉取 .gz，发送到当前飞机群。
  • 点击 [S3] 项：机器人通过后端服务器生成 7 天有效的 S3 presigned URL，发送“打开下载链接”按钮到当前飞机群。
  • 对直接发送的附件，如果超过 45MB，自动切成 .partNN 分片发送。

本次机器人验证：

  • 容器内插件语法检查通过。
  • 插件注册表已加载 日志排查。
  • prod-01 本地 PLAYSON 列表读取成功，找到 8 个小时 .gz。
  • prod-02 S3 PLAYSON 历史列表读取成功，找到 1 个小时 .gz。
  • S3 PLAYSON 历史包曾做实际发送验证：49,788,072 字节，自动切成 2 片发送到飞机群。

注意事项

  • Dozzle / Dozzle Agent 未安装。
  • docker/ben-bot/data/upload/* 是机器人运行缓存和日志，不纳入代码提交。
