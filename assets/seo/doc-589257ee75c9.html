任务边界

用户要求：

机器人日志查看按钮里面目前只有老的 2 台后端日志，把新加入的后端日志也加入进来；
宝塔服务器上把机器人相关的东西起来；
后续机器人都部署到备用 nginx 服务器上。
按标准工作流：workbench、逐步群通知、完成后验证、汇总文档发群、最后合并提交本地代码。

一、排查结论

01/02：日志维护定时器 bizops-log-maintenance.timer enabled+active，今日仍在运行（小时轮转 + S3 归档）。
03：缺少整套日志维护栈（/usr/local/bin/bizops_game_log_archive.py、/etc/bizops-game-log-s3.env、
    /etc/bizops-logrotate/*、systemd service/timer），日志从不轮转（只有 pg.log，无 .gz）。
日志查看代码（日志排查/action.py）SERVERS 已含 p3（192.0.2.1），问题仅在 03 无轮转产物。

二、修复

1. 03 部署日志维护栈（从 01 复制，凭据 root 600 不落日志）：
   - /usr/local/bin/bizops_game_log_archive.py
   - /etc/bizops-game-log-s3.env
   - /etc/bizops-logrotate/pgserver、pgserver-hourly、docker-json-existing
   - /etc/systemd/system/bizops-log-maintenance.service、bizops-log-maintenance.timer
   - systemctl enable --now bizops-log-maintenance.timer；强制轮转生成 8 个厂家 .gz。
2. 宝塔 bot 重建为备用空闲实例：
   - 从停止容器导出环境到 /opt/benbot-runtime.env（root 600）；
   - run_standby_bot.sh 身份变量支持覆盖；宝塔以 CONTAINER_NAME=bizops-ben-bot idle 运行；
   - 身份标识：宝塔备用实例（空闲）/ bizops-saopaulo-game-results-data-bt / 192.0.2.8 / 192.0.2.1。
3. 文档更新：机器人架构图、交接总览（活动实例=备用机、宝塔=备用空闲、部署原则=备用 nginx 服务器）。

三、验证

日志按钮真实列表（备用机 bot 逻辑）：pg 共 411 项，servers=['p1','p2','p3']，03 已有 pg.log-20260807-123346.gz —— 通过；
03 定时器 active，8 个厂家 .gz 已生成；
双实例：备用机 bot poll（活动）、宝塔 bot idle（备用空闲），无 409 冲突；
/start 标识：备用实例（192.0.2.13）活动 / 宝塔备用实例（空闲）；
机器人架构图更新后渲染正常。

最后安全点 / 遗留事项

当前 master：eebbdd3a（本地 = origin/master；本次文档提交后更新）。
活动 bot：备用机 bizops-ben-bot-standby（poll）；宝塔 bizops-ben-bot 备用空闲（idle）。
日志查看覆盖 prod-01/02/03；03 日志栈已启用小时轮转 + S3 归档。
部署原则：后续机器人统一部署到备用 nginx 服务器。
遗留：
  - 03 首个轮转由强制触发，后续按小时定时轮转。
  - 宝塔 bot 为 idle，切回活动需先停备用机 poll（同 token 禁止双轮询）。
  - 本地工作区 docker/services 端口目标态改动仍未提交（待单独维护窗口）。
