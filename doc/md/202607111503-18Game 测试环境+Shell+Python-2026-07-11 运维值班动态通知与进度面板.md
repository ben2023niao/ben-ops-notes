# 2026-07-11 运维值班动态通知与进度面板

> 来源文件：`~/Desktop/18game_devops/devops/python/ben-bot/doc/2026-07-11_1503-【优化+运维记录】运维值班动态通知与进度面板.md`

> 整理日期：2026-07-11 15:03｜日期依据：文件名日期

环境标签：通用

## 1. 背景与目标

原运维值班表使用整月日历按钮，日期、班次、规则和人员信息重复展示，在手机端不易快速判断“现在谁在岗”。经过多轮界面验证，最终将功能收敛为一个面向当天的动态值班面板。

本次改造目标：

- 默认只展示今天，不在首屏堆叠整周信息。
- 每人工作时长固定为 8 小时。
- 未上班显示空进度条，在岗显示实时进度和剩余时间，完成 8 小时后显示已下班。
- 点击值班人员姓名可直接打开 Telegram 私聊。
- 值班面板每 60 秒原位编辑，不通过新消息刷屏。
- 在上班、下班和交接节点自动广播完整值班状态。
- 机器人部署和重启通知复用同一套实时进度面板。

## 2. 最终班次模型

| 班次 | 时间 | 人员 | 工作时长 | 主要职责 |
|---|---|---|---:|---|
| 早班 | 14:00—22:00 | Ben、Jett、Kermit | 8 小时 | 发布、数据库变更、带教、升级支援 |
| 晚班 | 17:00—01:00 | Melo、Davie | 8 小时 | 参与发布和变更，22:00 后继续监控值守 |

每周星期日全员休息，当天无早班、晚班和交接安排。星期日面板只显示休息状态，不计算个人进度。

关键时段：

- 17:00—22:00：早晚班重合，共同处理发布、数据库变更和新人带教。
- 22:00—01:00：晚班接管监控，故障可升级给早班人员。
- 晚班跨越自然日，进度计算已对 00:00—01:00 做跨日处理。

## 3. 用户界面

打开“运维值班表”后，机器人展示当天进度：

```text
🖥 今日运维值班 · 2026-07-11 16:23:29

🌤 早班 14:00—22:00
Ben     ██░░░░░░   30%  在岗 · 剩余 5:37
Jett    ██░░░░░░   30%  在岗 · 剩余 5:37
Kermit  ██░░░░░░   30%  在岗 · 剩余 5:37

🌙 晚班 17:00—01:00
Melo    ░░░░░░░░    0%  未上班 · 17:00
Davie   ░░░░░░░░    0%  未上班 · 17:00
```

实际 Telegram 消息使用 HTML 富文本：

- 姓名使用 `https://t.me/<username>` 链接。
- 进度条使用 `<code>` 等宽样式。
- 状态、百分比和剩余时间使用普通文本，保持手机端可读性。
- 颜色由 Telegram 客户端主题控制，机器人无法强制指定暗色背景。

## 4. 进度计算规则

进度宽度为 8 格，对应 8 个工作小时。

### 4.1 未上班

```text
Melo    ░░░░░░░░    0%  未上班 · 17:00
```

### 4.2 在岗

使用当前时间减去班次开始时间，再除以 480 分钟：

```text
ratio = (current_minutes - shift_start) / 480
```

显示内容包括：

- 已消耗进度格。
- 已完成百分比。
- 距离下班的剩余时间。

### 4.3 已下班

```text
Ben     ████████  100%  已下班
```

进度条不再增长，固定为 100%。

## 5. 动态刷新机制

动态刷新参考 CICD 发布进度的“编辑原消息”方式：

1. 用户打开值班表。
2. `benbot_plugin.py` 编辑当前菜单消息为值班面板。
3. 将 `(chat_id, message_id)` 登记到进程内存集合。
4. `duty:live_refresh` 每 60 秒运行一次。
5. 重新计算当前时间、进度、百分比和剩余时间。
6. 调用 `edit_message_text` 编辑原消息，不发送新消息。

异常处理：

- `Message is not modified`：忽略。
- `message to edit not found`：从内存登记表移除。
- `Forbidden` / `Unauthorized`：移除无法继续编辑的消息。
- 其他失败：写入机器人日志，不影响主轮询。

### 5.1 当前限制

动态消息登记目前只保存在进程内存中：

- 机器人重启后，旧值班消息不再自动刷新。
- 用户需重新通过 `/start` 打开值班表，完成新消息登记。
- 如需跨重启恢复，后续可将登记表持久化到 `data/upload` 下的 JSON 文件。

## 6. 值班事件通知

APScheduler 每天按 `Asia/Shanghai` 时区触发四类事件：

| 任务名 | 上海时间 | 事件 | 通知重点 |
|---|---:|---|---|
| `duty:early_start` | 14:00 | 早班上班 | Ben、Jett、Kermit 开始值班 |
| `duty:handoff_start` | 17:00 | 晚班上班、交接开始 | Melo、Davie 上班，进入发布和带教重合时段 |
| `duty:handoff_end` | 22:00 | 早班下班、交接完成 | 晚班接管监控 |
| `duty:late_end` | 01:00 | 晚班下班 | Melo、Davie 完成 8 小时值班 |

星期日事件规则：

- 星期日 14:00、17:00、22:00 不发送值班事件。
- 01:00 下班事件按前一天的晚班判断：星期日 01:00 可结束星期六晚班，星期一 01:00 不发送不存在的星期日晚班下班通知。

每条事件通知都附带触发时刻的完整进度面板，并发送到：

- `STARTUP_NOTIFY_CHAT_IDS` 配置的目标。
- `known_chat_ids.json` 中机器人已记录的群或用户。

时区注意：

- 进度计算使用标准库 `ZoneInfo`。
- 当前项目使用的旧版 APScheduler 只接受 `pytz` 时区。
- 定时任务注册必须使用 `pytz.timezone("Asia/Shanghai")`，否则会在启动时报 `Only timezones from the pytz library are supported`。

机器人启动通知已收敛为：

```text
🤖 ben-bot 已启动

<当前实时值班面板>

【本次更新】
- 变更说明

版本：<git short id>
```

已删除旧通知中重复的机器人自然文案、系统和容器主机信息。启动通知、事件通知和值班表入口共享 `duty_status.py` 中的格式化逻辑，避免后续修改出现三套不一致文案。

## 8. 代码结构

### `app/benbot/duty_status.py`

值班域的核心模块，负责：

- 班次成员和 Telegram username 映射。
- 8 小时进度计算。
- 纯文本和 HTML 值班面板渲染。
- 值班事件文案。
- 动态消息的注册、取消和查询。

### `app/benbot/main.py`

负责：

- 注册四个每日值班事件。
- 注册 `duty:live_refresh` 60 秒循环任务。
- 向已知群和用户广播事件通知。
- 编辑已登记的动态值班消息。
- 在部署和重启时发送当前值班面板。

### `data/scripts/运维值班表/benbot_plugin.py`

负责：

- 处理值班表入口的 Telegram callback。
- 将菜单消息替换为当天值班面板。
- 登记需要每 60 秒刷新的 `(chat_id, message_id)`。

### `data/scripts/运维值班表/duty_schedule.py`

保留完整的班次、周排班和 JSON 输出能力，便于未来恢复周视图、导出报表或接入排班存储。当前首页视图只消费当天状态。

| 时间 | 早班期望 | 晚班期望 |

容器日志应出现 5 个任务：

```text
Added job "duty:early_start"
Added job "duty:handoff_start"
Added job "duty:handoff_end"
Added job "duty:late_end"

```

### 9.4 部署后检查

```bash
sudo docker ps --filter 'name=^ben-bot$' --format '{{.Names}} | {{.Status}}'
sudo docker logs --since 60s ben-bot | grep -E \
  'Added job|ben-bot started|startup|启动通知发送完成|ERROR|WARNING|Traceback|Conflict'
```

当前线上验证结果：

- 容器运行正常，无重启循环。
- 5 个调度任务注册成功。
- 启动通知发送成功 7/7。
- 未出现 Telegram polling conflict。

## 10. 部署流程

```bash
cd devops/python/ben-bot
BEN_BOT_UPDATE_NOTES="- 本次值班功能变更" sh build_and_run_ben_bot.sh
```

线上部署依然使用仓库现有流程：

1. 推送 `main`。
2. 线上服务器 `git pull --ff-only origin main`。
3. 执行 `build_and_run_ben_bot.sh`。
4. 检查容器主进程日志，不能只看容器是否为 `Up`。

第 4 点很重要：入口脚本可能同时存在后台工具安装进程，即使 Python 主程序退出，容器也可能短时显示 `Up`。

## 11. 后续优化建议

建议按优先级继续改造：

1. **持久化动态消息登记**：重启后恢复原消息刷新，并定期清理失效消息。
2. **抽离排班数据源**：目前成员同时存在 `duty_schedule.py` 和 `duty_status.py`，建议迁移到单一 JSON/YAML 或数据库。
3. **支持调休和临时换班**：事件通知应读取当天实际排班，而不是固定成员常量。
4. **添加管理命令**：例如 `/duty swap`、`/duty leave`、`/duty status`，并记录操作人。
5. **事件去重和补发**：将每日已发事件写入持久化状态，防止重启边界重复发送，并支持短暂停机后补发。
6. **通知范围管理**：将启动通知、值班事件和其他广播的目标群分开配置。
7. **自动化测试**：为跨日进度、HTML 链接、调度时区和消息注册补充 pytest 用例。
