# 测试策略

> 来源文件：`~/Projects/work/game/xiaolan-watches/dev/docs/qa/test-strategy.md`

> 整理日期：2026-06-04 01:09｜日期依据：文件创建/修改时间

Kickoff（小蓝看夜场） 的测试策略必须覆盖核心业务、高风险逻辑、权限和主要用户路径。测试不是补充材料，而是项目是否具备上线资格的核心证据。

## 测试层级

| 层级 | 目标 |
| --- | --- |
| Unit | 验证纯业务逻辑。 |
| Contract | 验证 API 响应与 `packages/contracts` 一致。 |
| Integration | 验证服务端与数据库、第三方服务、异步任务协作。 |
| E2E | 验证主要用户路径。 |
| Manual QA | 验证 UI、体验、兼容性和第三方沙箱。 |

## P0 必测链路

1. 登录与权限。
2. 核心业务主流程。
3. 后台敏感操作。
4. 关键数据状态机。
5. 第三方回调或异步任务，如项目需要。

## 高风险测试规则

1. 高风险状态不得只由客户端决定。
2. 敏感操作必须有审计日志。
3. 回调必须幂等。
4. 异常路径必须有测试。

## 完成定义

任何需求、页面或接口不能只靠“能打开”“接口 200”“冒烟测试通过”标记完成。完成必须同时满足：

1. PRD 有明确条目或任务卡。
2. OpenAPI 或事件契约已更新，若不涉及契约必须写明。
3. 实现文件明确。
4. 自动化测试覆盖核心行为和异常路径。
5. 页面类需求必须有真实手机视口截图或录屏。
6. 后台类需求必须有权限和审计日志验收。
7. `docs/qa/acceptance-evidence.md` 对应行状态为 `已完成` 且证据完整。
8. Agent 最终回复引用完成证据和合入判断。

`docs/qa/acceptance-evidence.md` 由 `npm run check:acceptance` 校验。证据不足时只能标记为 `进行中`、`阻塞` 或 `未开始`。
上线测试底线由 `npm run check:release-testing` 校验。业务项目中，冒烟测试、health check、页面能打开或接口 200 不能单独支撑 `已完成`。

## 项目级闭环验收

模块验收必须登记到 `docs/qa/project-acceptance.md`，并覆盖以下链路：

1. PRD。
2. OpenAPI 或事件契约。
3. 数据模型、权限或账本规则。
4. 服务端实现。
5. 客户端或后台实现。
6. 自动化测试。
7. E2E 或手工验收。
8. 测试环境。
9. 红蓝对抗 review。
10. Agent 日志。

只验证某一端不能判定模块完成。测试环境由 `docs/qa/test-environments.md` 管理，`staging` 未配置前不得宣称生产可上线。
