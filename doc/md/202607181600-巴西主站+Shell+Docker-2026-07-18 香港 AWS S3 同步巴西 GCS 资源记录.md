# 2026-07-18 香港 AWS S3 同步巴西 GCS 资源记录

> 来源文件：`~/Projects/work/game/pgserver/master/docs/history/hongkong/cn/2026-07-18-1600-【补静态资源】香港AWS-S3同步巴西GCS资源记录.md`

> 整理日期：2026-07-18 16:00｜日期依据：文件名日期

## 背景

香港项目静态资源已切到 AWS S3 + CloudFront，但客户端资源仍与巴西项目共用同一套源资源。巴西项目下午补资源后，香港 AWS S3 也需要同步跟进，避免 CloudFront 访问缺文件或目录入口 403。

本次目标：

- 检查巴西侧 Google S3 / GCS 静态资源是否有新增或变化。
- 将变化同步到香港 AWS 私有桶 `dbqp-h5-hk-517506432530`。
- 保持 JILI 复用 TADA 前端资源的特殊关系。
- 同步完成后抽检 CloudFront 域名。

## 执行位置

- 香港 Nginx 运维机：`34.92.13.108`
- 同步工具：`/usr/local/bin/dbqp-sync-gcs-to-s3`
- AWS Profile：`dbqp-hk`
- AWS S3 桶：`dbqp-h5-hk-517506432530`

执行命令：

```bash
AWS_PROFILE=dbqp-hk dbqp-sync-gcs-to-s3
```

说明：

- 目标对象数包含额外同步的“目录入口对象”，因此工具使用 `adjusted_destination_count` 与源端对象数对齐校验。
- 本轮实际有变化的重点是：
  - PG 系列目录入口对象补齐。
  - PANDA 目录入口对象补齐 51 个。
  - TADA2 目录入口对象补齐 3 个。
- JILI 前端复用 TADA 资源，因此 TADA2 变化后已触发 `jili-static2` CloudFront 刷新。

## CloudFront 刷新

本轮 TADA2 有 3 个目录入口变化，工具已自动创建 JILI static2 分配刷新：

```text
marker_invalidation_created comment=DBQP HK jili-static2 distribution=E38M63JF95BKAL paths=3
```

## 当前结论

本轮巴西 GCS 到香港 AWS S3 同步完成，所有配置内前缀均校验通过。PANDA 与 TADA2 的新增目录入口已经同步到 AWS，并可通过 CloudFront 访问。

JILI 当前仍以开发提供资源为准；开发确认缺资源的问题不在本轮继续处理，本轮只负责同步源端已经存在的资源。
