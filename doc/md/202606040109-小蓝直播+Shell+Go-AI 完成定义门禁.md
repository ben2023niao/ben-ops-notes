# AI 完成定义门禁

> 来源文件：`~/Projects/work/game/xiaolan-watches/dev/docs/quality/ai-completion-gates.md`

> 整理日期：2026-06-04 01:09｜日期依据：文件创建/修改时间

本门禁用于防止 Agent 把工程草图、mock 页面、冒烟测试或健康检查误报为完成。

## 适用范围

只要变更涉及 `framework.config.json` 中登记的前端 app 路径，就必须通过 `npm run check:ai-gates`。

AI completion gate 的核心不是让 Agent 自己宣布完成，而是检查它是否有资格提交完成申请。Agent Claim 只能是 `implemented`、`verified`、`blocked`；Project Decision 才能是 `pending-review`、`accepted`、`rejected`、`released`。

模板默认登记：

1. `apps/mobile/**`
2. `apps/admin/**`

项目可以按自身情况调整 app 路径和 `designMode`。

## UI 验收模式

公共框架不强制所有项目都有设计图。前端 app 必须在 `framework.config.json` 声明 `designMode`：

| 模式 | 说明 |
| --- | --- |
| `no-design-mvp` | 快速 MVP，不强制设计图，但必须有目标视口、交互闭环、API 状态和可用性验收。 |
| `wireframe` | 对齐线框图或草图。 |
| `reference-style` | 对齐参考产品或风格来源。 |
| `strict-design` | 必须有设计图、截图和视觉差异说明。 |

## Mobile 完成证据

涉及 `apps/mobile/**` 时，Agent 日志必须包含：

1. PRD 来源和需求 ID，必须引用 `docs/prd/**` 和 `AUTH-001` 这类 ID。
2. UI 验收模式；`strict-design` 模式才要求 `docs/design/design-coverage-matrix.md` 中存在的设计图文件名。
3. 设计图尺寸或目标手机视口，优先 375×812。
4. 页面截图证据。
5. 公共组件拆分说明。
6. API endpoint 或 mock 原因。
7. 红蓝对抗和明确合入判断。

## Admin 完成证据

涉及 `apps/admin/**` 时，Agent 日志必须包含：

1. PRD 来源和需求 ID，必须引用 `docs/prd/modules/admin.md` 和 `ADMIN-001` 这类 ID。
2. API 契约来源，必须引用 `docs/api/admin-api.md` 或 `packages/contracts/openapi`。
3. 后台模块和真实业务对象。
4. API endpoint、状态和 owner service。
5. 权限与审计日志说明。
6. fallback/mock/placeholder 的占位原因，如仍存在。
7. 红蓝对抗和明确合入判断。

## 重要边界

冒烟测试只证明服务可达，不能证明功能完成。真实完成必须同时满足 PRD、OpenAPI、UI 验收来源、测试、日志和 Review 结论。

## UI Visual Evidence

页面类需求不能只靠“看过了”或 Agent 日志宣称完成。截图、视口矩阵和 visual diff 必须写入：

```text
docs/qa/ui-visual-evidence.json
```

并通过：

```bash
npm run capture:ui-visual
npm run check:ui-visual-validator
npm run check:ui-visual
```

`no-design-mvp` 不要求设计源，但仍需要 current screenshot 和目标视口；`strict-design` 必须有 baseline/current/diff。

`npm run capture:ui-visual` 是 Agent-neutral 的真实浏览器截图入口。乌托邦 Core 不默认启用 hook；Claude Code Stop hook、Codex final checklist 或 CI/MR 可以作为项目自选增强，但都应调用同一条命令链：

```bash
npm run verify:ui-runtime
```

该命令会先从 `docs/qa/ui-visual-evidence.json` 读取 `completed` 页面和视口，用 Playwright 截图并回写 `current` 路径，再运行 UI visual evidence 和 AI completion gate。项目需要提供正在运行的页面地址：

```bash
UI_VISUAL_BASE_URL=http://localhost:3000 npm run verify:ui-runtime
```

没有真实截图、没有目标视口、截图打不开、console error 未处理，或者 Agent 日志没有 PRD/验收/红蓝对抗证据，都不能声明完成。

## Performance / SLO Evidence

进入 `growth`、`scale`、`enterprise` 后，压测、SLO 和观测证据必须写入：

```text
docs/qa/performance-evidence.json
```

并通过：

```bash
npm run check:performance-validator
npm run check:performance
```

没有真实报告和阈值结果，不能把大流量治理标记为完成。

## 技术栈完成证据

公共框架优先沉淀团队默认后端技术线：

```text
Go Gin + Laravel
```

技术栈选择必须写入 `framework.config.json`，并通过：

```bash
npm run check:tech-stack
```

没有声明 runtime/framework/role 的服务，不能作为已纳入框架治理的工程模块。

## 代码与数据表规范

实现类任务必须遵守：

```text
docs/quality/code-standards.md
docs/architecture/database-design-standards.md
```

涉及数据表、migration、索引、账本或审计时，必须更新 `docs/architecture/data-model.md` 或使用 `docs/templates/database-table-template.md`。该入口由：

```bash
npm run check:engineering-standards
```

校验基础规范、模板和 Review/Agent 日志字段是否齐全。

## 运维就绪

上线、部署、环境、密钥、备份恢复、观测和故障处理必须遵守：

```text
docs/operations/ops-readiness.md
docs/operations/secrets-management.md
docs/operations/backup-restore.md
docs/operations/incident-response.md
```

上线前必须通过：

```bash
npm run check:ops
```

只有部署没有回滚、只有备份没有恢复步骤、只有日志没有 trace/request id、只有 health check 没有故障 runbook，都不能声明生产可上线。

## 需求验收矩阵

每个需求、页面、后台模块或接口都必须登记到：

```text
docs/qa/acceptance-evidence.md
```

状态写 `已完成` 时，必须提供 PRD、契约、实现、自动化测试、手工/E2E、截图或录屏、Agent 日志和结论。该矩阵由 `npm run check:acceptance` 校验。

## 项目级闭环

项目验收必须登记到：

```text
docs/qa/project-acceptance.md
```

每个模块必须同时覆盖 PRD、契约、数据/权限、服务端、客户端或后台、自动化测试、E2E/手工、测试环境、红蓝对抗和 Agent 日志。该矩阵由 `npm run check:project` 校验。

测试环境必须登记到：

```text
docs/qa/test-environments.md
```

启用环境必须写明基础 URL、数据库/存储、部署/启动命令和必跑检查。该矩阵由 `npm run check:test-env` 校验。

实现变更必须执行红蓝对抗 review。该规则由 `npm run check:red-blue` 校验。
