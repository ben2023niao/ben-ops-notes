## 四、执行动作

```text
1. 在香港入口机写入初始化脚本 /root/hk-backend-startup.sh（945 字节，
   sha256 918da669a127b69cffae649d14038e767598545ca6e01863d7bfdfbadce4d0a7）：
   设置 root 密码、开启 SSH 密码登录、时区 UTC、安装基础包与 Docker、启用 docker 服务
2. 小规格试跑一台探针实例，确认服务账号具备创建权限、镜像族可用，随后删除
3. 创建 dbqp-hongkong-sanic-prod-01（asia-east2-b，内网 203.0.113.1，绑定 34.92.83.132）
4. 创建 dbqp-hongkong-sanic-prod-02（asia-east2-c，内网 203.0.113.1，绑定 34.150.91.228）
5. 两台共用同一份 startup-script（创建时通过 metadata 注入）
```

遇到的问题与处理：

```text
问题：创建时 --image-family=ubuntu-pro-2604-lts-amd64 报 imageFamilyViews not found。
处理：改用实践可用的 ubuntu-2204-lts（与香港入口机同版本）。
问题：startup-script 执行成功（串口日志 exit status 0、Docker 已装），但 SSH 密码登录
  仍被拒（Permission denied (publickey)）。
原因：Ubuntu 云镜像的 cloud-init 写 /etc/ssh/sshd_config.d/50-cloud-init.conf，
  内含 PasswordAuthentication no；sshd 配置为「首次匹配优先」，主配置里追加的设置不生效。
处理：新增 /etc/ssh/sshd_config.d/00-dbqp-password.conf（字母序在 50- 之前），
  写入 PasswordAuthentication yes + PermitRootLogin yes 并重启 sshd；
  通过 gcloud compute ssh（项目 metadata 临时密钥）进入执行，
  修复后两台 `sshd -T` 均为 passwordauthentication yes / permitrootlogin yes。
```

## 七、安全说明（重要）

```text
1. root 密码按用户指定值设置，明文不写入本仓库、工作台、日志或文档。
2. 初始化脚本 /root/hk-backend-startup.sh 含该明文密码，仅保留在香港入口机（权限 700），
   需要时可删除；实例 metadata 的 startup-script 也含该值，如需收敛可在实例内
   `gcloud compute instances remove-metadata --keys=startup-script` 清除。
3. 为执行修复，`gcloud compute ssh` 向项目 metadata 写入了运维公钥
   （key 名 `compute.511057654766442468`、`compute.2166080764923942857`）。
   如不需要，可在 GCP 控制台/命令删除对应 ssh-keys 条目。
4. 两台新机只加了 ssh/内网/beszel 端口规则，未开放数据库、Redis、Docker API 等公网端口。
```
