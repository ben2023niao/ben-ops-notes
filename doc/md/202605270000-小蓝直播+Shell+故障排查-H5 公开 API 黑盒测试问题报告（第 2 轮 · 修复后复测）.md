## 三、P1 详情

### ISS-A1 `status:"UNKNOWN"` 不在枚举且状态永不切换（P1）

- **现象**：`home/today-matches`、`schedule/days`、`match/{id}`、`match/{id}/score` 的赛事 `status` 全部返回 `"UNKNOWN"`。
- **契约**：`HomeMatch.status` 枚举 `[UPCOMING,LIVE,ENDED,CANCEL]`；`Match.status` 引用 `MatchStatus`=`[UPCOMING,LIVE,ENDED,CANCEL]`。`UNKNOWN` 不在任一枚举。
- **影响**：前端被迫把 `UNKNOWN` 映射为「未开赛」，已过开赛时间的赛事也不切换（TC-SCH-002/009、TC-LIVE-007 倒计时归零状态切换无法验证）。这是首页/赛程「状态不实时」的根因（前端按映射处理，不写适配）。
- **建议**：后端按开赛时间 / 赛况返回正确的 `MatchStatus` 枚举值。

### ISS-A2 `/match/{id}` 返回 HomeMatch 形而非契约 Match（P1）

- **实际 keys**：`id, match_no, stage, round, status, start_at_ms, venue, home_team, away_team, home_score, away_score`。
- **契约 Match**：`id, stage, group_name, home_team, away_team, venue, kickoff_at, kickoff_ts, status, score_home, score_away, period, phase, minute, stoppage, mvp_player, mvp_team`。
- **脱节**：时间字段 `start_at_ms`（契约 `kickoff_at/kickoff_ts`）、比分 `home_score/away_score`（契约 `score_home/score_away`）、多了 `match_no/round`、缺 `group_name/period/phase/minute/stoppage/mvp_*`。
- **建议**：`/match/{id}` 按 `Match` schema 返回完整详情字段。

### ISS-A3 半决赛 stage 值 `semi_final` ≠ 契约 `semi`（P1）

- **现象**：后端各端点半决赛返回 `stage:"semi_final"`；契约 `MatchStage` 枚举为 `semi`。`group_stage`、`final` 已一致。
- **影响**：契约消费方（ts-sdk 类型）按 `semi` 生成，`semi_final` 为枚举外值。前端 `adapters.ts` STAGE_LABEL 已用 `semi`/`semi_final` 双键兜底（源码注释亦标注此 drift）。
- **建议**：后端统一返回契约规范值 `semi`（或契约补 `semi_final`），二选一对齐。

## 四、P2 详情

- **ISS-A4 `/match/{id}/score`**：实际 `home_score/away_score/status/updated_at_ms`；契约 `score_home/score_away/period/minute/status`。字段名 + 缺字段 + status=UNKNOWN。
- **ISS-A5 `/match/{id}/goals`**：data 包成 `{items:[]}`，契约 data 应直接是 `[MatchGoal]` 数组。
- **ISS-A6 `recharge/init` 500**：通道未启用属已知业务条件，返回 HTTP 500 + 通用内部错误码 10001（前端能展示 message，但 500 不利于区分系统故障与业务拒绝）。建议改受控 4xx + 专用业务码。
- **ISS-A7 最小充值不一致**：`config/system.recharge_min_amount=6` 与 `recharge/breakdown` 实拒 <10 矛盾，二者应统一（业务规则 / 用例为 10）。
- **ISS-A8 预设金额可疑**：`recharge_amount_options=[6,30,100,300,500,2000]` 含 6、30 碎额，与产品预设不符，需确认是否为有效运营配置（前端目前未消费此字段，硬编码自己的预设，见 web 报告 N-03）。
- **ISS-A9 注册首字符校验缺失**：后端接受 `1abcde9`（首字符数字）注册成功，业务规则要求首字符非数字。前端已严格拦截，后端应补齐（防直连接口绕过）。
