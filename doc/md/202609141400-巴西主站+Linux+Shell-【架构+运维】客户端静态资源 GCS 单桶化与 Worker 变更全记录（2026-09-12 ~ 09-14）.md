```text

              │

```

## 二、GCS 单桶化（本次核心操作）

### 2.1 变更前状态（09-14 盘点，只读）

备份目录：`docker/scripts/worker-js-cdn-代码备份/`，命名规范：

| 版本 | 时间 | 改动 | 备注 |

| v20 | 09-14 | **开发版**：国家白名单 `["BR","SG","HK","AE"]`（非白名单返回 403 页面）+ 语法改为 **ES Module** | 历史 |

**踩坑（重要）**：

```text
1) ES Module 上传方式不同：GET 拉取会返回 multipart 封装（--boundary + Content-Disposition），
   存盘时必须剥离；上传必须用 multipart + mevendor_ata.main_module（application/javascript+module），
   按经典脚本直传会 400。cf_worker_deploy.py 已支持自动识别 + strip_multipart()。
2) 部署工具需要 CF_API_TOKEN 环境变量；脚本里用 subprocess 调用时必须显式传 env，
   否则会「静默失败」（本次批量切换时踩到）。
3) 批量后台任务必须用 setsid 启动：只用 nohup 时 SSH 会话结束会把进程带走
   （本次第二批 vendor_a 跑完后被杀，群里表现为「通知卡住」）。
4) 每次改 Worker 都必须备份线上源码（用户要求），并按「一个厂家切换一次验证一次」推进。
```

## 四、同期排查的静态资源问题（都有结论）

### 4.1 游戏目录 URL 打不开（`/c7d/` → 404）

```text
原因：静态资源走 Worker → GCS，GCS 没有 nginx 的 index 指令，不会把 /c7d/ 补成 /c7d/index.html。
两套解法（都已验证）：
  A. GCS 侧补「目录别名对象」<game>/ = <game>/index.html 的内容（gcs_dir_alias.py，已停用待清理）
  B. 开发在 Worker 里做目录 302 重定向（v19 起生效）——当前采用方案 B
```

### 4.2 手机打不开、控制台报 `Unterminated group`

```text
现象：index.74706.js:20 Uncaught SyntaxError: Invalid regular expression: /[a-z]+;[0-9]+;[^锛宂*/g
根因：静态响应 Content-Type: text/javascript **没有 charset**；文件本身是合法 UTF-8
      （那行实际是 [^，]*/g），中文手机 WebView 在 script 未声明 charset 时回退系统编码（GBK），
      把 UTF-8 的「，」解成「锛宂」并吃掉后面的 ] → 语法错误。电脑内核默认 UTF-8 所以正常。
处理：开发在 v21 给文本类资源补 charset（已上线）。
```

### 4.3 图片/资源 200 但大小不对（例如 972B 的 PNG 只返回 107B）

```text
原因：Cloudflare 边缘缓存里存了旧的坏条目（10×4 占位图，107B），
      带随机参数绕过缓存就能拿到正确的 972B 原图。
处理：purge 三个 zone 后复验，pg3/pg5/vendor_a-statics3 等对象的字节数与源文件一致。
```

### 4.4 大量 403（抽检脚本报全部 403）

```text
两种来源，都不是故障：
  a) 抽检脚本用 python-urllib 默认 UA，被 Cloudflare 拦截 → 换真实浏览器 UA 后全部 200
  b) 国家白名单：本地 VPN 出口切到 PH（loc=PH）→ 静态域按要求返回 403 页面；BR/SG/HK/AE 正常
```

## 六、踩坑总表（新增）

```text
1) GCS 没有 rename：要「改名」只能新建+复制，或利用同名镜像已存在的事实直接删旧桶
2) 删桶前必须先做并集比对，否则单边独有文件会永久丢失
3) ESM Worker 的 GET 返回 multipart 封装（备份要剥离）
4) 部署脚本子进程缺 CF_API_TOKEN 会静默失败
5) nohup 不足以让后台任务存活，必须 setsid
6) Cloudflare 会拦 python-urllib 的 UA（巡检脚本要用浏览器 UA）
7) 国家白名单会让「非白名单出口」的巡检脚本整体 403，排查时要先看 loc
8) 边缘缓存可能存旧/坏条目（甚至内容与 ETag 不一致），purge 后要用字节数复核
```
