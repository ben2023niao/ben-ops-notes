执行范围：`dbqp-ops-console`、03 打包机、巴西/香港域名发布流程。

## 一、结论

一键准备已增加域名配置保护和发布后审计：

- 拉代码前备份巴西/香港源码及运行目录，共四份配置；
- 备份包含 40 个正式 JSON 文件、metadata、SHA256 清单和 tar 归档；
- `latest-before-prepare` 始终指向最近一次准备前备份；
- 打包完成后另存一份最终发布快照；
- 自动比较准备前后 Host 集合；
- Host 变化只告警、不删除，便于人工核对和回滚；
- 页面同时提供独立的“域名配置备份”执行命令。

## 三、一键准备新顺序

```text
1. 备份 03 上巴西/香港源码与运行目录
2. 03 拉取 ben 最新代码
3. 同步 03 最新结果集
4. 4 路动态并发打包
5. 生成最终域名快照
6. 比较准备前后 Host
7. 校验源码与运行目录一致
```

备份发生在 `git pull` 之前，因此如果新提交再次把其他环境域名带进来，仍保留
发布前可恢复基线。

## 七、验证中发现并修复的问题

首次独立执行最终快照检查时，历史 `jili.json.bak-*` 被 `diff -qr` 误判为目录
差异。实际 10 个正式 JSON 完全一致。

已改为只逐个 `cmp` 正式的 10 个 `*.json`，不把历史备份文件纳入发布一致性
判断。修复后完整执行通过：

```text
DOMAIN_FINAL_SNAPSHOT=…post-build-4b6d2a04
DOMAIN_SOURCE_RUNTIME_EQUAL=1
```

## 九、回滚

查看最近准备前备份：

```bash
readlink -f /data/domain-config-backups/latest-before-prepare
```

恢复巴西源码：

```bash
rsync -a /data/domain-config-backups/latest-before-prepare/br-source/ \
  /data/pgserver/platform-api/conf/domains/
```

恢复香港源码：

```bash
rsync -a /data/domain-config-backups/latest-before-prepare/hk-source/ \
  /data/pgserver/platform-api/conf/domains-hk/
```

运行目录恢复使用同目录下的 `br-runtime`、`hk-runtime`。恢复前先确认目标环境，
不要交叉覆盖。
