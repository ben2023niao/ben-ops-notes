# 【配置维护】线上环境自有监控程序白名单放开（不拦截 / 不限流 / 不记日志）记录

> 整理日期：2026-09-26 11:17｜日期依据：正文日期

文档日期：2026-09-26 11:17（CST）/ 03:17（UTC）
环境：游点涩线上环境（main 分支）
分类：配置维护 + 误伤复盘
风险等级：P2（网关 nginx 白名单与日志策略）
标签：监控程序、DomainSecurityMonitor、白名单、X-Forwarded-For、限流、访问日志

## 一、发现：被我们封掉的“授权安全测试 IP”实为自有监控

```text
用户反馈“把监控的 IP 放开拦截”，核查网关日志确认：
· 监控 UA：Mozilla/5.0 DomainSecurityMonitor/1.0
· 出口 IP：2a02:4780:5e:7a89::1（同段 4 个 IP）
· 行为：GET /（页面探测，所有落地页）；另有 POST /api/v1/modules/home（接口探测，UA 为 python-requests）
· 之前 09-26 的“IPv6 刷量授权安全测试”结论中，该 IP 被判定为脚本刷量并整段封禁 → 实际上就是公司自有监控
  （监控结果在群里表现为多条「网页访问已恢复 / SDK 接口已恢复」）

复盘：该监控 24 小时高频探测全部落地页（约 4 次/秒），一天产生 12-13G 网关日志，
      是 09-26 早上根盘被打满的直接驱动因素之一。
```

## 二、白名单放开动作（网关 nginx）

```text
备份：/root/nginx-monitor-whitelist-20260926-031349/
      （10-youdianse-prod-maps.conf、20-youdianse-prod-unified.conf、abuse-blocklist.conf）

1) 解除拦截
   · /etc/nginx/conf.d/abuse-blocklist.conf 移除 2a02:4780 条目（map 结构保留，供守卫后续使用）
   · 删除 ip6tables 对 2a02:4780::/32 的 DROP 直连封禁
2) 白名单识别（10-youdianse-prod-maps.conf 追加）
   map $http_user_agent $is_monitor_ua { default 0; ~*DomainSecurityMonitor 1; }
   map $http_x_forwarded_for $is_monitor_ip { default 0; ~*2a02:4780 1; }
   map "$is_monitor_ua$is_monitor_ip" $monitor_request { "01" 1; "10" 1; "11" 1; default 0; }
3) 不限流：/api 限流键对监控置空（nginx 对空 key 不计入限流）
   map $monitor_request $api_limit_key { default $api_client_key; 1 ""; }
4) 不写访问日志：日志条件叠加监控判断
   map "$log_ssr:$monitor_request" $log_final { "1:0" 1; default 0; }
   20-youdianse-prod-unified.conf：access_log … if=$log_ssr  → if=$log_final
   nginx.conf（http 级）：access_log … youdianse_ext  → if=$log_final（双重保险）
5) nginx -t 通过 → nginx -s reload（服务不中断）
```

## 三、守卫侧同步（避免再次误封）

```text
文件：devops/scripts/cc_guard/youdianse_cc_guard.py（ben-bot 运行机）
备份：/root/cc_guard-backup-20260926-111700.py
· 移除固定拦截段 XFF_BLOCK_PREFIXES 中的 2a02:4780（改为空）；
· 新增监控白名单：MONITOR_PREFIXES = ("2a02:4780",)、MONITOR_UA_MARKERS；
· SKIP_PREFIXES 增加 "2a02:4780"，is_skippable() 生效 → 刷量判定与自动封禁都会跳过监控；
· write_gateway_blocklist() 增加 is_monitor_client() 过滤（双保险，不写监控段）。
```

## 四、验证

```text
1. 拦截解除：模拟监控请求（UA DomainSecurityMonitor + XFF 2a02:4780…）→ 200（此前为 444）
2. 白名单变量：临时调试 location 实测 is_monitor_ua/is_monitor_ip/$monitor_request/$log_final
   → 监控请求 $log_final=0、普通用户 $log_final=1（验证后已删除调试配置）
3. 不写日志：监控段日志在 03:15:54 后停止写入；唯一标记探针验证
   · 监控请求（IP+UA）不写日志；普通用户请求正常写日志
4. 守卫：跑一轮输出 api_flood=0/0（监控不再被计入刷量），网关拦截清单为空
5. 业务侧：群里 SSL Monitor 连续回「网页访问已恢复 / SDK 接口已恢复」（h5.18h.game 等重点域名 200）
```

## 五、影响与收益

```text
· 监控恢复正常：不再被 444、不被 /api 限流；
· 日志量大幅下降：监控此前约占网关日志的主要增量（12-13G/天），白名单后不再产生该部分日志，
  配合「每 6 小时归档 S3 + 本地 1-2 天 + 磁盘 75% 看门狗」，根盘被打满的风险显著降低；
· 误伤防复发：守卫已把监控段列入跳过名单，后续新规则也会自动跳过。
```

## 六、回滚

```text
· 网关：恢复 /root/nginx-monitor-whitelist-20260926-031349/ 三个文件 → nginx -t → nginx -s reload
· 守卫：覆盖回 /root/cc_guard-backup-20260926-111700.py
```

## 七、后续建议

```text
1. 监控探测频率建议评估（当前约 4 次/秒，覆盖数百域名）；如可降频，日志与源站压力都会更小；
2. 监控 UA（DomainSecurityMonitor）建议固定并与出口 IP 段一起登记到工作台，作为“已知可信来源”；
3. 后续若监控换机房/换 IP，需要同步更新白名单（nginx 两处 map + 守卫 SKIP_PREFIXES）。
```
