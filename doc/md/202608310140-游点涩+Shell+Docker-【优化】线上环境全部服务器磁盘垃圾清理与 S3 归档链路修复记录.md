## 背景

数据汇报 bot 连续报告后端 `ip-172-31-31-108` 根盘 75%+（75.5% -> 76.2%），磁盘自动清理每次
都返回“清理完成但失败步骤=1”：S3 归档 exit=2（403）、本地兜底删除 0、业务日志 195G 不变。
用户要求：清理全部服务器磁盘垃圾；操作一步、分析一步、飞机群通知一步；默认只本地 Commit 不 Push。

## S3 归档失败根因与修复

```text
现象：youdianse-log-s3-retention.py preflight 403（exit=2），自 2026-07-31 起每日失败
实测：
  aws sts get-caller-identity                    OK（arn:aws:iam::176528004422:user/s3-game-prod）
  aws s3api put-object / delete-object           成功（同桶同前缀）
  aws s3api head-bucket                          403（无 ListBucket）
  rclone copyto / deletefile（v1.53.3-DEV、v1.75.0） 403：操作前必做 HeadObject（无 GetObject）
根因：IAM s3-game-prod 只有 PutObject/DeleteObject，rclone 无法跳过对象 HEAD -> 403
修复：脚本上传/删除改用 aws s3api put-object / delete-object（>4G 走 aws s3 cp 兜底），
      移除 rclone 依赖；rclone v1.75.0 已装 /usr/local/bin 备用（旧版备份 .v1.53.3-DEV.bak）
小批量实测：--max-files 3 -> deleted=3 failed=0
```
