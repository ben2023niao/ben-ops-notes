## 背景与目标

用户要求：
1. 巴西项目静态资源桶使用圣保罗地区（southamerica-east1），香港项目使用亚洲（东京）桶；
2. 静态资源 URL 直接使用 GCS 桶公开地址（storage.googleapis.com），不再依赖 Google CDN/负载均衡，
   也不需要 Cloudflare 二级域名映射；
3. 巴西用户就近访问圣保罗桶，亚洲用户后续访问亚洲桶。

## 技术约束（实测确认）

- GCS 要求请求 Host 头等于桶名：域名 CNAME 直指 `BUCKET.storage.googleapis.com` 时浏览器带的是原域名，
  GCS 返回 404，因此"二级域名直接解析到桶"不可行；
- Cloudflare Free 套餐无法为 242 条静态记录做 Host 改写（Origin Rules 改 Host 仅 Enterprise、
  Transform Rules 禁改 Host、Snippets Free 不可用、Page Rules 仅 3 条/zone）；
- 最终选定方案：platform-api 静态域名配置直接使用桶公开地址（虚拟主机域名），游戏资源 URL 直出桶。

## 执行内容

### 1. 圣保罗桶创建与同步（southamerica-east1）

```text

bizops-gcs-vendor_a-statics-sa / vendor_a-statics1-sa / vendor_a-statics2-sa
bizops-gcs-pp-static-sa / ppk-static-sa / vendor_c-static-sa / vendor_d-static-sa
```

- g759 桶 `bizops-gcs-g759-static` 本就在圣保罗，无需复制；
- 东京桶保留为香港/亚洲副本（ASIA），备份桶 `bizops-game-statics-gcs` 不变。

## 补充（2026-08-28 22:40 双桶测速自动选优）

用户确认巴西桶与香港桶内容一致，且亚洲测试巴西桶偏慢。

因此把巴西（圣保罗）桶与香港/亚洲（东京）桶**并列写入 static_hosts**：

```text
例：PG  -> ["bizops-gcs-pg-static-sa.storage.googleapis.com",      # 圣保罗
             "bizops-gcs-pg-static.storage.googleapis.com"]        # 东京
```
