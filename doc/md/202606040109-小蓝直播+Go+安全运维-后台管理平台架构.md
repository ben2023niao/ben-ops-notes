# 后台管理平台架构

> 来源文件：`~/Projects/work/game/xiaolan-watches/dev/docs/architecture/admin-platform.md`

> 整理日期：2026-06-04 01:09｜日期依据：文件创建/修改时间

本文说明 乌托邦 中后台管理端的统一架构。后台前端、Go Gin Admin API、Laravel Admin API 和 Laravel Filament 是不同层次，不能混在一个概念里。

## 1. 目录分工

```text
apps/admin
  统一后台管理前端，前后端分离，不放服务端业务代码。

services/go-app
  可以暴露 Admin API，适合核心、高并发、强事务、账本、订单、风控等后台接口。

services/laravel-app
  可以暴露 Admin API，也可以直接使用 Filament 做一体后台。
```

## 2. 两种后台模式

| 模式 | 目录 | 适用场景 |
| --- | --- | --- |
| 前后端分离后台 | `apps/admin` + `services/go-app` 或 `services/laravel-app` | 统一后台 UI、复杂交互、多后端 API、长期产品化后台。 |
| Laravel Filament 一体后台 | `services/laravel-app/app/Filament` | 快速 CRUD、运营配置、内容审核、内部工具。 |

两种模式可以并存，但必须写清楚模块归属。例如：订单账本由 Go Admin API 提供，内容审核由 Laravel Admin API 提供，配置项由 Filament 提供。

## 3. 契约优先

只要启用 `apps/admin`，后台接口必须先写：

```text
docs/prd/modules/admin.md
docs/api/admin-api.md
packages/contracts/openapi/paths/admin/*.yaml
```

OpenAPI path 必须标注：

```yaml
x-owner-service: services/go-app
```

或：

```yaml
x-owner-service: services/laravel-app
```

这样前端、后端、测试和 AI Agent 才能围绕同一份契约并行。

## 4. 权限与审计

后台管理端的 P0 底线：

1. 登录态和管理员会话。
2. RBAC：角色、权限、菜单、按钮级权限。
3. 审计日志：敏感操作必须记录。
4. 数据 owner：谁拥有写权限必须明确。
5. 高风险操作：二次确认、幂等、回滚或人工复核策略。

没有这些内容时，只能标记为后台原型或占位，不能声明后台可用。
