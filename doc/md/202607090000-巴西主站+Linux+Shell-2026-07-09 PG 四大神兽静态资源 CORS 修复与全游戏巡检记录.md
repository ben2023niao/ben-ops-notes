本文记录 PG 线上试玩 `1849515` 四大神兽静态资源跨域报错的处理、复测和飞机群通知。

## 问题

测试反馈 PG 四大神兽进入游戏时浏览器控制台出现 CORS 报错。

报错资源：

```text
https://pg3-static.xqv9m8.icu/1849515/shared/984721902a/index.json
```

页面来源：

```text
https://pg-games.m7v8k3.cyou
```

浏览器表现：

```text
Access to XMLHttpRequest ... has been blocked by CORS policy:
Response to preflight request doesn't pass access control check:
No 'Access-Control-Allow-Origin' header is present on the requested resource.

GET .../1849515/shared/984721902a/index.json net::ERR_FAILED
```

## 判断

四大神兽属于 PG3 静态资源分组：

```text
group=pg3
game_id=1849515
static root=/www/wwwroot/pg3-static
GCS live bucket=gs://bizops-gcs-pg3-static
backup bucket=gs://bizops-game-statics-gcs/pg3-static
```

这类问题优先看静态链路，不需要先动后端业务代码：

```text
browser origin -> pg3-static.* -> Google Cloud Load Balancer / Cloud CDN -> GCS backend bucket
```

接手时公网探针检查，截图里的具体资源已经能返回 CORS 头：

```text
OPTIONS https://pg3-static.xqv9m8.icu/1849515/shared/984721902a/index.json
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET,HEAD,OPTIONS

GET https://pg3-static.xqv9m8.icu/1849515/shared/984721902a/index.json
Access-Control-Allow-Origin: *
status=200
```

为了防止 bucket CORS 配置漂移，仍补跑了一次 PG 静态相关 GCS bucket 的 CORS 兜底写入。

## 处理

本次没有修改业务代码，也没有重新发布 `platform-api`。

通过 Python 远程调宝塔上的 `gsutil cors set`，对以下 bucket 重新写入同一份 CORS 配置：

```text
gs://bizops-gcs-pg-static
gs://bizops-gcs-pg3-static
gs://bizops-gcs-pg4-static
gs://bizops-gcs-pg5-static
gs://bizops-game-statics-gcs
```

CORS 模板：

```json
[
  {
    "origin": ["*"],
    "method": ["GET", "HEAD", "OPTIONS"],
    "responseHeader": [
      "Content-Type",
      "Content-Length",
      "Range",
      "Content-Range",
      "Accept-Ranges",
      "ETag",
      "Cache-Control"
    ],
    "maxAgeSeconds": 3600
  }
]
```

执行结果：

```text
bizops-gcs-pg-static: exit=0
bizops-gcs-pg3-static: exit=0
bizops-gcs-pg4-static: exit=0
bizops-gcs-pg5-static: exit=0
bizops-game-statics-gcs: exit=0
```

复查 `gsutil cors get`，上述 5 个 bucket 均已是同一份配置。

## 后续排查规则

后续如果再看到 PG 静态资源 CORS 报错，按这个顺序处理：

```text
1. 先用实际报错 URL 做 OPTIONS + GET 探针，带上浏览器里的 Origin。
2. 如果公网 URL 缺 Access-Control-Allow-Origin，先查对应 bucket 的 gsutil cors get。
3. 如果 bucket CORS 不对，补跑 gsutil cors set。
4. 如果 GCS 直连有 CORS，但静态域名没有，说明可能是 Cloud CDN 缓存旧响应头，需要按具体 path 做 CDN invalidation。
5. 如果静态资源 CORS 正常但游戏仍报登录失败，再看动态接口 api.* / pg-games.* / verify 请求。
```

维护建议：

```text
1. 继续优先用 Python 写巡检和远程维护逻辑，shell 只做 SSH / docker exec 启动器。
2. PG3 / PG4 / PG5 新静态目录上线后，要同时确认 GCS live、GCS backup 和 CORS 配置。
3. 飞机群当前默认通知 chat_id=-5203304347；如果要发单独“18game运维”群，需要先补该群 chat_id。
```
