## 一、TADA 的两个服务是什么

```text
TADA HTTP   ：游戏接口（登录/旋转/事件上报），端口 9096，入口 /app/tada/tada.py
TADA WS2    ：实时推送 WebSocket，端口 8765，入口 /app/tada/lifeservice/tada_ws2.py
              对外路径 https://tada-games.<域名>/lifeservice/ws2，握手成功返回 101
两者原本在同一个容器里跑（01 就是这样）；02 现在是拆成两个容器跑。
```

## 二、01 上「原始」的启动方式（单容器跑两个服务）

01 的容器 `dbqp-tada-release-01` 用的镜像 `pgserver:master-1516f8dd`，启动命令是
`python /app/docker/scripts/start_service_group.py`，靠一个环境变量声明要跑哪几个服务：

```bash
docker run -d \
  --name dbqp-tada-release-01 \
  --restart unless-stopped \
  -p 9096:9096 \
  -p 8765:8765 \
  -e SANIC_WORKER_ACK_TIMEOUT=120 \
  -e 'SERVICE_GROUP_CONFIG=[{"title": "TADA HTTP", "log_file": "tada.log", "command": "python -u tada/tada.py"}, {"title": "TADA WS2", "log_file": "tada-ws2.log", "command": "python -u tada/lifeservice/tada_ws2.py"}]' \
  -v /opt/pgserver/version.json:/app/version.json \
  -v /opt/pgserver/server_configs:/app/server_configs \
  -v /opt/pgserver/logs/dbqp-tada-release-01:/app/logs \
  -v /opt/game_results_datas/tada:/app/game_result_datas/tada \
  pgserver:master-1516f8dd \
  python /app/docker/scripts/start_service_group.py
```

要点：

```text
· 一个容器里同时跑 HTTP 与 WS2，两个端口都发布（9096 + 8765）
· WS2 有没有起来，取决于 SERVICE_GROUP_CONFIG 里有没有那一条
· 镜像自带 PATH/PYTHONPATH=/app/VERSION_FILE_PATH/GAME_DOMAINS_PATH 等 env，
  容器只额外传了 SANIC_WORKER_ACK_TIMEOUT 和 SERVICE_GROUP_CONFIG
```

## 三、02 现在的启动方式（脚本化，每个厂家一个容器）

02 的容器不是手工一条条 `docker run`，而是脚本批量起：

```text
/data/server-runtime/start.sh    用法: sh start.sh <厂商|all> <镜像tag>
/data/server-runtime/stop.sh     用法: sh stop.sh  <厂商|all>

镜像来自 03 上的私有 registry：203.0.113.1:5000/game-service-<厂商>:<tag>
当前 tag（本次）：20260916-ben-cb8f2c55
厂商列表：api pg tada ppk pp playson panda g759 （端口 9090/9091/9096/9098/9099/9020/9018/9019）
```

start.sh 里给每个厂家拼的 docker 参数（原文摘录）：

```bash
docker_args="-d --name $container_name -p ${port}:${port} --restart=always \
  -v /data/server-runtime/share.so:/usr/local/lib/python3.11/site-packages/share.so \
  -v /data/server-runtime/server_configs:/app/server_configs \
  -v /data/server-runtime/version.json:/app/config/version.json \
  -v /data/server-runtime/xxxxxx.mmdb:/app/config/xxxxxx.mmdb \
  -v /data/server-runtime/conf/domains:/app/config/domains \
  -v /data/server-runtime/game_result_datas/${v}:/app/data/game_result_datas/${v} \
  -v /data/server-runtime/logs:/app/${appdir}/logs"
docker run $docker_args "$image"                     # 普通厂家：用镜像默认 CMD
docker run $docker_args "$image" python /app/tada/jili.py   # 只有 jili 有特例入口
```

镜像是 `game-service-tada:20260916-ben-cb8f2c55`，它的：

```text
默认 CMD = /bin/sh -c python /app/${CURRENT_VENDOR}/${MAIN_ENTRY}
           （CURRENT_VENDOR=tada、MAIN_ENTRY=tada.py → 即只跑 HTTP，不跑 WS2）
内置 env = PYTHONPATH=/app、VERSION_FILE_PATH=/app/config/version.json、
           GAME_RESULT_DATAS_PATH=/app/data/game_result_datas/tada、
           GAME_DOMAINS_PATH=/app/config/domains、SERVER_CONFIGS_PATH=/app/config/server_configs
镜像内已有 /app/tada/lifeservice/tada_ws2.py（WS2 入口就在镜像里）
```

所以 `sh start.sh all` 只会起 8 个厂家容器，**TADA 只有 HTTP，没有 WS2** —— 这就是 02 缺 WS 的原因。
（docker 事件也印证：`game-service-tada-ws-prod` 是后来单独 create/start 的。）

## 四、02 上手动启动 TADA WS2 的命令（可直接复制）

与 start.sh 的参数保持完全一致，只是容器名/端口换成 WS 的，并把入口换成 tada_ws2.py：

```bash
docker run -d \
  --name game-service-tada-ws-prod \
  -p 8765:8765 \
  --restart=always \
  -v /data/server-runtime/share.so:/usr/local/lib/python3.11/site-packages/share.so \
  -v /data/server-runtime/server_configs:/app/server_configs \
  -v /data/server-runtime/version.json:/app/config/version.json \
  -v /data/server-runtime/xxxxxx.mmdb:/app/config/xxxxxx.mmdb \
  -v /data/server-runtime/conf/domains:/app/config/domains \
  -v /data/server-runtime/game_result_datas/tada:/app/data/game_result_datas/tada \
  -v /data/server-runtime/logs:/app/tada/logs \
  203.0.113.1:5000/game-service-tada:20260916-ben-cb8f2c55 \
  python /app/tada/lifeservice/tada_ws2.py
```

重启（先删后起，幂等）：

```bash
docker rm -f game-service-tada-ws-prod 2>/dev/null
# 然后重新执行上面那条 docker run
```

停止：

```bash
docker stop game-service-tada-ws-prod && docker rm game-service-tada-ws-prod
```

一键脚本（已放在 02 上）：`/data/server-runtime/run_tada_ws.sh`

```bash
cd /data/server-runtime
sh run_tada_ws.sh                      # 自动用与 TADA HTTP 容器相同的镜像 tag
sh run_tada_ws.sh 20260916-ben-cb8f2c55  # 或指定 tag
```

> 本命令已在 02 上用**临时端口 8766** 实测通过（不碰线上 8765）：
> 容器正常启动、日志出现 `🚀 WebSocket 服务已启动 ws://203.0.113.1:8765/ws2`、握手返回 `101 Switching Protocols`。

## 六、建议：把 WS2 固化进 start.sh（避免每次手工补）

start.sh 目前只有 `jili` 特例。建议按同样方式加一个 TADA WS 分支，例如在
`for v in $ALL_VENDORS` 循环之后追加：

```bash
# TADA WS2（与 TADA HTTP 同镜像，单独容器、单独端口）
if [ "$VENDOR" = "all" ] || [ "$VENDOR" = "tada" ]; then
    WS_NAME="game-service-tada-ws-prod"
    WS_IMAGE="${REGISTRY}/game-service-tada:${VERSION_TAG}"
    [ "$(docker ps -a -q -f name=^/${WS_NAME}$)" ] && { docker stop "$WS_NAME" >/dev/null 2>&1; docker rm "$WS_NAME" >/dev/null 2>&1; }
    docker run -d --name "$WS_NAME" -p 8765:8765 --restart=always \
      -v /data/server-runtime/share.so:/usr/local/lib/python3.11/site-packages/share.so \
      -v /data/server-runtime/server_configs:/app/server_configs \
      -v /data/server-runtime/version.json:/app/config/version.json \
      -v /data/server-runtime/xxxxxx.mmdb:/app/config/xxxxxx.mmdb \
      -v /data/server-runtime/conf/domains:/app/config/domains \
      -v /data/server-runtime/game_result_datas/tada:/app/data/game_result_datas/tada \
      -v /data/server-runtime/logs:/app/tada/logs \
      "$WS_IMAGE" python /app/tada/lifeservice/tada_ws2.py
fi
```

对应地，stop.sh 的 `ALL_VENDORS` 停止逻辑里也要能停掉它（`docker stop game-service-tada-ws-prod`），
否则 `sh stop.sh all` 之后 WS 容器还在跑。

## 七、注意事项

1. **镜像来源**：02 用的是 03 上的私有 registry `203.0.113.1:5000/game-service-tada:<tag>`；
   02 上必须能拉到该 tag（本地已有就不需要拉）。01 用的是 `pgserver:master-<commit>`，两套镜像不同。
2. **配置来源**：02 的容器把宿主机 `/data/server-runtime/...` 挂进容器的 `/app/config/...`；
   配置（version.json / conf/domains / server_configs）是从 03 `rsync` 过来的，更新配置后要重启容器生效。
   之前那个手工起的 WS 容器**没有挂载**（用的是镜像内配置），建议按本文的命令带上挂载，与 TADA HTTP 保持一致。
3. **端口不要写错**：WS 是 `-p 8765:8765`；02 上 TADA HTTP 是 9096，PP/PPK/PlaySon/Panda 分别是 9099/9098/9020/9018（与 01 的 910x 不同）。
4. **WS 与 HTTP 可以切到不同机器**：现在就是 HTTP 在 02、WS 在 01；切完一定要分别验证（HTTP 看 /health，WS 看 101）。
