## 先看结论

宝塔面板会根据自己的站点数据重新生成 vhost 配置，尤其是 `#PROXY-CONF` 区域。之前手动写在主 vhost 里的反代规则会被面板保存动作覆盖，导致：

- `/_nuxt/` 静态资源可能被错误转发或丢失 CORS 头。
- `/api`、`/channel`、`/customer` 可能不再走后端 PHP。
- API 请求可能缺少 `version`、`deviceType`、`time` 等头，返回“数据封装错误”。
- CloudFront 回源 Host 可能因为宝塔 DB 中的错误域名而匹配不到正确站点。

当前修复方式：

- 主 vhost 只保留基础站点、证书、`location /` 到 Nuxt SSR。
- 固定分流规则放到宝塔 `extension/<domain>/00-youdianse-fixed-reverse-proxy.conf`。
- 三个主 vhost 和三个固定扩展文件使用 `chattr +i` 加锁。
- 宝塔 `site.db` 的 CloudFront 域名已修正为 `d38owkgqvg83bq.cloudfront.net`。
- 2026-06-18：`h5.youdianse.com` 和 `youdianse.com` 的宝塔重定向都指向 `https://www.youdianse.com$request_uri`。注意 `h5.youdianse.com.conf` 仍是独立 active vhost，所以也必须 include `redirect/youdianse.com/*.conf`。

正常状态下，宝塔保存配置时如果尝试覆盖这些文件，会被系统拒绝。后续要改配置，需要先手动解锁，改完测试通过后重新加锁。

## 为什么不直接在主配置里写全部规则

宝塔会管理主 vhost 文件，并在面板保存、证书更新、反向代理设置保存时重写部分配置。高风险区域是：

```nginx
#PROXY-CONF-START
...
#PROXY-CONF-END
```

如果把 `/api`、`/_nuxt`、API 头兜底全部写在这里，宝塔下一次保存就可能恢复成面板 DB 里的单一代理地址。之前面板列表里显示 H5 域名代理到 `http://203.0.113.1:8088`，这会让页面路由和静态资源都错误地回到后端 PHP。

现在把关键规则放在：

```text
/www/server/panel/vhost/nginx/extension/<domain>/00-youdianse-fixed-reverse-proxy.conf
```

主 vhost 里已有：

```nginx
include /www/server/panel/vhost/nginx/extension/<domain>/*.conf;
```

这样即使主 vhost 以后被重写，扩展规则也有独立文件承载。同时对主 vhost 和扩展文件加锁，阻止宝塔自动覆盖当前生效状态。

## 当前加锁状态

查看锁：

```bash
VHOST=/www/server/panel/vhost/nginx
lsattr "$VHOST/new.youdianse.com.conf" \
  "$VHOST/h5.youdianse.com.conf" \
  "$VHOST/h5.youdianse-main.xyz.conf" \
  "$VHOST/extension/new.youdianse.com/00-youdianse-fixed-reverse-proxy.conf" \
  "$VHOST/extension/h5.youdianse.com/00-youdianse-fixed-reverse-proxy.conf" \
  "$VHOST/extension/h5.youdianse-main.xyz/00-youdianse-fixed-reverse-proxy.conf"
```

正常应看到每行包含 `i`：

```text
----i---------e------- /www/server/panel/vhost/nginx/new.youdianse.com.conf
```

`i` 表示 immutable，不允许写入、覆盖、删除、重命名。即使 root 也需要先 `chattr -i` 解锁。

## 标准修改流程

所有修改都按这个顺序走：

```text
1. SSH 登录宝塔服务器
2. 记录当前 sha256 和 lsattr
3. 备份 DB、主配置、扩展配置
4. 解锁
5. 修改配置
6. nginx -t
7. reload
8. curl 验证业务
9. 重新加锁
10. 重新导出配置
```

## 修改场景 1：改前端 Nuxt 上游地址

当前前端上游：

```text

```

需要修改两个位置：

- 主 vhost 的 `location /`
- 扩展配置的 `location ^~ /_nuxt/`

批量替换示例：

```bash

for site in new.youdianse.com h5.youdianse.com h5.youdianse-main.xyz; do
```

## 修改场景 3：新增 API 路径前缀

当前 API 匹配：

```nginx
location ~ ^/(api|channel|customer)(/|$) {
```

如果新增 `/pay` 也要走后端 PHP，改成：

```nginx
location ~ ^/(api|channel|customer|pay)(/|$) {
```

三份扩展配置都要改：

```bash
VHOST=/www/server/panel/vhost/nginx

for site in new.youdianse.com h5.youdianse.com h5.youdianse-main.xyz; do
  sed -i 's#location ~ \^/(api|channel|customer)(/|$)#location ~ ^/(api|channel|customer|pay)(/|$)#' \
    "$VHOST/extension/$site/00-youdianse-fixed-reverse-proxy.conf"
done
```

注意：Nginx 正则里括号、竖线和 `$` 很容易被 shell 误处理。改完必须用 `nginx -t`。

## 修改场景 4：改 CDN 静态资源 CORS

当前 `/_nuxt/` 静态资源允许任意来源：

```nginx
add_header Access-Control-Allow-Origin "*" always;
```

如果要改成只允许指定来源，例如只允许 `https://h5.youdianse.com`：

```nginx
add_header Access-Control-Allow-Origin "https://h5.youdianse.com" always;
```

三份扩展配置都要改：

```bash
VHOST=/www/server/panel/vhost/nginx

for site in new.youdianse.com h5.youdianse.com h5.youdianse-main.xyz; do
  sed -i 's#add_header Access-Control-Allow-Origin "\\*" always;#add_header Access-Control-Allow-Origin "https://h5.youdianse.com" always;#' \
    "$VHOST/extension/$site/00-youdianse-fixed-reverse-proxy.conf"
done
```

当前业务有多个域名、CloudFront 域名和跨站加载场景，收紧 CORS 前要先确认所有页面来源。

## 修改场景 5：增加 CloudFront 回源域名

如果 CloudFront 分配域名变化，或者新增一个 CloudFront origin Host，需要改两处：

### 1. 主 vhost 的 `server_name`

`d38owkgqvg83bq.cloudfront.net` 当前写在：

```text
/www/server/panel/vhost/nginx/new.youdianse.com.conf
```

检查：

```bash
grep -n "server_name" /www/server/panel/vhost/nginx/new.youdianse.com.conf
```

新增域名时，把新域名追加到 `server_name` 行，末尾保留分号。

### 2. 宝塔 DB 的 `domain` 表

宝塔面板读域名列表时会使用：

```text
/www/server/panel/data/db/site.db
```

查看当前域名：

```bash
sqlite3 -header -column /www/server/panel/data/db/site.db \
  "select id,pid,name,port,addtime from domain where name like '%cloudfront%' or name like '%youdianse%' order by id;"
```

如果只是修正旧值：

```bash
sqlite3 /www/server/panel/data/db/site.db \
  "update domain set name='新cloudfront域名' where name='旧cloudfront域名';"
```

如果是新增域名到 `new.youdianse.com` 这个站点，需要先确认 `pid`。当前 `new.youdianse.com` 对应 `sites.id=23`，所以 domain 表里 `pid=23`。

新增示例：

```bash
sqlite3 /www/server/panel/data/db/site.db \
  "insert into domain(pid,name,port,addtime) values(23,'新cloudfront域名',80,datetime('now','localtime'));"
```

新增前先确认不要重复：

```bash
sqlite3 -header -column /www/server/panel/data/db/site.db \
  "select * from domain where name='新cloudfront域名';"
```

## 修改场景 6：新增一个 H5 域名

推荐做法：

```text
1. 先在宝塔面板创建反向代理站点或复制现有 vhost。
2. 确认主 vhost 有 include extension/<新域名>/*.conf。
3. 把固定扩展配置复制过去。
4. 主 vhost 的 location / 指向前端 Nuxt。
5. 如果该域名也有 API，扩展配置保留 API 分流。
6. nginx -t && nginx -s reload。
7. curl 验证。
8. chattr +i 锁住主 vhost 和固定扩展配置。
9. 更新本地文档和服务器导出。
```

复制扩展配置示例：

```bash
VHOST=/www/server/panel/vhost/nginx
NEW_SITE=example.youdianse.com

mkdir -p "$VHOST/extension/$NEW_SITE"
cp "$VHOST/extension/new.youdianse.com/00-youdianse-fixed-reverse-proxy.conf" \
  "$VHOST/extension/$NEW_SITE/00-youdianse-fixed-reverse-proxy.conf"
```

主 vhost 里必须有：

```nginx
include /www/server/panel/vhost/nginx/extension/example.youdianse.com/*.conf;
```

加锁：

```bash
chattr +i "$VHOST/$NEW_SITE.conf"
chattr +i "$VHOST/extension/$NEW_SITE/00-youdianse-fixed-reverse-proxy.conf"
```

### 本机回源测试

在宝塔服务器本机测试，不经过 DNS 和 CDN：

```bash

  -H 'Host: new.youdianse.com'

  -H 'Origin: https://www.bochuang99.com'
```

## 常见问题定位

### 1. 宝塔面板保存提示失败或配置不生效

先看是否加锁：

```bash
lsattr /www/server/panel/vhost/nginx/new.youdianse.com.conf
```

如果有 `i`，这是预期行为。需要按标准流程解锁后再改。

### 2. `Operation not permitted`

通常是文件有 immutable 锁。

解锁：

```bash
chattr -i /path/to/file
```

改完记得：

```bash
chattr +i /path/to/file
```

### 3. `/_nuxt/*.js` 404

检查：

```bash
grep -Rni "_nuxt\|proxy_pass" /www/server/panel/vhost/nginx/extension/new.youdianse.com/
curl -sS -D - -o /dev/null http://203.0.113.1/_nuxt/BACjjO3D.js -H 'Host: new.youdianse.com'
```

重点确认：

- `location ^~ /_nuxt/` 是否存在。
- `proxy_pass` 是否指向 Nuxt SSR：`http://203.0.113.1:3003`。
- Nuxt 容器是否正在运行并且该资源真实存在。

### 4. 静态资源跨域

检查：

```bash
curl -sS -D - -o /dev/null \
  'https://d38owkgqvg83bq.cloudfront.net/_nuxt/BACjjO3D.js' \
  -H 'Origin: https://www.bochuang99.com'
```

必须有：

```text
access-control-allow-origin: *
cross-origin-resource-policy: cross-origin
```

如果没有，检查扩展配置里的 `add_header ... always;` 是否存在，以及 CloudFront 是否缓存了旧响应。

### 5. API 返回“数据封装错误”

检查 API 反代是否给后端补头：

```bash
grep -Rni "proxy_set_header version\|proxy_set_header deviceType\|proxy_set_header time" \
  /www/server/panel/vhost/nginx/extension/new.youdianse.com/00-youdianse-fixed-reverse-proxy.conf
```

应包含：

```nginx
proxy_set_header version $youdianse_api_version;
proxy_set_header deviceType $youdianse_api_device_type;
proxy_set_header time $youdianse_api_time;
```

再测试：

```bash
curl -sS --max-time 20 -X POST \
  'https://new.youdianse.com/api/v1/modules/home' \
  -H 'accept: */*' \
  -H 'content-type: application/json' \
  --data '{}'
```

如果返回加密字符串，说明 Nginx 必需头兜底已生效。正式业务仍需要前端发送正确加密请求体。

### 6. `ERR_TOO_MANY_REDIRECTS`

优先检查：

```bash
grep -Rni "HTTP_TO_HTTPS\|rewrite\|return 301\|error_page 497" \
  /www/server/panel/vhost/nginx/new.youdianse.com.conf \
  /www/server/panel/vhost/nginx/h5.youdianse.com.conf \
  /www/server/panel/vhost/nginx/h5.youdianse-main.xyz.conf
```

常见原因：

- CloudFront Viewer 到 Origin 的协议策略和源站强制 HTTPS 互相打架。
- 宝塔主 vhost 被重写，出现重复跳转规则。
- CDN 缓存了旧的 301/302。

### 7. CloudFront 仍然拿到旧内容

先看是否 CloudFront 缓存命中：

```bash
curl -sS -D - -o /dev/null https://h5.youdianse.com/ | grep -i "x-cache"
```

如果是旧缓存，做 CloudFront invalidation。至少清：

```text
/
/_nuxt/*
/api/*
```

如果只是 Nuxt 构建文件换了 hash，通常新 hash 不需要清缓存；如果旧 hash 曾经缓存了 404 或错误 CORS，建议清 `/_nuxt/*`。

## 运维注意事项

- 不要在宝塔面板里随手保存这三个 H5 站点的反代配置；如果文件还锁着，保存会失败或不完整。
- 如果必须用宝塔面板改，先解锁，改完马上 `nginx -t`、reload、curl 验证、重新加锁。
- 不要把 `/api`、`/_nuxt` 固定规则重新塞回主 vhost 的 `#PROXY-CONF` 区域。
- 不要只改一个域名的扩展配置，三个 H5 域名应保持一致，除非明确要做灰度。
- 改 CloudFront 域名时，Nginx `server_name` 和宝塔 `site.db.domain` 都要同步。
- 改前端上游时，主 vhost 的 `location /` 和扩展配置的 `/_nuxt/` 都要同步。
- 改后端上游时，扩展配置的 API `proxy_pass` 要同步。
- 每次线上改完，都更新服务器导出和本地文档。
