# 备份与恢复规范

> GitHub 仓库源文件：[点击打开网页渲染版](https://github.com/ben2023niao/ben-ops-notes/blob/main/doc/md/202606040109-%E5%B0%8F%E8%93%9D%E7%9B%B4%E6%92%AD%2BMySQL%2BRedis-%E5%A4%87%E4%BB%BD%E4%B8%8E%E6%81%A2%E5%A4%8D%E8%A7%84%E8%8C%83.md)

> 整理日期：2026-06-04 01:09｜日期依据：文件创建/修改时间

备份的价值不在“有文件”，而在“能恢复”。所有生产项目必须知道数据丢失、误删、迁移失败、对象存储损坏时如何恢复。

## 1. 备份对象

项目必须明确以下对象是否备份：

| 对象 | 是否必须评估 | 说明 |
| --- | --- | --- |
| 主数据库 | 是 | MySQL/PostgreSQL 等业务主库。 |
| Redis | 是 | 如果 Redis 只做缓存，可以不备份；如果做队列、会话、限流计数，必须说明策略。 |
| 对象存储 | 是 | 用户上传、图片、视频、文件。 |
| 审计日志 | 是 | 后台敏感操作、权限、处罚、配置变更。 |
| 账本流水 | 是 | 余额、金币、订单、支付、收益。 |
| 配置和第三方回调记录 | 是 | 支付、短信、IM、音视频等。 |

## 2. RPO / RTO

每个生产项目必须声明：

```text
RPO: 最多允许丢失多少时间的数据
RTO: 发生故障后多久必须恢复服务
```

MVP 可以先写保守目标，例如：

```text
RPO: 24h
RTO: 4h
```

涉及支付、账本、审核处罚、会员、订单的项目必须单独评估。

## 3. 备份策略

至少说明：

1. 备份频率。
2. 备份保留时间。
3. 备份存储位置。
4. 是否异地。
5. 是否加密。
6. 谁有恢复权限。
7. 如何验证备份可用。

## 4. 恢复步骤

恢复文档必须包含：

1. 停写或维护模式策略。
2. 确认恢复点。
3. 恢复数据库或对象存储。
4. 校验数据完整性。
5. 恢复服务流量。
6. 补偿第三方回调或队列任务。
7. 记录事故和复盘。

## 5. Migration 上线

涉及 migration 的上线必须遵守：

1. 生产前在 staging 执行。
2. 大表变更先评估锁表和耗时。
3. 高风险变更上线前确认最近备份可恢复。
4. 优先 expand -> backfill -> contract。
5. 删除字段、改类型、改唯一约束必须写 ADR 或发布计划。

## 6. 验收

不能只写“已配置备份”。至少要有：

1. 最近一次备份时间。
2. 最近一次恢复演练时间，或明确未演练的风险。
3. 恢复负责人。
4. 恢复 runbook。
5. 失败时的业务降级方案。
