## 审计结论(共 12 项问题)

### 🔴 P0(5 项,阻塞前端 codegen)

1. OpenAPI `RechargeOrder` / `WithdrawOrder` / `WithdrawInfo` schema **字段名/类型与 dto 全员对不上**
   - 例:OpenAPI `amount_rmb` vs dto `rmb_amount`;OpenAPI `expire_at(Iso8601)` vs dto `expires_at(int64 unix ms)`
2. 时间字段格式两套并存(Iso8601 string vs unix ms int64)
3. `WALLET-103 提现 = 仅支付宝` vs 代码 `WithdrawSubmitRequest.bank_account_id` — 但**没有任何「添加/列出支付宝账号」接口**,用户根本拿不到 id
4. `WALLET-008` 充值协议同意字段缺失(`agree_terms` 未在 RechargeInitRequest 出现)
5. 路径冲突:`/wallet/recharge-records`(实有) vs `/me/recharge-records`(PRD 规定),OpenAPI 两条并存,实际后者 404

### 🟠 P1(4 项,不严谨)

6. WS 钱包 13 个事件 **0 个落地**(wallet service 注入了 broadcaster 但 grep 全文 0 处调用 `SendUser`)
7. WALLET-007 充值超时无 cron 兜底
8. WALLET-302 退款待调账无 admin 工单接口
9. WALLET-107 邮件推送缺失(本期暂不修,需要 SMTP 基建)

### 🟡 P2(3 项,OpenAPI 历史残留)

10. `bonus_diamond` 字段残留(v0.3 已废赠送钻石)
11. WithdrawSubmitRequest 冗余 `channel` 字段
12. 多处 schema 用旧 `Iso8601` 描述时间(已被 unix ms 覆盖)

## 本次修复批次(B1-B6,用户选 B1-6 一次性全量)

### B1 OpenAPI 重写(以 dto 为准)
- **RechargeInitRequest / Response / StatusResponse / OrderItem** 重写,字段全部 snake_case + `_ms` 时间
- **WithdrawSubmitRequest / Response / StatusResponse / OrderItem / Info** 重写
- 新增 schema:`BankAccountCreateRequest` / `BankAccountItem` / `BankAccountListResponse`
- 删除 `bonus_diamond` / 冗余 `channel` / 过时 `Iso8601` 时间字段
- 保留 `RechargeOrder` / `WithdrawOrder` 旧名作 `$ref` alias 不破坏其他模块引用

### B1.x 路径统一(遵 PRD §8.1)
- router:`/wallet/recharge-records` `/wallet/withdraw-records` 迁入 `/me/recharge-records` `/me/withdraw-records`
- OpenAPI 删旧 `/wallet/*-records` 路径定义,新增 `/me/withdraw-records`

### B2 BankAccount(支付宝账号管理 — WALLET-103 配套)
- repo 加 `Create / FindByUserAndHash / SoftDelete`
- service 加 `ListBankAccounts / CreateBankAccount / DeleteBankAccount`
  - AES-256-GCM 加密 account + holder_name 入库,HMAC-SHA256 hash 防重
  - 格式校验:11 位手机号 或 邮箱(含 @ + 顶级域)
  - 掩码:`ali****@gmail.com` / `138****1234`
- handler 3 个 endpoint:`ListBankAccounts / CreateBankAccount / DeleteBankAccount`
- router 挂 `/me/bank-accounts` GET/POST/DELETE
- OpenAPI 新增 3 个路径定义 + 复用 BankAccount* schema
- 注入:wallet.Service.SetCrypto(aes, hmacKey) 复用 member service 的同一套 AES/HMAC 密钥

### B3 协议同意字段
- `RechargeInitRequest.AgreeTerms bool` 必填 + `binding:"required,eq=true"`
- OpenAPI 同步 required + enum:[true]

### B4 WS 13 个事件落地 5 个关键事件
- protocol.go 加常量:`wallet.balance.updated` / `wallet.recharge.success` / `wallet.recharge.refunded` / `wallet.withdraw.submitted` + 保留旧 `wallet_update`
- service 加 4 个私有方法:`broadcastRechargeSuccess` / `broadcastRechargeRefunded` / `broadcastWithdrawSubmitted` / `broadcastBalanceUpdated`
- 接入点:
  - `SettleRechargePaid` 事务提交后 → `recharge.success` + `balance.updated`
  - `MarkRechargeRefundRequested` → `recharge.refunded`
  - `SubmitWithdraw` 事务提交后 → `withdraw.submitted` + `balance.updated`
- 设计原则:事务外推送(避免脏读) + 失败仅打日志不阻塞 + payload snake_case + `_ms` 时间

### B5 充值超时 sweeper(WALLET-007)
- repo 加 `MarkExpiredAsFailed(ctx, before, batchSize)`,内部用 SELECT id LIMIT N + WHERE id IN (...) 批量更新,防热点
- service 加 `SweepExpiredRecharges(ctx, maxBatches)`,默认 50 批 × 200 = 1w 上限
- 调用方:worker 进程 cron 调本接口(本服务只提供同步 API,scheduler 在 services/worker 接)

### B6 退款待调账工单 admin
- 不开独立路径,直接复用 `GET /api/v1/admin/orders/recharges` + `?status=REFUNDED`
- admin handler 透传 `?status=` + `?user_id=` query 到 service(原本写死 nil)
- 新增 helper `parseRechargeStatusQuery` / `parseUserIDQuery`,enum 与 dto.Status* 对齐
- OpenAPI 同步:加 status/user_id query param + 描述 v0.3.2 用法

## 设计决策摘录(供后续 Reviewer)

1. **以 dto 为准重写 OpenAPI**(不反过来改代码):dto 已被测试覆盖、调用方对齐,改 OpenAPI 工作量小且零风险
2. **时间统一 unix ms**(`*_at_ms` / `*_until_ms`):JS `new Date(ms)` 友好;Iso8601 string 还得 parse
3. **B6 不开独立路径**:复用 `GET /admin/orders/recharges?status=REFUNDED`,通用且符合 REST 风格
4. **WS 事务外推送**:避免脏读 + 推送失败不破坏业务路径
5. **BankAccount AES/HMAC 复用 member 同一套密钥**:不重复造轮子,密钥管理统一
