## 一、起因

Mark 反馈「堡垒机 admin 账号被锁了」。排查结论：**不是内部操作，是公网在暴力破解登录接口**。

## 二、排查过程与证据

1. 查 `audits.UserLoginLog`：近 2 天 3100+ 次失败登录，集中在三个 IP：

| 来源 IP | 失败次数 | 归属 |

| --- | --- | --- |

| 203.0.113.1 | 1036 | DigitalOcean 圣克拉拉（爆破主机） |

| 203.0.113.1 | 434 | 境外 |

| 203.0.113.1 | 303 | 阿里云杭州 |

2. UA 全是 `Go-http-client/1.1` → 脚本直接打 API 登录接口，网页验证码拦不住。
3. 被猜账号：`root` 1426 次、`admin` 54 次，还有 `user/test/ubuntu/ftpuser/zhang/adm` 等（持续换用户名）。
4. 锁定机制：`SECURITY_LOGIN_LIMIT_COUNT=7`（错 7 次）+ `SECURITY_LOGIN_LIMIT_TIME=30`（锁 30 分钟），攻击者每 30 分钟一轮 → admin 反复被锁。
5. 成功登录记录逐条核对，全部来自我们自己的 IP（Ben 的出口、Bruce 曼谷、Berd、AK 线路），**没有发现被攻入的迹象**。

## 三、处置（含 10-16 下午追加的"填 IP 才开启"改造）

### 1. 登录来源 IP 黑/白名单（JumpServer 内置）

```
SECURITY_LOGIN_IP_BLACK_LIST = ["203.0.113.1", "203.0.113.1", "203.0.113.1"]
SECURITY_LOGIN_IP_WHITE_LIST = ["203.0.113.1", "203.0.113.1", "203.0.113.1",
                                "203.0.113.1", "203.0.113.1", "203.0.113.1"]
SECURITY_LOGIN_IP_LIMIT_COUNT = 30     # 原来是 99999，等于没限速
SECURITY_LOGIN_IP_LIMIT_TIME  = 30
```

代码逻辑（`users/utils.py` 的 `BlockGlobalIpUtilBase`）：

- `is_block()`：白名单 → 永不拦；黑名单 → 直接拦；否则看 IP 限速计数。
- 黑名单在**验密码之前**拦 → 攻击流量不再累计失败次数，admin 也就不会被它们锁掉了。
- 白名单里的 IP 不参与限速计数 → 自己人反复试密码也不会被自己的限速封掉。

白名单里 `203.0.113.1` 是 docker 网关（nginx → JumpServer 的通道），**必须留**，否则控制台直接打不开。

### 2. 解锁 admin

```
LoginBlockUtil.unblock_user("admin")   # 顺带清了 root
```

### 3. 机器人专用 API 账号

机器人要能开关堡垒机账号，就不能依赖 admin（admin 被关掉后没人能再打开）。所以建了独立服务账号：

- 账号 `botapi`，角色 `SystemAdmin`，`mfa_level=0`，`is_active=True`
- 密码只写在服务器 `/opt/ben-bot/docker/.env`（600 权限），不进仓库
- 机器人用 `network_mode: host` 直连 `203.0.113.1:8081` 调 API

### 4. 机器人「🌐 堡垒机放行 IP」面板（最终版：只做白名单 IP 增删）

> 演进说明：最初做的是"每个账号一对开启/关闭按钮，开启时必须填公网 IP"；当天下午按需求**简化**成"账号全部保持启用，机器人只管登录白名单 IP 的增删"。下面是最新形态。

菜单入口（运维和后端可见）：

流程：

## 四、验证

1. 账号状态互通：容器内 `jms_accounts.py list` 输出 5 个账号状态。
2. 增加 IP：`add_ip_only("203.0.113.1")` → 白名单新增 `203.0.113.1/32`，面板出现对应的删除按钮。
3. 删除 IP：用不带掩码的 `203.0.113.1` 也能删掉（做了规范化）。
4. 基线保护：删除 `203.0.113.1` 被拒（提示是基线 IP）。
5. 输入校验：`999.1.1.1` 被拒（格式不对）。
6. 账号状态：5 个账号全部 `is_active=True`。
7. 面板渲染：登录地址、URL 按钮、IP 列表、增删按钮都正确；基线 IP 不出现删除按钮。
8. 写入即时生效：改白名单后立即读取已包含新 IP（不需要重启容器）。
3. 菜单按角色渲染：运维/后端看到 4 个入口（值班表/堡垒机账号/堡垒机/监控），其他人只有值班表。
4. 插件渲染：面板文案与按钮回调（`plugin:<node>:enable:<user>`）生成正确。
5. 封禁效果：容器重启后攻击者的登录尝试停止（之前约每 30 秒一次）。

## 五、踩的坑

1. **Cloudflare 会拦脚本调用**：从公网用脚本 POST 登录接口被 CF 以 `error code: 1010` 拒绝（bot 防护）。给服务器做接口调用要走内部地址 `203.0.113.1:8081`。
2. **设置改完要重启容器**：IP 黑白名单写进了数据库，但进程内是启动时加载的，不重启不生效（第一次验证时读到的还是旧值就是这原因）。
3. **admin 被锁时 API 也用不了**：「解锁」这个动作本身需要登录 → 死锁。解决办法是用 ORM 直接跑（`docker exec` + Django），不经 API。
4. **攻击者会换 IP 和用户名**：黑名单只能挡已知的，长期要靠 IP 限速（30/30min）+ 全局 MFA + 域名侧访问控制。
5. **设计上让机器人不依赖 admin**：否则一旦按流程把 admin 关掉，就没人能再打开了。
6. **JumpServer 的"白名单"是豁免名单，不是准入名单**：白名单里的 IP 不受限速/封禁影响，但**不会**限制其它 IP 登录。要做到"只有这个 IP 能登录"，需要另加 nginx 层 allow 列表或 JumpServer 的登录限制（ACL），属于下一步可选项。
7. **隐藏文件差点漏传**：菜单目录的配置文件名是 `.benbot.json`（点开头）。第一次同步用了 `cp 目录/*`，通配符不匹配隐藏文件，结果服务器上没这个配置 → 按钮点进去变成"下一级目录"，面板根本不出现。同步要整目录复制（`cp -R` / `shutil.copytree`）。
8. **compose 的 `.env` 不等于容器环境变量**：`docker/.env` 只用于 compose 里 `${VAR}` 的替换；容器要拿到变量必须写进 `environment:` 段。第一版基线 IP 没生效就是这个原因。

## 七、方案调整（同一天晚些时候，按最新决定改成"nginx 密码保护"）

讨论之后大家认为：**机器人里挂堡垒机功能没必要，而且有安全隐患**（"就是个堡垒机，不用搞这么多花里胡哨"）。所以：

### 1. 撤销机器人里的堡垒机功能

- 删除菜单节点 `data/scripts/堡垒机账号/`（服务器上归档到 `/opt/_removed_20261016/`）
- 删除接 IP 输入的 `app/benbot/handlers/jms.py` 与相关 handler 注册（普通文本机器人不再处理）
- compose 里去掉 `JMS_*` 环境变量，服务器 `docker/.env` 清空
- 菜单恢复成三个入口：`📅 运维值班表` / `🖥 堡垒机` / `📊 监控`
- 当初为这个功能建的 API 账号 `botapi` 已**停用**（`is_active=False`，留着以后做工作台再用）

### 2. 改用 nginx 给堡垒机域名加访问密码

思路：打开 `manage.evercare.id` 先弹一个 HTTP Basic 认证，输入运维内部知道的账号密码才能看到登录页。这样扫到的工具连页面都拿不到，也顺手挡掉一批扫描。

配置（`code/ops-scripts-运维部署脚本/nginx/`）：

```nginx
# 10-manage.conf，server 段
auth_basic "BKL UAT";
auth_basic_user_file /etc/nginx/auth/manage.htpasswd;

location /.well-known/acme-challenge/ {
    root /var/www/certbot;
    auth_basic off;      # 证书续期必须免密
}
```

细节：

- 密码文件 `/opt/nginx/auth/manage.htpasswd`，用 `openssl passwd -apr1` 生成（不用装 apache2-utils）
- nginx compose 增加挂载 `./auth:/etc/nginx/auth:ro`
- 账号密码另存在服务器 `/root/nginx-manage-password.txt`（600）
- **证书续期路径必须 `auth_basic off`**，否则 90 天后自动续期会失败

验证：不带密码访问 `https://manage.evercare.id` → 401；带账号密码 → 200；`/.well-known/acme-challenge/` 免密可访问；监控域名不受影响（还是 200）。

### 3. 按 Mark 要求开启全局 MFA

```
SECURITY_MFA_AUTH = 1   # 1 = 全员强制
```

效果：5 个账号下次登录都会被要求绑定 Google Authenticator（扫码），之后每次登录要输验证码。

注意（踩坑）：改完设置后**接口读回可能还是旧值**（进程内缓存），别被误导；确认要看数据库里的 `settings.Setting` 或重新登录试一次。这次就是"读回 0、实际已经是 1"，直到再登录报 `mfa_required` 才发现已生效。
