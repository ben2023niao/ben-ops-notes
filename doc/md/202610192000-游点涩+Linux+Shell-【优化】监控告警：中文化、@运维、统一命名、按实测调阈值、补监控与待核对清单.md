## 一、告警文案中文化 + 每条告警 @ 全部运维

Beszel 告警文案写死在 Go 源码，已按官方 v0.18.7 打补丁重建镜像（只改文案，逻辑未动）：

| 类型 | 改后 |
| --- | --- |
| 阈值告警标题 | `%s 低于阈值` / `高于阈值` |
| 阈值告警正文 | `%s 最近 %v 分钟平均 %.2f%s` |
| 告警名展示 | 带宽 / 内存 / 磁盘 / 温度 / CPU 使用率 / 1・5・15 分钟负载 |
| 在线状态 | `X：运行正常 ✅` / `X：已断开 🔴` |
| SMART / 使用率 / 传感器 | 磁盘 X SMART 状态变为 Y / `/ 使用率` / `最高传感器 X` |
| 链接文字 | `查看 X` |
| **每条告警正文末尾** | **`@Ben_Bird @jett_yunwei @Kermit0824 @melo_sre @Daviea2 @fyb99`** |

告警链接由 `APP_URL` 决定，已改为 `http://52.79.252.255:8090`（不再是 localhost）。

> 关键点：告警名在 `alerts_system.go` 里按**英文名 switch 取值**，数据库必须保留英文名，仅在展示时映射中文，否则告警不触发。

## 三、按实测数据重设阈值

用近 7 天 `system_stats` 的 **p95** 计算：CPU = p95+10（下限 60，上限 95）、内存 = p95+8（下限 70）、磁盘 = p95+5（下限 60）、带宽 = p95×1.5（下限 30）。

典型变化：

| 系统 | CPU | 内存 | 磁盘 | 带宽 |
| --- | --- | --- | --- | --- |
| 游点涩-后端 | p95 10.7% → 60 | 13.3% → 70 | 49.4% → 60 | **59.2MB/s → 89**（原 20/35，导致频繁告警） |
| 游点涩-网关 | 45.1% → 60 | 47.1% → 70 | 44.8% → 60 | 21.5 → 33 |
| 数据库-从库01 | 9.3% → 60 | 54.0% → 70 | 55.6% → 60 | 30.7 → 47 |
| 数据库-从库02 | 8.0% → 60 | 54.6% → 70 | 56.3% → 61 | 22.7 → 35 |
| 数据库-主库 | 20.2% → 60 | 50.4% → 70 | 39.5% → 60 | 7.6 → 30 |
| msb-MongoDB | 0.6% → 60 | 74.0% → 81 | 22.6% → 60 | 0 → 30 |

> 目的：把「正常业务波动」从告警里排除，只对真正的异常幅度报警。
