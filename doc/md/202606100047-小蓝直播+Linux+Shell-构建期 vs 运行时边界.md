# 构建期 vs 运行时边界

> GitHub 仓库源文件：[点击打开网页渲染版](https://github.com/ben2023niao/ben-ops-notes/blob/main/doc/md/202606100047-%E5%B0%8F%E8%93%9D%E7%9B%B4%E6%92%AD%2BLinux%2BShell-%E6%9E%84%E5%BB%BA%E6%9C%9F%20vs%20%E8%BF%90%E8%A1%8C%E6%97%B6%E8%BE%B9%E7%95%8C.md)

> 整理日期：2026-06-10 00:47｜日期依据：文件创建/修改时间

> 一句话：**framework 产物只活在开发机和 CI 阶段，绝对不进生产服务器 / 容器镜像 / 静态站。**

---

## 1. 三层环境的边界

| 阶段 | 在哪 | 需要 framework？ | 包含什么 |
|---|---|---|---|
| **开发期** | 工程师笔记本 | ✅ 完整需要 | `.ai-framework/` submodule + `devtools/framework` + `scripts/validate-*` + `docs/templates/*` 等全套 |
| **CI 阶段** | GitLab Runner / GitHub Actions | ✅ 完整需要 | 拉 framework → 跑 17 个 validator → 业务 build / test → 产出制品 |
| **运行时（生产服务器 / 容器）** | 阿里云 ECS / k8s Pod | ❌ **绝对不要** | 仅 `bin/api` `bin/admin` 二进制 + `apps/admin/dist/` 静态 + `migrations/` + `config.prod.yaml` |

---

## 2. 为什么生产不能有 framework

| 风险 | 说明 |
|---|---|
| **授权安全测试面增大** | `scripts/validate-*.py` 数十个 Python 脚本，prod 镜像里跑 python interpreter 多此一举 |
| **泄露内部规范** | `docs/architecture/funds-and-ledger.md` 等含业务架构 / 风控规则，**绝不能被授权安全测试者读到** |
| **镜像膨胀** | framework + docs + node_modules + .git 加起来 200MB+，运行时镜像应 < 50MB |
| **PRD 泄露** | `docs/prd/` 含业务需求、定价、活动规则；prod 拉公网静态不能有 |
| **审计混乱** | prod 上跑 `validate-*` 没意义，反而被 ops 误以为是业务工具 |

## 3. CI/CD 流水线分层（参考）

```yaml
# .gitlab-ci.yml / .github/workflows/ci.yml

stages:
  - validate      # framework 自检 + 业务 lint
  - test          # 单测 / 集成测试 / E2E
  - build         # 编译二进制 + 前端 dist
  - package       # 制作生产镜像（不带 framework）
  - deploy        # 推到生产

# 阶段 1：validate（用得着 framework）
validate:
  image: golang:1.22  # 或带 python3 + node 的镜像
  before_script:
    - git submodule update --init --recursive
    - make framework-init
  script:
    - make framework-check        # 17 个 validator 全绿
    - cd services/go-app && go vet ./...
    - pnpm --filter @kickoff/admin lint

# 阶段 2：test
test:
  script:
    - cd services/go-app && go test -race ./...
    - pnpm --filter @kickoff/admin run test

# 阶段 3：build
build:
  script:
    - cd services/go-app && make build      # 产出 bin/api bin/admin
    - pnpm --filter @kickoff/admin build    # 产出 apps/admin/dist/
  artifacts:
    paths:
      - services/go-app/bin/
      - services/go-app/migrations/
      - apps/admin/dist/
    expire_in: 1 week

# 阶段 4：package（关键 — 用多阶段 Dockerfile）
package:
  script:
    - docker build -f infra/deploy/Dockerfile -t kickoff/api:$CI_COMMIT_SHA .
    - docker push registry.example.com/kickoff/api:$CI_COMMIT_SHA

# 阶段 5：deploy（rsync 或 k8s apply）
deploy:
  only: [main]
  script:
    - rsync 模式: bash infra/deploy/rsync-to-prod.sh
    - 或 k8s: kubectl set image deployment/api api=registry.example.com/kickoff/api:$CI_COMMIT_SHA
```

## 4. Docker 多阶段构建（关键样板）

```dockerfile
# infra/deploy/Dockerfile

# ===== Stage 1: validator + builder（开发期工具齐全）=====
FROM golang:1.22-bookworm AS builder

WORKDIR /src
COPY . .

# 拉 submodule + framework 产物（CI 环境）
RUN git submodule update --init --recursive \
 && bash .ai-framework/scripts/sync-framework.sh --apply

# 跑 validator（任一不绿 build 失败）
RUN apt-get update && apt-get install -y python3 \
 && python3 scripts/validate-runtime-environment.py \
 && python3 scripts/validate-prd.py \
 && python3 scripts/validate-engineering-standards.py \
 && python3 scripts/validate-capability-gates.py \
 && python3 scripts/validate-completion-claims.py \
 && python3 scripts/validate-ops-readiness.py \
 && python3 scripts/validate-mr-gates.py \
 && python3 scripts/validate-openapi.py

# 编译业务二进制
WORKDIR /src/services/go-app
RUN CGO_ENABLED=0 go build -ldflags="-s -w" -o /out/api ./cmd/api \
 && CGO_ENABLED=0 go build -ldflags="-s -w" -o /out/admin ./cmd/admin

# ===== Stage 2: 运行时（只带必要文件）=====
FROM gcr.io/distroless/static-debian12:nonroot

# 注意：以下三条复制路径，绝不能有 .ai-framework / docs / scripts / framework
COPY --from=builder /out/api /app/api
COPY --from=builder /out/admin /app/admin
COPY --from=builder /out/ws /app/ws
COPY --from=builder /out/worker /app/worker
COPY --from=builder /src/services/go-app/migrations /app/migrations

USER nonroot:nonroot
WORKDIR /app

# config.prod.yaml 由 k8s ConfigMap / docker -v 挂入，不打进镜像
# 实际镜像可以按服务拆成单入口；这里列出 go runtime 全部内部端口。
EXPOSE 8080 8081 8082 8083
ENTRYPOINT ["/app/api"]
```

**运行时镜像大小：~20-30 MB**（vs builder 阶段 ~1 GB）。

## 5. Rsync 单机部署 exclude 清单

如果不走 Docker，直接 rsync 到 ECS：

```bash
# infra/deploy/rsync-to-prod.sh

PROD_HOST="kickoff-prod-1"
PROD_DIR="/opt/kickoff"

# 严格 include 列表（白名单模式，最稳）
rsync -avz --delete \
  --include 'services/go-app/bin/' \
  --include 'services/go-app/bin/**' \
  --include 'services/go-app/migrations/' \
  --include 'services/go-app/migrations/**' \
  --include 'apps/admin/dist/' \
  --include 'apps/admin/dist/**' \
  --include 'infra/deploy/' \
  --include 'infra/deploy/**' \
  --exclude '*' \
  ./ \
  $PROD_HOST:$PROD_DIR/

# 配置由运维 SCP 单独传，不进同步：
# scp /local/secrets/config.prod.yaml $PROD_HOST:/etc/kickoff/
# scp /local/secrets/api.env $PROD_HOST:/etc/kickoff/
```

**绝对不能 rsync 的目录**（白名单已经排除，但 .rsync-exclude 加双保险）：

## 7. 检查项（部署前 5 秒确认）

```bash
# 1. 镜像里不应有 framework
docker run --rm kickoff/api:latest ls / | grep -E "ai-framework|framework|scripts|docs|devtools" || echo "✅ 干净"

# 2. 镜像大小合理（< 50 MB 期望）
docker images kickoff/api:latest --format "{{.Size}}"

# 3. 进程不依赖 python（运行时不需要）
docker run --rm kickoff/api:latest which python3 && echo "❌ 不该有 python" || echo "✅ 干净"

# 4. 没有源码泄露
docker run --rm kickoff/api:latest find / -name "*.go" 2>/dev/null | head && echo "❌ 不该有 .go 源码" || echo "✅ 干净"
```

## 8. 如果生产出问题怎么办（不能跑 validator）

prod 不带 framework，**调试只能靠**：
- zap 结构化日志（trace_id 串联）
- Prometheus 指标
- Grafana 看板
- 临时 ssh + binary 自带的 debug 端点

**绝不允许**为了 debug 在生产临时拉 framework 产物。

## 9. CI 流水线快速检查（CI 失败时优先看这里）

| CI 阶段失败 | 看哪里 |
|---|---|
| `framework-init` 失败 | 检查 `.ai-framework` submodule 权限 / 网络 |
| `framework-check` 任一 validator 红 | 看具体哪个文档 / 关键字缺失（详 `make framework-check` 输出） |
| `go test` 失败 | 业务代码 bug |
| `go build` 失败 | 用 `build-error-resolver` agent |
| Docker build 失败 | 看 multi-stage Dockerfile 哪一层挂了 |
| 部署后镜像里发现 framework | 检查 `.dockerignore` + Dockerfile COPY 路径 |

---

## 10. 一句话总结

> **framework 是开发期的"考试老师"，不是运行时的"业务代码"。**
> **CI 让老师监考你（validator 全绿才放行 build），但 prod 镜像里只有学生（业务二进制）。**
