# 部署策略

> 来源文件：`~/Projects/work/game/xiaolan-watches/dev/docs/operations/deployment-strategy.md`

> 整理日期：2026-06-04 01:09｜日期依据：文件创建/修改时间

本文档定义 {{PROJECT_NAME}} 的环境、服务拆分和部署原则。目标是让 Monorepo 中的多个应用和服务可以独立构建、独立部署、可回滚。

## 1. 环境划分

```text
dev        开发联调环境，对应 develop
staging    测试/验收/预发布环境，对应 release/*
prod       生产环境，对应 main
```

推荐关系：

```text
develop   -> dev
release/* -> staging
main      -> prod
```

## 2. 服务拆分

早期可以合并部署，后期按压力拆分。

推荐逻辑服务：

```text
apps/admin          后台管理端静态资源
apps/mobile         用户端 App 或 H5 资源，如适用
services/go-app        核心业务 API
services/realtime   IM、世界频道、通话事件、在线状态
services/worker     支付补单、审核回调、定时任务
packages/*          不单独部署，只作为依赖
docs                不部署，或部署为内部文档站
```

## 3. 服务器布局

早期低成本：

```text
server-1        admin + go-app + realtime + worker
server-db       PostgreSQL / MySQL
server-cache    Redis
```

生产推荐：

```text
server-web           admin 静态资源、H5 静态资源、Nginx
server-go-app           services/go-app
server-realtime      services/realtime
server-worker        services/worker
server-db            PostgreSQL / MySQL
server-cache         Redis
server-observability 日志、监控、告警
```

规模扩大后：

```text
server-go-app-1 / server-go-app-2
server-realtime-1 / server-realtime-2
server-worker-1 / server-worker-2
server-db-primary / server-db-replica
```

## 4. 部署产物

```text
apps/admin          静态文件或 Docker image
apps/mobile         App 构建产物或 H5 静态文件
services/go-app        Docker image
services/realtime   Docker image
services/worker     Docker image
packages/*          不单独部署
docs                可选文档站
```

## 5. 配置规则

1. 环境变量不提交真实密钥。
2. `.env.example` 可以提交。
3. 每个环境独立配置。
4. 生产密钥必须走服务器或 CI/CD Secret 管理。
5. 支付、审核、对象存储、IM、音视频等第三方配置必须区分 dev/staging/prod。

## 6. 数据库迁移

1. 数据库迁移必须可追踪。
2. 高风险迁移需要备份和回滚方案。
3. 生产迁移先在 staging 验证。
4. 破坏性迁移必须写 ADR 或发布说明。

## 7. 回滚策略

每次部署必须知道如何回滚：

```text
前端静态资源：回滚到上一版本构建产物
API 服务：回滚到上一 Docker image
Worker：暂停任务 -> 回滚 image -> 恢复任务
数据库：优先向前兼容，避免依赖数据库回滚
```

## 8. 发布检查

发布前检查：

1. CI 通过。
2. OpenAPI 契约检查通过。
3. 数据库迁移已验证。
4. 高风险功能有回归记录。
5. 监控和日志可用。
6. 回滚方案明确。
7. 运维就绪门禁通过：

```bash
npm run check:ops
```
