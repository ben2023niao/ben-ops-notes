# 测试环境硬规则

> GitHub 仓库源文件：[点击打开网页渲染版](https://github.com/ben2023niao/ben-ops-notes/blob/main/doc/md/202606040109-%E5%B0%8F%E8%93%9D%E7%9B%B4%E6%92%AD%2B%E7%9B%91%E6%8E%A7%E5%91%8A%E8%AD%A6%2B%E8%87%AA%E5%8A%A8%E5%8C%96-%E6%B5%8B%E8%AF%95%E7%8E%AF%E5%A2%83%E7%A1%AC%E8%A7%84%E5%88%99.md)

> 整理日期：2026-06-04 01:09｜日期依据：文件创建/修改时间

测试环境是项目验收的硬前置。任何需求不能只在开发者脑子里或本机临时状态下验收。

## 环境矩阵

| 环境 | 用途 | 基础 URL | 数据库/存储 | 部署/启动命令 | 必跑检查 | 状态 | 说明 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| local | 本地开发与单元测试 | `http://localhost` | 本地进程或 fake store | `npm run check` | `npm run check` | 启用 | 用于快速验证，不代表上线验收 |
| dev | 团队开发联调 | 待配置 | 待配置 | 待配置 | `npm run check`、线上关键链路验证 | 待配置 | 新项目初始化后必须配置 |
| staging | 上线前验收 | 待配置 | 待配置 | 待配置 | 项目级 E2E、回归、权限、账本、截图验收 | 待配置 | 未建好前不得宣称生产可上线 |
| production | 真实用户环境 | 待配置 | 待配置 | 待配置 | 发布检查、监控、回滚、审计 | 待配置 | 初始化模板默认不允许直接上线 |

## 硬规则

1. 任何模块写 `已完成` 前，必须在 `docs/qa/project-acceptance.md` 绑定测试环境。
2. `local` 只能证明代码基本正确，不能证明项目可上线。
3. `dev` 必须验证真实部署路径、真实 API base URL、真实构建产物和基础数据。
4. `staging` 未配置前，不允许说“生产可上线”。
5. 高风险链路必须至少在 `dev` 完成闭环验收，生产前必须在 `staging` 复验。
