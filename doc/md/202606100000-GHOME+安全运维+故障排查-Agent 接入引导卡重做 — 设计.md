## 0. 背景与动因

现有 `/agent-clients`(`apps/admin/app/(admin)/agent-clients/page.tsx`)的"公开自助配对通道"卡片过于简陋:只甩出一个裸 URL `…/agent/pair.md` 和一个开/关按钮,运营不清楚"把这个链接给谁、对方做什么、然后我该干嘛"。输码确认还要跳到独立的 `/agent-clients/pair` 页。

参考同类产品 BotLearn 的接入弹窗(可复制话术 + 三步引导 + 就地完成),把这张卡片重做成清晰的引导,降低运营接入一个 Agent 的认知成本。

### 已确认的范围约束

| 维度 | 选定 |
|---|---|
| 优化对象 | **登录后的运营后台** `/agent-clients`(运营操作者),不是面向外部 Agent 主人的公开页 |
| 信任模型 | **不变** —— 仍是"运营在环":Agent 读 `pair.md` 拿 8 位码 → 运营手动输码确认 → 系统发 token |
| 页面结构 | **列表页内精修引导卡**(不新增独立向导路由);把现有独立 `/agent-clients/pair` 输码页**内联**进卡片 |
| 后端 API / 数据模型 | 不变(`AgentPairingCode` / `confirmPairingCode` / token 铸造逻辑均复用) |

### 不在本次范围内

- 公开自助落地页(BotLearn 那种给 Agent 主人的对外页)
- "claim 链接"机制(我们仍用 8 位码,不引入链接式认领)
- 客户端列表表格本身的改版(表格保持现状)
- 管理员"直接新建 Agent"入口(现状无,不在此次补)

---

## 1. 目标体验

运营在 `/agent-clients` 顶部看到一张引导卡,沿"自上而下"三步走:

1. **① 把这段发给你的 Agent** —— 一段可一键复制的自然语言话术(内嵌公开配对 URL),替代现在的裸链接。
2. **② 提示** —— Agent 读取后会返回一串 8 位配对码。
3. **③ 把配对码填到这里完成接入** —— 输码 + 可选 Agent 名称,就地提交;校验通过沿用现有一次性 token 横幅。

下方的已接入 Agent 列表表格不变。

---

## 2. 卡片三种状态

引导卡是"通道开关"与"接入引导"的合并体,按状态渲染:

| 状态 | 渲染 |
|---|---|
| **通道关闭**(`isPairingEnabled() === false`) | 收起为一行:「公开自助配对通道未开启 [开启通道]」;①②③ 区域灰显/隐藏。话术与输码在通道关时无意义(`pair.md` 会返回"已关闭")。 |
| **通道开启 + 无任何 Agent** | 卡片默认完整展开、视觉放大,作为页面主焦点。 |
| **通道开启 + 已有 Agent** | 卡片**默认展开**完整 ①②③,并提供"收起为「+ 接入新 Agent」一行"的手动折叠入口。折叠态**不持久化**(刷新即回默认展开)。 |

卡片头部副标题承载次级动作:通道状态指示(● 已开启)、关闭通道、配对码日志链接 —— 即把现有 `setPairingChannelAction` 开/关与 `/agent-clients/pairing-codes` 入口收编进卡头。

---

## 3. ① 区的话术(可复制文案)

默认话术(中文,内嵌当前 `pairUrl`):

> 这是我想让你接入的内容站。阅读 `{pairUrl}` 并按页面说明完成配对,然后把拿到的 **8 位配对码** 发给我。如果遇到安全风险,请与我逐一确认。

文案决策(均可在 spec 审阅时调整):

- **站点名**:保持泛指"内容站",不硬编码品牌名 —— 降低跨环境/改名维护成本。(若要点名,改一处常量即可。)
- **不在话术里塞权限说明**:`content:published` 的权限边界由 `pair.md`(`renderPairingSkillMd`)负责解释,话术保持短。
- **保留安全提示句**「如果遇到安全风险,请与我逐一确认」—— 对齐 BotLearn,给 Agent 一个安全兜底信号。

`pairUrl` 复用 `page.tsx` 现有计算逻辑(`ADMIN_BASE_URL` 或按当前 host 实时拼 `+ /agent/pair.md`)。

**复制按钮**:客户端组件,`navigator.clipboard.writeText(话术全文)`,复制后短暂反馈("已复制")。这是本次唯一新增的客户端交互。

---

## 4. ③ 区输码内联

把现有独立 `/agent-clients/pair` 页的表单内联进卡片第 ③ 步:

- 复用现有 Server Action `confirmPairingAction(form)`(`actions.ts`),字段不变:`code`(必填)、`name`(可选)。
- 成功:沿用现有跳转 —— `redirect('/agent-clients/{id}/edit?敏感凭据：[已脱敏] edit 页的 `TokenRevealBanner` 一次性展示 token。
- 失败:现有实现是 `redirect('/agent-clients/pair?error=…')`。内联后改为回跳列表页并把错误透出在卡片上,例如 `redirect('/agent-clients?pairError=…')`,卡片读 `searchParams.pairError` 渲染错误条(错误码文案沿用 `pair/page.tsx` 里的 `ERRORS` 映射,迁移到卡片组件)。

### 连带改动(必须同步,否则文档与 UI 不一致)

- **`/agent-clients/pair` 页**:内联后该独立页冗余。处理方式:删除该路由;`pair.md` 里指向它的步骤需同步更新。
- **`pairing-skill-md.ts` 的 `renderPairingSkillMd`**:现有步骤文案写"进入「Agent 接入」→ 点「输入配对码」→ 填入"。内联后没有独立「输入配对码」按钮,需把步骤改为"进入「Agent 接入」→ 在接入卡第 ③ 步填入配对码"。保持 Agent 侧文档与新 UI 一致。

## 6. 测试

- **现有 e2e `apps/admin/e2e/agent-clients.spec.ts`**:若覆盖了 `/agent-clients/pair` 独立页流程,需改为走列表页内联输码;新增"复制话术按钮存在且复制出含 `pairUrl` 的文本"。
- **状态渲染**:通道关 → 显示开启 CTA、不显示 ①②③;通道开+无 Agent → 卡片展开;通道开+有 Agent → 可折叠。
- **输码内联**:有效码 → 跳转 token 横幅;无效/过期/已用码 → 卡片上透出对应中文错误。
- 后端配对逻辑无改动,沿用现有 `agent-clients-db.test.ts` / `agent-post-write.test.ts`,无需新增后端单测。

---

## 7. 验收标准

1. `/agent-clients` 顶部引导卡含可一键复制的话术(内嵌正确 `pairUrl`),不再是裸链接。
2. 输码在卡片内就地完成,无需跳转独立页;独立 `/agent-clients/pair` 路由已删除。
3. 通道开/关、配对码日志入口收编进卡片,行为与现状等价。
4. 三种状态(通道关 / 无 Agent / 有 Agent)渲染正确。
5. `pair.md` 的 Agent 侧步骤文案与内联后的新 UI 一致。
6. 既有配对/发 token 流程行为不变,相关测试通过。
