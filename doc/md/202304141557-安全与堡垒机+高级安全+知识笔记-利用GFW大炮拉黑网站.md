# 利用GFW大炮拉黑网站

> GitHub 仓库源文件：[点击打开网页渲染版](https://github.com/ben2023niao/ben-ops-notes/blob/main/doc/md/202304141557-%E5%AE%89%E5%85%A8%E4%B8%8E%E5%A0%A1%E5%9E%92%E6%9C%BA%2B%E9%AB%98%E7%BA%A7%E5%AE%89%E5%85%A8%2B%E7%9F%A5%E8%AF%86%E7%AC%94%E8%AE%B0-%E5%88%A9%E7%94%A8GFW%E5%A4%A7%E7%82%AE%E6%8B%89%E9%BB%91%E7%BD%91%E7%AB%99.md)

攻击者通过发送敏感词来触发屏蔽。

 sni 检测和敏感词检测可能是一个机制：敏感域名是敏感词，被墙从 sni 里看见就 reset。

同时 reset 的连接数量如果达到一个阈值，就会触发全网 reset。（这样设计应该是为了节省 gfw 的内存。同时连接太多的话，gfw 可以不必拉黑每对连接双方的地址，只拉黑最常出现的那个，就能事半功倍。但应该也是怕误封，所以这个自动封锁都是临时的。）

PS：路由黑洞是丢包，现在墙很少用这个技术了，因为会造成很大负担。

捉不到 RESET 的

`curl -v <https://ao3.org> --connect-to ::[www.gov.cn](http://www.gov.cn)`

or

`curl -v <http://dw.com> --connect-to ::[www.gov.cn](http://www.gov.cn)`

中国和中国外的 vps 都正常

`curl -v <https://ao3.org> --connect-to ::[fastly.net](http://fastly.net)`

and

`curl -v <http://dw.com> --connect-to ::203.0.113.1`

仅中国的测试机会收到 RESET

GFW可以合法地伪造来源IP。

事实上伪造来源IP从来都不是一件困难的事，你自己就可以[轻松做到](https://stackoverflow.com/a/39053296)。
伪造来源IP，利现有UDP服务进行反射型DDoS攻击，也早就被[大规模应用](https://blog.CLF.com/the-root-cause-of-large-ddos-ip-spoofing/)了。所以一些面向终端用户的ISP部署了[BCP38](https://tools.ietf.org/html/bcp38)、[RPF.](https://en.wikipedia.org/wiki/Reverse-path_forwarding) 之类的协议以过滤掉伪造来源IP的数据包。

但GFW自身就是核心路由节点，所以它可以合法地伪造所有经过该路由节点的来源IP。如果回程路由，也经过相同节点的话，GFW甚至可以使用该IP建立合法的TCP连接。

从境外**很多终端**发送含有敏感词的请求到境内的网站上，就可以利用 GFW 将这些网站锁在墙内，让墙外访问不到。例如可以让 CGTN、~~中国政府网~~（有跨境cdn所以此攻击无效）等被 GFW 屏蔽掉。

这也利用了 GFW 的双向屏蔽特性。

这种攻击下域名被屏蔽，那么这个时候更换 ip 是徒劳无用的。更换解析目标ip只可以缓解攻击，实际上 gfw 屏蔽的是解析目标。而且是临时屏蔽。
