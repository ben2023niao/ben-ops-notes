# 游戏维护与更新通知模板

> 来源文件：`~/Projects/work/game/pgserver/master/docs/history/【模板】游戏维护与更新通知模板.md`

> 整理日期：2026-09-15 01:00｜日期依据：正文日期

用途：本项目按固定周期维护各厂家的游戏前端资源、后端服务、数据集、内容与配置。
每次维护按本模板发通知，必须写清两点：维护时间范围（北京时间、巴西圣保罗时间都要写）、
受影响的厂家和具体游戏。文字保持简洁，不使用符号和表情。

配套生成器（自动换算两个时间，可直接发群）：

```
python3 docker/scripts/maintenance_notice.py \
  --start-bj "2026-09-15 01:00" --minutes 60 \
  --kind "前端资源" --detail "17 个厂家客户端资源同步并刷新 CDN" \
  --item "PG|FORTUNE TIGER|前端资源" \
  --item "TADA|FORTUNE GEMS 500|后端重启" \
  --notify
```

也可以只给巴西时间（--start-br），北京时间自动加 11 小时。

## 一、模板

```
游戏维护与更新通知

维护时间-共 60 分钟
北京时间 2026-09-15 01:00 到 02:00，
巴西圣保罗时间 2026-09-14 14:00 到 15:00

维护内容
前端资源 17 个厂家客户端资源同步并刷新 CDN

受影响厂家与具体游戏
PG FORTUNE TIGER 前端资源
TADA FORTUNE GEMS 500 前端资源 后端重启
PP CHESTS OF CAI SHEN 2 前端资源 数据集
PPK POPOK YO DRANGON 前端资源
G759 HUGE DOLLAR 前端资源
PANDA PROSPERITY RABBIT 前端资源

用户可能遇到的情况
维护期间以上游戏可能短暂打不开或卡在加载页
维护完成后重新进入即可，如果还进不去请清除缓存后再试
未列出的厂家和游戏不受影响

异常处理
前端异常时把资源切回旧桶，后端回滚到上一个版本

完成后会发汇总和验证结果
对接人 运维值班 开发
```

## 二、填写要求

1. 时间两个都写：北京时间给团队，巴西圣保罗时间给客户市场；巴西比北京晚 11 小时。
2. 厂家和游戏都写具体名字，不要只写厂家；出问题时开发和客服要能直接定位。
3. 影响内容分清楚是前端资源、后端服务、数据集、还是内容与配置，四类处理方式不同。
4. 通知分三次发：开始前十分钟预告，进行中每个厂家完成各发一条，全部完成后发汇总和验证结果。
5. 静态资源维护必须带 CDN 刷新；静态资源浏览器缓存是七天，要提醒用户清缓存或用隐私窗口。
