# 运维维护指南

> 来源文件：`~/Projects/work/game/pgserver/master/deliverables/dbqp-ops-console/docs/运维维护指南.md`

> 整理日期：2026-10-29 16:23｜日期依据：文件创建/修改时间

## 1. 日常检查

- 容器健康状态；
- `/api/health`；
- 最近失败 Job；
- WebSocket 连接错误；
- 结果集权限 timer 是否 enabled + active，以及最近一次 service 是否为 `success`；
- 磁盘、审计库和日志增长；
- Beszel 告警。

## 2. 备份

每日备份：

```text
/opt/dbqp-ops-console/data/audit.db
/opt/dbqp-ops-console/config/
```

Secret 单独备份，不与普通审计日志混放。

建议保留：

- 审计：90 天；
- Job 完整日志：30 天；
- 压缩历史：180 天；
- 配置和 Secret 轮换记录：长期。

## 3. 日志轮转

- Docker 容器日志限制大小和数量；
- Job 日志按日期/大小轮转；
- 审计数据库执行 VACUUM/索引维护；
- 清理前先验证备份可恢复。

## 4. Secret 轮换

建议周期：90 天或人员变动时立即执行。

顺序：

1. 新 Secret 写入只读 Secret 文件；
2. 健康检查；
3. 运行只读 SSH 测试；
4. 删除旧 Secret；
5. 记录轮换时间和执行人。

## 5. 更新

- 镜像使用不可变 tag 或 digest；
- 先更新测试环境；
- 保留上一个镜像；
- `docker compose up -d` 后检查 `/api/health`；
- 失败立即切回上一镜像。

## 6. 故障恢复

如果控制台故障：

- 不影响正在承接流量的业务容器；
- 不自动执行回滚；
- 通过 SSH 继续现有发布页命令；
- 恢复后确认 Job 中断点和审计记录；
- 禁止盲目重跑未确认的批量发布。

## 7. 审计检查

每日抽查：

- 操作人；
- 来源 IP；
- recipe；
- 版本号；
- 目标主机；
- 是否 dry-run；
- 校验结果；
- 是否人工确认；
- stdout/stderr 是否已脱敏。

审计数据位于 SQLite：

```text
audit_events  页面点击、输入、复制、校验、确认、通知、登录和执行结果
jobs          命令任务、操作者、来源 IP、状态、开始/结束时间、退出码
job_events    实时 stdout/stderr 和阶段事件
sessions      单密码登录会话（仅保存 token 的 SHA256）
```

导出：

```text
GET /api/audit/export
```

页面也提供“刷新记录”和“导出 JSON”按钮。
