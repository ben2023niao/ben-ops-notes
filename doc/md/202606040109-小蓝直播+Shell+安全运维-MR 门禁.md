# MR 门禁

> GitHub 仓库源文件：[点击打开网页渲染版](https://github.com/ben2023niao/ben-ops-notes/blob/main/doc/md/202606040109-%E5%B0%8F%E8%93%9D%E7%9B%B4%E6%92%AD%2BShell%2B%E5%AE%89%E5%85%A8%E8%BF%90%E7%BB%B4-MR%20%E9%97%A8%E7%A6%81.md)

> 整理日期：2026-06-04 01:09｜日期依据：文件创建/修改时间

乌托邦 的 MR 不是代码提交入口，而是工程质量门禁。所有业务项目都应把 GitLab Merge Request 作为合入边界，让 AI Agent、团队开发者、Reviewer 和 CI 围绕同一套规则工作。

## 1. 必须运行的基础门禁

每个 MR 至少运行：

```bash
npm run check
npm run check:init
```

`npm run check` 覆盖 PRD、OpenAPI、契约测试、工程规范、运维、UI、性能、测试环境、验收证据、项目闭环、红蓝对抗和 Agent 完成定义。`npm run check:init` 验证新项目初始化流程仍然可用。

## 2. 变更类型与追加要求

| 变更范围 | 必须补充 |
| --- | --- |
| `docs/prd/**` | 需求 ID、结构化需求索引、验收引用。 |
| `packages/contracts/openapi/**` | OpenAPI 校验、契约测试证据、mock server 状态、接口文档入口。 |
| `services/**` | 服务端测试、OpenAPI 响应对齐、鉴权/权限、审计日志。 |
| `apps/**` | UI 验收、API 接入说明、mock/fallback 原因、截图或 E2E 证据。 |
| `database/**` 或 migration | 数据模型、表设计、索引、回滚和备份恢复影响。 |
| `docs/operations/**` 或 `infra/**` | 部署、回滚、密钥、备份恢复、观测和 runbook。 |
| `.ai-framework` 或框架同步文件 | 升级报告、advisory review、`devtools/framework plan` 输出。 |

## 3. GitLab CI

框架仓库提供 `.gitlab-ci.yml`，默认在 Merge Request 和默认分支运行：

1. `npm run check`
2. `npm run check:init`

业务项目可以扩展部署、构建、E2E 和压测 job，但不能移除基础质量门禁。

## 4. Reviewer 检查

Reviewer 必须确认：

1. MR 描述引用需求 ID 或说明不涉及业务需求。
2. Agent 日志记录读取资料、修改文件、验证命令、风险和框架摩擦。
3. OpenAPI、PRD、测试、验收证据和实现没有互相漂移。
4. advisory 文件不是自动覆盖，而是人工 review 后选择性采纳。
5. 任何例外都有 owner、风险和退出条件。

没有这些证据的 MR，不应合入。
