## 二、发现的重点问题

### 1. GitLab 容器日志 123.3 GB（最大单点）

```
/var/lib/docker/containers/8b0feb…/8b0feb…-json.log   → 124 GB
```

已截断，并写入 Docker 日志轮转配置：

```json
{ "log-driver": "json-file", "log-opts": { "max-size": "100m", "max-file": "3" } }
```

> 该配置对**现有容器**需重启 Docker 才生效（GitLab 会中断 1~2 分钟），建议低峰执行；已备份原 `/etc/docker/daemon.json`。

### 2. 后端与网关的构建缓存长期不清理

后端 6.07 GB、网关 8.58 GB、前端 9.62 GB 的 build cache——发布频繁的机器应定期 `docker builder prune`。

## 四、清理脚本

```bash
# 通用清理（保守策略，只清日志轮转/包缓存/悬空镜像/构建缓存/旧临时文件）
sudo bash /tmp/disk_clean.sh
```

脚本要点：
- `journalctl --vacuum-time=7d`
- `docker container/image/builder prune -f`（**不动数据卷、不动运行中容器**）
- `apt-get clean` / `yum clean all` / `dnf clean all`
- `/var/log` 下 `.gz/.old/.N` 且 >14 天的文件
- `/tmp` 下 >14 天的普通文件（不删目录）
