## 核心决策

1. **v1 marquee 仅最小集**（与用户明确反馈对齐）：v1 marquee 只展示 比分 + 双方 + 阶段 + 码率（客户端探测），不做控球/射门/角球/黄牌/越位。理由：团队无第三方体育数据 API 接入能力，admin 手动录入工作量大且实时性差。原型 v4.45 marquee 显示这些字段视为"视觉占位"，前端实现时裁切。v1.1 或 v2 接通第三方赛事 API 后再升级
2. **rank_badge 服务端计算 + Redis ZSET**：每个房间维度按累计打赏排 Top 3 → 写 Redis ZSET `live:tip:rank:{room_id}`；写打赏时立即重算；发弹幕/进场/打赏 WS 推送前查 ZSET 拼装 rank_badge。降级：Redis 不可达 → 字段缺省 → 客户端 fallback `football`
3. **MatchPhase 与 status 派生关系**：phase 是细粒度（9 个枚举），status 是粗粒度（3 个枚举），phase 由 admin 手动切换驱动 status 自动派生；老 `period` 字段保留兼容但标 deprecated
4. **充值通道 + 状态机锁定字段名而不锁实现顺序**：6 通道（含 USDT 双链）字段定义、状态机 6 状态、status/channel 在 RechargeRecord 上锁定；实际上线由 ADR-0010 决策；admin 后台 ADM—914 通过 system_configs `wallet.recharge.channels.enabled` JSON 列控制开关
5. **H5 广告位 D 复用 home_banners 表 + position 枚举扩展**：不新建表，position 加 `h5_sticky / h5_corner / h5_bubble / h5_theater_topbar` 4 个枚举；admin 后台统一管理；A/B/C 用 title/icon/sub 字段，D 用 text 字段
6. **直播线路独立表 live_lines**：新增表（v0.3.1 migration 待写）— `id, name, edge_url, recommended, enabled, sort_order, created_at`；admin 后台 CRUD；user 端 GET /live/lines 不返回 edge_url，由后续 /play-url 接口拼装真实流地址
7. **PRD ID 跨模块冲突用 em-dash 引用**（沿用 memory 1879 技巧）：跨文件引用 `LIVE—016` / `H5—026` / `LIVE—002` / `WALLET—010` 用 em-dash（`—` U+2014）绕过 validator REQ_ID_RE 正则；自身定义仍用普通连字符 `LIVE-016`
8. **重命名我新加的 ID 避免与既存定义冲突**：MATCH-013/014 → MATCH-015/016；WALLET-007/008 → WALLET-009/010；ADM-901~904 → ADM-911~914（既存子模块已占用 ADM-901~910 / WALLET-007~008 / MATCH-013/014 等）

## 红蓝对抗

| 角色 | 结论 |
| --- | --- |
| 蓝队自检 | (1) 9 处缺口已逐项在对应 PRD 模块落地；(2) OpenAPI 加 8 接口 + 10 schemas；(3) Admin 后台 4 个管理功能详细规范（接口 + 字段 + 权限 + 审计）齐全；(4) 跨模块引用全部用 em-dash 绕过 validator；(5) v1 marquee 与 user feedback 严格对齐——只做 4 段最小集 |
| 红队质疑 | (1) `period` vs `phase` 字段并存会不会让前端混淆？→ 蓝队答：description 已明确"客户端请用 phase"，period 标 deprecated；下个版本可删；(2) Redis ZSET 排名重算频率？→ 写打赏后立即重算单房间 Top 3 即可（O(log N) ZRANGEBYSCORE），不需要定时任务；写流量 ≪ 读流量；(3) admin 手动改比赛阶段如果忘了切，phase 卡在 first_half 整场？→ 蓝队答：admin 后台 UI 应做"自动校验"提醒：超过 60 分钟还在 first_half 弹出警告；本期 PRD 不要求实现，归到 ADM-911 验收下个迭代细化；(4) H5 广告位 D 没关闭按钮是否过于强势？→ 蓝队答：D 是剧场式 TopBar 滚动文字（marquee），不是弹窗；用户离开剧场式即消失；运营硬投放有商业逻辑（首充翻倍等高 ROI 场景），符合产品设计意图；(5) ADR-0010 还没决策就先锁字段名是否过早？→ 蓝队答：字段名是前端契约的事实标准，原型已展示；锁定字段名不影响 ADR 决策"先上线哪几个通道"，反而能让前端先把 UI 跑通 |
