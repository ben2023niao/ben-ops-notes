# 2026-07-20 巴西 PG3 四大神兽 Token 预检跨域修复记录

> 公开版脱敏说明：公司、平台、节点、账号、地址和业务对象均已替换为示例标识；替换后的名称仅用于公开复盘。

> 整理日期：2026-07-20 00:00｜日期依据：文件名日期

## 故障

游戏 `1849515`（四大神兽）从以下入口启动时出现 G1002：

```text
https://pg-games.m7v8k3.cyou/1849515/index.html
```

浏览器报错资源：

```text
https://pg3-static.t6qv8m.icu/1849515/shared/984721902a/index.json
```

页面普通 GET 能取到对象，但浏览器携带自定义 `Token` 请求头时会先发送 OPTIONS。故障时 OPTIONS 返回 200，却没有 `Access-Control-Allow-Origin` 和 `Access-Control-Allow-Headers`，浏览器因此阻止实际 GET。

## 根因

PG3 live bucket 与公共 backup bucket 的 CORS 配置为：

```text
origin: *
methods: GET, HEAD, OPTIONS
responseHeader: Content-Type, Content-Length, Range, Content-Range,
                Accept-Ranges, ETag, Cache-Control
```

配置漏掉了 `Token`。GCS 的 `responseHeader` 同时用于匹配预检请求中的 `Access-Control-Request-Headers`；因此无自定义头的 GET 有 `ACAO=*`，带 `token` 的预检却不返回 CORS 允许头。

宝塔 `/www/server/cron/gcs_static_sync` 也内置了同一份旧模板。只临时修改 bucket 会在后续定时同步时再次被旧模板覆盖。

故障基线：PG3 22/22 静态域名 GET 200 且 `ACAO=*`，但带 `Access-Control-Request-Headers: token` 的 OPTIONS 22/22 都缺少 ACAO。

## 处理

### 1. 备份

宝塔备份目录：

```text
/root/bizops-pg3-token-cors-20260720/
```

其中保留：

- `bizops-gcs-pg3-static.before.json`
- `bizops-game-statics-gcs.before.json`
- `gcs_static_sync.before.sh`
- 22 个 CDN invalidation operation 清单

### 2. 持久修复

以下两个 bucket 的 CORS `responseHeader` 已加入 `Token` 并回读确认：

```text
gs://bizops-gcs-pg3-static
gs://bizops-game-statics-gcs
```

宝塔实际定时脚本 `/www/server/cron/gcs_static_sync` 也只新增了同一行 `"Token",`，`bash -n` 通过；旧脚本 SHA256 为 `74a97e95fdeaa9c330c2e84478112f12bc0f892ef0a7167561f9d4bcd28f910a`，新脚本 SHA256 为 `f526cfe709707dc2a2c5ec69c4353a0189dcac227b7d31f4268e1e5643971527`。

仓库中的脱敏任务镜像与 GCS 运维规范同步更新，防止后续维护恢复旧模板。

### 3. Cloud CDN 精确刷新

URL Map：

```text
bizops-static-gcs-map
```

只对 PG3 的 22 个 `static_hosts` 刷新以下路径：

```text
/1849515/shared/984721902a/index.json
```

没有使用 `/*`。结果：提交 22，`DONE` 22，operation error 0。

## 验收

- 截图域名的 `token` 预检返回 200、`Access-Control-Allow-Origin: *`、允许方法 `GET,HEAD,OPTIONS`、允许头包含 `Token`。
- 截图域名以 `token,content-type` 预检同样通过。
- PG3 22 个静态域名带 `Token` 的 GET：22/22 通过。
- PG3 22 个静态域名带 `token,content-type` 的 OPTIONS：22/22 通过。
- 22 个 GET 对象 SHA256 唯一值：`7322d24cbf0186a2df3d7fb9d8ebc60bd769355b4721e0eb10f56cf2cd5e701d`。
- 巴西后端 01 连续 OPTIONS：5/5 通过。
- 巴西后端 02 连续 OPTIONS：5/5 通过。

用户提供的页面 token 未用于复测，避免重放登录凭据。网络层 CORS/G1002 故障已经修复；原浏览器页面需强制刷新一次以清除旧失败请求。
