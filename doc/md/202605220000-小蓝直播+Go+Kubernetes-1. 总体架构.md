## 1.1 设计原则

1. **可正式上线优先**：v1 即生产标准，不做"先简单后扩展"的妥协
2. **强一致与最终一致明确分级**：资金链路强一致；统计/广播链路最终一致
3. **CDN/源站/Go API 三层流量解耦**：业务请求和流媒体请求物理隔离
4. **模块化单体 + 多 Worker**：避免微服务复杂度，但保留拆分边界
5. **不允许通过缓存替代数据库做资金账本**
6. **可扩展性内置**：分片键、Topic 规划、读写分离开关提前预留

## 1.3 组件职责边界

| 组件 | 唯一职责 | 严禁 |
| --- | --- | --- |
| **CDN** | 视频流分发、HLS/FLV 边缘缓存、静态资源 | 做业务鉴权（业务层用短期 token） |
| **直播源站**（SRS 或 云直播） | RTMP 接入、转码、录制、截图、HTTP-FLV/HLS 输出 | 直接对公网用户暴露 |
| **Cloudflare** | 抗压能力测试 防护、WAF、Bot Management | 业务路由 |
| **Nginx Ingress** | TLS termination、路由分发、WS upgrade | 业务逻辑 |
| **go-api** | C 端业务编排（REST），强一致写 | 抗静态/视频流量；OLAP |
| **go-admin** | 后台业务编排（REST + RBAC + 2FA） | 与 C 端共享路由 |
| **go-ws** | WebSocket 长连接、弹幕/进场/钱包推送 | 业务写操作（仅消费推送） |
| **go-srs-hook** | 直播回调处理（推流校验/关播登记） | 业务路由 |
| **worker-settle** | 竞猜结算、对账跑批、月结 | 同步对外接口 |
| **worker-realtime** | 打赏连击合并、进场广播、排行榜、录制后处理 | 强一致写 |
| **worker-risk** | 风控规则评估、告警生成 | 自动资金操作 |
| **worker-cron** | 定时任务（每日对账、统计快照、Token 续期） | 业务写 |
| **MySQL** | 资金账本（唯一真相）、业务主数据 | 缓存、OLAP、高频计数 |
| **Redis** | 读缓存、分布式锁、限流、HLL/ZSet 计数、幂等键、Token 暂存 | 资金账本、关键数据持久化 |
| **Kafka / Redis Streams** | 异步事件、多消费方解耦 | 替代 DB |
| **OSS** | 录制 / 截图 / 头像 / 静态资源 | 业务热数据 |

## 1.4 流量与压力归属（10k CCU）

| 流量类型 | 量级（峰值） | 谁承担 | Go 服务承压？ |
| --- | --- | --- | --- |
| 视频拉流出站 | **20 Gbps**（1080p×10k×2Mbps） | **CDN 95%+** | 否 |
| 视频回源带宽 | 1-2 Gbps（CDN miss） | **直播 Pull Edge** | 否 |
| OBS 推流入站 | 50 主播 × ~5 Mbps = 250 Mbps | **直播 Push Edge** | 否 |
| HLS 切片请求 | ~30w QPS | **CDN 边缘** | 否 |
| FLV 长连接 | 10k 并发（Web 主推） | **CDN 边缘** | 否 |
| WebSocket 长连接 | 10k 并发 | **go-ws × 3 Pod** | 是（独立服务） |
| 弹幕入站 | ~1k QPS | **go-ws** | 是 |
| 弹幕广播 | ~5w msg/s | **go-ws + Redis Pub/Sub** | 是（扇出） |
| 押注 | 峰值 800 QPS | **go-api + MySQL** | 是（强一致写） |
| 打赏 | 峰值 500 QPS | **go-api + MySQL** | 是 |
| 充值/提现 | 峰值 50 QPS | **go-api + 三方回调** | 是 |
| 首页 / 赛程 | 2000 QPS | **CDN（静态化）+ Redis** | Go 承 ~100 QPS |
| 在线心跳 | 333 QPS（10k/30s） | **go-ws + Redis HLL** | 是（轻量） |
| SRS HTTP hook | ~100 QPS | **go-srs-hook** | 是 |

## 1.7 API 风格

| 类型 | 风格 | 前缀 | 文档 |
| --- | --- | --- | --- |
| C 端业务 | REST | `/api/v1/` | OpenAPI v1 |

### 1.7.2 错误码规范（五位）

| 段 | 类型 | 示例 |
| --- | --- | --- |
| `1xxxx` | 系统错误 | `10001` 参数错误、`10500` 服务异常 |
| `2xxxx` | 业务错误 | `20101` 余额不足、`20102` 押注超限、`20103` 已封盘 |
| `3xxxx` | 权限错误 | `30001` 未登录、`30002` 未实名、`30003` 等级不足 |

### 1.7.3 资金类接口约束

资金写操作（充值/提现/兑换/押注/派彩/打赏）必须：
- 携带 `Idempotency-Key` HTTP Header
- 服务端 `(user_id, idempotency_key)` 联合 UNIQUE 约束
- Redis SETNX 双保险（24h TTL）

## 1.8 数据流（写路径示例：押注）

```
1. 用户 → CDN → Cloudflare → Nginx Ingress → go-api (POST /predict/bet)
2. go-api 中间件链：
   ├─ JWT 鉴权 → 取出 user_id
   ├─ 限流（用户 1s ≤ 5 笔）
   ├─ 幂等校验（Redis SETNX + DB UNIQUE 双保险）
   └─ TraceID 注入
3. service/predict:
   ├─ 开 MySQL 事务（RR 隔离）
   ├─ SELECT predict_activities FOR UPDATE → 校验状态
   ├─ SELECT user_wallets FOR UPDATE → 校验余额
   ├─ 校验等级单次 + 日累计上限
   ├─ UPDATE user_wallets（带 version 乐观锁）
   ├─ INSERT predict_bets
   ├─ UPDATE predict_activities（奖池累加）
   ├─ UPDATE user_consume_total
   ├─ INSERT wallet_ledger × 2（双向）
   ├─ INSERT audit_log
   └─ COMMIT
4. 异步事件：XADD stream:bet.placed → worker 消费（排行榜 / 风控 / 大屏）
5. 响应用户：{ code: 0, data: { bet_id, balance_after, ... } }
```

## 1.9 数据流（读路径示例：首页）

```
1. 用户 → CDN（首页 HTML 静态化，5min 缓存）
2. CDN miss → go-api (GET /api/v1/home/feed)
3. go-api → Redis（命中率 95%+）
   ├─ Redis miss → MySQL → 回写 Redis（TTL 5-30s 随机化）
   └─ 返回聚合 JSON
4. 响应客户端
```

## 1.10 配置与密钥管理

| 类别 | 存储 | 注入方式 |
| --- | --- | --- |
| 普通配置（DB 地址、Redis 地址、CDN domain） | K8s ConfigMap | 环境变量 |
| 数据库密码 / Redis 密码 / JWT secret / 支付商户私钥 | K8s Secret | 环境变量或文件挂载 |
| 通道签名密钥 / 推流 secret / 播放 secret | K8s Secret | 文件挂载（PEM） |
| 业务运营配置（抽水率、赠送倍率、等级门槛、风控阈值） | DB `system_config` 表 | 启动加载 + 5min 刷新 |
| 敏感词词库 | DB `forbidden_words` | 启动加载 + 1min 刷新 |

v2 可上 Vault 做密钥统一管理。

## 1.11 服务拆分边界（未来微服务化方向）

按 PRD 模块边界预留拆分路径，触发条件 §[messaging-strategy.md](messaging-strategy.md) §扩展阶段：

| 未来微服务 | 当前 package | 拆分触发 |
| --- | --- | --- |
| `wallet-svc` | `internal/service/wallet/` + `repository/ledger/` | 资金 QPS > 2000 或 团队拆分 |
| `predict-svc` | `internal/service/predict/` | 押注 QPS > 1500 或 引入实时滚球 |
| `live-svc` | `internal/service/live/` + `liveroom/` | 直播间数 > 5000 |
| `streamer-svc` | `internal/service/streamer/` + `recording/` | 主播数 > 500 |
| `risk-svc` | `worker-risk/` | 规则数 > 50 或 引入 ML 模型 |
| `admin-svc` | `cmd/admin/` | 已物理隔离，可直接拆 |

拆分时通信切 gRPC，注册中心 Consul，跨服务事务用 Saga + 补偿。
