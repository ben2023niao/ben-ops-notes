# 2026-07-06 PG 动态入口 m.icu 域名下线特例说明

> GitHub 仓库源文件：[点击打开网页渲染版](https://github.com/ben2023niao/ben-ops-notes/blob/main/doc/md/202607060000-%E5%B7%B4%E8%A5%BF%E4%B8%BB%E7%AB%99%2BShell%2BPython-2026-07-06%20PG%20%E5%8A%A8%E6%80%81%E5%85%A5%E5%8F%A3%20m.icu%20%E5%9F%9F%E5%90%8D%E4%B8%8B%E7%BA%BF%E7%89%B9%E4%BE%8B%E8%AF%B4%E6%98%8E.md)

> 整理日期：2026-07-06 00:00｜日期依据：文件名日期

本文记录 PG `game_hosts` 里 `m.icu` 结尾动态入口域名的特殊风险、当前运维处理、发布预检和后续维护规则。后续 AI / 运维接手 PG 域名池时，必须先看这份文档。

## 背景

2026-07-06 巴西试玩 PG 全游戏扫描期间，阿努比斯、玻尔修斯传奇等游戏出现卡 50% / 登录失败 / 后端看不到 verify 请求。

经浏览器和后端日志排查，问题不是静态资源缺失，也不是 GCS / Cloud CDN 同步问题，而是 PG 客户端会对动态入口域名做 API host 派生。

异常链路：

```text
入口：
https://pg-games.t6qv8m.icu/<gid>/index.html

客户端实际请求：
https://pg-games.t6qv8api.icu/web-api/auth/session/v2/verifyOperatorPlayerSession

浏览器错误：
net::ERR_NAME_NOT_RESOLVED
```

`pg-games.t6qv8api.icu` 不是线上合法域名，请求没有到 Cloudflare / 宝塔 Nginx / 后端，所以后端日志看不到 verify。

## 根因判断

从现象看，PG 客户端里存在不可控的字符串替换规则，会把 hostname 里的 `m.` 替换成 `api.`。

示例：

```text
pg-games.t6qv8m.icu -> pg-games.t6qv8api.icu
pg-games.6qv8m.icu  -> pg-games.6qv8api.icu
```

正常期望如果要切 API host，应只做明确前缀替换：

```text
pg-games.<root> -> api.<root>
```

但是当前客户端源码不在我们手里，开发侧也确认只能猜测客户端替换规则，短期无法从前端源码根治。

## 当前下线范围

已从 `platform-api/conf/domains/pg.json` 的所有 PG 动态入口 `game_hosts` 移除：

```text
pg-games.t6qv8m.icu
pg-games.6qv8m.icu
```

覆盖范围：

```text
default.game_hosts
special_games.pg3.game_hosts
special_games.pg4.game_hosts
special_games.pg5.game_hosts
```

变更后每组 `game_hosts` 从 22 个变成 20 个。

## 不变范围

以下静态资源域名暂时不下线：

```text
pg-static.t6qv8m.icu
pg-static.6qv8m.icu
pg3-static.t6qv8m.icu
pg3-static.6qv8m.icu
pg4-static.t6qv8m.icu
pg4-static.6qv8m.icu
pg5-static.t6qv8m.icu
pg5-static.6qv8m.icu
```

原因：

```text
1. 本次问题发生在 pg-games 动态入口派生 verify/API host。
2. static_hosts 只负责静态资源加载，不走 verifyOperatorPlayerSession。
3. 下线静态域名会减少静态 CDN 池容量，且目前没有证据表明静态域名触发同类问题。
```

## 后续维护硬规则

PG 的 `game_hosts` 后续不要再加入任何 `m.icu` 结尾的动态入口域名。

判断规则：

```text
host.endswith("m.icu") == true
```

风险例子：

```text
pg-games.xxxm.icu
pg-games.t6qv8m.icu
pg-games.6qv8m.icu
```

不属于本规则的例子：

```text
pg-games.m7v8k3.cyou
pg-games.m6xv8q.cyou
pg-static.t6qv8m.icu
```

说明：

```text
1. 规则只针对 PG game_hosts。
2. 目前只确认 PG 客户端存在这类替换行为，其他厂牌不要无证据扩大处理。
3. static_hosts 不在这条拦截规则内。
```

## 发布预检

已在 `docker/deploy/update_pgserver.py` 增加发布前预检：

```text
发布 platform-api 或 all 时，读取 platform-api/conf/domains/pg.json。
检查 default / pg3 / pg4 / pg5 的 game_hosts。
如果发现 m.icu 结尾动态入口，直接中断发布。
```

预检通过日志：

```text
PG 域名池预检通过：game_hosts 未包含 m.icu 结尾动态入口
```

紧急跳过开关：

```bash
PGSERVER_SKIP_PG_DOMAIN_PREFLIGHT=1 python3 docker/deploy/deploy_all_servers.py platform-api
```

只有明确知道风险且需要临时救火时才允许跳过；跳过后必须补充原因到 `docker/doc`。

## 本地验证命令

改完 `pg.json` 后可以执行：

```bash
python3 - <<'PY'
import json
from pathlib import Path

path = Path("platform-api/conf/domains/pg.json")
data = json.loads(path.read_text())
bad = []

def scan(scope, label):
    for host in scope.get("game_hosts", []):
        if host.endswith("m.icu"):
            bad.append((label, host))

scan(data["default"], "default")
for group in data.get("special_games", []):
    scan(group, group.get("group_name", "special"))

print("bad_game_hosts", bad)
print("default", len(data["default"]["game_hosts"]))
for group in data.get("special_games", []):
    print(group.get("group_name"), len(group.get("game_hosts", [])))
PY
```

期望输出：

```text
bad_game_hosts []
default 20
pg3 20
pg4 20
pg5 20
```

## 给开发的说明

可以直接转发给后端 / C++ 开发：

```text
PG m.icu 动态入口这次先由运维规避：

已从 platform-api/conf/domains/pg.json 的 default / pg3 / pg4 / pg5 game_hosts 下线：
- pg-games.t6qv8m.icu
- pg-games.6qv8m.icu

原因：
PG 客户端会把 hostname 里的 m. 替换成 api.，导致：
pg-games.t6qv8m.icu -> pg-games.t6qv8api.icu
pg-games.6qv8m.icu  -> pg-games.6qv8api.icu

误拼域名没有 DNS，请求无法到后端，表现为游戏卡 50% / verify 无日志。

建议根因修复：
1. 直接使用当前 pg-games 同源 /web-api 和 /game-api；
2. 如果必须派生 api 域名，只允许 pg-games.<root> -> api.<root> 的前缀替换；
3. 不要替换 hostname 任意位置的 "m."。
```
