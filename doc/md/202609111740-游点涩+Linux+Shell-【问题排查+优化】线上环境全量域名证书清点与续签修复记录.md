## 一、工单与背景

```text
来源：SEO异常验证 报警 + 游戏发行运维群反馈
内容：裸域 youdianse.com 证书于 2026-09-09 到期（已续费），
      但源站 nginx 没有 reload / 没指向新证书文件，仍在吐旧证书；
      群内跟进：“ng 需要重启”。
追加要求：全部域名都检查证书情况，快到期的都续签；
          续好一个域名就群里通知一个域名（18GAME_ 上线群 + 18game运维）；
          此前已处理的域名要补通知；通知格式美化。
```

## 二、影响与链路

```text
公网 youdianse.com -> 16.208.38.88（ip-172-31-27-233，18game H5/PC 统一网关）
  -> 网关 nginx 按 SNI 动态加载证书：ssl_certificate $youdianse_cert_dir/fullchain.pem
  -> $youdianse_cert_dir = /etc/letsencrypt/live/<SNI 主机名>

实测（修复前）：
  openssl s_client -connect youdianse.com:443 -servername youdianse.com
    -> CN=youdianse.com, notAfter=Sep 9 12:35:55 2026 GMT（已过期）
  curl -sS https://youdianse.com/ -> 握手失败 / 证书告警
```

## 三、根因

```text
1. 网关 /etc/letsencrypt/live/youdianse.com/ 内的 fullchain.pem、privkey.pem
   是 2026-08-12 手工放置的证书文件，未随续期更新；
2. 该目录不是 certbot lineage（无 renewal 配置），certbot.timer 只续 webroot 域名，
   因此网关侧这张证书不会被自动续期；
3. 宝塔侧同名证书已于 2026-09-09 21:43 续期成功（SAN: youdianse.com、*.youdianse.com,
   notAfter 2026-12-08 12:45:08），但从未同步到网关；
4. 网关多个 live 目录（iymbs.com、kf.game-app543.com、new.youdianse.com、
   www.youdianse.com、h5.youdianse.com 等）指向/引用了同一份证书，
   因此一次证书替换同时修复了这批域名；
5. 同类隐患：h5.youdianse-main.xyz（DNS 同样指向网关）证书已于 2026-09-06 过期 5 天无人发现；
6. 宝塔自动续签任务（acme_v2 --renew_v2=1，每日执行）对
   cron.youdianse-test.xyz、ssl.ksrlfs.com、ssl.bjxwlz.com 这类“通配符且未绑定 DNS-API”
   的证书会直接跳过（日志：未绑定dns-api，跳过域名），导致其静默过期。
```

## 四、执行步骤与结果

| 步骤 | 内容 | 结果 |
| --- | --- | --- |
| 1 | 开工前核对本地/远程提交与工作区改动 | 本地 main 领先 origin/main 8 个提交、工作区干净；线上后端仓库存在历史未提交改动 |
| 2 | 核验 youdianse.com 公网链路、源站证书与续期机制 | 定位到网关证书文件陈旧；宝塔侧已续期但未同步 |
| 3 | 备份网关旧证书 → 从宝塔同步新证书 → nginx 重载 | youdianse.com、h5.youdianse-main.xyz 恢复（md5 一致、证书私钥 MATCH） |
| 4 | 三层复验证书链与业务可达性 | 网关本地、SG 后端、PH 本地均 verify=0；301→www 链路 200 |
| 5 | 全量域名证书清点（166 个）并续签到期证书 | 2 个已过期域名 + 1 个无续签通道域名完成续签 |
| 6 | 上线网关证书到期巡检（脚本 + cron） | 每日 10:40 CST 巡检，≤14 天或已过期告警上线群 |

步骤 3 过程说明（如实记录）：替换后曾因私钥权限设为 600 root 且 fullchain 未同步属组，
导致网关 worker（www-data）约 2 分钟无法读取证书（09:31:50-09:32:30）；
已改为 fullchain 644 root:root、privkey 640 root:www-data 并重载，之后 error.log 无新增证书加载错误。

步骤 6 过程说明（如实记录）：首次安装 cron 时误用 `crontab -` 覆盖后端 root crontab；
发现后用覆盖前生成的备份 `/tmp/crontab.before-cert-alert.20260911` 完整恢复（25 行、8 个既有任务齐全），
随后改用追加方式重新安装（26 行）。约 1 分钟内每分钟执行的自动更新任务可能少跑 1 次，恢复后已确认 cron 正常。

## 七、新增监控

```text
脚本：ops/production/scripts/youdianse-gateway-cert-alert.py
部署：后端服务器 /opt/docker-youdianse-php/ops/production/scripts/（0755 root:root）
cron：40 10 * * * /usr/bin/flock -n /var/lock/youdianse-gateway-cert-alert.lock \
      /usr/bin/python3 /opt/docker-youdianse-php/ops/production/scripts/youdianse-gateway-cert-alert.py \
      >> /var/log/youdianse-gateway-cert-alert.log 2>&1

行为：SSH 只读巡检网关 /etc/letsencrypt/live/；
      仅对“DNS 确实解析到网关”的域名做判定（避免 150 个目录里未暴露域名产生噪声）；
      ≤14 天或已过期 -> 告警上线群，同一域名每天最多一次；
      支持 --dry-run 与 YOUDIANSE_GATEWAY_CERT_HOSTS 强制巡检列表。

验证：dry-run 正常；强制域名 + 100 天阈值测试可正确识别；实跑输出
      ok: no gateway-exposed cert within 14 days。
回滚：sudo crontab -l | grep -v youdianse-gateway-cert-alert | sudo crontab -
```

## 八、后续建议

```text
1. 网关手工放置证书（非 certbot lineage）需要固定同步机制：
   建议把“宝塔续期 -> 网关同步 -> reload”纳入自动化，避免再次漏同步；
2. 宝塔通配符证书补绑 DNS-API，或统一改为单域名 + HTTP-01（本轮已按此处理 3 个域名）；
3. 建议增加宝塔侧证书到期巡检（当前巡检脚本只覆盖网关动态证书）；
4. 建立域名证书台账（本文件第六节为 2026-09-11 快照），随域名增减更新。
```
