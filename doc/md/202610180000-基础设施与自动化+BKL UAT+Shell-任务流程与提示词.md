# 任务流程与提示词

> 来源文件：`~/Projects/work/ops/devops/devops-bkl/workbench-kit-通用AI工作台/docs/04-任务流程与提示词.md`

> 整理日期：2026-10-18 00:00｜日期依据：正文日期

## 1. 任务 ID

建议格式：

```text
TASK-YYYYMMDD-序号
TASK-20261019-001
```

一个任务一个 ID，对应：

- `workbench/ACTIVE_TASKS.md` 一行
- `workbench/handoff/to-cc/<ID>-context.md`
- `workbench/handoff/to-cc/<ID>-plan.md`
- `workbench/handoff/from-cc/<ID>-result.md`
- `doc/YYYY年MM月DD日-事项/`

## 2. 标准流程

```text
① git status / git fetch / git log
② 读 AGENTS + START_HERE + ACTIVE_TASKS
③ 写 context
④ 写 plan
⑤ 只读核验
⑥ 执行第一步 → 通知
⑦ 执行第二步 → 通知
⑧ 技术验证 + 业务验证
⑨ 写 result + doc
⑩ 汇总发群
⑪ git commit
⑫ 提交结果发群
⑬ 更新 ACTIVE_TASKS / CURRENT_STATE
```

## 3. 风险分级

| 等级 | 判断 | 例子 |
| --- | --- | --- |
| `R0` | 只读 | `docker ps`、`curl -I`、查日志 |
| `C1` | 测试环境 / 低风险 | 改测试配置、重启测试容器 |
| `P2` | 生产 / 入口 / 权限 | DNS、证书、CDN、生产发布 |
| `D3` | 数据 | 改表、修数据、迁移 |
| `E4` | 事故 | 服务全挂、数据损坏、安全事件 |

同时命中多个时取最高。

## 4. Context 模板

```markdown
# TASK-20261019-001 Context

## 用户目标

- 把 UAT 的监控告警接到新群

## 已验证事实

- `VERIFIED`：Beszel 运行在 203.0.113.1:8090
- `VERIFIED`：当前告警群 chat_id 为 -100...

## 用户确认事实

- `USER_CONFIRMED`：新群由 SVD 创建

## 推断或未知

- `UNKNOWN`：新群 chat_id

## 目标范围

- 项目：UAT 运维
- 环境：UAT
- 服务器：43.x.x.x
- 仓库/分支：main

## 执行边界

- 允许：改 Beszel 通知配置
- 禁止：改监控采集项
- 停止条件：新群 chat_id 未确认

## 证据位置

- 日志：/opt/beszel/logs
- 备份：/opt/beszel/backup
- 相关文档：doc/2026年10月18日-...
```

## 5. Plan 模板

```markdown
# TASK-20261019-001 Plan

## 方案信息

- 风险等级：C1
- 方案版本：v1
- 批准状态：approved

## 执行前只读核验

- [ ] 确认 Beszel 容器状态
- [ ] 确认当前通知配置
- [ ] 确认新群 chat_id

## 分阶段步骤

1. 备份当前配置
2. 修改通知目标
3. 发送测试消息
4. 触发一次测试告警

## 回滚方案

- 恢复备份配置，重启 Beszel

## 验证方案

- 技术验证：测试消息返回 ok
- 业务验证：群内收到告警
- 回归检查：旧群不再收到
```

## 6. 可直接复制的提示词

### 6.1 开始新任务

```text
先读 AGENTS.md 和 workbench/START_HERE.md，按读取顺序读完
ACTIVE_TASKS / PROJECT_INDEX / MACHINE_ACCESS_MATRIX /
PROJECT_RUNTIME_CHAINS / NOTIFICATION_TARGETS /
CURRENT_STATE / CURRENT_TASK。

然后为 TASK-20261019-001 写 context：
- 只写已验证事实，未知项标 UNKNOWN
- 写清目标、范围、边界、停止条件
- 不猜服务器、端口、账号
写完先给我看，不要执行任何写操作。
```

### 6.2 只读排查

```text
这是 R0 只读排查。
只允许执行只读命令：状态、日志、版本、端口、HTTP HEAD。
不要重启、不要改配置、不要写数据库。
每一步先说明目的，再给命令，执行后把关键输出贴出来。
最后按「现象 / 证据 / 根因 / 建议」四段总结。
```

### 6.3 执行变更

```text
按 TASK-20261019-001 的 plan 执行。
执行前先做 plan 里的只读核验，任何一项不一致就停下来。
每完成一步发群通知：
【项目名｜任务名】步骤 N ...
通知里不发密码、token、连接串。
验证失败先修复，不要提交。
```

### 6.4 验证

```text
现在只做验证，不改任何配置。
按 plan 的验证方案逐条执行：
1. 技术验证：进程 / 端口 / HTTP / 日志
2. 业务验证：真实入口 / 关键流程
3. 回归检查：相邻功能
把每条结果写成 PASS / FAIL，FAIL 给出证据和修复建议。
```

### 6.5 交接给下一个 AI

```text
请把当前任务整理成 handoff：
- 已完成什么
- 改了哪些文件/资源
- 验证结果
- 未完成事项
- 下一步第一个动作
写到 workbench/handoff/from-cc/<TASK-ID>-result.md
不要写密码和 token。
```

### 6.6 收尾

```text
任务完成后：
1. 更新 workbench/ACTIVE_TASKS.md
2. 更新 projects/<slug>/CURRENT_STATE.md
3. 写 doc/YYYY年MM月DD日-事项/ 主文档
4. 运行 make check（或项目检查）
5. 汇总发群
6. 提交 Git
7. 提交结果发群
```

## 7. 通知模板

### 步骤通知

```text
【项目名｜任务名】步骤 1/5 前置检查
· 本地 main 与 origin/main 一致：abc1234
· 工作区干净
· 目标服务器 hostname 已核验
下一步：备份当前配置。
```

### 阻塞通知

```text
【项目名｜任务名】阻塞
· 阻塞点：新群 chat_id 未确认
· 已尝试：查 getUpdates、问群成员
· 需要：SVD 提供新群 chat_id
· 当前状态：暂停写操作，已完成的步骤不受影响
```

### 完成通知

```text
【项目名｜任务名】完成
· 提交：abc1234
· 验证：技术 PASS / 业务 PASS
· 文档：doc/YYYY年MM月DD日-事项/
· 遗留：无
```

## 8. 提交模板

```text
<动词>：<一句话说明>

- 任务：TASK-20261019-001
- 变更：<关键文件/资源>
- 验证：<检查命令与结果>
```

示例：

```text
修复：Beszel 告警切到新群

- 任务：TASK-20261019-001
- 变更：通知配置、备份脚本
- 验证：测试消息 ok，测试告警到达新群
```

## 9. 反模式

| 反模式 | 后果 | 正确做法 |
| --- | --- | --- |
| 一上来就执行命令 | 改错环境 | 先读事实，再只读核验 |
| 把聊天当文档 | 下次找不到 | 写进 doc 和 workbench |
| 计划写在脑子里 | 无法交接 | 写 context / plan |
| 验证只看命令返回 0 | 业务其实没通 | 加 HTTP / 入口 / 日志验证 |
| 密码写进脚本默认值 | 泄露 | 只读环境变量 |
| 一次改很多件事 | 出问题难定位 | 一个任务一个目标 |
| 失败后直接重试 | 掩盖根因 | 先保留证据，再修复 |
| 通知刷屏 | 团队忽略 | 每步一次，合并同一步的输出 |
