# 2026-08-25 监控报警抖动确认机制与假报警治理记录

项目：DBQP / PGServer master
范围：入口监控与容器监控假报警治理
执行人：Codex（本地工作区 + 备用机）

## 背景

```text
监控报警过频，大量为假报警。近 3 天报警记录显示：
- 绝大多数为单次 12 秒超时后 2 分钟自动恢复（瞬时抖动，如 ind-h5 入口偶发慢响应）；
- 2026-08-23 21:52 六个静态游戏页 SSL 证书验证批量失败一次（瞬时环境问题）；
- 2026-08-25 03:42 容器监控后端 02 SSH 握手失败一次后 4 分钟恢复。
根因：两个监控脚本均为“单次失败即报警、单次成功即恢复”，无确认机制，瞬时抖动全部触发报警。
```

## 处理

```text
1. entry_health_monitor.py：
   - 单入口超时 12s -> 20s（外部源站偶发慢响应更宽容）；
   - 连续失败 3 次（约 6 分钟）才报警，报警文案标注“连续 3 次失败”；
   - 连续成功 2 次（约 4 分钟）才发恢复通知；
   - 状态文件升级为 {fails, oks, alerted} 计数结构，兼容旧 {"name":"down"/"ok"} 自动迁移。
2. container_health_monitor.py：
   - 后端 SSH 不可达连续失败 3 次才报警、恢复连续成功 2 次才通知；
   - 容器异常/重启事件仍即时报警（不降级）；
   - 状态文件同样升级并兼容旧格式。
3. 环境变量可调：DBQP_MONITOR_FAIL_THRESHOLD / RECOVER_THRESHOLD、
   DBQP_CONTAINER_FAIL_THRESHOLD / RECOVER_THRESHOLD。
```

## 验证

```text
1. 状态机单元测试：fail 1/2 静默、fail 3 报警；ok 1 不恢复、ok 2 恢复；中断后计数重置，全部符合预期；
2. 入口监控备用机真实检查：OK（无假报警）；
3. 容器监控 dry-run：alerts=0 recovers=0（基线正常）；
4. 旧状态文件迁移：PG down -> alerted=true 不再重复报警。
```

## 结论

```text
瞬时抖动不再直接报警，只有持续约 6 分钟的故障才通知，恢复也需稳定约 4 分钟确认；
真故障（容器异常/重启/持续不可达）仍会第一时间报警，监控灵敏度与噪音平衡。
```
