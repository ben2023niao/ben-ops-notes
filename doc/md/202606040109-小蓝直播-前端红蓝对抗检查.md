# 前端红蓝对抗检查

> 来源文件：`~/Projects/work/game/xiaolan-watches/dev/docs/quality/frontend-red-blue-review.md`

> 整理日期：2026-06-04 01:09｜日期依据：文件创建/修改时间

目标：防止 Agent 越写越懒，防止工程占位 UI 混进产品实现。

## 蓝队提交前自检

1. 已在 `docs/design/design-coverage-matrix.md` 找到本次涉及设计图。
2. 已确认设计图尺寸、页面状态、公共组件候选。
3. 已复用公共组件，未在 screen/navigator 临时拼重复结构。
4. 已接入可用 API；未实现 API 已明确标注 mock/placeholder。
5. 已跑 `npm run check`，并做 375×812 或对应尺寸浏览器验收。

## 红队必须质疑

1. 这是不是看起来能用，但不像设计图？
2. 是否遗漏了同一模块的其他状态图？
3. 是否把跨页面公共挂件写死在单个页面？
4. 是否存在字符占位、工程 scaffold、默认深色卡片？
5. 是否只验证了页面 200，没有验证 API、console、静态资源？
6. 是否有截图/浏览器证据，还是只靠口头说“已对齐”？

## 合入标准

只有同时满足以下条件才允许说“完成”：

1. 设计覆盖矩阵状态已更新。
2. Agent 日志记录蓝队实现和红队质疑。
3. 自动检查通过：`npm run check`。
4. 浏览器验收通过，关键页面和 API 有证据。
5. 剩余偏差被写成明确待办，而不是藏起来。
