## 背景

```text
用户要求检查各厂家游戏能否正常加载打开；检查中发现三台后端容器版本不一致：
01/02 为 pgserver:master-514d8c77（7 天前），03 为 pgserver:master-b5bbfb16（8 天前）。
按用户要求把三台全部厂家容器统一发布到 GitLab 最新 master，访问策略验证版本差异。
```

## 检查与处理

```text
1. 游戏链路初检：
   - H5 七个入口（pg/vendor_a/pp/popok/vendor_c/vendor_d/g759）全部 200；
   - 外部游戏平台 games.repair127.com 200；api.repair127.com 需 uid 参数（404 属正常）；
   - 各厂家静态游戏页 200（pg 126 / vendor_a wondershow / pp openGame / ppk 29 / vendor_c power_crown / vendor_d iron-valor / g759 slorio）；
   - PG/PP 动态域名提供游戏页（200）；vendor_c/PANDA/vendor_a/G759 游戏页由静态域名提供，
     动态域名仅提供 API（vendor_c/vendor_d/vendor_a 动态页面路径 404/500、g759 动态页面 404 属路径模型差异，非故障）。
2. 数据库链路核查（用户提示）：
   - 宝塔 infra-gateway（haproxy）3306->MySQL 主 192.0.2.1、3309->从 192.0.2.1 正常；
   - 后端 01 vendor_d 容器到宝塔代理 3306/3309 TCP 均通；
   - haproxy 日志显示后端实际 MySQL 查询正常（延迟 1ms 级），无数据库连接故障。
3. 版本差异处理：
   - 发现 03 全部容器为 8 天前镜像 b5bbfb16（g759 之外未跟进 514d8c77）；
   - 首次发布被 git pull 拦截：三台 /opt/pgserver 均有未跟踪 docker/scripts/disk_cleanup.sh
     （与仓库新版本同名、内容 md5 一致，系上次磁盘清理任务部署遗留）；
   - 三台将该文件备份到 /tmp/disk_cleanup.sh.untracked.bak 后重试。
4. 统一发布：
   - 目标：GitLab master b3083550（gitlab.zg-qptest.com/platgames/server-release）；
   - 服务：pg / vendor_a / pp / popok / vendor_c / vendor_d / platform-api / g759（8 个启用服务）；
   - 策略：单机低负载构建（prod-01）+ 内网镜像分发；发布结果 3/3 成功。
```
