## 架构调整

- `cn` 分支不再部署或维护香港后端容器。
- 香港入口 Nginx：`192.0.2.14`。
- 外部已部署后端 01：`192.0.2.18`。
- 外部已部署后端 02：`192.0.2.19`。
- 巴西项目和巴西服务器未修改。

| PP | 9099 |

本地模板：`docker/deploy/hongkong/nginx-bizops.conf`。

## 防误部署

`docker/deploy/deploy_all_servers.py` 已移除原香港后端 inventory。如设置 `PGSERVER_DEPLOY_ENV=hongkong`，脚本会立即终止并提示香港后端部署已禁用，避免再向旧服务器发布 `cn` 代码。

## 旧后端处理

原香港后端 `192.0.2.16` 和 `192.0.2.17` 已不再承载 `cn` 业务。项目负责人已于 2026-07-16 确认两台后端服务器完成清理，它们不再属于当前运行架构或本分支维护对象。

本仓库曾执行以下项目清理：

- 删除每台 7 个 `bizops-*` 业务容器。
- 删除 `pgserver:cn-1e7cf5c` 镜像。
- 清理 Docker builder 构建缓存和本轮临时镜像文件。
- 删除 `/opt/pgserver` 代码、日志和发布脚本。
- 保留正在运行的 `beszel-agent` 监控容器。
- 当时为避免误删，本仓库的首轮清理未删除 `/opt/game_results_datas`。后续服务器由项目负责人自行完成最终清理，当前架构不依赖也不假设旧机仍保留任何数据。

清理后复核：

- `/opt/pgserver` 不存在。
- `bizops-*` 容器数量为 `0`。
- `pgserver` 镜像数量为 `0`。
- `8765` / `9090` / `9091` / `9096` / `9101-9104` 无本地监听进程。
- 上述复核是首轮清理当时的历史状态；最终服务器清理由项目负责人完成，不再从 `cn` 分支登录、部署或巡检这两台机器。

## 连通性复核和当前阻塞

2026-07-16 从香港入口机 `192.0.2.14` 实测两台新后端：

- `80` / `443` 连接被拒绝。
- `8765` / `9018` / `9090` / `9091` / `9096` / `9098` / `9099` 连接超时。
- Nginx error log 明确记录连接 `192.0.2.18:9090/9091` 和 `192.0.2.19:9090/9091` 超时。
- `api.hkplaycore.com` 和 `verify.hkplaycore.com` 当前返回 `504`。
- `pg-static.hkcloudplay01.com` 代表性静态资源仍返回 `200`，证书、Cloudflare/CDN 和静态反代未受影响。

当前需要新后端侧完成以下任一处理：

1. 在防火墙/安全组中允许来源 `192.0.2.14/32` 访问 TCP `8765,9018,9090,9091,9096,9098,9099`；或
2. 如新后端实际只对外提供统一 `80/443` 端口，提供各厂商的域名/路径映射，再相应调整入口 upstream。

在新后端端口可达前，动态 API、verify 和游戏入口无法通过最终验收。

## PP 静态资源反代修复

2026-07-16 排查 `https://ind-h5.bizopsplus999.com/pponline/` 点击 PP 游戏后的 404，入口日志确认浏览器请求了错误路径 `/gs2c/desktop/bootstrap.js`。

根因是静态反代原先使用：

```nginx
rewrite ^/(.*)$ /$bizops_gcs_bucket/$1 break;
```

`$bizops_gcs_bucket` 来自正则 `map`，求值时会覆盖位置捕获 `$1`，导致对象路径丢失，实际回源到 GCS 桶根目录。桶根目录返回 `200 application/xml` 的对象列表，因此此前只检查状态码的探针会产生误判。

现已改为不依赖位置捕获：

```nginx
rewrite ^ /$bizops_gcs_bucket$uri break;
```

同时参考巴西项目，为 5 个 `pp-static.hkcloudplay0[1-5].com` 增加 `customizations.info` 空 `200` 兜底。

发布验证：

- 线上 `nginx -t` 成功并完成 reload。
- 5 个 PP 静态域名的 `customizations.info` 均为 `200 application/octet-stream`、`0` 字节。
- 5 个 PP 静态域名的 `html5-script-external.js` 均为 `200 text/javascript`、`4104` 字节。
- 5 个 PP 静态域名的 `vs20starprss/desktop/bootstrap.js` 均为 `200 text/javascript`、`102781` 字节。
- PG、vendor_a、PPK、PANDA 代表性静态对象均返回真实内容，不再返回 GCS XML 桶列表。
