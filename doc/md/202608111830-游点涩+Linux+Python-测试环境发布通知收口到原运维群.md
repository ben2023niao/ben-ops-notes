# 测试环境发布通知收口到原运维群

## 背景

用户要求：

```text
测试环境发布 和自动化发布信息不要发 18game运维 群。
```

并贴出人工发布消息示例（运维-@Ben_Bird，git id 2926c1fd0fb0）：

```text
【游点涩-后端-dev】发布占用（发布中/空闲）
【游点涩-后端-dev-2926c1fd0fb0】发布开始
【游点涩-后端-dev-2926c1fd0fb0】发布成功
📎 【游点涩-后端-dev-2926c1fd0fb0】详细部署日志
```

## 现状

```text
2026-08-07 已把 Webhook 自动发布通知收口到原运维监控报警群（TG_WEBHOOK_CHAT_IDS）。
但人工网页发布仍走全量群：发布占用、发布开始/成功/失败、详细部署日志会同时发到
原运维监控报警群和 18game运维 群。
```

## 改动

### 1. 配置

```text
cicd-web/config.py：新增 TG_PUBLISH_CHAT_IDS（发布类通知专用群），
  兼容旧名 TG_WEBHOOK_CHAT_IDS；未配置时回退全量群。
cicd-web/config/settings.json：telegram 增加 publish_chat_ids: []。
```

### 2. 通知覆盖

```text
cicd-web/telegram.py：set_publish_chat_override / clear_publish_chat_override
  （旧名 set/clear_webhook_chat_override 保留兼容别名）。
```

### 3. 发布会话挂接（核心）

```text
cicd-web/core.py：
  try_begin_publish_session 获取发布锁后启用发布专用群覆盖；
  finish_publish_session 结束发布会话后清理覆盖（若锁已被强制踢出则跳过结束通知）；
  force_release_publish_session 强制踢人后清理覆盖。
覆盖范围：人工发布全部步骤、Webhook 自动发布、发布会话内的运行配置同步。
cicd-web/webhook.py：移除重复的专用群设置，统一由 try_begin/finish 管理。
```

### 4. 服务器运行密钥

```text
/opt/docker-youdianse-php/cicd-web/runtime/secrets.env：
  TG_WEBHOOK_CHAT_IDS → TG_PUBLISH_CHAT_IDS（同值，只写服务器本地，不提交 Git）。
```

## 效果

```text
发布会话内所有通知只发原运维监控报警群：
  发布占用（发布中/空闲）、发布开始/成功/失败、详细部署日志、强制踢人、运行配置同步。
文档/步骤通知、健康告警：仍发已配置群（原运维监控报警群 + 18game运维）。
```

## 验证

```text
1. 本地：python3 -m py_compile 通过；TG_PUBLISH_CHAT_IDS 解析/旧名兼容/回退全量通过；
   try_begin/finish 覆盖设置与清理行为通过（dry-run）。
2. 测试服务器：重启 CICD Web 后 TG_CHAT_IDS=2、TG_PUBLISH_CHAT_IDS=1。
3. 模拟发布会话：try_begin_publish_session 后发送目标为 1 群（仅原运维群），
   finish_publish_session 后恢复 2 群。
4. CICD Web 18090 HTTP 200。
```

## 回滚

```text
1. 回退运维仓库本次提交并同步 /opt。
2. 用 secrets.env 修改前备份恢复 TG_PUBLISH_CHAT_IDS / TG_WEBHOOK_CHAT_IDS。
3. 重启 CICD Web。
```

## 安全要求

```text
不输出、不记录、不提交 Telegram token/chat_id、SSH 密码、发布密码、私钥和带凭据仓库 URL。
TG_PUBLISH_CHAT_IDS 只写测试服务器 secrets.env。
```
