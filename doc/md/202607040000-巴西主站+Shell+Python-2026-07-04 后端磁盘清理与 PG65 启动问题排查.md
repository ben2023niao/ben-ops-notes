## 已固化到 docker/deploy 的策略

本次把发布前清理策略固化到：

```text
docker/deploy/update_pgserver.py
docker/deploy/deploy_all_servers.py
docker/deploy/README.md
```

新增参数：

```text
PGSERVER_DEPLOY_HISTORY_CLEAN_THRESHOLD
默认值: 75
含义: 根分区使用率达到该值时，清理较老且未使用的 Docker 历史镜像和 build cache。

PGSERVER_DEPLOY_HISTORY_CLEAN_UNTIL
默认值: 168h
含义: 只清理该时间以前的未使用 Docker 镜像和 build cache。

PGSERVER_DEPLOY_DEEP_CLEAN_THRESHOLD
默认值: 85
含义: 达到该值时，才执行无时间限制的深度 Docker 清理。
```

发布前清理分层：

1. 总是打印 `df -h /` 和 `docker system df`。
2. 总是清理历史 `/tmp/pgserver-image-*.tar*`，保留本次 `--image-tar`。
3. 总是执行 `docker container prune -f` 和 `docker image prune -f`。
4. `>= 75%` 时清理 `168h` 以前未使用镜像和 build cache。
5. `>= 85%` 时才做深度 `docker image prune -af` 和 `docker builder prune -af`。

## PG65 / Mahjong Ways 复测结论

### 接口状态

本地 curl 复测：

```text
POST https://pg-games.xqv9m8.icu/cdn-cgi/rum? -> 404 text/html, body 来自 Cloudflare
GET  https://pg-games.xqv9m8.icu/65/index.html?... -> 200 text/html
GET  https://pg4-static.m7v8k3.cyou/65/922d4f1ffd.f244d.json -> 200 application/json
GET  https://verify.repair127.com/web-api/auth/session/v2/verifyOperatorPlayerSession -> 405
```

解释：

- `/cdn-cgi/rum` 是 Cloudflare Browser Insights / RUM 埋点路径。
- PG65 HTML 内置了 `https://static.cloudflareinsights.com/beacon.min.js/...`。
- 该 beacon 会向当前域名的 `/cdn-cgi/rum?` 上报。
- 404 响应体来自 Cloudflare，不是 PG 业务接口，也不是 platform-api。
- 源站 Nginx 或 PG 服务通常接不到 `/cdn-cgi/*`，因此不能靠给 PG 服务加普通路由解决。
- 如果测试只看到这条红色请求，建议先忽略它；要消除红色噪音，需要从 HTML 移除 Cloudflare beacon，或在 Cloudflare 侧正确启用/配置对应 RUM。

### 更值得开发排查的 PG65 点

PG65 的 verify 模板存在：

```text
pg/data/operator/65/verifyOperatorPlayerSession.json
pg/data/verifySession/65/verifySession.json
```

但模板内：

```json
"gm": [
  {
    "gid": 1543462
  }
]
```

实际 PG65 应为：

```text
gid = 65
```

全量检查结果：

```text
pg/data/operator      有 123 个 game 目录的 gm[0].gid 固定为 1543462
pg/data/verifySession 有 123 个 game 目录的 gm[0].gid 固定为 1543462
```

`pg/server.py` 里 `verify_operator_player_session` 曾有动态修正逻辑，但当前是注释状态：

```python
# verify_data["dt"]["gm"][0]["gid"] = gameid
```

`verify_session` 当前也没有给 `verify_data["dt"]["gm"][0]["gid"]` 动态赋值。

建议给开发的话术：

```text
PG65 Mahjong Ways 入口页和 pg4-static 资源 200，platform-api 登录和 launcher 生成正常。
浏览器里的 /cdn-cgi/rum 404 是 Cloudflare RUM 埋点，不是游戏认证接口。
真正需要重点看 PG verify 响应：pg/data/operator/65 和 pg/data/verifySession/65 的 gm[0].gid 仍是 1543462，不是 65；server.py 里 operator verify 的动态覆盖 gid 代码被注释，verifySession 也没有覆盖。
请开发确认新版 PG 客户端是否会校验 gm[0].gid。如果会，请在 verifyOperatorPlayerSession 和 verifySession 返回前统一执行：
verify_data["dt"]["gm"][0]["gid"] = int(gameid)
并检查 123 个模板固定 gid 是否会影响其他 PG 游戏。
另外 PG 容器刷屏的 sync_gametoday_to_mysql today_users ambiguous SQL 也需要修复，但它不是 /cdn-cgi/rum 404 的来源。
```

## PG API 跨域修复

用户后续截图显示真实 blocker：

```text
Access to XMLHttpRequest at
https://api.xqv9m8.icu/web-api/auth/session/v2/verifyOperatorPlayerSession?traceId=...
from origin https://pg-games.xqv9m8.icu
has been blocked by CORS policy: No 'Access-Control-Allow-Origin' header is present.

https://api.xqv9m8.icu/api/report/timing -> 520
```

线上复测修复前：

```text
OPTIONS https://api.xqv9m8.icu/web-api/auth/session/v2/verifyOperatorPlayerSession -> 520
POST    https://api.xqv9m8.icu/web-api/auth/session/v2/verifyOperatorPlayerSession -> 520
POST    https://api.xqv9m8.icu/api/report/timing -> 520
```

根因：

- 新版 PG 客户端在 `pg-games.<root>` 启动，但验证接口仍请求 `api.<root>`。
- 宝塔活跃 Nginx 站点 `pg-games.xqv9m8.icu.conf` 只包含 `pg-games.*`，没有包含 `api.*`。
- 历史 `api.xqv9m8.icu.conf.category-split-disabled-...` 文件已禁用，不会被 Nginx 加载。
- 因此 Cloudflare 请求 `api.xqv9m8.icu` 时源站没有有效活跃站点，返回 520，浏览器表现为 CORS 缺失。

已改动的运维文件：

```text
docker/线上服务器信息/baota/scheduled-tasks/sanitized/sync_all_game_domains_to_baota.py
docker/线上服务器信息/baota/nginx/panel-vhost-nginx/common/all-games-proxy.conf
```

修复内容：

1. `sync_all_game_domains_to_baota.py`
   - 增加 `PG_API_PREFIX = "api"`。
   - PG game 站点域名从 22 个 `pg-games.*` 扩展为 44 个：`pg-games.*` + `api.*`。
   - `managed_prefixes` 加入 `api`，同步时会把 22 个 `api.*` 域名归到 PG 活跃站点 id `35`。
   - platform-api 的 `pg.json` 仍只保留 `pg-games.*` 作为 game_hosts，不把 `api.*` 暴露给 launcher。

2. `all-games-proxy.conf`
   - `api.*` host 路由到 `pg_game_backend`。
   - `OPTIONS` 预检统一返回 204，并补充：

```nginx
Access-Control-Allow-Origin: *
Access-Control-Allow-Methods: GET, POST, OPTIONS
Access-Control-Allow-Headers: *
```

   - `@pg_game_backend` 统一补 CORS 响应头，并 hide 上游已有 CORS 头，避免重复/冲突。
   - `/api/report/timing` 直接返回 204，消除 PG HTML 注入 `shared/report.js` 带来的 520 噪音。

```text
PG 活跃站点 server_name:
22 个 pg-games.* + 22 个 api.*

POST    https://api.xqv9m8.icu/api/report/timing -> 204
```

空参数 POST 返回 400 是预期行为，说明请求已经到 PG 后端；真实游戏请求带 `gi/otk/os` 时应继续走 PG verify 逻辑。
