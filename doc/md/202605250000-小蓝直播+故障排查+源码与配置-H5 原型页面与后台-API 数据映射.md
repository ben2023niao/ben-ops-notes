# H5 原型页面与后台/API 数据映射

> 来源文件：`~/Projects/work/game/xiaolan-watches/dev/docs/api/h5-admin-public-api-mapping.md`

原则：不再拆 `h5-*` 前台接口；前台统一使用 `/api/v1/...`，PC 后续复用同一套读取接口。

## 当前修复结论

| H5 页面/组件 | 后台怎么管理 | 前台怎么拿数据 | 本轮状态 |
| --- | --- | --- | --- |
| 首页广告/浮层/入口广告 | 后台「广告管理」维护广告位和广告内容：`GET/POST/PATCH/DELETE /api/v1/admin/ads/slots`、`/api/v1/admin/ads/creatives` | `GET /api/v1/ads/slots`，`GET /api/v1/ads/slots/{slot_code}/creatives` | 已补统一公开读取接口、OpenAPI、后台契约 |
| 首页 Banner/主推比赛 | 后台「系统配置/赛事」维护 Banner 或主推赛事 | `GET /api/v1/home`、`GET /api/v1/matches` | 已在契约里保留；旧 Banner 入口后续按 ADR 清理 |
| 赛事列表/比分 | 后台「赛事 & 比分」「球队管理」维护球队、比赛、比分、进球、MVP | `GET /api/v1/matches`、比赛详情相关接口 | 已修 admin YAML 的球队、比赛创建/编辑/比分/结果/进球字段 |
| 直播间基础信息 | 后台「直播间管理」「主播管理」维护房间、主播、封面、关联赛事、推流密钥 | `GET /api/v1/live/rooms`、`GET /api/v1/live/room/{room_id}`、播放 token 接口 | 已修 `refresh-token` 为 POST，并同步 web 调用 |
| 直播间线路选择 | 后台新增/接入「直播线路」页面，维护 code/name/edge_url/recommended/enabled/sort_order | `GET /api/v1/live/lines`，`POST /api/v1/live/lines/select` | 已补 admin 页面、admin API 契约、public API 契约；前端可先用假播放切流，但后台数据源已具备 |
| 直播间竞猜卡片 | 后台「竞猜活动」维护活动、选项、开盘/关盘/结算/退款 | `GET /api/v1/predict/activities`、投注接口 | 已修 admin create/settle/pending-settle-count/list 契约 |
| 充值页 | 后台「支付通道」维护通道开关、手续费、推荐状态；系统配置维护充值金额/限额 | `GET /api/v1/wallet/channels`，`GET /api/v1/config/system` | 已补 public/admin YAML；后台接口已有，支付通道 UI 待接菜单页 |
| 提现页/提现订单 | 后台「提现订单」审核、派单、成功/失败回执、出款流水 | 钱包提现相关接口 | 已补 `mark-paid`、`mark-success`、`mark-failed`、`disbursements` YAML |
| 图片上传 | 后台通用上传组件供广告、主播头像、房间封面使用 | 无公开读取；返回 URL 后由业务对象引用 | 已补 `POST /api/v1/admin/upload` YAML |
| 用户/个人信息 | 后台「用户管理」维护冻结、解冻、调账、重置密码 | `GET /api/v1/me` 等会员接口 | 本轮未改，保留既有实现 |

## 已识别待收口

1. 支付通道后台接口和 YAML 已对齐，但 admin 菜单页还未补。
2. 旧 `/api/v1/config/h5-ads`、`/api/v1/admin/ads/h5` 属于早期 H5 专用入口，后续应按统一广告位模型下线，避免新项目继续背兼容包袱。
3. 仍需按原型继续逐页核对：钱包明细、个人中心、等级权益、直播间互动/弹幕、竞猜中心独立页。
