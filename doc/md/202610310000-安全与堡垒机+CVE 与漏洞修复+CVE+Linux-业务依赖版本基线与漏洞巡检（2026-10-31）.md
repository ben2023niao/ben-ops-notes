## 目标

- 记录全部服务器上的业务运行时、中间件和关键组件版本。
- 判断是否有新版本以及是否适合升级。
- 查询当前版本的公开漏洞与可利用条件。
- 建立可重复比对的固定 MD、JSON 基线和采集/比较脚本。

## 覆盖

- 可 SSH 巡检：堡垒机、middleware、manager、worker01、worker02。
- 无 SSH：SRS 韩国、SRS 新加坡，通过 Beszel 容器元数据覆盖。
- 当前 24 个业务 Swarm 服务、48 个任务全部运行。
- 本次没有执行组件升级，避免未经测试的数据库、协议和直播链路变更。

## 关键结果

- 5 台 UAT 主机运行时一致：Ubuntu 24.04.5、Docker 29.9.1、containerd 2.4.2、runc 1.5.2、Compose 5.6.0、Python 3.12.3。
- 24 个业务服务均使用 `1.0.0-uat`，运行 OpenJDK 17.0.10；当前 Java 17 最新安全线为 17.0.21。
- 业务主框架：Spring Boot 3.3.13、Spring Framework 6.1.21、Tomcat 10.1.42、Jackson 2.17.3、Log4j 2.23.1、Kafka Client 3.7.2。
- 业务 JAR 同时存在旧传递依赖 Jackson 2.3.3、Jetty 8.1.15、Jettison 1.1、Snappy 203.0.113.1，风险明显高于主框架版本。
- Beszel 标记 11 个容器实例有镜像更新。
- MySQL 5.7.44、Redis 5.0.14、Node 18 已过生命周期，不应继续作为长期基线。

固定人工基线见 `workbench/BUSINESS_DEPENDENCIES.md`，机器基线与比对工具见 `workbench/business-dependencies-baseline.json` 和 `code/ops-scripts-运维部署脚本/dependency/`。

本次实采基线共 15,094 项，包括 48 个业务 Java 运行时、115 个容器镜像记录、101 个镜像 ID 和 14,788 条 JAR 依赖记录。采集脚本已在 5 台可 SSH UAT 主机实际运行。

## 更新判断

### 适合测试后更新的小版本

- GitLab 19.5.0 → 19.5.1：同 minor 补丁，先备份配置、数据库和升级路径。
- Grafana 13.0.11 → 13.3.0：新版本修复多项安全 CVE，需检查插件、数据源和面板兼容性。
- Alertmanager 0.34.1 → 0.34.2：修复 CVE-2026-111943；新版本默认不再返回 CORS 头，已有跨域调用需调整。
- Portainer Agent 2.45.2 → 2.45.3：包含安全修复；新版不再信任受影响的 eMudhra CA，需先核对 OIDC/LDAP/Registry。
- RocketMQ 5.5.0 → 5.5.1：移除 fastjson1，fastjson2 升到 2.0.63；Broker/NameServer 需要滚动验证。
- RabbitMQ 3.13.6 → 3.13.7：低成本补丁；升级到 4.x 属于大版本迁移。
- Docker 29.9.1 → 29.9.2、Compose 5.6.0 → 5.6.1：维护窗口验证即可。

### 有条件更新

- Beszel 0.21.0 → 0.21.1：Hub 有中文告警补丁，必须重新构建；Agent 要与 Hub 一起验证。
- GitLab `latest` 与 SRS `6`、Nginx `alpine`、Prometheus `v3`、Alertmanager `v0` 等浮动 tag 不可复现，应改为固定精确版本或 digest。
- SRS 6.0 当前 tag 更新到 6.0-r3：涉及在线流，使用双机滚动和回退 digest。
- Jenkins 2.541.3 → 2.580.2：跨多个 LTS，需要按升级指南检查插件兼容。
- Nginx 1.27.5/1.29.0 → 1.31.8：先验证配置语法、上游健康检查和模块。
- Harbor 2.15.2 → 2.15.4：同系列补丁，备份 Harbor DB 后维护窗口升级。

### 不建议直接更新

- JumpServer 4.10.19 → 5.1.1：跨大版本，需迁移评估、备份和回滚演练。
- Nacos 3.0.2 → 3.3.0：认证默认和客户端兼容变化，业务 Nacos Client 2.4.3 不能直接跟随。
- XXL-JOB 3.4.0 → 3.5.0：AccessToken 改为执行器维度，有数据库脚本和调度中心/执行器协议升级，必须一起升级。
- Elastic Stack 8.17.4 → 9.5.5、Kafka 3.9 → 4.x：跨大版本。
- MySQL 5.7.44 与 Redis 5.0.14：没有安全的小版本路线，应设计蓝绿迁移。

## 优先处置建议

1. 先由开发移除业务 JAR 中的 Jackson 2.3.3、Jetty 8.1.15 等旧传递依赖，并升级 Spring Boot/Spring Framework/Tomcat 到受支持补丁线。
2. 把业务基础镜像升级到 17.0.21，重新构建全部 24 个镜像。
3. 为 MySQL 5.7、Redis 5、Node 18 建立迁移项目；不再继续把它们视为可维护版本。
4. 在维护窗口依次验证 MySQL 8.0.46、Harbor 2.15.4、GitLab 19.5.1、Alertmanager 0.34.2、Grafana 13.3.0。
5. JumpServer、Nacos、XXL-JOB、Elastic Stack、Kafka 大版本升级进入独立变更计划。

## 固定巡检机制

```bash
# 每台 Linux 主机
sudo bash code/ops-scripts-运维部署脚本/dependency/collect_inventory.sh > "/var/tmp/deps-$(hostname -s).txt"

# 汇总比较
python3 code/ops-scripts-运维部署脚本/dependency/compare_inventory.py \
  --baseline workbench/business-dependencies-baseline.json \
  /var/tmp/deps-*.txt
```

比较器会报告新增、删除和值变化；可用 `--notify-script` 触发 Telegram。只有人工确认后才更新基线，防止自动把异常版本变化“洗白”。

验证结果：

- 相同快照与基线比较返回“依赖快照与基线一致”，退出码 0。
- 构造测试快照后正确识别新增 1、删除 1、版本变化 1，退出码 1。
