## 背景

```text
线上游戏需时刻监控可用状态，不能等业主客户反馈才处理（G759 两次故障均客户先发现）。
要求：巡检全部厂家全部游戏能否加载、能否进游戏、能否玩，异常自动报警到飞机群。
```

## 实现

```text
1. 扩展 docker/scripts/post_deploy_browser_smoke.py：
   - TARGETS 增加 G759（入口 https://ind-h5.bizopsplus999.com/g759bronlineone/），
     现覆盖 7 家：pg / vendor_a / pp / popok / vendor_c / vendor_d / g759；
   - 复用其成熟链路：打开大厅 -> 点击游戏卡片 -> 等待游戏 shell 加载（canvas/frame）
     -> 试玩点击 -> 输出通过/失败与截图。
2. 新增 docker/scripts/game_availability_monitor.py：
   - 每厂家抽样 1 个游戏（某业务公司_GAME_MONITOR_CARDS_PER_GAME 可调）；
   - 连续失败 3 次（约 45 分钟）才报警、连续成功 2 次（约 30 分钟）才发恢复
     （与入口/容器监控确认机制一致，避免瞬时抖动误报）；
   - 状态文件 /var/tmp/bizops-game-availability.json 防重复报警；
   - 报警含厂家与失败摘要，恢复单独通知。
3. 备用机部署：
   - 安装 pip + playwright + chromium（headless shell，约 115MB）；
   - cron：*/15 * * * * 运行 game_availability_monitor.py（全厂家模式），日志 /var/log/bizops-game-availability.log。
4. 2026-08-26 14:10 优化（按用户要求缩短报警时效）：
   - game_availability_monitor.py 支持 --vendor <厂家> 单厂家模式，状态文件按厂家独立
     （/var/tmp/bizops-game-availability-<vendor>.json），多 cron 并行互不冲突；
   - 备用机改为 7 个单厂家 cron，每厂家每 2 分钟一次：
     偶数分钟 pg / vendor_a / pp / popok，奇数分钟 vendor_c / vendor_d / g759（错开避免同刻全并发）；
   - 报警时效：连续失败 3 次 -> 约 6 分钟报警（原约 45 分钟），恢复连续 2 次确认。
```

## 验证

```text
1. 单家：本地 PG、备用机 G759 均 browser_smoke=OK；
2. 全厂家试跑 7/7 全部 OK（pg/vendor_a/pp/popok/vendor_c/vendor_d/g759），
   真实浏览器均能打开大厅->点击->加载->试玩；
3. cron 3 条：入口监控(2min)、容器监控(2min)、游戏可用性巡检(15min)；
4. cron 更新后：入口监控(2min)、容器监控(2min)、游戏可用性 7 个单厂家任务(各 2min)；
5. 状态文件记录 7 厂家均为 alerted=false、oks=1；单厂家模式 PG 实测通过。
```

## 结论

```text
全部厂家游戏已纳入自动巡检：每 15 分钟真实浏览器验证游戏加载/进入/试玩，
连续失败自动报警到飞机群；G759 等新厂家入口已覆盖，避免“客户先发现”的情况。
```
