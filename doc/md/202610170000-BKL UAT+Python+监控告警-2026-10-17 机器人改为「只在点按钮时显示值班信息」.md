# 2026-10-17 机器人改为「只在点按钮时显示值班信息」

> 来源文件：`~/Projects/work/ops/devops/devops-bkl/doc/2026年10月17日-关闭值班自动推送与启动通知/2026年10月17日-关闭值班自动推送与启动通知.md`

> 整理日期：2026-10-17 00:00｜日期依据：文件名日期

| 项 | 内容 |
| --- | --- |
| 日期 | 2026 年 10 月 17 日 |
| 事项 | 关闭值班信息的定时推送；关闭机器人启动时的在线通知 |
| 原因 | 群里反馈：值班信息不要自动发到报警群，启动也不要"啥都报告" |

## 一、调整前的问题

机器人每天会往报警群推三条值班消息（08:30 值班提醒 / 09:00 值班开始 / 19:00 值班结束），每次容器重启还会发一条"ben-bot 已恢复在线"的启动通知。

10-17 19:00 那条"🌙 值班结束"发到 BKLUAT ALARM 后，SVD 明确说"值班信息先别发这里"，Ben 也确认"别一启动啥都报告"。

## 二、改动

### 1. 关闭值班定时推送

`app/benbot/duty_status.py`：

```python
# 值班信息只在点「运维值班表」按钮时查看，不自动推送。
DUTY_NOTIFY_CHAT_IDS: tuple[str, ...] = ()   # 原来是 ("-1004438007285",)
```

`app/benbot/main.py` 的 `schedule_duty_event_notices()` 增加前置判断：没配推送目标就直接返回，不再注册 08:30 / 09:00 / 19:00 的定时任务，也不注册每分钟刷新任务。

### 2. 关闭启动通知

`main()` 里删掉 `send_startup_notice(updater, update_notice)` 调用。机器人启动只写日志，不再往任何群发"已恢复在线"。

## 三、验证

重新部署后看容器日志：

```
apscheduler.scheduler - INFO - Scheduler started
benbot.state - INFO - 值班提醒未配置推送目标，跳过定时任务（只支持按钮查看）
benbot.state - INFO - ben-bot started.
```

- 日志里**没有**"准备发送启动通知"✓
- 日志里**没有** `duty:shift_remind / shift_start / shift_end` 的注册记录（计数 0）✓
- 「运维值班表」按钮仍正常：容器内跑 `duty_schedule.py` 输出今天/本周安排 ✓

## 四、现在的行为

| 场景 | 行为 |
| --- | --- |
| 点「📅 运维值班表」 | 显示值班人、工作时间、今天状态、本周七天安排 |
| 每天 08:30 / 09:00 / 19:00 | 不发任何消息 |
| 容器重启 | 不发任何消息（只写日志） |
| 监控告警 | 照旧发报警群（这个不受影响） |

## 五、以后要恢复推送

把群 ID 填回 `duty_status.py` 的 `DUTY_NOTIFY_CHAT_IDS`，重启容器即可恢复三条定时提醒；启动通知如果也要恢复，把 `main()` 里那行 `send_startup_notice(...)` 加回去。
