# 2026-07-16 香港 PP 静态资源 Nginx 特殊处理与验证记录

## 处理范围

- 问题入口：`https://ind-h5.bizopsplus999.com/pponline/`
- 香港入口 Nginx：`192.0.2.14`
- PP 静态域名：`pp-static.hkcloudplay01.com` 至 `pp-static.hkcloudplay05.com`
- 配置模板：`docker/deploy/hongkong/nginx-bizops.conf`
- 线上配置：`/etc/nginx/sites-available/bizops-hongkong.conf`
- 巴西项目仅用于参考，未修改巴西代码、配置或服务器。

## 故障现象和根因

PP 试玩入口点击游戏后出现多条 `404`。入口日志确认浏览器请求了错误路径：

```text
/gs2c/desktop/bootstrap.js?key=9b893
```

继续检查发现，香港静态域名请求 JavaScript 时虽然返回 HTTP 200，内容实际是 `application/xml` 的 GCS 桶对象列表，不是真实 JavaScript。

原静态反代使用：

```nginx
rewrite ^/(.*)$ /$bizops_gcs_bucket/$1 break;
```

`$bizops_gcs_bucket` 由正则 `map $host` 计算。Nginx 计算该变量时会覆盖位置捕获 `$1`，使原始对象路径丢失，最终只访问 GCS 桶根目录。桶根目录返回 HTTP 200，因此此前只检查状态码的探针产生了误判。

## 修复内容

### 修正 GCS 对象路径

静态回源改为不依赖位置捕获：

```nginx
rewrite ^ /$bizops_gcs_bucket$uri break;
```

该修复同时覆盖香港的 PP、PG、vendor_a、PPK、vendor_c、PANDA 静态域名。

### 增加 PP 特殊处理

参考巴西项目，把 PP 静态域名从通用静态 server 中拆出并增加：

```nginx
location ~* /customizations\.info$ {
    default_type application/octet-stream;
    return 200 "";
}
```

任意 PP 游戏目录下的 `customizations.info` 均返回空文件 200，避免缺失文件产生无意义的 404。

## 部署记录

部署过程：

1. 上传新配置到香港入口机临时路径。
2. 备份线上配置。
3. 覆盖 `/etc/nginx/sites-available/bizops-hongkong.conf`。
4. 执行 `nginx -t`。
5. 语法检查成功后执行 `systemctl reload nginx`。

保留的线上回滚备份：

```text
/etc/nginx/sites-available/bizops-hongkong.conf.bak.20260716085346
/etc/nginx/sites-available/bizops-hongkong.conf.bak.20260716085515
```

两轮 `nginx -t` 和 reload 均成功，未触发回滚。

## 公网验证结果

`pp-static.hkcloudplay01.com` 至 `pp-static.hkcloudplay05.com` 全部通过：

| 检查项 | 结果 |
| --- | --- |
| `customizations.info` | `200 application/octet-stream`，0 字节 |
| `gs2c/common/js/html5-script-external.js` | `200 text/javascript`，4104 字节 |
| `vs20starprss/desktop/bootstrap.js` | `200 text/javascript`，102781 字节 |

`pp-games.hkcloudplay01.com` 至 `pp-games.hkcloudplay05.com` 根路径均返回应用层 `403`，说明 5 个动态域名均已到达 PP 后端。

其他静态域名也已做代表性回归，真实对象内容可以正常返回，不再退化为 GCS XML 桶列表。

后续静态资源验收不能只检查 HTTP 状态码，还应同时检查 `Content-Type`、响应大小以及文件内容或固定哈希。
