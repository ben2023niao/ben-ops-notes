## 二、容器监控调整

### 2.1 问题

备用入口机原有两个重叠定时任务：


用户要求取消历史遗留的完整健康巡检，只保留“发生重启则通知群”。

### 2.2 调整结果

- `container_health_monitor.py` 定时任务已加 `#DISABLED-20261028` 前缀停用，脚本保留。

  - cron stdout 与日志文件双写问题已修复。
- 新脚本保留 `--show`、`--dry-run`、`--test-notify` 运维入口。

## 三、G759 20261028 重启故障

### 3.1 影响

巴西 01/02、香港 01/02 四台 G759 均处于 Restarting；其他厂家正常。

四台共同报错：

```text
File "/app/g759/g759.py", line 63, in <module>
  from history_details_codec import (
      HistoryDetailsCodecError,
      decode_history_details,
      encode_history_details,
  )
ModuleNotFoundError: No module named 'history_details_codec'
```

### 3.2 根因

- `ben f8e49c4b` 的 `g759/g759.py` 已新增导入。
- 同一提交的 Git 树中不存在 `g759/history_details_codec.py`。
- 20261028-ben 镜像中同样没有该模块，启动后立即重启。
- 20261023-ben 镜像也没有该模块，但旧版 `g759.py` 不导入它，因此可回滚运行。

### 3.3 临时处置

按巴西 01 → 巴西 02 → 香港 01 → 香港 02 顺序执行：

```bash
cd /data/server-runtime
sh start.sh g759 20261023-ben
```

最终状态：

```text
BR01 running restarts=0 game-service-g759:20261023-ben
BR02 running restarts=0 game-service-g759:20261023-ben
HK01 running restarts=0 game-service-g759:20261023-ben
HK02 running restarts=0 game-service-g759:20261023-ben
```

其他厂家保持 `20261028-ben`，未重启。

### 3.4 开发修复要求

1. 提交 `g759/history_details_codec.py`。
2. 至少提供：
   - `HistoryDetailsCodecError`
   - `decode_history_details`
   - `encode_history_details`
3. 构建前执行 `python -c "import history_details_codec"`。
4. 补历史详情 encode/decode 单元测试。
5. 重打 G759 镜像，不再发布缺少模块的 20261028-ben。
6. 按巴西 01→02、香港 01→02 顺序更新，确认 running、RestartCount 不增长。

详细报错和修复步骤已发群 message_id=589。
