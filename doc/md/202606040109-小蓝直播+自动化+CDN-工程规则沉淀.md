## 代码与契约

1. 业务代码开发前，先确认 PRD、需求 ID 和契约。
2. API 字段来自 `packages/contracts`，每个 operation 必须能追踪到 `docs/prd/requirements.md` 的需求 ID。
3. 数据模型变更必须更新 `docs/architecture/data-model.md`。
4. 重大架构决策必须写 ADR。
5. 复杂任务必须写 Agent 工作日志。
6. 每次任务都要判断是否暴露了框架摩擦，并将可复用规则沉淀到模板或规则文档。
7. 所有实现必须遵守 `docs/quality/code-standards.md`。
8. 所有数据表、索引、迁移、账本和审计设计必须遵守 `docs/architecture/database-design-standards.md`。
9. 所有影响上线、部署、回滚、密钥、备份恢复、观测或故障响应的变更必须遵守 `docs/operations/ops-readiness.md`。

## 高风险逻辑

1. 支付、余额、订单、权限、审核、数据删除等逻辑必须服务端校验。
2. 高风险逻辑必须有测试。
3. 回调和异步任务必须幂等。
4. 敏感后台操作必须写审计日志。

## 架构能力门禁

1. Agent 在实现需求前必须进行架构能力判断，并对照 `docs/architecture/capability-gates.md` 判断是否涉及异步、缓存、CDN、统计、搜索、推荐、高可用、可观测性、数据一致性、权限、安全和数据迁移。
2. Agent 不能默认 CRUD 就足够；如果需求不是纯 CRUD，必须说明复杂点、当前方案、后续扩展和升级触发指标。
3. 涉及复杂业务时，必须补充 `docs/qa/architecture-capability-evidence.json` 或等价的能力判断证据，并通过 `npm run check:capability-gates`。
4. 涉及资金、订单、扣费、收益、权限、审核、处罚、用户数据、生产发布时，必须追加高风险门禁，至少覆盖服务端校验、RBAC、审计日志、事务/幂等、回滚/补偿和测试。
5. 不涉及项必须写“不适用”及原因，不能省略。
6. 不允许把“当前 MVP”作为跳过架构能力判断的理由；MVP 可以分阶段实现，但必须写清边界、迁移成本和升级触发指标。

## 运维就绪

1. 生产上线必须有部署步骤和回滚步骤。
2. 真实 secret 不能进入 Git、日志、截图或 Agent 日志。
3. 数据库高风险变更必须有备份和恢复方案。
4. 服务必须有 health check、错误日志和基础观测入口。
5. P0/P1 故障必须保留证据、止损、恢复、复盘，并把缺失门禁沉淀回框架。

## AI 原生协作

1. {{PROJECT_NAME}} 采用 AI 原生协作框架，框架规则、模板、契约和日志沉淀都是核心工程资产。
2. 后续约 95% 业务代码预计由 AI 生成，规则必须显式、可执行、可复制。
3. 每次任务都应同时完成业务目标和框架优化目标。
4. 发现流程、命名、权限、CI、CODEOWNERS、日志模板等问题时，必须记录或创建框架优化任务。
5. 可复用框架规则需要同步到公共 AI 框架仓库，再由项目 `.ai-framework` 子仓库升级。

## 团队成员协作与 Agent Scope

1. 团队成员给 Agent 派活前必须写清需求 ID、执行角色、允许写入目录、只读参考目录、禁止修改目录和需要 Review 的 owner。
2. 默认规则是“读全局，写局部”。Agent 可以读取 PRD、OpenAPI、架构、QA 和日志，但默认只能写入 `allowedWritePaths`。
3. 跨边界修改必须声明 `requestedWritePaths`、原因和 `requiresReview`，不能在实现过程中顺手改其他角色目录。
4. 团队成员 Review 必须检查 `docs/operations/team-member-operating-model.md` 和 `docs/templates/team-member-task-brief-template.md` 的要求，不能只看代码或页面表象。
5. 缺少目录边界、任务 Brief、验收证据或 owner review 时，任务不能标记为完成。

## 前端体验

1. UI 必须对齐设计图和设计系统。
2. 关键操作必须有加载、成功、失败状态。
3. 移动端必须适配安全区。
4. 后台端必须优先可扫读、可批量处理、可追踪。
5. Web 页面部署不能只验证 `curl 200`；必须用浏览器验证页面有可见内容、根节点已挂载、静态资源 200、console 无 error，并记录截图或验证结果。
6. 前端页面开发必须遵守 `docs/design/frontend-implementation-rules.md`。
7. 设计图存在时，禁止用工程占位页、通用 dashboard 或自行发明的视觉风格替代设计图。
8. Agent 日志必须写明本次页面对应的具体设计图文件名；没有设计图文件名的前端实现不得视为完成。
9. 涉及 `apps/mobile/**` 的页面变更必须通过 `npm run check:ai-gates`，并记录真实手机视口截图、公共组件拆分、API 接入或 mock 原因。
10. 涉及 `apps/admin/**` 的后台变更必须通过 `npm run check:ai-gates`，并记录权限、审计日志和真实接口状态；fallback/mock/placeholder 不得冒充完成。
11. 冒烟测试不能作为前端完成证据，只能作为上线后基础连通性证据。
