## 一、来由

团队讨论后定下来的方向：**不要在机器人里堆堡垒机相关的功能**（"就是个堡垒机，不用搞这么多花里胡哨"、"一定要安全"）。改成：

1. 堡垒机域名用 nginx 加访问密码（已做，见同目录另一篇记录）；
2. 做一个**运维工作台页面**，把常用入口集中到一个 https 页面，团队成员收藏一个网址就够。

**打开方式**（`openInNewWindow` 字段，双击图标生效）：

| 打开方式 | 按钮 | 原因 |
| --- | --- | --- |
| 内嵌面板（`false`） | 监控、文档 | 双击后在工作台页面里弹一个可拖动/缩放的窗口，不跳走 |
| 新窗口（`true`） | 堡垒机、运维机器人、报警群、Cloudflare | 堡垒机要输访问密码 + 跳转，放新窗口体验更好（实测后定的）；Telegram 和 Cloudflare 是外部服务，发 `X-Frame-Options` 禁止被 iframe 嵌入，只能新窗口 |

其中**监控（Beszel）原本也禁止内嵌**（响应头 `X-Frame-Options: SAMEORIGIN`），在 nginx 里用 `proxy_hide_header X-Frame-Options;` 去掉后才允许（文档站的反代配置里也预先加了这一行）。堡垒机的响应头本来就不限制内嵌，改成新窗口是按使用体验定的。

为什么不用普通链接：普通 Drive 链接返回 `X-Frame-Options: SAMEORIGIN`，iframe 会被浏览器拦；Google 专门提供了 `embeddedfolderview` 这个可内嵌的文件夹视图，所以按钮用它。

限制：内嵌视图要求**浏览器里已登录有权限的 Google 账号**（匿名请求会返回 401 登录页）。如果面板里显示登录提示或空白，直接用上面的普通地址打开即可。

## 四、部署步骤

1. 上传静态文件到 `/opt/nginx/www/work/`。
2. 新增 nginx 站点 `conf.d/40-work.conf`（HTTP 版先上，方便签证书）：静态根 `/var/www/work` + 与堡垒机同一套 Basic 认证 + ACME 路径免密。
3. 签证书：`certbot certonly --webroot -w /var/www -d work.evercare.id`（DNS 已由 Mark 解析到 Cloudflare）。
4. 换成带 443 的正式配置，`nginx -t` + `reload`。

## 六、踩的坑

1. **配置没生效前会落到默认站点**：刚开始测公网时返回 302 —— 因为 `work.evercare.id` 还没匹配到站点，落到 `99-default.conf`（跳转到堡垒机域名）。配置生效后再测就是 401/200，属于正常现象，别误判成配置错误。
2. **证书要在 HTTP 配置下签**：带 `listen 443 ssl` 的配置在证书不存在时 `nginx -t` 会失败，所以先上 HTTP 版、签完证书再切 443。
3. **Basic 认证要放行 ACME 路径**：否则证书 90 天自动续期会失败（`auth_basic off`）。
4. 用 `cp 目录/*` 同步会漏掉隐藏文件（这次是 `.user.ini` / `.well-known`，不影响），同步整目录更稳。
