# 2026-08-26 巴西 G759 旋转报错结果库权限修复记录

时间：2026-08-26 13:45（Asia/Manila）
项目：DBQP / PGServer master
范围：巴西 G759 点击“玩游戏”旋转报错故障排查与修复
执行人：Codex（本地工作区 + 宝塔 + 备用机 + 三台后端 + 真实浏览器）

## 背景

```text
浏览器打开 G759 游戏加载完成后，点击“玩游戏”旋转（spin）转圈报错。
（注：前一日已修复线路探测根路径 404/403，游戏可进入；本次为进入后 spin 阶段报错。）
```

## 排查过程

```text
1. 后端容器/端口正常：三台 dbqp-g759-release running（master-b3083550），9019 正常；
2. 真实浏览器进入游戏成功：登录/进入接口 code=0，投注档位正常加载；
3. 点击旋转后端日志报错：
   - G759 request failed: 游戏 56 的模式 0 没有可用结果
   - 建立 G759 只读连接失败 [56]: attempt to write a readonly database
4. 数据库核查：g759_56.db 存在且 33.9 万行（mode=0 有 31.9 万行），数据本身充足；
5. 权限对比发现根因：
   - 服务容器以 appuser(uid=1000) 运行；
   - 03 的 g759 结果库 owner=uid1000（appuser）-> 正常；
   - 01/02 的 g759 结果库 owner=root、文件 644、目录 755 -> appuser 无写权限，
     SQLite 只读连接初始化（mmap/journal）时 “attempt to write a readonly database”
     -> 连接失败 -> 查不到结果 -> 报“模式 0 没有可用结果”；
   - 对照：PG 结果库 owner=1002:1003 且 755，一直正常。
```

## 修复

```text
01/02 后端：
    chown -R 1000:1000 /opt/game_results_datas/g759
    chmod -R u+rwX,go+rX /opt/game_results_datas/g759
（03 原 owner 即 appuser，无需修改；修改后三台一致。）
```

## 验证

```text
1. 三台容器内以 appuser 身份调用 get_random_result(56,0) 全部 FOUND；
2. 真实浏览器完整复测：进入幸运兔（slorabbitnew）成功，点击旋转完成一局
   （后端 gameid=56 rounds=1 bet=50.0），今日统计同步 MySQL 成功；
3. 不再出现“没有可用结果”/“只读连接失败”报错；
4. 剩余 /?t= 请求为客户端并发线路探测正常中止（net::ERR_ABORTED），非故障。
```

## 结论

```text
巴西 G759 旋转报错根因为 01/02 结果库属主/权限与容器运行用户不匹配，
已统一为 uid=1000(appuser) 可写；三台后端结果库读取恢复正常，真实玩家可正常旋转。
```

```text
本地 master：a77cb272（本次本地 Commit 后更新；未 Push；origin= b3083550）。
```
