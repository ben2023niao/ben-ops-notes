# 【事故】测试环境配置发版失败导致容器未起来（已恢复并修复根因）

> 来源文件：`~/Projects/work/game/youdianse-docker/main/docker-youdianse-php/docs/2026-10-20-2030-【事故】测试环境配置发版失败导致容器未起来（已恢复并修复根因）.md`

> 整理日期：2026-10-20 20:30｜日期依据：文件名日期

- 时间：2026-10-20 20:20 ~ 20:45（北京时间）
- 环境：测试环境 15.152.247.196
- 现象：配置发版（`sync-config --ref fc4df6e`）在 `docker compose up --force-recreate` 阶段失败，web/nginx 停在 `Created` 状态，测试环境后端不可用；同时 alb_white.txt 回到镜像里的旧副本（37 行），新接入的《我踏马都要》配置丢失

## 一、现场

```
d89cd7683f0c_youdianse-dev-php-cron    Created    ← 残留
212ec95b96b7_youdianse-dev-php-nginx   Created    ← 残留
youdianse-dev-php-web                  Created    ← 未启动
youdianse-dev-php-cron                 Up
```

报错：

```
Container youdianse-dev-php-nginx  Recreate
Error response from daemon: No such container: d89cd7683f0cdbc40b85df250d70a252edc8879b59411f97e59a1836540ee4fc
退出码：1
```

## 二、根因

`docker compose up -d --force-recreate` 在重建过程中被打断（上一次尝试/并发操作），会留下 `<hash>_youdianse-dev-php-nginx` 这类 **Created 状态的中间容器**。

下一次 compose 再执行重建时，会引用到这些已经消失的容器 ID，于是报 `No such container` 并中止，导致先停掉的 web/nginx 没有被拉起。

**不是配置内容的问题**：配置仓库本身是好的（fc4df6e，alb_white 84 行含 `n4bs.wqdyapi.top`、secret 含 `tmdy=`）。

## 三、处置

### 3.1 恢复服务

```bash
# 清理 Created 状态残留
for c in $(docker ps -a --format '{{.Names}}|{{.Status}}' | grep '|Created' | cut -d'|' -f1); do
  docker rm -f "$c"
done
# 重新拉起
docker compose --env-file .ops-build.env --profile cron up -d --force-recreate --no-build web nginx cron
```

### 3.2 补回白名单

重建后的容器又回到镜像里的旧副本（37 行），从配置仓库同步结果重新写入：

```bash
for f in alb_white.txt alb_white_secret.txt; do
  for c in youdianse-dev-php-web youdianse-dev-php-cron; do
    docker cp /opt/docker-youdianse-php/cicd-web/runtime/app-local-files/$f $c:/var/www/html/youdianse-php/$f
    docker exec -u root $c sh -c "chown root:www-data /var/www/html/youdianse-php/$f; chmod 640 /var/www/html/youdianse-php/$f"
  done
done
```

### 3.3 根因修复（CICD 代码）

新增 `cleanup_created_containers()`：在每次 compose 重建前，清理本项目处于 `Created` 状态的残留容器。

```python
def cleanup_created_containers(logger) -> None:
    """清理 compose 中断后残留的 Created 状态容器（避免 No such container 导致发布失败）。"""
    result = run_cmd(["docker", "ps", "-a", "--filter", "status=created", "--format", "{{.Names}}"], timeout=20)
    if result.code != 0 or not result.output.strip():
        return
    for name in result.output.split():
        if "youdianse" not in name:
            continue
        logger.log("清理残留的 Created 容器：" + name)
        run_stream(["docker", "rm", "-f", name], logger, notify_enabled=False)
```

接入两处：`up_services()`（正常发布）与 `sync_runtime_config_no_build()`（配置发布）。

- 线上 CICD（16.209.16.108）：整体替换为仓库最新 core.py，`systemctl restart cicd-web` → active
- 测试 CICD（15.152.247.196）：该机代码版本较旧，**只打最小补丁**（不整体覆盖，避免 `ADMIN_LOGIN_PATH` 等 ImportError），`py_compile` 通过，进程重启后 18090 → 200

## 五、给开发的提醒

**不要在服务器上用 `echo >>` 直接改 `alb_white.txt` / `alb_white_secret.txt`**：

- 改动只存在于容器内，重建容器即丢失
- 正确做法：改配置仓库 `app-local-files/`，提交并 push，再走「配置发版」
- 平台主机（如 `n4bs.wqdyapi.top`）与密钥（如 `tmdy=...`）都必须进配置仓库，才能被发布流程带进容器
