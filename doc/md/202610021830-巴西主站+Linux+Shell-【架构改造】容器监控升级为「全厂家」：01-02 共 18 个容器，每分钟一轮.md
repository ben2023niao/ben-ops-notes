## 一、监控对象：2 台 × 9 厂家 = 18 个容器

```text
厂家（每台都有）：api / pg / vendor_a / vendor_a_ws / ppk / pp / vendor_c / vendor_d / g759
容器名：game-service-<厂家>-prod
特例：vendor_a WS2 两台命名不一致，两种都认
  01（192.0.2.1）：game-service-vendor_a_ws-prod（下划线）
  02（192.0.2.1）：game-service-vendor_a-ws-prod（连字符）
  → 脚本按「厂家」维度记账，状态键用 <ip>:<厂家>，不受命名差异影响
不在范围：beszel-agent（监控基础设施，由 container_health_monitor 覆盖）、
          03（打包机，没有厂家容器）
```

## 二、脚本完善点（docker/scripts/critical_restart_watch.py）

```text
1) 从「固定 3 个容器」升级为「按厂家列表驱动」：VENDORS 一处配置，
   容器名自动推导 + 别名（vendor_a_ws）自动匹配，以后加/减厂家只改一行。
2) 报警正文信息更全（便于直接定位，不用再登机器）：
   容器名 / 状态 / restarts / 已运行时长 / 容器内存 / 镜像 tag / 重启策略，
   报警里再带上 OOMKilled、ExitCode。
3) 新增「疑似发版窗口」提示：同一条 SSH 里顺带 pgrep 检测 rsync/start.sh/stop.sh/build.sh，
   命中就在报警头部附一句「检测到 XX 上正在跑同步动作」——**只提示不抑制**，
   因为开发的要求就是这些容器不允许重启，发版导致的重启同样需要知道。
4) 宿主机内存前置预警保留（默认 <3000MB 报警，某业务公司_HOST_MEM_MIN_MB 可调）：
   这些容器都没有内存上限，真正的重启风险是宿主 OOM 杀进程 → --restart=always 拉起。
5) 自动清理旧版状态键：上一版按容器名记账（<ip>:game-service-xxx-prod），
   这一版按厂家记账（<ip>:api），历史键会在首轮自动删除（实测已清）。
6) 每次采样仍只用一次 SSH：一条命令里取 MemAvailable、发版进程、9 个容器的
   docker inspect + cgroup 内存（v2/v1 都兼容），开销很小，1 分钟一轮绰绰有余。
```

## 三、判定规则（沿用 + 微调）

```text
命中任意一条立即报警（不等多次采样）：
  1) RestartCount 变多          → 容器被 Docker 重启过
  2) 容器 ID 变了               → 被删掉重建（start.sh 的 stop+rm+run 会这样）
  3) State.Status != running    → 当前不在运行
  4) 容器查不到                  → 容器缺失
  5) 宿主机可用内存 < 3000MB    → OOM 前置预警
一次性事件（重启次数+1、被重建）不会在下一轮误发「已恢复」；
持续性状态（缺失 / 不在 running / 内存告急）恢复时补一条「已恢复」；重复采样不刷屏。
```

```text
⚠️ 顺带发现（历史遗留，不是本轮造成）：
   01 上有 3 个容器的历史重启计数不是 0：ppk=10、vendor_c=9、g759=9；
   而 02 上同厂家全都是 0。这几个容器 14 天前创建，计数在 2026-09-24
   我上次做容器监控改造时就已经是这个数（当时也是 9/10），之后一直没再增长。
   也就是说：这 9~10 次重启发生在 9/24 之前，之后这两周是稳定的。
   现在的监控以「当前计数」为基线，只会在**再增长**时报警，不会因为历史数字反复吵。
   如果开发想追溯那几次重启的原因，可以从容器创建时间（9/18 前后）那天的
   系统日志/内存记录入手 —— 需要的话我可以去捞。
```

## 六、运维手册

```bash
# 看 18 个容器当前快照（不写状态、不发群）
/usr/bin/python3 /opt/pgserver/docker/scripts/critical_restart_watch.py --show

# 只检查不落状态不发群
/usr/bin/python3 /opt/pgserver/docker/scripts/critical_restart_watch.py --dry-run

# 验证飞机群通道
/usr/bin/python3 /opt/pgserver/docker/scripts/critical_restart_watch.py --test-notify

# 日志 / 状态 / cron
tail -20 /var/log/bizops-restart-watch.log
cat /var/tmp/bizops-restart-watch.json
crontab -l | grep critical_restart_watch

# 临时停用（注释那一行即可）
crontab -l | sed 's|^\* \* \* \* \* \(set -a; . /opt/benbot-runtime.env.*critical_restart_watch.*\)|#PAUSED \1|' | crontab -

# 换监控对象（例如只盯某几个厂家）：脚本顶部 VENDORS 改一行，重跑一次即可
# 换后端：环境变量 某业务公司_WATCH_HOSTS=192.0.2.1,192.0.2.1
# 调内存阈值：crontab 那行前加 某业务公司_HOST_MEM_MIN_MB=5000
```
