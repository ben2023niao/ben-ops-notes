# 2026-07-16 vendor_a 幸运鹦鹉 lm 斜杠对象漏同步修复记录

本文记录 vendor_a 幸运鹦鹉试玩加载到 100% 后提示断线 `MSG 999.2`，浏览器把正确游戏域名 `vendor_a-games.p8m7xv.cyou` 错误拼成 `vendor_a-games.p8m7xv.cyou.com` 的排查、修复、Cloud CDN 刷新和公开验证过程。

## 问题现象

测试页面来自：

```text
https://vendor_a-statics2.xqv9m8.icu/lm/?...
```

浏览器 Network 中失败的预检请求：

```text
OPTIONS https://vendor_a-games.p8m7xv.cyou.com/lm/req
Origin: https://vendor_a-statics2.xqv9m8.icu
Access-Control-Request-Method: POST
Access-Control-Request-Headers: token
```

错误域名 `vendor_a-games.p8m7xv.cyou.com` 无 DNS 记录，浏览器无法建立请求。

## 初始部署记录复核

此前覆盖的新文件：

```text
/www/wwwroot/vendor_a-statics2/lm/index.html
size: 95433 bytes
md5: 56c84444263376cbc1c8ded516ac6637
sha256: 9f966f2d282cc152d1798dec0ebabb17a1fd50611e3ac2801624773b29576bb5
```

宝塔、GCS live、GCS backup 和公开 CDN 的 `/lm/index.html` 均已是新版本，原验证结论对这个精确对象成立。

但实际试玩 URL 使用 `/lm/?...`，不是 `/lm/index.html?...`。

## 根因

Google Cloud Storage backend bucket 不提供 Nginx 风格的目录索引，不会自动把 `/lm/` 转换成 `/lm/index.html`。

某业务公司 的 GCS 静态同步脚本会为包含 `index.html` 或 `index.htm` 的目录额外生成一个末尾带斜杠的对象：

```text
源文件：lm/index.html
斜杠别名对象：lm/
```

此前手工覆盖只更新并刷新了：

```text
/lm/index.html
```

遗漏了实际试玩入口使用的：

```text
/lm/
```

修复前两个 GCS 桶的斜杠对象均为旧版本：

```text
size: 32318 bytes
sha256: a4193744a5f79af2c601e856fc1a0d475a254b8a328cd29926b8d4ec79048070
```

新旧页面精确 diff 显示，新 `index.html` 在页面头部新增了约 `63KB` 的混淆 JavaScript，旧 `lm/` 页面没有这段脚本。浏览器访问 `/lm/?...` 时一直执行旧页面，因此没有加载供应方本次提供的域名修正逻辑。

## 修复前备份

覆盖 GCS 斜杠对象前，分别保存 live 和 backup 的旧响应体：

```text
/root/bizops-static-import/live-vendor_a-statics2-lm-slash-before-20260716-203500.html
/root/bizops-static-import/backup-vendor_a-statics2-lm-slash-before-20260716-203500.html
```

两个备份均为：

```text
size: 32318 bytes
sha256: a4193744a5f79af2c601e856fc1a0d475a254b8a328cd29926b8d4ec79048070
```

## GCS 斜杠对象修复

使用与 `/www/server/cron/gcs_static_sync` 中 `sync_slash_aliases` 相同的 GCS JSON API 逻辑，将宝塔新 `index.html` 内容写入精确对象名：

```text
gs://bizops-gcs-vendor_a-statics2/lm/
gs://bizops-game-statics-gcs/vendor_a-statics2/lm/
```

上传结果：

```text
live object: lm/
live generation: 1784205307084920
backup object: vendor_a-statics2/lm/
backup generation: 1784205309240064
size: 95433 bytes
GCS md5Hash: VshERCYzdsvByN7VFqxmNw==
sha256: 9f966f2d282cc152d1798dec0ebabb17a1fd50611e3ac2801624773b29576bb5
```

上传后通过两个公开 GCS URL 重新下载响应体，HTTP、大小和 SHA256 均通过。

## Cloud CDN 刷新

从线上 `/opt/pgserver/platform-api/conf/domains/vendor_a.json` 的 `SPECIAL_GAMES_v2.static_hosts` 读取 22 个 `vendor_a-statics2.*` 域名，对每个 host 提交精确路径 `/lm/` 的缓存失效。

最终 operation 状态：

```text
目标：22
DONE：22
缺失：0
错误：0
```

operation 清单：

```text
/root/bizops-static-import/vendor_a2-lm-slash-invalidation-ops-20260716.txt
```

非零 `Age` 证明 Cloud CDN 当前缓存的是修复后的新页面，不是依靠 cache-bust 每次回源得到的临时成功结果。

## 二次浏览器实测与运行时域名修正

补齐 `lm/` 斜杠对象后，使用本地 Docker Chromium 从测试大厅真实点击 `gameID=598`。浏览器确认加载的是 95KB 新页面，但游戏加载到约 96% 后仍然发出：

```text
POST https://vendor_a-games.<domain>.cyou.com/lm/req
POST https://vendor_a-games.<domain>.icu.com/lm/req
```

因此，斜杠对象漏同步是第一层问题，但供应方提供的 95KB 页面仍未覆盖游戏运行阶段实际发出的 Fetch 请求。正确 `sip=vendor_a-games.<domain>.cyou|icu` 会被游戏代码再次追加 `.com`，最终触发 DNS 失败和 `MSG 999.2`。

先在容器浏览器启动阶段临时注入同等规则验证修复方向：

```text
.cyou.com -> .cyou
.icu.com  -> .icu
```

临时验证结果：正确 `/lm/req` 两次 HTTP 200，错误域名为 0，游戏进入完整引导页。临时注入截图未作为线上成功截图发送。

随后在 `index.html` 最前部加入正式 Fetch/XHR URL 规范化逻辑，并重新发布。正式文件：

```text
size: 96447 bytes
md5: 709e9706b93166170eaac81199c24125
sha256: f91b9a1d8ee2aa8a55fc2fcf3ff83592968da58a79590d84a097c9a98babb87e
```

宝塔旧文件备份：

```text
/www/wwwroot/vendor_a-statics2/lm/index.html.bak-20260716-2108
```

GCS 覆盖前的 95KB 对象备份：

```text
/root/bizops-static-import/live-lm-index-before-20260716-2108.html
/root/bizops-static-import/live-lm-slash-before-20260716-2108.html
/root/bizops-static-import/backup-lm-index-before-20260716-2108.html
/root/bizops-static-import/backup-lm-slash-before-20260716-2108.html
```

正式文件同步到四个精确对象：

```text
gs://bizops-gcs-vendor_a-statics2/lm/index.html
gs://bizops-gcs-vendor_a-statics2/lm/
gs://bizops-game-statics-gcs/vendor_a-statics2/lm/index.html
gs://bizops-game-statics-gcs/vendor_a-statics2/lm/
```

四个对象重新下载后均为 `96447 bytes`，SHA256 全部匹配。

## 人工复测建议

旧 32KB 页面可能仍在测试人员浏览器内存或磁盘缓存中。复测时应：

```text
1. 关闭旧游戏标签页后重新打开试玩入口；或
2. 打开 DevTools，勾选 Disable cache，再执行硬刷新；
3. 在 Network 确认 Document 请求路径是 `/lm/?...`，响应体大小为 `96447 bytes`；
4. 确认 `/lm/req` 的 Request URL 不包含 `.cyou.com` 或 `.icu.com`；
5. 确认游戏能进入 `JOGAR` 界面，且没有 `MSG 999.2`。
```

## 后续发布规则

以后手工覆盖任意静态目录的 `index.html` 或 `index.htm` 时，必须同时处理并验证两类 URL：

```text
/path/index.html
/path/
```

最低检查项：

```text
1. 宝塔 index 文件哈希；
2. GCS live/backup 的 index 对象哈希；
3. GCS live/backup 的斜杠别名对象哈希；
4. CDN 的 /path/index.html；
5. CDN 的 /path/；
6. 两个路径均提交对应的 CDN invalidation；
7. 按真实试玩 URL 形式进行最终验证。
```

## 最终结论

幸运鹦鹉断线包含两层原因：第一次手工发布遗漏 GCS `lm/` 斜杠别名对象；补齐后，供应方 95KB 页面在运行阶段仍把自定义 `.cyou/.icu` 后端追加为 `.com`。现已在 `index.html` 加入最小 Fetch/XHR 域名规范化逻辑，四个 GCS 对象均更新为 96KB 正式版本，22 个域名的两个入口 44/44 内容验证通过。最终无临时注入的 Docker Chromium 实测已进入 `JOGAR` 页面，`/lm/req` 两次 200，错误域名和 `MSG 999.2` 均为 0；截图已发送监控报警群 `message_id=2693`。
