# DNS实战四 DNS负载均衡

## 1. 编辑zone文件

```
[root@master ~]# vim /var/named/chroot/etc/example.com.zone
$ORIGIN .
$TTL 3600 ; 1 hour
example.com IN SOA op.example.com. dns.example.com. (
 2004 ; serial #自增+1，生产中可通过加时间戳来设定
 900 ; refresh (15 minutes)
 600 ; retry (10 minutes)
 86400 ; expire (1 day)
 3600 ; minimum (1 hour)
 )
 NS op.example.com.
$ORIGIN example.com.
chegva A 203.0.113.1
op A 203.0.113.1
a A 203.0.113.1
a A 203.0.113.1
a A 203.0.113.1 #增加一条A解析
cname CNAME a.example.com.
mx MX 5 203.0.113.1

[root@master ~]# rndc reload
WARNING: key file (/etc/rndc.key) exists, but using default configuration file (/etc/rndc.conf)
server reload successful
```

### 2. 测试结果

```
[root@master ~]# nslookup a.example.com 203.0.113.1
Server: 203.0.113.1
Address: 203.0.113.1#53

Name: a.example.com
Address: 203.0.113.1 #虽然3个IP都解析到了，但拿到第一个IP，实际上已经解析出结果
Name: a.example.com
Address: 203.0.113.1
Name: a.example.com
Address: 203.0.113.1

[root@master ~]# nslookup a.example.com 203.0.113.1
Server: 203.0.113.1
Address: 203.0.113.1#53

Name: a.example.com
Address: 203.0.113.1 #再执行一次，轮询到1.2.3.4这个IP
Name: a.example.com
Address: 203.0.113.1
Name: a.example.com
Address: 203.0.113.1

[root@master ~]# nslookup a.example.com 203.0.113.1
Server: 203.0.113.1
Address: 203.0.113.1#53

Name: a.example.com
Address: 203.0.113.1 #依次轮询，DNS只有轮询的算法
Name: a.example.com
Address: 203.0.113.1
Name: a.example.com
Address: 203.0.113.1
```

**注意： DNS可以作负载均衡，但主要有两点不足**

1. 只有轮询算法
2. DNS解析只是一个记录类型，不会去探测后边的服务是死是活。因此，DNS负载均衡功能要慎用！
