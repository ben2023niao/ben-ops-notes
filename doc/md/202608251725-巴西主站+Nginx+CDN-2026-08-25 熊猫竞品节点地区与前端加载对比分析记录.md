## 一、竞品节点部署地区

```text
竞品域名：
  96A.com（入口）            -> Cloudflare
  m6kk678n.com（客户端主域）  -> Cloudflare（NS kimora/yew.ns.cloudflare.com）
  api4.a-b-c-8.com / api3.a-b-3-d.com（API）-> Cloudflare
  game-logo.6-q-r-s.com（游戏图）-> Cloudflare
  upload-us.x-y-2-z.com（上传）-> Cloudflare
  upload-us.f-1-g-h.com（上传）-> 192.0.2.27 菲律宾 Makati（Smart Broadband）
  o.alicdn.com（图标）       -> 192.0.2.28 菲律宾 Manila（阿里云淘宝网络）
```

结论：

```text
1. 竞品使用 Cloudflare Anycast 全球边缘：从巴西访问落 GRU（圣保罗）、从马尼拉/香港访问落 HKG，
   全球就近接入；真实业务源站位于菲律宾马尼拉（192.0.2.27 + 阿里云 CDN 菲律宾节点）。
2. 竞品主要面向巴西市场（页面含 R$/Depósito，html lang=en），但源站设在菲律宾，
   通过 Cloudflare 边缘 + 阿里云 CDN 分发到巴西/全球。
3. 我方：宝塔/备用 nginx/后端 01-03 均在巴西圣保罗（GRU），静态走 Google CDN/GCS，
   动态走 Cloudflare 回源宝塔——源站单一（巴西），边缘同样有 Cloudflare/Google 全球覆盖。
```

## 二、前端加载对比（真实浏览器）

```text
首页 HTML：
  FF789 首页 TTFB 0.78s / 96A 1.79s（我方更快）
  ff789p3.com DCL 0.71s、148 资源、1.30MB
  m6kk678n.com DCL 2.0s、109 资源、2.66MB（竞品体积更大但资源集中）

游戏启动（PG Fortune Tiger）：
  我方：登录后点击正常打开，游戏 iframe 约 4s 出现，
        路由 ff789p3.com/#/game/play?...thirdId=126 ->
        pg-games.*/launcher?provider=pg&ticket=... ->
        静态资源 pg4-static.*/126/（239 个请求，CDN 缓存命中）
  竞品：客户端为 Ionic（shadow DOM），游戏卡片用图片 logo 懒加载，
        从 API 可见同一游戏 Fortune Tiger（gameId=2196, code=HHSC）

性能差异点：
  我方大厅初始化预加载 image.prod-br.com 100+ 张游戏封面图
  （单张 400-1200ms，累计 12s+），且首次点击可能被 APP 推广弹窗
  （van-overlay）拦截导致跳消息中心——真实登录用户操作正常，但
  弹窗与图片预加载会拖慢“进度条”体验；
  竞品图片走 game-logo/upload-us 等 CDN 域名、资源更集中、懒加载。
```

## 三、结论与建议

```text
1. 竞品源站布局：菲律宾马尼拉（1 个真实源站 + 阿里云 CDN），Cloudflare 全球边缘；
   我方源站：巴西圣保罗单点，Cloudflare/Google CDN 全球边缘——边缘覆盖差距不大，
   源站地区不同（菲 vs 巴），对巴西用户我方更近。
2. 前端加载我方 HTML/DCL 更快，但大厅图片预加载策略（image.prod-br.com 100+ 张）
   与 APP 推广弹窗会拖慢首次进入体验，建议：图片懒加载/压缩、弹窗改为可跳过。
```
