# Admin API 契约说明

> 来源文件：`~/Projects/work/game/xiaolan-watches/dev/docs/api/admin-api.md`

> 整理日期：2026-06-04 01:09｜日期依据：文件创建/修改时间

本文定义前后端分离后台的 API 文档规则。`apps/admin` 是统一后台管理前端，可以对接 Go Gin 或 Laravel；具体接口归属必须由 OpenAPI 明确标注，不能靠口头约定。

## 1. 适用范围

后台管理 API 至少覆盖：

1. 管理员登录、会话、退出。
2. RBAC：角色、权限、菜单。
3. 用户、内容、订单、配置等管理资源。
4. 审核、处罚、人工修改、导出等敏感操作。
5. 审计日志查询。

项目可按 PRD 裁剪，但启用 `apps/admin` 时必须说明每个后台模块的接口 owner 和验收范围。

## 2. Owner Service

每个后台 OpenAPI path 必须标明 owner service：

```yaml
x-owner-service: services/go-app
x-auth: admin-rbac
x-audit: required
```

或：

```yaml
x-owner-service: services/laravel-app
x-auth: admin-rbac
x-audit: required
```

规则：

1. `apps/admin` 不直接判断接口由 Go 还是 Laravel 提供，只依赖 OpenAPI。
2. `services/go-app` 适合承接高并发、强事务、账本、订单、核心风控相关 Admin API。
3. `services/laravel-app` 适合承接运营后台、内容管理、审核流程、Filament 生态相关 Admin API。
4. 同一个资源不能被 Go 和 Laravel 同时随意写入；数据 owner 必须写入 `docs/architecture/data-model.md`。

## 3. 推荐拆分

```text
packages/contracts/openapi/
  paths/
    admin/
      auth.yaml
      users.yaml
      roles.yaml
      permissions.yaml
      menus.yaml
      audit-logs.yaml
      settings.yaml
      content-review.yaml
      orders.yaml
  schemas/
    admin.yaml
    rbac.yaml
    audit.yaml
```

## 4. 接口硬规则

1. 后台接口必须鉴权，不允许匿名访问。
2. RBAC 权限必须由服务端判断，前端菜单隐藏不能代替权限控制。
3. 敏感操作必须写审计日志，至少包含操作人、目标对象、动作、原因、时间、请求 ID。
4. 高风险写操作必须考虑幂等和二次确认。
5. 列表接口必须有分页、筛选、排序边界。
6. 导出、批量操作、人工改数必须有权限与审计说明。

## 5. Agent 验收

涉及 `apps/admin/**`、后台 OpenAPI 或后台服务实现时，Agent 日志必须记录：

1. PRD 来源：`docs/prd/modules/admin.md`。
2. API 文档：`docs/api/admin-api.md`。
3. OpenAPI path 和 `x-owner-service`。
4. 权限、审计、幂等或二次确认处理。
5. 前端、后端、测试的闭环验证结果。
