## 一、任务

```text
1. 香港后端 bizops-hongkong-sanic-prod-01 / -02 使用巴西 prod-03 上的容器仓库
2. 在 prod-02 起一个后端容器做测试（prod-01 正在同步结果集，不动它）
```

## 二、巴西容器仓库现状（prod-03）

```text
仓库：Docker Registry 2（容器名未命名，docker-proxy 监听 192.0.2.3:5000）
地址：内网 192.0.2.1:5000（巴西 01/02 用这个）/ 公网 192.0.2.20:5000（香港用这个）
数据：/data/registry（docker 目录）
认证：匿名可拉（GET /v2/ 返回 200，无需 token）
既有配置（巴西 prod-01）：daemon.json = insecure-registries ["192.0.2.1:5000"] +
  json-file 日志（max-size 100m / max-file 7）
镜像（catalog）：game-service-api / vendor_b / vendor_d / pg / vendor_c / pp / ppk / vendor_a / g759
  + bizops-browser-test，每个约 1GB（解压后 2.4GB+），tag 形如 20260923-ben、
  20260916-ben-cb8f2c55、ben-0df45abd、7500f11a（**没有 latest**，latest 只是本机 tag）
```

## 三、香港配置（01 / 02 两台）

```text
/etc/docker/daemon.json（原来不存在，本次新建）：
{
  "insecure-registries": ["192.0.2.20:5000"],
  "log-driver": "json-file",
  "log-opts": { "max-size": "100m", "max-file": "7" }
}
systemctl restart docker 后 docker info 已显示 Insecure Registries: 192.0.2.20:5000
```

说明：香港与巴西不在同一 VPC，只能走公网地址，所以 insecure-registries 填
`192.0.2.20:5000`（巴西 01/02 填内网 `192.0.2.1:5000`）。日志策略与巴西保持一致。

拉取验证（两台都实测）：

```bash
docker pull 192.0.2.20:5000/game-service-pg:20260921-ben
# 两台均成功：Status: Downloaded newer image ...（2.44GB）
```

注意：`docker manifest inspect` 是客户端命令、不读 daemon 的 insecure-registries，
对 HTTP registry 会失败，**验证要用 docker pull**（本次踩过）。

## 四、prod-02 容器启动测试

### 4.1 运行依赖准备

pg 容器需要的挂载全部来自 `/data/server-runtime`，而 prod-02 的结果集同步（第二阶段）
还没开始，所以先同步运行必需的小文件（不拉 152G）：

```text
share.so (6.3MB)、version.json、md5sum.txt、xxxxxx.mmdb (65MB)、conf/（88K）、
server_configs（**注意：巴西侧是文件，不是目录**，第一次按目录建导致同步失败，已修正）
并建 logs/、game_result_datas/pg/ 空目录；统一 chown 1000:1000
```

### 4.2 容器启动（复刻巴西 pg 容器配置）

```bash
docker run -d --name game-service-pg-test --restart unless-stopped --user appuser -p 9091:9091 \
  -v /data/server-runtime/share.so:/usr/local/lib/python3.11/site-packages/share.so \
  -v /data/server-runtime/server_configs:/app/server_configs \
  -v /data/server-runtime/version.json:/app/config/version.json \
  -v /data/server-runtime/xxxxxx.mmdb:/app/config/xxxxxx.mmdb \
  -v /data/server-runtime/conf/domains:/app/config/domains \
  -v /data/server-runtime/game_result_datas/pg:/app/data/game_result_datas/pg \
  -v /data/server-runtime/logs:/app/pg/logs \
  -e PYTHONPATH=/app -e PYTHONUNBUFFERED=1 -e VERSION_FILE_PATH=/app/config/version.json \
  -e GAME_RESULT_DATAS_PATH=/app/data/game_result_datas/pg \
  -e GAME_DOMAINS_PATH=/app/config/domains \
  -e SERVER_CONFIGS_PATH=/app/config/server_configs \
  -e CURRENT_VENDOR=pg -e MAIN_ENTRY=server.py \
  192.0.2.20:5000/game-service-pg:20260921-ben
```

与巴西 pg 容器对齐的关键项（`docker inspect` 实测）：

```text
User=appuser（uid 1000）  Cmd=/bin/sh -c python /app/${CURRENT_VENDOR}/${MAIN_ENTRY}
WorkingDir=/app  RestartPolicy=always(本次用 unless-stopped)  ShmSize=64MB（默认，无需调）
端口 9091  其余挂载/env 见上面命令
```

### 4.3 测试结果

```text
1) 不加 --user appuser 时（root 运行）：应用能启动但很快崩溃、容器进入重启循环
   （日志出现 multiprocessing ConnectionResetError / resource_tracker KeyError）。
2) 加 --user appuser 后：RestartCount=0，Sanic 正常启动
   （Goin' Fast @ http://192.0.2.3:9091，mode: production, w/ 4 workers），
   容器内 4 个 worker 均 LISTEN 192.0.2.3:9091，Redis（192.0.2.1:6379）连接建立成功，
   GeoIP 库 /app/config/xxxxxx.mmdb 加载成功，pg 配置装载成功。
3) HTTP 请求仍被重置：用户说明「数据库没开权限的」——即业务进程访问 MySQL 权限未开，
   属于**预期现象**，不是本次配置问题。
4) 按用户要求测试后已关闭并删除容器（docker stop + rm），
   镜像 192.0.2.20:5000/game-service-pg:20260921-ben 保留备用。
```

## 五、结论与待办

```text
结论：
  - 香港 01/02 已能用巴西 prod-03 的容器仓库（insecure-registry + 公网地址），拉取实测通过；
  - 后端容器的启动方式已摸清（关键是 --user appuser + 那 7 个挂载 + 6 个 env）；
  - 业务能否跑起来取决于数据库权限/连通性，与镜像仓库无关。
待办：
  1. 数据库权限开通（用户侧）后，prod-02 可直接用上面的 docker run 起 pg 容器复测；
  2. 等 /data/server-runtime 同步（STAGE2）完成后，prod-01/02 具备完整数据再正式部署；
  3. 后续如需批量起 9 个厂家容器，建议落一份 compose/启动脚本（当前先记录单容器命令）；
  4. prod-02 上出现的 beszel-agent 容器（非本次操作）保留观察，如需纳管再统一。
```
