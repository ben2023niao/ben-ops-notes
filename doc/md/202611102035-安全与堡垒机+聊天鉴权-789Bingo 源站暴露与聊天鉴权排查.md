# 789Bingo 源站暴露与聊天鉴权排查

> 公开版整理说明：原文中的存储 IP、相邻网段和完整 Host/SNI 对照细节已移除。记录保留方法论、已验证边界和聊天鉴权复核建议，避免把公开页面变成目标资产清单或扫描手册。

## 目的与边界

本次排查有两个问题：

1. 公开证据是否存在当前可验证的主站源站地址。
2. 聊天客户端是否提供了直接获取其他用户 Token 的入口。

检查只使用公开 DNS、被动 DNS、RDAP、证书透明度、历史 URL 和静态客户端代码，并对已公开的对象存储入口做少量单次 TLS/Host 对照。没有执行端口扫描、网段扫描、口令尝试、用户枚举或业务数据读取。

服务端聊天鉴权不能仅靠静态代码下结论，需要两个隔离测试账号完成 A/B 验证。

## 源站边界结论

主站及主要 API、上传、测试和 WebSocket 入口当前解析到 Cloudflare。公开历史扫描和当前 DNS 没有给出可信的当前源站地址。

对象图片域名可以解析到独立 CDN 或对象存储边缘，这些地址能返回对象存储响应，但在主站和 API Host 下没有返回对应页面或证书。因此它们属于图片分发基础设施，不承载主站和 API。

对公开存储地址附近的少量对照同样只发现 CDN 边缘和对象分发节点，没有返回主站 HTML、API JSON 或主站证书。继续扩大相邻地址扫描会把大量共享客户基础设施纳入范围，又没有高质量证据，因此主动停止。

最终判断：

- Cloudflare 代理状态有效。
- 未发现当前可验证的主站源站 IP。
- 对象存储可直连不等于源站暴露。
- 历史 DNS 地址不匹配当前证书，不能作为当前源站证据。

## 找源站的正确方法

公开旁路信息永远不如控制面证据可靠。需要确认源站时，应优先读取：

- Cloudflare 的 DNS、Origin Rules、Tunnel、Load Balancer 和日志。
- 源站 Envoy/Nginx 的真实客户端与回源日志。
- 负载均衡器、Kubernetes Ingress 或 API Gateway 的安全组。
- 云厂商审计日志中的资产归属和开放策略。

如果必须做直连验证，应由客户提供候选源站 IP/CIDR、允许端口和明确时间窗，不应通过猜测或大规模扫段完成。

## 聊天鉴权设计

客户端静态代码显示聊天入口分为访客认证、登录态验证、实时连接刷新、房间信息、历史消息、图片上传和消息撤回等类别。

关键设计特征：

- 登录态聊天认证从当前 Authorization 会话推导身份。
- 实时连接刷新同样不要求客户端传入目标用户 ID。
- 返回模型包含角色、封禁状态、VIP 等级和默认房间等字段。
- 客户端没有发现通过参数指定其他用户 ID 来请求聊天 Token 的入口。

这只是客户端调用面结论。服务端仍必须重新校验身份、资源和动作权限，不能信任客户端传入的角色或用户 ID。

## 需要 A/B 验证的问题

服务端聊天鉴权应使用两个隔离测试账号 A、B 验证：

1. A 登录后取得的 Token 只能代表 A。
2. A 替换 B 的消息 ID、房间 ID 或用户 ID 时必须返回 403 或 404。
3. 普通用户调用管理员动作必须失败。
4. A 不能订阅 B 的私有频道或其他房间频道。
5. 历史消息、批量撤回和房间信息都验证资源归属。
6. 红包领取在并发、重复请求和跨用户参数下保持正确。
7. 聊天图片的猜测 URL 不能绕过访问控制。
8. 消息、昵称和图片说明具备 XSS/Markdown 过滤。

不得使用真实用户数据完成这些验证。

## 风险判断

| 等级 | 项目 | 当前结论 |
|---|---|---|
| 信息 | 主站源站 IP 暴露 | 未发现当前可验证地址 |
| 低 | 对象存储可直连 | 可识别对象边缘，但不承载主站 |
| 待验证 | 聊天 Token 越权 | 客户端没有任意用户 ID 参数，服务端仍待 A/B 验证 |
| 待验证 | 房间与消息 IDOR | 需要测试账号验证历史和撤回权限 |
| 待验证 | 管理员越权 | 角色字段不能替代服务端动作鉴权 |
| 待验证 | 私有频道越权 | 需验证订阅与 Presence 权限 |
| 待验证 | 图片和红包授权 | 需验证随机访问、并发和重放 |

## 结论

当前公开证据没有找到主站源站地址，Cloudflare 仍然隐藏了主站和主要 API 的真实承载地址。对象存储边缘可识别，但通过证书和 Host 对照确认其不承载主站。

聊天客户端按当前会话换取实时凭据，没有发现客户端直接指定其他用户的入口。服务端是否存在 IDOR、管理员越权或频道越权，必须通过隔离测试账号和日志证据确认。
