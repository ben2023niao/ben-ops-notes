# PRD 门禁

> GitHub 仓库源文件：[点击打开网页渲染版](https://github.com/ben2023niao/ben-ops-notes/blob/main/doc/md/202606040109-%E5%B0%8F%E8%93%9D%E7%9B%B4%E6%92%AD%2B%E5%AE%89%E5%85%A8%E8%BF%90%E7%BB%B4%2B%E6%95%85%E9%9A%9C%E6%8E%92%E6%9F%A5-PRD%20%E9%97%A8%E7%A6%81.md)

> 整理日期：2026-06-04 01:09｜日期依据：文件创建/修改时间

PRD 门禁用于保证需求、契约、验收和测试之间可追踪，避免代码实现脱离业务需求。

## 必备文件

1. `docs/prd/product-prd.md`
2. `docs/prd/requirements.md`
3. `docs/prd/requirements.index.json`
4. `docs/prd/requirements.schema.json`
5. `docs/prd/modules/README.md`
6. `docs/templates/prd-module-template.md`
7. `docs/templates/prd-item-template.md`

## 模块 PRD 要求

每个模块 PRD 必须包含：

1. 模块目标。
2. 用户角色。
3. 需求列表。
4. 业务规则。
5. 边界与异常。
6. 权限与风控。
7. 数据对象。
8. API/事件契约。
9. 验收标准。
10. 测试要求。
11. 待确认问题。

## 需求 ID

需求 ID 使用 `<PREFIX>-<NNN>` 格式，例如 `AUTH-001`、`ADM-214`。

要求：

1. 全仓唯一。
2. 已确认、进行中、已完成的需求必须出现在模块 PRD。
3. 已完成需求必须有验收证据和测试记录。
4. 改代码、契约、数据表或运营配置时，提交信息和工作日志必须引用需求 ID。

## 契约优先

涉及接口、事件、DTO 的需求，必须先更新契约：

1. OpenAPI：`docs/api/openapi.yaml`
2. 事件契约：`packages/contracts/`
3. 前后端类型：`packages/generated/` 或 `packages/ts-sdk/`

不涉及契约时，要在需求总账或 Agent 日志中写明原因。

## 验收

验收标准必须可复现、可截图、可测试。不能用“已实现”“已完成”“看起来正常”作为验收结论。
