# 2026-07-04 PG 拆分静态资源接入 GCS 和 CDN 说明

> 公开版脱敏说明：公司、平台、节点、账号、地址和业务对象均已替换为示例标识；替换后的名称仅用于公开复盘。

> 来源文件：`~/Projects/ops/private-notes/master/docs/history/2026-07-04-【架构改造】PG拆分静态资源接入GCS和CDN说明.md`

> 整理日期：2026-07-04 00:00｜日期依据：文件名日期

## 背景

PG 新版资源拆出了 3 组特殊静态目录：

```text
/www/wwwroot/pg3-static
/www/wwwroot/pg4-static
/www/wwwroot/pg5-static
```

`platform-api/conf/domains/pg.json` 已经按游戏 ID 把 PG 特殊资源分到 `pg3-static.*`、`pg4-static.*`、`pg5-static.*`：

```text
pg3: 1799745, 2100928, 1849515, 1940257, 1981965, 67
pg4: 65, 74
pg5: 91
```

用户反馈 PG 麻将胡了加载很慢，浏览器里静态资源长时间等待；此前 `pg4-static.*` 域名仍然通过 Cloudflare 橙云回源宝塔，响应头里能看到 `server: cloudflare`、`cf-cache-status: DYNAMIC`、`set-cookie: server_name_session=...`，单个小 JSON 约 2s，说明没有走原有 Google HTTPS LB + Cloud CDN + GCS 静态桶链路。

## 排查结论

慢加载主因不是业务认证接口，而是 PG3 / PG4 / PG5 新静态域名没有接入 GCS/Cloud CDN：

```text
旧 pg-static.*:
  DNS -> 192.0.2.9
  Google HTTPS LB -> bb-pg-static -> gs://bizops-gcs-pg-static

新 pg3-static.* / pg4-static.* / pg5-static.*:
  DNS -> Cloudflare 橙云
  回源宝塔 /www/wwwroot/pg3-static|pg4-static|pg5-static
  不在 /www/server/cron/gcs_static_sync
  不存在 bizops-gcs-pg3-static / bizops-gcs-pg4-static / bizops-gcs-pg5-static live bucket
  URL map bizops-static-gcs-map 没有 pg3/pg4/pg5 host rule
```

已验证现象：

```text
https://pg4-static.m7v8k3.cyou/65/922d4f1ffd.f244d.json -> 200, Cloudflare DYNAMIC, set-cookie, 约 2s
https://pg-static.m7v8k3.cyou/65/922d4f1ffd.f244d.json  -> 404, Google UploadServer, 说明老 pg-static 已走 GCS 但没有 PG65 新资源

gcloud compute backend-buckets list | grep pg:
  bb-pg-static -> bizops-gcs-pg-static

bizops-static-gcs-map hostRules:
  只有 pg-static.*，没有 pg3-static.* / pg4-static.* / pg5-static.*

/www/server/cron/gcs_static_sync:
  只有 PG / vendor_a / vendor_a1 / vendor_a2 / PP / PPK / vendor_c / PANDA
  没有 PG3 / PG4 / PG5
```

## 本次运维侧改造目标

新增 3 条 live 静态桶：

```text
PG3 /www/wwwroot/pg3-static -> gs://bizops-gcs-pg3-static/
PG4 /www/wwwroot/pg4-static -> gs://bizops-gcs-pg4-static/
PG5 /www/wwwroot/pg5-static -> gs://bizops-gcs-pg5-static/
```

新增 3 条 backup 前缀：

```text
PG3 /www/wwwroot/pg3-static -> gs://bizops-game-statics-gcs/pg3-static
PG4 /www/wwwroot/pg4-static -> gs://bizops-game-statics-gcs/pg4-static
PG5 /www/wwwroot/pg5-static -> gs://bizops-game-statics-gcs/pg5-static
```

新增 Google backend bucket：

```text
bb-pg3-static -> bizops-gcs-pg3-static, Cloud CDN enabled, CACHE_ALL_STATIC
bb-pg4-static -> bizops-gcs-pg4-static, Cloud CDN enabled, CACHE_ALL_STATIC
bb-pg5-static -> bizops-gcs-pg5-static, Cloud CDN enabled, CACHE_ALL_STATIC
```

新增 URL map host 分流：

```text
pg3-static.* -> bb-pg3-static
pg4-static.* -> bb-pg4-static
pg5-static.* -> bb-pg5-static
```

Cloudflare DNS 需要把 66 个新静态域名全部改为：

```text
A 192.0.2.9
proxied=false
```

## 线上操作顺序

1. 在 GCP 项目 `infra-alc-20260511` 创建 3 个 live bucket，开启公开读和 CORS。
2. 在 Google Compute 创建 3 个 backend bucket，开启 Cloud CDN。
3. 把 `pg3-static.*`、`pg4-static.*`、`pg5-static.*` 66 个 host 加入 `bizops-static-gcs-map`。
4. 把 Cloudflare DNS 中 66 个静态域名改成 `192.0.2.9` 且灰云。
5. 上传新版 `/www/server/cron/gcs_static_sync` 到宝塔。
6. 执行 live 同步，确认 probe 和样例资源 200。
7. 再跑 backup 同步或等待每日任务。

## 验证命令

```bash
dig +short pg4-static.xqv9m8.icu
curl -I https://pg4-static.xqv9m8.icu/65/922d4f1ffd.f244d.json
curl -sS -o /dev/null -w '%{http_code} %{time_total}\n' \
  https://pg4-static.xqv9m8.icu/65/922d4f1ffd.f244d.json
gsutil ls gs://bizops-gcs-pg4-static/65/922d4f1ffd.f244d.json
gcloud compute backend-buckets list --project=infra-alc-20260511 | grep pg
```

期望：

```text
DNS 返回 192.0.2.9
响应头 server 不再是 Cloudflare DYNAMIC 回源宝塔
不再出现 server_name_session cookie
样例 JSON 200
Cloud CDN warm 后响应明显快于宝塔回源
```

## 回滚

如 GCS 链路异常，可临时把对应 Cloudflare DNS 改回橙云回源宝塔，`pg3-static.*` / `pg4-static.*` / `pg5-static.*` 仍会落到 `/www/wwwroot/pg3-static`、`pg4-static`、`pg5-static`。这个回滚会恢复慢加载风险，但可以保障资源可访问。

不要删除 bucket 和 backend bucket；只回滚 DNS 即可。
