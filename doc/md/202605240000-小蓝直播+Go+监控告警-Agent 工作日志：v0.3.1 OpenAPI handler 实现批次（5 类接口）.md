## 核心决策

1. **数据复用 vs 新表**：
   - **新表 `live_lines`**：线路数据有独立生命周期（CRUD / 软删 / 排序），逻辑独立于现有任何表，建表更清晰
   - **复用 `home_banners`**：H5 4 广告位本质是带 position 维度的"轮播配置"，已有表完全够用；只需扩 position 枚举值（4 个新值），避免重复造轮子；D 位 marquee 文本暂用 link_target 字段承载（避免再加列）
   - **复用 `system_configs`**：支付通道状态本质是 K-V 配置（enabled set / 推荐 set / 通道独立费率），用既有 system_configs 表 + JSON value 即可
2. **rowsAffected==0 = upsert insert 分支**：H5 ads + payment_channels 都遵循"先 update；不存在则 insert"；不用 ON DUPLICATE KEY UPDATE 因为没有合适唯一键（home_banners 无 position 唯一索引）
3. **Match phase → status 派生联动**：admin 切 phase 时自动派生 status（pre_match→UPCOMING / finished→ENDED / else→LIVE），保持 status 与 phase 不冲突，公共 GET /match/{id} 两个字段恒一致
4. **半场/中场/比赛前/结束态的 minute 强制 NULL**：phase 在 half_time / et_break / pre_match / finished 时 minute 没语义，直接 NULL；其他阶段才看请求传值
5. **LiveLine.Code 作为 client 切线 ID**：user 端 GET /live/lines 不暴露内部 BIGINT id（防爬+预留未来 ID 迁移空间），返回业务 code（如 "line_2"），select 上报也用 code
6. **user 端线路 select 是 fail-open**：审计上报失败 / 线路不存在都不阻塞客户端切流（用户体验优先；统计有缺漏可后续补）
7. **payment_channels.update fee_rate 范围 [0, 0.5]**：5% 是当前默认，给上限 50% 防止误操作打错小数点（5.0 被填进去当 500% 抽水）
8. **/config/h5-ads 匿名可访问**：home 页加载即拉，无登录前提；与 /home/banner 一致策略
9. **PaymentChannels.Update 加 requireFinance 角色限制**：通道费率 / 开关属财务敏感，仅 finance_admin 可操作；list 走普通 requireAdmin
