## 三、为什么完整 7 天无法提供

Panda 日志路径：

```text
/data/server-runtime/logs/panda/
```

日志按 UTC 日期和小时轮转为：

```text
YYYY-MM-DD.log
YYYY-MM-DD.log-YYYYMMDD-HHMMSS.gz
```

但当前生产保留策略已于 2026-10-20 调整为 **48 小时**，不是 7 天：

```text
脚本：/usr/local/sbin/prune_game_logs.sh
策略：MINUTES=2880
计划：每天 09:10 UTC
```

2026-10-30 的清理证据：

```text
prod-01  09:10:04 UTC  删除 200 个文件 / 22,135,061 bytes
prod-02  09:10:03 UTC  删除 200 个文件 / 22,289,683 bytes
prod-04  09:10:01 UTC  删除 0 个文件（新扩容节点）
prod-05  09:10:02 UTC  删除 0 个文件（新扩容节点）
```

清理后最早可读记录：

```text
prod-01：2026-10-28 09:09:39.317 UTC
prod-02：2026-10-28 09:08:03.379 UTC
prod-04：2026-10-29 07:43:51.281 UTC（扩容上线）
prod-05：2026-10-29 07:43:22.450 UTC（扩容上线）
```

同时核查了：

```text
01/02/04/05 全盘可能副本：未找到 10-23 至 10-27 Panda 文件
prod-03 日志目录：空
S3 backend-game-logs：没有 10-23 至 10-27 对象
S3 full-logs：只有 10-04～10-11、10-14～10-15 历史导出
S3 error-packs：Panda 最后日期为 10-18
```

结论：

```text
请求窗口：2026-10-23 09:43 UTC ～ 2026-10-30 09:43 UTC
实际可恢复：2026-10-28 09:08 UTC ～ 2026-10-30 09:43 UTC
缺失区间：约 2026-10-23 09:43 ～ 2026-10-28 09:08 UTC
```

缺失原因是 48 小时保留策略，不是本次导出失败，也不是 S3 下载失败。
