# 项目内域名写死排查

> GitHub 仓库源文件：[点击打开网页渲染版](https://github.com/ben2023niao/ben-ops-notes/blob/main/doc/md/202304141557-%E6%95%85%E9%9A%9C%E6%8E%92%E6%9F%A5%2B%E9%97%AE%E9%A2%98%E6%8E%92%E6%9F%A5%2BNginx%2BPHP-%E9%A1%B9%E7%9B%AE%E5%86%85%E5%9F%9F%E5%90%8D%E5%86%99%E6%AD%BB%E6%8E%92%E6%9F%A5.md)

反馈人  ramon

问题描述
前端php业务配置有 a.com b.com 等
[a.com](http://a.com) 下访问业务一切正常
b.com 访问业务就出现部分接口显示 a.com 调用跨域报错
已排查nginx配置都是正常，看日志确实是跨域调用，检查前端代码没出现XSS等劫持情况，然后开发那边一口咬死说没写死域名

原因
进php项目文件内 index.php 文件的 ajax 写死了请求域名

处理方法

-r 是递归查找 -n 是显示行号 -R 查找所有文件包含子目录 -i 忽略大小写 ---xargs配合grep查找

find -type f -name '*.php'|xargs grep '://'

一、查看文件追加的含有关键字的内容

tail -f xxxxx.log | grep '://'

二、查看文件含有关键字的内容

cat xxx.log | grep keyword

三、统计文件中关键字出现的次数

cat xxx.log | grep -o keyword | wc -l

四、查看当前文件夹中包含某字符的文件

grep -r 'XXX' ./

然后通知开发把 index.php 内ajax调用域名写活
