环境：

```text

```

涉及游戏：

```text
后端日志看不到 verify 请求，表现为“网络没到服务器”。
```

## 核心结论

这次不是 PG 静态资源没同步，也不是两个游戏目录缺资源。

两款游戏的 `pg-static` 静态资源目录存在，GCS / CDN 抽样访问 200。真正问题集中在部分 `pg-games` 入口域名生成 verify/API host 的逻辑：

```text
正常入口：
https://pg-games.xqv9m8.icu/128/index.html

正常 verify：
https://pg-games.xqv9m8.icu/web-api/auth/session/v2/verifyOperatorPlayerSession

异常入口：
https://pg-games.t6qv8m.icu/128/index.html

异常 verify：
https://pg-games.t6qv8api.icu/web-api/auth/session/v2/verifyOperatorPlayerSession
```

`pg-games.t6qv8api.icu` 不是当前合法域名，没有 DNS 记录，浏览器直接报：

```text
net::ERR_NAME_NOT_RESOLVED
```

因此请求根本到不了 Cloudflare / 宝塔 Nginx / 后端服务，后端日志自然没有 verify 记录。

## 为什么会拼出 t6qv8api.icu

从现象看，客户端或后端返回给客户端的域名派生逻辑很可能做了类似：

```text
把 hostname 里的 "m." 替换成 "api."
```

`pg-games.t6qv8m.icu` 末尾正好包含：

```text
m.icu
```

如果做字符串替换，就会变成：

```text
pg-games.t6qv8api.icu
```

这不是预期的 API 域名。预期应是以下二选一：

```text
https://pg-games.t6qv8m.icu/web-api/...
```

或者：

```text
https://api.t6qv8m.icu/web-api/...
```

当前宝塔运维侧已经支持 `pg-games.*` 和 `api.*` 两类 host 反代 PG API；但是不支持这种误拼出来的 `pg-games.t6qv8api.icu`。

同类风险域名：

```text
pg-games.t6qv8m.icu -> 可能被误拼成 pg-games.t6qv8api.icu
pg-games.6qv8m.icu -> 可能被误拼成 pg-games.6qv8api.icu
```

只要根域名最后是 `m.icu`，都要重点检查。

## 后端开发建议修复

优先修业务侧 API host 派生逻辑，不建议长期靠新增奇怪域名兜底。

建议规则：

1. 如果当前入口是 `pg-games.<root>`，verify / game-proxy / game-api 可以直接走同源：

```text
apiBase = window.location.origin
```

最终请求：

```text
https://pg-games.<root>/web-api/auth/session/v2/verifyOperatorPlayerSession
https://pg-games.<root>/web-api/game-proxy/v2/GameName/Get
https://pg-games.<root>/game-api/pg/v2/GameInfo/Get
```

2. 如果必须分离到 `api.<root>`，只能做明确前缀替换：

```text
pg-games.t6qv8m.icu -> api.t6qv8m.icu
```

不要对 hostname 做泛化字符串替换，例如不要替换任意位置的 `m.`。

伪代码：

```python
def pg_api_host(game_host: str) -> str:
    if game_host.startswith("pg-games."):
        return "api." + game_host[len("pg-games."):]
    return game_host
```

需要加单测的 host：

```text
pg-games.xqv9m8.icu      -> api.xqv9m8.icu 或 pg-games.xqv9m8.icu
pg-games.t6qv8m.icu      -> api.t6qv8m.icu 或 pg-games.t6qv8m.icu
pg-games.6qv8m.icu       -> api.6qv8m.icu 或 pg-games.6qv8m.icu
pg-games.p8m7xv.cyou     -> api.p8m7xv.cyou 或 pg-games.p8m7xv.cyou
pg-games.m7v8k3.cyou     -> api.m7v8k3.cyou 或 pg-games.m7v8k3.cyou
```

## 额外发现：Service Worker scope 警告

两款游戏的 Console 都有同一个警告：

```text
The path of the provided scope ('/') is not under the max scope allowed ('/shared/service-worker/').
Adjust the scope, move the Service Worker script, or use the Service-Worker-Allowed HTTP header to allow the scope.
```

这不是本次 verify 不到服务器的主因，因为 `xqv9m8` 入口在出现该警告的同时仍能成功进入游戏。

但它会影响 service worker 缓存注册，可能造成缓存策略不生效或某些浏览器表现不一致。后续可在 Nginx 对：

```text
/shared/service-worker/sw.js
```

补：

```nginx
add_header Service-Worker-Allowed "/" always;
```

这个属于优化项，不应替代 API host 根因修复。
