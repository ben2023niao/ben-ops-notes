# 2026-09-30 香港后端域名配置切换到 m4q7z1.shop（腾讯 CDN）

> 公开版脱敏说明：公司、平台、节点、账号、地址和业务对象均已替换为示例标识；替换后的名称仅用于公开复盘。

> GitHub 仓库源文件：[点击打开网页渲染版](https://github.com/ben2023niao/ben-ops-notes/blob/main/doc/md/202609301650-%E9%A6%99%E6%B8%AF%20CN%2BShell%2BDocker-2026-09-30%20%E9%A6%99%E6%B8%AF%E5%90%8E%E7%AB%AF%E5%9F%9F%E5%90%8D%E9%85%8D%E7%BD%AE%E5%88%87%E6%8D%A2%E5%88%B0%20m4q7z1.shop%EF%BC%88%E8%85%BE%E8%AE%AF%20CDN%EF%BC%89.md)

> 整理日期：2026-09-30 16:50｜日期依据：文件名日期

## 一、需求与结论

```text
需求（用户）：香港 prod-01/02 容器里的域名配置现在是 hkcloudplay06.com / hkcloudplay07.com，
             换成腾讯 CDN 的 m4q7z1.shop；容器是热更新读配置的，没生效才重启（重启 api 容器即可）。
结论：
  · 配置已替换（两台后端），**无需重启**——代码是「每次请求实时读 JSON」，
    且 bind mount 下容器内立刻可见新内容（已实测）。
  · 端到端对比通过：pg-games.m4q7z1.shop/65/index.html 与 CF 06 同为 200 且 33341B；
    8 个厂商 /health 经 EdgeOne 全部 200。
```

## 二、改动范围（只替换 EdgeOne 上确实存在的二级域名）

```text
改（34 处 host 列表）：
  static_hosts : pg-static / pg3~pg7-static / pp-static / ppk-static / vendor_d-static /
                 vendor_c-static / g759-static / vendor_b-static / vendor_b-static1 / vendor_b-static2
                 -> <前缀>.m4q7z1.shop
  game_hosts   : pg-games / vendor_b-games / pp-games / ppk-games / vendor_d-games /
                 vendor_c-games / g759-games -> <前缀>.m4q7z1.shop
  别名映射     : vendor_b-static1-aws -> vendor_b-static1.m4q7z1.shop
                 vendor_b-static2-aws -> vendor_b-static2.m4q7z1.shop
                 （巴西命名遗留；这两个前缀在 CF 06 上本来就是 404，映射后反而可用）
  去重         : 原来 06+07 两条同前缀域名 -> 合并成一条 m4q7z1.shop

不改（EdgeOne 无对应域名，且这些前缀在 CF 06 上本来也是 404）：
  fc.json      fachai-test / fachai-api
  jdb.json     jdb-test / jdb-api
  vendor_b.json    vendor_b-static3-aws / vendor_b-static4-aws / vendor_b-static5-aws
  vendor_a.json    vendor_a-games / vendor_a-statics3 / vendor_a-statics4 / vendor_a-statics5
  pg.json      api_hosts = socket.hk-socket.com（独立商户域名，未动）
```

## 三、执行过程

```text
1. 两台后端（192.0.2.17 = prod-02 / 192.0.2.16 = prod-01）的 conf/domains 内容完全一致
   （10 个 json：fc g759 jdb vendor_b vendor_d pg vendor_c popok pp vendor_a）。
2. 备份：cp -a /data/server-runtime/conf/domains /data/server-runtime/conf/domains.bak-20260930-m4q7z1
3. 用脚本按上面的规则转换，本地生成后 scp 覆盖两台的 /data/server-runtime/conf/domains/。
4. 校验：两台逐文件 json.load 通过；grep 确认已无「本该替换的」06/07 残留。
5. 生效性核验：
   · start.sh 把 /data/server-runtime/conf/domains 挂到容器 /app/config/domains（bind mount）
     -> docker exec 里读到的已经是 m4q7z1.shop
   · platform-api 的 game_domains_manager.load_provider_config() 是**每次请求**打开
     /app/config/domains/<厂商>.json，无内存缓存 -> 属热更新，不需要重启
```

## 四、验证

```text
入口页对比：
  https://pg-games.hkcloudplay06.com/65/index.html   -> 200  33341B（CF 链路）
  http://pg-games.m4q7z1.shop/65/index.html          -> 200  33341B（EdgeOne 链路，内容一致）
动态 /health（经 EdgeOne）：
  pg-games / api / vendor_b-games / pp-games / ppk-games / vendor_d-games / vendor_c-games
  / g759-games -> 全部 200
容器内读取：
  docker exec game-service-api-prod (及 vendor_b/pg 容器) 里 /app/config/domains/pg.json
  已显示 pg-games.m4q7z1.shop / pg-static.m4q7z1.shop / pg3~pg7-static.m4q7z1.shop
```

## 五、回滚

```text
两台各执行：
  mv /data/server-runtime/conf/domains /data/server-runtime/conf/domains.m4q7z1-broken
  mv /data/server-runtime/conf/domains.bak-20260930-m4q7z1 /data/server-runtime/conf/domains
（因为是每次请求读文件，回滚同样是即时生效；不需要重启容器）
```

## 六、待确认

```text
1. vendor_a.json 的 game_hosts 仍是 vendor_a-games.hkcloudplay06.com（EdgeOne 无该域名、CF 上也是 404）。
   若希望 vendor_b 的动态入口也走腾讯 CDN，可把它改成 vendor_b-games.m4q7z1.shop（说一声我就改）。
2. vendor_b-static3/4/5-aws、vendor_a-statics3/4/5、fachai-*、jdb-* 这些历史前缀保持原样；
   若某个厂商要真正在 HK 上线，需要在 EdgeOne 建对应加速域名 + nginx 站点后一起切。
3. m4q7z1 的 HTTPS 证书仍在签发（18 applying / 2 重试），客户端若强制 https 需等证书就绪。
```
