# Jenkins 容器访问 Docker 2376 修复（2026-11-01）

> 来源文件：`~/Projects/work/ops/devops/devops-bkl/doc/2026年11月1日-Jenkins容器访问Docker2376修复/2026年11月1日-Jenkins容器访问Docker2376修复.md`

> 整理日期：2026-11-01 00:00｜日期依据：文件名日期

日期：2026-11-01
执行人：Ben（运维）
环境：BKL UAT middleware `203.0.113.1`

## 问题

Jenkins 发布服务失败，流水线无法连接：

```text
Connect to 203.0.113.1:2376 failed: Connection timed out
```

最新失败记录确认：

- `game-backend` build #69：在 `game-scheduler` Docker Maven 插件阶段超时。
- `pay-backend` build #26：在 `pay-scheduler` Docker Maven 插件阶段超时。
- 同一时间 `middle-station-backend` build #28 成功构建并推送镜像。

## 根因

Jenkins 容器所在网络：

```text
network=jenkins_default
container_ip=203.0.113.1
```

middleware Docker daemon 正常监听双向 TLS：

```text
0.0.0.0:2376
tlsverify=true
```

问题位于 `UAT-INPUT` 规则顺序：

1. 先仅允许来源 `203.0.113.1/24` 访问 2376。
2. 紧接着 DROP 所有其他来源的 2376。
3. 通用内网放行 `203.0.113.1/12` 和 `203.0.113.1/8` 在 2376 DROP 之后，因此 Jenkins 的 `203.0.113.1` 永远到不了通用内网放行规则。

这解释了为什么宿主机通过 `203.0.113.1:2376` 可以访问，而 Docker bridge 内的 Jenkins 不可以。

## 修复

修改 `security/apply_uat_firewall.sh`：

- 2375 仍只允许 `203.0.113.1/24`。
- 2376 继续要求双向 TLS，并显式放开实际需要的网段：
  - `203.0.113.1/16`，Jenkins bridge（当前 Jenkins 为 `203.0.113.1`）
  - `203.0.113.1/8`，Docker overlay
  - `203.0.113.1/24`，UAT 主机内网
  - `203.0.113.1/24`，SRS 专线
- 所有其他来源，包括公网，继续对 2376 执行 DROP。

变更前备份：

- `/usr/local/sbin/uat-firewall.sh.bak-20261101`
- `/root/uat-iptables-before-2376-20261101.rules`
- `/usr/local/sbin/uat-firewall.sh.bak-20261101-pre-explicit`（按 SVD 要求改为显式容器网段前的版本）

修复脚本已重新安装并通过 `uat-firewall.service` 持久化：

```text
uat-firewall.service: active
enabled: enabled
```

## 验证

### 容器到 Docker API

修复前：

```text
Jenkins -> 203.0.113.1:2376
timeout 5 /dev/tcp
status=124
```

修复后：

```text
tcp_status=0
CONNECTED(00000003)
subject=CN=43.249.251.11
```

Jenkins 容器使用已挂载的客户端证书调用 Docker API：

```text
docker_api_ok 29.9.1 api 1.56
```

这证明容器不仅端口可达，而且 mTLS 身份认证和 Docker API 请求均正常。

### 安全验证

- 不带客户端证书访问 2376：`TLSv13 alert certificate required`，正确拒绝。
- 从堡垒机访问公网 `43.249.251.11:2376`：超时。
- 从堡垒机访问公网 `43.249.251.11:2375`：超时。
- 2375 仍未对容器开放。

### 当前规则命中

```text
ACCEPT 203.0.113.1/16   tcp dpt:2376  pkts=5
ACCEPT 203.0.113.1/8      tcp dpt:2376  pkts=0
ACCEPT 203.0.113.1/24 tcp dpt:2376  pkts=0
ACCEPT 192.168.172/24  tcp dpt:2376  pkts=0
DROP   0.0.0.0/0       tcp dpt:2376  pkts=0
```

## 影响与后续

- 未重启 Jenkins、Docker daemon 或任何业务容器。
- 未修改业务数据。
- 未主动触发完整发布流水线，避免产生非必要部署；下一次 Jenkins 发布应重点观察 Docker Maven 插件是否继续报超时。
- 2376 仍是双向 TLS，不是无认证 Docker API；不得为了排障把 2375 或公开 2376 打开。
- 群内已通知：Jenkins 容器源地址、规则顺序、修复范围和外网阻断结果。
