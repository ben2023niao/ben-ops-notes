# 2026-08-26 巴西 G759 无法游戏线路探测根路径修复记录

## 背景

```text
用户反馈巴西 G759 无法游戏。
```

## 排查过程

```text
1. 后端核验：三台 bizops-g759-release 容器 running（master-b3083550，Up 5 天），
   9019 端口 404（业务根路径），/v2/MsgGameAuthReq 401“缺少平台认证令牌”（正常业务校验）——后端无故障。
2. 入口核验：H5 入口 g759bronlineone 200、g759-static 静态页 200。
3. 真实浏览器点击游戏：跳转到 g759-static 游戏页（.../games/slorabbitnew/index.html?...server_url=g759-games.*），
   但游戏卡在“正在登录”，控制台出现大量 g759-games.*/?t= 与 g759-static.*/?t= 请求失败。
4. 根因定位：g759 客户端对 g759-games/static 各根域根路径（/?t=）做线路连通探测，
   期望 HTTP 200 才判定线路可用；宝塔对 g759-games 根路径返回 404、g759-static 根路径返回 403，
   客户端判定所有线路不可用 -> 无法进入游戏。
   对照：pg-games 根路径返回 200（launcher HTML），PG 游戏正常。
```

## 修复

```text
宝塔与备用机 nginx 给 g759-games / g759-static 站点增加根路径精确匹配：
    location = / {
        default_type text/plain;
        return 200 "ok";
    }
其他路径行为不变；nginx -t 通过并 reload；
原配置备份：*.conf.bak-20260826。
```

## 验证

```text
1. 根路径：g759-games.*/?t= 与 g759-static.*/?t= 全部 200（GET/HEAD）；
2. 正常路径不受影响：g759-static 游戏页 200、/v2/MsgGameAuthReq 401（业务校验）；
3. 真实浏览器完整复测：点击游戏成功进入（资源加载后 canvas 接管，约 30s），
   后端日志 POST /v2/MsgGameAuthReq 200、MsgGameEnterReq 200（登录+进入成功）；
4. 剩余 /?t= 请求为 net::ERR_ABORTED，属客户端并发线路探测正常中止（已找到可用线路），非故障。
```

## 结论

```text
巴西 G759 无法游戏根因为客户端线路探测根路径 404/403 误判，已通过 nginx 根路径返回 200 修复；
宝塔与备用机同步，真实浏览器验证可正常进入游戏。
```
