## 已落地配置

### 业务日志

配置文件：`/etc/dbqp-logrotate/pgserver`

策略如下：

- 匹配 `/opt/pgserver/logs/*/*.log`。
- 每天轮转；单文件超过 1GB 时由小时任务提前轮转。
- 轮转文件最多保留 7 天，使用 gzip 压缩。
- 使用 `copytruncate`，不要求业务进程重新打开日志文件。
- 使用日期和时间后缀，避免同一天内大文件多次轮转时重名。

```text
/opt/pgserver/logs/*/*.log {
    su root root
    daily
    rotate 200
    maxage 7
    maxsize 1G
    missingok
    notifempty
    compress
    copytruncate
    dateext
    dateformat -%Y%m%d-%H%M%S
}
```

### Docker 日志

Docker daemon 配置文件：`/etc/docker/daemon.json`

```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "100m",
    "max-file": "7"
  }
}
```

该配置对后续新建或重新创建的容器生效。现有业务容器没有为修改日志参数而强制重建，改由 `/etc/dbqp-logrotate/docker-json-existing` 对现有 JSON 日志执行 `100MB × 7` 外部轮转；业务正常发布并重建容器后，会自动使用 Docker daemon 内建轮转参数。

### journald

配置文件：`/etc/systemd/journald.conf.d/99-dbqp-retention.conf`

```text
[Journal]
SystemMaxUse=1G
SystemKeepFree=10G
MaxRetentionSec=7day
MaxFileSec=1day
Compress=yes
```

journald 最长保留 7 天，总占用上限 1GB，同时为根磁盘至少保留 10GB 空闲空间。

### 定时任务

新增 systemd 单次任务和定时器：

```text
/etc/systemd/system/dbqp-log-maintenance.service
/etc/systemd/system/dbqp-log-maintenance.timer
```

定时器每小时执行一次，并增加 0 至 5 分钟随机延迟，依次处理业务日志、现有 Docker JSON 日志和 journald。定时器已设置为开机自动启用，并使用独立 logrotate 状态文件，避免与系统默认 logrotate 任务冲突。

## 备份与回滚

操作前配置和 Docker 容器 inspect 信息已分别备份：

```text
后端 01：/root/dbqp-log-retention-backup-20260715_151804
后端 02：/root/dbqp-log-retention-backup-20260715-152400
```

如需停用本次策略，可先执行：

```bash
systemctl disable --now dbqp-log-maintenance.timer
rm -f /etc/systemd/system/dbqp-log-maintenance.timer
rm -f /etc/systemd/system/dbqp-log-maintenance.service
rm -rf /etc/dbqp-logrotate
rm -f /etc/systemd/journald.conf.d/99-dbqp-retention.conf
rm -f /etc/docker/daemon.json
systemctl daemon-reload
systemctl restart systemd-journald
systemctl restart docker
```

如果服务器操作前已有同名配置，应从对应备份目录恢复，而不是直接删除。回滚 Docker 时仍应逐台执行，并在每台完成七个容器和八个端口检查后再处理下一台。
