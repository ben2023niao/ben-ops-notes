# AI 原生协作框架规则

> 来源文件：`~/Projects/work/game/xiaolan-watches/dev/docs/agents/rules/ai-native-framework-rules.md`

> 整理日期：2026-06-04 01:09｜日期依据：文件创建/修改时间

{{PROJECT_NAME}} 首先是团队 AI 原生协作框架的试验仓，不只是产品仓库。产品代码、PRD、OpenAPI、Git 规则、CI、日志、模板和协作方式都服务于一个核心目标：让团队能高效、可复制地用 AI Agent 交付复杂项目。

## 1. 仓库定位

{{PROJECT_NAME}} 的核心资产不是某一次业务实现，而是：

1. 规则。
2. 模板。
3. 契约。
4. 工作流。
5. 日志沉淀。
6. 可复制的 AI 工程团队协作方式。

业务代码会持续变化，但框架规则必须沉淀下来，后续项目可以复制复用。

## 1.1 技术价值判断

AI 框架的价值不以文档数量衡量，而以是否产生可复用、可规模化的技术资产衡量。

一项实践只有满足以下条件，才算框架价值：

1. 可复用：不绑定单一项目、业务接口、设计图、服务器或密钥。
2. 可配置：能通过模板变量、`framework.config.json`、`project.config.json` 或 ADR 适配新项目。
3. 可验证：有脚本、CI、测试或清单证明规则被执行。
4. 可规模化：能支撑多 Agent、多端、多 Web surface、多服务、多技术栈协作。
5. 可迁移：复制到新项目后能直接指导开工。

如果只是修复当前项目，但没有沉淀为规则、模板、契约结构、校验器、CI、技术栈适配器或 Playbook，只能算项目经验。

框架价值模型见：

```text
docs/quality/framework-value-model.md
```

## 1.2 公共框架与项目 Overlay

公共框架和项目 Overlay 必须分层维护。

公共框架负责沉淀团队通用能力：

1. Monorepo 目录边界。
2. Git、CI、日志、红蓝对抗、验收门禁。
3. PRD、OpenAPI、ADR、测试证据结构。
4. Go Gin、Laravel、Nuxt 4、Tailwind CSS v4、packages 边界等技术栈适配器。

项目 Overlay 负责沉淀当前项目选择：

1. 启用哪些 apps 和 services。
2. 当前项目类型和 Scale Profile。
3. 当前项目的第三方服务、环境、设计验收强度。
4. 当前项目允许的临时例外和补齐条件。

项目 Overlay 写入：

```text
project.config.json
docs/project/**
```

公共硬规则不能被项目 Overlay 关闭。Agent 日志、红蓝对抗、Contract First、项目级验收和 mock 不能冒充完成，永远是底线。

## 2. AI 生成代码假设

后续约 95% 业务代码预计由 AI 生成。因此所有规则必须面向 AI reviewer 和 AI implementer 设计。

这意味着：

1. 隐性知识必须显式写入文档。
2. 不要依赖“大家都懂”。
3. 不要依赖 reviewer 凭经验补齐遗漏。
4. PRD、OpenAPI、数据模型、Git 规则和日志必须足够明确。
5. AI 输出必须通过契约、测试、日志和 Review 约束。

## 3. 每次任务的双重目标

每次任务都有两个目标：

1. 完成具体改动。
2. 打磨 AI 原生协作框架。

如果任务中发现流程、模板、命名、权限、CI、CODEOWNERS、OpenAPI 拆分、日志格式等有摩擦，不能只解决眼前问题就略过。必须：

1. 写入本次 Agent 日志的“风险与待办”。
2. 或单独创建框架优化任务/MR。
3. 必要时更新模板，确保后续项目不重复踩坑。

## 4. 框架摩擦必须记录

以下情况都属于框架摩擦：

1. 分支命名导致拒推。
2. token scope 或 SSH key 权限导致推送失败。
3. CODEOWNERS 不生效。
4. CI 路径触发不合理。
5. OpenAPI 拆分导致引用难维护。
6. Agent 写入范围不清导致冲突。
7. 文档模板缺字段。
8. 规则只存在聊天里，没有落到仓库。

遇到这些问题，必须显式记录。不能把一次性踩坑当成个人经验留在脑子里。

## 5. 隐性知识显式化

所有隐性知识必须落到以下位置之一：

| 类型 | 落地位置 |
| --- | --- |
| 产品规则 | `docs/prd/` |
| 跨模块业务规则 | `docs/agents/rules/business-rules.md` |
| 工程规则 | `docs/agents/rules/engineering-rules.md` |
| AI 协作规则 | `docs/agents/rules/ai-native-framework-rules.md` |
| API 契约 | `packages/contracts/openapi/` |
| 文档双视图模型 | `docs/architecture/documentation-model.md` |
| 数据模型 | `docs/architecture/data-model.md` |
| 技术决策 | `docs/decisions/ADR-*.md` |
| Git/部署/CI 规则 | `docs/operations/`、`infra/ci/` |
| 踩坑和交接 | `docs/agents/logs/` |
| 公共框架资产 | 公共 AI 框架仓库，经 `.ai-framework` 子仓库进入项目 |
| 项目 Overlay | `project.config.json`、`docs/project/**` |

如果一条知识没有落地，就默认 AI reviewer 不知道。

## 6. 例外必须记录

早期阶段允许个别例外，例如：

1. author 自合文档类 MR。
2. 暂时没有真实 CODEOWNERS。
3. 暂时没有完整 CI。
4. 暂时用占位 handler 或 mock client。
5. 暂时跳过某些依赖安装或编译验证。

但例外必须写入 Agent 日志，说明：

1. 为什么例外。
2. 风险是什么。
3. 什么时候补齐。

例外不能沉默地变成默认流程。

## 7. 规则必须尽量可执行

AI Agent 会倾向于把软规则理解成建议。框架规则不能只写“应该”，还要尽量变成脚本、CI、模板字段或 Review 阻断项。

以下规则必须优先脚本化：

1. 涉及 `apps/mobile/**` 或 `apps/admin/**` 的变更，必须有 Agent 日志。
2. 实现类变更必须引用 `docs/prd/requirements.md` 中的需求 ID；没有需求 ID 时只能停在 PRD 阶段。
3. OpenAPI operation 必须写 `x-prd-id`，或明确 `x-prd-not-applicable: true`。
4. 代码实现必须遵守 `docs/quality/code-standards.md`；例外必须写进 Agent 日志和 Review。
5. 数据表、索引、迁移、账本和审计设计必须遵守 `docs/architecture/database-design-standards.md`，并更新 `docs/architecture/data-model.md`。
6. 上线、部署、回滚、密钥、备份恢复、观测和故障响应必须遵守 `docs/operations/ops-readiness.md`，并通过 `npm run check:ops`。
7. 移动端页面必须记录设计图文件名、尺寸、真实手机视口截图、公共组件拆分和 API 接入说明。
8. 后台页面必须记录真实业务对象、接口路径、权限和审计日志处理。
9. 仍存在 fallback/mock/placeholder 的后台实现必须写明 `占位原因`，不能标记为完成。
10. 红蓝对抗必须给出明确结论：允许合入、不允许合入、允许继续或不允许继续。
11. 冒烟测试只能证明基础可达，不能替代产品验收、视觉验收或业务验收。
12. 每个需求、页面、接口和后台模块都必须有 `docs/qa/acceptance-evidence.md` 证据行；没有证据行不能说完成。
13. 测试环境必须显式登记到 `docs/qa/test-environments.md`，没有测试环境证据不能说上线完成。
14. 项目级闭环必须登记到 `docs/qa/project-acceptance.md`，不能只验 `apps/mobile`、`services/go-app` 或 `apps/admin` 的单点。
15. 红蓝对抗 review 是实现任务的硬门禁，不是可选日志段。
16. 登录、鉴权、支付、账本、权限、审核等系统入口或高风险链路，不允许用本地假状态、mock client、静态 token 或只改前端页面冒充完成。
17. 只要 OpenAPI 标记 `bearerAuth` 或等价安全方案，后端必须至少有无凭证返回 401、有效凭证返回 2xx 的自动化测试；前端必须有凭证注入或 401 清会话测试。
18. 运行时代码不得保留未使用的完整 mock API client。设计预览数据只能放在显式 fixture、测试文件或有清晰 `mock 原因` 的临时入口中。
19. 浏览器验收必须覆盖真实用户路径和失败路径：未登录直达业务路由、登录/注册成功、关键接口状态码、关键接口请求头、console 和真实手机视口截图。
20. Web 不是临时附属模块。涉及官网、下载页、PC 站、H5 或公开 Web 产品时，必须使用 `apps/web` 并记录响应式、SEO异常验证/下载渠道和 API 状态。
21. 移动 App 项目默认必须评估 `apps/web`，因为官网、下载入口、隐私政策、服务条款和上架资料是产品闭环的一部分。
22. 团队默认 Web 技术栈为 Nuxt 4 + Tailwind CSS v4；涉及 `apps/web` 时，必须遵守 `docs/architecture/web-stack-nuxt-tailwind.md`。
23. 公共包必须按 `contracts/generated/ts/ui/go/php` 分层，禁止恢复万能 `packages/shared`。新增公共代码前必须遵守 `docs/architecture/package-boundaries.md`。
24. 大流量演进必须声明 Scale Profile。`growth` 及以上变更必须记录容量、观测、回滚、数据 owner 和跨服务 ECC，不能只靠快速开发目录继续硬撑。
25. 当前项目的差异必须进入项目 Overlay。新增 app、service、第三方、设计验收强度、Scale Profile 或项目例外时，必须同步 `project.config.json` 和 `docs/project/**`，并通过 `npm run check:project-overlay`。
26. 公共框架不接受项目污染。不能因为某个项目用了 ZEGO、Stripe、Laravel Filament 或严格设计图，就把它写成所有项目默认；这些必须作为项目 Overlay 或技术栈适配器存在。
27. 文档采用双视图模型。团队可读文档负责解释背景和流程，AI/工具控制文件负责承载需求 ID、OpenAPI、schema、状态、owner、验收证据和门禁输入；不能把项目的具体文档形态写成公共框架硬规则。
28. 新项目必须优先通过 preset 初始化。正式 preset 为 `mobile-app`、`go-gin-api`、`laravel-app`、`nuxt-web`、`fullstack-monorepo`、`custom`；兼容别名只用于旧项目升级。
29. OpenAPI 变更必须进入契约测试证据。`npm run check:contract` 必须能确认 mock server、后端 conformance、前端 mock 来源和测试状态。
30. GitLab MR 是质量边界。涉及框架升级时，必须运行 `devtools/framework report` 并把升级报告、sync plan 和 advisory review 结论放入 MR。
31. 团队成员任务 Brief 是 Agent Scope 的入口。团队成员发起实现任务时必须声明执行角色、`allowedWritePaths`、`readOnlyPaths`、`forbiddenPaths` 和 `requiresReview`；Agent 默认遵守“读全局，写局部”。
32. Agent 需要跨目录写入时，必须先记录 `requestedWritePaths`、原因和 owner review，不能把跨边界修改混在实现细节里。

当前模板用 `scripts/validate-ai-completion-gates.py` 和 `scripts/validate-project-overlay.py` 落地这些规则，并在 `npm run check` 中执行。后续发现新的偷懒路径，必须继续把规则升级成门禁。

## 8. 框架同步规则

凡是属于框架能力的改动，都需要判断是否进入公共 AI 框架仓库，并通过版本发布后由项目 `.ai-framework` 子仓库升级：

```text
AI_FRAMEWORK_REPO_PATH 或团队约定的公共框架仓库路径
```

需要同步的典型内容：

1. Agent 规则。
2. Git workflow。
3. CI/CD 规则。
4. CODEOWNERS 模板。
5. PRD/OpenAPI 拆分结构。
6. 文档双视图模型。
7. 日志模板。
8. Review 模板。
9. 框架踩坑修正。

不需要同步的内容：

1. {{PROJECT_NAME}} 专属业务规则。
2. {{PROJECT_NAME}} 专属设计图。
3. {{PROJECT_NAME}} 专属 PRD 细节。
4. {{PROJECT_NAME}} 专属 OpenAPI 业务接口。
