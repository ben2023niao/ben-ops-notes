## P1 详情

### A-01 赛事状态枚举异常（前台根因）
- 现象：「赛事 & 比分」共 5 场，其中 M1 / M103 / M101 / M102 状态显示「未知状态」，仅 M100 显示「未开赛」并带「开赛」操作。
- 接口侧：`/api/v1/schedule/days`、`/home/today-matches` 返回这些赛事 `status:"UNKNOWN"`（见 api 报告 P1）。
- 影响链：
  1. 「未知状态」赛事在后台**无任何操作按钮**，运营无法将其流转为未开赛/进行中/已结束。
  2. H5 首页对 UNKNOWN 赛事只能按开赛时间猜测状态（如英格兰vs挪威被显示成「LIVE·进行中」）。
  3. H5 赛程 tab 依赖 `schedule/timeline`（返回空）而非 `days`，叠加状态异常，整页空白（见 web 报告 W-01）。
- 建议：后端修复 match status 计算/落库（UNKNOWN 不应作为对外状态）；后台为各状态提供完整流转操作。

### A-02 提现限额配置与 PRD 矛盾（资金风控）
- 系统配置实测值：
  - `wallet.withdraw.daily_limit_rmb` = **200000**（说明：单用户日累计提现上限）
  - `wallet.withdraw.max_amount_rmb` = **50000**（单次提现最高）
  - `wallet.withdraw.min_amount_rmb` = 10、`platform_fee_rate` = 0.05 ✅
- 冲突：PRD/用例 TC-WD-006 明确**单日上限 5,000 RMB**；H5 提现页硬编码文案也是「单日 5,000 / 单月 50,000」。
- 后果：`withdraw/info` 据配置返回 50000/200000（api 报告 P1），与业务规则、前端文案三方不一致；风控阈值被放大 40 倍，存在资损风险。
- 建议：明确 5,000 为准则后修正配置；前端文案改为读取配置而非硬编码。

## P2 / 观察详情

- **A-03 竞猜状态不流转**：「蓝方测试-西班牙vs加拿大」关停时间 05-26 19:00 已过，后台仍标「进行中」（17 押注、奖池 1712💎）。H5 投注被后端以「活动已截止」拒绝（web W-07）。建议关停时间到点后自动流转状态。后台已有未结算告警 banner（「有 1 个活动已截止押注但还没结算」）属正向能力 ✅。
- **A-04 banner 上限**：`home.banner_count`=5 vs PRD 最多 6（TC-LIVE-004）。广告管理「首页顶部轮播」slot 也限「最多 5 条」。需与产品对齐 5 还是 6。
- **A-05 直播间未关联赛事**：3 房间「关联赛事」列均为「—」。导致 H5 直播间顶部比分条只能显示占位「0-0 主队 vs 客队 高清」。属造数据缺失，建议为在播房间绑定赛事。
- **A-06 直播中 vs 真实推流**：房间经 `admin.room.force_start` 标记「直播中」「推流码已配置」，但 dev 无真实 RTMP 推流，H5 打赏 tip 返回「直播未开始」(20301)。force_start 的房间状态与真实流会话状态是两套，需在前台/后台明确区分或对齐。
- **A-07 充值通道全不可用**：充值订单 11 笔全「已取消」，通道 `shark/wechat`、`shark/alipay`，init 报「大白鲨支付通道未启用」。dev 无法验证充值成功/到账/派彩闭环（用例 TC-RCG-015 等阻断）。
- **A-08 后端注册首字符未校验**：用户列表存在 `1abcdef`（USR590017，首字符为数字）。H5 前端拦截了此类账号，但后端注册接口放行，校验不一致（api 报告已记 P1）。
- **A-09 广告位未被前端消费**：广告管理「剧场式 TopBar 跑马灯」(h5_theater_topbar) 内容为空(0/5)，但 H5 直播间剧场式仍显示「新人首充翻倍·充100送200」跑马灯——前端 `AdMarquee.vue` 为硬编码，未拉取该广告位（详见 web 报告 W-16）。且该文案为 v1 范围外的充值赠送活动（项目 `CLAUDE.md` 标为「错误展示」）。
