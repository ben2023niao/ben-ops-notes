## 背景

开发确认巴西环境需要把副本库 `192.0.2.1:3306` 暴露一个公网访问入口，用于和现有主库公网入口区分。

本次目标映射：

```text
192.0.2.8:3309 -> 192.0.2.1:3306
```

说明：本次最终处理方式不是新增独立 HAProxy 容器，而是在老 HAProxy 容器 `infra-gateway` 的配置里新增一个 `3309` frontend/backend。

## 机器与组件

- 入口公网 IP：`192.0.2.8`
- 入口宿主机：`bizops-saopaulo-game-results-data-bt`
- 宿主机内网 IP：`192.0.2.1`
- HAProxy 容器：`infra-gateway`
- HAProxy 镜像：`haproxy:2.9`
- HAProxy 配置：`/data/haproxy/haproxy.cfg`
- Docker Compose 配置：`/data/haproxy/docker-compose.yml`
- HAProxy 网络模式：`host`

## 已有映射梳理

变更前已存在主库公网映射：

```text
192.0.2.8:3306 -> 192.0.2.1:3306
```

该映射由 `infra-gateway` 容器里的 HAProxy 监听 `192.0.2.3:3306` 后转发，不是宝塔 Nginx 转发，也不是 iptables DNAT。

## 变更内容

在 `/data/haproxy/haproxy.cfg` 中新增以下配置块：

```haproxy
########################################
# MySQL Replica
########################################

frontend mysql_replica_3309
    bind *:3309
    default_backend mysql_replica_backend

backend mysql_replica_backend
    balance roundrobin
    option tcp-check
    server mysql_replica1 192.0.2.1:3306 check inter 3s fall 3 rise 2
```

同时放行入口防火墙：

- 宿主机 UFW：`3309/tcp`
- GCP VPC Firewall：`mysql-replica-3309`
- GCP 网络：`bizops-saopaulo-slotsapi-network-v2`
- 放行端口：`tcp:3309`
- 来源范围：`192.0.2.3/0`


## 回滚方式

如需回滚本次副本库公网映射：

1. 从 `/data/haproxy/haproxy.cfg` 删除 `frontend mysql_replica_3309` 和 `backend mysql_replica_backend` 配置块。
2. 执行 HAProxy 配置校验：

```bash
docker exec infra-gateway haproxy -c -f /usr/local/etc/haproxy/haproxy.cfg
```

3. 重启或 reload HAProxy 容器：

```bash
docker restart infra-gateway
```

4. 移除入口放行规则：

```bash
ufw delete allow 3309/tcp
gcloud compute firewall-rules delete mysql-replica-3309 --quiet
```

5. 验证 `192.0.2.8:3309` 不再连通，且 `192.0.2.8:3306` 主库入口仍正常。

也可以直接用变更前备份恢复配置：

```bash
cp -a /data/haproxy/haproxy.cfg.backup-20260724-142559 /data/haproxy/haproxy.cfg
docker restart infra-gateway
```

## 风险与建议

- 当前 `3309` 的 GCP 防火墙来源范围为 `192.0.2.3/0`，与已有 `3306` 公网入口策略一致。
- 如果后续能固定开发或业务访问出口 IP，建议把 `mysql-replica-3309` 的 source range 收窄，降低 MySQL 公网暴露风险。
- 该入口只负责 TCP 转发，不改变 MySQL 用户、密码、权限和数据库内部访问控制。
