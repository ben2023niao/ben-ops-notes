## 四、P0-4 全量资源预加载灰度结论（回滚）

```text
实验：launcher 跳转前并行 preload 254 个静态资源，等完成或 4s 超时再跳转
结果：马尼拉 loaded 21.0s → 25.0s（变慢）
原因：4s 等待 + 254 preload 抢占连接，与游戏自身加载争抢；只预载 61/254
决定：回滚等待机制（保留 80ms 跳转），发布 master-c59985df 3/3
遗留：conf/preload/126.json 清单保留，供 iframe 壳方案（launcher 不跳转、
      游戏 iframe 边载边预热）后续灰度

## 五、P0-5 iframe 壳灰度结果（2026-08-30）

```text
实施：launcher 不跳转，游戏在 iframe 加载；全量 preload（254 路径）并发执行不被导航取消
发布：master-1c3eef78（3/3），灰度仅 game 126（有清单的游戏）
马尼拉实测：入口 3.8s → 画布 9.9s → 继续 13.1s → loaded 21.1s（跳转版 21.0s，持平）
iframe 模式确认生效（游戏在 iframe 内加载，无新顶层页）
结论：预加载等待版/iframe 版均无净收益；
瓶颈：vendor 引擎串行加载 + fetch 类资源 preload 的 CORS 缓存模式不匹配
      （link preload as=fetch 不带 crossorigin 无法命中 CORS 模式 fetch 的缓存）
后续选项：A. crossorigin 细化（小收益待验证）；B. 保留 iframe 灰度观察 + vendor 并行化；
         C. 回滚 iframe（东南亚维持 21s，巴西不受影响）

## 六、P0-5 回滚完成（2026-08-30，用户选 C）
