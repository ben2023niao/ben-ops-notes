# 【问题排查】线上环境小时数据报告缺失排查与兜底记录

## 背景

2026-08-20 22:00、23:00 小时数据报告未发到群里（20:00、21:00 正常）。
小时数据报告由 Spug 定时任务 `HourlyStatsMonitor monitor` 每小时执行：
Spug 通过 SSH 登录业务服务器，`docker exec youdianse-main-php-web` 调用
`php bin/shell.php HourlyStatsMonitor monitor`，生成“上一小时”报告并发群。

## 排查过程

```text
1. hourly_stats_monitor 集合：8/20 记录到 hour=21 为止，hour=22、23 缺失；
   8/18、8/19 的 22/23 点均正常，确认仅 8/20 缺失。
2. 时间换算：hour=20 记录 created_at=21:08:21、hour=21 记录=22:08:26，
   即 Spug 每小时 :07 执行、约 :08 完成，生成上一小时报告。
3. Spug 任务列表：HourlyStatsMonitor monitor 状态=失败（23:07 那次）；
   同期 BalanceReconcile、totalMinute 等任务成功，调度本身正常。
4. sudo 日志：22:07:00、23:07:00 Spug 均执行了
   docker exec youdianse-main-php-web ... HourlyStatsMonitor monitor。
5. 容器时间：web 容器 created=23:07:05、started=23:07:23；
   Spug 23:07:00 执行时容器尚不存在 -> docker exec 失败 -> 任务失败。
6. 手动补跑（cron 容器）成功：22 点、23 点报告均已重新生成并发群，
   确认业务侧代码与 Mongo 从库链路正常。
```

## 根因

```text
发布 e91c91979d9d（22:57 开始构建，23:07 重建 web/cron 容器）与 Spug
整点任务执行时间（:07）重叠：23:07:00 Spug docker exec 时 web 容器
刚创建/未启动，执行失败，导致 22 点小时数据报告缺失。
属发布窗口与定时任务冲突，非业务代码故障。
```

## 处置

```text
1. 立即补发：手动补跑 hour=22、hour=23 报告（已发群，记录已补齐）；
2. 兜底机制：新增 ops/production/scripts/youdianse-hourly-report-guard.py，
   每小时 :09 检查 hourly_stats_monitor 上一小时记录，缺失自动补跑
   HourlyStatsMonitor monitor；已加入宿主机 crontab
   （9 * * * * flock ... youdianse-hourly-report-guard.py），
   日志 /var/log/youdianse-hourly-report-guard.log；
3. Spug 侧：建议为该任务开启失败重试，或调整执行时间避开发布窗口。
```

```text
1. hourly_stats_monitor：2026-08-20_22（注册 3629/付款 476/金额 19376）、
   2026-08-20_23（注册 2476/付款 252/金额 9022）均已补齐；
2. 兜底脚本线上部署、语法通过、skip 路径实测正常，crontab 生效；
3. bigDataJob 队列、web/cron 容器均正常。
```

## 后续建议

```text
1. Spug 为 HourlyStatsMonitor 配置失败重试（如 5 分钟后重试 2 次）；
2. 发布窗口尽量避开整点 :00-:10，或发布前临时暂停小时任务；
3. 观察兜底巡检日志 2-3 天，确认无重复发送/漏发；
4. 若 Spug 任务长期不稳定，可考虑将小时报告调度迁至宿主机 crontab。
```

### 去重行为说明

```text
HourlyStatsMonitorJob 按 _id（日期_小时）去重：记录已存在时跳过且不重复发送。
因此手动补跑后，Spug 与兜底在下一个整点检查同一小时时会 skip，
不会重复发报告——属预期行为。
```
