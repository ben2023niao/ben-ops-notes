# 域名配置同步到 03 打包机记录

> 公开版脱敏说明：公司、平台、节点、账号、地址和业务对象均已替换为示例标识；替换后的名称仅用于公开复盘。

需求：巴西 01 / 香港 01 上的域名配置同步到巴西 03 打包机，
      否则手动更新后一打包又被还原成旧域名。

## 一、为什么会还原

打包脚本 `/data/pgserver/build.sh` 第 128–131 行：

```bash
if [ -d "platform-api/conf/domains" ]; then
    cp -r "platform-api/conf/domains" "$RUNTIME_DIR/conf/"
fi
```

`RUNTIME_DIR=/data/server-runtime`，也就是说每次打包都会用
`/data/pgserver/platform-api/conf/domains` 覆盖 `server-runtime/conf/domains`。
打包源里还是 10-19 单域名收敛之前的双域名配置，所以一打包就回退。

## 二、同步前差异

巴西 01 / 02 已经是单域名，03 打包源和运行目录还是双域名，差异 7 个文件：

| 文件 | 01（正确） | 03 打包源（旧） |
| --- | --- | --- |
| vendor_d.json | `vendor_d-static.xqv9m8.icu` | `xqv9m8` + `vendor_a-cdn-2026` |
| pg.json | `pg-static.xqv9m8.icu` | 双域名 |
| vendor_c.json | 单域名 | 双域名 |
| popok.json | 单域名 | 双域名 |
| pp.json | 单域名 | 双域名 |
| vendor_a.json | 单域名 | 双域名 |
| g759.json | `g759-static.xqv9m8.icu` | 双域名 |

fc / jdb / vendor_b 三个文件本来就一致，不需要改。

香港：03 的 `/data/server-runtime-hk/conf/domains` 与香港 01
`/data/server-runtime/conf/domains` 的 10 个文件 md5 全部一致，无需同步。

## 三、执行

1. 备份 03 两个目录：

   ```text
   /data/pgserver/platform-api/conf/domains.bak-20261021-092035
   /data/server-runtime/conf/domains.bak-20261021-092035
   ```

2. 从巴西 01 打包 `domains/` 并解到 03：

   ```bash
   # 01
   tar -C /data/server-runtime/conf -czf - domains

   # 03（两份都解）
   tar -xzf - -C /data/pgserver/platform-api/conf
   tar -xzf - -C /data/server-runtime/conf
   ```

3. 校验：

   ```bash
   cd /data/pgserver/platform-api/conf/domains && md5sum *.json | sort
   cd /data/server-runtime/conf/domains && md5sum *.json | sort
   python3 -c 'import glob,json;[json.load(open(f)) for f in glob.glob(".../*.json")]'
   ```

## 四、结果

- 03 的打包源与运行目录 10 个文件 md5 与巴西 01 **完全一致**；
- 全部 JSON 校验通过；
- 以后执行 `build.sh` 不会再覆盖成双域名配置；
- 03 当前没有运行 game-service 容器（只跑 registry / JumpServer / beszel-agent），
  所以本次不需要重启业务。

## 五、回滚

```bash
rm -rf /data/pgserver/platform-api/conf/domains
cp -a /data/pgserver/platform-api/conf/domains.bak-20261021-092035 \
      /data/pgserver/platform-api/conf/domains

rm -rf /data/server-runtime/conf/domains
cp -a /data/server-runtime/conf/domains.bak-20261021-092035 \
      /data/server-runtime/conf/domains
```
