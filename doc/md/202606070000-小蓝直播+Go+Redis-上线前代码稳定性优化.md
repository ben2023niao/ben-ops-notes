## 本次目标

1. 只做低风险代码优化，不改变业务语义。
2. 提升 worker、WS 异步回调和统计 goroutine 的线上容错能力。
3. 减少非 WS 进程不必要的 Redis Pub/Sub 订阅资源。

## 修改文件

| 文件 | 说明 |
| --- | --- |
| `services/go-app/internal/pkg/safego/safego.go` | 新增安全 goroutine 工具，统一恢复 panic 并记录堆栈。 |
| `services/go-app/internal/pkg/safego/safego_test.go` | 覆盖正常执行、panic 恢复和 nil 输入。 |
| `services/go-app/internal/pkg/wsx/hub.go` | 增加 publisher-only Hub，WS 订阅 goroutine 使用 safego。 |
| `services/go-app/internal/http/router/public.go` | REST-only API 进程使用 publisher-only Hub，WS 进程保持订阅模式。 |
| `services/go-app/cmd/worker/main.go` | worker 进程使用 publisher-only Hub。 |
| `services/go-app/internal/worker/*.go` | 长驻 worker goroutine 和单次 tick 增加 panic 保护。 |
| `services/go-app/internal/http/wsapi/handlers.go` | WS 进场与在线统计异步回调增加 panic 保护。 |
| `services/go-app/internal/service/live/service.go` | 弹幕计数异步统计增加 panic 保护。 |
| `services/go-app/internal/http/router/admin.go` | 修正 admin Hub 注释，避免误判后台弹幕监控订阅能力。 |

## 核心决策

1. 不拆大文件、不改业务流程、不改接口契约，避免上线前引入结构性风险。
2. worker 每个 tick 单独 recover，避免单次异常永久停止后台任务。
3. admin 进程保留 Redis 订阅，因为后台弹幕监控需要订阅房间频道。
