## 一、背景

```text
三域名时静态资源“没走上 CDN 缓存”，单域名正常；
现切双域名（vendor_a-cdn-2026 + xqv9m8），需结合 nginx/CDN 配置验证并解决。
```

## 二、链路核查

```text
1) DNS：静态子域 CNAME -> GCS 桶（proxied），g759 类走通配 A(proxied)；
2) CF Worker 路由：两域均挂 *-static / vendor_a-statics(1/2) -> summer-wave-c94f；
3) Cache Rules：statics（cache=true, edge TTL 604800）两域均存在；
4) 响应头转换规则 statics-cache-response：已全部禁用（不影响边缘缓存）；
5) nginx：静态请求不经 nginx（响应带 x-goog-* = GCS 回源标记）。
```

## 三、实测（双域 × 各厂商代表性静态文件 × 3 次）

```text
pg-static/126/index、pg3-7 各游戏 index、vendor_a-statics JS、
pp/ppk/vendor_c/vendor_d health.json：
vendor_a-cdn-2026.icu：全部 [200/MISS] -> [200/HIT] -> [200/HIT]
xqv9m8.icu：     全部 [200/MISS] -> [200/HIT] -> [200/HIT]
结论：双域名下 CDN 静态缓存已生效（每个域名各自独立缓存）。
```

## 四、“3 域名不缓存”主因判断

```text
1) 首次访问/首次边缘本来就是 MISS，只测 1 次易误判；
2) 测试常带随机参数（?cb=timestamp），query 进缓存键 -> 每次都 MISS；
3) 多域名摊薄预热命中率，每个域名/前缀各自冷；
4) 残留风险：线上 Worker 仍为 v16“缓存键归一化”（跨前缀共享 key），
   当前测试未见串扰，但恢复三域后风险放大，建议恢复仓库 V4
   （按域名/bucket 隔离缓存键）。
```

## 五、建议

```text
A. 发布后用 cdn_warm_static.py 对 vendor_a-cdn-2026 + xqv9m8 双域预热；
B. 线上 Worker 恢复仓库 V4（备份 v16 快照可回滚）——待用户确认；
C. 验证缓存：固定 URL 连测 2 次看 HIT，勿带随机参数。
```
