# 配置与密钥管理规范

> 来源文件：`~/Projects/work/game/xiaolan-watches/dev/docs/operations/secrets-management.md`

> 整理日期：2026-06-04 01:09｜日期依据：文件创建/修改时间

本规范定义项目配置和密钥的最低要求。目标是避免真实密钥进入 Git、日志、截图、PRD、Agent 日志或公开文档。

## 1. 配置分层

| 层级 | 用途 | 是否可提交 |
| --- | --- | --- |
| `.env.example` | 变量清单、说明、默认策略 | 可以 |
| `.env.local` | 本地开发真实值 | 不可以 |
| CI/CD Secret | 构建、部署、发布密钥 | 不可以 |
| Server Secret | 生产运行时密钥 | 不可以 |
| docs/project/third-party.md | 第三方服务说明、owner、环境差异 | 可以，但不能写真实 secret |

## 2. 必填字段

`.env.example` 或项目配置文档必须说明：

1. 变量名。
2. 用途。
3. 是否 secret。
4. 默认值策略。
5. 适用环境：local/dev/staging/production。
6. owner。
7. 轮换或失效策略。

推荐格式：

```text
NAME=
用途：
是否 secret：是/否
环境：local/dev/staging/production
owner：
默认值：
```

## 3. 禁止事项

真实 secret 不进 Git。

1. 禁止把真实 secret 写入 Git。
2. 禁止把真实 secret 写入 Agent 日志、PRD、README、截图、录屏。
3. 禁止在前端包中暴露服务端 secret。
4. 禁止 production 使用 dev/staging key。
5. 禁止把第三方测试 key 当作生产可用配置。
6. 禁止在日志中打印 token、验证码、cookie、Authorization header、签名密钥。

## 4. 第三方服务

第三方服务必须登记到：

```text
docs/project/third-party.md
```

至少记录：

1. 服务名称。
2. 使用场景。
3. 环境差异。
4. owner。
5. 回调地址。
6. 是否有 sandbox。
7. 故障降级策略。
8. 密钥轮换责任人。

## 5. 泄漏处置

发现 secret 泄漏时：

1. 立即撤销或轮换密钥。
2. 检查 Git 历史、CI 日志、部署日志、Agent 日志。
3. 记录影响范围。
4. 补充事故日志和复盘。
5. 如果泄漏进入 Git 历史，按团队安全流程清理并通知相关 owner。

## 6. Agent 规则

AI Agent 遇到密钥时：

1. 不能复述完整 secret。
2. 只能记录变量名和配置位置。
3. 如果用户贴出测试 key，默认当作敏感信息处理。
4. 需要写入文档时，用 `<SECRET>`、`<TOKEN>`、`<APP_ID>` 等占位符。
5. 发现 secret 已经进入仓库时，必须记录为 P0 风险。
