# 4. 资金闭环与账本设计

## 4.1 总原则

1. **唯一真相在 MySQL `wallet_ledger`**（复式账本表），任何资金动作必落账
2. **Redis 只缓存读余额**，绝对不能 INCR/DECR 当账本
3. **强一致事务隔离级别 `REPEATABLE READ`**，押注 / 派彩 / 充值 / 提现 / 兑换 / 打赏全部走单事务
4. **资金类接口必须携带 `Idempotency-Key`**，DB UNIQUE + Redis SETNX 双保险
5. **任何资金状态变更必落审计日志**，`audit_log` 表保留至少 1 年
6. **派彩极端缩放保险丝**：Σ命中派彩 > 派彩池时按比例缩放
7. **主播收益独立账本** `streamer_income_ledger`，月结、人工出账
8. **T+1 全量对账**，差异 ≤ 0.05% 才算健康

## 4.2 双货币模型

| 货币 | 用途 | 充值 | 提现 | 兑换 |
| --- | --- | --- | --- | --- |
| RMB | 现金钱包 | 微信 / 支付宝 | 仅支付宝 | 1 RMB → 10 💎（正向） |
| 💎 钻石 | 押注 / 打赏 | RMB 兑换 + 赠送 + 派彩 | 反向兑换 RMB（扣 20%） | 10 💎 → 0.8 RMB（反向） |

业务规则严格按 PRD §6.1（首充冷却 14 天、单日/月限额）。等级特权已下线，不再按用户等级设置押注上限。

## 4.3 复式账本 `wallet_ledger`

### 4.3.1 设计原则

- 每笔资金动作产生 **2 行**（debit + credit），借贷必相等
- 账户主体可以是用户、平台收款、活动奖池、平台抽水池、主播收益池
- 不允许 UPDATE / DELETE，仅 INSERT / SELECT

### 4.3.2 op_type 全清单

| op_type | 方向 | 货币 | 业务触发 |
| --- | --- | --- | --- |
| RECHARGE_IN | + | RMB | 充值到账 |
| RECHARGE_CLEARING | - | RMB | 平台收款清算（debit 对方） |
| RECHARGE_BONUS_OUT | + | 💎 | 充值赠送钻石 |
| EXCHANGE_FWD_OUT | - | RMB | 正向兑换扣 RMB |
| EXCHANGE_FWD_IN | + | 💎 | 正向兑换收 💎 |
| EXCHANGE_REV_OUT | - | 💎 | 反向兑换扣 💎 |
| EXCHANGE_REV_IN | + | RMB | 反向兑换收 RMB |
| EXCHANGE_FEE | + | RMB | 反向兑换 20% 手续费 → 平台手续费池 |
| WITHDRAW_FREEZE | 冻结 | RMB | 提现申请，冻结金额 |
| WITHDRAW_OUT | - | RMB | 提现审核通过，实际扣减 |
| WITHDRAW_FEE | + | RMB | 提现 2% 平台费 → 平台手续费池 |
| WITHDRAW_UNFREEZE | 解冻 | RMB | 提现驳回，解除冻结 |
| BET_OUT | - | 💎 | 押注扣钻 |
| BET_POOL_IN | + | 💎 | 押注流入活动奖池 |
| BET_IN | + | 💎 | 派彩入账（中奖） |
| BET_POOL_OUT | - | 💎 | 派彩从活动池流出 |
| BET_RAKE | + | 💎 | 平台抽水 → 平台抽水池 |
| BET_REFUND | + | 💎 | 退单回退（用户） |
| BET_REFUND_POOL_OUT | - | 💎 | 退单时活动池退还 |
| TIP_OUT | - | 💎 | 打赏扣钻（用户） |
| TIP_STREAMER_IN | + | 💎 | 打赏流入主播收益池 |
| TIP_RAKE | + | 💎 | 打赏平台分成 → 平台分成池 |
| STREAMER_SETTLE_OUT | - | RMB | 主播月结扣减收益池 → 财务出账 |

### 4.3.3 示例事务记账

#### 充值 50 RMB（含赠送 250 钻 = 50 × 5 钻/元）

```
事务 ID: T-1001
  ledger row 1: user_X / RECHARGE_IN / +50.00 RMB
  ledger row 2: platform_recharge_clearing / RECHARGE_CLEARING / -50.00 RMB
  ledger row 3: user_X / RECHARGE_BONUS_OUT / +250 💎
  ledger row 4: platform_gift_pool / RECHARGE_BONUS_OUT / -250 💎
```

四行同事务 INSERT，借贷必平。

#### 押注 1000 钻

```
事务 ID: T-2001
  ledger row 1: user_X / BET_OUT / -1000 💎
  ledger row 2: predict_activity_Y / BET_POOL_IN / +1000 💎
```

#### 派彩 1700 钻（含本金 1000 + 派彩 700）

```
事务 ID: T-3001
  ledger row 1: user_X / BET_IN / +1700 💎
  ledger row 2: predict_activity_Y / BET_POOL_OUT / -1700 💎
  ledger row 3: platform_rake_pool / BET_RAKE / +平台抽水
  ledger row 4: predict_activity_Y / BET_POOL_OUT / -平台抽水
```

#### 打赏 100 钻

```
事务 ID: T-4001
  ledger row 1: user_X / TIP_OUT / -100 💎
  ledger row 2: streamer_Y_income_pool / TIP_STREAMER_IN / +XX 💎（扣分成后）
  ledger row 3: platform_tip_rake / TIP_RAKE / +(100-XX) 💎
```

#### 运营账号加钻 / 送礼

运营账号用于测试、活动演示和运营互动，不代表真实用户消费。

1. 后台给运营账号加钻仍必须走 `wallet_journals`、`wallet_journal_entries`、`balance_adjustments` 和 `admin_audit_logs`，但对账账户使用 `platform:operations`，不使用 `platform:income`，不生成 `recharge_orders`，不增加 `users.cumulative_recharge`。
2. 运营账号在前台送礼仍扣减自身钱包并广播礼物互动，`live_tips.is_operator_tip = 1`；`live_tips.rmb_equiv` 保留礼物本身 RMB 等值，供互动历史和审计查看。
3. 运营账号送礼的 `live_tips.settlement_diamond_amount = 0`、`live_tips.settlement_rmb_equiv = 0`；普通用户送礼则与 `diamond_amount`、`rmb_equiv` 一致。
4. `live_sessions.settlement_tip_rmb` 存主播结算口径，`operator_tip_rmb/operator_tip_diamond` 单独存运营礼物口径；主播对账使用结算口径，不用礼物总额口径。
5. `is_operator_tip = 1` 的送礼会进入 C 端/主播端实时礼物榜、众筹解锁进度等互动展示口径，但不进入真实 GMV、主播收益、主播结算、消费档位和奖励派发。
6. 如果取消运营账号，只影响后续新发生的送礼；历史 `live_tips.is_operator_tip` 是发生时快照，不回算。

## 4.4 各类资金事务

### 4.4.1 充值订单状态机

```
[PENDING_PAYMENT] ──支付成功回调──► [PAID] ──记账完成──► [COMPLETED]
       │                              │
       ├──超时(30 min)──► [TIMEOUT]   ├──记账失败(系统异常)──► [PAID_BUT_FAIL_LEDGER]
       │                                                              │
       │                                                              ▼
       └──用户取消──► [CANCELLED]                          告警 + 人工补单
```

**关键规范**：

| 项 | 实现 |
| --- | --- |
| 回调验签 | 微信：`WECHATPAY-SIGNATURE` HMAC-SHA256；支付宝：RSA2 |
| 验签失败 | 立即拒绝（不入账）+ 告警 |
| 回调幂等 | `(channel, third_party_no)` 联合 UNIQUE |
| 回调原始 payload | 全量落 `payment_callbacks` 表 |
| 重复回调 | 直接 ACK 不重入（前置 SELECT 已处理则跳过） |
| 超时 | 二维码 30 min 过期，订单标记 TIMEOUT |
| 3 min 未到账 | 显示"长时间未到账，请联系客服" |
| 已到账但记账失败 | 标记 PAID_BUT_FAIL_LEDGER + 告警，人工跑补单脚本 |

### 4.4.2 押注事务

完整代码示例见 [system-architecture.md §1.8](system-architecture.md#18-数据流写路径示例押注)。关键节点：

```sql
BEGIN TRANSACTION ISOLATION LEVEL REPEATABLE READ;

SELECT * FROM predict_activities WHERE id = :activity_id FOR UPDATE;
-- 校验 status = '进行中' AND now < close_at；否则 ROLLBACK

SELECT * FROM user_wallets WHERE user_id = :user_id FOR UPDATE;
-- 校验 diamond_balance >= :amount；否则 ROLLBACK

-- 校验活动 / 全局风控单次上限 + 当日累计上限（查 predict_bets 当日汇总）
-- 等级押注上限已下线；触发全局或活动限额则 ROLLBACK

UPDATE user_wallets
  SET diamond_balance = diamond_balance - :amount,
      version = version + 1
  WHERE user_id = :user_id AND version = :prev_version;
-- 影响行 0 → 并发冲突，ROLLBACK 重试一次

INSERT INTO predict_bets (
  id, user_id, activity_id, option_key,
  amount_diamond, rate_at_bet, status,
  idempotency_key, created_at
) VALUES (...);

UPDATE predict_activities
  SET pool_total = pool_total + :amount,
      participant_count = participant_count + (:is_new_participant ? 1 : 0)
  WHERE id = :activity_id;

UPDATE user_consume_total
  SET rmb_equiv_total = rmb_equiv_total + :amount / 10,
      updated_at = NOW()
  WHERE user_id = :user_id;

INSERT INTO wallet_ledger (op_type='BET_OUT', user_id, amount=-:amount, ...);
INSERT INTO wallet_ledger (op_type='BET_POOL_IN', account='predict_activity_:id', amount=+:amount, ...);

INSERT INTO audit_log (action='predict.bet', actor=:user_id, details=JSON, ...);

COMMIT;
```

事务后：
- Redis 写最新余额（best-effort，**DB 是真相**）
- `XADD stream:bet.placed` 异步通知排行榜/风控 worker

### 4.4.3 派彩流程（worker-settle）

```
比赛结束 → 运营在后台输入实际结果 →
  worker-settle 消费 stream:match.ended:

    1. 锁定该 match 所有 predict_activities → status='派彩中'

    2. 对每个活动:
       a. 计算派彩池 = pool_total × (1 - rake_rate)  -- 默认 80%
       b. 找出命中选项的所有 predict_bets
       c. 计算每人派彩 = bet.amount × bet.rate_at_bet（用快照赔率）
       d. 极端缩放保险丝:
          if Σ(命中派彩) > 派彩池:
             scale = 派彩池 / Σ(命中派彩)
             每人 payout *= scale
       e. 批量事务（每批 ≤ 100 用户）:
          - UPDATE user_wallets SET diamond_balance += payout
          - UPDATE predict_bets SET status='已开奖', payout_diamond=...
          - INSERT wallet_ledger × 2/4（命中用户 + 平台抽水）
          - UPDATE predict_activities SET pool_total -= 派彩总额
       f. 活动 status = '已开奖'
       g. INSERT audit_log

    3. 一致性验证:
       SELECT SUM(amount) FROM wallet_ledger
         WHERE ref_table='predict_activities' AND ref_id=:id;
       必须 = 0（容差 < 0.001 💎）；否则报警 + 人工介入

    4. XADD stream:bet.settled → 通知用户站内信 + 推 WS
```

### 4.4.4 提现流程

```
1. 用户提交 → go-api 校验 KYC 状态 + 限额 → 风控引擎打分
2. 评分 < 30 (低)：自动放行
   评分 30-69 (中)：进入"待审核"队列，运营 24h 内人工
   评分 ≥ 70 (高)：自动驳回 + 通知用户
   即使评分低，单笔 > ¥5,000 也强制人工审核

3. 申请创建时:
   - 钱包冻结对应金额（不扣减）
   - INSERT withdraw_orders (status='待审核' or 'AUTO_APPROVED')
   - INSERT wallet_ledger (WITHDRAW_FREEZE)

4. 审核通过:
   - 解冻 + 实际扣减
   - 调通道（支付宝商家批量付款）
   - INSERT wallet_ledger (WITHDRAW_OUT)
   - INSERT wallet_ledger (WITHDRAW_FEE - 平台收 2%)
   - 通道成功 → status='已到账'
   - 通道失败 → 自动重试 3 次（间隔 30s/2min/10min）
   - 仍失败 → status='转账异常' + 告警

5. 审核驳回:
   - 解冻 + 通知用户原因
   - INSERT wallet_ledger (WITHDRAW_UNFREEZE)
   - status='已驳回'
```

### 4.4.5 兑换流程

| 方向 | 流程 |
| --- | --- |
| 正向 RMB → 💎 | 单事务：扣 RMB → 加 💎 → 双向 ledger × 2 行（无手续费）|
| 反向 💎 → RMB | 单事务：扣 💎 → 加 (10:8) RMB → 收 20% 手续费 → ledger × 4 行；反向当日次数 ≤ 5 校验 |

兑换**不计入累计消费**（只有押注消费才计入）。

### 4.4.6 主播收益月结

```
每月 1 日 02:00 跑批 worker-cron:

  1. 拉取上月所有 streamer_income_ledger 行（settled=false）
  2. 按主播聚合
  3. 扣平台分成（PRD 待确认比例，默认 50%）
  4. 生成结算单 streamer_settlement
  5. 财务侧手工出账（支付宝 / 银行转账）
  6. 财务确认后：UPDATE streamer_income_ledger SET settled=true, settled_at=NOW()
  7. INSERT wallet_ledger (STREAMER_SETTLE_OUT)
  8. INSERT audit_log

主播端 v1 不展示 GMV / 打赏明细（防内幕；PRD 已确认）
```

## 4.5 幂等设计

### 4.5.1 三层防护

| 层 | 实现 |
| --- | --- |
| 1. 客户端 | `Idempotency-Key` HTTP Header（UUID v4） |
| 2. Redis 双保险 | `SETNX idem:{user_id}:{key} 1 EX 86400` 失败则查首次结果 |
| 3. DB 终极防护 | `predict_bets` / `recharge_orders` / `withdraw_orders` 表 `(user_id, idempotency_key)` 联合 UNIQUE |

### 4.5.2 重复请求处理

- 首次：执行业务，存结果到 Redis
- 重复：Redis 命中 → 直接返回首次结果（不重入业务）
- Redis 过期但 DB 唯一冲突：捕获错误后 SELECT 已有订单返回

## 4.6 对账（T+1）

### 4.6.1 跑批流程

```
每日 02:00 worker-cron:

  1. 拉取昨日通道对账文件:
     - 微信: 商户后台 .csv API
     - 支付宝: 商家后台 .csv API
  2. JOIN 系统订单:
     - recharge_orders + payment_callbacks
     - withdraw_orders + transfer_records
  3. 三类差异检查:
     a. 系统单边（通道无对应流水）→ "系统多"
     b. 通道单边（系统无订单）→ 触发补单流程
     c. 金额不一致 → 标记"金额差异"
  4. 写 recon_diff 表
  5. 运营在 Admin Portal 处置:
     - 补单（系统重建订单）
     - 挂账（暂搁，等通道补流水）
     - 核对（人工联系通道）
  6. 全平账 → 写 admin_audit_log
  7. 推 Telegram + 邮件告警（差异 > ¥1000 或 > 5 笔 紧急级，双通道兜底）
```

### 4.6.2 健康标准

| 指标 | 阈值 |
| --- | --- |
| 单日差异率 | ≤ 0.05% |
| 单日差异金额 | ≤ ¥1,000 |
| 单日差异笔数 | ≤ 5 笔 |
| 单笔差异金额 | ≤ ¥100 |
| 待处理超过 7 天 | 0 笔 |

## 4.7 资金一致性最终清单

部署前必须逐项验证：

- [ ] `wallet_ledger` 复式记账，debit + credit 必同事务
- [ ] `user_wallets` 带 `version` 乐观锁
- [ ] DB 层 CHECK 约束：`rmb_balance >= 0` 且 `diamond_balance >= 0`
- [ ] `idempotency_key` 在订单表 UNIQUE + Redis SETNX 双保险
- [ ] 充值回调签名验证（微信 HMAC、支付宝 RSA2）
- [ ] `payment_callbacks` 表保留所有原始 payload
- [ ] 押注 / 派彩事务隔离级别 `REPEATABLE READ`
- [ ] 派彩走 worker-settle 批量处理，单批次事务 ≤ 100 用户
- [ ] **派彩极端缩放保险丝**：Σ命中派彩 > 派彩池时按比例缩放
- [ ] 主播收益独立账本 `streamer_income_ledger`，月结
- [ ] T+1 对账跑批 + 三类差异处置
- [ ] DB 用户**仅授予 INSERT/SELECT**；UPDATE/DELETE 仅在 schema migration role
- [ ] `audit_log` retention ≥ 365 天
- [ ] 所有资金动作写 `audit.write` Kafka topic（或 Redis Stream，按 §5）
- [ ] 资金类接口 P99 < 500ms（押注 / 充值发起）
- [ ] 资金类接口失败率 < 0.05%
- [ ] 跨服务事务 = 0（v1 单库单事务，不引入分布式事务）

## 4.8 Redis 不可作账本的硬证据

| 场景 | Redis 行为 | 后果 |
| --- | --- | --- |
| 主从切换瞬间 | 异步复制延迟 → 主节点写入后从节点未同步 | INCR 计数丢失 |
| AOF everysec | 1 秒数据丢失风险 | 押注/打赏丢失 |
| `INCR` + `EXPIRE` 非原子 | TTL 设置失败 → key 不过期 | 内存膨胀 |
| 多 key 操作 | 无事务跨多 key 强保证（除 Lua） | 不一致 |
| 网络分区 | 脑裂 | 双写 |

Redis 在资金链路的**合法用途**：
- 缓存只读余额（用于显示，DB 为准）
- 幂等键 SETNX
- 限流计数器
- 热点活动奖池缓存（**展示用**，不参与扣减）
