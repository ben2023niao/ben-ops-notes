## 一、分析目的与方法

```text
目的：把「刷量攻击来源」和「真实用户」区分开，避免误封真实用户，同时不放过脚本。

数据源：
  · 网关日志（203.0.113.1，2026-09-26 已补 X-Forwarded-For，可看到真实客户端 IP、UA、路径）；
  · 后端业务日志（runtime/app-logs/api_request-2026-09-2x.log，含 ip / deviceId / userId / action / version）。

三条判据：
  1) 是否带设备号 deviceId：正常 App/H5 每个请求都带；脚本通常为空；
  2) 访问接口数量：真人会跨首页/详情/列表/充值等；脚本常固定打 1 个接口；
  3) 频率形态：真人随浏览波动；脚本 24 小时恒定。

辅助手段：对来源 IP 做反查（PTR）。
  · 含 hstgr.cloud / compute.amazonaws.com → 机房、云服务器；
  · 含 adsl / broad / dynamic / 省份+运营商 → 家宽或移动网络（真实用户）。
```


## 三、区分真实用户 vs 刷量脚本（判定口径）

| 特征 | 真实用户 | 刷量脚本 |

| --- | --- | --- |

| IP 归属 | 家宽/移动网络（PTR 含 adsl / broad / dynamic） | 机房/云厂商（hstgr.cloud、compute.amazonaws.com） |

| deviceId | 有 | 空 |

| userId | 登录后有 | 空 |

| 访问接口 | 多个（首页/详情/列表/充值…） | 常固定 1 个 |

| 访问频率 | 随浏览波动 | 24 小时恒定（如 4.4 次/秒） |

| UA | 手机浏览器/App（HeyTap / Chrome / Safari…） | 非浏览器或固定值（Dart / python-requests…） |

封禁口径（防误伤）：

```text
1. 只封「机房段 + 单接口 + 无 deviceId + 恒定高频」四项同时命中的来源；
2. 家宽/移动段（含 adsl/broad/dynamic）一律不按段封，仅做频率限制；
3. CDN 边缘段永不封。
```
