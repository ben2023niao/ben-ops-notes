## 方法

双方同一套标准：点击/打开游戏后记录
- canvas_ms：页面出现 canvas/iframe（游戏出画）耗时
- idle_ms：网络连续 3 秒无新请求（游戏加载稳定）耗时

我方：H5 入口（ind-h5.dbqpplus999.com/pgbronline/）输入游戏 ID 过滤 → 点击游戏卡。
竞品：账号 11955336688 登录 → 直接打开 /game/action/<游戏ID>（与点击卡片同一流程，
内部走 game.login API）。

汇总：
- 出画：我方约 6.3-7.2s，竞品约 1.0s（竞品快约 6.5 倍）
- 网络稳定：我方约 9.4-10.2s，竞品约 4.0s（竞品快约 2.4 倍）
- 竞品 5 款游戏数据非常稳定（canvas≈1.0s、idle≈4.0s），我方也稳定但整体慢一档

## 我方慢的原因（推测，待进一步定位）

1. launcher 流程：点击后先经过 platform-api 生成 ticket → launcher 页并发测速
   （ping 静态/游戏域名，超时 3s）→ 再跳游戏页，额外增加 1-3s；
2. 游戏动态页 pg-games.<root> 走 Cloudflare → 宝塔 → 后端，马尼拉 TTFB≈1.2s；
3. 我方游戏静态资源加载量大（239 个请求，旧分析），竞品客户端更轻。

注：我方静态桶双地址（圣保罗/东京）已生效，本次全部走东京桶（or=pg4-static），
静态部分不是瓶颈；差异主要在启动链路（launcher 测速 + 动态页往返 + 资源量）。
