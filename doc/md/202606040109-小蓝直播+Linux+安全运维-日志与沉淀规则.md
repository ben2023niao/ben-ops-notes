# 日志与沉淀规则

> 来源文件：`~/Projects/work/game/xiaolan-watches/dev/docs/agents/rules/logging-rules.md`

> 整理日期：2026-06-04 01:09｜日期依据：文件创建/修改时间

## Agent 日志

每个复杂任务必须在 `docs/agents/logs/` 记录工作日志。

日志边界遵守 `docs/architecture/agent-log-governance.md`：

1. 项目日志是项目事实源，只记录当前项目自己的任务。
2. 框架日志是 乌托邦 框架事实源，只留在 乌托邦 仓库。
3. 新项目初始化后不得继承 乌托邦 历史日志。
4. 跨项目汇总只能通过只读采集进入 乌托邦 Log Hub，不能把其他项目日志复制进当前项目。

文件名：

```text
YYYY-MM-DD-short-task.md
```

必须包含：

1. 输入资料。
2. 需求 ID 和 PRD 来源。
3. 本次目标。
4. 修改文件。
5. 核心决策。
6. 验证记录。
7. 风险与待办。
8. 交接说明。

## 框架摩擦记录

遇到以下情况时，必须写入日志的“风险与待办”，或者单独创建框架优化任务：

1. 分支命名或保护规则导致拒推。
2. token scope、SSH key、权限导致操作失败。
3. CODEOWNERS 或 Review 规则不生效。
4. CI 路径触发不合理。
5. OpenAPI 拆分和引用维护困难。
6. Agent 写入范围不清导致冲突。
7. 文档模板缺少字段。
8. 规则只存在聊天里，没有落到仓库。

## 例外记录

早期阶段允许个别例外，但必须写明：

1. 为什么例外。
2. 风险是什么。
3. 什么时候补齐。

例外不能沉默地变成默认流程。

## 决策记录

以下情况必须写 ADR：

1. 技术栈选择。
2. 数据库选择。
3. 第三方供应商选择。
4. Monorepo 结构调整。
5. 核心计费、权限、审核模型调整。
6. 后台权限模型调整。
