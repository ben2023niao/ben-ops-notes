# 2026-09-24 香港 CN 静态域名 CDN 与巴西口径差异清单

> 公开版脱敏说明：公司、平台、节点、账号、地址和业务对象均已替换为示例标识；替换后的名称仅用于公开复盘。

> GitHub 仓库源文件：[点击打开网页渲染版](https://github.com/ben2023niao/ben-ops-notes/blob/main/doc/md/202609241230-%E9%A6%99%E6%B8%AF%20CN%2BShell%2BPython-2026-09-24%20%E9%A6%99%E6%B8%AF%20CN%20%E9%9D%99%E6%80%81%E5%9F%9F%E5%90%8D%20CDN%20%E4%B8%8E%E5%B7%B4%E8%A5%BF%E5%8F%A3%E5%BE%84%E5%B7%AE%E5%BC%82%E6%B8%85%E5%8D%95.md)

> 整理日期：2026-09-24 12:30｜日期依据：文件名日期

本文回答两个问题：

1. 「把巴西的静态域名 CDN 配置导出，把香港的导出，比较不同」；
2. 「香港的域名都需要调整修改哪些地方」。

> 可直接照着做的操作步骤见 **`docker/doc/2026-09-24-1245-【运维记录】香港静态域名上CDN操作手册（运维+后端手动）.md`**（本文负责「差异是什么」，手册负责「怎么点、怎么敲」）。

**本轮为只读导出与比对：没有改 DNS、没有建 Worker 路由、没有部署 Worker、没有改 Cache Rules，也没有改任何 CloudFront/S3/nginx 配置。** 所有改造项都只列清单，等确认后再执行。

## 一、导出方式与产物

新增工具 `docker/deploy/hongkong/static_cdn_config.py`（三种能力，输出同构 JSON，可直接对比）：

| 子命令 | 用途 | 是否需要 token |
| --- | --- | --- |
| `export` | Cloudflare API 导出权威配置：静态 DNS（含 proxied）、Worker 路由、Cache Rules、Tiered Cache、Cache Reserve、zone 缓存设置 | 需要（巴西/香港各自 token） |
| `probe` | 公网探测线上可观测行为：DNS 是否走 CF 代理、响应头、目录请求、OPTIONS 预检 | 不需要 |
| `compare` | 两份导出归一化后逐项比对，输出差异表 | 不需要 |

本次实际导出的产物（已落仓库）：

```text
docker/deploy/hongkong/exports/br-static-cdn-probe-20260924.json   巴西基准（3 个代表 zone）
docker/deploy/hongkong/exports/hk-static-cdn-probe-20260924.json   香港目标（2 个代表 zone）
docker/deploy/hongkong/exports/static-cdn-diff-20260924.md         compare 生成结果
```

命令：

```bash
python3 docker/deploy/hongkong/static_cdn_config.py probe --side br \
    --zones xqv9m8.icu,vendor_a-cdn-2026.icu,8m7xv.cyou \
    --prefixes pg-static,pp-static,vendor_a-statics \
    --out docker/deploy/hongkong/exports/br-static-cdn-probe-20260924.json
python3 docker/deploy/hongkong/static_cdn_config.py probe --side hk \
    --zones hkcloudplay01.com,hkcloudplay02.com \
    --prefixes pg-static,pp-static,vendor_b-static1 \
    --out docker/deploy/hongkong/exports/hk-static-cdn-probe-20260924.json
python3 docker/deploy/hongkong/static_cdn_config.py compare \
    --base docker/deploy/hongkong/exports/br-static-cdn-probe-20260924.json \
    --target docker/deploy/hongkong/exports/hk-static-cdn-probe-20260924.json
```

### 还需要在服务器上补做的一步（本次未做）

`probe` 只能导出「公网可观测」的部分。**zone 内部的 Cache Rules 表达式、Tiered Cache 开关、Cache Reserve、Browser Cache TTL、Cache Level、Worker 路由条目** 必须用 API 导出，需要在持有 token 的机器上执行：

```bash
# 巴西（宝塔，master token）
python3 static_cdn_config.py export --side br --zones 6xv8q.cyou,7m9v8.icu,...,xqv9m8.icu \
    --token-env CLOUDFLARE_WORKERS_TOKEN --out exports/br-static-cdn-api.json
# 香港（入口机 /root/.config/cloudflare/api-token，需补 Workers Scripts/Routes 权限）
python3 static_cdn_config.py export --side hk --zones hkcloudplay01.com,...,hkcloudplay05.com \
    --token-file /root/.config/cloudflare/api-token --out exports/hk-static-cdn-api.json
```

## 二、巴西侧静态 CDN 配置（基准）

```text
玩家浏览器
  -> <prefix>.<zone>（20 个 zone，橙云代理）
  -> Cloudflare Cache Rules「statics」+ Cloudflare Worker summer-wave-c94f
  -> fetch 到 gs://newgg2-bizops-gcs-<前缀>（公开读）
```

| 项 | 值 | 证据 |
| --- | --- | --- |
| zone 池 | 20 个（`xqv9m8.icu`、`vendor_a-cdn-2026.icu`、`8m7xv.cyou`、`q7m9v8.icu`、`cdn-tokyo-bizops.icu` …） | `master/docker/scripts/git_static_gcs_sync.py` WARM_ZONES |
| 静态前缀 | 14 个（pg/pg3-pg7-static、vendor_a-statics/1/2、pp/ppk/vendor_c/vendor_d/g759-static） | 同上 + `cdn_warm_static.py` |
| DNS 代理 | **橙云（已代理）**：20 个 zone 里 19 个解析到 Cloudflare 边缘 IP（`172.67/104.21/104.26` 段），1 个本次探测超时 | 本次 `dig` + probe 导出 |
| 边缘 | Cloudflare（`server: cloudflare`、`cf-ray`、`cf-cache-status`） | probe 导出 |
| Cache Rules | zone 级规则名 **statics**，匹配「主机名结尾为 `-static.<zone>` 或 主机名开头为 `vendor_a-statics.<zone>`」，动作「符合缓存条件 + 边缘 TTL」，状态活动（以 `8m7xv.cyou` 为例，用户提供 UI 实况） | 用户提供 + 待 API 导出补全其它 zone |
| Worker | 脚本 `summer-wave-c94f`（ES Module），回源 GCS；`cf.cacheEverything + cacheTtl=604800`；目录 302 → index.html；OPTIONS 边缘 204；`CACHE_SALT` 失效 | `master/docker/scripts/worker-js-cdn-代码备份/【线上在用】worker.js` |
| 响应缓存头 | `cache-control: public, max-age=604800`（200 响应） | 实测 `pg-static.xqv9m8.icu` |
| CORS | 一律 `access-control-allow-origin: *`；allow-methods `GET, HEAD, OPTIONS`；预检 max-age `86400` | 实测 |
| 目录请求 | `/shared/3c4695a542/` → **302** → `/shared/3c4695a542/index.html` | 实测 |
| OPTIONS | 带预检头 → 204；不带预检头 → 204（Worker 一律边缘回答） | 实测 |
| 地区限制 | Worker 白名单 `BR/SG/HK/AE` | Worker 源码 |
| 发布后失效 | 改 `CACHE_SALT` 重部署（Cache API 按 zone 隔离，zone purge 清不掉）+ 可选 zone purge | Worker README + 0914 文档 |
| 发布后预热 | 逐 20 zone 增量预热（宝塔 cron 每 30 分钟 `--warm`） | `2026-09-02-2018` 文档 |
| 缓存状态 | 预热后 `cf-cache-status: HIT` | 实测（第二次请求） |

## 三、香港侧静态 CDN 配置（现状）

```text
玩家浏览器
  -> <prefix>.hkcloudplay0[1-5].com（5 个 zone，灰云 DNS-only）
  -> CloudFront（每前缀一个分配，OAC）
  -> 香港私有 S3 bizops-h5-hk-517506432530/<前缀>（前缀公开读）
  另：platform-api 下发的 static_hosts 目前直指 S3 公开地址（2026-08-28 起）
```

| 项 | 值 |
| --- | --- |
| zone | 5 个：`hkcloudplay01.com` ～ `hkcloudplay05.com` |
| 静态前缀 | 14 个：`pg-static`、`pg3`~`pg7-static`、`vendor_b-static`/`1`/`2`（内部读 `vendor_a-statics`/`1`/`2`）、`pp-static`、`ppk-static`、`vendor_d-static`、`vendor_c-static`、`g759-static` |
| DNS 代理 | **灰云（仅 DNS）**：CNAME 直指 CloudFront 分配域名，0 条走 CF 代理 |
| 边缘 | CloudFront（`server: AmazonS3`、`via: …cloudfront.net`、`x-cache: Miss from cloudfront`） |
| Worker | **无**（0 条路由、无脚本） |
| Cache Rules | **无** |
| 缓存 | 17 个静态分配为 `Managed-CachingDisabled`（逐请求回源，2026-09-02 为保证 CORS 精确回显），响应无 `Cache-Control` |
| CORS | 平台域（hkcloudplay0[1-5]/hkplaycore/bizopsplus999）精确回显 + 其它 `*`；allow-methods `GET, HEAD`；预检 max-age `3600` |
| 目录请求 | **403**（S3 无目录别名对象，也没有 302） |
| OPTIONS | 带完整预检头 → 200；缺 `Access-Control-Request-Method` → 400 |
| 失效 | CloudFront `/*` invalidation |
| 预热 | 无（已列为待办 `TASK-20260902-HK-POST-RELEASE-PREWARM`） |

## 四、差异清单（probe 实测 11 项）

| # | 配置项 | 巴西（基准） | 香港（现状） | 影响 |
| ---: | --- | --- | --- | --- |
| 1 | 走 CF 代理的记录 | 3/3（橙云） | 0/3（灰云） | 香港根本不经过 Cloudflare，Worker/规则无法生效 |
| 2 | DNS 解析到的边缘 | `cloudflare` | `cloudfront` | 边缘平台不同 |
| 3 | 响应 `server` | `cloudflare` | `AmazonS3` | 香港是 CF→S3 直出 |
| 4 | 边缘缓存状态 | `cf-cache-status: HIT` | `x-cache: Miss from cloudfront` | 香港无边缘缓存，每次回源 |
| 5 | 响应 `Cache-Control` | `public, max-age=604800` | 空 | 浏览器端也不缓存 |
| 6 | ACAO（平台 Origin） | `*` | 精确回显 Origin | 口径不同（香港为修串源故障而收紧） |
| 7 | allow-methods | `GET, HEAD, OPTIONS` | `GET, HEAD` | 预检差异 |
| 8 | 预检 max-age | `86400` | `3600` | 预检缓存时长不同 |
| 9 | 目录请求 | `302` → `index.html` | `403` | 香港目录入口不可用 |
| 10 | OPTIONS（带 ACRM） | `204` | `200` | 香港需回源 S3 处理预检 |
| 11 | OPTIONS（无 ACRM） | `204` | `400` | 裸 OPTIONS 香港报错 |

未纳入 probe、需 API 导出才能比的项：Cache Rules 表达式与动作、Tiered Cache、Cache Reserve、Browser Cache TTL、Cache Level、Worker 路由条目、zone 计划等级。

### 5.3 香港 Cache Rules 表达式（对照巴西写法）

巴西（以 `8m7xv.cyou` 为例，UI 实况）：

```text
(ends_with(http.host, "-static.8m7xv.cyou"))
or (starts_with(http.host, "vendor_a-statics.8m7xv.cyou"))
```

香港**不能照抄**：香港对外是 `vendor_b-static` / `vendor_b-static1` / `vendor_b-static2`，`starts_with("vendor_a-statics…")` 在香港不成立，且 `vendor_b-static1/2` 也不满足 `-static.` 结尾。建议（每个 zone 一条）：

```text
(ends_with(http.host, "-static.hkcloudplay0N.com"))
or (ends_with(http.host, "-static1.hkcloudplay0N.com"))
or (ends_with(http.host, "-static2.hkcloudplay0N.com"))
```

等价正则写法：

```text
matches(http.host, "^[a-z0-9-]+-static[0-9]?\.hkcloudplay0[1-5]\.com$")
```

## 六、不能照抄巴西的部分

```text
1. 源站桶：巴西是 GCS newgg2-bizops-gcs-*；香港是私有 S3 bizops-h5-hk-517506432530。
2. 静态前缀命名：巴西对外用 vendor_a-statics*；香港对外用 vendor_b-static*（内部才映射 vendor_a-statics*）。

4. 地区白名单：巴西 BR/SG/HK/AE；香港面向国内，需单独决定。
5. platform-api 配置：香港 domains JSON 的 static_hosts 当前是 S3 公开地址，需与后端约定切换时机。
```
