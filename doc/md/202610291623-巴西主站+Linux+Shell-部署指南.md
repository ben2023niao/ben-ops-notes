# 部署指南

> 来源文件：`~/Projects/work/game/pgserver/master/deliverables/dbqp-ops-console/docs/部署指南.md`

> 整理日期：2026-10-29 16:23｜日期依据：文件创建/修改时间

## 1. 当前部署拓扑

```text
浏览器
  -> 宝塔 Nginx 公网 35.247.205.6:8787
  -> 203.0.113.1:8788
  -> dbqp-ops-console 容器
  -> 私网 SSH
  -> 03 / 巴西后端 / 香港后端
```

容器部署在宝塔，后端服务器保持不直接暴露公网。容器不挂载宿主机
Docker Socket。

## 2. 前置条件

- 独立内部访问域名；
- HTTPS 证书或 Cloudflare Access；
- 容器镜像仓库；
- SSH 部署凭据；
- 对 03、巴西和香港目标主机的 TCP/22 访问；
- 可写目录 `/opt/dbqp-ops-console/data`；
- 只读 Secret 目录 `/opt/dbqp-ops-console/secrets`；
- 每台后端已部署 `/opt/dbqp-scripts/fix_result_perms.sh`，并启用
  `dbqp-result-perms.timer`。

## 3. 目录

```text
/opt/dbqp-ops-console/
├── .env
├── compose.yml
├── data/
├── secrets/
├── config/
└── backups/
```

权限建议：

```bash
chmod 700 /opt/dbqp-ops-console/secrets
chmod 600 /opt/dbqp-ops-console/secrets/*
```

## 4. 环境变量

从模板复制：

```bash
cp config/ops-console.env.example /opt/dbqp-ops-console/.env
```

容器只监听：

```text
203.0.113.1:8788
```

Secret 文件：

```text
/opt/dbqp-ops-console/secrets/ops_console_password
/opt/dbqp-ops-console/secrets/pgs_deploy_pass
/opt/dbqp-ops-console/secrets/git_pull_url
/opt/dbqp-ops-console/secrets/telegram_bot_token
/opt/dbqp-ops-console/secrets/telegram_chat_ids
/opt/dbqp-ops-console/secrets/tencentcloud_secret_id
/opt/dbqp-ops-console/secrets/tencentcloud_secret_key
/opt/dbqp-ops-console/secrets/cloudflare_api_token
```

腾讯云密钥使用仅授予 EdgeOne/TEO 权限的子用户；Cloudflare Token 至少需要
`Zone:Read` 和 `Zone.Cache Purge`。这三个文件只读挂载到容器，不得写入
Compose、镜像、页面 HTML、任务命令或审计正文。

全部设置为 0400，由容器 UID 10001 读取。真实 Secret 不进入 `.env`、
页面、Git 或审计数据库。

## 5. 启动

```bash
cd /opt/dbqp-ops-console
docker compose -f deploy/docker-compose.yml up -d --build
```

容器默认只监听本机回环地址，由宝塔 Nginx 对外提供访问。

结果集权限任务必须由宿主机 root 部署，容器不直接修改 systemd：

```bash
sudo install -o root -g root -m 0755 \
  scripts/fix_result_perms.sh /opt/dbqp-scripts/fix_result_perms.sh
sudo install -o root -g root -m 0644 \
  scripts/systemd/dbqp-result-perms.service \
  scripts/systemd/dbqp-result-perms.timer \
  /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now dbqp-result-perms.timer
```

香港节点需把 service 中的 `PROJECT_NAME` 设置为 `香港项目`。发布命令会在
同步结束、启动容器前执行一次静默修复，并验证 timer 为 enabled + active；
只要仍存在非 `1000:1000` 或 owner 不可读写的条目，发布立即中止。

## 6. 健康检查

```bash
curl -fsS http://203.0.113.1:8788/api/health
docker ps --filter name=^/dbqp-ops-console$
docker logs --tail 100 dbqp-ops-console
```

健康状态应同时发送到 Beszel 或现有监控。

## 7. Nginx 反向代理

需要代理 WebSocket：

```nginx
location / {
    proxy_pass http://203.0.113.1:8788;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_read_timeout 3600s;
}
```

同时配置 HTTPS、认证、来源 IP 白名单和访问日志。

## 8. 访问控制

当前采用单密码登录：

- `/login` 只要求输入一个高强度访问密码；
- 服务端写入 HttpOnly + SameSite=Lax Cookie，支持本机快捷入口表单登录；
- 默认会话 12 小时；
- 同一 IP 5 分钟内失败 5 次后限速；
- 登录成功、失败和所有页面操作写 SQLite 审计。

公网入口只开放宝塔 Nginx `8787`。后端与 03 不增加公网访问规则。
