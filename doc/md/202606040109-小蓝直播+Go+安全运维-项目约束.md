# 项目约束

本文件记录当前项目覆盖在公共 AI 框架之上的项目级约束。

## 1. 项目定位

- 项目名称：`Kickoff（小蓝看夜场）`
- 项目 slug：`kickoff`
- 项目类型：`go-gin-app`
- 项目 preset：`go-gin-app`
- Scale Profile：默认 `mvp`，如进入 `growth`、`scale` 或 `enterprise`，必须补 `docs/templates/scale-review-template.md` 的评审内容。

## 2. 启用模块

以 `project.config.json` 为准。

| 类型 | 配置位置 | 说明 |
| --- | --- | --- |
| App | `apps` | mobile、web、admin |
| Service | `services` | go-app、laravel-app、realtime、worker |
| 第三方 | `thirdParty` | 视频、支付、短信、存储等 |
| 验收 | `quality` | 架构能力门禁、设计矩阵、红蓝对抗、项目闭环 |

## 3. 不可覆盖公共规则

项目可以选择技术栈和模块，但不能关闭以下规则：

1. Agent 日志必须记录。
2. 红蓝对抗必须执行。
3. 接口和事件必须契约优先。
4. 项目级验收必须覆盖前端、后端、后台、数据、环境和 E2E。
5. 复杂业务必须完成架构能力判断，当前 MVP 不能作为跳过理由。
6. mock、fixture、fallback 不能冒充真实完成。
7. 高风险链路必须有服务端测试、权限、审计和幂等设计。

## 4. 项目例外

所有例外必须写入 `project.config.json.exceptions`，并包含：

1. `id`
2. `reason`
3. `risk`
4. `expiresAt` 或补齐条件
5. `owner`

没有登记的例外，AI Agent 不能当作默认规则。
