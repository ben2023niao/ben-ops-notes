# ADR-0015： LSJ 体育直播源后端接入与 ZEGO 节目流边界

## 背景

项目 C 端和主播端均为 Web。世界杯类赛事源来自 LSJ（老司机资源库）第三方 API：

- `POST /lsjapi/system/domains`
- `POST /lsjapi/sportsLive/search`
- `POST /lsjapi/sportsLive/play`

LSJ 协议要求 `appid` 通过 header 传递，请求体与响应 `data` 使用 `appkey` 做 AES-128-ECB 加解密并 base64 编码。播放流只有在直播 `status=1` 且列表项 `is_played=1` 时可用。

## 决策

LSJ 不直接暴露给 C 端 Web。目标方案采用 ZEGO 云播放器 + ZEGO Web 混流：

- 后端隐藏 LSJ `appid` / `appkey`，只由后端调用 LSJ。
- LSJ 是当前唯一赛事源；后台只保存 LSJ `app_name` / `stream_name` 线路标识，不允许手填 m3u8。
- 后台创建直播间必须关联赛事；赛事必须先绑定 LSJ 源。
- 开播由后台发起准备，后端启动 ZEGO 云播放器后，主播端再进入房间推自己的流。
- 后端调用 LSJ `sportsLive/play` 获取 m3u8 主/备地址后，调用 ZEGO 云播放器 `CreatePlayer`，把 LSJ 比赛源推到 ZEGO 房间，产出 `match_stream_id`。
- 主播端 Web 通过节目配置接口拿 `match_stream_id`，拉它作为比赛预览源，同时只推自己的摄像头/麦克风流 `host_stream_id`。
- 主播端 Web 使用 ZEGO Web SDK 发起混流任务，输入 `match_stream_id + host_stream_id`，输出 `mixed_stream_id`。
- 主播端 Web 混流成功后把 `mixed_stream_id` 回写后端。
- C 端只拉 `mixed_stream_id`，不拉 LSJ、不拉 `match_stream_id`、不拉 `host_stream_id`。

正式链路：

1. 后台创建赛事，并绑定 LSJ 源 `app_name` / `stream_name`。
2. 后台创建直播间，并关联主播和赛事。
3. 后台发起开播准备 `adminRoomPrepareLive`。
4. Go 后端调用 LSJ `sportsLive/play` 获取 `main_url` / `backup_url`。
5. Go 后端调用 ZEGO 云播放器 `CreatePlayer`：
   - `StreamUrl = main_url`
   - `BackupStreamUrl = backup_url`
   - `RoomId = zego_room_id`
   - `StreamId = match_stream_id`
6. ZEGO 云播放器把比赛源推到 ZEGO 房间，主播端 Web 调 `streamerRoomProgram` 获取并拉 `match_stream_id`。
7. 主播端 Web 推自己的摄像头/麦克风为 `host_stream_id`。
8. 主播端 Web 调 ZEGO Web SDK 混流，输入：
   - `match_stream_id`：比赛主画面
   - `host_stream_id`：主播小窗/解说音频
   输出：
   - `mixed_stream_id`
9. 主播端 Web 调 `streamerRoomMixedStreamReport` 回写 `mixed_stream_id`。
10. C 端调用我方播放接口时只拿 `mixed_stream_id`，观看最终节目流。

## 后端边界

- `internal/infra/live/lsj`：只负责 LSJ 协议、加解密、响应校验和 CDN URL 签名辅助。
- `internal/infra/live/zego` 或 `pkg/zego`：后续补 ZEGO 云播放器 `CreatePlayer` / `DeletePlayer` / `DescribePlayers` 服务端 API 适配。
- `internal/service` / worker：负责同步策略、状态机、重试、熔断、审计、云播放器任务编排。
- `docs/api/openapi.yaml`：暴露后台赛事源绑定、后台房间开播准备、主播端节目配置、主播端混流回写接口；不暴露 LSJ `appid` / `appkey` 或 LSJ m3u8。
- `apps/web/**`：不直接请求 LSJ，不保存 LSJ 播放 URL。
- 主播端 Web：只能使用后端返回的 ZEGO `match_stream_id`，不直接使用 LSJ m3u8。

## 安全要求

1. `APP_LIVE_SOURCE_LSJ_APPKEY` 必须从 env/secret 注入，禁止写入 yaml、前端包、日志或 API 响应。
2. LSJ `main_url` / `backup_url` 视为敏感上游源地址，只允许后端和 ZEGO 云播放器任务使用；目标方案禁止返回 C 端，也不再返回主播端 Web。
3. 如果使用 LSJ `movie_cn_cdn` / `movie_vip_cdn`，必须按文档追加 `time`、`rand`、`uid`、`sign` 和可选 `expired` 参数。
4. LSJ 响应是第三方不可信数据，必须在 adapter/service 边界校验字段，不得直接透传给 C 端。

## 同步策略

- 全量同步：每 30 分钟调用一次 `sportsLive/search`。
- 直播中刷新：对本地播放中的直播每 30 秒刷新一次。
- 下线判定：理论规则为“上游返回列表中不再存在的本地播放中直播，标记为已完结”；正式实现时需要增加短暂容错窗口，避免单次上游抖动导致误关播。

## 后果

优点：

- 不泄露第三方 appkey 和源流 URL。
- C 端播放契约保持稳定，仍由 ZEGO 节目流承接。
- 未来可替换 LSJ 或增加其他体育源，不影响 C 端。

代价：

- 需要开通 ZEGO 云播放器权限；同一 AppID 默认运行中云播放器数量有限，需按业务并发向 ZEGO 申请额度。
- 需要补充后端 ZEGO 云播放器 API 适配、状态表、任务清理、回调与告警。
- 主播端 Web 仍需完成 ZEGO Web 混流接入，负责布局 `match_stream_id + host_stream_id -> mixed_stream_id`。

暂未落地：

- ZEGO 云播放器服务端 API 适配。
- 主播端“启动比赛云播放器”接口，返回 `player_id` / `match_stream_id`。
- 主播端“停止比赛云播放器”接口。
- 后台管理“体育源绑定/预览/状态检查/强制切换”。
- 房间级云播放器任务配置落库。
- 源失效后的主备切换和告警。
- 主播端 Web 混流 UI 与 ZEGO 推流联调。
