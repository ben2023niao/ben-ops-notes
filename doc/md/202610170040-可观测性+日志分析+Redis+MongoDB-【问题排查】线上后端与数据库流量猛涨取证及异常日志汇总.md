# 【问题排查】线上后端与数据库流量猛涨取证及异常日志汇总

> 来源：本地项目文档 `game/youdianse-docker/main/docker-youdianse-php/docs/2026-10-17-0040-【问题排查】线上后端与数据库流量猛涨取证及异常日志汇总.md`
> 整理：2026-11-09。仅复制到知识库，未改动原项目文件；敏感凭据已脱敏。

- 时间：2026-10-17 00:18 ~ 00:35（北京时间）
- 环境：线上（正式环境）
- 主机：后端 `203.0.113.1`（ip-172-31-31-108）、数据库主库 `203.0.113.1`（`server.db1.com` = 203.0.113.1）
- 触发：Beszel 告警「游点涩-后端 带宽 > 35MB/s」「游点涩-数据库-主库 带宽 > 25MB/s」，且观察与前一日基线不同
- 结论一句话：**不是被攻击，也不是前端用户流量变大；是 PHP 后端以 ~90MB/s 从 MongoDB 主库拉数据（占宿主机入流量 97%），主库同时以 107MB/s 对外发送，且读放大达 ~280 倍。**

---

## 一、结论摘要

| 现象 | 实测数据 | 说明 |

| --- | --- | --- |

| 后端宿主机 ens5 入流量 | **90~107 MB/s** | 出流量仅 7~8 MB/s |

| PHP web 容器 eth0 入流量 | **93~104 MB/s（占宿主机入流 97%）** | 同一时段 nginx 容器仅 7.19 MB/s |

| 前端（nginx）用户流量 | 入 7.19 / 出 7.40 MB/s | 与用户访问量一致，**用户侧没涨** |

| Mongo 主库下行 | **90.32 MB/s**（203.0.113.1，即 server.db1.com） | 从库 203.0.113.1 仅 2.40 MB/s |

| 数据库主库对外发送 | **107.1 MB/s**，对内接收 1.0 MB/s | 出/入 ≈ 107:1，典型「读放大」 |

| 主库查询速率 | query 534.9/s、getmore 396.9/s、command 691/s | insert 74.8/s、update 29.1/s |

| 主库扫描放大 | scanned 1,280,252/s、scannedObjects 1,717,052/s，**returned 仅 5,752/s** | 扫描/返回 ≈ **222~299 倍** |

## 五、原因分析

1. **流量方向搞清了**：后端 90+ MB/s 是「后端 → 数据库」的内部读流量，不是用户流量、也不是攻击流量；用户侧 nginx 只有 7 MB/s。
2. **读放大为根因**：主库每秒扫描 128 万索引键 / 172 万文档对象，只返回 5,752 个文档（放大 222~299 倍），因此主库以 107 MB/s 发送、只接收 1 MB/s。
3. **命中重复查询的配置类集合**：`game_category` 累计 14.4 亿次 query，`adv` 2.19 亿，`app_version` 1.39 亿，`user_sign_config` 1.33 亿，`user_task_list` 1.42 亿；这些数据变更极少，属于典型可缓存对象。
4. **读流量没有分流到从库**：`default` 与 `channel` 都配置成 `server.db1.com`（主库），`slave1/slave2` 指向 `server.db2.com` 但未承接读流量；主库同时承担读写与复制源。
5. **慢日志集中在支付链路**：`recharge/create` 慢主要是 `curl_exec` 调用第三方支付（sharkPayment），其次是 Mongo 命令进入慢栈；后台报表 `getNewReportData`、`ChannelPackageController::getList` 也在慢栈中。
6. **日志体量本身也是「猛涨」的一部分**：24 小时新增 13.9 GB，其中请求/响应全量日志 9 GB。

## 六、处置建议（待确认，未执行任何变更）

| 优先级 | 建议 | 预期效果 |

| --- | --- | --- |

| P0 | 对 `game_category`、`app_version`、`user_sign_config`、`adv*`、`channel_package` 等低变更集合加应用层缓存（或每请求合并成一次批量查询） | 直接砍掉主库大部分 query 与下行流量 |

| P0 | 将 `channel` 库及 `default` 的只读查询指向从库 `server.db2.com`，主库只承担写与复制源 | 主库 107MB/s 发送大幅下降，读放大由从库分摊 |

| P1 | 主库开启 profiling（level 1、slowms 200）采样 1~2 小时，拿到具体慢查询/集合后再做索引优化 | 用数据确认 222~299 倍放大的具体语句 |

| P1 | `recharge/create` 给第三方支付 HTTP 调用加超时与快速失败（当前进慢日志 1,500+ 次/天） | 支付下单耗时可控，慢接口错误日志大幅下降 |

| P1 | `api_request` / `api_response` 日志改为只记录慢请求与错误请求（或降采样） | 每天少写 9 GB 日志 |

| P2 | 复核 nginx 错误日志中的 642 次 `recv() failed`、302 次 `connect() refused`（上游 php-fpm 抖动）与 15 次 upstream timed out，结合发布窗口排查 | 减少 5xx/超时 |
