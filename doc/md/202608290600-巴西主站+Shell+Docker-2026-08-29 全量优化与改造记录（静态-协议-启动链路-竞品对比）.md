### report.js / shared 静态边缘缓存（纯 nginx 实现）

- 根因：宝塔 WAF(btwaf) Lua 注入 `server_name_session` cookie，CF 免费版不缓存带
  Set-Cookie 响应；
- 宝塔：`/shared/` 专属 location（按 host 映射厂商 upstream）+ Cache-Control public 1 天
  + 隐藏 Set-Cookie；btwaf `header.lua` 对 `/shared/` 跳过 cookie 注入；
- 备用机同步相同配置（无 WAF，天然无 cookie）；
- 实测：cf-cache-status BYPASS → MISS → HIT（age 递增），report.js 1s → 边缘 ~50ms；
- 备份：nginx/btwaf 相关文件 `.bak-20260829`。

### nginx 连接复用（宝塔 + 备用机同步）

- 根因：`0.websocket.conf` map 把非 WS 请求 Connection 设为 close → 每次新建后端连接；
- 修复：`'' close;` → `'' "";`（启用 upstream keep-alive）；
- keepalive_timeout 60→300s，keepalive_requests 10000；
- gzip 原本已开启；TLS 会话缓存 10m 够用。

### preconnect / Early Hints（评估后暂缓）

- 游戏页 HTML 为厂商页面、launcher 路由在镜像内，repo 侧无法注入 preconnect/Link 头；
- 需要厂商/前端配合或 Cloudflare 响应头规则（规则集权限），记为后续。

## 七、多地区部署 / AWS 评估结论

- A 档（边缘缓存静态/稳定 GET）：已部分落地（shared/report.js、GCS 缓存头）；
- B 档（亚洲 platform-api + Redis 副本）：可行但 MySQL 仍回巴西，收益有限，
  需 MySQL 只读副本；亚洲用户约 10%，性价比需评估；
- C 档（游戏服务亚洲化）：追平竞品源站距离的完整路径，成本最高；
- AWS CloudFront 用于动态 API：边缘不解决源站距离（源站仍在巴西），不建议切换。
