## 任务边界

用户要求：

```text
设置备用 nginx 服务器与 3 台后端服务器的 SSH root 密码为指定值，方便登录；
按标准工作流：workbench、逐步群通知、完成后验证、汇总文档发群、最后合并提交本地代码。
```

安全处理：root 密码为用户指定值，明文不写入本仓库、群通知、日志或命令回显；临时密码文件执行后删除。

## 一、目标服务器

```text
备用 nginx：bizops-saopaulo-nginx-standby-01（192.0.2.13 / 192.0.2.1）
后端 01：bizops-saopaulo-sanic-prod-01（192.0.2.10 / 192.0.2.1）
后端 02：bizops-saopaulo-sanic-prod-02（192.0.2.11 / 192.0.2.1）
后端 03：bizops-saopaulo-sanic-prod-03（192.0.2.20 / 192.0.2.1）
宝塔 root 密码未改动（用户未要求）。
```

## 二、调查结论

```text
3 台后端已允许 root 密码登录（PermitRootLogin yes + PasswordAuthentication yes）。
备用机默认禁止 root 密码登录（Ubuntu prohibit-password），需显式开启。
机器人通过 PGSERVER_DEPLOY_PASS 连接后端（备用机/宝塔 env 文件 + 宝塔 compose .env）。
宝塔结果同步 cron 使用独立非 root 用户密码，不受 root 密码变更影响。
```

## 三、执行

```text
1. 备用机：chpasswd 设置 root 密码；新增 /etc/ssh/sshd_config.d/00-root-pass.conf
   （PermitRootLogin yes + PasswordAuthentication yes，排序先于 cloud-init 默认），重启 ssh。
2. 后端 01/02/03：逐台以旧密码登录后 chpasswd 设置 root 密码，逐台验证。
3. PGSERVER_DEPLOY_PASS 同步更新：
   - 备用机 /opt/benbot-runtime.env
   - 宝塔 /opt/benbot-runtime.env、/opt/pgserver/docker/ben-bot/.env（compose 源）
   - 重建备用机 bot（poll）与宝塔 bot（idle）。
4. 临时密码文件在两台主机删除（root 600 创建，用后即删）。
```

## 四、验证

```text
新密码 SSH 登录：
  - 备用机 bot 容器 -> 192.0.2.1/.4/.11/192.0.2.1 全部 hostname 正常；
  - 宝塔 bot 容器 -> 192.0.2.1/.4/.11 全部正常。
备用机 root 密码登录生效（sshd -T：permitrootlogin yes / passwordauthentication yes），密钥登录保留。
机器人功能：热更新 dry-run 通过；无 409 轮询冲突。
```
