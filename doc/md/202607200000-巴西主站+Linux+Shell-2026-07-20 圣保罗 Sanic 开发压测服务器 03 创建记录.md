## 当前结论

已基于圣保罗后台 01/02 的共同基础设施规格创建独立开发压测机 `bizops-saopaulo-sanic-prod-03`，完成 Docker、Python、Sanic、接口测试和压力测试环境部署。

## 创建原则

源服务器：

- `bizops-saopaulo-sanic-prod-01`
- `bizops-saopaulo-sanic-prod-02`

两台源机共同使用 `southamerica-east1-a`、`e2-standard-8`、500GB 系统盘、Ubuntu 26.04 LTS 和圣保罗业务 VPC。新机复用共同基础设施规格，但使用全新 Ubuntu 系统盘，没有复制生产磁盘、生产数据或生产容器。

源机磁盘分别为 `pd-ssd` 和 `pd-standard`，新机采用两者之间的 `pd-balanced`。

## 网络隔离

由于圣保罗 VPC 存在历史公网端口规则，新机增加了实例内隔离：

- UFW 开机自启，默认拒绝入站、允许出站。
- 公网仅允许 TCP 22。
- `192.0.2.1/20` 内网允许接口联调和压测。
- `bizops-docker-internal-only.service` 开机自启，通过 `DOCKER-USER` 链阻止公网访问 Docker 发布端口。
- 宝塔 Nginx 配置中没有新机名称、公网 IP 或内网 IP 引用。

隔离实测使用临时 Nginx Docker 容器发布 `9090`：

```text
192.0.2.1:9090 -> 内网访问成功
192.0.2.20:9090 -> 公网访问被阻断
```

测试后已删除临时容器和镜像，端口 9090 不再监听。

## Beszel 监控

```text
container: beszel-agent
image: henrygd/beszel-agent
network: host
restart policy: unless-stopped
hub: http://192.0.2.15:8090/
listen env: 45876
docker socket: read-only
data volume: beszel_agent_data
```

Agent 使用 TOKEN/WebSocket 主动连接模式，日志已确认 `WebSocket connected`，容器状态 `running`、重启次数 0。UFW 仅允许 Hub `192.0.2.15` 访问 TCP 45876；其他公网来源仍被拒绝。

TOKEN、KEY 和其他认证值不写入仓库或通知。
