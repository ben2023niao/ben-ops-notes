## 背景

一次发布在正式群会产生约 10 条通知，用户反馈“通知太多”，要求精简：

```text
精简前（Web 页面发布）：
1. 发布占用｜已进入发布流程
2. 发布占用｜第一步：查看确认
3. 发布占用｜第二步：选择部署 git id
4. 发布占用｜第三步：选择部署模式
5. 发布占用｜第四步：等待开始执行
6. 发布占用｜第四步：开始执行
7. 发布开始（目标/服务/配置）
8. 发布结果（成功/警告/失败）
9. 详细部署日志文件
10. 发布占用｜发布锁已释放
```

## 通知链路分析

```text
发布占用/步骤流水：update_publish_state(notify=True) 每次变化都发一条（6 条）
发布开始/发布结果：run_deploy 内 send_telegram(build_start_report / build_deploy_report)
详细日志文件：发布流程成功/失败都 send_telegram_document（保留）
发布锁释放：finish_publish_session -> update_publish_state（1 条）
强制踢人：force_release_publish_session（人工操作，保留）
CICD 自动更新：cicd-web-auto-update.py 每次发“开始 + 完成”2 条
```

## 改造内容

### 1. 发布占用与步骤流水不再发群（cicd-web/core.py）

- `update_publish_state` 的 `notify` 默认值从 `True` 改为 `False`：
  发布过程中的步骤流水只写锁文件与页面，不再触发 Telegram；
- `try_begin_publish_session` 不再发送“已进入发布流程”占用通知；
- 锁文件互斥与页面“发布占用”面板逻辑不变；
- 人工“强制踢人”通知保留（显式 notify=True 场景）。

### 2. CICD 自动更新通知合并（cicd-web-auto-update.py）

- 移除“自动更新开始”通知，只保留“自动更新完成”一条（含版本与提交清单）；
- 更新失败仍保留失败通知；细节在 `cicd-web-auto-update.log`。

## 精简后的通知结构

```text
正常发布（Web / CLI 一致）：
1. 发布开始（操作人、机器、目标 git、服务、配置）
2. 发布结果（成功/警告/失败 + 版本/镜像/健康检查）
3. 详细部署日志文件（完整步骤、构建输出、验证细节）

预检查失败：仅 1 条“发布流程日志”文件（结果写在文件名与标题）
人工强制踢人：保留 1 条（低频率、需要知会）
CICD 自动更新：1 条“完成”（原 2 条）
```

细节（第一步~第四步、构建日志、健康检查明细）全部保留在发布日志文件里，群内不再刷屏。
