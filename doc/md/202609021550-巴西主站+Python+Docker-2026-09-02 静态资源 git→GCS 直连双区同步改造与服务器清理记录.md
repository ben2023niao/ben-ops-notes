## 一、方案与工具

```text
新工具：docker/scripts/git_static_gcs_sync.py
- 默认模式：以 last-synced commit 为基线，fetch client.git master 新提交，
  diff 变化文件后只把新增/修改文件上传到目标桶（增量、不删除）；
- --full-audit：只读报告（git tree vs LIVE 桶名称差异），绝不自动回灌；
  原因：GCS 与 git 存在历史差异（PNG->WebP 等运维转换、health.json 等运维
  补充对象、历史删除），整库“补缺失”会把已优化掉的旧资源大量回灌；
- 临时目录用完即清；不在服务器 wwwroot 落盘；仓库缓存仅保留 git 元数据
  （/root/.client-git-cache，blobless sparse，可增量 fetch）。

目录映射（14 组，与 gcs_static_sync 同源）：
  pgnew->pg-static / pg3->pg3-static / pg4static->pg4-static /
  pg5static->pg5-static / pg6static->pg6-static / pg7static->pg7-static /
  tadastatic->tada-statics / tadastatic1->tada-statics1 /
  tadastatic2->tada-statics2 / ppstatic->pp-static / popok->ppk-static /
  playsonstatic->playson-static / panda->panda-static / G759static->g759-static

目标桶：
  LIVE（巴西）  gs://dbqp-gcs-<prefix>-sa        （g759: dbqp-gcs-g759-static）
  ASIA（香港/东京） gs://dbqp-gcs-<prefix>         （g759: dbqp-gcs-g759-static-asia）
  BACKUP         gs://dbqp-game-statics-gcs/<prefix>
```
