## 五、发现并解决的一个「配置不生效」的坑

### 现象

```text
PG 容器内配置已是新版：version.json=448fa821 / server_configs=ae200e82
其余 7 个厂家容器仍是旧版：version.json=00a0ff50 / server_configs=4f7cb550
```

### 根因

```text
这 7 个容器用「文件级 bind mount」把宿主机文件挂到容器内：
  /opt/pgserver/version.json  -> /app/version.json
  /opt/pgserver/server_configs -> /app/server_configs
git checkout 换版本时文件被替换成新 inode，运行中的容器仍绑定旧 inode，看不到新内容。
宿主机 md5 已是新版，容器内却是旧版 —— 只看宿主机校验会误判「已生效」。

直接补文件也不行：
  docker cp → Error response from daemon: unlinkat /app/version.json: device or resource busy
```

### 处理

```text
重启容器 → 重新解析 bind mount → 拿到新 inode 内容。
先在 tada 验证（重启 3.2s，容器内配置立刻变为 448fa821/ae200e82），
再按 pp → popok → playson → panda → g759 → platform-api 逐个串行重启，间隔 5s。
结果：8/8 容器内配置均为 448fa821 / ae200e82。
```
