# 2026-07-09 机器人重启通知轮换验证

> 来源文件：`~/Desktop/18game_devops/devops/python/ben-bot/doc/2026-07-09_1503-【优化】机器人重启通知轮换验证.md`

> 整理日期：2026-07-09 15:03｜日期依据：文件名日期

环境标签：通用

## 背景

线上 ben-bot 例行重启后，启动通知长期使用固定文案，群里看起来过于机械：

```text
ben-bot 已上线。
【本次更新】
- 更新 ben-bot 运行代码并重启容器
- 发布任务使用单条实时进度框和完整日志附件
- /start 可重新打开最新菜单
```

本次优化目标：

- 重启通知使用多套自然文案，不再固定三段拼接。
- 连续重启时优先避免重复文案。
- 保留关键运维信息：版本、本次更新、系统、主机、/start 入口说明。
- 不影响启动通知发送目标、权限、菜单、发布脚本和日志附件能力。

## 改动范围

涉及文件：

- `devops/python/ben-bot/app/benbot/main.py`
- `devops/python/ben-bot/build_and_run_ben_bot.sh`

主要变化：

- 启动通知改为 `STARTUP_NOTICE_TEMPLATES` 整段自然文案。
- 使用持久化洗牌队列 `startup_notice_variant_queue.txt` 轮换模板。
- 一轮模板用完前不重复；下一轮重新洗牌，并避开上一轮最后一条开头。
- 默认例行重启说明也记录上一版，避免连续两次相同。

## 本地验证

语法检查：

```bash
python3 -m py_compile devops/python/ben-bot/app/benbot/main.py
sh -n devops/python/ben-bot/build_and_run_ben_bot.sh
```

结果：通过。

容器内模拟 12 次模板选择：

```text
seen=3,9,7,2,8,6,5,4,0,1,0,1
first10_unique=True
first10=3,9,7,2,8,6,5,4,0,1
after_round=0,1
```

结论：

- 前 10 次使用 10 套不同模板。
- 第 11 次开始进入下一轮模板队列。

## 线上验证

线上部署后连续真实重启 5 次 ben-bot。

验证命令核心逻辑：

```bash
sudo docker restart ben-bot
sleep 8
sudo docker logs --since 20s ben-bot | grep -E "ben-bot started|启动通知发送完成"
```

重启结果：

| 轮次 | 模板编号 | 文案开头 | 通知结果 |
|---:|---:|---|---|
| 1 | 5 | ben-bot 已重新接上。 | 成功=6 失败=0 |
| 2 | 6 | ben-bot 已上线待命。 | 成功=6 失败=0 |
| 3 | 7 | ben-bot 本次启动检查已完成。 | 成功=6 失败=0 |
| 4 | 8 | ben-bot 服务已恢复。 | 成功=6 失败=0 |
| 5 | 3 | ben-bot 回来了。 | 成功=6 失败=0 |

结论：

- 连续 5 次真实重启文案均不同。
- 每次启动通知均成功发送到 6 个目标。
- 容器状态正常，未发现启动异常。

## 注意事项

- 本机制只保证一轮模板队列内不重复，不保证不同群收到不同文案；同一次重启会向所有目标发送同一版文案，便于排查。
- 如果 `data/upload` 持久化目录被清空，模板队列会重新生成，不影响机器人启动。
- 启动通知只表示 ben-bot 在线，不代表业务发布完成；业务发布仍以发布任务结果和日志附件为准。
