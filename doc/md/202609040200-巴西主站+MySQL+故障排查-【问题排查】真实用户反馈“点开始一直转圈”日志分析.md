## 一、反馈

```text
真实用户（Lion）：巴西本地很多游戏不能正常娱乐；
视频中试了两款游戏，一款不行一款可以；游戏加载成功后点开始一直转圈。
Ben 运维备注：同地区首个用户打开后，后续用户打开很快（预热机制），
但“第一次不能玩”不像速度问题，更像游戏本身问题。
```

## 二、日志排查过程

```text
1) 三台后端（203.0.113.1/.4/.11）最近日志扫描（至 2026-09-03 17:56 UTC）；
2) 按 ERROR/Exception/Timeout/5xx 初筛 -> 结合 doSpin/do_game_spin 上下文；
3) 对比同商户成功/失败 betsettle 请求参数；
4) 对照 platform-api open_game_list 与仓库游戏映射。
```

## 三、根因

```text
1) 主因（真实不能玩）：无缝钱包 mypg.prod-br.com/dbqp/v2/wallet/seamless/betsettle
   对商户 SHYYTYBRLMCH3165(YYTYBRL) 的特定游戏返回 rcode 1110 Parameter error：
   - PP 108 财神聚宝盒2（17:05/17:36 UTC 多台出现）
   - PANDA 11 繁荣兔（17:48 UTC 多台出现）
   同商户其它游戏（PP 127 等）相同结构参数可正常结算 ->
   排除我方请求字段差异，疑似钱包/商户侧未开通该两款游戏或游戏级参数配置问题。
2) 次因（大厅可见但未开放）：open_game_list 只放行部分游戏
   - PANDA 45 Solar Pong 未开放、G759 6115 仙灵女巫 未开放（g759 仅 4 款开放）
   大厅卡片数远多于开放名单，用户点入报“尚未开放”，体验像坏了。
3) 旁证（统计落库）：sp_upsert_user_day / sp_upsert_game_day
   MySQL 1318 参数不匹配（expected 11/9 got 12/10），各厂商每分钟刷错，
   影响“今日汇总”类落库，需代码与 DB 存储过程对齐。
```


## 五、建议

```text
1) 联系钱包方确认 YYTYBRL 商户下 PP108/PANDA11 开通状态与参数
   （currency BRL / jurisdiction / gameid 白名单）；
2) 上线前核对 open_game_list 与大厅展示名单一致，避免“看着能点进去却未开放”；
3) DB 存储过程参数与代码调用对齐（1318 持续刷错会掩盖真实问题）。
```
