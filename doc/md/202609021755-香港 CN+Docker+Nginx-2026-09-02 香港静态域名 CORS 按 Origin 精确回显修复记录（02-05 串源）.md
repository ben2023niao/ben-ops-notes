## 一、现象与根因

```text
现象：用户实测 pg-games.hkcloudplay01.com 游戏页加载同 zone 静态正常，
      02-05 全部失败。
初步定位：CloudFront 缓存键不含 Origin 头。zone01 首次请求的响应
  （ACAO=https://pg-games.hkcloudplay01.com）被缓存，02-05 命中同一缓存对象，
  返回的 ACAO 不是请求方 Origin，游戏客户端严格解析 ACAO 失败。
实测证据：zone02-05 GET/OPTIONS 均 x-cache=Hit 且 ACAO 为 zone01 的 Origin。
```

## 二、约束与尝试

```text
香港 AWS IAM（bizops-hk-nginx-ai）权限受限：
  - cloudfront:CreateResponseHeadersPolicy 拒绝；
  - cloudfront:CreateFunction 拒绝；
  - cloudfront:CreateCachePolicy 拒绝。
尝试过的路径：
  1) CloudFront Function viewer-response 按请求 Origin 覆盖 ACAO -> 无建函数权限；
  2) 现成自定义缓存策略 UseOriginCacheControlHeaders(-QueryStrings)
     （缓存键含 Origin）-> 该策略会把 Host 头转发给 S3 源，破坏虚拟主机路由，
     17 分配全部 404，已回退；
  3) 最终采用 Managed-CachingDisabled：静态分配不缓存，每次请求回源 S3，
     S3 显式 CORS（43 Origin）按请求方精确回显，无跨 Origin 缓存串源。
```

## 三、最终配置（17 个静态分配）

```text
- OriginRequestPolicyId：88a5eaf4-2fd4-4709-b370-b4c650ea3fcf（CORS-CustomOrigin）；
- ResponseHeadersPolicyId：""（移除 Managed-CORS-With-Preflight 通配策略）；
- CachePolicyId：4135ea2d-6df8-44a3-9df3-4b5a84be39ad（Managed-CachingDisabled）；
- S3 桶 CORS：AllowedOrigins=43 项显式（2026-09-02-1735 文档已记录）；
- nginx 静态兜底：显式 map 回显（2026-09-02-1735 文档已记录）。
工具：docker/deploy/hongkong/configure_cloudfront_static_cors.py
  （幂等：检查 ORP/RHP/CachePolicy 三项，不符即更新）。
```

## 四、验证结果

```text
1. zone 01-05：pg-games.hkcloudplay0X Origin -> pg7-static.hkcloudplay0X
   GET 全 200 且 ACAO 精确等于请求 Origin（Miss from cloudfront）；
2. 同一 URL 交叉 5 种允许 Origin：每次返回各自 Origin，无串源；
3. OPTIONS 预检 01-05：200 + 精确 ACAO；
4. 非法 Origin：GET 200 无 ACAO；OPTIONS 403 拦截；
5. 70 静态域名（14 前缀×5）GET 带 ind-h5 Origin：70/70 精确回显；
6. 真实文件 200 无回归；动态接口保持后端 CORS（未动）。
```

## 回滚 / 遗留

```text
回滚：将 17 个静态分配 CachePolicyId 改回 658327ea（Managed-CachingOptimized）
  即恢复缓存（但会重现串源问题，需配合其它方案）。
遗留/后续建议：
  - 静态域名当前不启用 CF 边缘缓存（逐请求回源）。正确性优先；
    恢复缓存两条路径：
    a) IAM 增加 cloudfront:CreateCachePolicy/UpdateCachePolicy，创建
       “缓存键仅含 Origin、TTL 正常、不转发 Host”的自定义缓存策略；
    b) 给 S3 对象补 Cache-Control 元数据并配合含 Origin 缓存键策略
       （注意该策略不能转发 Host）；
  - 新增门户域名时同步更新 S3 桶规则、nginx map、本工具缓存/回显清单。
```

## 附二：自有随机子域放开 ACAO *（2026-09-02 19:00）

```text
用户测试域：games-cf.nuvastone.com（Cloudflare）、games-aws.cxkerui.com（自有 CF）；
页面子域随机，用户明确要求这些根域放开为 ACAO *。
处理：S3 桶 CORS 改为两条规则——
  规则1（在前）：hkcloudplay01-05.com / hkplaycore.com / bizopsplus999.com
    根模式 + 根域，命中后精确回显请求 Origin（credentials:true）；
  规则2（兜底）：AllowedOrigins ["*"]，命中任意其它 Origin（含 nuvastone.com /
    cxkerui.com 随机子域）返回 ACAO:*（GET；OPTIONS 由 S3 回显请求 Origin）。
nginx map：nuvastone/cxkerui 任意子域映射 "*"，平台根域继续精确回显。
验证：games-cf.nuvastone.com / games-aws.cxkerui.com / 任意随机子域
  CF 与 S3 直连均 200 + ACAO:*；ind-h5/pg-games.*/games.hkplaycore.com 精确回显；
  OPTIONS 200。
注意：兜底 * 也作用于其它未列 Origin（静态资源本就公开，风险可控）；
  若阿里云 CDN（pg4-static-ali.shangdefu.com）侧仍回 *，属其边缘配置，
  与我方 S3/CF 无关。
工具：configure_s3_bucket_cors.py（cors_rules 2 条）、nginx map。
```
