## 核心决策

1. **subject 独立而非用 role 字段**:延用 jwtx.Subject 一等公民模式,中间件 `JWT(issuer, SubjectStreamer, redis)` 直接拒绝跨端 token,避免 user→admin→streamer 任意串台
2. **service 与 admin/streamer 分包**:`internal/service/streamer/` 只服务主播自管(单行),`internal/service/admin/streamer.go` 处理后台批量/审批/分页,接口面积差异大,合并会出现 50+ 方法的 god service
3. **repo 接口 4 方法**:不暴露 GORM,便于 service 用 fakeRepo 单测;UpdatePassword 把 must_change_password 当业务参数显式传入,避免 service 直接拼 map[string]any
4. **bcrypt cost 与 user 端一致**:走 `password.Hash`(默认 cost),后续若主播账号被暴破再单独提
