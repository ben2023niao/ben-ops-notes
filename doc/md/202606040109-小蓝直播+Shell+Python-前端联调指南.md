## 3. 引入 TypeScript SDK（推荐）

后端所有接口都有 OpenAPI 契约（`docs/api/openapi.yaml`），前端可以直接生成 TS 类型 + 强类型 HTTP 客户端。

### 安装

`pnpm-workspace.yaml` 里已经包含 `packages/ts-sdk`。

在前端 `apps/web/package.json` 或 `apps/admin/package.json` 里加：

```json
{
  "dependencies": {
    "@kickoff/ts-sdk": "workspace:*"
  }
}
```

### 使用

```ts
// composables/useApi.ts (Nuxt) 或 src/api/client.ts (Vue)
import { createKickoffClient } from '@kickoff/ts-sdk'

export const client = createKickoffClient({
  baseUrl: import.meta.env.VITE_API_BASE,            // e.g. http://localhost:8080
  [敏感内容已脱敏] => useAuthStore().accessToken,  // pinia store
  onUnauthorized: () => useAuthStore().logout(),
})

// 完全类型安全
const { data, error } = await client.POST('/api/v1/auth/login', {
  body: { account: 'demo', 敏感凭据：[已脱敏] },
})

// 类型推断
type LoginRes = NonNullable<typeof data>['data']     // AuthResponse
```

### 重新生成（后端契约改了之后）

```bash
# 在 monorepo 根目录
make sdk           # = pnpm --filter @kickoff/ts-sdk run generate
```

会更新 `packages/ts-sdk/src/generated/schema.ts`（前端自动跟随）。

## 4. 请求 / 响应统一约定

### 4.1 响应 envelope

所有 API 返回统一结构：

```jsonc
{
  "code": 0,                    // 0=成功；非 0 见错误码表
  "message": "ok",
  "data": { ... },              // 业务数据（失败时为 null）
  "trace_id": "uuid",           // 追踪 ID（前端贴到 bug 报告里方便后端查）
  "timestamp": 1779482635343    // unix ms
}
```

### 4.2 错误码

5 位正整数：

| 段 | 含义 |
|---|---|
| 1xxxx | 系统错误（10001 internal / 10004 rate-limited / 10007 feature-closed） |
| 2xxxx | 业务错误（20001 param / 20003 conflict / 20004 idempotency / 20101 余额不足 / 20201 押注超限 / 20301 比赛未直播 / 20401 KYC required） |
| 3xxxx | 权限错误（30001 unauthorized / 30002 token expired / 30003 token invalid / 30004 forbidden / 30005 admin scope） |

### 4.3 字段类型

| 类型 | JSON 表达 | 说明 |
|---|---|---|
| BIGINT ID | `"20581585086578689"` | **字符串**，避免 JS Number 精度丢失 |
| RMB 金额 | `"100.50"` | **字符串**，保留 2 位小数 |
| 钻石数量 | `1000` | int64 |
| 时间 | `1779482635343` | unix ms (int64) |
| 状态 | `"PENDING"` / `"PAID"` | 大写字符串枚举 |

### 4.4 必带 header

| Header | 何时 | 说明 |
|---|---|---|
| `Authorization: Bearer <token>` | 登录后所有受保护接口 | JWT access token (2h TTL) |
| `X-Idempotency-Key: <uuid v4>` | 资金类写接口（recharge/withdraw/exchange/bet/tip）| 客户端生成 UUID，同 key 重复请求会被拒（10004 / 20004）|
| `X-Trace-Id` | 可选 | 客户端可生成 trace ID 自带；不带服务端会生成 |
| `X-Request-Id` | 可选 | 跨服务链路 ID（nginx/api-gateway 注入）|

### 4.5 限流

| 接口 | 限制 |
|---|---|
| `/api/v1/auth/login` | 10 次 / 分钟 / IP |
| `/api/v1/auth/register` | 10 次 / 分钟 / IP |

超过返回 HTTP 429 + body `{code: 10004, message: "请求过于频繁"}` + header `Retry-After: <seconds>`。

## 5. 关键流程示例

### 5.1 C 端注册 + 登录

```ts
// 1. 注册
const reg = await client.POST('/api/v1/auth/register', {
  body: { account: 'demo01', 敏感凭据：[已脱敏] nickname: '演示账号' },
})
// reg.data 即 AuthResponse：含 user_id + token.access_token + token.refresh_token

// 2. 存 token
useAuthStore().setTokens(reg.data!.data!.token)

// 3. 后续请求会自动带 Authorization 头
```

### 5.2 充值 → 等待回调 → 余额变更

```ts
// 1. 发起充值（拿 idem key）
const idem = crypto.randomUUID()
const init = await client.POST('/api/v1/wallet/recharge/init', {
  headers: { 'X-Idempotency-Key': idem },
  body: { channel: 'wechat', rmb_amount: '100.00' },
})
const orderNo = init.data!.data!.order_no
// 跳转到 init.data.data.pay_url（生产环境）；本地测试可手动触发 hook

// 2. 轮询状态（或用 WebSocket 监听）
const status = await client.GET('/api/v1/wallet/recharge/{order_no}/status', {
  params: { path: { order_no: orderNo } },
})
// status.data.data.status 变成 "PAID" 后，钻石余额已到账
```

### 5.3 押注

```ts
const idem = crypto.randomUUID()
const bet = await client.POST('/api/v1/predict/bet', {
  headers: { 'X-Idempotency-Key': idem },
  body: { activity_id: '101', option_id: '10011', bet_amount: 500 },
})
// 钻石余额自动扣 500；bet.status 初始 = "PLACED"
```

### 5.4 Admin 登录 + balance-adjust

```ts
const login = await adminClient.POST('/api/v1/admin/auth/login', {
  body: { username: 'kickoff_admin', 敏感凭据：[已脱敏] },
})
// JWT subject="admin"，前端用 admin token 调 /api/v1/admin/*

// 给用户加 200 💎
await adminClient.POST('/api/v1/admin/users/{id}/balance-adjust', {
  params: { path: { id: '20581585086578689' } },
  body: { currency: 'diamond', direction: 'add', amount: '200', reason: '客服补偿' },
})
// 后端走 ledger 复式记账 + 写 balance_adjustments 表 + admin_audit_logs
```

## 7. 常见问题

### Q1: 401 unauthorized
- access token 过期（2h TTL）→ 用 refresh token 调 `/auth/refresh` 换新对
- refresh token 也过期（30d）→ 重新登录

### Q2: 20004 幂等键冲突
- 同一 `X-Idempotency-Key` 二次请求会被拒。每次资金操作前 `crypto.randomUUID()` 重新生成

### Q3: 资金类接口都返回 20003 conflict
- 检查请求体里的 ID 字段（user_id / order_no）是不是字符串而非 number — JS Number 会丢失 BIGINT 精度

### Q4: 拉不到列表数据
- 先 `make dev-up` 灌 seed
- 列表分页：默认 page=1, size=20，传 query `?page=2&size=50`

### Q5: 弹幕表查不到
- 弹幕按月分表 `live_chat_messages_YYYYMM`。每月 1 日需运营提前建好下月表（本期手动）

### Q6: 直播间状态不对
- 房间状态机：1=IDLE / 2=LIVE / 3=ENDED / 4=BANNED
- 拉流地址 `/play-url` 仅在 LIVE 状态返回；其他状态返回 20301

### Q7: 重置数据库
```bash
make dev-reset   # 销毁数据卷 + 重新 dev-up + seed
```

### Q8: 怎么测 SRS hook
- 当前 docker-compose 注释了 SRS 容器
- 用 `curl` 模拟回调：
```bash
curl -X POST http://localhost:8080/api/v1/hooks/srs/on_publish \
  -H 'Content-Type: application/json' \
  -d '{"action":"on_publish","stream":"room_R0001_keysk_r0001_aabbccddeeff1122"}'
# 返回 {"code":0} 即表示推流被放行
```

## 8. H5 直播间接口对接口径

原型里的 `/rooms/{id}`、`/tip`、`/bets` 是产品说明简写；联调必须使用 OpenAPI 中的 `/api/v1/*` 路径。

| 产品原型场景 | 后端接口 | 响应/请求口径 |
| --- | --- | --- |
| 进入直播间 | `GET /api/v1/live/room/{room_id}` | `data` 是 `LiveRoom`，含主播、状态、观看数、关联比赛与比分快照。 |
| 拉流 | `GET /api/v1/live/room/{room_id}/play-url` | `data.flv_url` / `data.hls_url` / `data.expire_at`。 |
| 播放 token 续期 | `POST /api/v1/live/room/{room_id}/refresh-token` | 需登录；返回 `play_token` / `expire_at`。 |
| 弹幕历史 | `GET /api/v1/live/room/{room_id}/danmaku?limit=50` | `data.items[]` 是 `LiveDanmaku[]`，不是 `data[]`。 |
| 发弹幕 | `POST /api/v1/live/room/{room_id}/danmaku` | body `{ "content": "..." }`；v0.3.1 上限 100 字；登录用户均可发，不需要等级。 |
| 打赏 | `POST /api/v1/live/room/{room_id}/tip` | body `{ "diamond_amount": 100, "client_combo_seq": 1 }`；字段不是 `amount`。 |
| 直播间竞猜卡 | `GET /api/v1/live/room/{room_id}/activities` | `data.main` 是主推活动；`data.all[]` 是全部可展示活动。 |
| 直播线路 | `GET /api/v1/live/lines?room_id={room_id}` | `data.items[]` 是后端启用线路；`auto` 由前端自行添加。 |
| 线路选择 | `POST /api/v1/live/lines/select` | body `{ "room_id": "...", "line_id": "auto" }` 或真实线路 code。 |
| 房间 WS | `WS /ws/v1/live/{room_id}` | 弹幕、进场、打赏、观看数、下播/封禁事件。 |
| 比分 WS | `WS /ws/v1/match/{match_id}` | `match_id` 从房间元数据取；断线兜底 `GET /api/v1/match/{match_id}/score`。 |

当前 v0.3.1 的线路选择只做上报与统计，`play-url` 尚未按 `line_id` 返回不同 CDN 地址；前端可以保留线路 UI，但不要假设切线会改变播放 URL。

后台已有对应管理入口：

| 模块 | 页面 | 核心接口 |
| --- | --- | --- |
| 直播间管理 | `apps/admin/src/views/rooms/RoomListView.vue` / `RoomDetailView.vue` | `/api/v1/admin/rooms*` |
| 管理员账号 | `apps/admin/src/views/admins/AdminAccountListView.vue` | `/api/v1/admin/admins*`；仅 `super_admin` 可新增/启用/禁用管理员账号。 |
| 直播线路 | `apps/admin/src/views/live-lines/LiveLineListView.vue` | `/api/v1/admin/live-lines*` |
| 主播管理 | `apps/admin/src/views/streamers/StreamerListView.vue` | `/api/v1/admin/streamers*` |
| 竞猜活动 | `apps/admin/src/views/predict/PredictListView.vue` | `/api/v1/admin/predict/activities*` |
| 用户运营标签 | `apps/admin/src/views/users/UserListView.vue` / `UserDetailView.vue` | `/api/v1/admin/users*` 返回 `spender_tier` / `total_tip_diamond`；大 R 按累计送出打赏钻石计算，不是等级特权。 |

已实现但后台页面还未完整做 UI 的房间能力：切换主播、切换关联比赛、会话历史、删除弹幕和禁言操作。接口可用，UI 仍需补齐。房间管理员分配已在房间详情页提供基础 UI。

前端注意：旧原型里的 `level`、等级弹幕颜色、等级进场、等级投注上限、等级不足无法发弹幕都已废弃。C 端不要展示或依赖等级特权；后台如需识别大 R，只使用 `spender_tier` 和 `total_tip_diamond`。

## 9. 后端联调期可能动的接口

以下接口可能在前端联调过程中有微调，前端最好用 `@kickoff/ts-sdk` 而不是手写：

- 列表接口的 query 参数命名
- 错误码细分（特别是 2xxxx 业务错误）
- 状态字符串大小写
- 资金类接口的 idempotency_key scope

约定：**契约（v1.yaml）变更时**，后端一定会 `make openapi && make sdk` 重新生成；前端 `pnpm install` 拉最新即可。

## 10. 联系方式

- 后端接口问题 / 错误码不明：把 `trace_id` 贴出来，后端能查到完整日志
- 联调环境挂了：`make dev-reset` 重置
