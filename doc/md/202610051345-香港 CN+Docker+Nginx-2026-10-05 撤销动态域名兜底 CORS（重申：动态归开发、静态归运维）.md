# 2026-10-05 撤销动态域名兜底 CORS（重申：动态归开发、静态归运维）

> 公开版脱敏说明：公司、平台、节点、账号、地址和业务对象均已替换为示例标识；替换后的名称仅用于公开复盘。

> 来源文件：`~/Projects/ops/private-notes/cn/docker/doc/2026-10-05-1345-【运维】撤销动态域名兜底CORS-重申动态归开发静态归运维.md`

> 整理日期：2026-10-05 13:45｜日期依据：文件名日期

## 一、用户口径（2026-10-05 二次确认）

```text
「运维对动态域名不做任何跨域处理，只处理静态域名的跨域。」

对应既有决策：DEC-20261005-HK-CORS-SPLIT（USER_CONFIRMED）
  · 动态域名（*-games / api / socket 等）：CORS 全部由后端/开发代码负责，
    nginx 侧**不做任何跨域处理**（含 nginx 自产的 502/503/504 也不补头）。
  · 运维只负责静态域名（*-static）：ACAO * + GET/HEAD/OPTIONS + OPTIONS 204，
    以及 customizations.info / .js / 目录 302 这类静态特例。
```

## 二、本轮为什么又要撤回

```text
14:35 那轮为了解决「游戏页 cors 模式请求 /lj500/ 被浏览器拦掉」，我在
     vendor_b-games（动态域名）的 @vendor_b_page_static1 / @vendor_b_page_static0 四个 location
     include 了 snippets/bizops-hk-standby-vendor_b-cors.conf（回显 Origin + allow-credentials + Vary）。
     这属于对**动态域名**做跨域处理，与上面的口径冲突 → 按用户要求撤回。
说明：那些响应确实是「nginx 自己从 S3 取静态页」产出的，后端加不了头；
     但按职责划分，这条链路的跨域问题应由开发从代码侧解决（例如改请求方式/不依赖该调用），
     运维侧不动。若开发确需服务端补头，需要另行明确授权。
```

## 三、执行与验证

```text
1) 仓库：删除 docker/deploy/hongkong/nginx-standby-vendor_b-cors.conf，
        移除 nginx-standby.conf 里 4 处 include（m4q7z1 / k8x2v9 两个 vendor_b-games 块）。
2) 服务器：scp 覆盖 bizops-hk-standby.conf；片段文件 mv 成
        /etc/nginx/snippets/bizops-hk-standby-vendor_b-cors.conf.removed-20261005-1320（留档不删）；
        备份 bizops-hk-standby.conf.bak-20261005-1320-corsrevert；nginx -t 通过后 reload。

验证（经 EdgeOne）：
  · 动态：GET vendor_b-games.k8x2v9.shop/lj500/ 带 Origin → 200/97,383B，**无任何 CORS 头**（已撤回）
  · 动态：后端自己产出的响应仍带自己的 CORS（GET /webservice/nope 404 → ACAO 回显 + allow-credentials）
  · 静态：vendor_b-static1.k8x2v9.shop 仍 ACAO * + methods/headers；/lj500/index.html 200/97,383B、
          /lj500/src/polyfills.bundle.5adbf.js 200/14,750B（老 vendor_a 前缀兜底）、
          customizations.info 200 空、/cdn-cgi/rum 204
```

## 四、保留项（不涉及动态跨域，继续有效）

```text
· 静态域名兜底回老 vendor_a 前缀（@vendor_b_vendor_a_fallback）：路径映射，不是跨域处理。
· 静态域名 /cdn-cgi/rum → 204：属于静态域名的行为处理（CF 探针在非 CF 域名上不再 405）。
```
