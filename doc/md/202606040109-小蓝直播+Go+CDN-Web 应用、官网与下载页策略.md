# Web 应用、官网与下载页策略

> 来源文件：`~/Projects/work/game/xiaolan-watches/dev/docs/architecture/web-surface-strategy.md`

> 整理日期：2026-06-04 01:09｜日期依据：文件创建/修改时间

本文件定义公共 AI 框架如何支持 Web 项目。Web 不是移动 App 的附属品，也不是后台的别名；它是 Monorepo 中的一等应用类型。

## 1. Web Surface 分类

| Surface | 默认目录 | 说明 |
| --- | --- | --- |
| 移动 App | `apps/mobile` | React Native、Expo、原生壳或主客户端。 |
| 官网/下载页 | `apps/web` | App 官网、下载页、投放页、隐私条款入口。 |
| PC/H5/Public Web | `apps/web` | 面向用户的 Web 产品站、H5、内容站或响应式 Web App。 |
| 后台管理端 | `apps/admin` | 运营、审核、配置、报表、权限工作台。 |

移动 App 项目默认要考虑 `apps/web`，因为真实产品通常需要官网、下载入口、隐私政策、服务条款、投放页和应用商店审核材料。纯 Web 项目可以不创建 `apps/mobile`，但必须明确 `apps/web` 内包含哪些 surface。

## 2. 目录选择规则

```text
只做 App 客户端：apps/mobile + apps/web
App + 官网：apps/mobile + apps/web
PC/H5 产品：apps/web
运营后台：apps/admin 或 services/laravel-app/app/Filament
复杂全端产品：apps/mobile + apps/web + apps/admin
```

禁止把：

1. 官网下载页塞进 `apps/mobile`。
2. PC 用户站塞进 `apps/admin`。
3. 后台管理端伪装成 `apps/web`。
4. 营销官网和后台共用同一个无边界应用。

## 3. Web 技术栈选择

团队默认 Web 技术栈为 Nuxt 4 + Tailwind CSS v4，但公共框架仍要求在 `framework.config.json` 显式声明：

```json
{
  "web": {
    "stackProfile": "nuxt4-tailwindcss4",
    "supportedSurfaces": ["official-site", "download-page", "pc-web", "h5", "mobile-web-preview"],
    "defaultFramework": "nuxt",
    "defaultFrameworkVersion": "4",
    "defaultCssFramework": "tailwindcss",
    "defaultCssFrameworkVersion": "4"
  }
}
```

常见选择：

| 场景 | 推荐 |
| --- | --- |
| 官网、SEO异常验证、内容站 | 默认 Nuxt 4 + Tailwind CSS v4；特殊项目可选 Next.js、Astro、Laravel Blade/Inertia |
| 内部后台 | React/Vue + 后台 UI 框架，或 Laravel Filament |
| H5 活动页 | 默认 Nuxt 4；轻量活动可选 Vite React/Vue |
| 强交互 Web App | 默认 Nuxt 4；特殊项目可选 React/Vue/Svelte + API 契约 |

选型必须写 ADR 或技术栈文档。不能因为模板有 `apps/web` 就默认可随手写一个无测试页面。

Nuxt 4 + Tailwind CSS v4 目录、配置、共享 UI 和门禁见：

```text
docs/architecture/web-stack-nuxt-tailwind.md
```

## 4. 响应式验收

Web 应用默认至少验证：

```text
375x812    手机
768x1024   平板
1440x900   桌面
```

如果项目有特殊目标设备，可以在任务卡和 Agent 日志中替换，但必须显式说明。

官网/下载页还必须验证：

1. 下载按钮区域状态：已上线、即将上线、不可用、渠道未配置。
2. App Store / Google Play / APK / 企业包入口不能伪装。
3. 首屏、功能介绍、信任说明、下载转化区顺序清晰。
4. 触控轮播、桌面轮播、键盘可访问性或替代交互。
5. SEO异常验证 title、description、社交分享图或项目约定元数据。

## 5. 契约与数据

`apps/web` 仍然遵守契约优先：

1. 读取业务数据前先确认 OpenAPI。
2. 已有接口时不得用静态假数据冒充已完成。
3. CMS、活动配置、下载渠道配置也要有 owner 和契约。
4. 表单提交、预约、订阅、登录、支付等行为必须有服务端实现或明确标记占位。

## 6. 部署边界

早期可合并部署：

```text
server-web
  /              -> apps/web
  /app           -> apps/web
  /admin         -> apps/admin 或 Laravel Filament
  /api           -> services/go-app
```

流量增长后按压力拆：

```text
cdn-static       静态资源、图片、构建产物
server-web       官网、下载页、PC/H5 产品站
server-go-admin  后台管理端
server-go-app    API 服务
```

部署规则写在 `infra/deploy/`，不要写进 `apps/*` 私有目录。

## 7. Agent 验收要求

涉及 `apps/web/**` 的任务，Agent 日志必须写：

1. PRD 或营销目标来源。
2. UI 验收模式和参考来源。
3. 响应式视口截图，至少手机 + 桌面。
4. 关键 API、下载渠道或表单提交状态。
5. SEO异常验证 / 分享 / 统计埋点状态，如不涉及必须说明。
6. 红蓝对抗和明确合入判断。
