## 20G 提醒处理 SOP

达到 `APP_LOG_ALERT_GB` 阈值时只提醒，不自动删除。

先看大文件：

```bash
cd /opt/docker-youdianse-php
du -sh runtime/app-logs
find runtime/app-logs -type f -printf '%s %TY-%Tm-%Td %p\n' | sort -nr | head -30
```

确认无排障价值后再清理，示例：

```bash
: > runtime/app-logs/queue/watchdog.log
find runtime/app-logs -type f -name '*.log' -mtime +30 -delete
```

清理前要确认业务是否仍需这些日志，避免影响问题追踪。

## 已知观察项

2026-07-06 手动发布后观察到业务运行期输出：

```text
event_mqs not found, task_id=s
event_mqs not found, task_id=i
event_mqs not found, task_id=b
```

这不是日志持久化挂载失败。需要后端确认是否为业务队列任务的正常提示。

另一个维护项：

- `entrypoint/web-entrypoint.sh` 和 `entrypoint/cron-entrypoint.sh` 会输出 `YOUDIANSE_PHP_REPO_URL`。
- 如果运行环境里该变量含认证信息，Docker json 日志里可能出现敏感仓库 URL。
- 后续应把 entrypoint 输出改成脱敏格式，只展示仓库域名/路径或 `https://***@...`。
- 修改后需要重新构建并发布一次镜像；如果线上 Docker json 日志已经包含敏感内容，需要评估是否清理或轮转对应容器日志。

## 后续建议

- 把客服 URL 等频繁变化配置逐步从 `.env` 迁到后台或安全配置中心。
- 给 `runtime/app-logs` 增加更明确的人工清理 SOP。
- 保持 `ops/production/` 只记录可提交的脱敏运维信息。
- 每次改 CICD 发布流程，都要重新做一次手动发布或 no-build 同步验证。
