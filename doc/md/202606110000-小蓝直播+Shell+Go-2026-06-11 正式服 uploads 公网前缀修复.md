# 2026-06-11 正式服 uploads 公网前缀修复

> GitHub 仓库源文件：[点击打开网页渲染版](https://github.com/ben2023niao/ben-ops-notes/blob/main/doc/md/202606110000-%E5%B0%8F%E8%93%9D%E7%9B%B4%E6%92%AD%2BShell%2BGo-2026-06-11%20%E6%AD%A3%E5%BC%8F%E6%9C%8D%20uploads%20%E5%85%AC%E7%BD%91%E5%89%8D%E7%BC%80%E4%BF%AE%E5%A4%8D.md)

> 整理日期：2026-06-11 00:00｜日期依据：文件名日期

## 背景

正式后台球队列表中的队徽图片加载失败，浏览器控制台显示 HTTPS 页面尝试加载 `http://203.0.113.1:8081/uploads/...`，触发 mixed content 和 localhost 连接失败。

## 根因

正式服当前使用 local storage 临时方案，后端上传服务会把 `storage.local_public_base` 拼入返回 URL。正式 compose 和发布脚本没有把 `APP_STORAGE_*` 变量传入后端容器，导致容器继续使用 docker 默认配置 `http://203.0.113.1:8081/uploads`。

这不是 uploads volume 未挂载。`kickoff-admin-api` 已挂载 `kickoff_uploads:/workspace/services/go-app/uploads`；问题是返回给浏览器的公网 URL 前缀错误。

## 变更

- 后端配置加载器显式绑定 `APP_STORAGE_*` 环境变量。
- main 正式 compose 为后端服务注入 storage 环境变量，local uploads 默认公网前缀为 `https://admin-api.shijiebeixl.com/uploads`。
- Spug main 发布脚本保留并传递 storage 环境变量，避免 `sudo env docker compose` 丢失配置。
- 更新 main 发布文档和 Spug 任务模板，明确 local uploads 临时方案必须使用 HTTPS 公网域名。

## 验证

- `go test ./...`
- `npm run check:ops`
- `sh -n infra/deploy/spug-main-update.sh`
- `.gitlab-ci.yml` 和 `infra/deploy/docker-compose.main.yml` YAML 解析通过。

## 红蓝对抗

- 红队质疑：这是否只是 uploads volume 没挂载，改 URL 前缀会不会掩盖真实文件不存在问题？
- 蓝队结论：不是挂载问题。生产容器已经挂载 `kickoff_uploads:/workspace/services/go-app/uploads`，浏览器报错为 mixed content 和 `203.0.113.1` 连接失败，属于返回 URL 不可被公网浏览器访问。
- 红队质疑：只改 `.cicd.env` 是否足够？
- 蓝队结论：不够。发布脚本通过 `sudo env docker compose` 显式传递环境变量，正式 compose 也需要声明 service environment，否则 storage env 可能不会进入后端容器。
- 红队质疑：是否会影响 S3 方案？
- 蓝队结论：不会。变更保留 `APP_STORAGE_DRIVER` 和 S3 相关 env，local 只是当前生产临时方案的默认值，后续可切换为 S3/CloudFront。

## 合入判断

可以合入。该变更只影响后端配置加载和 main 镜像发布环境变量，不改变 API 字段、不改变数据库结构、不触碰 C 端/主播端前端实现。风险点是生产 `.cicd.env` 需要同步补齐 `APP_STORAGE_*`，并对已有数据库中的旧 localhost URL 做一次替换。项目级闭环状态按 `docs/qa/project-acceptance.md` 继续跟踪。

## 生产处理说明

代码发布后，需要在正式 `.cicd.env` 中保留：

```bash
APP_STORAGE_DRIVER=local
APP_STORAGE_LOCAL_BASE_DIR=/workspace/services/go-app/uploads
APP_STORAGE_LOCAL_PUBLIC_BASE=https://admin-api.shijiebeixl.com/uploads
APP_STORAGE_MAX_SIZE_MB=10
```

已经写入数据库的旧 URL 需要一次性替换 `http://203.0.113.1:8081/uploads` 为 `https://admin-api.shijiebeixl.com/uploads`。

不涉及前端字段变更。
